RICH NETLIST · TOOLKIT 0.1Edits text · solves on the desktop

Tools

Open a netlist in your browser, or download the viewer for Windows, Linux or macOS.

The RNL toolkit comes with two viewers: the web viewer, with nothing to install, and the desktop viewer for Windows 10 and 11, Linux and macOS. They read netlists with RNL records and draw them as schematics, and they edit the netlist’s text and draw it again when you apply the changes. The web viewer saves by downloading the file; the desktop viewer writes it back where it was read, and it also solves, showing the result as a preview that writes nothing into the files.

01 · Viewers

Open a netlist, see the schematic. Nothing is written until you save.

A viewer opens a SPICE or Spectre netlist with RNL records, with the files it includes, draws each level of the circuit, and shows the netlist text, the problems and the hierarchy beside it. A netlist’s text in the clipboard opens too: File › Load from Clipboard shows the text first, and opens it when you confirm.

Draws every level

The top level and each subcircuit are drawings of their own, shown one at a time; drag to move, scroll to zoom. Double-click a subcircuit instance to open its drawing; Backspace goes back up.

The netlist text

The netlist and the files it includes, in tabs, with the RNL records and the netlist’s statements highlighted; statements that do not take effect have a soft background. While a subcircuit is drawn, the text outside its definition is dimmed, and entering it brings the start of its definition into view.

Problems

Errors, warnings and hints are listed below the text; click one to see its line. The line numbers of those lines are coloured too.

Hierarchy

The tree of instances under the top level, and below it every subcircuit by name, grouped by initial, with a search box; pick one to open its drawing.

Drawing and text, linked

Click an instance or a wire in the drawing, and the text marks its statement and every place that names it; click the text, and the drawing selects it.

Objects not drawn

Objects without a position are not drawn, and the Not drawn view of the side panel lists them, each with its symbol and the nets at its terminals, searchable by name; pick one to see its statement in the netlist. The status bar says what the level lacks, and a click on it opens the view.

Edit, apply, save

Both viewers edit the netlist’s text. A change does nothing by itself: it is drawn when you apply it and written when you save it, and nothing solves by itself.

Edit the text

Edit › Edit Text (Ctrl+E) turns the netlist into a text box per file, each in its tab, with line numbers. A file with changes not saved has a dot on its tab, and the bar above the text says when changes are not applied yet.

Apply

Edit › Apply Changes (Ctrl+Enter) builds the netlist again from the edited text and draws it, with the problems and the hierarchy made again, keeping the level, the view and the selection. If the build fails, the changes stay and the viewer says why.

Save

File › Save (Ctrl+S): the desktop viewer writes the edited files back where they were read, each in its encoding and with its line ends, and no other file; the web viewer cannot write a file it read, so Save downloads the file shown. With changes not saved, opening another file, reading it again or closing asks first.

Both viewers draw the same schematic: one Rust core decides where every line and every piece of text goes, natively on the desktop and as WebAssembly in the browser, and lays out text in the fonts it ships.

02 · Web viewer

The web viewer: nothing to install.

Library is the first sidebar tab: opened files also join Files without duplicates. Include File / Include Folder add without opening; Exclude removes from search while leaving the current document open. Files starts expanded; the read-only Built-in group (standard series 0.3 and 0.2) starts collapsed. Collapse state lasts for the session, and root-file rows are highlighted. Clipboard text has one temporary · not searched row outside lookup; click to return to its last applied text. The next paste replaces it, and closing clears it. Include Public Package adds packages such as SKY130 from this site, without the GitHub API. Browsers use the file pool instead of searching arbitrary local PATH directories.

The web viewer is a static web page, with the RNL core compiled to WebAssembly running inside it. It opens files or a whole folder from your computer, or a netlist on the web; files dropped on the page open too.

Open the web viewerrich-netlist.github.io/rnl/viewer/

Try these samples

The samples come from RNL’s conformance corpus and are published with the web viewer. Click one and the viewer opens it.

  1. 04HierarchyA two-stage buffer: a drawing for each subcircuit, drawn as a block symbol one level up, and a file it includes.
  2. 15ChineseA five-transistor OTA written with the Chinese alias package rnl-zh, with Chinese labels in the drawing.
  3. 17Line stylesEvery line style on every kind of shape: dashed, dotted, bold and double lines on rectangles, circles, ellipses, arcs and curves, and on a wire.

Your files stay in the browser

Files you open from your computer are read in the page and uploaded nowhere: the site is only static files, with no server to receive them.

Open a URL

File › Open URL reads a netlist from another web server, and the files it includes from the same place. That server has to allow cross-origin reads (CORS), as GitHub’s raw file links do.

Browsers

Chrome and Edge 109 or later, Safari 16 or later, and Firefox 114 or later, the first with module Workers.

The web viewer edits the text and draws it again when the changes are applied, as above. A page cannot write the files it read, so File › Save is a download: of the file shown, with the line ends it had, in UTF-8. Only the desktop viewer solves; the web viewer has no Solve menu.

The viewer’s address can name the netlist to open, so a link can be shared: viewer/?url=https://raw.githubusercontent.com/…/04-hierarchy.sp opens a netlist on GitHub with the file it includes.

Embedding in another page

Use viewer/?embed=1 in an iframe for a canvas-only interactive viewer. Switch netlists, levels and backgrounds through postMessage without reloading. See the embedding API and example, or try the demo.

The web viewer here is built from the newest commit of the main branch; Help › About names its version and commit, and Help › Desktop Viewer leads back to this page.

03 · Desktop viewer

The desktop viewer for Windows, Linux and macOS.

The desktop RNL Viewer reads and writes files on disk by their paths: the files a netlist includes are found wherever they are, F5 reads a changed file again, edited text is saved back where it was read, and File › Save As saves the netlist under a new name. Its window shows the same page as the web viewer, with a Solve menu besides, which solves.

The desktop Library shows ordered PATH groups between Files and Built-in, initially collapsed, with add, move and remove controls. Expand a group to see direct .rnl files and those in one version-number subdirectory; opening a row also adds it to Files. Directories rescan on entering Library and after PATH changes. All settings, including solver, display and PATH, live in settings.json in Tauri’s application configuration directory; old browser settings migrate on first start, and the exact path is fixed at the bottom of Library. Includes try their relative location first; bare filenames fall back to the pool, then PATH, with a hint naming the selected file. Packages search the pool, PATH and built-ins, taking the first copy of the selected version. Each directory prefers name.rnl and version/name.rnl, then scans other .rnl files and checks their PACKAGE headers, so filenames may differ from package names. A user’s rnl-std can override the bundled copy.

Solving, as a preview

The desktop viewer’s Solve menu places the objects without a position with the solver of rnl solve. The result is shown in the window only, and the files stay as they are.

A solved preview

Solve › Solve (F9) solves the netlist shown, with the files it includes, as rnl solve does, from the text applied. It runs in the background, so the window stays usable, and the status bar shows the level being solved, with a Cancel button. The bar above the drawing says that this is a preview and the files are unchanged, and the Solve view of the side panel has the solve’s report, each line shown in the netlist when clicked. Solve › Close Preview shows the file as written.

Save a solved copy

Solve › Save Solved Copy As (Ctrl+Shift+S) saves the result where you choose: one file, offered as NAME-solved.EXT, for a netlist that includes no other file; otherwise a folder with the files solved and the other files read, as rnl solve -o DIR writes them. A place that would replace any file that was read is refused.

The solver’s settings

Solve › Settings sets the solver’s options: the time limit of each level, the tolerance, the grid, the beam, the work of the search and the router, and the objectives that rank the placements: which are on, which counts first, and the weights of those that share a level. The priority of a constraint (low, normal, high) is written in the netlist, not set here. Restore Defaults brings back the solver’s defaults, and the settings stay for the next start.

04 · Command line

Download, extract, run.

Use rnl to check netlists, render SVGs and solve layouts. No Rust installation is needed; Windows also needs no separate VC++ runtime. The CLI and npm package share the core version, independently of Viewer and the language standard.

RNL core · CLICore release
  • Windows x64.zip · MSVC

    Extract, then run .\rnl.exe --version.

  • Linux x86_64.tar.gz · musl

    Statically linked. Extract, then run ./rnl --version.

  • macOS · Apple Silicon.tar.gz · arm64

    For Macs with Apple Silicon.

  • macOS · Intel.tar.gz · x86_64

    For Macs with Intel processors.

SHA256SUMS.txt: verify the archive's SHA256 before running it. rnl --version shows the core version and build commit; use rnl check my.sp to check a netlist and rnl render my.sp -o svg to export drawings.

Downloads become available with the first core-v* release and follow the latest core. Files are unsigned: Windows may show SmartScreen; macOS browser downloads may need xattr -d com.apple.quarantine rnl. Linux arm64 currently needs a source build. See the CLI guide for download, extraction and checksum commands.

05 · Virtuoso export

Export Virtuoso schematics to RNL.

rnl-virtuoso adds RNL → Export RNL... to Virtuoso’s schematic editor and File → Export → RNL... to the CIW. It exports one cell or a whole library, keeping hierarchy, custom block symbols, placement, orientation, wires and buses, and draws with the eda-symbol and eda-style packages.

06 · Toolchain

The RNL toolchain: read, solve, draw, edit.

The toolchain keeps “understanding RNL” and “turning intent into coordinates” in separate modules: you can view a drawing without a solver and solve only when needed. What exists today: the runtime, the host adapters, the renderer and the command line, the two viewers above, and a first version of the solver, in rnl solve and the desktop viewer. Pick a path to see how data flows; click a module to see what it does.

App shells Web viewer · WebAssembly Desktop viewer · Tauri 2 Mobile browsers The two viewers share one page; the core is written in Rust and runs natively on the desktop and as WebAssembly in the browser. Previews of the core as WebAssembly are on npm as @rich-netlist/runtime.
