Tools

Open a netlist in your browser, or download the viewer for Windows, Linux or macOS

The RNL toolkit comes with two viewers: the web viewer, with nothing to install, and the desktop viewer for Windows 10 and 11, Linux and macOS. They read netlists with RNL records and draw them as schematics, and they edit the netlist’s text and draw it again when you apply the changes. The web viewer saves by downloading the file; the desktop viewer writes it back where it was read. Both also solve, showing the result as a preview that writes nothing into the files.

01 · Viewers

Open a netlist, see the schematic. Nothing is written until you save

A viewer opens a SPICE or Spectre netlist with RNL records, with the files it includes, draws each level of the circuit, and shows the netlist text, the problems and the hierarchy beside it. A netlist’s text in the clipboard opens too: File › Load from Clipboard shows the text first, and opens it when you confirm.

Draws every level

The top level and each subcircuit are drawings of their own, shown one at a time; drag to move, scroll to zoom. Double-click a subcircuit instance to open its drawing; Backspace goes back up.

The netlist text

The netlist and the files it includes, with the RNL records and the netlist’s statements highlighted; statements that do not take effect have a soft background. While a subcircuit is drawn, the text outside its definition is dimmed, and entering the subcircuit brings the start of its definition into view.

Problems

Errors, warnings and hints are listed below the text; click one to see its line. The line numbers of those lines are colored too.

Hierarchy

The tree of instances under the top level, and below it every subcircuit by name, grouped by initial, with a search box; pick one to open its drawing.

Drawing and text, linked

Click an instance or a wire in the drawing, and the text marks its statement and every place that names it; click the text, and the drawing selects it.

Objects not drawn

Objects without a position are not drawn; the Not drawn view of the side panel lists them with their symbols and terminal nets, searchable by name, and clicking one highlights its statement in the netlist. The status bar reports how many objects are not drawn, and clicking that message opens the view.

Edit, apply, save

Both viewers edit the netlist’s text. A change does nothing by itself: it is drawn when you apply it and written when you save it. Only opening a netlist with components not drawn asks whether to solve it, and the answer is a preview that changes no file.

Edit the text

Edit › Edit Text (Ctrl+Q, the Control key on macOS too) turns the netlist view into an editable text box with line numbers for each file. Unsaved changes are marked with a dot beside the file path, and the bar above the text indicates when changes have not been applied yet. Edit › Discard Changes drops unapplied changes and exits editing.

Apply

Edit › Apply and Exit Editing (Ctrl+Enter) rebuilds the netlist from the edited text, redraws the schematic, refreshes the problems list and hierarchy while keeping the current level, view and selection, and exits editing. If the build fails, your edits remain open and the viewer reports why.

Save

File › Save (Ctrl+S; File › Download File in the web viewer): the desktop viewer writes only the edited files back where they were read, preserving each file’s encoding and line endings; the web viewer cannot overwrite local files, so Download File downloads the file shown. With unsaved changes, the viewer asks before opening another file, reloading or closing.

Both viewers draw the same schematic: one Rust core decides where every line and every piece of text goes, natively on the desktop and as WebAssembly in the browser, and lays out text in the fonts it ships.

02 · Web viewer

The web viewer: nothing to install

In the Library sidebar tab (the first tab), opened files are added to the Files group without duplicates. Include File and Include Folder add files to the Library without opening them, while Exclude removes a file from search without closing the current document. Include Public Package adds hosted packages such as SKY130 from this site without using the GitHub API. Files starts expanded and the read-only Built-in group (standard series 0.4) starts collapsed; collapse state lasts for the session, and root-file rows are highlighted. Pasted clipboard text appears as a single temporary · not searched row outside lookup—click it to return to its last applied text, paste again to replace it, or close it to clear it. Because browsers cannot search arbitrary local PATH directories, the web viewer resolves includes and packages from the Library.

The web viewer is a static web page, with the RNL core compiled to WebAssembly running inside it. It opens files or a whole folder from your computer, or a netlist on the web; files dropped on the page open too.

Open the web viewerrich-netlist.github.io/rnl/viewer/

Try these samples

The samples come from RNL’s conformance corpus, written for the solver and solved by it, and are published with the web viewer. Click one and the viewer opens it.

  1. 04HierarchyA two-stage buffer: a drawing for each subcircuit, drawn as a block symbol one level up, and a file it includes.
  2. 15ChineseA five-transistor OTA written with the Chinese alias package alias-zh, with Chinese labels in the drawing.
  3. 17Line stylesEvery line style on every kind of shape: dashed, dotted, bold and double lines on rectangles, circles, ellipses, arcs and curves, and on a wire.

Your files stay in the browser

Files you open from your computer are read in the page and uploaded nowhere: the site is only static files, with no server to receive them.

Open a URL

File › Open URL reads a netlist from another web server, and the files it includes from the same place. That server has to allow cross-origin reads (CORS), as GitHub’s raw file links do.

Browsers

Chrome and Edge 109 or later, Safari 16 or later, and Firefox 114 or later (the earliest versions with module Worker support).

The web viewer edits the text and redraws the schematic when changes are applied, as described above. Because a browser page cannot overwrite local files, File › Download File (Ctrl+S) downloads the file shown in UTF-8 with its original line endings. The web viewer has the Solve menu too, described below: the solver is loaded into the page when you first use it, runs in the browser, and sends nothing anywhere.

The viewer’s address can name the netlist to open, so a link can be shared: viewer/?url=https://raw.githubusercontent.com/…/04-hierarchy.sp opens a netlist on GitHub with the file it includes.

Embedding in another page

Use viewer/?embed=1 in an iframe for a canvas-only interactive viewer. Switch netlists, levels and backgrounds through postMessage without reloading. See the embedding API and example, or try the demo.

The web viewer here is built from the latest commit on the main branch; Help › About RNL Viewer shows its version and commit, and Help › Desktop Viewer leads back to this page.

03 · Desktop viewer

The desktop viewer for Windows, Linux and macOS

The desktop RNL Viewer reads and writes files on disk by their paths: the files a netlist includes are found wherever they are, F5 reads a changed file again, edited text is saved back where it was read, and File › Save As saves the netlist under a new name. It shares the web viewer’s interface, Solve menu included, and adds what needs the disk: saving a solved copy, and solving a netlist whose included files are found by Auto Include.

The desktop Library shows ordered PATH groups between Files and Built-in, initially collapsed, with add, move and remove controls. Expand a group to see .rnl files directly in that folder or one level deep in a version-number subfolder; opening a row also adds it to Files. Directories are rescanned when you open Library and after PATH changes. All settings—including solver, display and PATH—are stored in settings.json in Tauri’s application configuration directory; existing web-view settings migrate on first start, and the exact path to settings.json is shown at the bottom of Library. Includes try their relative path first; bare filenames fall back to the Library and then PATH, emitting a hint that names the resolved file. Packages search the Library, PATH and built-ins, taking the first match for the requested version. Each directory checks name.rnl and version/name.rnl first, then scans other .rnl files for their PACKAGE headers, so filenames need not match package names. A user’s copy of a standard package, such as rnl-std-all, can override the bundled one.

Solving

The Solve menu of the web and desktop viewers places the objects without a position with the solver of rnl solve; the web viewer loads it into the page at the first solve. The result is shown in the window only, and the files stay as they are; the desktop viewer can save it as a copy.

A solved preview

Solve › Solve (F9) solves the applied text of the circuit shown, with the files it includes, the same way as rnl solve; Solve › Solve All Circuits solves every circuit. A progress panel over the drawing shows the circuit being solved, the stage, the time and the candidates tried, with a Cancel button. The result is a preview: the files are unchanged, and the Solve view in the side panel shows the solver’s report—click any entry to jump to its line in the netlist. Solve › Close Preview returns to the file as written. A netlist opened with components not drawn asks whether to solve it; Solve › Ask to Solve on Open turns the question off.

Save a solved copy

On the desktop, Solve › Save Solved Copy As (Ctrl+Shift+S) saves the result where you choose: one file, offered as NAME-solved.EXT, for a netlist that includes no other file; otherwise a folder with the files solved and the other files read, as rnl solve -o DIR writes them. A place that would replace any file that was read is refused. The web viewer has no Save Solved Copy and no Auto Include, so a netlist that needs them is solved in the desktop viewer.

The solver’s settings

Solve › Settings is drawn from the solver’s own table of settings and shows those of the chosen layout: the time limit per level, the time for the whole file, and the objectives that rank placements, with their order and weights. It lists what the netlist and its packages set, and a value set here wins. Constraint priority (low, normal, high) is written in the netlist, not set here. Restore Defaults resets all options to their defaults, and settings persist across launches.

New in the Viewer for 0.4

The Viewer that reads language 0.4 has more ways to look at a drawing.

Layout table

Solve › Show Layout Table draws a thin table over the schematic that shows which row and column each object and group of the level falls in. It is worked out from the drawing, so it needs no solve.

Skeleton lines

Solve › Show Component and Pin Skeleton Lines and Solve › Show Wire Skeleton Lines draw thin dashed reference lines across the schematic: a cross through each component’s registration point, a line along each pin’s direction, and the extension of each wire. Lines that coincide are drawn once, and pointing at one names its component, pin or wire. They are worked out from the drawing, so they work on any schematic however it was laid out.

Groups in the tree

In the Solve panel, Groups lists the groups of the level as the tree the solver takes them in, each under the smallest group that holds all its members. Click one to light it in the drawing; a check shows or hides its frame. Groups the solver does not take in (left out because they cross another group, with the same members as another, or turned off by PRIORITY) follow, greyed, with the reason.

Flylines

A connection that has no wire yet is drawn as a flyline between its pins; View › Show Flylines (L) turns them on or off, and they are off to begin with. rnl render --flylines draws them.

04 · Command line

Download, extract, run

Use rnl to check netlists, render SVGs and solve layouts. No Rust installation is needed; Windows also needs no separate VC++ runtime. The CLI and npm package share the core version, independently of Viewer and the language standard.

RNL core · CLICore release
  • Windows x64.zip · MSVC

    Extract, then run .\rnl.exe --version.

  • Linux x86_64.tar.gz · musl

    Statically linked. Extract, then run ./rnl --version.

  • macOS · Apple Silicon.tar.gz · arm64

    For Macs with Apple Silicon.

  • macOS · Intel.tar.gz · x86_64

    For Macs with Intel processors.

SHA256SUMS.txt: verify the archive's SHA256 before running it. rnl --version shows the core version and build commit; use rnl check my.sp to check a netlist and rnl render my.sp -o svg to export drawings.

From 0.3 to 0.4

Language 0.4 does not read files of 0.3, and versions before 1.0 promise no compatibility. The last core of the 0.5 series, 0.5.7, carries the upgrade tool: it reads a file of 0.3 (or 0.2) and writes it as 0.4. Core 0.6.0 and later read 0.4 only.

A file of 0.3, such as one that rnl-virtuoso 0.9.6 or earlier exports, can be opened as it is in the web viewer of the 0.5 series, kept on this site, or upgraded to 0.4 with the steps below. rnl-virtuoso 0.10.0 and later export 0.4.

  1. Download the command line of core 0.5.7 from its release page and extract it. The npm package @rich-netlist/runtime has no rnl command.
  2. Preview, which writes nothing: rnl upgrade my.sp. It prints a one-line summary of what it would change and what it leaves to a person; add --report REPORT.json for the full list.
  3. Save the upgraded file: rnl upgrade my.sp -o DIR, or rnl upgrade my.sp --in-place to rewrite the file where it is. --report REPORT.json keeps the full list.
  4. Some changes are choices that may change meaning, such as which of the two definitions a differential pair or a current mirror becomes. They are made only with --approximate, and each is reported with its risk.
  5. Check the result with the core 0.6.0 or later: rnl check my.sp. By default the upgrade drops the records the solver wrote (type="generated") and the report says the file needs a new solve; with --keep-generated it upgrades them instead and keeps their placements.

The report lists a difference only where meaning or geometry changed. Changes that only come from the 0.4 standard package’s default look, such as label places and styles, are listed apart as default_look_changes and do not make the upgrade fail.

For an AI agent: if a file is 0.3, use the upgrade tool; do not edit it by hand. Until you have upgraded, the web viewer of the 0.5 series, kept on this site, still reads files of 0.3.

These links always follow the latest core-v* release. Files are unsigned: Windows may show SmartScreen; macOS browser downloads may need xattr -d com.apple.quarantine rnl. Linux arm64 currently needs a source build. See the CLI guide for download, extraction and checksum commands.

05 · Virtuoso export

Export Virtuoso schematics to RNL

rnl-virtuoso adds RNL → Export RNL... to Virtuoso’s schematic editor and File → Export → RNL... to the CIW. It exports one cell or a whole library, keeping hierarchy, custom block symbols, placement, orientation, wires and buses, and draws with the eda-symbol and eda-style packages.

06 · Toolchain

The RNL toolchain: read, solve, draw, edit

The toolchain keeps “understanding RNL” and “turning intent into coordinates” in separate modules: you can view a drawing without a solver and solve only when needed. What exists today: the runtime, the host adapters, the renderer and the command line, the two viewers above, and the solver, in rnl solve and both viewers. Pick a path to see how data flows; click a module to see what it does.

App shells Web viewer · WebAssembly Desktop viewer · Tauri 2 Mobile browsers The two viewers share one UI; the core is written in Rust and runs natively on the desktop and as WebAssembly in the browser. The WebAssembly core is also published on npm as @rich-netlist/runtime.
