T1 · 句子T1 · Sentences

语句读作事实：记号、例句、中文。Statements read as facts: notation, sentences, Chinese.

机器只读记号：# & % $ 开头的引用、@ 开头的关键字、括号里的参数、花括号、分号和 =>。记号之间的词都是自由文本，可以写，也可以不写。标准例句给每个关键字配好了词，让同一类语句到处读起来一样；中文代称包把同样的句子换成中文。 Machines read only the notation: references starting with # & % $, keywords starting with @, parameters in parentheses, braces, semicolons and =>. The words between them are free text, there or not. The standard sentences give every keyword its words, so statements of one kind read the same everywhere; the Chinese alias package turns the same sentences into Chinese.

标准例句怎样写How the standard sentences are written

  • 读作事实Facts, not commands语句说的是图上成立的事实，不是要做的操作。对象是主语，关键字是谓语或名词，参数是它的值；只加 is、are、has、there is 或“是、位于、有、按……排列”这样的连接词。A statement says what holds in the drawing, not an action to take. Objects are the subject, the keyword is the verb or noun, parameters are its values; only linking words such as is, are, has and there is are added.
  • 不说多No more than it says不写 must、only、“必须”这类比语句说得多的词：读的人会相信它们，机器却不读。No words that claim more than the statement, such as must, only or required: readers believe them, and machines ignore them.
  • 补一句A gloss朝向码和轴后面可以补“, i.e., …”“，即……”说明含义：#M2 @朝向("MX")，即上下镜像。A code or axis can be followed by “, i.e., …” saying what it means: #M2 @ORIENT("MX"), i.e., flipped upside down.
  • 能写什么What free text may contain括号外，除了 @ # & % $ ? " ; = { } ( ) [ ] < >，别的字符都能写在记号之间，包括中文和标点；@ 前面要有一个空格。Outside parentheses, anything except @ # & % $ ? " ; = { } ( ) [ ] < > may sit between tokens, including punctuation; a space goes before every @.

四个常见的坑Four common slips

自由文本里的引用照样是引用；漏了前缀的名字却成了自由文本。下面的提示是 RNL 原型的检查工具给出的。 A reference inside free text is still a reference, while a name without its prefix becomes free text. The messages below come from the RNL prototype’s checker.

自由文本里的 M3 与元件 #M3 同名，是不是漏了前缀？The free text M3 has the same name as instance #M3; is a prefix missing?

M3 没有 #，是自由文本：这句只对齐 M1、M2。M3 has no #, so it is free text: only M1 and M2 are aligned.

没有提示：写法完全合法。No message: this is perfectly valid.

#M2 写在“说明”里也还是对象：PLACE 收到两个对象，逐个放，M2 也到了 x = 0。只是说明的话写进 /* */。#M2 is an object even inside the “explanation”: PLACE receives two objects and places each, so M2 also lands on x = 0. Put mere remarks in /* */.

引用后面紧跟 . 加名字：端子要写 :，这里的 .d 是自由文本。A reference is followed by . and a name: terminals use :, so .d here is free text.

这句指的是 M1 本身，不是漏极；CURRENT 只收端子，于是失效。写 #M1:d。This refers to M1 itself, not its drain; CURRENT takes only terminals, so the statement fails. Write #M1:d.

引用后面紧跟 !：名字里有这个字符时要加引号，如 &"vdd!"。A reference is followed by !: a name containing it must be quoted, as in &"vdd!".

没有引号时这是网络 vdd 加上自由文本“!”，而本层没有网络 vdd。Unquoted, this is the net vdd plus the free text “!”, and this level has no net vdd.

T2 · 定义T2 · Definitions

AS 说“是什么”，ATTACH 说“添上什么”。AS says what things are; ATTACH says what is added to them.

普通定义（@DEFINE）有角色、参数和一个体。用 AS 或 ATTACH 套用它，就产生一个用例：一个可以起名、可以被选择的对象。差分对、镜像对、地、端口都是这样来的，它们的定义都在标准包里。 A definition (@DEFINE) has roles, parameters and a body. Applying it with AS or ATTACH makes a usage: an object that can be named and selected. Differential pairs, mirror pairs, grounds and port tags all come about this way, and their definitions live in the standard package.

@AS

对象合起来构成这个东西。定义写在最后，对象按角色填进去：M1 填 in_p，M2 填 in_n。The objects together form the thing. The definition comes last, and the objects fill its roles: M1 fills in_p, M2 fills in_n.

@ATTACH

这个东西添在对象上。定义写在最前：地符号添在网络 vss 上，它只为显示而存在，不产生连接。The thing is added onto the objects. The definition comes first: a ground is added on net vss; it exists only for display and makes no connection.

语义定义和布局定义Semantic and layout definitions

$DIFFPAIR 的体是空的，套用它只记下“这是差分对”，不改画法。$MIRROR_PAIR 的体里写了约束，套用时角色换成对象，约束就展开到这一层。“是什么”和“怎么画”分开套用。 $DIFFPAIR has an empty body: applying it records “this is a differential pair” and changes nothing in the drawing. $MIRROR_PAIR has constraints in its body; when it is applied, the roles are replaced by the objects and the constraints expand into this level. What things are and how to draw them are applied separately.

T3 · 标准包T3 · Defaults

什么都不写，也能画出来。Write nothing, and it still draws.

标准包是一份 RNL 文件：默认符号、样式、定义，和几条补位规则。它排在每个文件前面，所以文件里写的总能盖过它。每个包里有什么，见标准包图库。下面这个共射级只有网表；依次加上三句，看标准包补上的东西怎样变化（灰色的都是它补的）。 The standard package is an RNL file: default symbols, styles, definitions and a few fill rules. It comes before every file, so whatever a file writes can override it; what each of its packages holds is in the gallery of the standard packages. The common-emitter stage below is a bare netlist; add three lines one by one and watch what the standard package fills in change (everything gray is its doing).

    T4 · 集合与选择T4 · Sets and selections

    集合打散一层；选择是规则。Sets spread one level; selections are rules.

    花括号写一个有序的集合。集合里引用另一个集合时，把它的成员放进来；要让它作为一个成员，就再套一层花括号。按条件选出的对象也是集合，而选择会在写它的层和下面每一层各求一次。 Braces write an ordered set. A set referenced inside another set contributes its members; to keep it as one member, wrap it in another pair of braces. Objects picked by a selection form a set too, and a selection is evaluated on its own level and once on each level below.

    打散，还是作一个成员Spread, or one member

    先有 %s1 = {#M1 #M2}、%s2 = {#M3 #M4}。试写里约 15 次运行写了左边那种，本意却是右边那种。点“换一种摆法”，看两句各允许哪些排列。 Given %s1 = {#M1 #M2} and %s2 = {#M3 #M4}. In the writing trial, about 15 runs wrote the left form while meaning the right one. Press “Another arrangement” to see which arrangements each allows.

    成员：Members: M1 M2 M3 M4

    四个元件逐个排序：只有 M1 M2 M3 M4 或倒过来。Four instances ordered one by one: only M1 M2 M3 M4, or the reverse.

    成员：Members: {M1 M2} {M3 M4}

    两组之间排序，各按自己的中心算；组内谁先谁后都行。The two groups are ordered by their centers; inside each group any order holds.

    按条件选Selecting by condition

    选择从一个范围里按条件挑对象：范围是 # 时是整层，给网络时是接在上面的东西。点一句，看它选出了什么。 A selection picks objects from a scope by condition: with # the scope is the whole level; with a net it is what is connected to it. Click a statement to see what it picks.

      每一层各求一次Once on every level

      规则按定义对待：写在顶层，就在顶层和下面每个子电路各求一次，每次只看那一层的对象。加 recursive=false 就只在写它的那一层生效。 A rule is treated like a definition: written at the top, it is evaluated on the top level and once in every subcircuit below, each time looking only at that level’s objects.       T5 · 导线T5 · Wires

      只有共用一个点，才算接上。Only a shared point joins wires.

      WIRE 收一个网络和一串有序的点，点可以是端子或点对象。网络只是注明，连接仍由网表定义；导线之间怎样相接，只看它们是否共用同一个点对象或端子。 WIRE takes a net and an ordered list of points, each a terminal or a point object. The net is only a note; connections are still defined by the netlist. Whether drawn wires join depends only on whether they share the same point object or terminal.

      六种走法Six routing modes

      点列里的点都是必经点；相邻两点之间怎样走，由 mode 决定。除了 auto，每种都是严格的规则，查看器照着画。点图里任意位置移动终点。 Every point in the list is visited; how a wire goes between neighbors is set by mode. Apart from auto, each mode is a strict rule that viewers follow. Click anywhere in the drawing to move the end point.

      总线、分接和叠画Buses, taps and bundles

      网表里没有总线：总线只是画法，几个网络画成一根粗线。单根导线与总线共用一个点，就是分接。叠画（BUNDLE）把一组元件画成一个符号，它的引脚代表各成员的同名端子。 Netlists have no buses: a bus is only a way of drawing several nets as one thick line. A single wire sharing a point with the bus is a tap. A bundle (BUNDLE) draws a group of instances as one symbol, whose pins stand for the members’ terminals of the same name.

      不想自己写走线时，&D<1> @ROUTE 把整个网络交给求解器：分叉、走法和圆点都由它定。To avoid writing the route, &D<1> @ROUTE hands the whole net to the solver: branches, paths and dots are up to it.

      T6 · 文字T6 · Text

      附着在对象上是标签，附着在点上是标注。Text on an object is a label; on a point, an annotation.

      TEXT 附着在什么上，决定了三件事：${…} 读谁的属性，文字默认放在哪，写了 key 时它是谁的子对象。文字自己的位置另算，可以用 PLACE 或 dx、dy 定。 What TEXT attaches to decides three things: whose properties ${…} reads, where the text goes by default, and, with a key, whose child object it is. The text’s own position is separate; PLACE or dx and dy can set it.

      文字记号Text markup

      借用 LaTeX 的一小部分，模型熟悉，写对的比例高。上下标必须带花括号，所以 g_m 照原样显示；${…} 读附着对象的属性，这里附着在 M1（W=2u L=0.5u）上。认不得的命令照原样显示并给警告，这段文字仍然有效。 A small subset of LaTeX, which models know well and get right. Subscripts and superscripts need braces, so g_m shows as is; ${…} reads properties of what the text is attached to, here M1 (W=2u L=0.5u). An unknown command shows as written with a warning, and the text stays valid.

      T7 · 朝向T7 · Orientation

      x 向右，y 向上；八个朝向码。x right, y up; eight orientation codes.

      坐标是网格单位，y 向上，与 Virtuoso 相同。朝向绕符号的原点作用：引脚的位置和出线方向跟着变，接的端子不变。只认下面八个码，R90 是逆时针转；MYR90、MXR90 先镜像再转。 Coordinates are grid units with y up, as in Virtuoso. An orientation acts about the symbol’s origin: pin positions and wire directions change with it, the terminals they belong to do not. Only these eight codes are accepted; R90 turns counterclockwise, and MYR90 and MXR90 mirror first, then turn.

      朝向关系Orientation relations

      ORIENT-RELATION 不定谁朝哪边，只定两者的关系：B 的朝向是 A 的朝向再做这个变换。$MIRROR_PAIR 里就是 "MY"：A 怎么转，B 都是它左右翻过来的样子。 ORIENT-RELATION fixes no direction, only the relation: B’s orientation is A’s followed by this transform. $MIRROR_PAIR uses "MY": however A turns, B is its left-right mirror image.

      T8 · 优先级T8 · Priority

      冲突不是错误：先比优先级，再比先后。Conflicts are not errors: priority first, then order.

      每个几何事实都有优先级：disabled、low、normal（默认）、high。取舍时按优先级从高到低、同一档里后写的在前，逐条纳入，与已纳入的矛盾就丢弃。一条 PLACE 是 x、y 两个事实，可以各自丢弃；用例展开出的事实排在套用它的那一句的位置。 Every geometric fact has a priority: disabled, low, normal (the default) or high. Facts are taken in order of priority, highest first, and within one priority the later-written first; each is kept unless it contradicts those already kept. A PLACE is two facts, x and y, which can be dropped separately; facts expanded from a usage stand where the statement applying it stands.

      三条记录怎样相处How three records get along

      1设计者Designer

      语义和约束，默认 normal。可以随时改。Semantics and constraints, normal by default. Edited at will.

      2求解器Solver

      坐标和导线，high。每次求解整段换掉；hash 记下求解时的输入。Coordinates and wires, high. Replaced as a whole on each solve; hash records the input it solved.

      3编辑器Editor

      手动的修改追加在后面，也是 high：同一档里后写的生效，所以盖过求解结果。Manual edits are appended after it, also high: within one priority the later wins, so they override the solver.

      输入改了、hash 对不上时，旧结果照常显示，查看器只建议重新求解，不报错。重新求解时，编辑器的 high 坐标是固定的位置，其余跟着调整。When the input changes and the hash no longer matches, the old result still displays; the viewer only suggests solving again, with no error. On the next solve, the editor’s high coordinates are fixed positions and everything else adjusts.

      T9 · 文件头T9 · Header

      头段记录：版本、代称包、器件的端子名。The header record: version, alias packages, device terminals.

      头段记录可以不写；写的话，它是文件的第一条记录，在子电路之外，至多一条。它总按标准写法读，里面不认代称。不写时按工具默认的版本读，工具保存文件时会补上。 The header record is optional; if written, it is the first record of the file, outside any subcircuit, and there is at most one. It is always read in standard spelling, without aliases. Without it, the file is read with the tool’s default version, and tools add the header when they save the file.

      提示Tip把鼠标放到头段记录的各部分上，看它们管什么。Hover over the parts of the header record to see what each does.

      PDK 器件的端子名Terminal names for PDK devices

      网表里没有定义的子电路，比如 PDK 里的 sky130_fd_pr__nfet_01v8，不知道端子叫什么，只能按序号写。@DEVICE 按名字和模型的通配给它们起端子名。 A subcircuit the netlist does not define, such as sky130_fd_pr__nfet_01v8 from a PDK, has no known terminal names, so only positions work. @DEVICE names its terminals, matching by name and model patterns.
