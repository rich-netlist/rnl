01 · What RNL is

Netlists rich in circuit semantics

RNL fills the high-level semantic gap between netlists and schematics: structures, intent and drawing

A real RNL case designed by an agent, and the schematic rendered from it

Review needs no line-by-line reading of the netlist, only a check of the semantics it declares. Exact schematic information can be generated by a solver or output directly by a model.

ota5t.sp Open in viewer
RNL recordsLines of the picked item

High-level semantics checklistHover or click an item

    The netlist owns devices and types, parameters, connections, the subcircuit interface

    RNL owns structures, intent, the drawing, display symbols; it only references the netlist

    The netlist describes the electrical facts, and Rich Netlist describes how to understand and present the circuit

    Hidden in comments

    Written in the host netlist’s legal comments, such as SPICE’s * @RNL {…}. Simulators skip it; nothing has to be stripped.

    Leaves the circuit alone

    It only references the netlist’s devices, nets and terminals; it cannot add devices, connections or parameters.

    Any level of detail

    From “M1 and M2 are a differential pair” down to every coordinate and bend, mixed freely in one file.

    RNL is not

    • Another netlist language
    • A second connection list
    • A format that prescribes one drawing
    • A pixel-level image archive

    Netlists and schematics each miss half the picture

    Simulation runs on netlists; understanding a circuit takes a schematic. Each falls short on its own.

    New challenges in AI-driven design flows

    AI writes netlists people cannot review

    A few hundred generated lines do not tell a reviewer what the circuit is.

    AI draws schematics unreliably

    Drawing a schematic stroke by stroke is hard for language models, and results vary widely between models.

    Agents reach schematics only through EDA tools

    The schematic is in a proprietary binary database: reading it or changing one wire goes through the tool’s interface.

    Today’s workarounds

    Redraw by hand

    Slow, and every netlist change means redrawing.

    Generate automatically

    Auto-layout knows the connections but not the structure: you cannot tell which transistors form a pair.

    Screenshots and exports

    You keep the picture and lose the circuit: no simulation, no further edits.

    Relying on EDA APIs

    AI can only edit the circuit through the EDA tool’s API, bound by the EDA ecosystem.

    RNL’s approach: a plain-text format that people and AI can read and edit directly, independent of any specific EDA tool

    03 · Advantages

    What you get from writing the meaning down

    Meaning first

    Say which devices form a differential pair or a current mirror, what is symmetric, where the current flows. These statements stay in the file however the drawing changes.

    One plain-text file

    Simulators run it as before; it diffs and merges in Git; the drawing and the netlist cannot drift apart.

    AI writes, people review

    AI writes the circuit together with its structures and drawing; people review the declared structures and intent in a viewer.

    Open

    A public standard and symbol libraries, open-source tools, a viewer that opens in the browser.

    Circuit separate from style

    The netlist defines what the circuit is; packages decide how it looks, like HTML for content and CSS for style. Include the public packages eda-symbol and eda-style, and the same file draws as a traditional EDA schematic. Switch the look in the example.

    FAQ

    Will simulators complain about a netlist with RNL in it?

    No. RNL is written only in the host netlist’s legal comments, which simulators skip with no preprocessing. Which exact marker is safe in every vendor’s simulator is still being verified.

    Will RNL change my circuit?

    No. Devices, parameters and connections are defined only by the netlist; RNL can only reference them. When only RNL changes, the netlist body is kept as is.

    Do I have to write coordinates?

    No. “M1 and M2 are a differential pair, symmetric about the center line” is a valid description on its own; coordinates can be left to the solver or added later.

    Will different tools draw the same RNL the same way?

    Parts with exact geometry will match. Parts that state only intent may be drawn differently by different solvers while still satisfying that intent; RNL does not promise pixel-identical output.

    How is this different from Virtuoso or KiCad schematic files?

    Those are each tool’s own graphical formats, stored apart from the netlist. RNL is attached to the netlist, any tool that supports it can read it, and symbols are themselves defined in RNL.

    Why does AI come up so often?

    Language models are good at reading and writing text such as netlists. RNL turns the circuit’s structure, intent and drawing into text too, so an agent writes a circuit and its meaning in one file and people review what it declared in a viewer. Free text between statements helps people read, but never changes what machines understand.

    Can RNL be written in other languages?

    Keywords and standard-package names can have aliases in another language. A file can declare individual aliases with @ALIAS in its header record, or load an alias package (a package file collecting the aliases of a language) with @USE-ALIASES(name=…, version=…), or path=… for a custom file. Standard series 0.3 bundles one so far, Chinese (rnl-zh): write @USE-ALIASES(name="rnl-zh", version="0.3") in the header record to use aliases such as #M1 @位于(10, 20). An alias is only an alternate spelling: the two can be mixed freely and machines read the same statements; the header record itself always uses standard spelling.Keywords and standard-package names can have aliases in another language.     Can I use it now?

    For viewing schematics and editing netlist text, yes: the viewers open netlists with RNL in the browser or on Windows, Linux and macOS, draw placed objects, and let you edit the text and re-render. Automatic layout is early: a first solver is in rnl solve and, as a preview, in the desktop viewer. The web viewer does not run it yet, so it lists unplaced objects in its Not drawn view. Drag-and-drop editing is not yet available.
