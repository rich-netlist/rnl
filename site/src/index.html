01 · 是什么01 · What

网表定义电路，RNL 描述怎样理解和呈现它。 The netlist defines the circuit. RNL describes how to understand and present it.

Rich Netlist（RNL）不是一种新的网表格式。它是写在现有网表注释里的一层描述：这些器件构成什么结构，设计者希望怎么摆，图上怎么画。 Rich Netlist (RNL) is not a new netlist format. It is a layer of description written in the comments of existing netlists: which structures the devices form, how the designer wants them placed, and how the drawing should look.

原生网表定义电路；Rich Netlist 描述如何理解和呈现这个电路。语义描述可以独立于几何存在，几何可以逐步细化，但两者都不能重新定义电路。 The native netlist defines the circuit; Rich Netlist describes how to understand and present that circuit. Semantic description can exist without geometry, and geometry can be refined step by step, but neither may redefine the circuit.

藏在注释里Hidden in comments

写在宿主网表的合法注释里，比如 SPICE 的 * @RNL {…}。仿真器把它当普通注释，不需要先剥掉。 Written in the host netlist’s legal comments, such as SPICE’s * @RNL {…}. Simulators treat it as an ordinary comment; nothing has to be stripped first.

不改电路Leaves the circuit alone

只能引用网表里的器件、网络和端子，不能新建器件、连接或参数。图上的线交叉、重叠，都不算连接。 It can only reference the netlist’s devices, nets and terminals; it cannot add devices, connections or parameters. Lines that cross or overlap in the drawing are not connections.

粒度随意Any level of detail

可以只写一句“M1、M2 是差分对”，也可以写到每个坐标和拐点，两种写法能在同一个文件里混用。 Write just “M1 and M2 are a differential pair”, or go down to every coordinate and bend; both styles can be mixed in one file.

RNL 不是RNL is not

  • 又一种网表语言Another netlist language
  • 第二份连接表A second connection list
  • 规定唯一画法的格式A format that prescribes one drawing
  • 像素级的图片存档A pixel-level image archive

原理图和网表各自保存一份连接关系。改了一边，另一边就可能过期；图上看着连着的线，网表里未必连着。 The schematic and the netlist each keep their own copy of the connections. Change one and the other may go stale; a line that looks connected in the drawing may not be connected in the netlist.

用 RNLWith RNL

连接只由网表定义。RNL 只能引用器件和网络，不能增删器件或连接；图上两条线交叉、端点重合，都不会变成连接。画导线时也一样：只有共用同一个点或端子的线才接在一起。 Connectivity is defined only by the netlist. Drawn wires work the same way: they join only where they share a point or a terminal.

06 · 设计原则06 · Principles

语法还在变，这几条原则已经定下。The syntax is still moving; these principles are settled.

它们来自 RNL 原则草案，是后续所有语法讨论的前提。 They come from the RNL principles draft and frame every later syntax discussion.

SPICE
Spectre
仿真器：注释，跳过Simulator: comment, skippedRNL 工具：读取RNL tools: read

住在注释里Lives in comments

RNL 只写在宿主网表的合法注释里。仿真器把它当注释，不需要先剥离；不同网表只是注释前缀不同。 RNL is written only in the host netlist’s legal comments. Simulators treat it as a comment with nothing to strip first; netlist formats differ only in the comment prefix.

电路只有一份真相One source of truth for the circuit

器件、参数、连接只由网表定义。RNL 可以引用它们，不能改写；图上的线交叉或重叠，也不产生连接。 Devices, parameters and connections are defined only by the netlist. RNL can reference them but not rewrite them; lines that cross or overlap in the drawing create no connection.

语义和几何，粒度随意Semantics and geometry at any detail

可以只写“这是差分对”，也可以只写一条对齐约束，或者写到精确坐标；几种粒度能在同一个对象上混写。 Write only “this is a differential pair”, or a single alignment constraint, or exact coordinates; the levels can be mixed on the same object.

描述意图，不规定唯一画法Describe intent, not one drawing

@ORDER("x") 只定轴，不定方向：从左到右、从右到左都满足；要定方向就写 "left-to-right"。满足意图的画法都算对，由求解器按风格挑选。 @ORDER("x") fixes the axis, not the direction: left-to-right and right-to-left both satisfy it; write "left-to-right" to fix it. Any drawing that meets the intent is correct; the solver picks one to suit its style.

冲突按优先级取舍Conflicts resolve by priority

互相冲突的事实先比优先级，同一档里后写的为准；没冲突的部分都保留：x 改成 14，y 还是 20，low 的 x = 6 被丢弃。修改既可以就地改，也可以追加在后面。 Among conflicting facts priority decides first, and within one priority the later statement wins; whatever does not conflict is kept: x becomes 14, y stays 20, and the low x = 6 is dropped. Changes can be made in place or appended.

检查工具：1 个错误Checker: 1 error查看器：照常显示Viewer: displays as usual

出错只影响这一句Errors stay local

写错的语句被忽略，依赖它的语句随之失效，其余照常生效。检查工具报告错误的位置，查看器照常显示。 A malformed statement is ignored, statements that depend on it drop out with it, and the rest take effect. The checker reports where the error is; the viewer displays as usual.

机器只读正式记号：M2 照样会移到 x = 30。 Machines read only the formal notation: M2 still moves to x = 30.

人和模型都读得懂Readable by people and models

正式记号之间可以夹自由文本；照标准例句写，语句读起来就是一句话，没有渲染器也能读。但自由文本没有含义，写 “do not move” 也挡不住后面的 @PLACE。 Free text can sit between the formal tokens; written as a standard sentence, a statement reads as prose, even without a renderer. But free text has no meaning, so writing “do not move” does not stop the @PLACE that follows.

作用域跟着电路层次走Scope follows the circuit hierarchy

写在子电路里的描述只管这个子电路。一个名字在一层里只绑定一次；$ 开头的定义向下继承，下层可以重新定义；% 开头的名字只在本层。规则在写它的这一层和下面每一层各求一次。 A description written in a subcircuit applies only to that subcircuit. A name is bound once per level; definitions starting with $ are inherited downward and can be redefined below; names starting with % stay on their own level. A rule is evaluated on its own level and once on each level below.

另外，RNL 是纯数据：处理时不执行任何代码，也不会因为出现某个类型名就自动联网下载。 Also, RNL is pure data: processing it runs no code, and a type name never triggers a network download.

差分对、镜像对称这些定义，默认符号，补地、补端口的规则，都在标准包里，本身用 RNL 写成；语言只规定怎么写、怎么生效，不认识具体的电路词汇。 Definitions such as the differential pair and the mirrored pair, the default symbols and the rules that add grounds and port tags all live in the standard package, itself written in RNL; the language only says how things are written and take effect, and has no circuit vocabulary of its own.

语句的几种形态Statement shapes

对象 + 关键字Object + keyword

把 M1 放在 (10, 20)。也可以只写一轴，如 @PLACE(x=10)，另一轴留给求解器。 Puts M1 at (10, 20). One axis is fine too, as in @PLACE(x=10); the other is left to the solver.

集合Set

花括号是有序的一组对象：M1、M2 的 y 坐标相同。 Braces hold an ordered group of objects: M1 and M2 share the same y.

角色Roles

括号紧跟对象，说明它填定义的哪个角色；and、are treated 是自由文本。 Parentheses right after an object say which role of the definition it fills; “and” and “are treated” are free text.

命名Naming

给语句产生的对象起名，之后就能引用 %g0，比如给它定位置；写在末尾的 => %g0 也一样。 Names the object the statement makes, so %g0 can be used later, for example to place it; => %g0 at the end does the same.

管道Pipe

前一段的结果交给后一段：先放好位置，再左右镜像。 Each part passes its result to the next: place it first, then mirror it left to right.

记录Record

一段记录，语句用分号分开。记录头作用于里面每一句：author 说明谁写的，priority 是它们默认的优先级；只有 AS 和 ATTACH 例外，它们只随 disabled 一起关掉。 One record, statements separated by semicolons. The header applies to every statement inside: author says who wrote it, priority gives their default priority, except to AS and ATTACH, which follow it only when it is disabled.

五种布局约束Five layout constraints

布局意图最终都落到这几种关系上：前四种作用于 x 或 y 坐标，第五种作用于朝向。只写轴的约束不定方向，写了 "left-to-right" 这样的方向才定先后。 All layout intent comes down to these relations: the first four act on x or y coordinates, the fifth on orientations. A constraint that names only an axis fixes no direction; a direction such as "left-to-right" fixes which comes first.

对齐：y 坐标相同，排成一行。Align: same y, in one row.

顺序：沿 x 严格排开。只写轴，正序倒序都满足；写 "left-to-right" 才定方向。Order: strictly along x. With only the axis, forward and reverse both satisfy it; "left-to-right" fixes the direction.

等距：相邻间距相等，比如让尾管居中。Distribute: equal steps between neighbors, for example to center the tail.

距离：B 在 A 右边至少 3 格；方向写成 "x" 就不分先后。Distance: B at least 3 units right of A; with "x" as the direction, either may come first.

朝向关系：B 的朝向是 A 的左右镜像；两个各朝哪边，由求解器定。Orientation relation: B is A mirrored left to right; which way each one faces is up to the solver.

一层电路是怎样生效的How one level of a circuit takes effect

整层读完以后，按九个固定阶段处理。所以名字可以先用后定义，出错的语句只影响自己；规则生成的对象，比如标准包补上的地，也照样定符号、排位置。 Once a whole level is read, it is processed in nine fixed phases. That is why a name can be used before it is defined and a bad statement affects only itself; objects generated by rules, such as the grounds the standard package adds, still get symbols and positions.

常见问题FAQ

加了 RNL 的网表，仿真器会报错吗？Will simulators complain about a netlist with RNL in it?

不会。RNL 只写在宿主网表的合法注释里，仿真器当普通注释跳过，不需要预处理。具体用哪个标记在各家仿真器里都安全，还在调研和验证。 No. RNL is written only in the host netlist’s legal comments, and simulators skip it like any other comment, with no preprocessing. Which exact marker is safe in every vendor’s simulator is still being researched and verified.

RNL 会改我的电路吗？Will RNL change my circuit?

不会。器件、参数和连接只由网表定义，RNL 只能引用它们。图上的线交叉、重叠，都不会产生连接；只改 RNL 时，网表正文原样保留。 No. Devices, parameters and connections are defined only by the netlist; RNL can only reference them. Lines that cross or overlap in the drawing never create connections, and when only RNL changes, the netlist body is kept as is.

一定要写坐标吗？Do I have to write coordinates?

不用。只写“M1、M2 是差分对，关于中轴对称”也是合法、有用的描述；坐标可以交给求解器，也可以以后逐步补上。 No. “M1 and M2 are a differential pair, symmetric about the center line” on its own is a valid and useful description; coordinates can be left to the solver or added later, bit by bit.

同一份 RNL，不同工具画出来一样吗？Will different tools draw the same RNL the same way?

写了精确几何的部分会一致；只写了意图的部分，不同求解器可以给出不同、但都满足意图的画法。RNL 不承诺像素级一致。 Parts with exact geometry will match. For parts that state only intent, different solvers may produce different drawings that all satisfy it. RNL does not promise pixel-identical output.

和 Virtuoso、KiCad 的原理图文件有什么不同？How is this different from Virtuoso or KiCad schematic files?

那些是各个工具自己的图形格式，和网表分开保存。RNL 附着在网表上，任何支持它的工具都能读；查看器也不自带元件库，符号本身就用 RNL 定义。 Those are each tool’s own graphical formats, stored apart from the netlist. RNL is attached to the netlist, and any tool that supports it can read it; viewers ship no component library either, because symbols are themselves defined in RNL.

为什么常提到 AI？Why does AI come up so often?

大模型擅长读写网表这样的文本。RNL 让“画法”也变成文本，模型能直接写出、局部修改。第一轮试写里，11 个模型照着参考写了 264 次，大多数写出了能用的 RNL。语句之间可以夹自由文本方便人读，但自由文本不改变机器读到的含义。 Language models are good at reading and writing text such as netlists. RNL makes the drawing text too, so a model can write it directly and edit it in place. In the first writing trial, 11 models wrote 264 runs from a reference, and most produced usable RNL. Free text between statements helps people read, but it never changes what machines understand.

可以用中文写 RNL 吗？Can RNL be written in Chinese?

可以。关键字和标准包里的名字都有中文代称，在文件头段记录里写 @USE-ALIASES(name="rnl-zh", version="0.3") 就能用，比如 #M1 @位于(10, 20)。代称只是另一种拼写：中英文写法可以混用，机器读到的完全相同；头段记录本身总按标准写法读。 Yes. Keywords and the names in the standard package have Chinese aliases; write @USE-ALIASES(name="rnl-zh", version="0.3") in the file’s header record and use them, as in #M1 @位于(10, 20). An alias is only another spelling: the two can be mixed, and machines read exactly the same thing; the header record itself is always read in standard spelling.

现在能用吗？Can I use it now?

看图和改文本可以：第一版工具链 0.1 的查看器能在浏览器里或 Windows 上打开带 RNL 的网表，画出写了坐标的部分，也能改文本、应用后重画。自动排版刚起步：求解器有了第一版，rnl solve 和桌面版查看器能用它排出只写了意图、没写坐标的部分，桌面版先作为预览显示。网页版还不能求解，这些部分它画不出来，只在 Not drawn 视图里列出。拖动器件的编辑器还没有。 For looking at drawings and editing the text, yes: the viewers of the first toolkit, 0.1, open a netlist with RNL in the browser or on Windows, draw the parts that have coordinates, and edit the text and draw it again. Laying out has just begun: the solver has a first version, with which rnl solve and the desktop viewer place the parts that give intent without coordinates, the desktop viewer as a preview. The web viewer does not solve yet, so it does not draw those parts and lists them in its Not drawn view. There is no editor for dragging devices yet.
