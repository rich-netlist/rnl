RNL Viewer 0.4.1 saves and opens projects, exports images, and opens the designs of the RNL gallery by their manifests. It goes with RNL core 0.4.1, which hints at subcircuits that no file defines.

## Projects

- **Save Project** (desktop) and **Download Project** (web) save the Library as a project: one ZIP archive with your files and a manifest, `rnl-project.json`, that records how they are set up: the file shown, the order files are searched in, the format chosen for a file, the level shown and Auto Include. Files not referenced by the netlist, changes not yet saved and public packages go in too; the built-in standard packages, which every viewer has, do not. The desktop also copies each PATH folder's files into the project.
- **Open Project** reads a project back, on the desktop or the web: its files become the Library's, and the file it records opens at its level, read in the formats it records. The desktop asks for a folder to put the files in, starting where the archive is, and asks before replacing files there; Save Project then offers to save to the archive it opened. Opening a project does not change PATH, and its formats hold for that window without changing your saved choices.
- **Download Library is replaced** by Download Project, whose archive holds the same files with their set-up.
- **Download Manifest** and **Load Manifest** (web): when every file in the Library came from a web address, Download Manifest saves a small manifest of the files' addresses and checksums with the same set-up, and Load Manifest opens such a file again, fetching the files. A file opened from your computer or changed but not saved cannot be in it; Download Manifest then says to use Download Project.
- The web viewer opens projects of up to 256 MB; open a larger one in the desktop viewer.

## Export Image

- **File › Export Image › Export SVG / Export PNG** saves the whole of the level shown, not just the part in view, drawn by the core. Usages and current directions are drawn when they are shown, each usage in its colour, and left out when they are hidden. The selection, the hover highlight and the grid are not drawn. The background is opaque, and dark when the drawing is shown on the dark background.
- The SVG carries the fonts its texts use, so it shows them as the viewer does wherever it is opened. The PNG is drawn at twice the SVG's size.
- The image is named after the file and the level. The web viewer downloads it; the desktop asks where to save it.

## External manifests (web)

- **`?manifest=ADDRESS`** opens the files that a manifest lists, such as the designs of the [RNL gallery](https://rich-netlist.github.io/rnl/en/gallery.html): every file is fetched and checked against its checksum, with a count while they load. A file that does not match or cannot be fetched stops the opening, and the error names it.
- The files are listed, read only, in a Library group of their own, **From external manifest**. They are searched like the Library's files, for includes, packages and Auto Include, also by other files you open.
- The netlist opens on the level the manifest names, or on `?level=` from the address, inside the netlist with everything it includes. A slim bar above the drawing shows the manifest's title, authors (with links) and source when it gives them, and stays while a file of the manifest is shown.
- Embedded viewers take `?embed=1&manifest=`, and the embedding API's `open` message takes `manifest`.

## Other changes

- **A level named by an embedding page** (`?level=`, or the API's `level` message) is now shown inside the netlist that was opened, with everything it includes, also when the subcircuit is defined in an included file. It used to open that file on its own.
- **Structures in Analog Canvas exports.** A netlist that uses `rnl-std-no-labels`, as every Analog Canvas export does, can now declare structures such as `$MIRRORED` or `$DIFFERENTIAL_PAIR` and draws them; it used to stop with an error. The [core's notes](https://github.com/rich-netlist/rnl/releases/tag/core-v0.4.1) say how this departs on purpose from the text of RNL 0.3.
- **Hints for undefined subcircuits.** The Problems pane now shows a hint for each subcircuit that no file read defines and that is drawn as a box of its terminals, such as one whose include is missing. Subcircuits that a rule or a package gives a symbol, such as PDK devices, are not mentioned.

Windows requires 64-bit Windows 10 or 11 and Microsoft Edge WebView2. The installers download WebView2 when it is missing. Linux requires x86_64, WebKitGTK 4.1 and a glibc version compatible with Ubuntu 22.04 or newer.

The macOS app has an ad-hoc signature only, with no Developer ID and no Apple notarization. If macOS blocks the first start of a download you trust, choose Open Anyway in System Settings › Privacy & Security, or run `xattr -dr com.apple.quarantine "/Applications/RNL Viewer.app"`.

The downloads are not code-signed with a publisher certificate. Windows may display a SmartScreen or unknown-publisher warning. Verify downloads against `SHA256SUMS.txt`, for example with `shasum -a 256` on macOS.
