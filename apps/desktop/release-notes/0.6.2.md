RNL Viewer 0.6.2 carries the core of RNL core 0.6.2, which is released with it. Every viewer now reads a design of many files file by file: the file shown is read alone, in the context of its entry, and what the core reads of each file is kept in memory, so that a file shown again is not read again while it and what it uses are unchanged. The desktop viewer, the web viewer and the local viewer now do the same things the same way, except where a browser cannot. The local viewer is the desktop viewer for computers where the app cannot run, and comes with the public packages beside it.

## Reading the file shown

- **The file shown is read alone, in the context of its entry.** Opening a netlist reads the outline of the whole document (its files, their subcircuits and what each calls, without interpreting the drawing records) and the drawing of the file shown. Entering a subcircuit that another file defines, a pick in the hierarchy or the index, a manifest's level or an include link in the text reads that file, with the rules and packages of the entry, as the whole document gives them. Until now the web viewer opened such a file as an entry of its own and added it to the Library, and the desktop viewer read the whole document.
- **The hierarchy lists the levels of every file** from the outline, the files not read yet among them; opening one reads its file. A name the netlist does not define is one row for all its instances, with their number.
- **Many instances of one subcircuit are one row of the hierarchy**: a level with more than 50 instances of a subcircuit lists them under one row, such as "22572×V1_decap_notap", that opens with a click and lists 200 of them at a time, more as they are scrolled into view. The level shown is always listed, with its row open. A top level of tens of thousands of decoupling cells no longer holds up the viewer when the Hierarchy view is shown, and the hierarchy is not drawn while it is hidden.
- **The path bar** keeps the way through the files of the entry and goes back through it.
- **The netlist pane** shows the text of the file read.
- **Each file's reading is kept in memory** while the window or the page is open, and shown again without reading the file while the file, the files and packages it used, the definitions it calls, the Library and the options that change a reading are unchanged. The loading indicator then says "Using cached drawing…", in every viewer. Reload reads the file again. Nothing is kept on the disk or in the browser's storage; the web viewer deletes what an earlier version kept in the browser.
- **While the viewer is idle, the files below the file shown are read** and kept, one at a time, a subcircuit's file before those its levels call. This only fills free room in the cache: it removes nothing kept, shows nothing, and stops at any input.
- **File › Memory Cache** is one dialog in every viewer:
  - **Keep the readings in memory**, on by default;
  - the limit in memory, 256 MiB by default, 0 to keep nothing;
  - **Preload the files below the file shown while idle**, on by default;
  - how many readings are kept, their size, and the hits and misses;
  - **Clear Cache**, which empties it and leaves the drawing shown as it is.

  The desktop's dialog of cached documents and its preloading switch are gone. A cache limit set in an earlier desktop viewer is not carried over: the limit starts again at 256 MiB.
- **An entry that only includes other files** no longer opens on an empty top level. A card lists the subcircuits that nothing calls, each with its symbol, the file that defines it, its instances, and whether its file's reading is kept ("Kept: opens at once") or how long that reading took the last time; a click opens one. When there is one alone, it opens at once.
- **The problems list** has the problems of the file shown, of the packages it uses and of a reading that failed; before, a subcircuit of an included file listed the entry's problems again under it. For a document of several files:
  - **All Files**, a switch at the right of the problems' heading, adds those of the other files, as their readings gave them or, for a file not read yet, as the outline gives them (an include not found, a subcircuit defined twice), and says how many files were checked;
  - **Edit › Check All Files** (and a button beside the count) reads the files not read yet, one by one in the background, from the readings kept where they hold; the count goes up as each is read.
  - The numbers of the lines in the text are coloured by the problems listed.
- **Projects and manifests** say, for a level written in another file than the entry, which file it is (`file`), so that Open Project and a manifest's level open that file in the context of the entry. A manifest without it means the entry, as before, and opens as before; a viewer that does not know the field opens the level by its name alone.

## Verilog-A

- **The modules of Verilog-A** of the document's Verilog-A files (`ahdl_include`) are in the hierarchy and the index, marked *Verilog-A*, each with the modules its instances name; a name no module has is *not defined*, and a module nothing calls is under *Not called from the top level*.
- **An instance of a module opens it**, as a subcircuit of another file opens. A module has no drawing: the page shows a symbol of its ports, in the order the module writes them, and its instances, each with the module it names and its line. A click shows the line in the text; a double click or Enter opens the module it names. The parameters an instance gives are not passed to the module, and none are shown.
- **The page of a module and the entry page take their colours from the drawing's background** (View › Background), as the drawing does, not from the window's theme: their text is dark on a light background and light on a dark one. Before, a light theme with a dark background wrote them dark on dark.

## Opening files

- **Files chosen or dropped together:** when only one of them is a netlist, it opens at once, in every viewer; otherwise the viewer asks which one. Before, the desktop asked whenever more than one file was dropped. Verilog-A files (`.va`, `.vams`) count as files the netlist uses, as `.inc`, `.lib` and `.rnl` files do, so a netlist with its Verilog-A files opens at once.
- **Every viewer lists the same file suffixes**, those of the core, in its file dialogs, for files dropped and in a folder it includes.

## Library and PATH

- **A folder included lists the same files in every viewer**: those of the folder and of up to 8 levels of folders below it, up to 2000 files from each folder included, of the suffixes the viewer lists, and nothing hidden (a file or folder whose name starts with a dot). Before, the web viewer took every file of a folder chosen or dropped: at any depth, any number, hidden ones too.
- **When a folder has more files than are listed**, the viewer says so for each such folder: "Only the first 2000 files of lib are listed."
- **A folder dropped on the desktop viewer joins the Library**, as Include Folder adds one, with the files dropped beside it; nothing opens. Before, the desktop refused it. A folder dropped on the web viewer joins the Library, as before.
- **The included files the Library lists open.** The grey rows under the file opened in Files, the files the netlist includes that are not in the Library, open with a click, as the include link in the text does; Shift opens a new window. Beside each, **Add to Library** adds the file to the Library's Files, as Include File would; its folder is not added to PATH.
- **Add to Library reads the document again only when the drawing can change**: when the file defines a subcircuit that the netlist calls and did not find, or the document has a file not found. Otherwise the file joins the Library and the drawing stays as it is; before, the viewer said "Parsing netlist…" and "Displaying netlist…" and showed the same drawing again. When it reads again, it says "Reading files…" alone.
- **File › Add Folder to PATH (with Sub-folders)…** adds a folder to PATH with its sub-folders, as the Library's Add PATH with Sub-folders does, in the desktop viewer and the local viewer.
- **File › Include Folder (with Sub-folders)…** is the new name of Include Folder, on every platform: it takes the sub-folders too, as it always did.

## Solving

- **Constraints write their directions as RNL 0.4 does**: the Solve view's list of constraints, the box drawn for one, and `rnl solve`'s report say `ORDER left-to-right`, `DISTRIBUTE top-to-bottom` or `DISTANCE bottom-to-top exact=6`, where they said `ORDER x increasing` and `min=6 max=6`. Either way along an axis is the axis alone, `DISTRIBUTE x`. What is solved does not change.
- **The solve's settings start the same in every viewer**: each net is routed again (`reroute_nets`), as the web viewer already did. A desktop user who never changed this setting now solves with it; Solve › Settings turns it off, and it stays off. `rnl solve` keeps its own default.
- **A solve in the web viewer and the local viewer reads the files as the drawing did**: the Library, PATH and Auto Include. Before, a subcircuit that Auto Include took from the Library was missing from the solve.
- **Solve › Save Solved Copy As… in the web viewer** downloads the solve: a netlist that reads no other file under its name with `-solved`, else a ZIP of the files the solve wrote and the files they read, in their places. The files opened are not changed.
- **In a solve's preview, an instance of a module of Verilog-A opens the module**, as it does outside a preview, and the preview's hierarchy lists the modules. The module opens below the levels of the preview, and the way back leads to the preview. Before, the instance was a block that could not be entered.
- **Export Image of a solve's preview** draws the preview, in the web viewer and the local viewer as in the desktop viewer. Before, it failed with "This document was not loaded in this page".
- What Save Solved Copy says it saved is in the viewer's language on the desktop too.

## Files and windows

- **The desktop viewer tells when a file of the document shown changes on disk**, as the local viewer does: "top.sp changed on disk. F5 reloads the netlist." The viewer's own saves are not told.
- **New Window on the desktop carries the changes applied and not saved**, as a new tab of the web viewer does; it asks first only when a change is not applied yet.
- **A name chosen in a save dialog is never written through a link** on the desktop (Save As, Export Image, Save Project): the viewer asks for another name, as the local viewer did.
- **Save says which files it wrote**, in the viewer's language.
- **The window's title has its dot** (`● top.sp - RNL Viewer`) while files have changes not saved, on a browser's tab too.
- **Help › About** is one box in every viewer, and **Help › Check for Updates** is in every viewer that says its version. It goes online only when it is chosen.
- On macOS, the application menu's Quit RNL Viewer is in the viewer's language.

## The local viewer

The local viewer (`rnl-viewer-local`) is now the desktop viewer for computers where the app cannot run, such as older enterprise Linux. It has the desktop's menus and follows its rules. It differs from the desktop only where a browser cannot do the same: the page draws its menus and dialogs, and its chooser lists the files of the computer the program runs on.

- **It no longer has the web viewer's own features**: Open URL, Load Manifest and Download Manifest; the page addresses with `?url=` or `?manifest=`, and the Viewer API; Include Public Package, the online catalog and the offers to include a missing package; Help › Desktop Viewer; and the files of the computer the browser is on. It uses only the packages beside it.
- **A file dropped on the page is not opened**, since a browser does not tell the page where it is. The page says to use File › Open.
- **Save Project, Export Image, Open Project and Solve › Save Solved Copy As… write on the computer**, as the desktop's do: the chooser asks where, and the viewer asks before it replaces a file. Open Project writes the project's files into the folder chosen. A solved copy of a netlist that reads other files goes into a folder, with those files beside it, and never over a file the solve read. Before, the browser downloaded them.
- **The public packages beside the program** are found by name without a network, listed in the Library's "Public packages (bundled)" and named in Help › Public Packages, as on the desktop. A package not found is hinted at as on the desktop.
- **PATH is searched as the desktop searches it**: folder by folder, a bare include in each folder itself, not in its version folders. The local viewer has PATH: Add PATH and Add PATH with Sub-folders in the Library, and the File menu's item above. The program lists only the folders the settings have as PATH, and their sub-folders only when they were added with them; it follows no link out of a folder.
- **Its settings file is kept as the desktop keeps its own**: two programs that keep the same file no longer lose each other's settings.
- **The format chosen for a file is kept** for the next start, and a project saved with PATH holds the files of its PATH folders.

## Translations

- The new texts of this release are in all seven languages.
- In Spanish, the access key of File › Memory Cache is *h* (`Cac&hé de memoria...`), as in English, where it was the *e* of Load Manifest on the web.
- In Chinese and Japanese, what Save Solved Copy says ends with "。".

## Known trade-offs

- The trade-offs of Viewer 0.6.1 still hold.
- The first reading of the largest file of a design is not much faster than before: a file is read with the records of the subcircuits it depends on, and its own levels whole. Shown again, it comes from the readings kept.
- A module of Verilog-A is shown without the parameters of the instance that opened it.
- The web viewer has no PATH, cannot save a file to a place of the user's choice, and is not told when a file changes on disk: a browser does not allow them.
- The local viewer has no Exit and no file associations: closing its browser window stops it, as does Ctrl-C where it was started.
- A level of many instances whose pins the standard package's fill gives stubs still reads in a time that grows faster than the level; the core 0.6.2 notes say more.

## Downloads for older enterprise Linux

- **Every Viewer release now has the local viewer among its downloads**, with the version of the release: one static program, for CentOS 7, RHEL 8 and 9 and any Linux x86_64 of kernel 3.2 or newer, that serves the viewer on the computer and shows it in a browser. It was released on its own before, as local viewer 0.1.0; Viewer 0.6.0 had its packages added after the release.
- It comes three ways: alone; with the public packages beside it; and with the public packages and Firefox ESR beside it, for a computer whose browser is too old.
