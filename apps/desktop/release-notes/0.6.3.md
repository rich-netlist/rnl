RNL Viewer 0.6.3 carries the core of RNL core 0.6.3, which is released with it. Opening a design of many files is much faster in every viewer: the core reads each file faster, the viewer reads nothing twice and copies nothing it keeps, and the drawing of the file shown comes before the links of its text and its problems. A file of RNL 0.2 or 0.3 now says which viewer reads it. This release also fixes what a review of these changes found.

## Opening a large design

- **Opening is much faster.** In a large design whose entry only includes other files, with its largest level written in a file of its own, the web viewer and the local viewer measured:
  - opening the entry, up to the drawing of the largest level: about 71% less time (5.1 s → 1.5 s);
  - opening the largest level's file directly: about 56% less time (2.6 s → 1.1 s);
  - showing that level again, from the readings kept: about 0.3 s → 0.2 s.

  These are measured against the code of 24 November, between Viewer 0.6.2 and this release, on the same computer. The desktop viewer was not timed in its window; the same steps, timed apart, give about 3.1 s → 1.1 s for the entry and 1.4 s → 0.85 s for the file.
- **The drawing comes first.** The file shown is drawn from a smaller first answer of the core, without the texts of its files, the links of its text and the geometry hints. The links of the text and the problems list come right after, while the viewer still says it is busy. The problems list is made once, when they are in.
- **Nothing is read twice.** The outline of a document and the reading of the file shown share what the core read of the files. The file shown is read once, with the packages it uses. A document's outline and readings stay kept when its entry joins the Library by being opened, so entering a subcircuit of another file no longer makes the outline again. The web viewer and the local viewer give each reading the files the readings of the same entry were asked for. Readings are kept and given again without being copied.
- **An entry that only includes the one circuit to show opens it without reading the entry first.** When the entry's own file holds nothing but its header record and its includes, and one subcircuit, written in another file, is called by nothing, that subcircuit's file is read in place of the entry's, and the entry page is not shown on the way. The level, the path and the hierarchy are those the entry page gave. An entry with something to draw, a record besides its header, or another root, is read and shown first, as before. An entry of RNL 0.2 or 0.3 stays, with the notice below.
- **The entry page reads the symbols of its subcircuits only when it stays.** An entry page left at once for its one root no longer reads them; one left shown because another open took over reads them then.

## Files of RNL 0.2 and 0.3

- **A level written in a file of RNL 0.2 or 0.3 says so**, in place of the drawing: "Unsupported old file format (RNL 0.3)", with the viewer that reads it. Before, it said that nothing on the level had a position yet, with a link to solve it. Nothing offers to solve such a level: Solve and Respace are not enabled there, and F9 does nothing. Solve All Circuits stays, since the other files of the document may be of RNL 0.4. A level of a file of RNL 0.4 in the same document draws as before.
- **Where the old viewer is depends on the viewer:**
  - the web viewer links to the web viewer of the 0.5 series, which the site keeps, on the same circuit: the same `?url=` or `?manifest=` when the entry is of an earlier version, else the address of the file itself. A file from this computer cannot be passed by a link: the link opens the old viewer alone, in a new tab, and the notice says to open the file there with File › Open;
  - the desktop viewer opens the release page of RNL Viewer 0.5.3, in the system's browser, to download it;
  - the local viewer gives both: that release page, and the old web viewer, where the file is opened with File › Open.
- **An embedded canvas** shows the notice in place of the error, with the full old viewer in a new tab, and still answers its page with the error. It does so only when the old viewer reads every file refused: a file of RNL 0.3 that includes a file of a later version shows the error, as other errors do.

## The problems list

- **When the checks of the file shown could not be made**, the problems list says "The geometry checks of this file could not be made. Open it again to check it." where it would have said "No errors, warnings or hints." This happens when the geometry hints could not be had after the drawing was shown: when the open was taken over and its reading stopped, or, on the desktop, when the file was saved between the drawing and the hints. The problems of the reading are still listed. The file is not counted among those checked, and Check All Files is not offered for it; opened again, it is read whole and checked.

## Other fixes

- **Save Solved Copy As… no longer saves an include removed from the file**, in the web viewer and the local viewer. After an include was removed and the file opened again, the solve still read the removed file, and Save Solved Copy As… gave a ZIP of it with the file where it should give the one solved file. Export Image and the drawings of objects without a position read the same files as the drawing.
- **The desktop viewer's netlist pane shows the text the drawing was read from.** The text of the file shown came from the disk after the drawing; a file saved in between showed its new text with the objects of the old one, a line off. The web viewer and the local viewer always showed the text they read.
- **The spans of a file read again are not put into a reading of another state of it.** When the core no longer held the rest of a reading, the viewer read the file again and took its links and hints; on the desktop, a file saved in between gave them for other objects. They are now taken only when the file is as it was; otherwise the reading is shown without them, as above.

## Translations

- The new texts of this release are in all seven languages.

## Known trade-offs

- The trade-offs of Viewer 0.6.2 still hold, but for the time to read the largest file of a design, which this release cuts.
- The first reading of the largest file of a large design still takes about a second: the file is read once, whole, with the records of the subcircuits it depends on.
- A file of the document saved after it was read and before it was shown is not told as changed on disk when the viewer looks at that file for the first time; File › Reload shows it as saved.
- A file of RNL 0.2 or 0.3 is not read by this viewer: the old viewer reads it.

Windows requires 64-bit Windows 10 or 11 and Microsoft Edge WebView2. The installers download WebView2 when it is missing. Linux requires x86_64, WebKitGTK 4.1 and a glibc version compatible with Ubuntu 22.04 or newer; the local viewer needs neither, only a browser.

The macOS app has an ad-hoc signature only, with no Developer ID and no Apple notarization. If macOS blocks the first start of a download you trust, choose Open Anyway in System Settings › Privacy & Security, or run `xattr -dr com.apple.quarantine "/Applications/RNL Viewer.app"`.

The downloads are not code-signed with a publisher certificate. Windows may display a SmartScreen or unknown-publisher warning. Verify downloads against `SHA256SUMS.txt`, for example with `shasum -a 256` on macOS.
