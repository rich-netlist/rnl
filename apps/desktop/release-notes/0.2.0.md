RNL Viewer 0.2.0 adds usage inspection, configurable Netlist colors and complete Library downloads. The desktop and [web viewer](https://rich-netlist.github.io/rnl/viewer/) share the changes below unless a platform is named. Viewer and core versions are independent; this release keeps the core version at 0.2.0.

## Usage inspection and schematic overlays

- **New Usage side panel.** It lists only usages in the displayed circuit, grouped and sorted by type, with expandable counts and individual visibility checkboxes. Selecting a usage shows its original statement, roles and editable Color. Each type has a visibility switch for all its usages.
- **Show Usages in View, with Ctrl+R.** The global switch starts enabled. Usages that produce drawing objects themselves or through their contents start hidden; purely semantic usages start visible. Selecting a usage in the panel temporarily displays and selects it even when its visibility switches are off. Selecting another object or clearing the selection removes that temporary display.
- **Interactive overlays.** Rounded, dotted frames enclose each usage's visible roles and use its Color with a 20% fill. Clicking a visible frame selects the usage and highlights its definition in Netlist. Selection doubles the frame width, raises its fill to 40%, shows role names at their centers and adjusts other objects' colors toward the background. Frame widths, titles and role text retain their screen size while zooming. Unselected titles appear only when they fit inside the frame; selected titles always appear.
- **Visibility follows the usage.** Hidden usages cannot be selected through a hidden frame. Their virtual symbols retain ordinary component selection. Role bounds refer to their actual local objects rather than every repeated GND or VDD symbol.
- **Updated panel keys:** 1 Library, 2 Netlist, 3 Hierarchy, 4 Symbol, 5 Usage, 6 Not drawn, and 7 Solve on the desktop. Number keys also open a hidden side panel.

## Netlist colors and label highlights

- **View > Color Scheme** configures component and net names, RNL backgrounds and keywords, `$` and `%` objects, strings, parameters and roles, free text, other text, the Netlist background and the selection highlight. Each row has a hex input and color picker. Changes preview immediately; Save persists them and Cancel restores the previous palette. Restore Defaults is beside Cancel.
- **New default palette.** RNL uses a pale green background, components use blue, nets dark red, `$` objects green and `%` objects purple. Strings and free text remain distinct from the orange selection color. Selected Netlist names also have an underline.
- **Net-label highlight fixes.** Wire-label text in the schematic now changes color on selection even when display IDs repeat, consistently across the native and WebAssembly cores.

## Web packages, editing and downloads

- **Background public-package discovery.** Explicit `USE-PACKAGE` references that cannot be resolved locally trigger a public-catalog lookup whether Auto Include is on or off. A single prompt offers the matching packages for inclusion in Library. The lookup runs in the background and times out after ten seconds; it does not block normal viewing or editing. Missing symbols and subcircuits alone do not trigger package searches.
- **Download before Apply keeps the edit.** Downloading newly typed text, including a new `USE-PACKAGE`, no longer lets the next Apply or Library rebuild revert it to the original File or URL. Native saves continue to update their disk baseline. Text typed while an earlier save is pending remains unsaved.
- **Download File replaces Save on the web**, retaining Ctrl+S and downloading the current editor text.
- **New Download Library on the web** exports `rnl-library.zip`. It includes unused Library files, included public packages, every built-in standard package and version under `standard-packages/`, available companion files and the temporary clipboard source. It preserves directory structure and original bytes for unedited local files, includes pending and applied edits, and handles file/directory name collisions. Exporting does not Apply or clear the unsaved state. Supported browsers offer a destination picker; other browsers use their download settings. Canceling the picker exports nothing, and unreadable files are reported instead of silently omitted.

## Linux startup verification

The blank Linux smoke-test images seen for 0.1.3 and 0.1.4 were reproduced during the startup
handoff: a populated DOM did not yet mean that the sidebar and schematic had been painted.
Delayed WebKit snapshots and independent X11 captures of ordinary launches show complete content,
including the current unbundled release executable, AppImage and deb on Ubuntu 22.04.
No rendering workaround is needed for this startup capture race. This does not establish how every
Linux graphics driver behaves.

Native smoke tests now wait for the startup/loading overlays to clear and require actual text and
schematic pixels. Linux checks both the X11 framebuffer and WebKit snapshot; Windows checks the
WebView2 screenshot. A manual-only diagnostic mode retains timed captures, DOM/styles and renderer
environment comparisons without publishing a release.

Windows requires 64-bit Windows 10 or 11 and Microsoft Edge WebView2. The installers download WebView2 when it is missing. Linux requires x86_64, WebKitGTK 4.1 and a glibc version compatible with Ubuntu 22.04 or newer. For macOS, build from [source](https://github.com/rich-netlist/rnl/tree/viewer-v0.2.0/apps/desktop).

The downloads are not code-signed. Windows may display a SmartScreen or unknown-publisher warning. Verify downloads against `SHA256SUMS.txt`.
