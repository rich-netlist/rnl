RNL Viewer 0.6.0 reads the language RNL 0.4 and carries the core of RNL core 0.6.0, which is released with it. The web viewer now solves in the browser, as the desktop viewer does. The Solve view lists the constraints and the groups the solver takes in. Usages that frame the same devices can be drawn as one frame. A netlist opened with components not drawn asks whether to solve them. In Edit Text, Enter continues a comment and Tab indents. Projects are written only within the folder that was chosen. The desktop viewer is built from the same source as the web viewer, which has all of this as well, except where a section says otherwise.

## RNL 0.4, and what to do with files of 0.3

- **The viewers read RNL 0.4 alone.** The core 0.6.0 that they carry reads files that declare `@VERSION("0.4")`, with the standard packages of the series 0.4: `rnl-std-all` in the place of `rnl-std`, `rnl-std-core` and `rnl-std-full`; `rnl-std-semantics` in the place of `rnl-std-structures`; and `alias-zh` in the place of `rnl-zh`. The Library and Help › Public Packages list the packages of 0.4.
- **A file of RNL 0.3 or 0.2 is not drawn by this viewer.** There are two ways to go on:
  - open it in the **frozen viewer for files of 0.3**, <https://rich-netlist.github.io/rnl/viewer-0.3/>, which is the web viewer of Viewer 0.5.3, kept on the site as it was, with a banner that links back to the current viewer; or keep RNL Viewer 0.5.3 installed for it;
  - convert it with **`rnl upgrade`** of **RNL core 0.5.7**, the last core that reads 0.2 and 0.3, and open the converted file here. `rnl upgrade --approximate` also converts what has no exact equivalent in 0.4.
- **A transistor whose model card is not found is drawn.** In 0.4 such an instance is drawn with the default block symbol, a box of its terminals (9.2.6). So it is no longer listed in **Not drawn**, which now lists only the objects that have no position.
- In 0.4 a pin is an object of its own. A stub that `rnl-std-fill` puts on a terminal names the pin, so it is listed among the usages of the pin and not among those of the instance.
- 0.4's constraints have their boxes in the Solve view (below): the direction of a DISTRIBUTE, lists of orientations such as `[MY, R0]`, PIN-ORIENT, PIN-ORIENT-RELATION and TABLE, with their titles, the badges of their cells and pins, and their objects lit.
- A problem can be a **violation**, the fourth kind of problem, between the error and the warning: a statement about the circuit that does not hold, while nothing fails. The Problems list, its counts and the line numbers of the text show it in purple.

## Solving, on the desktop and on the web

- **A netlist opened with components not drawn asks whether to solve them.** When a file or a project is opened and its circuits have components with no position, the ones the Not drawn list shows, *Solve the Netlist?* says how many. **Solve**, the default, solves as Solve › Solve does, or as Solve All Circuits when they are in other circuits than the one shown, with your solver settings, as a preview: the files are not changed. **Not now** is remembered for that file until the viewer is closed. It asks only when a file is opened, not when it is read again or an edit is applied, and only where a solver is: not in an embedded drawing, nor for a netlist with errors. **Solve › Ask to Solve on Open** turns it off.
- **The web viewer solves in the browser.** The solver runs as WebAssembly in a Worker of its own, fetched on the first solve (7 MB, 2 MB compressed). **Solve** (F9), **Solve All Circuits**, the progress panel, Cancel and the Solve view's report work as on the desktop.
- **A progress panel** over the drawing shows the circuit being solved and its place among those to solve, the stage, the share of the time limit and the time, the candidates tried and the better ones found, and how each circuit ended. F9 solves the circuit shown. **Solve › Solve All Circuits** solves every circuit.
- **Solve › Settings** is drawn from the solver's own table of settings: each control follows its setting's type, the bounds are checked in the dialog, and a refused value is shown at its field. The dialog shows only the settings, objectives and tiers of the chosen layout, and sends only those. A line under the fields counts what is hidden, and **Show** shows it greyed. The lines layout's two weights are two boxes, and its ranking is a setting of the dialog. **Time for the whole file** (`--timeall`) is beside them. The dialog lists what the netlist and its packages set, and says that a value set here wins.
- **Solve › Respace** and **Respace All Circuits** draw each circuit where the solver's record in the file last put its objects, route the wires again and widen the gaps to the settings' spacing, without a search. A circuit with no fitting record is left as it is, and the report gives the reason.
- **A solve's preview can be edited.** **Edit Text** edits the files as they are written. Applying asks *Solve the netlist again with these changes?*: **Yes** (Enter) solves again, **No** applies and closes the preview. Until then the old preview stays, marked as not having the edits.
- **File › Export Image** writes the preview while a solve is shown, where it used to write an empty image. (Desktop: the web viewer does not export a solve's preview yet.)
- A read-only file, such as a file of a manifest or a built-in package, can be solved. The drawing is fitted to the window after a solve and after Close Preview.

## Edit Text

- **Enter in a comment continues it.** On a comment line, after its marker (`*` in SPICE, `//` or `*` in Spectre), Enter begins the next line with the same marker and the same space after it, so `*   ` in an `@RNL { … }` record goes on as `*   `. Before the marker, on a line that is no comment, or with Shift, it is a plain Enter.
- **Tab indents instead of moving the focus.** Tab puts in two spaces, and indents each line of a selection over several lines; Shift+Tab takes up to two out. A comment's indent is the space after its marker. **Esc, then Tab** moves the focus out of the text, as Help › Keyboard Shortcuts says. Undo takes back what these keys do.

## The Solve view

- **Constraints** lists, level by level, every fact the solver takes in: its rank, what it says, its priority, the structure it comes from and a button for its line, with a filter. After a solve each row has a mark: ✓ kept and holds on the drawing, a red ✗ kept but does not hold, `!` set aside or failed, `?` undecided.
- **A clicked constraint is boxed in the drawing**: a dashed box around the objects it acts on, its kind and parameters as the title, and the objects numbered in the order the constraint lists them; a pin is numbered where the core puts the pin. The other frames are dimmed meanwhile. The box is not in an exported image.
- **Groups** lists the groups as the tree the solver takes them in, with a check to show or hide each frame, and the groups that are not in the tree with the core's reason. The groups are listed only here now, and **Group frames** (off to begin with) draws their frames; View › Show Usages draws only the usages.
- **Solve › Show Layout Table**, **Show Component and Pin Skeleton Lines** and **Show Wire Skeleton Lines** draw thin reference lines of the layout over the drawing. They are not in an exported image.

## Usages

- **Selecting a usage dims the others** and shows only its own title. Selecting a device keeps the usages it is in, as its table of usages lists them, and dims the rest, and pointing at a row of that table does the same. What is selected is drawn on top. The title of a selected usage has a button that hides it; the switch in the Usage panel shows it again.
- **Hide duplicate usages**, in the Usage panel, draws one frame for the usages that frame the same objects: the last written, or the outermost one that the others are made inside. The others keep their rows, marked *duplicate of …*, and selecting one still draws it. It takes the place of Hide nested usages, and keeps that setting. Two usages of one instance at different named points are not duplicates of each other, so both are drawn.

## The drawing and the View menu

- **With no settings kept, only View › Show Names on Hover is on.** The usages and the grid, which were on, are off to begin with. Settings that are kept are read as before.
- **View › Show Flylines** (L), off to begin with, shows the flylines, which are named on hover and selected like a wire. **View › Show Net Names** (N), off to begin with, writes each net's name at its places. An exported image follows both choices.
- **View › Show Registration Points**, off to begin with, marks where each object is placed. It is not in an exported image.

## The Problems list

- **A problem is one line**, as in an IDE: its kind, its code (RNL and four digits), its short name and line:column. Its message opens under it. A click on a row shows the line in the text and opens the row, and another click closes it. The file name is given when the problem is in another file than the one shown.
- The core's **geometry hints** are rows of the same list, each with its own kind and a small *geo* tag. The heading's counts are switches that show only that kind.

## Projects, saving and files

- **Open Project and Save Project write only within the archive and the folder chosen**: never through a link or a junction, and never to a name that climbs out of the folder, is absolute, or names a drive or a stream. The project archive and the image of **File › Export Image** are written whole, so a failed write leaves the old file as it was. (Desktop.)
- **Save and Save As replace a file whole**: a new file with the same owner, group and mode is written, flushed and renamed over it, so a full disk or a crash no longer leaves a netlist empty or cut off. Where a rename would change the file (a hard link, a file of another user, extended attributes or an ACL, a folder that cannot be written, a file held open on Windows), the file is written in place without being emptied first, and its old bytes are put back on any failure. On macOS a file with an ACL keeps it. (Desktop.)
- **A project keeps the bytes that were not edited.** An unedited file of the Library is archived as its own bytes. An edit keeps each line's end, and an edited file is written in the encoding the file has on disk. A project with `%` in a file name opens again after it is saved.
- **Read only limits saving, not editing.** Edit Text and Apply work on a file of a manifest or a built-in package. Save never writes over such a file: the web viewer downloads it, and the desktop viewer saves it as another file and opens that one.
- A server's solve (the web viewer's development server) reads each file in the format the page chose, so a Spectre file named `.sp` is not solved as SPICE. The server reads nothing outside the solve's own folder.
- A manifest's source address is a link only when it is an `https` address.

## Desktop only

- File › Open Project, Save Project and Export Image work again: they failed with "write_bytes needs a path", Export Image always offered `drawing.svg`, and Export PNG could not draw its image.

## Embedded viewer

- **Every display setting can be given** by the address, by a `postMessage` of `{ rnl: 1, type: "display", values: {...} }`, or by the manifest, without reading or writing the browser's storage. Names on hover are on to begin with, and the others are off unless they are turned on.
- An embedded drawing starts without the directions of the currents. A page that showed them must write `currents=1` or send the message.
- The `loaded` message gives `violations` beside `errors` and `warnings`. A netlist with violations still opens.

### Known trade-offs

- **This viewer does not read RNL 0.3 or 0.2.** Such a file is for the frozen viewer at `viewer-0.3/`, for Viewer 0.5.3, or for `rnl upgrade` of core 0.5.7 first (above).
- **The web viewer's solve does without what only the desktop has**: there is no Save Solved Copy, and no Auto Include or search for a named `.inc`, so a netlist that needs them is solved in the desktop viewer.
- **Respace only widens.** A wider drawing needs the file respaced again, and the spacing is that of the settings, not a `SOLVER-CONFIG` of the file. A respace record fits only the file whose name it gives.
- **Editing a solve's preview:** a line of the report does not show a line in the text boxes while they are open, since the report's lines are in the solved files. The edits are not in the drawing until Yes is chosen.
- The descriptions of the solver's settings are shown as the solver writes them, in English.
- A constraint whose objects are on another level, or have no position, has no box in the drawing.
- The CLI's in-place solve (`rnl solve`, writing back) is not changed by the safety of the projects above.

Windows requires 64-bit Windows 10 or 11 and Microsoft Edge WebView2. The installers download WebView2 when it is missing. Linux requires x86_64, WebKitGTK 4.1 and a glibc version compatible with Ubuntu 22.04 or newer.

The macOS app has an ad-hoc signature only, with no Developer ID and no Apple notarization. If macOS blocks the first start of a download you trust, choose Open Anyway in System Settings › Privacy & Security, or run `xattr -dr com.apple.quarantine "/Applications/RNL Viewer.app"`.

The downloads are not code-signed with a publisher certificate. Windows may display a SmartScreen or unknown-publisher warning. Verify downloads against `SHA256SUMS.txt`, for example with `shasum -a 256` on macOS.
