The third release of RNL Viewer, the desktop viewer of Rich Netlist (RNL), and the first for Linux. Since 0.1.1 it keeps a library of the files it searches for packages and includes, draws hairlines that stay thin at every zoom, offers a dark background, zooms to a rectangle dragged with the right button and pans with the arrow keys, and frames a selected symbol by its box, which in the standard symbols now passes through their pins. The web viewer, https://rich-netlist.github.io/rnl/viewer/, shares the page and gets what is not marked as the desktop's.

## What is new since 0.1.1

- **Runs on Linux** (x86_64), as an AppImage, which runs without installing, and as a deb package for Debian and Ubuntu. Both are built and tested on Ubuntu 22.04, the oldest Ubuntu supported; newer ones work too, and other distributions need a compatible glibc and WebKitGTK 4.1.
- **Keeps a library of files it searches.** The side panel's first tab, Library, lists in the order they are searched the files that a `@USE-PACKAGE` without a path and an include written as a bare file name can find: the files you opened or included, each directory of the search path with the packages found in it (the desktop only), and the packages built into the viewer. File › Include File and Include Folder add files without opening them, and a file you open is added too; Exclude takes one out again. Text pasted from the clipboard gets one temporary row, which is not searched, so that you can switch back to it; the next paste replaces it. The file open is highlighted wherever it is listed, and the groups other than your files start collapsed. In the web viewer, Include Public Package adds a package published with the site, such as the SkyWater SKY130 symbols.
- **Finds packages by name** in the directories of the search path, as RNL 0.3 asks (16.2): first a file named after the package, then one in a folder named after its version, then any `.rnl` file whose `@PACKAGE` header has the name and version. An include that names only a file, and is not found beside the file that includes it, is looked for in the library and then in the search path. The search path is edited in the Library tab: add a directory, move it up or down, remove it (the desktop only).
- **Keeps its settings in a file** (the desktop only): the search path, the solver's settings, the grid, the background, the names shown on hover and the side panel's layout are saved in `settings.json` in the app's configuration folder, such as `%APPDATA%` on Windows and `~/.config` on Linux, and settings an earlier version kept in the window's storage are moved there when it starts.
- **Draws hairlines.** A line of width 0, which is the default, is now 1.2 pixels wide at every zoom, as RNL 0.3 asks (9.3); a line given a width in the drawing's units still grows and shrinks with the view. Exported SVG files keep the hairlines thin too.
- **Has a dark background.** View › Background › Dark darkens the drawing's background and shows each colour whose lightness is below 25%, such as black, with its lightness reversed and its hue kept, so black becomes white and dark blue light blue; other colours stay as they are. Only the display changes: the file and the exported SVG keep their colours. The choice is remembered.
- **Zooms to a rectangle and pans with the keys.** Drag with the right mouse button to draw a rectangle, and the view zooms to fit it; a short drag does nothing and Escape cancels. The arrow keys move the view by a tenth of its size, or three tenths with Shift, unless a text box, the editor, a list or a menu has the focus.
- **Frames a selected symbol by its box.** The frame of a selected instance is the symbol's box exactly, not a few units larger, and the button that opens a subcircuit keeps the same small gap from its corner at every zoom. The standard symbols of RNL 0.3, the Analog Canvas extensions and the SKY130 symbols have their boxes revised so that each side that has pins passes through the outermost of them; the sides without pins are as before. The solver places symbols by those boxes, so it now puts them closer, pin to pin. A solver record written against the earlier 0.3 boxes is reported as not matching its input until it is solved again; the positions in it are still drawn.
- **Draws Analog Canvas's round controlled sources.** The Analog Canvas extensions add `$CANVAS_VCVS_CIRCLE`, `$CANVAS_VCCS_CIRCLE`, `$CANVAS_CCVS_CIRCLE` and `$CANVAS_CCCS_CIRCLE`, the circle-shaped controlled sources of Analog Canvas, beside the standard diamond-shaped ones.
- **Reads RNL 0.3 more completely**, after an audit of the toolkit against revision 2 of the standard. A record head that writes a field twice keeps its other fields instead of being dropped; symbols drawn inside symbols keep their order and their text at any depth; pins whose names differ only in case are told apart where the netlist's language tells them apart; an included file that declares a supported version is read even when the file that includes it is not; the regions of a netlist that its simulator does not read as a netlist, such as scripts and embedded Verilog, are left alone; and more advisory checks are reported.
- **Saves each file in its own encoding.** Saving keeps a file's UTF-8 (with or without a byte-order mark) or Latin-1 encoding; a change that the encoding cannot hold is refused with a message that offers to convert the file to UTF-8, and no file is written until all of them can be.

## Requirements

Windows 10 or 11, 64-bit, with the Microsoft Edge WebView2 runtime, which Windows 11 and an up-to-date Windows 10 have. When it is missing, the installers download it from Microsoft and install it, which needs a connection to the internet; for the single file, install it from https://developer.microsoft.com/microsoft-edge/webview2/.

Linux on x86_64 with glibc as recent as Ubuntu 22.04's and WebKitGTK 4.1. The deb brings what it needs through apt; the AppImage bundles most of it but cannot make an older glibc work.

For macOS, build the viewer from the source: see [`apps/desktop`](https://github.com/rich-netlist/rnl/tree/viewer-v0.1.2/apps/desktop).

## Not signed

The files are not code-signed, so Windows may warn before running one: SmartScreen's "Windows protected your PC", where More info > Run anyway runs it, or an unknown publisher when the MSI asks for administrator rights. Check a file against `SHA256SUMS.txt` before you run it.
