RNL Viewer 0.5.3 asks which definition to enter when Auto Include found several, and shows the parameters of a subcircuit, with the values its instance gives and a dialog to change them. It is built from the same source as the web viewer, which has these as well, and carries the core of RNL core 0.5.5, which is released with it: the parameters in the Document that these changes read are that release's.

## Choosing among the definitions

- **An instance of a subcircuit that the Library defines more than once asks which to open.** Auto Include still includes none of the definitions, so the instance used to be a dead end. Entering it now, by E or Enter, a double click in the drawing or the text, **Edit › Open Subcircuit**, or the open badge, opens one dialog in the middle of the window, titled *Choose a definition of X*, that lists each definition as `file:line`. The arrow keys and Enter choose, Escape cancels, and Shift sends the choice to a new window. Selecting such an instance says in the status line that it has several definitions and that entering asks which.
- The one chosen opens as a view of its own file, at its subcircuit, as a subcircuit defined in an included file does, **with the parameters of the instance** (below). The netlist shown is not changed, and the choice is not remembered, so entering asks again.
- The warning in Problems now reads "subcircuit X is defined 2 times in the Library (/a.inc:1, /b.inc:1); enter the instance to choose one, or add an explicit include".
- Going into another file no longer leaves the status line of the instance selected in the file before.

## Parameters

- **A bar of the parameters.** A subcircuit that has parameters shows them in a row under the path: `name = value` for each, and where the value comes from: *from X1* (the instance it was entered through), *default*, *changed*, or `?` and *not set* when there is none. A value that cannot be evaluated stays as written, with a question mark. More than four parameters, or a row that wraps, fold into a summary, "11 parameters: 2 from X4, 9 default", which **Show all** unfolds. The drawing is unchanged: `${w}` stays as written, and the values are shown only in the bar and the dialog. The embedded viewer has no bar.
- **A dialog changes them.** **Edit Parameters...** on the bar, or **Edit › Subcircuit Parameters...**, opens a dialog with a field for each parameter, its default and where its value comes from. **Apply** builds the Document again with the values bound to the subcircuit; the level, the view and the selection stay. An empty field is the default, and *Restore the values of X1* puts the instance's back. The netlist is not changed.
- **A subcircuit shown by itself asks for the values it lacks.** Opened from the index or as a file of its own, a subcircuit with a parameter that has no default and no value asks for it before it is looked at, once for each document. One whose parameters all have values opens with its defaults, and the bar says so.
- **Entering a subcircuit of another file takes the values of its instance.** The view of a subcircuit defined in a Library or an included file is built with the parameters the instance writes: a plain number as written, an expression as the number it comes to where the instance is. The bar shows them as the instance's.
- The new texts are translated in every language of the interface.

### Known trade-offs

- **The values belong to the build that made them.** Changing the parameters builds the document again with the values bound, and only that build shows them: Apply Changes, Reload and Solve show the instance's values again.
- A value written in the dialog that the core cannot evaluate is not refused: it is shown as written, with a question mark.
- A name the instance writes that is not a parameter of the subcircuit in another file is ignored with the core's warning, which is in the Problems of that view.

Windows requires 64-bit Windows 10 or 11 and Microsoft Edge WebView2. The installers download WebView2 when it is missing. Linux requires x86_64, WebKitGTK 4.1 and a glibc version compatible with Ubuntu 22.04 or newer.

The macOS app has an ad-hoc signature only, with no Developer ID and no Apple notarization. If macOS blocks the first start of a download you trust, choose Open Anyway in System Settings › Privacy & Security, or run `xattr -dr com.apple.quarantine "/Applications/RNL Viewer.app"`.

The downloads are not code-signed with a publisher certificate. Windows may display a SmartScreen or unknown-publisher warning. Verify downloads against `SHA256SUMS.txt`, for example with `shasum -a 256` on macOS.
