## 4 구문

### 4.1 문법

레코드의 문법은 EBNF로 주어진다. 각 생성 규칙은 `name = expression ;`으로 쓰며, `|`는 대안을 구분하고, `[ … ]`는 선택 사항이며, `{ … }`는 0회 이상 반복, `( … )`는 그룹화, 큰따옴표 안의 텍스트는 리터럴 문자, `(* … *)`는 주석이다.

```ebnf
record         = "@RNL" [ parameters ] set ;          (* the bracket touches "@RNL" *)
set            = "{" [ member ] { ";" [ member ] } "}" ;
member         = [ front-naming ] segment { naming } { "=>" segment { naming } } ;
front-naming   = ( "%" rnl-name | "$" rnl-name ) "=" ;
naming         = "=>" ( "%" rnl-name | "$" rnl-name ) ;
segment        = argument { argument } [ call { argument } ]
               | call { argument } ;
call           = keyword [ parameters ] ;          (* the bracket touches the keyword *)
keyword        = "@" keyword-name ;                (* upper case, or a declared alias *)
argument       = object [ "(" role-label ")" ] ;   (* the bracket touches the object *)
object         = reference | placeholder | point | set ;
reference      = "#" [ host-name [ subscript ] ] path
               | "&" host-name [ subscript ] path
               | "%" rnl-name [ places ] path
               | "%#" integer path                (* a number, in a record of the solver, 5.9 *)
               | "$" rnl-name [ places ] ;
placeholder    = "?" rnl-name [ places ] path
               | "?" path ;                        (* alone: in a symbol body, or in a general definition, 9.4; a path only in a general definition *)
places         = "{" place-item { "," place-item } "}" ;    (* touching the name, 5.2.3 *)
place-item     = place [ ":" place [ ":" integer ] ] ;
place          = integer | "end" [ "-" integer ] ;
path           = { ":" terminal-name [ subscript ] | "::" rnl-name } ;
subscript      = "<" subscript-item { "," subscript-item } ">"
               | "[" subscript-item { "," subscript-item } "]" ;
subscript-item = integer [ ":" integer [ ":" integer ] ] ;   (* unsigned, 6.11 *)
host-name      = name | string ;
rnl-name       = name | string ;
terminal-name  = name | string ;
role-label     = bracket-name | string ;
point          = "(" coordinate "," coordinate ")" ;   (* after white space, a comment, "{", ";", "=>" or "=", 3.8 *)
coordinate     = number | "_" | parameter-placeholder ;
parameters     = "(" [ value { "," value } [ "," named-value { "," named-value } ]
                     | named-value { "," named-value } ] ")" ;
named-value    = parameter-name "=" value ;
parameter-name = bracket-name | string ;
value          = number | string | "true" | "false"
               | "[" [ value { "," value } ] "]"
               | parameter-placeholder ;
parameter-placeholder = "?" rnl-name ;
```

- `name`, `bracket-name`, `keyword-name`, `string`, `number` 및 `integer`는 제3장이 정의한 대로 쓴다. `name`은 따옴표 없는 이름이다(3.6). `bracket-name`은 역할의 괄호 안이나 매개변수의 `=` 앞에 오는 따옴표 없는 이름이며, ASCII 글자, 숫자, `_` 및 모든 비-ASCII 문자로 이루어지고 ASCII 숫자로 시작하지 않는다(3.6). `keyword-name`은 글자, 숫자, `_`로 이루어지며 단어들은 `-`로 이어진다. `-`는 뒤에 글자가 올 때만 이름에 속한다(3.3). 표준 키워드는 대문자이며(3.6), 별칭은 어떤 문자의 글자든 글자, 숫자 및 `_`로 이루어지고 `-`가 없다(16.5). `string`과 `number`는 3.7에 있으며, `integer`는 부호 없는 십진 정수이다.
- `rnl-name`, `host-name`, `terminal-name`, `role-label` 및 `parameter-name`은 따옴표로 묶어 써도 같은 의미이지만, 역할과 매개변수 이름 자리에서는 따옴표로 묶인 이름이 결코 별칭이 아니다(3.6). 키워드, 매개변수 이름, 역할 괄호 안의 슬롯 이름, 하위 객체 이름, `true` 및 `false`는 선언된 별칭으로 쓸 수 있다. 따옴표 없는 비-ASCII 별칭은 `@` 뒤와 괄호 안에서만 쓰며, `::` 뒤의 별칭은 따옴표로 묶는다(16.5).
- 첨자는 호스트 이름이나 단자 이름 바로 뒤에 공백 없이 붙으며, 첨자 안에는 공백과 주석을 쓸 수 있다(3.5, 6.11). 어느 이름이 첨자를 받는지는 4.2 항목 10에 있다.
- 매개변수 괄호는 키워드에 붙이고 역할 괄호는 객체에 붙인다. 공백이나 주석 뒤의 `(`는 점을 시작한다(3.5).
- `=>`는 뒤에 무엇이 오느냐에 따라 파이프이거나 이름 붙이기이다(4.2 항목 3).
- 이름이 붙은 자리표시자는 일반 정의의 본문 안에서만 쓰며, 그 이름은 역할 목록이나 매개변수 목록에 있어야 한다(6.10). 객체 자리에서는 역할이며 경로를 가질 수 있고, 리터럴을 받는 자리(매개변수 값, 배열 원소, 점의 좌표)에서는 정의의 매개변수이며 경로가 없다(6.10, 9.4). 단독 `?`는 심볼 본문(13.3)과 일반 정의의 본문(9.4)에서 쓰며, 일반 정의 안에서만 `?::position` 같은 경로를 가질 수 있다.
- 자유 텍스트와 주석은 괄호 바깥의 임의의 두 토큰 사이와 멤버의 시작에 쓸 수 있으며(3.3, 3.4), 괄호 안에서도 공백과 주석을 쓸 수 있다. 문법은 이를 표시하지 않는다.
- 빈 멤버(`;;` 등)는 무시되며, 마지막 멤버 뒤의 `;`는 생략할 수 있다.

### 4.2 문법 밖의 제약

1. 세그먼트는 비어 있지 않다.
2. 세그먼트에는 키워드가 최대 하나만 온다. `@RNL`은 레코드의 시작에만 온다.
3. 뒤에 `%` 또는 `$` 이름이 오고 그 뒤에 `=>`, `;`, `}` 또는 멤버의 끝이 이어지는 `=>`는 이름 붙이기이다. 그 밖의 모든 `=>`는 다음 세그먼트를 시작하며, 그 세그먼트는 정확히 하나의 키워드를 가지고 그곳에 쓰인 이름은 그 세그먼트의 객체가 된다. 파이프의 첫 번째 세그먼트는 키워드가 없을 수 있으며, 그때는 정확히 하나의 객체를 가진다. 따라서 결과에 이름을 붙이고 파이프를 계속 이어 가려면 `=> %g0 => @PLACE(1, 2)`로 쓴다. `=> %g0 @PLACE(1, 2)`에서 `%g0`은 PLACE의 객체이며, 대개 바인딩되어 있지 않으므로 `%g0`을 찾지 못해 구문이 실패한다. 진단은 `=>`가 빠졌는지 물을 수 있다.
4. 키워드가 없는 세그먼트에서는 각 인자가 독립된 구문이다. `{#M1 #M2}` 안의 `#M1 #M2`는 두 개의 구문이다. 이러한 세그먼트에 이름(`%p =` 또는 `=> %p`)을 붙일 때는 객체가 하나만 있어야 하므로 `%p = #M1 #M2`가 아니라 `%p = {#M1 #M2}`로 쓴다.
5. 역할은 키워드가 있는 세그먼트의 인자에만 표시한다. 파이프 뒤의 세그먼트에서는 역할을 표시하지 않는다.
6. 한 세그먼트 안에서 모든 인자에 역할을 표시하거나 아무것에도 표시하지 않는다. 같은 역할을 두 번 표시하지 않는다.
7. 정의를 받는 키워드의 경우 키워드가 정의의 슬롯을 고정한다. ATTACH는 맨 앞에 쓴 객체, AS, SET-SYMBOL, SET-STYLE, SELECT-USAGE 및 SELECT-ANCESTOR-USAGE는 맨 뒤에 쓴 객체가 정의이다. SELECT-USAGE는 정의를 생략할 수 있으며, 맨 뒤 객체가 정의일 때만 정의 슬롯을 채운다(10.1). 정의에는 역할을 표시하지 않으며 규칙 6의 대상에도 들어가지 않는다(5.6).
8. 이름 붙이기에는 두 가지 방식이 있으며 함께 쓸 수 있다. `name =`은 멤버의 첫 번째 토큰으로만 올 수 있고(앞에 자유 텍스트가 올 수 있음) 한 멤버에 최대 한 번 쓴다. `=> name`은 세그먼트 뒤에, 즉 멤버의 끝이나 다음 세그먼트의 `=>` 앞에 오며 한 멤버에 여러 번 쓸 수 있다. 규칙 3이 이를 파이프와 구별한다.
9. 위치로 전달하는 매개변수가 먼저 오고 이름으로 전달하는 매개변수가 뒤에 온다. `name=value`가 하나 나온 뒤의 모든 매개변수는 이름으로 전달한다. 시그니처에 위치 순서가 적힌 매개변수만 그 순서대로 위치 전달할 수 있다. 같은 매개변수를 두 번 주지 않는다.
10. 첨자는 `#` 또는 `&` 뒤의 호스트 이름이나 `#` 참조 안의 단자 이름·포트 이름 뒤에만 온다. RNL 이름, 역할 이름 및 하위 객체 이름은 첨자를 받지 않는다(6.11).
11. 하나의 참조에는 이름 목록으로 확장되는 첨자가 최대 하나만 온다(6.11).

### 4.3 어순

- 매개변수가 붙은 키워드는 객체들 사이 어디에나 놓일 수 있으며, 객체들의 순서가 중요하다. `#M1 #M2 @DISTANCE(…)`, `#M1 @DISTANCE(…) #M2`, `@DISTANCE(…) #M1 #M2`는 같다.
- 각 키워드에는 하나의 표준 형식이 있으며, 도구는 오직 그 형식으로만 써야 한다. 표준 형식은 단어 목록에 기록되어 있다(5.3). 즉 키워드가 놓이는 위치, 어떤 매개변수를 위치로 주고 어떤 매개변수를 이름으로 주는지, 역할을 표시하는지 여부를 정한다.
- 기본적으로 표준 형식은 객체들이 먼저 오고, 그다음 매개변수가 붙은 키워드, 그다음 키워드 뒤에 정의가 오는 순서이다. ATTACH는 정의를 먼저 쓰고 그다음 키워드, 그다음 객체들을 쓴다: `$GROUND @ATTACH &vss`. TABLE은 표 앞에 키워드를 먼저 쓴다: `@TABLE layout: {…}`(14.11). 시그니처에 위치 순서가 적힌 매개변수는 위치로 먼저 주고, 나머지는 단어 목록 순서대로 이름으로 준다: `@PLACE(10, 20)`, `@ORIENT("R90")`, `@DISTANCE("bottom-to-top", min=4)`, `@TEXT("W/L", key="wl")`. PLACE는 둘 다 쓸 때만 x와 y를 위치로 주며, 한 축만 쓸 때는 `@PLACE(x=10)`처럼 이름으로 쓴다. WIRE의 `mode="auto"`처럼 지워도 의미가 바뀌지 않는 매개변수는 쓰지 않는다. 내장 키워드는 역할 없이 쓰고, AS와 ATTACH는 일반 정의에 역할이 둘 이상일 때 모든 역할을 표시한다.
- 배치(레이아웃): 괄호 안의 각 쉼표 뒤 공백 한 칸, 매개변수 `=` 양쪽 공백 없음, 이름 붙이기 `=`와 `=>` 양쪽 공백 한 칸, 키워드와 그 괄호는 붙여 씀, `{ @…`처럼 `{`와 키워드 사이 공백 한 칸(2.3), 숫자는 다시 읽었을 때 같은 값이 되는 가장 짧은 십진수로 씀.
- **이름 붙이기의 표준 형식.** 파이프가 없는 멤버는 앞쪽에 `%x = statement`로 이름을 붙이고, 파이프가 있는 멤버는 끝쪽에 `statement => … => %x`로, 즉 이름을 붙일 세그먼트 바로 뒤에 이름을 붙인다. 따라서 앞쪽의 이름은 항상 멤버 전체에 이름을 붙이며, 읽는 이가 파이프의 어느 세그먼트에 붙은 이름인지 추측할 필요가 없다. 구문 자체는 두 형식을 모두 허용한다.
- "오직 그 형식으로만"은 도구가 새로 쓰는 구문에 적용된다. 도구가 기존 레코드를 다시 쓸 때는 사용자가 작성한 구문의 순서를 바꾸어서는 안 되며(16.4), 사용자가 서식 정리를 요청할 때만 표준 형식으로 맞춘다.
- 표준 문장은 4.5에 있다.

### 4.4 오류 예제

다음은 모두 오류이며, 주석이 그 이유를 설명한다.

```rnl error
#M1 @PLACE (10, 20)    /* a bracket after white space is a point, and PLACE has no parameters (3.5) */
```

```rnl error
#M1 (left) #M2 (right) #M5 (tail) @AS $DIFFERENTIAL_PAIR_N    /* role brackets touch the object; a separate bracket is a point (3.5) */
```

```rnl error
#M2 @PLACE(62, 40) (MY)    /* the second bracket is a point, and its content is not a point */
```

```rnl error
&vss @ATTACH $GROUND    /* the definition of ATTACH is written first: $GROUND @ATTACH &vss */
```

```rnl error
R1 -> R2 {#R1 #R2} @ORDER("left-to-right")    /* ">" cannot be free text (3.3) */
```

```rnl error
#M1 @PLACE(1, 2), #M2 @PLACE(3, 4)    /* a comma does not separate statements: two keywords in one segment */
```

```rnl error
#M1 #M2 @SET-SYMBOL $NMOS    /* three objects, and SET-SYMBOL has two slots (5.2.1); write {#M1 #M2} @SET-SYMBOL $NMOS */
```

```rnl error
#M1 => #M2    /* the segment after a pipe has no keyword */
```

```rnl error
#M1 #M2 #M3 @DISTANCE("left-to-right", min=1)    /* three objects for two slots */
```

```rnl error
#M1 @PLACE(x=10, 20)    /* a parameter given by position after one given by name (4.2 item 9) */
```

```rnl error
{#M1 #M2} @ORDER(axis="x", direction="increasing")
/* ORDER has no axis: the axis and the direction are one parameter, direction, as in @ORDER("left-to-right") (14.3) */
```

```rnl error
#M1 @SET-SYMBOL($NMOS)    /* brackets hold only literals */
```

```rnl error
{#M1 #M2} @ALIGN(axis=y)    /* enumerations are written as strings */
```

```rnl error
%ax = (_, _);
#M1(left) #M2 %ax @AS $MIRRORED_LAYOUT /* roles are marked on all objects or on none */
```

```rnl error
$NMOS(symbol) #M1(target) @SET-SYMBOL    /* the definition is written last and is not marked with a role */
```

```rnl error
#R1(source) #R2(chain) #R3(chain) #R4(load) @AS $CHAIN_ROW    /* the same role is marked twice */
```

```rnl error
(0, 0) @PIN(terminal=1)    /* a pin cannot be written in the scene (13.4) */
```

```rnl error
#M1 @CURRENT("in")    /* CURRENT takes only terminals (15.2) */
```

```rnl error
&D<1:0>[1:0]    /* a name has at most one subscript (6.11) */
```

```rnl error
#XI0<1:0>:D<1:0>    /* one reference has at most one expansion (6.11) */
```

```rnl error
&D<_, 1>    /* a "<" directly after a name starts a subscript, and its content is not a subscript (3.5) */
```

```rnl error
%p<1, 2>    /* RNL names take no subscript; a point is written (1, 2) (6.11) */
```

### 4.5 표준 문장

표준 문장은 표준 형식의 구문에 토큰 사이 자유 텍스트를 넣어 문장처럼 읽히게 한 것이다. 표준 문장은 작성 가이드와 구문에 단어를 넣거나 빼는 서식 도구에서 사용된다. 자유 텍스트는 의미에 영향을 주지 않으므로(3.3), 이 문장들은 제안일 뿐이며 사용자와 언어 모델은 이를 쓸 수도, 아무것도 쓰지 않을 수도, 다른 단어를 쓸 수도 있다.

- **사실.** 구문은 수행할 작업이 아니라 도면에서 성립하는 바를 서술한다. 객체가 주어로 먼저 오고, 키워드는 서술어나 명사 역할을 하며, 매개변수가 그 값이다. `is`, `are`, `has`, `is at`, `there is` 같은 연결어만 추가한다. `#M1 @SET-SYMBOL to $NMOS`처럼 몇몇 구문은 동작처럼 읽힐 수 있다.
- **단어는 구문에서 따라 나온다.** 도구가 생성하는 단어는 회로의 의미가 아니라 키워드, 매개변수, 객체의 수와 종류 및 구문이 작성된 레벨에만 의존한다. 예를 들어 객체 수에 따라 `is` 또는 `are`가 선택되고, 한 축만 주어졌을 때는 `the x of`가 쓰이며, 선택식의 후보 문구는 범위와 선택되는 종류를 따른다(부록 B). 이는 문장이 생성되는 방식이며 사용자를 제한하지 않는다.
- **구문에 없는 뜻을 암시하는 단어 금지.** `must`, `required`, `only` 같은 단어는 쓰지 않으며, 방향 단어는 매개변수가 그 방향을 가질 때만 쓴다. 읽는 이는 문장 속 단어를 믿게 되므로 작성 가이드에서도 이를 경고하는 것이 좋다.
- **풀이.** 읽는 이가 방향 코드나 축을 모를 수도 있으므로 키워드 뒤에 `, i.e., …`로 코드 자체의 뜻을 덧붙일 수 있다(예: `#M2 @ORIENT("MX"), i.e., flipped upside down`).
- **ORIENT-RELATION과 DISTANCE**는 슬롯이 둘이므로 `from A to B`로 읽힌다.
- **선택식**은 항상 후보 중에서 고르는 형태로 읽힌다: `among <candidates>, @SELECT-…`. 범위가 `#`일 때 후보는 `the <kind> in # only`이고, 구문이 아래 레벨에 도달할 때는 `the <kind> at each level in # and below`가 되어 규칙이 각 레벨에서 평가됨을 드러낸다(10.1, 10.4). 종류를 알아낼 수 없을 때는 `for X,`로 읽힌다.
- **AS와 ATTACH.** AS는 객체들이 모여 그 대상을 이룰 때 쓴다: `#M1(left), #M2(right) and #M5(tail) are treated @AS $DIFFERENTIAL_PAIR_N`. ATTACH는 그 대상이 객체들에 덧붙여질 때 쓴다: `$GROUND is @ATTACH to &vss`(9.4).
- **파이프.** 다음 세그먼트는 앞 세그먼트의 결과를 가리킨다. 영어에서는 `it`(AS, ATTACH 또는 단일 객체 뒤)이나 `they`(선택식 뒤)를 쓴다. 파이프 안의 이름 앞에는 `… => named %pout`처럼 `named`를 붙이며, 이는 여전히 이름 붙이기이다(4.2 항목 3).
- **이름 붙이기.** 단일 구문의 이름은 앞에 쓴다(4.3). AS 구문에 이름이 붙을 때 영어에서는 `are`를 뺀다: `%dp = #M1(left), #M2(right) and #M5(tail) treated @AS $DIFFERENTIAL_PAIR_N`.
- **집합의 이름.** 집합을 가리키는 이름은 `$` 이름이면 `_SET`, `%` 이름이면 `_set`으로 끝나는 것이 좋다(예: `$GROUND_FILL_SET`, `%bias_set`). 표준 패키지는 이를 따른다.
- **`each` 사용 안 함.** `each` 같은 단어는 쓰지 않는다. 집합이 통째로 적용되는지 멤버별로 적용되는지는 정의의 역할 목록에 달려 있으며, 표준 문장은 어느 쪽인지 말하지 않는다.
- **다른 언어.** 이 표준은 문장을 영어로 제시한다. 다른 언어의 문장은 중국어용 `alias-zh` 같은 해당 언어 별칭 패키지의 별칭을 쓰고 그 문서를 따른다(16.5). 그 언어의 문장부호 뒤에서도 `@` 앞에는 여전히 공백 한 칸이 필요하다(2.3).

각 키워드의 표준 문장은 부록 B에 나열되어 있다.
