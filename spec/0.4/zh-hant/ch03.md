## 3 詞法結構

### 3.1 字元

- 記號由 ASCII 字元構成。
- 非 ASCII 字元僅出現於字串（含加引號名稱）、自由文字、註解與別名中，以及未加引號的角色與參數名稱中。在自由文字與註解之外，未加引號的非 ASCII 詞彙僅出現於 `@` 之後與括號之內：在 `@` 之後須為已宣告的別名；在括號之內則為別名，或本身即為角色名稱或參數名稱（3.6、16.5）。
- **編碼。** 宿主配接器依宿主規則解碼文字；RNL 在字元層面運作。寫出 RNL 的工具不得變更宿主檔案的編碼或換行符號，且不得加入位元組順序記號（BOM）；不得寫出宿主編碼無法表示的字元，否則須改為給出警告。新檔案應使用 UTF-8。
- **宿主註解中的非 ASCII 字元。** 配接器須說明哪些宿主的註解已驗證支援非 ASCII 字元；對其他宿主，遇到非 ASCII 字元時會給出提示。

  附註：各宿主支援情況不同。ngspice（自 42 版起）、WRspice（標題除外）、Xyce 與較新版本的 LTspice 皆接受註解中的非 ASCII 字元；HSPICE、PSpice 與 Eldo 的文件未加說明；Spectre 手冊將網表描述為 ASCII 檔案；QSPICE 使用 Windows-1252。不加入位元組順序記號的另一個原因：較舊版本的 ngspice 會將它併入引入檔案的第一個記號中，而 WRspice 當第 1 行以此開頭時會停止讀取。

### 3.2 記號

| 記號 | 形式 |
|---|---|
| 關鍵字 | `@` 後接大寫名稱，例如 `@PLACE`；或已宣告的別名（16.5） |
| 引用 | 前綴後接名稱，可能帶有端子與子物件，例如 `#M1`、`#M1:d`、`%dp1::left`（第 6 章）；或是單獨的 `#`、`?` 或 `&`（6.2）。宿主名稱或端子名稱後可直接緊接下標，例如 `&D<3>`、`&D<7:0>`（6.11）。對集合的引用後可直接緊接成員位置，例如 `%a{1}`、`?ref{2:end}`（5.2.3）。在求解器記錄中，亦包含 `%#` 後接無號整數構成的編號，例如 `%#3`（5.9） |
| 點 | `(x, y)`，不可緊貼關鍵字或物件：須位於空白字元、註解、`{`、`;`、`=>` 或 `=` 之後（3.8） |
| 括號 | 參數與角色的 `(` `)`，緊貼關鍵字或物件（3.5） |
| 大括號 | 集合的 `{` `}` |
| 分隔符 | `;`（分隔成員）、`=>`（管線與命名）、`=`（於成員開頭命名） |

在括號之內（參數、角色與點的 `()`，以及陣列的 `[]`）還可包含字串、數字、`,`、`=`、`_` 與名稱（參數名稱、角色名稱、`true`、`false`），以及在一般定義的定義本體中的參數佔位符 `?name`（6.10）。在下標的 `<>` 與 `[]` 之內僅能有無號整數、`,` 與 `:`（6.11）；在成員位置的大括號內僅能有無號整數、`end`、`-`、`,` 與 `:`（5.2.3）。

### 3.3 自由文字

- 在括號之外，除下列字元外，任何字元皆可作為自由文字。這包含所有非 ASCII 字元（如中文標點 `：`、`、`、`；`、`（`、`）`）以及 `-`、`:`、`'`、`!`、`+`、`/`、`*` 與 `|`。例外如下：
  - `@`、`#`、`&`、`%`、`$`、`?`、`"`、`;`、`=`、`{`、`}`、`(`、`)`：在括號之外，它們用來開始或屬於記號（3.2）。單獨的 `&`（後方不接名稱）是空節點（empty node）（6.3）。`?` 開頭為佔位符（6.10）；單獨的 `?` 在符號定義本體中指使用該符號繪製的物件（13.3），在一般定義的定義本體中則指正在展開的用例（9.4）；
  - `[`、`]`、`<`、`>`：陣列與下標的括號（3.7、6.11）；
  - `/*`：開始一段註解（3.4）。
- 位置規則確保含義唯一：
  - 緊接於引用之後且後接名稱或引號的 `:` 或 `::`，照常表示端子或子物件（6.4、6.5）。當後方沒有名稱時，`:` 即為自由文字，例如 `Input pair: %dp1 = …` 與 `#M1: the left one`。
  - 緊接於名稱之後的 `<` 或 `[` 為下標（6.11）。
  - 緊接於引用之後且無空白字元的 `{` 開啟成員位置（5.2.3）；位於空白字元之後者則開啟集合。
  - 在關鍵字名稱中，僅當 `-` 後方接有字母時才屬於該名稱（關鍵字：3.6）。`@GROUP- the pair` 是 GROUP 後接自由文字。
- 自由文字可寫在括號外任意兩個記號之間，以及成員開頭。
- **自由文字是敘述的一部分。** 寫在其中的引用並非單純說明，而是該敘述的物件：`Unlike #M2, #M1 @PLACE(x=0)` 同樣會把 M2 放到 x = 0。僅作為說明的文字應寫在註解中（3.4），或單獨寫成以 `;` 與下一成員分隔的成員：僅含自由文字的成員是空成員，會被略過（4.1）。
- 本標準不檢查自由文字，自由文字亦不影響含義（原則 2.8）：`do not move #M2 @PLACE(x=30)` 依然會移動 M2。實作可以針對否定詞等字眼自行給出警告（7.6）。
- 同理，誤寫為 `#M1.d` 時，`.d` 是自由文字，該引用指向 M1 本身而非其汲極（會給出警告，見下文）。
- 括號內沒有自由文字。
- **警告。** 以下疏失容易被靜默略過，因此會給出警告（7.6）：
  - 自由文字中出現本層級宿主實例名稱、可見的 RNL 名稱（不含前綴）或關鍵字名稱，例如 `#M1 #M2 M3 @ALIGN("y")` 中的 `M3` 或 `WIRE {…}` 中的 `WIRE`：很可能漏寫了 `#`、`%`、`$` 或 `@`。網路名稱常為普通單字（如 in 與 out），故不予檢查。
  - 引用後方緊接 `.` 與名稱，例如 `#M1.d`：端子須使用 `:`。
  - 引用後方緊接 `-`、`!`、`'`、`+`、`/`、`*`、`\`、`^`、`~` 或 `|`，例如 `&vdd!` 或 `#X1-a`：該名稱很可能包含此字元而需要加引號，如 `&"vdd!"`（3.6）；未加引號時，該引用會靜默指涉 `vdd` 或 `X1`。
  - 自由文字中出現 `|`：管線須寫作 `=>`（4.2 第 3 項）。
  - 引用後方緊接 `:` 或 `::` 且後接非 ASCII 詞彙，例如 `%c1::中点`：`::` 後方含非 ASCII 字元的名稱須加引號，如 `%c1::"中点"`（3.6）；未加引號時，`::` 與該詞彙會成為自由文字，該引用則指涉 `%c1`。
- 多數其他同類疏失本身即構成錯誤：括號內沒有自由文字，故 `@ORIENT(MY)` 是錯誤；`#M1 @PLACE 1 2` 不符合簽名；`#M1 (in_p)` 是錯誤，因為空白字元後的括號開啟一個點，而 `(in_p)` 不是點（3.5）；且 `R1 -> R2` 中的 `>` 不能作為自由文字。
- 給作者的撰寫指南是依詞彙表產生的（5.3）。求解器與編輯器寫出的記錄不得包含自由文字。

### 3.4 註解

凡允許空白字元之處皆可寫入 `/* … */`，包括括號之內。註解不可巢狀嵌寫，其中可寫入任何字元。包含引用或 `@`、`#`、`;` 等字元的說明文字應寫在註解中（3.3）。

### 3.5 空白字元與相鄰規則

- 空白字元包括空格、TAB 與換行。記號不得跨行拆開，字串不得跨行。
- 以下位置不得出現空白字元與註解：前綴與其名稱之間，或 `%#` 與其編號之間；`:` 與 `::` 的任一側；名稱與其下標之間（6.11）；引用與其成員位置的 `{` 之間（5.2.3）；關鍵字與其參數括號之間，以及 `@RNL` 與其記錄標頭括號之間（2.4）；物件與其角色括號之間。
- 位於空白字元或註解之後的 `(` 會開啟一個點（3.8）。因此 `#M1 @PLACE (10, 20)` 會被讀作 PLACE 後接一個點，而 PLACE 沒有無參數的形式：構成錯誤。`#M1 (in_p)` 則是 M1 後接一個格式不正確的點：同樣構成錯誤。診斷會建議移除空白字元。
- 緊接於名稱（無論是否加引號）之後的 `<` 或 `[` 一律開啟下標（6.11）。點寫作 `(x, y)`，不會與下標衝突；若要在名稱後方寫點，須以空白字元隔開，例如 `&D (1, 2)`。下標內部可以寫空白字元與註解，例如 `&D<1, 2:3>`（6.11）。
- 緊接於關鍵字之後的 `.` 是自由文字，例如 `{#M1 #M2} @GROUP.` 末尾的句點；`@BUNDLE.LOCK` 則是 BUNDLE 後接自由文字 `.LOCK`（16.4）。

### 3.6 名稱

- **未加引號的名稱**由一個或多個 ASCII 字母、數字與底線組成，依最長匹配讀取。
- **宿主名稱**（位於 `#` 與 `&` 之後）與端子名稱遵循宿主方言的規則（原則 2.1）：哪些名稱合法、是否區分大小寫，以及名稱能否以數字開頭（如 `&0`）。SPICE 不區分大小寫；Spectre 區分大小寫。含其他字元的名稱須寫在引號中，例如 `#"M1<0>"`、`&"vdd!"`、`#XU1:"in+"`；引號內的文字寫法與字串相同（3.7）。名稱後方可直接緊接下標：`#M1<0>` 等同 `#"M1<0>"`，而 `&D<7:0>` 是一串網路列表（6.11）。引號內的 `<` 或 `[` 是名稱本身的一部分，不進行剖析。
- **RNL 名稱**（`%`、`$` 與 `?` 之後的名稱、角色名稱，以及一般定義的參數名稱）：
  - 區分大小寫：`$DIFFERENTIAL_PAIR` 與 `$differential_pair` 是兩個不同的名稱。
  - 在 `%`、`$` 與 `?` 之後，名稱可以數字開頭，例如 `%1st`。在沒有前綴的位置（`(role)` 與 `parameter=`），未加引號的名稱由 ASCII 字母、數字、底線以及任意非 ASCII 字元組成，且不得以 ASCII 數字開頭，以免看似數字：`#M1(正输入)`、`@AS(间距=3) $X`。這兩處皆位於括號之內，該處沒有自由文字（3.3），因此不會將其他詞語吞入名稱中。
  - 可以加引號，含義相同：`$"a"` 即 `$a`；引號僅作跳脫之用。包含其他字元以及非 ASCII 字元的名稱須寫在引號中，例如 `%"差分对"`、`%"input pair"`、`?"正输入"`、`%dp::"正输入"`。在角色與參數名稱位置，非 ASCII 名稱可以不加引號（見上一項），但空格或其他 ASCII 標點仍須加引號，例如 `#M1("input pair")`。在角色與參數名稱位置，加引號的名稱永遠指該名稱本身，絕不視為別名。這點不適用於 `$` 名稱與 `::` 後的名稱，因它們的非 ASCII 別名本來就寫在引號中（16.5）。
  - 依書寫形式逐字元比較，不作 Unicode 正規化。空名稱為錯誤。
  - 不接受下標（6.11）：緊接其後的 `<` 或 `[` 為錯誤，例如 `%p<1, 2>`。點須寫作 `(1, 2)`，與名稱之間以空白字元隔開。
- **別名**（16.5）在檔頭記錄中宣告或來自別名套件。關鍵字與標準詞彙的別名可包含非 ASCII 字母；僅在 `@` 之後與括號之內可不加引號寫出。`$` 名稱的別名比照 `$` 名稱的寫法，包含非 ASCII 字元時須加引號，例如 `$"接地补位集"`。`#`、`&`、`%`、`$`、`?` 與 `::` 之後未加引號的名稱僅限 ASCII（見上文），因此 `#M1和#M2` 會讀作 `#M1`、自由文字 `和` 與 `#M2`。
- **關鍵字**僅限大寫，詞彙間以 `-` 連接，例如 `@AS` 與 `@SET-SYMBOL`；全大寫亦使其易於在自由文字中辨識。`@at` 是未知關鍵字，除非檔頭記錄將其宣告為別名（16.5）。
- **標準詞彙**區分大小寫，須依本標準拼寫：參數名稱、記錄標頭的欄位名稱、子物件名稱、篩選條件名稱與列舉值（如 `"x"`、`"low"`、`"MY"`）。指涉宿主事物的值（篩選條件中的名稱、模型名稱、網路名稱）遵循宿主規則。其他拼寫方式可透過別名接受（16.5）。
- **`true` 與 `false`** 為保留字且僅限小寫。它們不得作為角色名稱或參數名稱。

### 3.7 字面量

- **數字**採用十進位。可帶正負號與前導零，可省略小數點前的零或小數點後的位數，亦可使用指數記法：`0`、`+1`、`01`、`.5`、`1.`、`-2.5E-4`。`01` 是 1，而非八進位。不支援單位或工程後綴（`2u` 與 `10k` 皆為錯誤）、十六進位數字、`NaN` 與 `Infinity`。位數不限長度。當實作無法容納某個數值時，該敘述在該實作中失效，並給出指出已達實作上限的錯誤；不得靜默修改該值。座標比較帶有容差（11.7）。
- **字串**寫在雙引號內，且不得跨行。引號之間的字元依原樣讀取；僅 `"` 本身寫作 `""`，例如 `"say ""hi"""`。沒有反斜線跳脫：`\` 是一般字元，不支援 `\n` 或 `\uXXXX`；非 ASCII 字元直接寫入即可。字串中不能寫換行；文字中的換行須使用標記語法 `\\`（13.6）。TEXT 擁有自己的反斜線命令（13.6）；它們是 TEXT 解譯其文字的方式，而非字串的跳脫字元。記錄標頭中的字串寫法相同；這屬於外層形式，不會變更（16.1）。
- **陣列**寫作 `[value, value, …]`。其元素為字面量，且陣列可以巢狀嵌寫。
- **真假值**為 `true` 與 `false`。
- 沒有其他字面量。列舉值寫成字串，例如 `axis="x"`；沒有 `null`、映射（map）或建構值。
- 沒有運算式：運算子皆為錯誤。

### 3.8 點

- 點寫作 `(x, y)`，其中 x 與 y 為數字或 `_`（在一般定義的定義本體內，亦可為參數佔位符，6.10）。`_` 使該座標軸保持自由，交由約束或求解器決定。
- 寫出一個點即建立一個點物件（5.1）。
- 點不支援算術運算；相對位置寫作約束（第 14 章）。在一般定義的定義本體內，字面量座標是相對於該用例自身的點的偏移量（9.4）。
- 點的 `(` 前方須為空白字元或註解，或緊接在 `{`、`;`、`=>` 或 `=` 之後。緊貼關鍵字或物件的括號容納其參數或角色（3.5）。緊接在名稱後的 `<` 在任何情況下皆為下標（6.11）。
