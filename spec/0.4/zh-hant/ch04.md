## 4 語法

### 4.1 文法

記錄的文法以 EBNF 給出。每條產生式寫作 `name = expression ;`；`|` 分隔選項，`[ … ]` 表示可選，`{ … }` 表示重複零次或多次，`( … )` 用於分組，雙引號內的文字依字面書寫，`(* … *)` 為註解。

```ebnf
record         = "@RNL" [ parameters ] set ;          (* the bracket touches "@RNL" *)
set            = "{" [ member ] { ";" [ member ] } "}" ;
member         = [ front-naming ] segment { naming } { "=>" segment { naming } } ;
front-naming   = ( "%" rnl-name | "$" rnl-name ) "=" ;
naming         = "=>" ( "%" rnl-name | "$" rnl-name ) ;
segment        = argument { argument } [ call { argument } ]
               | call { argument } ;
call           = keyword [ parameters ] ;          (* the bracket touches the keyword *)
keyword        = "@" keyword-name ;                (* upper case, or a declared alias *)
argument       = object [ "(" role-label ")" ] ;   (* the bracket touches the object *)
object         = reference | placeholder | point | set ;
reference      = "#" [ host-name [ subscript ] ] path
               | "&" host-name [ subscript ] path
               | "%" rnl-name [ places ] path
               | "%#" integer path                (* a number, in a record of the solver, 5.9 *)
               | "$" rnl-name [ places ] ;
placeholder    = "?" rnl-name [ places ] path
               | "?" path ;                        (* alone: in a symbol body, or in a general definition, 9.4; a path only in a general definition *)
places         = "{" place-item { "," place-item } "}" ;    (* touching the name, 5.2.3 *)
place-item     = place [ ":" place [ ":" integer ] ] ;
place          = integer | "end" [ "-" integer ] ;
path           = { ":" terminal-name [ subscript ] | "::" rnl-name } ;
subscript      = "<" subscript-item { "," subscript-item } ">"
               | "[" subscript-item { "," subscript-item } "]" ;
subscript-item = integer [ ":" integer [ ":" integer ] ] ;   (* unsigned, 6.11 *)
host-name      = name | string ;
rnl-name       = name | string ;
terminal-name  = name | string ;
role-label     = bracket-name | string ;
point          = "(" coordinate "," coordinate ")" ;   (* after white space, a comment, "{", ";", "=>" or "=", 3.8 *)
coordinate     = number | "_" | parameter-placeholder ;
parameters     = "(" [ value { "," value } [ "," named-value { "," named-value } ]
                     | named-value { "," named-value } ] ")" ;
named-value    = parameter-name "=" value ;
parameter-name = bracket-name | string ;
value          = number | string | "true" | "false"
               | "[" [ value { "," value } ] "]"
               | parameter-placeholder ;
parameter-placeholder = "?" rnl-name ;
```

- `name`、`bracket-name`、`keyword-name`、`string`、`number` 與 `integer` 依第 3 章定義書寫。`name` 是未加引號的名稱（3.6）。`bracket-name` 是寫在角色括號內或參數 `=` 之前的未加引號名稱：由 ASCII 字母、數字、`_` 與任何非 ASCII 字元組成，且不以 ASCII 數字開頭（3.6）。`keyword-name` 由字母、數字與 `_` 組成，詞彙間以 `-` 連接；僅當 `-` 後方接有字母時才屬於該名稱（3.3）。標準關鍵字須為大寫（3.6）；別名由任意書寫系統的字母、數字與 `_` 組成，不含 `-`（16.5）。`string` 與 `number` 見 3.7；`integer` 是無號十進位整數。
- `rnl-name`、`host-name`、`terminal-name`、`role-label` 與 `parameter-name` 亦可加引號且含義相同，唯獨在角色與參數名稱位置，加引號的名稱絕不視為別名（3.6）。關鍵字、參數名稱、角色括號內的槽位名稱、子物件名稱、`true` 與 `false` 皆可寫作已宣告的別名；未加引號的非 ASCII 別名僅用於 `@` 之後與括號之內，`::` 之後的別名須加引號（16.5）。
- 下標須緊接在宿主名稱或端子名稱之後，兩者間不得有空白字元；下標內部允許空白字元與註解（3.5、6.11）。哪些名稱可帶下標見 4.2 第 10 項。
- 參數括號緊貼關鍵字，角色括號緊貼物件；位於空白字元或註解之後的 `(` 開啟一個點（3.5）。
- `=>` 是管線或命名，取決於後方所接內容（4.2 第 3 項）。
- 帶名稱的佔位符僅寫在一般定義的定義本體中（6.10）。在物件位置中它是角色，可帶路徑；在接收字面量的位置（參數值、陣列元素、點座標）中它是該定義的參數，不帶路徑（6.10、9.4）。單獨的 `?` 寫在符號定義本體中（13.3）與一般定義的定義本體中（9.4）；僅在一般定義中才可帶路徑，如 `?::position`。
- 自由文字與註解可寫在括號外任意兩個記號之間以及成員開頭（3.3、3.4）；括號內亦可寫空白字元與註解。上述文法未顯示它們。
- 空成員（如 `;;`）會被略過；最後一個成員後的 `;` 可以省略。

### 4.2 文法之外的約束

1. 段不得為空。
2. 一個段至多包含一個關鍵字。`@RNL` 僅出現於記錄開頭。
3. 若 `=>` 後方緊接 `%` 或 `$` 名稱，且該名稱之後為 `=>`、`;`、`}` 或成員結尾，則其為命名。任何其他 `=>` 開啟下一段；該段須恰好有一個關鍵字，且寫於該處的名稱為該段的物件。管線的第一段可以沒有關鍵字；此時該段僅有一個物件。因此若要為結果命名並繼續管線，須寫作 `=> %g0 => @PLACE(1, 2)`。在 `=> %g0 @PLACE(1, 2)` 中，`%g0` 是 PLACE 的物件；通常它尚未綁定，敘述會因找不到 `%g0` 而失效。診斷可能會詢問是否漏寫了 `=>`。
4. 在沒有關鍵字的段中，每個引數各為一條獨立敘述：`{#M1 #M2}` 中的 `#M1 #M2` 是兩條敘述。這類段若予以命名（`%p =` 或 `=> %p`），僅能有一個物件：須寫作 `%p = {#M1 #M2}`，而非 `%p = #M1 #M2`。
5. 僅帶有關鍵字的段的引數才能標記角色。管線之後的段不得標記角色。
6. 在同一段中，要嘛所有引數皆標記角色，要嘛全都不標記。同一角色不得標記兩次。
7. 對於接收定義的關鍵字，由關鍵字固定該定義所佔的槽位：對 ATTACH 而言是寫在最前面的第一個物件；對 AS、SET-SYMBOL、SET-STYLE、SELECT-USAGE 與 SELECT-ANCESTOR-USAGE 而言則是最後一個物件。SELECT-USAGE 可省略其定義：僅當其最後一個物件為定義時，該物件才填入定義槽位（10.1）。定義不標記角色，且不計入第 6 項規則的計算（5.6）。
8. 命名有兩種方式，且可同時併用。`name =` 僅能作為成員的第一個記號（前方可寫自由文字），每個成員至多寫一次。`=> name` 接在某段之後，位於成員末尾或下一段 `=>` 之前，且單一成員可寫多次。第 3 項規則用以區分它與管線。
9. 依位置傳入的參數須排在前面，依名稱傳入者排在後面：一旦出現 `name=value`，其後所有參數皆須依名稱傳入。僅簽名中列有位置順序的參數才可依位置傳入，且須依該順序書寫。同一參數不得重複傳入兩次。
10. 下標僅能緊接在 `#` 或 `&` 之後的宿主名稱後，或 `#` 引用中的端子名稱或連接埠名稱後。RNL 名稱、角色名稱與子物件名稱不接受下標（6.11）。
11. 一筆引用至多只能有一個會展開為名稱列表的下標（6.11）。

### 4.3 詞序

- 關鍵字及其參數可寫在物件之間的任意位置；物件之間的先後順序具有意義。`#M1 #M2 @DISTANCE(…)`、`#M1 @DISTANCE(…) #M2` 與 `@DISTANCE(…) #M1 #M2` 完全等價。
- 每個關鍵字皆有一種標準寫法，工具須僅寫出該標準寫法。標準寫法記錄於詞彙表中（5.3）：關鍵字置於何處、哪些參數依位置傳入與哪些依名稱傳入，以及是否標記角色。
- 預設的標準寫法為：物件在先，接連是帶參數的關鍵字，定義則寫在關鍵字之後。ATTACH 將定義寫在最前，接連是關鍵字，然後是物件：`$GROUND @ATTACH &vss`。TABLE 將關鍵字寫在最前，位於表格之前：`@TABLE layout: {…}`（14.11）。簽名列有位置順序的參數依位置寫於最前；其餘參數依詞彙表順序以名稱寫出：`@PLACE(10, 20)`、`@ORIENT("R90")`、`@DISTANCE("bottom-to-top", min=4)`、`@TEXT("W/L", key="wl")`。PLACE 僅在同時給出 x 與 y 時才依位置寫出；僅給單軸時須依名稱寫出，例如 `@PLACE(x=10)`。移除後不改變含義的參數不予寫出，例如 WIRE 的 `mode="auto"`。內建關鍵字不標記角色；當一般定義具有兩個或以上角色時，AS 與 ATTACH 須標記所有角色。
- 版面格式：括號內每個逗號後方留一個空格；參數 `=` 兩側不留空格；命名 `=` 與 `=>` 兩側各留一個空格；關鍵字緊貼其括號；`{` 與關鍵字之間留一個空格，例如 `{ @…`（2.3）；數字寫為能讀回相同數值的最短十進位表示法。
- **命名的標準寫法。** 不帶管線的成員於開頭命名，`%x = statement`；帶管線的成員於末尾命名，`statement => … => %x`，將名稱寫在其所命名的段之後。如此一來，開頭的名稱一律命名整個成員，讀者不需猜測它究竟命名管線的哪一段。語法上兩種寫法皆可接受。
- 「僅寫出該標準寫法」僅適用於工具新建的敘述。當工具重寫既有記錄時，不得重排使用者所寫的敘述（16.4）；僅在使用者要求格式化時，才將它們轉為標準寫法。
- 標準例句見 4.5。

### 4.4 錯誤範例

以下各例皆為錯誤；註解說明原因。

```rnl error
#M1 @PLACE (10, 20)    /* a bracket after white space is a point, and PLACE has no parameters (3.5) */
```

```rnl error
#M1 (left) #M2 (right) #M5 (tail) @AS $DIFFERENTIAL_PAIR_N    /* role brackets touch the object; a separate bracket is a point (3.5) */
```

```rnl error
#M2 @PLACE(62, 40) (MY)    /* the second bracket is a point, and its content is not a point */
```

```rnl error
&vss @ATTACH $GROUND    /* the definition of ATTACH is written first: $GROUND @ATTACH &vss */
```

```rnl error
R1 -> R2 {#R1 #R2} @ORDER("left-to-right")    /* ">" cannot be free text (3.3) */
```

```rnl error
#M1 @PLACE(1, 2), #M2 @PLACE(3, 4)    /* a comma does not separate statements: two keywords in one segment */
```

```rnl error
#M1 #M2 @SET-SYMBOL $NMOS    /* three objects, and SET-SYMBOL has two slots (5.2.1); write {#M1 #M2} @SET-SYMBOL $NMOS */
```

```rnl error
#M1 => #M2    /* the segment after a pipe has no keyword */
```

```rnl error
#M1 #M2 #M3 @DISTANCE("left-to-right", min=1)    /* three objects for two slots */
```

```rnl error
#M1 @PLACE(x=10, 20)    /* a parameter given by position after one given by name (4.2 item 9) */
```

```rnl error
{#M1 #M2} @ORDER(axis="x", direction="increasing")
/* ORDER has no axis: the axis and the direction are one parameter, direction, as in @ORDER("left-to-right") (14.3) */
```

```rnl error
#M1 @SET-SYMBOL($NMOS)    /* brackets hold only literals */
```

```rnl error
{#M1 #M2} @ALIGN(axis=y)    /* enumerations are written as strings */
```

```rnl error
%ax = (_, _);
#M1(left) #M2 %ax @AS $MIRRORED_LAYOUT /* roles are marked on all objects or on none */
```

```rnl error
$NMOS(symbol) #M1(target) @SET-SYMBOL    /* the definition is written last and is not marked with a role */
```

```rnl error
#R1(source) #R2(chain) #R3(chain) #R4(load) @AS $CHAIN_ROW    /* the same role is marked twice */
```

```rnl error
(0, 0) @PIN(terminal=1)    /* a pin cannot be written in the scene (13.4) */
```

```rnl error
#M1 @CURRENT("in")    /* CURRENT takes only terminals (15.2) */
```

```rnl error
&D<1:0>[1:0]    /* a name has at most one subscript (6.11) */
```

```rnl error
#XI0<1:0>:D<1:0>    /* one reference has at most one expansion (6.11) */
```

```rnl error
&D<_, 1>    /* a "<" directly after a name starts a subscript, and its content is not a subscript (3.5) */
```

```rnl error
%p<1, 2>    /* RNL names take no subscript; a point is written (1, 2) (6.11) */
```

### 4.5 標準例句

標準例句是依標準寫法撰寫、並在記號之間加上自由文字使其讀起來像句子的敘述。標準例句用於撰寫指南，以及用於為敘述補上或移除這些字詞的格式化工具。自由文字不影響含義（3.3）：這些例句僅供參考建議，使用者與大型語言模型可以採用、不寫，或改用其他字詞。

- **事實陳述。** 敘述表達圖面上成立的事實，而非要執行的動作。物件作為主詞居首，關鍵字充當動詞或名詞，參數則是其數值。僅加入連接詞語，例如 `is`、`are`、`has`、`is at` 與 `there is`。少數敘述可讀作動作形式，例如 `#M1 @SET-SYMBOL to $NMOS`。
- **詞語由敘述決定。** 工具產生的詞語僅取決於關鍵字、參數、物件數量與種類以及敘述所在的層級，而與電路含義無關。例如，使用 `is` 或 `are` 取決於物件數量；僅指定單軸時會寫出 `the x of`；篩選候選對象的措辭則取決於作用域與所選種類（附錄 B）。這規範的是句子如何產生，並不限制使用者。
- **不寫出似乎暗示語義以外含義的字眼。** 不會寫出 `must`、`required`、`only` 等字詞，且僅當參數帶有方向性時才寫出方向詞語。人類讀者會信以為真，撰寫指南應提醒讀者留意這一點。
- **補充說明。** 讀者可能不熟悉朝向代碼與座標軸。在關鍵字後方可加上 `, i.e., …` 說明該代碼的含義，例如 `#M2 @ORIENT("MX"), i.e., flipped upside down`。
- **ORIENT-RELATION 與 DISTANCE** 各有兩個槽位，讀作 `from A to B`。
- **篩選**一律讀作從候選對象中挑選：`among <candidates>, @SELECT-…`。當作用域為 `#` 時，候選對象讀作 `the <kind> in # only`；當敘述觸及下方層級時，讀作 `the <kind> at each level in # and below`，表示該規則會在每個層級分別評估（10.1、10.4）。當無法推斷種類時，句子讀作 `for X,`。
- **AS 與 ATTACH。** 當物件共同構成該事物時使用 AS：`#M1(left), #M2(right) and #M5(tail) are treated @AS $DIFFERENTIAL_PAIR_N`。當將該事物套加至物件上時使用 ATTACH：`$GROUND is @ATTACH to &vss`（9.4）。
- **管線。** 後段引用前一段的結果。英文會使用 `it`（在 AS、ATTACH 或單一物件之後）或 `they`（在篩選之後）。管線中的命名會在前方加上 `named`，例如 `… => named %pout`；它依然是一個命名（4.2 第 3 項）。
- **命名。** 單一敘述的名稱寫於開頭（4.3）。當為 AS 敘述命名時，英文會省略 `are`：`%dp = #M1(left), #M2(right) and #M5(tail) treated @AS $DIFFERENTIAL_PAIR_N`。
- **集合的名稱。** 指向集合的 `$` 名稱應以 `_SET` 結尾，`%` 名稱應以 `_set` 結尾，例如 `$GROUND_FILL_SET` 與 `%bias_set`；標準套件遵循此慣例。
- **不用 `each`。** 不寫出 `each` 這類詞。集合究竟是整體套用還是逐成員套用，取決於定義的角色列表，標準例句本身並不說明是哪一種。
- **其他語言。** 本標準以英文給出標準例句。其他語言的句子須使用該語言別名套件的別名（例如中文的 `alias-zh`），並遵循該套件的文件（16.5）；在該語言的標點符號之後，`@` 前方仍須留一個空格（2.3）。

每個關鍵字的標準例句列於附錄 B。
