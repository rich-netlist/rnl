## 16 檔案、版本、套件與別名

本章涵蓋檔案的語言版本、套件與套件檔案、標準套件、未知內容以及別名。

### 16.1 版本

```rnl
* @RNL(type="header") { @VERSION("0.4")}
```

- **每個檔案僅有一種語言版本。** 不同版本的 RNL 須寫在不同檔案中，再透過引入結合（6.1）。
- **在檔頭記錄中宣告。** VERSION 僅能寫在檔頭記錄（`type="header"`）中，該記錄為檔案的第一筆記錄（2.8）。版本僅能宣告一次，因此一個檔案絕不會有兩個版本值。寫在其他任何位置的 VERSION 皆為錯誤並予忽略。
- **讀取順序：**
  1. 宿主配接器提供註解；
  2. 依外層形式切分出所有記錄並讀取其記錄標頭；此步驟不依賴版本；
  3. 當第一筆記錄為檔頭記錄時，讀取其 VERSION；
  4. 其餘記錄皆依該版本進行剖析。
- **不隨版本變動的部分。** 註解載體、`@RNL` 入口、記錄標頭的形式以及檔頭記錄中 VERSION 的形式在任何後續版本中皆不更改；否則剖析器將無法找到版本。支援新宿主僅新增載體，不改變既有載體（2.2）。檔頭記錄的其餘部分則依宣告的版本讀取。
- **無檔頭記錄。** 檔頭記錄可以省略，其中的 VERSION 亦可省略。此時被引入檔案沿用引入它的檔案之版本；主檔案則採用工具的預設版本，並給出一條提示。工具在儲存檔案時必須寫出檔頭記錄與版本，因此手寫檔案可以省略它們，而工具寫出的檔案必然包含它們。套件檔案必須擁有檔頭記錄（16.2）；若未寫 VERSION，則如主檔案般採用工具的預設版本。內嵌套件使用撰寫它之檔案的版本（16.2）。
- **不受支援的版本。** 當工具不支援某檔案的版本時，該檔案中的 RNL 一律不予解譯、回報一項錯誤，並在儲存時原樣保留該檔案；其他檔案仍照常解譯。
- 實作必須宣告其支援的版本（原則 2.3）。語言版本、套件版本（USE-PACKAGE 的 `version=`）與宿主版本是三件不同的事。套件版本的寫法與匹配規則見 16.2。本版本的檔案僅能使用本版本的套件：宣告其他語言版本（或未宣告而依較早版本讀取）的套件檔案或別名套件，會在直接或透過其他套件觸及它的 USE-PACKAGE 或 USE-ALIASES 處構成錯誤（16.2、16.5）。
- **版本號。** 版本寫作 `"major.minor"`：兩個無符號十進位整數，例如 `"1.0"` 或 `"1.2"`。沒有修訂號（patch number）、日期或規範子集（profile）。`"1.0"` 之前的版本為草案，寫作 `"0.minor"`；0.x 各版本之間不保證彼此相容，且各自視同獨立的主版本。格式錯誤的版本（例如 `"1"` 或 `"v1.2"`）依不受支援的版本處理，而非視作缺漏版本，以免檔案遭誤用其他版本讀取。
- **檔案依其宣告的版本讀取。** 工具必須知道每個標準詞彙是在哪個版本加入的：在宣告較早版本的檔案中，較晚加入的詞彙不是標準詞彙。因此較晚加入的標準子物件名稱不會影響舊檔案中同拼寫的 key（6.5），新加入的屬性名稱不會影響同名的宿主參數（13.6），且 AS 與 ATTACH 新加入的標準參數也不會影響同名的定義參數（9.4）。
- **在同一主版本內，新的次版本僅新增內容而不改變含義。**
  - 允許：新增關鍵字、參數、參數值、標準詞彙、子物件名稱與屬性名稱；為原本會失效的寫法賦予含義。附錄 C 的項目以及本標準稱為純粹放寬限制的改動皆屬此類，將原本會導致整份解譯失效的情況（1.5 第 3 項）改為容錯亦同。
  - 若無新主版本則不允許：改變合法寫法的含義；移除任何內容；更改預設值；將原本合法的寫法變成錯誤。
  - 舊檔案在較新工具中維持原有含義。在較舊工具中，較新檔案裡屬於舊版已有的部分照常讀取，新增的部分則視為未知內容（16.4），並給出警告說明檔案版本高於工具所支援的版本。該工具亦可選擇不繪製該檔案，但絕不得假裝理解它。
- **不同的主版本。** 工具不支援的主版本檔案不予解譯並原樣保留（見上文）。其套件亦不使用：該檔案的 RNL 一概不予解譯，檢視器以其自身的預設外觀繪製網表，並回報不支援該版本。工具可以支援多個主版本。將檔案移至新主版本屬於明確的升級遷移，由工具改寫檔案與其檔頭記錄；工具絕不得默默以新主版本的規則讀取舊檔案。本標準的每個新主版本皆附帶遷移說明。
- **支援的版本。** 工具對每個主版本皆須說明其支援至哪個次版本，例如 `"1.0"`–`"1.3"`。支援 `"1.3"` 即表示同時能讀取 `"1.0"` 至 `"1.2"`。
- **提高版本。** 當工具在檔案中寫入僅較新版本才有的寫法時，須提高檔頭記錄中的版本。在此之前，工具須檢查這段期間新增的標準詞彙是否與檔案中既有名稱（文字的 key、角色名稱、定義參數、宿主參數）拼寫相同，並對每個此類名稱給出警告，因為提高版本可能改變其含義；版本仍照常提高。
- **0.3 版與 0.2 版。** 本版本取代 0.3 版。0.3 版與 0.2 版的檔案屬於其他主版本（見上文），本標準不予描述。它們透過能讀取 0.3 版的升級工具遷移至 0.4 版：工具提高版本號、將檔案移至標準系列 0.4 並在檔頭記錄寫入 `@USE-PACKAGE(name="rnl-std-all", version="0.4")` 以取代原處釘選的標準套件版本、依附錄 D 改寫檔案，並回報無法自動改寫的內容（例如使用了 0.4 系列已移除的定義）。

### 16.2 套件與 USE-PACKAGE

```rnl fragment
@USE-PACKAGE(name="acme-style", version="1.2");                               /* looked up in the package directories of the tool */
@USE-PACKAGE(name="acme-style", version="1.2", path="lib/acme-style.rnl");    /* reads this package file */
@USE-PACKAGE(name="acme-style", version="1.2") {…}                            /* an inline package */
```

**套件在何處生效。**

- 套件中的 `$` 定義在寫有其 USE-PACKAGE 的層級及其下方各層級生效。套件的規則視同寫在該層級：它們作用於該層級，且唯有透過自身篩選中的 `recursive=true`——或若無篩選，透過它們所使用的集合（10.1、10.4）——觸及下方層級時，才作用於下方層級。本版本沒有僅作用於自身層級的 USE-PACKAGE。寫在子電路中時，套件僅作用於該子電路；寫在檔案層級時，作用於該檔案的子電路及其引入的檔案（6.1）；寫在檔頭記錄中時，作用於與檔案層級相同的層級，但置於根層級（16.3）。
- 根層級的套件，無論是寫在檔頭記錄中還是透過工具設定加入（16.3），皆視同在檔案的頂層使用：在主檔案中即其頂層。因此檔頭記錄中使用的風格體系套件規則唯有加上 `recursive=true` 才能觸及子電路，如同標準套件的寫法。
- **在順序中的位置。** 套件的內容置於其 USE-PACKAGE 的位置，套件內部則依其文字順序排列，如同從定義展開的事實取其 AS 或 ATTACH 敘述的位置。衝突取捨（8.5）與外觀佇列（8.3）皆使用此位置。寫在某層級各敘述之前的套件作為一組預設值運作；寫在它們之後的套件則可藉規則覆寫較早的敘述。檔頭記錄中的 USE-PACKAGE 置於根層級（16.3）。

**套件中的名稱。** 僅有位置跟隨 USE-PACKAGE；套件的名稱仍保持獨立。

- 套件中的名稱會依序在以下範圍查找：先在套件自身的定義中、其次在它所引用的套件中（見下文「引用其他套件的套件」）、最後在該 USE-PACKAGE 所在層級生效的標準套件中。它不會在該層級或上層級的使用者定義中查找，也不會在其他套件中查找；如同定義本體（6.9），USE-PACKAGE 所在層級中的同名定義不會擷取它。因此內嵌套件（inline package）查找名稱的方式與內容相同的套件檔案完全一致，其文字可直接移出成為套件檔案；而套件檔案亦可搭配工具設定加入的標準套件單獨檢查（16.3）。標準套件及其直接或間接引用的套件僅能看見自身及它們所引用的套件，看不見標準套件自身，以免查找形成迴圈。
- 套件中的 `$` 定義為公開定義，且視同屬於 USE-PACKAGE 所在層級的上一層級：該層級中的同名定義會遮蔽套件的定義並給出提示（6.8），而不構成同一層級的重複綁定。當套件的 `$` 定義遮蔽了上層級或根層級套件的定義時，同樣會給出提示（6.8）。
- 套件中的 `%` 定義為該套件私有。

**套件的內容。**

- 套件容納定義、`$` 集合與規則。套件檔案的檔頭記錄容納 VERSION 與 PACKAGE，亦可容納作用於使用該套件之層級的 USE-PACKAGE、DEVICE（6.12）與 SOLVER-CONFIG（14.10），以及僅作用於該套件檔案自身的 ALIAS 與 USE-ALIASES（16.5）。USE-PACKAGE 引用其他套件（見下文），且可在僅針對一種語言的檔頭記錄中使用（2.8）。別名套件是僅含檔頭記錄的套件檔案，以 USE-ALIASES 載入（16.5）。
- 套件本身沒有電路，如同被引入檔案的檔案層級（6.1）：
  - 點名特定宿主物件的敘述（`#M1`、`&vss`、`#:inp`）會失效；單獨的 `#` 仍代表正在評估規則的層級，在一般定義的定義本體中亦然（9.4）；
  - 非規則且繪製單一場景物件的敘述（如 `(0, 0) @RECTANGLE …`）沒有可繪製於其中的層級，構成錯誤；
  - 在記錄標頭中使用 `scope=` 與 `type="generated"` 構成錯誤（2.8）；
  - 在套件的檔頭記錄以外的記錄中使用 USE-PACKAGE 構成錯誤：對其他套件的引用僅能寫在檔頭記錄中。
- 內嵌套件的定義本體遵循相同規則，但沒有檔頭記錄：套件的名稱與版本即為其 USE-PACKAGE 的參數，而 DEVICE 與 SOLVER-CONFIG 須寫在檔案自身的檔頭記錄中。內嵌套件不能引用其他套件；若要將一個套件集合凍結進檔案中，須依序將其展開後的內容寫入定義本體，並做相應修改以維持原意（16.3）。

**套件檔案。** 套件檔案的讀取方式見 2.7 及其範例。其檔頭記錄以 `@PACKAGE(name=…, version=…)` 宣告該檔案屬於哪個套件與哪個版本；沒有 PACKAGE 的檔案不是套件，對其使用 USE-PACKAGE 構成錯誤。一個套件即是一個檔案：若將一個套件拆成多個檔案便需要訂定它們之間的順序，本版本不提供此機制。套件檔案以 VERSION 宣告其語言版本，該版本必須與使用它的檔案之語言版本相同（16.1）；否則該 USE-PACKAGE 構成錯誤，且使用該套件名稱的敘述會因找不到名稱而失效。

**查找。**

- 帶有定義本體的 USE-PACKAGE 是內嵌套件，不進行查找。
- 帶有 `path=` 時，讀取該指定檔案。路徑相對於撰寫該 USE-PACKAGE 的檔案所在目錄，以 `/` 為分隔字元；它指定本機檔案，而非 URL。當該檔案不存在，或其 PACKAGE 命名了另一個套件或依下文規則不接受的版本時，改依名稱查找該套件，並給出一條警告。當該檔案存在但不是套件（缺少 PACKAGE，或 PACKAGE 中的 `version=` 寫法錯誤）時，該 USE-PACKAGE 失效，如同對任何非套件檔案的做法（見上文）。
- 其餘情況下，依套件的名稱與其 PACKAGE 的版本在工具所設定的套件目錄中查找。標準套件隨工具內附或安裝於套件目錄中。套件目錄是工具的設定，不寫在檔案中；若有多份相同版本的複本，由該設定中的目錄順序決定。
- 診斷訊息會說明實際使用了哪個檔案與哪個版本。
- 找不到套件時，USE-PACKAGE 失效（一項錯誤），使用該套件中名稱的敘述隨之失效（7.3）；診斷訊息指出缺少的套件作為原因。
- `name=` 為必填。它依完整字串比較並區分大小寫；套件名稱應使用小寫字母、數字與 `-`。
- 搭配 `path=`，網表與其套件檔案可放在一起並作為整體搬移；本版本沒有對應的清單（manifest）格式。

**套件版本。**

- 套件版本的寫法與語言版本相同，為 `"major.minor"`；每個 0.x 各自視同獨立的主版本（16.1）。
- 若寫出的版本存在，則使用該版本。否則使用同一主版本中較新的版本裡最小的那一個，並給出警告說明套件版本不同、繪圖結果可能隨之不同；當該主版本只有較舊版本或毫無版本時，視作找不到套件。不使用較舊版本，因為它可能缺少名稱。以 `path=` 指定的檔案依相同規則檢查。
- 未寫 `version=` 時，使用找到的最新版本，並給出一條提示。在 USE-PACKAGE、USE-ALIASES 或 PACKAGE 中，未依 16.1 規定寫出的 `version=` 構成錯誤且不進行查找：該 USE-PACKAGE 或 USE-ALIASES 失效，而 PACKAGE 中有此錯誤的套件檔案不是合法套件（見上文）。內嵌套件的 `version=` 僅用於標示版本而不進行查找；但寫法錯誤時同樣構成錯誤，該內嵌套件失效。
- 依名稱與版本找到的套件在一份文件中僅讀取一次：相同版本無論在何處使用皆為同一組定義。套件於使用處查找它所引用的套件以及當前生效標準套件的名稱：它們的版本與內嵌內容依下文規則決定——對於檔案直接使用的套件，取距離該層級最近的 USE-PACKAGE；對於僅經由其他套件帶入的套件，取該層級鏈上的最新版本。當這些對象在兩個使用處之間不同時，該套件會各自讀取一次，這兩次讀取結果屬於不同的定義集合，如同兩個不同版本（9.5）。每個內嵌套件各自為獨立複本：兩個內嵌套件即使文字完全相同亦為不同套件，因此在不同位置看見它們的套件會各自讀取一次。不同版本中的同名定義是兩個不同定義（9.5）；見 16.3 的範例。
- 套件作者應遵循語言的相容規則（16.1）：在同一主版本內，不移除或更改既有的名稱、角色、參數或接腳；繪圖方式可以改變。這是工具無法檢查的約定。
- 本版本沒有套件內容摘要（如 USE-PACKAGE 的 `digest=` 參數）。若要讓繪圖完全維持不變，請鎖定版本，或將套件內嵌寫入檔案中。記錄標頭中的 `hash` 如何計算由工具決定（第 17 章）。

**引用其他套件的套件。** 套件可以引用其他套件，以便將大型套件拆分為多個部分並組合成不同大小；標準套件便是以此方式建構（16.3）。檔頭記錄以外沒有內容、僅引用其他套件的套件檔案稱為**套件集合（package collection）**；本標準通常仍簡稱其為套件。

- **形式。** 在套件檔案的檔頭記錄中，為每個引用的套件寫出一條 `@USE-PACKAGE(name=…, version=…)`。`path=` 相對於該套件檔案所在目錄；查找與版本規則同上。引用不得帶有定義本體；帶有定義本體構成錯誤，因為內嵌內容沒有版本，無法參與選擇最新版本（見下文）。
- **順序。** 使用一個套件時，其檔頭記錄所引用的套件會先依引用順序展開並排在它之前；被引用套件若又引用其他套件，亦先依相同方式展開。隨後才是該套件自身的內容。在單一次展開中，每個套件僅於首次出現的位置置入一次。因此套件集合的內容即為它所引用各套件依序展開的內容。
- **名稱。** 被引用套件的 `$` 名稱在引用它的套件中可見，並傳遞給該套件的使用者；與套件自身的 `$` 名稱一樣，它們視同屬於 USE-PACKAGE 所在層級的上一層級。當多個被引用套件皆定義了 `$X` 時，較後的引用遮蔽較早的引用，而套件自身的定義遮蔽它們全部；每次遮蔽皆給出提示，與同一層級使用多個套件相同。本版本不區分「僅供套件自身使用的引用」與「傳遞給使用者的引用」。`%` 名稱維持各套件私有。
- **僅一個版本生效。** 套件依名稱去重，如同下文「哪個 USE-PACKAGE 生效」，包含透過其他套件帶入者，並在展開位置去重。
  - 對檔案直接使用的套件而言，檔案中距離該層級最近的 USE-PACKAGE 連同其版本與內嵌內容生效（如同下文「哪個 USE-PACKAGE 生效」），即使其他套件也引用了該套件亦然。當其主版本與引用它的套件所要求的版本不同時，會給出警告：引用方套件可能會用到該版本所沒有的名稱。
  - 對僅透過其他套件帶入的套件而言，在一條層級鏈的所有引用中，取同一主版本內的最新版本；若版本不同則給出一條提示；在同一主版本內較新版本只會新增內容，因此亦能滿足較早版本的引用。屬於不同主版本的引用構成錯誤：較後展開的引用失效，使用該套件中名稱的敘述亦隨之失效（7.3）。
- **取代或移除其中之一**直接依循「僅一個版本生效」的規則，無須額外規定。同名的空內嵌套件會將其移除，例如 `@USE-PACKAGE(name="rnl-std-fill") {}` 即關閉自動補齊；同名的另一版本或其他內嵌內容則取代它。當某個被移除的套件仍被其他套件使用時，那些套件中使用其名稱的敘述會失效。
- **循環引用。** 形成循環的引用構成錯誤，關閉該循環的那條引用失效。哪一條引用構成關閉取決於展開起點；若直接使用了循環中的多個套件，則對其中每一個各回報一次循環。
- **診斷於何處回報。** 版本不同的提示與主版本不同的警告皆回報於檔案中所寫的 USE-PACKAGE 上（套件內部的提示與警告不顯示給使用者，7.6）。失效引用的錯誤則回報於該引用本身，並說明檔案中是哪一條 USE-PACKAGE 帶入它的。
- 別名套件不能被引用（16.5）。套件檔案檔頭記錄中的 USE-ALIASES 照常僅作用於該檔案本身。

**多個套件定義同一個 `$` 名稱。**

- 當同一層級使用的多個套件皆定義了 `$X` 時，較後使用的遮蔽較早的，並給出一條提示。
- 名稱依以下順序查找：本層級 → 本層級使用的套件（較後者優先）→ 上一層級 → 上一層級使用的套件 → … → 根層級的套件（較後置入者優先）。
- 本版本沒有套件限定名稱、套件別名或層級標籤（如 `$acme.DIFFERENTIAL_PAIR` 或 `as=`）。附註：後續版本若新增此類寫法，須使用名稱後方接 `.` 以外的形式，因為該字元常用於句尾（`align #M1 and #M2.`）。

**哪個 USE-PACKAGE 生效。** 在從根層級到某一層級的層級鏈上，每個套件僅生效一次。寫在距離該層級最近之層級中的 USE-PACKAGE 連同其版本與內嵌內容生效；在同一層級內，較後者視為較近，而寫在檔頭記錄中者視同寫在檔案層級的最開頭。透過其他套件帶入的套件視同寫在帶入它的 USE-PACKAGE 處，其版本依上文「引用其他套件的套件」選擇。套件置於該 USE-PACKAGE 的位置；若該 USE-PACKAGE 位於檔頭記錄中，則置於根層級。

附註：否則套件中的產生規則（例如接地自動補齊）便會在下層級再執行一次並重複產生兩份物件。

**再次使用套件。** 子電路或程式庫檔案可以在其檔案層級或子電路內部再次使用標準套件。此時標準套件的外觀規則會排在從上層級（例如主檔案）流下的規則之後並再次覆寫它們，且該套件的 `$` 名稱視同屬於該 USE-PACKAGE 所在層級的上一層級，從而遮蔽來自上層級的同名定義。如此一來，本層級所使用的符號便不受上層級外觀規則的影響（6.1）。

- 這僅影響符號與名稱。從上層級流下的幾何規則與產生規則依然適用；若它們導致既有求解結果過時，會給出重新求解的提示（第 17 章）。
- 若只想鎖定版本，同時仍讓上層級的風格體系覆寫套件，請將 USE-PACKAGE 寫在檔頭記錄中（16.3）。

**內嵌套件。** USE-PACKAGE 可以帶有定義本體，即為該套件的內容。此時檔案自身攜帶該套件，不進行任何查找：

```rnl
@USE-PACKAGE(name="acme-style", version="1.2") {
  $NMOS_ACME = @DEFINE-SYMBOL {$NMOS; (-1, 0) @CIRCLE(radius=2.5)};
  # @SELECT-INSTANCE(type="nmos", recursive=true) => @SET-SYMBOL $NMOS_ACME
}
```

- 內嵌套件的含義與不帶定義本體的 USE-PACKAGE 相同：套件的名稱與版本、位於該 USE-PACKAGE 處的位置、依「套件中的名稱」進行的名稱查找、視同上一層級的 `$` 名稱、私有的 `%` 名稱，以及依套件名稱去重的「僅一個版本生效」規則，全都適用。定義本體依封裝方式消耗輸入（5.4）。內嵌套件具有撰寫它之檔案的語言版本（16.1）。
- 內嵌套件與套件檔案的差異僅在於：其內容直接寫在網表中，且沒有檔頭記錄——它的語言版本即檔案版本、其 `version=` 僅用於標示版本、它不能宣告 DEVICE、SOLVER-CONFIG 或 ALIAS，也不能引用其他套件。每個內嵌套件各自為獨立複本。因此將內嵌套件移出成為獨立檔案時，名稱的查找方式不變，但定義的身分未必相同：當文件中已經使用了同名同版本的套件檔案時，兩者會合併為同一組定義（見上文），使得依定義選取的規則（如 SELECT-USAGE，9.5）可能觸及更多用例。
- 內嵌套件通常僅用於兩件事：以同名的空內嵌套件移除某個套件（16.3），以及將整套套件展開後的完整內容寫入定義本體，使其自成一體並凍結於檔案中。
- 若要擴充標準套件或取代其中一部分，請撰寫一個在其檔頭記錄引用所使用標準套件的套件檔案並加入自身內容（16.2「引用其他套件的套件」），再從網表以 `path=` 指向它。帶有內容並取代標準套件某個子套件的內嵌套件視同標準套件的一部分，僅能看見自身：它無法使用標準套件其他子套件中的名稱。

**其他規則。**

- 處理套件時不得執行程式碼或隱式存取網路（原則 2.7）。
- 檢視器如何顯示繪圖，以及是否能依使用者偏好（如深色背景或列印）更改外觀，不在本標準範圍內。未獲任何樣式或參數賦值的屬性採用渲染器的預設值（9.3、原則 2.7）。

### 16.3 標準套件

- 標準套件不屬於本語言標準。它如同其他套件一樣以 RNL 撰寫並另行發布；其語義定義、虛擬組件與其他內容由該套件自身定義。
- 標準套件中的名稱沒有強制前綴，如 `$DIFFERENTIAL_PAIR_N`。使用者可以撰寫同名定義，藉由遮蔽來取代標準定義（6.8）。
- **套件集合。** 標準套件 `rnl-std-all` 僅含檔頭記錄：它是該系列唯一的集合，引用了除下文兩項選用套件之外的整個系列所有套件。檔案可使用整個集合，或逐一寫出所需的套件。
  - `rnl-std-style`（樣式與預設樣式規則）、`rnl-std-basic` 與 `rnl-std-semiconductors`（符號與定義，含接地、電源與連接埠標記等虛擬組件，以及接地、電源與偏壓網路集合），以及兩種方言的規則套件，用於為實例指派符號：`rnl-std-spice` 依元素字母與模型類型、`rnl-std-spectre` 依 master 與模型類型（見下文方言說明）。這些套件僅繪製網表而不額外加入任何內容。`rnl-std-basic` 的檔頭記錄包含 `@SOLVER-CONFIG(junction="$JUNCTION")`，使求解器以標準定義繪製交接圓點（13.2、14.10）。
  - `rnl-std-fill` 包含為無連線接腳加上接地、電源、偏壓標記與網路標籤的規則，各自畫在一段短樁上（10.5）；它引用 `rnl-std-basic`。它選取接腳，因此虛擬組件在網路上的接腳亦會被補齊，唯獨它自身所擺放組件的接腳除外。在 0.4 系列中它為 `$PORT_FILL_SET` 中的每個連接埠網路加上連接埠標記，每個層級排成一欄（12.4）；任何網路除非檔案或套件以 ROUTE-NET 或 ROUTE-OBJECT 指明，否則不繪製為連線；接地、電源與偏壓網路皆以 `@UNROUTE-NET(priority="high")` 排除，若檔案想要將它們繪製為連線，須寫出 `@ROUTE-NET(priority="high")` 或 WIRE（13.7）。已有連線（無論手工撰寫或由 ROUTE-NET / ROUTE-OBJECT 繪製，無論寫作敘述或規則）的接腳不會從自動補齊獲得接地或電源符號；若檔案想要，須自行附掛（10.5）。走線關鍵字的規則在自動補齊之前評估，因此自動補齊能看見它們建立的走線樹（8.2、10.2）。集合 `$GROUND_FILL_SET`、`$SUPPLY_FILL_SET`、`$BIAS_FILL_SET`、`$LABEL_FILL_SET` 與 `$PORT_FILL_SET` 保存自動補齊尚待加上的內容：一旦求解將其短樁與標記寫回（14.8），它們便不再保存那些接腳與網路，因此檔案不應在它們之上建立其他規則，例如對其接腳的 TEXT。
  - `rnl-std-semantics` 包含電路結構（如差動對、電流鏡、訊號流與功率流）與佈局（如 `$MIRRORED_LAYOUT`）的定義；其定義本體中的約束優先順序皆為 `"low"`（9.5、14.8）。只進行擺放、既不作斷言也不進行走線的定義對電路不說明任何事物，其名稱以 `_LAYOUT` 結尾，如 `$MIRRORED_LAYOUT`。結構名稱末尾的 `_N` 與 `_P`（如 `$DIFFERENTIAL_PAIR_N` 與 `$CURRENT_MIRROR_P`）給出其電晶體的極性——結構會對類型已知的電晶體斷言該極性（15.3）——並給出與之相配的畫法：n 型電晶體的源極或射極朝下，p 型電晶體的源極或射極朝上。
  - 特定領域的套件為 `rnl-std-functional`（放大器、比較器、轉換器等）、`rnl-std-rf`、`rnl-std-logic` 與 `rnl-std-signal-flow`。
  - 各套件中的名稱互不重複，因此使用者無須知道某個名稱來自哪個套件。
  - 選用套件 `rnl-std-45deg` 包含以 45 度繪製的符號，例如橋式電路、交叉耦合對與對角線繞組；它不在集合內，需要的檔案須自行寫出其 USE-PACKAGE。
  - 選用套件 `rnl-std-no-labels` 關閉標準符號的預設標籤，供自行撰寫所有標籤的檔案使用；它不在集合內。在 0.4 系列中它僅選取已繪製的物件（`drawn=true`，10.1），並為其名稱、數值與模型標籤，以及用例的符號所畫出的網路名稱，設定樣式 `textvisible=false`（9.3）；檔案可透過在標籤上寫出 `textvisible=true` 讓其中一個重新顯示（13.3）。選用套件 `rnl-std-no-instance-labels` 僅對已繪製的實例作同樣處理，因此用例的標籤保留，例如接地、電源、連接埠標記與網路標籤所畫出的網路名稱；它同樣不在集合內。後續版本可再新增更多套件。整套標準系列以單一版本號一同發布，且集合中釘選了各子套件的版本。
  - 以上即標準系列 0.4 的結構；其 `rnl-std-all` 為每種語言各設有一筆檔頭記錄（2.8）。
- **不隱式載入。** 0.4 版的檔案唯有透過 USE-PACKAGE 寫出時才會使用標準套件 `rnl-std-all`，與其他任何套件無異（16.2）。工具可以提供一項設定，當主檔案的檔頭記錄未以任何形式寫出 `rnl-std-all` 時自動加入它，例如命令列選項 `--include-std` 或檢視器的設定（可以預設開啟）。當該設定開啟時，工具讀取該檔案時視同其不帶 `language` 的檔頭記錄最開頭寫了 `@USE-PACKAGE(name="rnl-std-all", version="…")`，版本取工具所擁有以該檔案語言版本撰寫的最新標準系列版本；當工具寫入主檔案時，須將該 USE-PACKAGE 寫入其檔頭記錄中，確保任何工具都能以相同方式繪製該檔案。寫在某個檔案檔頭記錄中的釘選版本則作用於該檔案及其引入的檔案（見下文）。
  - 附註：標準套件只是普通套件。未針對 RNL 撰寫的網表僅能透過這類工具設定取得標準符號繪製；而使用了標準套件定義（如 `$GROUND`）的檔案必須寫出 USE-PACKAGE，否則會找不到這些名稱。每個找不到的名稱照常為錯誤；若未使用的標準系列套件定義了該名稱，則針對該檔案給出一次提示，指明該套件並提示使用 USE-PACKAGE 及工具設定。
- **另一種方言的規則套件。** 實例名稱在兩種方言中有不同含義：在 SPICE 中，`I0` 是電流源；在 Spectre 中，實例名稱不代表任何種類，而 Virtuoso 習慣將子電路實例命名為 `I0`。標準系列 0.4 透過 `language` 表達這點：其集合 `rnl-std-all` 含有一筆不帶 `language` 的檔頭記錄（供兩種語言共用）、一筆 `language="spice"` 的檔頭記錄引入 `rnl-std-spice`，以及一筆 `language="spectre"` 的檔頭記錄引入 `rnl-std-spectre`（2.8）。因此 Spectre 檔案中的 SPICE 區段會依 SPICE 規則尋找符號，Spectre 區段則依 Spectre 規則尋找。
  - 凍結 0.4 系列的工具有將每種語言的部分寫成對應語言檔頭記錄中的內嵌套件，並將共用部分寫在不帶 `language` 的檔頭記錄中的做法；內嵌套件容納敘述而非記錄，本身不能帶有 `language`。
- **根層級套件。** 主檔案或被引入檔案（包含 Verilog-A 檔案，2.9）的檔頭記錄皆可包含 USE-PACKAGE：

  ```rnl
  * @RNL(type="header") { @VERSION("0.4"); @USE-PACKAGE(name="rnl-std-all", version="0.4")}
  ```

  - 其作用範圍與檔案層級的 USE-PACKAGE 相同：寫出它的檔案及其引入的檔案。寫在被引入檔案中者作用於該檔案及其進一步引入的檔案，而不作用於引入它的檔案（6.1）。
  - 它置於根層級：排在所有層級的規則之前，亦排在方塊符號之前（8.3，第 1 組）。它的 `$` 名稱同樣位於根層級，因此某層級（如主檔案）中的同名定義仍會遮蔽它。相對地，寫在檔案層級的 USE-PACKAGE 則置於其自身所在位置：它屬於再次使用該套件（16.2），因此會覆寫自上層流下的規則，其 `$` 名稱視同屬於上一層級。寫在檔頭記錄中代表「本檔案依賴此版本，但上層級的風格體系仍可覆寫它」；寫在檔案層級中則代表「本檔案以此套件設定自身的繪圖」。
  - 哪個 USE-PACKAGE 生效依 16.2 判定：取距離本層級最近者，其中寫在檔頭記錄者視同寫在檔案層級的最開頭。
  - 根層級套件的順序：標準套件 `rnl-std-all` 排在最前（無論是哪個檔頭記錄寫出，或由工具設定加入），其餘套件則依首次寫出它的檔案順序（由最外層檔案向內）及該檔頭記錄內的順序排列。當內層檔案的檔頭記錄再次寫出同一個套件時，僅改變該檔案各層級使用的版本或內嵌內容；位置保持不變，因此釘選版本不會改變順序。
  - 檔頭記錄中的套件若定義了標準套件或排在它之前之根層級套件的 `$` 名稱，會遮蔽該定義並給出一條提示（6.8）。
  - 是否釘選版本由撰寫者決定。主檔案應釘選版本。未釘選版本的被引入檔案沿用引入它的檔案之版本；僅當它確實依賴特定版本時才應釘選版本。工具不得自行為被引入檔案加上版本，除非是從舊版升級檔案時寫入的釘選版本（16.1）。
  - 不應在主檔案的檔案層級以 USE-PACKAGE 釘選版本：該處的套件會排在方塊符號之後，且當該檔案被引入他處時，該 USE-PACKAGE 會成為再次使用套件（16.2），進而改變檔案原意。
- **範例。** `tb.sp` 的檔頭記錄寫了 `@USE-PACKAGE(name="rnl-std-all", version="1.2")`，而被 `tb.sp` 引入的 `ota.sp` 則寫了版本 `"1.0"`。
  - `tb.sp` 的頂層與定義於 `tb.sp` 中的子電路使用 `"1.2"`；`ota.sp` 中的子電路使用 `"1.0"`。`tb.sp` 的樣式規則依然流向 `ota.sp` 並覆寫 `"1.0"` 的預設值。
  - 預設選擇由標準套件內的規則完成，例如為 `$GROUND` 的用例指派接地符號的規則。每個版本在各自生效的層級中選取其自身的 `$GROUND`，因此 `ota.sp` 照常繪製。
  - 兩個版本中的同名定義屬於兩個不同定義（16.2）。因此 `tb.sp` 中依定義選取的規則（例如 `# @SELECT-USAGE(recursive=true) $GROUND => @SET-SYMBOL $MY_GND`）僅會找到 `"1.2"` 之 `$GROUND` 的用例；唯有當 `ota.sp` 未自行釘選版本時才會跟隨該規則。依宿主屬性選取的規則（例如 `# @SELECT-INSTANCE(type="nmos", recursive=true) => …`）則不受影響。
  - 若要使其符號不受 `tb.sp` 規則的影響，`ota.sp` 須在其檔案層級使用該套件（16.2）。
- **使用標準套件的一部分。** 工具設定僅加入套件名稱 `rnl-std-all`。
  - 若要略去部分套件，可用同名的空內嵌套件將其移除：`@USE-PACKAGE(name="rnl-std-fill") {}` 即關閉自動補齊。同名稱的套件僅生效一次，絕不生效兩次。
  - 若要僅使用少數幾個套件，須逐一寫出，並加上空的 `rnl-std-all`，以免工具設定又加入整個集合：

  ```rnl
  * @RNL(type="header") {
  *   @VERSION("0.4");
  *   @USE-PACKAGE(name="rnl-std-all") {};
  *   @USE-PACKAGE(name="rnl-std-style", version="0.4");
  *   @USE-PACKAGE(name="rnl-std-basic", version="0.4");
  *   @USE-PACKAGE(name="rnl-std-spice", version="0.4")
  * }
  ```

- **擴充標準套件或取代其中一部分。** 撰寫一個套件檔案，在其檔頭記錄引用所使用的標準套件並加入自身內容（16.2，內嵌套件）。僅對標準套件進行增補的定義與規則亦可直接寫在網表中；標準套件已有的規則則唯有透過同名套件才能移除或取代。
- **凍結或移除整個標準套件。** 在檔頭記錄中寫出同名的內嵌套件。這直接依循依套件名稱去重的「僅一個版本生效」規則，無須額外規定：
  - `@USE-PACKAGE(name="rnl-std-all", version="1.2") {…}` 將標準套件凍結進檔案中，使檔案自成一體；定義本體為其各子套件展開後的內容，依展開順序前後相接（16.2）。併入同一個定義本體後，兩個套件之間可能發生名稱衝突：兩者都使用了相同的私有 `%` 名稱，或其中一個的 `$` 名稱遮蔽了另一個。執行凍結的工具會重新命名衝突的名稱，確保每個引用仍找到原先在各自套件中所指向的對象，並將被凍結套件檔頭記錄中的 DEVICE 與 SOLVER-CONFIG 敘述依序寫入檔案的檔頭記錄中、排在檔案自身的敘述之前（2.8、6.12、14.10），因為內嵌套件不能容納它們：各別寫入與該套件使用路徑對應語言相同的檔頭記錄中，若未經由特定語言使用則寫入不帶 `language` 的檔頭記錄中；僅透過帶有 `language` 的檔頭記錄使用的套件，其 SOLVER-CONFIG 不予複製，因為它不產生效果（14.10）。這些複製出的敘述隨即排在比被凍結套件更晚使用的套件之後。當這類套件寫出了與複製項相同的 SOLVER-CONFIG key，或為複製之 DEVICE 也匹配的實例寫出了 DEVICE 項目（端子名稱或類型）時，若該套件使用於同一檔案的檔頭記錄中，工具會將該敘述寫入持有衝突複製項的檔頭記錄中（排在該複製項之後、檔案自身敘述之前）；若使用於被引入檔案或某層級中，則回報該衝突。除所回報的衝突外，凍結後的套件含義不變；
  - `@USE-PACKAGE(name="rnl-std-all") {}` 不使用標準套件，即使工具設定本會加入時亦然；此時每個實例皆採用預設方塊符號（9.2.6），其餘外觀則交由渲染器的預設值決定（原則 2.7）。
- 粗線匯流排、匯流排的分接符號以及匯流排寬度標記等慣例同樣屬於標準套件的內容。沒有標準套件時，每個實例皆採用預設方塊符號（9.2.6），繪圖樣式由渲染器決定（原則 2.7）。

### 16.4 擴充與未知內容

- **未知內容**（原則 2.3）。未知的關鍵字、參數與數值皆為錯誤：所在敘述失效，依賴它的敘述隨之失效（5.5、7.3），其餘部分照常解譯（7.6）。記錄標頭的未知欄位是例外，僅給出警告（2.8）。在 SOLVER-CONFIG 中，求解器不認識的 key 給出警告，不被接受的值只使其 key 失效（14.10）。此時繪圖可能不完整，診斷訊息必須說明此事。
- **儲存時保留。** 原則 2.3 建議原樣保留這類內容；本標準強制要求：
  - 不屬於該工具的記錄不予更改（第 17 章），宿主文字與一般註解亦原樣保留；
  - 當工具改寫自身記錄時，其中它不認識或失效的敘述須連同其自由文字依原順序原樣保留；
  - 不支援版本的檔案須完全原樣保留（16.1）；
  - 工具改寫的記錄不要求逐位元組完全相同。
- **本版本沒有擴充機制。** 新的語義、虛擬組件與繪圖方式在套件中寫成定義、符號與樣式（1.5 第 7 項），而非新增關鍵字；需要實作理解的新機制留待本標準的新版本。工具的私有資料（如編輯器的鎖定狀態或檢視狀態）不寫入 RNL 記錄；請存放在工具自身的檔案中，或寫在記錄之外的一般註解裡。
  - 附註：本版本先確保所有工具讀取同一套 RNL；過早出現廠商方言會分裂語言，而新語義已可在套件中撰寫。
  - 附註：後續版本可能會以帶有廠商前綴與 `.` 的關鍵字（如 `@ACME.ROUTE`）於檔頭記錄宣告並新增擴充功能：工具不認識的必要擴充會使整份檔案不予解譯，選用擴充則會略過並給出提示。此類關鍵字在目前為未知關鍵字（錯誤），因此日後新增屬於純粹放寬限制（16.1）；廠商前綴不得使用標準關鍵字的名稱。
- 不為擴充保留任何形式：緊接在標準關鍵字後的 `.` 為自由文字，因此 `@BUNDLE.LOCK` 是 BUNDLE 後接自由文字 `.LOCK`，而句尾的 `{#M1 #M2} @GROUP.` 亦屬合法（3.5）。
- **可辨識但不解譯。** 在本版本中屬於此類的內容為記錄標頭的未知欄位（2.8），以及求解器不認識的 SOLVER-CONFIG key（14.10）。若後續版本新增擴充功能，選用擴充將成為第二類。

### 16.5 別名

```rnl
* @RNL(type="header") {
*   @VERSION("0.4");
*   @USE-PACKAGE(name="rnl-std-all", version="0.4");
*   @USE-ALIASES(name="alias-zh");
*   @ALIAS("@at", "@PLACE")
* }
* @RNL {#M1 @位于(10, 20); {#M1 #M2} @对齐("y"); #M3 @at(x=4); #M1(左管) #M2(右管) #M5(尾管) @视作 $"差分对"}
```

- 別名為標準詞彙提供另一種拼寫，以便相容不同大小寫習慣，或以其他自然語言（如中文）的風格撰寫 RNL。
- **別名的來源：**
  - 直接寫在檔頭記錄中的 ALIAS 敘述，用於少數自訂別名；
  - 別名套件，在檔頭記錄中以 `@USE-ALIASES(name=…, version=…, path=…)` 載入。同一語言的別名整理為單一套件，使各檔案無須重複撰寫並保持用詞一致。標準中文別名套件為 `alias-zh`；它隨標準套件一同發布並內附於工具中（16.3）。
  - 兩者可同時使用，亦可載入多個別名套件；所有別名須一併接受下述對應規則檢查。
  - 別名僅作用於宣告它的檔案，不會透過引入繼承；使用別名的被引入檔案或套件檔案須在自身的檔頭記錄中宣告。同一個標準詞彙在不同檔案中可擁有不同別名。寫在符號中的文字 key 依撰寫該符號之檔案的別名檢查（6.5、13.3）。
  - 檔頭記錄自身一律以標準拼寫讀取，不辨識別名：在讀取 USE-ALIASES 與 ALIAS 之前尚未得知別名，且檔頭記錄多由工具寫出。因此為僅能寫在檔頭記錄中的關鍵字（VERSION、ALIAS、USE-ALIASES、DEVICE、PACKAGE）宣告別名毫無用處。
- **別名套件：**
  - 別名套件是一個套件檔案（16.2），其檔頭記錄僅包含 VERSION、PACKAGE 與一組 ALIAS 敘述，且不含其他任何記錄。其查找與版本選擇方式同 16.2。
  - 對非別名套件的檔案使用 USE-ALIASES，或對別名套件使用 USE-PACKAGE，皆構成錯誤。找不到別名套件時，該 USE-ALIASES 為錯誤，使用其別名的敘述隨之失效（7.3）；診斷訊息指出缺少的別名套件作為原因。
  - 附註：別名套件不以 USE-PACKAGE 載入，因為 USE-PACKAGE 可寫在任意層級、處理定義與規則並依位置排序，而別名決定如何讀取檔案文字，僅能逐檔案生效。兩者分開後，風格體系套件便無法改變檔案文字的讀取方式。
  - 別名套件的內容跟隨它所引用的對象：當標準套件中的名稱變更時，`alias-zh` 隨之更改並提高版本號。
- **形式。** `@ALIAS("alias", "original")`：別名在前。兩個參數為 `alias` 與 `original`，通常依位置傳入；第三個參數 `definition` 僅能依名稱傳入（見下文）。
- **原詞（original）：**
  - 本標準定義的關鍵字或標準詞彙，依其標準拼寫。關鍵字連同 `@` 寫出，如 `"@PLACE"`；其他詞彙則不帶該前綴，如 `"axis"` 或 `"low"`。別名依相同方式寫出：關鍵字的別名帶有 `@`，其他別名則不帶。`@` 用以區分關鍵字與同拼寫的標準詞彙，且別名於文字中須與宣告時完全一致。
  - `$` 名稱。別名與原詞皆須帶有 `$`，如 `@ALIAS("$接地补位集", "$GROUND_FILL_SET")`；於文字中寫作 `$"接地补位集"`（`$` 後的非 ASCII 名稱須加引號，3.6），並讀作 `$GROUND_FILL_SET`。`%` 名稱沒有別名：撰寫者可直接以另一種語言取自己的名稱，而套件中的 `%` 名稱為私有。
  - 定義中的名稱，以 `definition=` 宣告，例如 `@ALIAS("左管", "left", definition="$DIFFERENTIAL_PAIR_N")` 或 `@ALIAS("间距", "gap", definition="$GROUND_STUB")`。此類別名僅在該定義內查找：套用該定義時的角色名稱（`#M1(左管) #M2(right) #M5(tail) @AS $DIFFERENTIAL_PAIR_N`）、透過 AS 與 ATTACH 傳入的參數名稱（`$GROUND_STUB @ATTACH(间距=3) …`），以及透過 `::` 從其用例取用的區域名稱（`%c1::"中点"`）。`definition` 的值本身亦可寫成別名。標準詞彙的別名不在這些地方使用，唯獨 AS 與 ATTACH 自身的參數 `priority` 例外。
    - 這類別名跟隨該名稱：它們依附於該 `$` 名稱，且當較低層級以同名定義遮蔽原定義時依然適用，如同 `$` 名稱的別名僅替換拼寫。
    - 宣告別名時，不對照該定義檢查原詞；套用該定義時，找不到的名稱照常為錯誤（如「沒有角色 in_p」）。
    - `::` 後方的名稱依 6.5 的順序查找：用例自身的名稱、其 `definition=` 別名、標準子物件名稱及其別名、物件符號的接腳名稱、文字的 key。
    - 篩選條件 `role=` 的值以及 `${…}` 中沿角色向下的路徑亦辨識這些別名，於每一步在當時用例所屬的定義中查找，例如對 `$DIFFERENTIAL_PAIR_N` 的用例 `%dp1` 寫出 `%dp1 @SELECT-INSTANCE(role="左管")` 或 `${左管::w}`。當作用域包含多個定義的用例時，各自在自身的定義中查找；原本的名稱依然有效。
- **哪些詞彙可以有別名：** 詞彙表中除下一項所列以外的所有詞彙：關鍵字、內建關鍵字的槽位名稱、參數名稱與參數值、種類名稱、子物件名稱、屬性名稱、樣式屬性、`true` 與 `false`（5.3）；以及上文所述的 `$` 名稱與定義內名稱。
- **哪些詞彙不能有別名：** 外層形式，即 `@RNL`、記錄標頭的欄位名稱與 `type` 的值、以及 `@VERSION`；還有 `@ALIAS` 與 `@USE-ALIASES` 本身。
- **其他名稱。** 命名本來就是為物件取另一個名字：在 `$"差分对" = $DIFFERENTIAL_PAIR_N` 之後，`$"差分对"` 即為同一個定義。此類名稱屬於文字內容，無法再移除，也不及於角色名稱或參數名稱；若需要整套另一語言的名稱，請使用別名。
- **對應關係：**
  - 一個原詞可擁有多個別名；在同一作用域內，一個別名僅能對應一個原詞。每個定義的 `definition=` 別名各自構成一個作用域。
  - 別名不得與檔案所宣告版本之任何標準詞彙拼寫相同，亦不得為另一個原詞重複宣告。`definition=` 別名不得與該定義既有的角色、參數或區域名稱拼寫相同，亦不得與 AS 及 ATTACH 自身參數 `priority` 的別名拼寫相同。
  - 別名不能作為原詞使用，且不得與自身的原詞相同。當提高檔案版本而新加入的標準詞彙恰與既有的某個別名拼寫相同時，會給出警告且版本照常提高（16.1）；在新版本中該別名隨即與標準詞彙同拼寫，依上述規則構成錯誤。
  - 別名套件必須宣告使用它的檔案之語言版本（16.1）；否則載入它的 USE-ALIASES 構成錯誤。
- **別名僅新增拼寫。** 標準拼寫永遠有效，兩者可在同一檔案中混用。
- **別名僅替換完整記號：**
  - 別名替換的是完整記號，而非文字巨集，因此原始碼位置與診斷訊息維持正確；
  - 不帶 `@` 的標準詞彙依拼寫取得別名，因此拼寫相同的詞彙（如參數名稱 `x` 與參數值 `"x"`）共用同一個別名；
  - `$` 名稱的別名直接替換拼寫：撰寫者寫出 `$"接地补位集" = {…}` 即在該層級定義了 `$GROUND_FILL_SET`，從而遮蔽標準套件的同名定義並給出提示（6.8）。
- **詞法規則：**
  - 關鍵字的別名是緊接在 `@` 之後、由任意書寫系統的字母、數字與底線構成的序列（不含 `-`）；它們構成單一記號，且 `@` 前方必須有一個空格（2.3），即使在中文標點之後亦然：`对 &b，@选出元件` 是錯誤，必須寫作 `对 &b， @选出元件`。任何非字母、數字或底線的字元（空格，或任何書寫系統的標點，如 `，` 或 `。`）皆會結束該別名。因此 `@对齐两个器件` 是單一未知關鍵字（錯誤），其診斷訊息須詢問 `@对齐` 之後是否漏了一個空格。這裡沒有針對特定語言的規則：任何非任意書寫系統之字母、數字或底線的字元皆結束別名，而括號之外的非 ASCII 字元皆為自由文字（3.3）。記號不會依已宣告的別名拆開，因此讀取記號無須先看別名宣告。
  - 不加引號的非 ASCII 詞彙僅出現在兩處：`@` 之後，與括號之內。在 `@` 之後，該詞彙必須是已宣告的別名；否則為錯誤（「非 ASCII 名稱須加引號」）。在括號之內（參數名稱、內建關鍵字的槽位名稱、`true` 與 `false`、角色名稱），已宣告的別名為別名；在定義的角色名稱或參數名稱位置，不是別名的詞彙即為該名稱本身（3.6）；在其他位置，不是別名的詞彙皆為錯誤。其餘之處適用 3.6：宿主名稱、RNL 名稱、端子名稱與 `::` 後方的名稱在未加引號時僅能包含 ASCII 字元，因此 `::` 後方使用的別名亦須加引號，如 `#M1::"位置"`。
  - 括號內未加引號的別名若與同一位置可用的某個定義參數名稱或角色名稱拼寫相同，構成錯誤，因為其含義不唯一。括號內加引號的詞彙一律是名稱，絕非別名。`$` 名稱的別名與 `::` 後方的別名無論如何皆須加引號寫出（3.6）。
  - 列舉值的別名寫在字串中，僅於數值為列舉的參數內生效。`${…}` 中的屬性名稱亦辨識別名（13.6）。其他字串（如 TEXT 的 `text`）不予替換。
- **診斷與翻譯：**
  - 診斷訊息同時顯示檔案中所寫的詞彙及其標準拼寫。
  - 翻譯工具可在雙向機械式轉換。譯為別名時，在檔頭記錄中寫入 USE-ALIASES；若是自成一體的檔案，則改將所用別名寫成 ALIAS 敘述。當一個原詞有多個別名時，取最先宣告者。譯回標準拼寫時移除 USE-ALIASES 與 ALIAS，不遺失任何資訊。
  - 自由文字、註解與字串不予翻譯，唯獨列舉值與 `${…}` 中的屬性名稱除外。
  - 大型語言模型、求解器與編輯器寫出標準拼寫。當它們修改以別名撰寫的檔案時，新增的敘述同樣使用標準拼寫；兩者混用完全合法。
