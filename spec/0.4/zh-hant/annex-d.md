## 附錄 D 與 0.3 版的差異（參考性）

0.4 版在每個關於位置的敘述中寫明方向，使一項事實僅代表單一佈局，而非多個選項中的一種。0.x 各版本之間不保證彼此相容（16.1）；本附錄列出變更項目以及檔案如何遷移至 0.4 版。本標準僅描述 0.4 版；0.3 版的檔案須透過能讀取 0.3 版的升級工具遷移至 0.4 版，該工具會執行本附錄末尾所列的修改（16.1）。

| 變更項目 | 見 |
|---|---|
| 方向須明確寫出。ORDER 與 DISTANCE 僅接收四個方向；未固定方向的 `"x"` 與 `"y"` 屬於錯誤參數值。DISTRIBUTE 改為接收方向而非投影軸，參數為 `direction`（不再是 `axis`）：其成員依該方向嚴格相隨並等距排列，僅有兩個成員時即等同 ORDER。ALIGN 僅接收單一投影軸，不接收列表 | 14.1–14.5、8.5 |
| ORIENT 與 ORIENT-RELATION 接收代碼列表（如 `["R0", "MY"]`）：構成單一事實，當其中之一成立時即成立；求解器擇一並寫回單一代碼。朝向是唯一提供此類選擇的事實 | 11.2、14.9、8.5 |
| ORIENT-RELATION 為一物件對一物件。其中一個槽位傳入集合時逐成員處理，每個成員各為一項事實；兩個槽位皆傳入多於一個成員的集合屬於錯誤。0.3 版則是將兩個集合當作整體互相關聯 | 14.9、5.2.1 |
| 依位置取成員：緊接在集合引用後的 `{…}` 依位置取成員（對展開一層後的成員計數），如 `%a{1}`、`%a{end}`、`%a{2:end}`；用例依角色取成員，而對篩選結果依位置取成員構成錯誤。在 0.3 版中，`%a{#b}` 是兩個物件 | 5.2.3、3.2、3.3、3.5、4.1、6.10 |
| 約束僅接收最底層物件。集合沒有位置：沒有中心也沒有範圍，其 `::position` 是各成員位置的集合。集合依書寫保留其項目；在 ALIGN、ORDER 與 DISTRIBUTE 的成員列表中，作為集合的項目（`{…}` 或對集合的引用）代表其每個成員，每種組合各為一條約束，各自作為取捨單位；DISTANCE 則將一個槽位的每個成員關聯至另一個槽位的每個成員。在 0.3 版中，集合內的引用會被展開、`{%x}` 依中心計數，且 DISTANCE 比較範圍 | 14.1、14.3–14.5、5.2、5.2.1、6.5、8.5、11.1、11.2 |

| 一般定義可以沒有角色（`roles=[]`），套用為 `$PORT_LIST @ATTACH`。其定義本體可包含規則：它們作為該用例所在層級的規則於其敘述位置生效，定義本體中的 `#` 即該層級。一般定義中的單獨 `?` 可接路徑，如 `?::position` | 9.4、8.2、10.4、4.1 |
| 本標準僅描述 0.4 版：0.3 版與 0.2 版的檔案屬於其他主版本，須透過能讀取 0.3 版的升級工具遷移至 0.4 語言與 0.4 標準系列。0.3 版標準曾描述工具如何讀取 0.2 版檔案 | 16.1 |

| 一般定義定義本體中的字面座標（點與 PLACE 的座標）是相對於用例自身之點的偏移量，且用例的 ORIENT 不會旋轉它們。在 0.3 版中，它們採用的是層級座標 | 9.4、11.1、11.2、13.4 |

| 每個用例皆擁有自身的點，沒有符號的用例亦同，寫作 `%u::position`：PLACE 接收該點，帶有符號繪製的用例上的約束亦接收該點。在約束的成員列表中，沒有符號的用例代表其成員，如同 GROUP 一路向下展開至最底層物件，且同一物件取兩次的組合會被略去。一般定義本體中單獨的 `?` 指正在展開的用例。當受約束的用例之點未綁定至任何可繪製事物時會給出提示。在 0.3 版中，對無符號用例使用 PLACE 與約束會失效 | 14.1、9.4、12.1、6.2、6.5、3.3、7.1、8.2、11.1 |

**將檔案從 0.3 遷移至 0.4。** 本標準不描述 0.3 版的檔案；須透過能讀取 0.3 版的升級工具進行遷移（16.1）。工具會提高檔頭記錄中的版本、將檔案遷移至標準系列 0.4 並進行下列修改；無法自動修改之處會回報給撰寫者：

- 將 ORDER 或 DISTANCE 的方向 `"x"`、`"y"`，以及 DISTRIBUTE 的 `axis=`：改為選定一個方向。
- Spectre `transformer` 的端子名稱 `p_plus`、`p_minus`、`s_plus` 與 `s_minus`：改寫為 `p1`、`n1`、`p2` 與 `n2`。
- ORIENT-RELATION 兩側皆為集合：為每對組合各自寫出一項事實。
- 未寫 `recursive` 的規則：工具在檔案、其自身套件檔案與內嵌套件的篩選中寫入 `recursive=true`，使規則繼續觸及下方層級。若同一條規則中部分篩選寫了 `recursive=false` 而其他未寫，則回報之：在 0.4 版中，只要有一個 `true` 就會使整條規則觸及下方層級。
- ROUTE：工具改寫為 ROUTE-NET。
- 傳入篩選結果的 WIRE 或 BUNDLE：WIRE 改寫為 ROUTE-OBJECT，BUNDLE 則逐一列出成員。
- `%g:p` 等用例的端子：改寫為符號的具名接腳，如 `%g::pin`。0.3 系列符號曾依編號綁定用例角色，0.4 版不支援此做法（11.3）。
- `$GROUND @ATTACH #M5:3` 等第一個角色為端子或接腳的虛擬組件：現在它們位於該網路上並有自身獨立位置；若要維持在接腳上，須改寫為短樁 `$GROUND_STUB @ATTACH #M5:3`，或寫出約束將接地接腳置於 M5 接腳處（12.3）。
- SELECT-TERMINAL 上的 `wired=`：改寫為 SELECT-PIN，如 `# @SELECT-INSTANCE => @SELECT-PIN(wired=false)`。
- 依中心計數的 `{%x}`，以及原為集合中心的 `::position`：集合在 0.4 版中沒有位置，其 `::position` 是各成員位置的集合；升級工具會保留此類敘述供人工檢視。若要將這些物件作為單一整體擺放，請將它們作為某用例的成員，在其定義本體中綁定至用例自身的點，再對 `%u::position` 施加約束（14.1）。
- 約束成員列表中原依單一點計數的用例：升級工具會將沒有符號的用例改寫為 `%u::position`，否則它會代表其成員（14.1）。
- 兩個集合之間的 DISTANCE：現在對每一對組合皆成立，因此 `max` 約束的是每一對成員，而非外框範圍之間的間隙。
- 一般定義定義本體中的字面座標：現在是相對於用例自身之點的偏移量；原本意指層級座標的定義，須將其用例置於 `(0, 0)`，如 `$TITLE @ATTACH => @PLACE(0, 0)`。
- 標準套件：寫入 `@USE-PACKAGE(name="rnl-std-all", version="0.4")`，並依下文「標準系列 0.4」改寫 0.3 系列的用例：套用新名稱與新角色、為 0.3 自動補齊曾標記的每個連接埠網路補寫 `$IO_PORT @ATTACH`，並對每處已移除定義的使用回報提示。

**標準系列 0.4。** 標準套件不屬於本語言標準（16.3）；以下列出檔案從 0.3 系列遷移至 0.4 系列時的相關要點。

- **使用方式**：檔案須在檔頭記錄中寫出 `@USE-PACKAGE(name="rnl-std-all", version="0.4")`，或由工具透過設定自動加入（16.3）。
- **連接埠**：自動補齊為每個連接埠網路加上連接埠標記（電源與接地網路亦然），排成一欄，位於該層級實例左側至少 6 個單位處，各標記為 R0；檔案可從 `$PORT_FILL_SET` 中取出網路，以 `$IO_PORT @ATTACH` 寫出自己的標記，或以 `$PORT_LIST @ATTACH` 寫出該欄（12.4）。
- **自動補齊**：為無連線接腳加上各自畫作短樁的網路標籤；除非檔案或套件以 ROUTE-NET 或 ROUTE-OBJECT 指明，否則任何網路不繪製為連線；接地與電源網路以 `@UNROUTE-NET(priority="high")` 排除，想要將它們繪製為連線的檔案須寫出 `@ROUTE-NET(priority="high")` 或 WIRE。已有連線的接腳（無論手工連線或由寫成敘述或規則的 ROUTE-NET / ROUTE-OBJECT 繪製）不再由自動補齊加上接地或電源符號；想要顯示的檔案須自行附掛，如整條網路使用 `$GROUND @ATTACH &vss` 或單一接腳使用 `$GROUND_STUB @ATTACH #R1:2`。其規則皆寫 `recursive=true` 並選取接腳（含虛擬組件的接腳）。`$BIAS_NET_SET` 中的網路與接地、電源網路一樣各自獲得偏壓標記。
- **套件**：唯一的套件集合為 `rnl-std-all`，引用該系列的所有套件並為每種語言各設一筆檔頭記錄（2.8、16.3）；0.3 系列的集合 `rnl-std`、`rnl-std-core` 與 `rnl-std-full` 已移除，而 `rnl-std-structures` 更名為 `rnl-std-semantics`。`rnl-std-no-labels` 改以 `drawn=true` 選取並以樣式 `textvisible=false` 隱藏標籤（而非使用空文字），因此檔案能以 `textvisible=true` 重新顯示標籤。選用套件 `rnl-std-45deg` 為新增項目。
- **更名或變更**：`$DIFFERENTIAL_PAIR` 拆分為 `$DIFFERENTIAL_PAIR_N` 與 `$DIFFERENTIAL_PAIR_P`，角色為 `left`、`right` 與 `tail`；`$MIRRORED` 更名為 `$MIRRORED_LAYOUT`，角色為 `left`、`right` 與單一 `axis`，新增的 `$MIRRORED_VERTICAL_LAYOUT` 角色則為 `top`、`bottom` 與 `axis`，因為僅進行擺放的定義皆以 `_LAYOUT` 結尾；`_N` 與 `_P` 結構會斷言其電晶體的極性；`$FLOW` 改為 `$SIGNAL_FLOW`，不擺放任何位置也不接收方向，並可在其路徑上寫出來源與負載，而 `$POWER_FLOW` 與 `$BIAS_CIRCUIT` 為新增項目；`$CURRENT_MIRROR` 拆分為 `$CURRENT_MIRROR_N` 與 `$CURRENT_MIRROR_P`；`$NO_CONNECT` 的角色接收端子或接腳。該系列更名、合併、拆分或移除的完整定義列表載於標準套件說明中；RNL 核心 0.5.x 末版（工具版本，非語言版本）中的 `rnl upgrade` 命令依此列表改寫檔案。結構中所有關於位置的幾何事實皆須寫明方向，另一種畫法各自成為獨立變體，如 `$BRANCH_HORIZONTAL`。
- **已移除**：`$CHAIN`、`$SUPPLY_HIGH` 與 `$SUPPLY_LOW`。
