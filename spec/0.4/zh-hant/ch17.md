## 17 修改模型

- RNL 僅描述目前的狀態，不描述通往該狀態的編輯操作：
  - 沒有復原或刪除操作；刪除即是編輯文字；
  - 沒有相對移動；編輯器直接寫入新的絕對數值。
- **誰修改哪些記錄。** 求解器取代 `type="generated"` 的記錄。其他工具僅能修改 `author` 為其自身的記錄，例如編輯器整理自身寫出的修改，或新一次匯入取代前一次匯入寫出的內容。工具不得動用未帶 `author` 的撰寫者記錄（2.8）。
- 附在後方的描述依順序覆寫較早的描述（8.4）；對幾何事實而言，先比較優先順序（8.5）。`type` 與 `author` 不影響順序（8.3）。
- **輸出隨子電路存放。** 求解器的輸出與使用者在編輯器中所做的修改，皆寫入該層級自身的文字中：對子電路而言，寫在其 `.subckt … .ends` 內部，即使該子電路位於被引入檔案中亦然；對頂層而言，寫在主檔案的檔案層級（第 14.8 節）。求解器以 `priority="high"` 將輸出寫在該層級自身文字的末尾；求解時，會在不計入 `type="generated"` 記錄的情況下進行解譯（2.8），求解完成後隨即取代它們（14.8）。它必須寫回所做的每一項決定（14.8）。`scope=` 僅供撰寫者自行選擇從外部撰寫敘述時使用（2.6）。唯讀檔案是否儲存由工具決定。
- **Verilog-A 檔案。** 模組層級沒有可求解的內容，不會產生求解器的輸出。在 Verilog-A 檔案中，工具僅修改檔頭記錄以及位於各模組內部、以 `//` 撰寫的方塊符號記錄（2.9）。
- **過時的求解結果僅給出提示。** 當上層級或套件發生變更時，程式庫中某個子電路的求解結果可能會過時，例如主檔案更改了某個符號。舊求解結果依然生效；檢視器若發現記錄標頭中的 `hash` 與目前輸入不符，會給出一條提示建議重新求解（2.8）。
  - 雜湊值是根據繼承之後該層級的實際輸入計算的：包含流下並生效的規則、選定的符號、套件版本與求解器選項，但不含 `type="generated"` 的記錄與中繼資料欄位。它是逐層級計算而非逐檔案計算，亦不僅取子電路自身的文字，否則主檔案中的變更將無從察覺。
  - 雜湊值不改變解譯結果。其演算法屬於工具實作範疇；數值應帶有演算法標籤，如 `"sig1:…"`，不認識該演算法的工具不予比對。
  - 附註：若雜湊值不符就表示停用舊求解結果，該演算法便會成為語言規範的一部分，每款工具都必須以完全相同的方式計算它，且不進行求解的檢視器將無法繪製該層級。
  - 編號是例外：當建立無名物件的敘述發生變動時，編號的檢查碼不再符合，使用編號的敘述便不再生效，直到該層級重新求解為止（5.9）。該檢查碼僅涵蓋該層級與其所使用定義的文字，因此每款工具計算方式完全一致，且舊求解結果的其餘部分仍照常繪製。
- **產生的物件。** 當求解器已擺放並連接由規則產生的物件時，會將它們連同連線寫成明確敘述置於自身記錄中。明確物件優先生效，使得自動補齊規則不再產生相同物件（10.5）。定義本體中沒有區域名稱的物件透過編號引用（5.9）。
- **修改求解器建立的物件。** 求解器為其寫出之物件賦予的名稱僅綁定在求解器自身的記錄中，而該記錄在重新求解時會被略去（2.8）。因此其他記錄中使用該名稱的敘述在求解時會找不到對象，求解器也無法將其納入考量。若要單獨描述這類物件，編輯器須依 10.5 在自身記錄中手工寫出該物件並加上修改，如 `%g_r4 = $GROUND_STUB @ATTACH #R4:2; %g_r4::g @PLACE(30, -4, priority="high")`：短樁內的連線使該接腳變為已連線，自動補齊隨之略過它，且下次求解時不再寫出該物件；在下次求解前，求解器記錄中的物件亦會一併繪製。當修改的對象是產生的用例本身（如連接埠標記）時，從宿主物件出發的篩選在求解時與繪圖時皆能觸及它，如 `&out @SELECT-ANCESTOR-USAGE $IO_PORT => @PLACE(40, 20, priority="high")`；用例的區域物件則無法透過該用例被選出，僅能透過名稱或作為該層級的物件選取（9.4）。
- 記錄標頭的欄位適用於該記錄中的每一條敘述（2.8）。
- **範例：在編輯器中的修改。** 以下是一個完整片段，包含宿主的註解前綴。在檔頭記錄之後，設計者寫了第一筆記錄，求解器寫了第二筆；使用者在編輯器中將 VIN 向左拖曳，編輯器於末尾附加了第三筆：

  ```spice
  * Common-source stage
  * @RNL(type="header") { @VERSION("0.4"); @USE-PACKAGE(name="rnl-std-all", version="0.4")}
  .model nch nmos level=1
  M1 out in 0 0 nch W=4u L=1u
  RD vdd out 5k
  VDD vdd 0 1.8
  VIN in 0 DC 0.6 AC 1
  * @RNL {
  *   {#RD #M1} @ALIGN("x");
  *   #M1 #RD @DISTANCE("bottom-to-top", min=2);
  *   &vdd @ADD-TO $SUPPLY_NET_SET
  * }
  * @RNL(type="generated", priority="high", author="rnl-solver 0.3", hash="sig1:5be1c09a") {
  *   #M1 @PLACE(10, 0); #RD @PLACE(10, 8); #VIN @PLACE(0, -2); #VDD @PLACE(20, 4)
  * }
  * @RNL(author="rnl-editor 0.1") { #VIN @PLACE(x=-4, priority="high")}
  .end
  ```

  - 拖曳操作寫成一筆新記錄，附在求解器記錄之後，優先順序為 `"high"`。兩者皆為高優先順序，因此較後寫的被保留，而求解器寫出的 x 被捨棄並給出一條提示（8.5）；此後每次重新求解該層級時，新的 x 皆作為固定位置（14.8）。
  - 將它寫進設計者的記錄中是行不通的。該處的敘述預設為 `"normal"`，無法覆寫求解器的 `"high"`；即使寫成 `"high"` 仍然會敗下陣來，因為求解器的記錄排在較後方，而在同一優先順序內保留較後寫的事實。這個誤寫不算錯誤，只會給出關於衝突取捨的提示。該位置會等到下次重新求解該層級時才生效，屆時設計者的敘述成為約束之一；在此之前圖面不會改變。
  - 依位置傳入的參數排在依名稱傳入的參數之前（4.2 第 9 項）：`@PLACE(-4, -2, priority="high")` 等同 `@PLACE(x=-4, y=-2, priority="high")`，而 `@PLACE(x=-4, -2)` 是錯誤。
  - 若要更改設計者原本寫的內容（更換符號、重新命名、刪除約束），請直接編輯設計者的記錄。求解器的記錄無須理會，下次重新求解該層級時會被整體取代。
- 若要暫時停用某條敘述，請將它包在 `/* … */` 中。
- **往返轉換。** RNL 不保證任何匯出為 RNL 再匯入的過程都能使繪圖保持完全不變（原則 1）；匯出器可以選擇在座標層級寫出精確 RNL（原則 3）。本版本不定義何謂精確 RNL，亦不定義往返轉換的準則。
