## 9 定義

### 9.1 通用規則

- 定義共有三種：DEFINE-SYMBOL 建立符號，DEFINE-STYLE 建立樣式，DEFINE 建立一般定義。符號與樣式為專用定義（1.4.4）。每一種皆接收一個集合作為其定義本體；定義本體內的敘述逐條容錯處理（7.3）。
- 定義是一種物件。它以 `$name =` 或 `%name =` 命名（6.6），並作為關鍵字的物件填入該關鍵字為它指定的槽位（5.6）。
- 提交一個定義僅發布其名稱。定義本身不繪製任何內容，僅在使用時才生效：符號在 SET-SYMBOL 指派時生效，樣式在 SET-STYLE 指派時生效，一般定義在 AS 或 ATTACH 套用時生效。
- 直接寫作記錄成員（未巢狀於敘述中）且沒有名稱的定義永遠不會被使用，並會給出警告。巢狀於敘述中的匿名定義則照常使用。
- **引入其他定義**：在 DEFINE-SYMBOL 或 DEFINE-STYLE 的定義本體中寫出對同種類定義的引用，會將該定義的內容插入該處。較後寫出的帶 key 成員會覆寫較早寫出的同 key 成員；不帶 key 的成員則累積疊加。沒有 `base=` 參數。若一次引入直接或透過其他引入、或透過符號定義本體中所繪製用例的符號（9.2.7）回到正在建構內容的定義本身，便形成閉合循環：該次引入失效，其診斷須列出整條鏈，定義本體其餘部分照常生效。定義的內容是從該定義出發建構的，因此若 `$A` 引入 `$B` 且 `$B` 引入 `$A`，則 `$A` 的內容為其自身加上不含 `$A` 的 `$B`，`$B` 則反之。
- 一般定義之間不會互相引入；它們是透過在定義本體中呼叫 AS 與 ATTACH 來組合的。衍生與擴充的方式相同；沒有繼承關係（9.4）。

### 9.2 符號：DEFINE-SYMBOL

#### 9.2.1 評估

- 符號是一個數值：其定義本體在定義處評估，其中的敘述在符號的區域座標中產生接腳與圖形。這些構成該定義的內容，不會提交至場景中。
- 成員的順序即為繪圖順序。
- 區域座標使用與場景相同的單位與座標軸（x 向右、y 向上），且 (0, 0) 為符號的原點（6.5）；本版本不支援縮放（11.7）。定義本體中的點在兩軸上皆須給出數字；不得使用 `_`。

#### 9.2.2 定義本體中的敘述

- 定義本體僅能包含圖形、接腳、具名區域點（如 `%tip = (0, 0.7)`）、其他符號的引入、僅供繪圖而套用的用例（以 ATTACH 或 AS 套用，9.4）連同寫在它們上面的 SET-SYMBOL 與 ORIENT（9.2.7），以及附著於所屬物件 `?`（即使用此符號繪製的物件）的 TEXT 連同定位該文字的 PLACE（13.3）。
- 其他任何敘述皆會失效並被捨棄（定義本體採容錯處理）；出現宿主引用亦同。
- 接腳僅能寫在 DEFINE-SYMBOL 的定義本體中。圖形亦可寫在場景中（使用場景座標）；在場景中它們是標註（annotation）（13.4）。

#### 9.2.3 參數

- `box=[x1, y1, x2, y2]`：符號的邊界框，採區域座標且與座標軸對齊；它會隨實例的朝向一併變換。語言本身不使用此參數；檢視器通常將它用作選取框，求解器則將它作為隔開符號的邊界，具體使用方式由實作決定。未寫出時，預設為符號中除文字外所有圖形的邊界框，因為文字大小取決於字型與渲染器。

#### 9.2.4 接腳

```rnl
$RES_BOX = @DEFINE-SYMBOL {
  %p = (0, 3) @PIN(terminal=1, label="P", direction="up");
  %n = (0, -3) @PIN(terminal=2, label="N", direction="down");
  @LINE {%p (0, 1.5)};
  @LINE {(0, -1.5) %n};
  (0, 0) @RECTANGLE(width=1.2, height=3)
}
```

- **接腳是符號的物件**：每條 PIN 敘述建立一支接腳，亦即一個可綁定端子的點。在定義本體中，具名接腳可作為點使用，如上例引線分別起於 `%p` 並止於 `%n`。其區域名稱同時也是每個以該符號繪製之物件上該接腳作為子物件的名稱，例如 `#R1::p`（6.5）；沒有區域名稱的接腳沒有名稱，透過它綁定的端子來引用（5.2.4）。
- **名稱僅綁定一次**：接腳名稱在一個符號中僅能綁定一次，包含所引入符號中的接腳（9.2.7、6.6）；將同一名稱綁定至兩支接腳為錯誤。接腳不會彼此取代：每條 PIN 敘述各建立一支獨立的接腳。
- 接腳應擺放在整數座標點上（11.7）：當實例置於整數點上時，其接腳與連接至接腳的連線亦會落在整數點上。置於其他位置不算錯誤；實作可以給出提示。符號中的圖形不受此限。
- `terminal=`：該接腳綁定的端子，可為名稱或編號；這些是該符號的端子名稱。SET-SYMBOL 會將它們與物件的端子匹配（11.3）：名稱匹配至該名稱的端子（由 DEVICE 給出 6.12，或子電路的連接埠名稱），編號則匹配至該順序位置的端子。對於沒有端子的用例，名稱會匹配至其定義中同名的角色，而編號不綁定任何角色（11.3、12.1）。`terminal=` 可以省略：此時該接腳不綁定任何事物，僅供繪製，例如繪成圖樣的開關切刀端。
- **單一端子對應多支接腳**：同一個端子可繪製為多支接腳，例如大型區塊兩側皆有電源接腳。每支皆為獨立的接腳並以其名稱引用；凡將端子寫作接腳之處，它代表最後寫出的那一支接腳（5.2.4）。每支接腳各自獨立判定是否已連線（10.2）。
- **匯流排接腳**：`terminal=` 可接收陣列，為多個端子建立單一支接腳，例如子電路的匯流排連接埠：`(-4, 0) @PIN(terminal=["D<3>", "D<2>", "D<1>", "D<0>"], label="D<3:0>", direction="left")`。該陣列須至少有一個元素，且每個元素為編號或名稱。參數中的字串不會展開下標（6.11），因此須將名稱逐一寫出。
  - 所有這些端子皆繪製於此接腳處：連至其中任一端子的連線或約束即連至此接腳，且該接腳即視為已連線（10.2）。
  - 在同一座標點放置多支接腳不能替代匯流排接腳：座標相同並不會建立連接（13.1），連線僅會連到其中一支接腳，其餘接腳仍維持 `wired=false`，且標準套件的自動補齊規則會為它們加上標籤與接地。
- `label=`：顯示於接腳處的文字，僅供顯示。它不是名稱：接腳是透過符號中綁定的名稱引用（例如 `%p = (0, 3) @PIN(…)` 中的 `p`，寫作 `#R1::p`），而端子是透過其端子名稱引用（例如 `#R1:1`）；`label="P"` 既不會產生 `#R1::P`，也不會產生 `#R1:P`（6.4、6.5）。是否顯示以及顯示於何處由檢視器決定。它可使用文字標記語法，例如 `\overline{CS}`（13.6）。
- **未繪製的端子沒有接腳。** 沒有接腳的端子在繪圖上沒有意義：連至該端子的連線或約束會失效（「該符號沒有此端子的接腳」）；自動補齊亦不會選取它（10.1）。沒有專門用來隱藏既有接腳的記號；若要省略基體，請使用不含基體接腳的三端符號。
- `direction=`：連線離開該接腳的方向：`"right"`、`"up"`、`"left"` 或 `"down"`。它依符號的區域座標寫出，並隨朝向一併旋轉（11.2）。它是供求解器與檢視器參考的提示，例如自由走線離開接腳的方向、端子處的電流方向（15.2），或選擇朝向時的參考；它本身不是約束，不參與衝突取捨，但寫在接腳上的 ORIENT 與 ORIENT-RELATION 會約束它（11.2、14.9）。它可以省略，此時該接腳沒有方向：實作可依圖形推斷方向作為提示，但寫在該接腳上的 ORIENT 與 ORIENT-RELATION 會失效。
- 沒有引線長度參數：引線在符號中以 LINE 繪製。
- 沒有電氣類型：接腳與端子沒有諸如 input 或 output 等參數，網表亦無此類資訊。若需要此資訊，使用者會以語義定義的用例表達；匯出至 Virtuoso 等工具的匯出器則依自身組態將一般定義映射為電氣類型。
- 接腳僅是一個點：是否繪製引線由符號決定，而接腳的點如何標記（小方塊、圓點或不標記）由檢視器決定。因此不帶引線的接腳無須特殊記號：只需寫 PIN 而不寫 LINE。例如，匯入某個將連線連至隱藏基體接腳的編輯器圖面時，匯入為保留基體 PIN 但不繪製基體引線的符號即可。一般符號（含標準套件的符號）皆繪製引線。

#### 9.2.5 圖形

位置為點物件；純量為參數。下表中 *point* 代表任意點物件。

| 形式 | 含義 |
|---|---|
| `@LINE {point point …}` | 兩點形成線段，多點形成折線；當最後一點與第一點位置相同時，圖形閉合且交接點繪製為轉角 |
| `@RECTANGLE {point point}` | 矩形；兩點為對角頂點，順序不拘 |
| `(0, 0) @RECTANGLE(width=4, height=2)` | 矩形；點為中心，`width` 與 `height` 分別為寬度與高度 |
| `@CIRCLE {point point}` | 圓形；第一點為圓心，第二點在圓周上 |
| `(0, 0) @CIRCLE(radius=1)` | 圓形；點為圓心 |
| `@ELLIPSE {point point}` | 橢圓；兩點為其外接框的對角頂點 |
| `(0, 0) @ELLIPSE(width=4, height=2)` | 橢圓；點為中心，`width` 與 `height` 為其外接框的寬高 |
| `@ARC {point point point}` | 圓弧，自第一點經過第二點至第三點 |
| `@BEZIER {point point point point …}` | 3n+1 個點的三次貝茲曲線：起點，接著每段各有兩個控制點與一個終點；相鄰區段共用其端點 |
| `(1, 0) @TEXT("…")` | 附著於點的文字：符號的固定文字，無法依實例而異 |
| `? @TEXT("${name}", key="name") => @PLACE(1, 0)` | 附著於所屬物件（使用此符號繪製的物件）的文字，可讀取其屬性；其 key 為 `name`，因此對 M1 而言為 `#M1::name`，場景中具有相同 key 的文字會逐參數覆寫它（13.3） |

- **兩種形式**：RECTANGLE、CIRCLE 與 ELLIPSE 依是否寫出尺寸參數區分。寫出尺寸（RECTANGLE 與 ELLIPSE 為 `width` 與 `height`，CIRCLE 為 `radius`）時，物件槽位接收單一點（中心）；傳入集合時，對每個點各繪製一個圖形（5.2.1）。傳入篩選結果時，如 `# @SELECT-PIN => @RECTANGLE(width=0.4, height=0.4, fill="linecolor")`，它會在 8.2 的步驟 6 逐一產生（如同 TEXT），因此能看到符號；兩點形式的圖形則不接收篩選（10.4）：讀取時未知篩選會產生幾個點，而該形式固定接收恰好兩個點。未寫尺寸時，物件槽位接收包含兩個點的集合，點數不同則該圖形失效。尺寸僅寫出一部分為參數錯誤，該圖形失效。在兩點形式中，點本身即為物件：它們可命名或取自接腳位置，圖形會隨之移動。
- 矩形與橢圓皆與座標軸對齊；斜矩形須以閉合的 LINE 繪製。
- **填色**：除 TEXT 外的每個圖形皆接受 `fill=`。開放的 LINE、ARC 或 BEZIER 以最後一點連回第一點的直線所封閉的區域填色，該閉合線本身不描邊；填色的 ARC 即弦與弧所圍成的弓形。僅填色而不描邊的圖形（如 MOS 的閘極、箭頭、交接圓點）寫作 `fill="linecolor", linestyle="none"`（9.3）。
- **箭頭**：LINE、ARC 與 BEZIER 接受 `arrow=`：`"none"`（預設）、`"start"`、`"end"` 或 `"both"`，例如 `@LINE(arrow="end") {%from %to}`。箭尖位於起點或終點，指向該端線條的方向：LINE 為第一段或最後一段；ARC 為該端點處圓弧的切線；BEZIER 為鄰近控制點指向該端點的連線（若兩點重合，則取下一個不重合的點）。箭頭長度由 `arrowsize` 指定（9.3），形狀由實作決定。端點是點物件；當約束移動它們時，箭頭會隨之指向任意角度，而在點上繪製的箭頭用例僅有八種朝向。WIRE 不接受 `arrow=`。
- **樣式參數**：圖形可直接將樣式屬性寫為參數（9.3）：LINE、ARC 與 BEZIER 接受 `linecolor`、`linestyle`、`linewidth`、`cap`、`join`、`fillcolor` 與 `arrowsize`；RECTANGLE、CIRCLE 與 ELLIPSE 接受前六項；TEXT 接受 `textcolor`、`size`、`font`、`bold`、`italic` 與 `textvisible`。直接寫出的屬性為該圖形的直接樣式，位階高於所屬物件傳遞下來的樣式（8.3），因此寫在符號中的顏色不會隨主題改變；未寫出的屬性則取自所屬物件的樣式，因此切換主題無須修改符號。填色以 `fill=` 指定：`"none"`（預設）、`"linecolor"`（使用 `linecolor` 的顏色）或 `"fillcolor"`（使用 `fillcolor` 的顏色）。
- **未提供的項目**：SVG 路徑字串、POLYGON（請改用閉合 LINE）、獨立的箭頭圖形（線端箭頭見上文；其餘情況請使用填色的閉合 LINE 或繪於點上的箭頭用例，9.2.7）、圓角矩形、橢圓弧（請以 BEZIER 近似）以及圖片。
- **文字**：TEXT 亦具有 `size=`（字級，11.7）、`halign=`（水平對齊：`"start"`（預設）、`"middle"`、`"end"`）、`valign=`（垂直對齊：`"baseline"`（預設）、`"top"`、`"middle"`、`"bottom"`）與 `rotate=`（0、90、180 或 270；預設 0）。在符號定義本體中，附著於 `?` 的 TEXT 引用所屬物件的屬性，附著於點的 TEXT 則為固定文字；在場景中，TEXT 依所附著對象成為標註或標籤（13.3、13.4）。文字標記語法見 13.6。
- **基線**：使用 `valign="baseline"` 時，錨點位於第一行的基線上，後續各行向下排列，與 SVG、PostScript 及多數編輯器相同；`"top"`、`"middle"` 與 `"bottom"` 則對齊整個文字方塊。預設為基線。
- **文字方向**：錨點即文字自身的位置（13.3）。文字方塊依 `halign` 與 `valign` 擺放在錨點旁，並繞錨點逆時針旋轉 `rotate` 度（任意數字，如 `30`）；符號中的文字接著會隨實例的朝向一併變換（包含旋轉與鏡像）。預設的 `upright=true` 會使方塊內的字元保持正向易讀：水平文字由左至右、垂直文字由下至上，且字形絕不鏡像翻轉；經過實例朝向變換後最終角度大於 90 度且小於等於 270 度的文字，會繞其錨點旋轉 180 度。因此 `rotate=180` 顯示為 0 度，270 度顯示為 90 度，同時文字方塊移至錨點的另一側；當實例鏡像時，錨點照常鏡像，文字方塊沿鏡像方向移至錨點另一側，但字元本身不鏡像。這適用於所有對齊方式：`start` 與 `end` 互換，`top` 與 `bottom` 亦互換。使用 `valign="baseline"` 的文字依相同方式翻轉：它會懸於錨點下方，距離與原本高於錨點的距離相等。帶有 `fix_rotate=true` 的文字會保留其字元方向，僅文字方塊落在哪一側跟隨朝向（13.3）。當 `upright=false` 時，文字絕不為了易讀而翻轉：其字元完全遵循旋轉與鏡像（包含鏡像字形），適合用來當作文字書寫的箭頭與其他符號（如 `→`）。兩者可組合使用：`fix_rotate` 決定最終角度（在場景中即 `rotate`，或隨物件變換後的 `rotate`，鏡像會改變其正負號），而 `upright` 決定該角度是否再轉 180 度以利閱讀；`fix_rotate=true` 的文字絕不鏡像。例如，NMOS 的名稱錨點位於 (1.5, 1.5)，在 `halign="start"` 下向右延伸；在 `"MY"` 下錨點移至 (−1.5, 1.5)，文字改為向左延伸（遠離本體）；在 `"R90"` 下錨點移至 (−1.5, 1.5)，文字垂直排列並由下往上閱讀。場景中的文字不會隨實例轉動。
- **排成一欄的標籤**：符號中附著於 `?`、具有相同 x 座標、相同 `halign`、`valign`、`rotate`、`fix_rotate` 與 `upright`，且內容非空的文字會排成一欄，由上而下閱讀，例如電阻名稱位於阻值上方。當物件的朝向會使整欄顛倒——上下顛倒（`"MX"`、`"R180"`）或橫躺導致由右至左閱讀（`"R270"`、`"MXR90"`）——該欄文字的位置會互換（第一項移至最後一項的位置，依此類推），使該欄在原處仍維持由上而下或由左至右的順序閱讀。對齊方式不同的文字（例如方塊上方的名稱與方塊中央的公式）不屬同一欄，且位置由場景給出的文字（13.3）不參與此排列。

#### 9.2.6 方塊符號

寫於子電路 `.subckt ota5t … .ends` 內部：

```rnl subckt
%ota5t = @DEFINE-SYMBOL(box=[-4, -4, 4, 4]) {
  (-4, 1) @PIN(terminal="inp");
  (-4, -1) @PIN(terminal="inn");
  (4, 0) @PIN(terminal="out");
  @LINE {(-4, -4) (-4, 4) (4, 0) (-4, -4)};
  ? @TEXT("${name}", key="name") => @PLACE(-1, 0)
};
# @SET-SYMBOL %ota5t
```

- 子電路指派給自身 `#` 的符號，即其實例在各處的預設外觀：即其方塊符號。接腳依名稱對應至該子電路的連接埠。
- 這是對原則 2.5「定義僅向下生效」規則的唯一例外：它會作用於實例化該子電路的各個層級。
- 子電路的匯流排連接埠在網表中已拆分為單一連接埠（6.11）；方塊符號則以匯流排接腳將它們繪製為單一支接腳（9.2.4）。
- 在符號佇列中，它排在根層級套件的規則之後、各層級的規則（含層級內引入的套件）之前，因此上層級可以規則或針對個別實例的 SET-SYMBOL 覆寫它（8.3）。
- 沒有實例會實例化檔案層級，因此寫在檔案層級中的 `# @SET-SYMBOL` 不產生效果。
- Verilog-A 模組以相同方式給出其方塊符號，將 `# @SET-SYMBOL` 寫在 Verilog-A 檔案中的該模組內；其接腳依名稱對應至該模組的連接埠，向量連接埠則每個位元各對應一個端子（2.9）。
- **預設方塊符號。** 未獲任何規則、敘述或方塊符號指派符號的實例，以預設方塊符號繪製，由其端子構成：
  - **接腳。** 每個端子各有一個接腳。對於檔案所讀取之子電路或模組（2.9）的實例，接腳即為依定義順序排列的連接埠，每個接腳以其連接埠命名，例如 `terminal="inp"`。對於任何其他實例，例如其定義未被檔案讀取的單元，或無任何規則指明其種類的器件，接腳即為其所在行上的節點，每個接腳以其編號命名，例如 `terminal=1`。前半數接腳位於左側，其餘位於右側；數量為奇數時，左側多一個。每個接腳在方框內以其連接埠名稱標示，否則以其端子名稱（6.12）標示，再否則以其編號標示。
  - **方框。** 方框為正方形，邊長為左側接腳數的兩倍，且至少為 2；其中心即符號的原點。接腳彼此相距 2 並朝向方框外：左側的接腳自上角下方 1 處向下排列，右側的接腳則在其側邊置中。因此只有一個端子的實例，其方框邊長為 2，接腳在左側邊的中央；有三個端子的實例，其方框邊長為 4，接腳位於 (−2, 1)、(−2, −1) 與 (2, 0)；每個接腳都落在整數單位上。
  - **文字。** 方框上方是實例名稱（`key="name"`），下方是 `${model}`（`key="model"`），即子電路或模型的名稱（13.6）。
  - **在佇列中的位置。** 它位於整個符號佇列（8.3）之後、方塊符號組之外，因此任何為該實例指派符號的規則或敘述都會取代它，其子電路的方塊符號亦然。對 `drawn` 而言它算作符號，且不符合任何 `symbol=`（10.1）。
  - 因此每個實例都有符號，除非為其指派的符號省略了某個端子，否則每個端子皆有接腳（9.2.4）。
- 當子電路有多條 `# @SET-SYMBOL` 敘述時，它們位於符號佇列的同一組內，依文字順序排列，較後者生效（8.3）；實作可以給出警告。

#### 9.2.7 變體與片段

```rnl
$NMOS_BULK = @DEFINE-SYMBOL(box=[-3, -3, 2, 3]) {
  $NMOS;
  %b = (1, 0) @PIN(terminal=4, label="B", direction="right");
  @LINE {(0, 0) %b}
}
```

- 在定義本體中引入另一個符號並於其後追加內容即可構成變體：接腳與圖形會累積疊加，且被引入符號的接腳名稱同樣計入變體的名稱（9.2.4）。若要移動接腳，須將共用部分拆成片段，並在每個符號中各自寫出接腳，如同標準套件的做法。
- 僅在自身層級使用的片段以 `%` 命名，如 `%MOS_CHANNEL = @DEFINE-SYMBOL {…}`，另一個符號定義本體即可寫 `%MOS_CHANNEL;` 將其引入。
- 圖形沒有 key：引入只會追加，無法移除已引入的圖形。若要繪製較少內容，須定義另一個符號：將共用部分拆為片段，並在各符號中引入所需部分，例如 `$NMOS3 = @DEFINE-SYMBOL {%MOS_BODY}` 與 `$NMOS_4TERM = @DEFINE-SYMBOL {%MOS_BODY; %BULK}`。
- **定義本體中的用例**：若某個圖形需要出現在不同位置或不同朝向（例如箭頭），可將其寫作繪於點上的用例：

  ```rnl
  $ARROWHEAD = @DEFINE(roles=[["p", "point"]]) {};
  $ARROWHEAD_SYM = @DEFINE-SYMBOL {
    @LINE(fill="linecolor", linestyle="none") {(0.4, 0) (-0.4, 0.3) (-0.4, -0.3) (0.4, 0)}
  };
  $ISRC_DOWN = @DEFINE-SYMBOL {
    (0, 3) @PIN(terminal=1, direction="up");
    (0, -3) @PIN(terminal=2, direction="down");
    @LINE {(0, 3) (0, 1.5)};
    @LINE {(0, -1.5) (0, -3)};
    (0, 0) @CIRCLE(radius=1.5);
    @LINE {(0, 0.9) (0, -0.5)};
    $ARROWHEAD @ATTACH (0, -0.6) => @SET-SYMBOL $ARROWHEAD_SYM => @ORIENT("R270")
  }
  ```

  - 第一個角色填入定義本體中的點（採區域座標）。該用例會以其符號繪製於該點上，其朝向繞該點旋轉，並接著隨外層符號一併變換；巢狀用例的變換由內而外依序疊加，因此箭頭會隨器件一起旋轉。
  - 僅供繪圖：外部規則看不到符號定義本體內部，因此其符號須於定義本體內以 SET-SYMBOL 指派；未指定符號的用例不會繪製，並會給出一條警告。符號內部不會展開一般定義的定義本體，約束與連線在該處也沒有意義；此處的 ORIENT 僅為符號內部資料，不參與衝突取捨，亦無優先順序。
  - 若此處的 SET-SYMBOL 直接或透過引入與其他此類用例回到正在建構的符號本身，即形成閉合循環，如同引入循環（9.1）：該條 SET-SYMBOL 失效，該用例不予繪製，定義本體其餘部分照常生效。
  - 將用例繪製在填入其第一個角色的點上僅適用於符號定義本體，符號內部不由求解器佈局。在場景中，相同記法會建立擁有自身的點的用例（12.1 第 5 項），且規則可為其指派符號；風格體系套件的規則無法觸及符號內部。
- 接腳名稱與公式：是否顯示接腳名稱由檢視器決定（9.2.4）；公式單純就是引用屬性的 TEXT（13.6），沒有特殊規則。文字標記語法見 13.6。

#### 9.2.8 符號與物件的匹配

符號不區分為器件符號與用例符號。一個符號能否用於某個物件，取決於其接腳是否匹配該物件的端子。

- **沒有符號的實例。** 不會有實例沒有符號：當沒有任何敘述或規則為實例指定符號時，它採用預設方塊符號（9.2.6），每個端子各有一個接腳，與其他實例一樣被繪製與求解。套件在無法判斷器件種類時，可選擇不為該器件指派符號，以免將其誤繪為錯誤的器件，如同標準套件對未讀到模型卡的電晶體所做的處理；該器件此時繪製為每個節點各有一個接腳的方框。

### 9.3 樣式：DEFINE-STYLE

```rnl
$ink = @DEFINE-STYLE(linecolor="#202020", textcolor="#202020", fillcolor="#ffffff", size=1.2) {};
$accent = @DEFINE-STYLE(linecolor="#1f4fd8", linestyle="bold") {$ink};
$shade = @DEFINE-STYLE(fillcolor="#1f4fd833") {}
```

- 括號內的參數為該樣式自身的屬性，且最後生效。大括號集合僅能引用其他樣式，它們的屬性會依序引入該處，較後者覆寫較前者。沒有基底樣式的樣式寫作 `{}`。
- 樣式僅在 SET-STYLE 指派時才生效（11.3）。相同的屬性亦可直接寫為圖形、TEXT 與 WIRE 的參數（9.2.5、13.1），其數值依 8.3 的兩層優先級取捨。
- 樣式僅控制筆劃與顏色：位置、朝向、形狀（符號或圖形的點）以及文字內容皆不屬於樣式。
- **屬性**：

| 群組 | 屬性 | 取值 |
|---|---|---|
| 線條 | `linecolor` | 顏色；亦作為 `fill="linecolor"` 的顏色 |
| | `linestyle` | `"solid"`（預設）、`"dashed"`、`"dotted"`、`"dash-dot"`、`"double"`（兩條平行實線）、`"bold"`、`"none"`（無線條） |
| | `linewidth` | 線寬，以座標單位計（11.7）；`0` 為極細線，在任何縮放比例下皆保持最細，此為預設值 |
| | `cap` | 線端樣式：`"butt"`、`"round"`、`"square"` |
| | `join` | 轉角樣式：`"miter"`、`"round"`、`"bevel"` |
| 填色 | `fillcolor` | `fill="fillcolor"` 的顏色 |
| 文字 | `textcolor` | 文字顏色；未指定時使用 `linecolor` |
| | `size` | 字級，以座標單位計（11.7） |
| | `font` | 字型名稱，僅作提示；沒有此字型的檢視器改用自身字型 |
| | `bold`、`italic` | 整段文字的粗體或斜體，`true` 或 `false`；標記語法 `\textbf` 與 `\textit` 仍可套用於局部片段（13.6） |
| | `textvisible` | 文字可見性（textvisible）：文字是否顯示，預設為 `true`，或設為 `false`。設為 `false` 的文字不予繪製、不佔空間且無法點選：不參與碰撞偵測、不計入符號邊界框，亦不計入 9.2.5 的排成一欄計算。其內容、key、位置與屬性引用仍保留並照常評估；檢視器可提供顯示隱藏文字的選項。若要隱藏標籤，套件可定義樣式並套用之：`$hidden = @DEFINE-STYLE(textvisible=false) {};` 與 `# @SELECT-LABEL(recursive=true) => @SET-STYLE $hidden`；單一文字亦可直接寫出，如 `#M1 @TEXT("note", key="memo", textvisible=false)` |
| 其他 | `arrowsize` | 線端箭頭的長度，以座標單位計（9.2.5） |

- 一條線僅有五個屬性：顏色、線型、線寬、線端樣式與轉角樣式。`"bold"` 以兩倍線寬繪製，當線寬為 0 時則繪為極細線的兩倍；虛線的線段長與間距以及雙線的間距由實作決定，與線寬成比例。後續語言版本可能會新增更多 `linestyle` 取值（16.1）。
- `"none"` 不繪製線條，亦不繪製線端箭頭（箭頭屬於線條，9.2.5）；`fill="linecolor"` 仍會取用 `linecolor` 的顏色，因此僅填色不描邊的圖形寫作 `fill="linecolor", linestyle="none"`，其顏色仍會隨主題切換而改變。連線與圖形皆接受此設定；設為此線型的連線是看不見的連線，但依然是一條連線（13.1）。
- **顏色**以 CSS 十六進位顏色寫出：`"#RRGGBB"` 或 `"#RRGGBBAA"`，或其簡短形式 `"#RGB"` 與 `"#RGBA"`。透明度位於最後：`00` 為完全透明，`FF` 為完全不透明；省略透明度時為不透明。線條與填色各自擁有顏色屬性，因此透明度可分開設定，如上例 `$shade` 僅使填色半透明。本版本不接受顏色名稱或 `rgb()`。顏色皆為字串。
- 本版本不提供圖樣填色、漸層或陰影；不提供文字以外物件的可見性（顯示與隱藏由檢視器負責，16.2；`textvisible` 僅針對文字，以便日後能為其他物件加上各自名稱的可見性屬性，屆時文字須兩者皆為 true 才顯示）；亦不提供主題（theme）與設定檔（profile）等獨立物件（主題即為一組樣式與規則的套件，透過 USE-PACKAGE 引入，16.2）。
- 當沒有任何樣式與參數為某屬性給出值時，使用渲染器自身的預設值；這不算錯誤（原則 2.7）。標準套件提供可攜的預設外觀（16.3），可由使用者所寫的規則與敘述覆寫。
- 未知屬性視同語法錯誤處理（原則 2.3）。

### 9.4 一般定義：DEFINE

```rnl id=gdef
$TAIL_MID = @DEFINE(roles=["a", "b", "t"]) {
  %mid = (_, _);
  {?a %mid ?b} @DISTRIBUTE("left-to-right");
  {%mid ?t} @ALIGN("x")
};
$CHAIN_ROW = @DEFINE(roles=["source", "{chain}", "load"]) {
  {?source ?chain ?load} @ORDER("left-to-right")
};
$GND_BELOW = @DEFINE(roles=[["t", "pin"]], parameters=[["gap", 2]]) {
  %g = $GROUND @ATTACH ?t::net;
  ?t::net @WIRE {?t %g::pin};
  {?t %g::pin} @ALIGN("x");
  %g::pin ?t @DISTANCE("bottom-to-top", exact=?gap)
};
%c1 = #M1:3(a) #M2:3(b) #M5:1(t) @AS $TAIL_MID;
#R1(source) {#R2 #R3}(chain) #R4(load) @AS $CHAIN_ROW;
# @SELECT-INSTANCE => @SELECT-PIN(net="vss", wired=false) => $GND_BELOW @ATTACH(gap=3)
```

- 一般定義由角色列表、參數列表與定義本體組成。在定義本體中，角色與參數以 `?name` 引用（6.10）。定義的作用由其內容決定；見 9.5。
- **套用**：AS 與 ATTACH 以物件填入定義的角色並產生一個用例。這兩個關鍵字做的是同一件事，僅在於定義寫於何處：
  - AS 將定義寫在最後，讀作「這些物件，作為某某結構」；用於語義與佈局，例如 `#M1(left) #M2(right) #M5(tail) @AS $DIFFERENTIAL_PAIR_N`；
  - ATTACH 將定義寫在最前（在明確寫出的物件之前），標準寫法將關鍵字放在定義之後，例如 `$GROUND @ATTACH &vss`；它讀作「將某某事物，套加到這些物件上」，用於虛擬組件與自動補齊（第 12 章、10.5）。
  - 選用另一個關鍵字不算錯誤，僅讀起來較彆扭；將定義寫錯位置則為錯誤（4.2 第 7 項）。透過管線傳入的物件會直接依角色匹配，此時兩個關鍵字的寫法看起來相同；請依定義的用途選擇。
  - 選用原則：當物件共同構成該事物（例如電路結構、佈局，或由這些物件組成的區域繪圖方式）時，使用 AS；當將該事物套加到物件上（例如接地、連接埠標記、未連接標記、交接圓點、每個實例的標籤，或自動補齊）時，使用 ATTACH。標準例句為 `#M1(left), #M2(right) and #M5(tail) are treated @AS $DIFFERENTIAL_PAIR_N` 與 `$GROUND is @ATTACH to &vss`（4.5）。
- **角色列表**：參數 `roles`，是一個陣列，其元素為角色名稱或 `[name, kind]` 配對。DEFINE 的兩個參數皆僅能依名稱傳入。
  - 列表可以為空，`roles=[]`：此時單獨套用該定義，例如 `$PORT_LIST @ATTACH`，該用例沒有主物件；它仍擁有自身的點（14.1）。
  - 寫作 `"{name}"` 的項目是集合角色，整體接收一個集合；其餘皆為單一角色（5.2.1 第 4 項）。
  - 集合角色收到單一物件時，將其視為只含該物件的集合；空集合亦有效，定義本體中成員過少的約束會自動滿足（第 14 章）。
  - 單一角色收到集合時，會對每個成員各套用一次該定義，收到空集合時則套用零次；在單次套用中，至多只能有一個單一角色收到多於一個成員的集合（否則敘述失效，5.2.1）。
  - 套用的定義其角色皆為集合角色的規則，在其集合角色全為空的層級中不產生用例：規則會在其到達的每一個層級中求值（10.4），僅在集合角色有內容的層級才產生用例，如同單一角色收到空集合時套用零次。不是規則的敘述，即使其集合角色為空仍會產生其用例。因此標準系列 0.4 的自動補齊只在有連接埠標記的層級中，產生該層級的那一欄連接埠標記（12.4）。
  - 當集合角色的 `?name` 寫在 `{…}` 內時，它是該集合中的一個項目（5.2）：在約束中它代表該項目處的所有成員（14.1），因此上例中的 ORDER 會使 R2 與 R3 各自位於 R1 與 R4 之間。
  - 集合角色收到成員本身包含集合的集合時，原樣接收之；由定義本體決定如何使用。
  - 集合角色不對應任何端子（6.4）。
  - 在單次套用中，每個角色僅可標記一次；若要為集合角色傳入多個物件，須將它們寫成一個集合，如上例的 `{#R2 #R3}(chain)`。
  - **種類**：寫作 `[name, kind]` 的項目宣告該角色接收哪一種物件；僅寫名稱的項目則接收任何種類。種類名稱即詞彙表所列者（5.3）：`"instance"`、`"terminal"`、`"pin"`、`"net"`、`"point"`、`"wire"`、`"usage"`、`"bundle"`、`"text"`、`"annotation"` 與 `"label"`。在角色宣告中，`"instance"` 亦接收疊畫，`"terminal"` 亦接收疊畫的端子（11.8）；陣列表示可接收多種之一，例如 `["p", ["net", "terminal"]]`。屬於其中之一種類的物件原樣接收；不屬於其中任一種但可轉換為其中一種或多種者（5.2.4），依陣列順序轉換為最先符合的那一種，因此 `#R1::p` 傳入 `["net", "terminal"]` 會成為該接腳的網路。接收 `"net"` 的角色亦接收空節點（單獨的 `&`），表示該角色不連接任何網路（6.3）；集合角色則不接收，因為空節點不能成為集合成員。集合角色的種類套用於其每個成員，例如 `["{members}", "instance"]`。沒有專門指代某特定定義用例的種類。
  - 當角色收到錯誤種類的物件時，整次套用失效，診斷會說明哪個角色、預期接收什麼以及實際收到什麼；當集合角色的某個成員種類錯誤時亦同。當篩選逐一建立套用時，僅收到錯誤物件的那一次套用失效。
  - 附註：若定義本體為空，沒有任何內容會檢查填入角色的物件，此時唯有宣告種類才能偵測填錯的角色；若定義本體非空，展開後的每條敘述自身亦會受檢查（9.5）。宣告種類亦使定義本體中對角色的使用能在定義處即接受檢查（6.9）。
  - **可選角色與數量**：單一角色須填入；集合角色可留空，此時成為空集合。當物件依順序傳入且物件數少於角色數時，剩餘的角色須全為集合角色；當物件標記角色時，未寫出的集合角色即為空集合。沒有最小或最大成員數量限制：成員過少的約束自動滿足（第 14 章）。不同形狀的變體須寫成另一個定義（見下方衍生與擴充）。諸如同一個物件填入兩個角色或預期連接關係等有效性規則，見 9.5。
- **參數列表**：參數 `parameters`，可以省略。每個元素為參數名稱或 `[name, default]`。
  - 參數寫在 AS 與 ATTACH 的括號中傳入，如 `$GND_BELOW @ATTACH(gap=3)`，可依參數列表順序按位置傳入或依名稱傳入；兩者併用時，依位置傳入者排在前面（4.2 第 9 項）。標準寫法依名稱寫出它們（4.3）。不在參數列表中的名稱會使套用失效。當篩選逐一建立套用時，每次套用皆使用相同的參數。
  - 定義本體中凡可容納字面量之處皆可改寫為參數佔位符：參數的值、陣列的元素、點的座標。因此於定義本體內，「參數僅能容納字面量（4.1）」的規則放寬為「字面量或參數佔位符」；展開之後它們便再度成為字面量。AS 與 ATTACH 自身的參數僅能是字面量，不能傳遞物件；物件須透過角色傳入。
  - 未傳入且沒有預設值的參數，於使用處視同未寫：作為具名參數時視同未寫（如 `@TEXT(?label, size=?size)` 中的 `size=?size`，隨後該文字使用 TEXT 自身的預設字級或其樣式的字級，11.3）；作為點的座標時視同 `_`；在依位置傳入的參數或陣列元素中則沒有定義的含義，該敘述會失效。因此無須為必填參數另設標記。
  - 參數適用於數值與文字等量化設定；結構不同的變體應寫為獨立定義，語言本身不強制此點。參數僅傳入定義本體；無法依參數值篩選用例。
- 角色名稱與參數名稱共用同一張名稱表，須全部相異；兩者皆不得為標準子物件名稱（6.5）。參數亦不得名為 `priority`，此為 AS 與 ATTACH 的標準參數（14.8）。
- **用例本身**：在一般定義的定義本體中，單獨的 `?` 指正在展開的用例本身，以其自身的點參與（14.1）。`{?members::position ?} @ALIGN("y")` 將用例的點置於其成員的高度上，使針對該點的約束（如另一結構中繞軸的 DISTRIBUTE）能帶動其成員一併移動；`::position` 使身為無符號用例的成員仍計為單一點（14.1）。單獨的 `?` 是一個物件，而非角色。它可像用例一樣接路徑（6.5）：`?::position` 是它自身的點，定義本體中的連線或圖形可止於該點（5.2.4），而 `?::` 後接其符號的接腳名稱即指該接腳，例如名為 pin 的接腳寫作 `?::pin`。
- **定義本體中的規則**：定義本體可以包含規則（即篩選及由其接管線傳出的敘述，10.1）。它們作為該用例所在層級的規則運作，位於其 AS 或 ATTACH 敘述所在的位置（8.5、10.4），並依該處寫下的規則在 8.2 的對應階段生效：SET-SYMBOL 在符號佇列、走線關鍵字規則在步驟 5、產生規則在步驟 6、SET-STYLE 在樣式佇列。在定義本體中，`#` 即為該層級（10.3）。若該用例本身是在步驟 6 逐一產生的，其定義本體中的步驟 5 或步驟 6 規則（10.4）會失效，其餘規則則在後續階段照常生效，如同 10.5 所述。
- 定義本體中綁定的 `%` 名稱為區域名稱：每次套用皆為它們建立新物件，從外部透過該用例引用（見下文）。多個套用共享的物件（如對稱軸）須透過角色傳入。
- 套用時可為物件標記角色（`#M1(a) #M2(b) … @AS $T`、`$T @ATTACH #M1(a) #M2(b) …`），或依角色列表順序傳入（`#M1 #M2 … @AS $T`）。若有單一角色未填入，或傳入的物件多於角色數，整條敘述失效；未填入的集合角色則為空集合。
- 每次套用產生一個用例，記錄所用的定義與填入各角色的物件，且可予以命名（如 `%c1`）。刪除該敘述亦會移除由它展開的描述。用例沒有 key：每次套用皆為獨立物件（5.8）。
- **展開**：
  - 佔位符替換為引數與參數值；
  - 區域名稱替換為新的控制代碼「用例 + 區域名稱」，寫作 `%c1::mid`；未命名用例在診斷中依其敘述位置顯示；
  - 來自定義本體外部的名稱不在套用處重新解析（6.9）；
  - 展開結果在 AS 或 ATTACH 敘述所在位置提交，並在衝突取捨中佔用該位置（8.5）。
- **定義本體中的座標**：一般定義的定義本體中的字面量座標——位於如 `(1, 0)` 的點或 PLACE 中——是相對於該用例自身的點的偏移量（14.1），沿層級的座標軸計算：`(1, 0)` 位於該點右側 1 單位，`(0, 0)` 即該點本身 `?::position`。`_` 保持自由，而座標中的參數佔位符替換後同樣成為偏移量。僅有該點會移動定義本體：作用於用例的 ORIENT 只會旋轉其符號，不會旋轉其定義本體所繪製或擺放的內容（11.2）。因此定義可繞自身的點繪製標記（如兩條交叉於 `(0, 0)` 的 LINE），並將其點繫於接腳（12.1 第 5 項）。在定義本體自身中對單獨的 `?` 寫 PLACE 會失效，因為其偏移量將相對於自身。在定義本體之外（如求解器記錄中），位置一律為層級座標（14.8）。
- 巢狀用例逐層存取（`%c1::inner::mid`）。用例亦可填入另一個定義的角色：若有自訂定義 `$OTA = @DEFINE(roles=[["pair", "usage"], ["load", "usage"]]) {}`，則 `#M1(left) #M2(right) #M5(tail) @AS $DIFFERENTIAL_PAIR_N => %cm1 @AS $OTA` 是一個放大器，其 pair 角色填入差動對用例，load 角色則填入電流鏡 `%cm1`（5.5）。
- **循環套用**：展開過程中若出現套用一個外層用例正在展開的定義（直接或透過其他定義），即形成閉合循環。該次套用失效，其診斷須列出整條鏈，其餘部分照常生效。下例中，將 `$A` 套用至 M1 會展開 `$B`，其中套用 `$A` 則形成循環 `$A → $B → $A` 並失效；`$B` 中的 ORIENT 仍會翻轉 M1：

  ```rnl error
  $A = @DEFINE(roles=["x"]) {?x @AS $B};
  $B = @DEFINE(roles=["x"]) {
    ?x @AS $A;               /* closes the cycle $A → $B → $A: this application fails */
    ?x @ORIENT("MY")
  };
  #M1 @AS $A
  ```

- **從外部引用區域物件**：

  ```rnl use=gdef
  $DP_BLOCK = @DEFINE(roles=["in_p", "in_n"]) {
    %pair = {?in_p ?in_n} @GROUP
  };
  %dp1 = #M1(in_p) #M2(in_n) @AS $DP_BLOCK;
  %c1::mid @PLACE(x=20);              /* moves the midpoint of c1 */
  {%c1::mid #M9:1} @ALIGN("x");       /* aligns the drain of M9 with the midpoint of c1 */
  %dp1::pair @PRIORITY("disabled")    /* turns off only the group expanded for dp1 */
  ```

  - 定義本體中每個具名的區域物件皆可從外部透過該用例引用，寫作 `usage::local_name`；未命名者無法觸及，唯有求解器記錄可透過編號引用（5.9）。是否命名由定義作者決定，秉持「欲引用物件則命名之」（5.7）；沒有額外的匯出列表。
  - 路徑可串接：`%st1::dp::mid` 是 st1 定義本體中區域用例 dp 的 mid。穿過角色亦同：`%st1::pair::mid` 是填入角色 pair 的用例的 mid。
  - 這些是一般引用：可為它們新增事實（PLACE、SET-STYLE、TEXT、PRIORITY 等），可在其他敘述中使用，亦可填入其他定義的角色；與展開內容的事實發生衝突時依 8.5 取捨。不得從外部重新綁定區域名稱：`%c1::mid = …` 為錯誤。
  - 名稱：透過 `::` 在用例上存取的名稱須唯一。因此區域名稱不得與角色名稱或標準子物件名稱相同（於定義處檢查），且寫在該用例上之文字的 key 亦不得與這些名稱相同（6.5、13.3）。區域名稱可與參數名稱相同：參數是數值，而 `::` 不存取數值。
  - 優先順序：從外部直接寫在區域物件上的 PRIORITY 敘述會覆寫該用例的優先順序（14.8）。
  - 無法觸及者：未命名用例的區域物件（除非從求解器記錄以編號引用，5.9），以及由篩選逐一產生之用例的區域物件。以用例為作用域的篩選仍僅選出其角色的成員，而不選出其區域物件（10.1）：透過用例僅能以名稱觸及區域物件。以層級為作用域的篩選則將它們作為該層級的物件選出，如同任何其他物件（例如下文的 `# @SELECT-USAGE $FILTER`）；規則無法做到的是點名它並未編寫的定義中的區域物件。
  - 因此區域名稱是定義介面的一部分：當定義更改區域名稱時，外部引用便找不到它而失效（第 7 章），求解器結果亦隨之過時，提示會建議重新求解（第 17 章）。標準套件會說明其定義中哪些區域名稱可供依賴。
- **定義本體中的標記法**：角色與參數寫作 `?name`，區域名稱寫作 `%name`（6.9、6.10）。
- **衍生與擴充**：僅透過組合達成；沒有繼承關係（9.1）。衍生定義的定義本體會套用基底定義並加上自身的敘述：

  ```rnl
  $FILTER = @DEFINE(roles=["in", "out"]) {};
  $LOWPASS = @DEFINE(roles=["in", "out", "r", "c"]) {
    %f = ?in(in) ?out(out) @AS $FILTER;
    {?r ?c} @ORDER("left-to-right")
  }
  ```

  - 新增內容透過定義本體中的敘述加入，數值變體則透過參數達成；若要在較低層級遮蔽並擴充定義，定義本體須引用同名的外層定義（6.9）。
  - 依基底定義篩選不需特殊規則：從衍生定義展開的 FILTER 用例已在場景中，故 `# @SELECT-USAGE $FILTER` 會選出它，且為 `$FILTER` 編寫的規則亦會作用於低通濾波器上，僅作用於其內部的 FILTER 用例，而不影響衍生定義另外加入的敘述。
  - 沒有單獨移除基底定義某一部分的機制：衍生定義的定義本體雖可寫 `%f::x @PRIORITY("disabled")` 來關閉其中一部分，但外層用例上的優先順序會覆寫該設定（14.8）；若要可靠地略過某部分，請將基底定義拆分為更小的定義，或另寫一個定義。

### 9.5 一般定義的用途

定義的作用由其內容決定，而非由關鍵字決定：

```rnl
$PAIR = @DEFINE(roles=["in_p", "in_n"]) {};                /* meaning: roles only */
$SIDE_BY_SIDE = @DEFINE(roles=["a", "b"]) {               /* layout: constraints in the body */
  {?a ?b} @ALIGN("y");
  {?a ?b} @ORDER("left-to-right")
};
$PROBE = @DEFINE(roles=[["p", "net"]]) {};                 /* virtual part: a rule gives its usages a symbol (chapter 12) */
$PROBE_SYM = @DEFINE-SYMBOL {(0, 0) @PIN(terminal="p"); (0, 0) @CIRCLE(radius=0.5)};
# @SELECT-USAGE $PROBE => @SET-SYMBOL $PROBE_SYM
```

在標準套件中，`$CURRENT_MIRROR_N`、`$MIRRORED_LAYOUT` 與 `$GROUND` 分屬這三類；`$DIFFERENTIAL_PAIR_N` 則兼有角色與位於其定義本體中的預設佈局（見下文）。

- 它們本質上是同一種事物：一個用例（記錄所套用的定義與填入各角色的對象），加上由定義本體展開的描述。這兩部分有不同的對象：
  - 由定義本體展開的約束交由求解器處理，必須滿足，衝突時依 8.5 取捨；
  - 用例本身供人與大型語言模型閱讀，並供 RNL 自身的篩選與規則使用（10.1）。

  因此佈局定義的用例同樣承載語義；定義本體為空的定義（如 `$PAIR`）僅透過角色記錄語義，其含義由標準套件或其作者說明。記錄語義的定義亦可在其定義本體中附帶繪圖方式（見下文）。
- 語義用例不是註解：它的引用須能找到、角色須匹配、基本有效性須受檢查（原則 2.4），且篩選與規則可使用它；僅是未規定它要如何繪製。
- 「是什麼」與「怎麼畫」可寫在同一個定義中，也可分寫在兩個定義中。定義可在其定義本體中以 `"low"` 優先順序附帶預設繪圖方式：作者自身的事實優先於它，且用例的優先順序可關閉或提高它（如 `%dp1 @PRIORITY("disabled")`，或對該定義所有用例寫 `# @SELECT-USAGE $DIFFERENTIAL_PAIR_N => @PRIORITY("disabled")`），而該用例仍記錄物件是什麼（14.8）。從語義到繪圖的步驟亦可寫作套件中的規則，更換套件即可改變畫法：`# @SELECT-USAGE(recursive=true) $DIFFERENTIAL_PAIR_N => @AS $DP_LAYOUT`；刪除該佈局用例不影響語義用例。標準套件將預設畫法寫在定義的定義本體中，其中每條約束皆為 `"low"` 優先順序，例如差動對的尾端電晶體位於差動對中央下方、`$BRANCH` 的成員由上而下排成一欄（16.3）。
- **繪圖方式一律寫在 RNL 中**：某種語義之所以繪製成特定樣貌，僅源於 RNL 在其定義本體中或透過規則套用佈局定義（可能在套件中）所寫出的描述；不得依賴渲染器針對某種語義的預設慣例。定義是否附帶繪圖方式由其套件決定；本標準對此不作進一步規定。未經 RNL 描述的部分如何佈局由實作決定（原則 1），但這不是針對語義的繪圖慣例，不得依賴。至於渲染器決定未加描述物件的預設樣式（原則 2.7），以及沒有符號的實例採用預設方塊符號（9.2.6），則是另一回事。
- **詞彙屬於標準套件**：基礎的語義定義與標準虛擬組件是標準套件的內容，不屬於本語言標準的一部分（16.3）。標準套件中的定義如何說明其含義與角色，亦由標準套件決定。使用者自訂定義的含義即為其定義本體；其名稱僅供人閱讀。
- **基本有效性**（原則 2.4）：定義的語法不檢查兩個角色是否填入了同一個物件。單次套用的基本有效性包含：引用能找到、角色收到正確種類、單一角色已填入（9.4），且展開後的每條敘述自身皆合法。

  ```rnl error
  $DP_LAYOUT = @DEFINE(roles=[["in_p", "instance"], ["in_n", "instance"]]) {
    {?in_p ?in_n} @ALIGN("y");
    ?in_p ?in_n @DISTANCE("left-to-right", min=4)
  };
  #M1(in_p) #M1(in_n) @AS $DP_LAYOUT      /* the expanded DISTANCE asks M1 to be at least 4 from itself */
  ```

  - 在此例中，展開後的 DISTANCE 自相矛盾：它失效並附帶診斷，且僅它本身被捨棄（5.5、7.3）；ALIGN 照常成立。定義本體為空的定義（如上方的 `$PAIR`）無法偵測這類填入方式：`#M1(in_p) #M1(in_n) @AS $PAIR` 不會回報錯誤。
  - 兩端接在同一個網路上的虛擬組件具有明確含義，因此「同一物件填入兩個角色」不能一概視為錯誤。
  - 進一步的檢查（如要求兩個角色須為不同物件）須寫作斷言（15.3）。
- **關鍵字與一般定義**（1.5 第 7 項）：凡實作本身必須理解、且無法以其他描述寫出的，皆為關鍵字，如原子約束、GROUP、WIRE、TEXT 與 CURRENT；凡可寫入一般定義定義本體中的，皆為一般定義，如差動對、電流鏡、接地與電源，以及訊號流（14.6）。DEFINE-SYMBOL、DEFINE-STYLE、SET-SYMBOL 與 SET-STYLE 同樣是關鍵字：符號定義本體採區域座標且在定義處評估；樣式屬性為字面量；SET-SYMBOL 與 SET-STYLE 設定既有物件的單一屬性並在所有物件建立後於佇列中決定，而 AS 與 ATTACH 每次皆產生一個新物件。
- 定義是依其名稱解析後所指向的定義本身來識別，而非依名稱字串：當較低層級定義了自己的 `$DIFFERENTIAL_PAIR_N` 時，那是另一個定義，套件中為標準 `$DIFFERENTIAL_PAIR_N` 編寫的規則不會識別它。
