## 2 嵌入宿主網表

### 2.1 兩階段剖析

- 宿主配接器：
  - 識別宿主的合法一般註解，並決定哪些行是載體（2.2）；
  - 判斷每條註解屬於哪個層級，以及每筆記錄與每個子電路來自哪個檔案與哪次引入（6.1）；
  - 提供原始碼位置與文字順序；
  - 提供宿主物件：實例、網路、端子、子電路連接埠與模型類型。
- RNL 核心僅在這些註解中尋找記錄。不得忽略上下文而在整份網表中搜尋 `@RNL`：宿主敘述或宿主字串中的相同字元並非 RNL。
- 解譯器在處理 RNL 之前會完整剖析宿主網表（原則 2.9）。

### 2.2 載體

記錄寫在宿主的整行註解中；這類註解行稱為載體。宿主配接器逐行判斷哪些行是載體，移除註解字元及其後的一個空格，並將其餘內容傳遞給 RNL 核心（2.1）。

- **僅限整行註解。** 不讀取也不寫出任何行尾註解（`$`、`;`、`//`、`!` 等），且不使用區塊註解。
  - 行尾註解中的 `@RNL` 僅為宿主文字，並會給出警告。
  - 附註：行尾是否為註解取決於方言、模式與選項：在 HSPICE 中 `$` 可緊接在數字之後（`1k$x`），在 ngspice 的 `ps` 模式中 `$` 是一般字元，而 Eldo 可透過 `.COMCHAR` 修改註解字元；在 CDL 中，`$SUB=` 之類則是資料。寫在行尾也會改變宿主敘述所在的行（原則 2.1）。SPICE 與 Spectre 沒有區塊註解（Spectre 僅在 `reliability{}` 內部有）。
- **各宿主的註解字元。**

  | 宿主 | 註解字元 |
  |---|---|
  | SPICE 家族：SPICE3、ngspice、HSPICE、Xyce、LTspice、PSpice、WRspice、Eldo 與 CDL 網表 | `*` |
  | 處於 Spectre 語言模式的區段：`.scs` 檔案，或 `simulator lang=spectre` 之後的文字 | `//` 或 `*` |
  | 處於 Spectre 的 SPICE 語言模式的區段，包含無 `.scs` 副檔名且不以 `simulator lang=spectre` 開頭的引入檔案 | `*` |

  - `*` 在 Spectre 的兩種語言模式下皆為註解。`//` 僅於 Spectre 語言模式的文件中有記載，Eldo 與 CDL 則未支援。
  - 同一筆記錄的多行可以混用 `//` 與 `*`。寫出記錄的工具須沿用檔案中既有記錄的格式；若尚無記錄，則在 SPICE 模式下寫 `*`，在 Spectre 模式下寫 `//`。
  - 載體屬於外層形式，不會變更（16.1）。支援新宿主僅會新增載體，不會變更既有載體。
- **載體行。** 記錄的每一行皆須滿足以下兩個條件：
  - 註解字元位於第 1 欄，前方無任何空白字元。
  - 註解字元之後要嘛沒有內容、要嘛只有空白字元（構成空註解行），要嘛是一個 ASCII 空格後接內容。因此 `*@RNL`、`*#M1` 與 `//@RNL` 均不是載體行。

    附註：HSPICE 與 PSpice 要求 `*` 位於第 1 欄，且工具對縮排行的處理方式不同。緊貼註解字元的文字對其他工具具有特殊意義：ngspice 與 WRspice 會將 `*#` 行作為命令執行，WRspice 亦會執行 `*@` 行；`*.` 開始一條 CDL 指示詞（如 `*.PININFO`），`*|` 開始 DSPF 資料，而 `//pragma` 則是 Spectre 的加密封包標記。
  - 不符合這些條件的註解行（如 `*#M1 …`、`** …` 或縮排的 `* …`）會中斷尚未完成的記錄：整筆記錄失效（2.4）。在記錄之外，出現在這類行中的 `@RNL` 不是入口，並會給出警告。
  - 承載 RNL 的行不應以 `\` 結尾。這類行會給出警告，且工具不得寫出這類行。RNL 會照常讀取且不會失效；有風險的是宿主網表。附註：WRspice 會將下一行接續至這類註解行，透過 `-E`（經 C 前處理器）執行的 Spectre 以及啟用 `SLASHCONT` 的 Eldo 也可能如此；下一行的宿主敘述便會被吞入註解中。
- **不讀取 RNL 的位置。** 這些位置中的 `@RNL` 會給出警告，且工具不得寫入這些位置：
  - 每個宿主檔案的第 1 行，以及宿主視為標題的其他行（例如 WRspice 中 `.newjob` 之後的那一行）。主檔案的第 1 行是其標題，但該檔案被引入時則非標題；系統從不讀取第 1 行，以確保檔案作為主檔案與作為引入檔案時讀取方式一致。因此檔頭記錄最早可寫在第 2 行（2.8）。
  - 主檔案 `.end` 之後的文字。附註：在 `.end` 之後，ngspice 會繼續讀取，Xyce 會停止，而 HSPICE 與 PSpice 可能將其視為下一個電路。
  - 宿主不視為網表註解的區域：控制腳本（ngspice 會執行 `.control … .endc` 內的 `*#` 行）、其他語言的區塊與檔案（WRspice 的 `.verilog`、Spectre 的 `reliability{}`；以 `ahdl_include` 或 `.hdl` 帶入的 Verilog-A 檔案僅依 2.9 讀取）、加密文字、前處理移除的部分，以及未被選取的 `.lib` 區段。配接器無法確定分類的區域視為不讀取，並附上警告。
- **讀取但附上警告的位置：**
  - 介於一條敘述與其續行（`+` 行）之間的註解行。它們對 RNL 的含義明確，因此會被讀取；但各宿主對其處理不同（PSpice 會回報錯誤，SPICE 3f4 會將後方的 `+` 行併入註解）。這些行會給出警告，且工具不得寫入該處。
  - 以明文撰寫的加密區域（`.prot … .unprot`、`protect … unprotect`）。會讀取並附上警告：一旦該區域完成加密，記錄便會消失。
- **檔案起始的語言模式**是傳入工具的輸入設定。預設由副檔名決定，`.scs` 採用 Spectre 模式，其餘檔案採用 SPICE 模式，與 Spectre 本身一致；使用者可為每個檔案（含引入檔案）更改設定。起始之後，逐行依前述規則判斷（`simulator lang=`）。哪些行處於 SPICE 模式、哪些行處於 Spectre 模式，決定了帶有 `language` 的記錄所作用的對象（2.8），因此工具會依使用者所選的語言讀取每個檔案；工具如何讓使用者選擇則不在本標準範圍內。
- **寫出建議：**
  - RNL 本身不限制行長（2.4）。產生器應在空白處斷行，每行至多 132 個字元：這是舊版 PSpice 的限制，也是常見宿主中最嚴格的（HSPICE 允許 1024，Eldo 為 2000）。知道其宿主限制的配接器則遵循該宿主。當單一記號無法容納於一行時，工具須回報錯誤且不得寫出（字串無法跨行續寫，3.7）。
  - 編碼規定見 3.1。

### 2.3 入口

- 一筆記錄以 `@RNL` 開頭。入口僅識別大寫形式。
- 所有宿主使用相同的入口 `@RNL`；它是原則 2.1 中的子標記。
- `@RNL` 可寫在註解行的中間；同一行位於其前方的文字屬於宿主註解。
- **`@` 前方的空格。** 入口 `@RNL` 與關鍵字的 `@` 前緊鄰的字元須為一個 ASCII 空格（U+0020）；TAB、換行或行首皆不算。在載體行上，註解字元後方緊接的空格即計為 `@` 前方的空格，例如 `* @RNL`。字串、加引號名稱或 `/* */` 註解中的 `@` 不受此限制。
  - 因此寫在 `{`、`=>`、`=` 或 `;` 後方的關鍵字，前方同樣需要空格：`#M1 @SET-SYMBOL { @DEFINE-SYMBOL {…}}`、`%x = @DEFINE(…)`、`#M2 @PLACE(30, 20) => @ORIENT("MY")`。
  - 附註：`@` 常見於宿主註解中，例如電子郵件地址與 `@param`；依此規則，這類文字不會被誤認作 RNL。此外 WRspice 會執行以 `*@` 開頭的行（2.2）。
  - 在記錄之外，`x@RNL` 不是入口，僅為宿主註解。在記錄之內，前方沒有空格的 `@` 既不是關鍵字也不是自由文字字元：它是語法錯誤，所在成員會失效（7.4）。

### 2.4 記錄的範圍

- 一筆記錄寫作 `@RNL(…) {…}`。括號內的記錄標頭可以省略；大括號不可省略，即使只有單一條敘述也需要大括號。記錄標頭的括號須緊貼 `@RNL`，如同關鍵字的參數括號緊貼關鍵字（3.5）：`@RNL (type="header") {…}` 為錯誤，整筆記錄失效。
- 一筆記錄自 `@RNL` 起，至與其第一個 `{` 配對的 `}` 為止。尋找配對 `}` 時會略過字串與 `/* */` 註解。記錄標頭中的括號亦會略過；在第一個 `{` 之後，每個大括號皆計入配對（包含參數括號內的大括號），以確保未閉合的括號僅使所在成員失效（7.4）。字串不可跨行（3.7）：若未於同行閉合，則於該行結束，且該筆記錄視為不完整（7.4）。
- **跨越多行的記錄。** 一筆記錄可寫在多行連續的註解行上（載體，2.2）。移除每行的註解前綴後將內容接合；換行視為空白字元（3.5）。
  - 僅有 `*`（或 `*` 與空白字元）的空註解行視為空白字元，記錄繼續延伸。
  - 若在閉合 `}` 之前遇到非載體行——例如宿主敘述、`.subckt`、`.ends` 或 `.include` 等行、完全空白的行，或寫法不符合載體條件的註解行（2.2）——或是檔案結束，則該記錄不完整並整體失效。因此記錄絕不會跨越子電路或引入檔案的邊界。若要在記錄內留空一行，須寫僅含 `*` 的行。
  - 若在記錄結束前於字串與註解之外出現新的入口 `@RNL`，則前一筆記錄不完整並整體失效，讀取隨即從新入口重新開始。因此漏寫一個 `}` 至多只會失去一筆記錄。
  - 不完整的記錄是錯誤，且診斷須說明該記錄不完整以及在何處中斷。多出一個空白行就會導致整筆記錄失效；這極易發生，不得靜默略過（7.6）。
  - 記錄內的每一行註解都是 RNL。夾雜其中的一般備註行（如 `* the next line is for M2`）會被讀作自由文字，若包含不能作為自由文字的字元即構成錯誤。記錄內的備註須寫在 `/* */` 中（3.4）。
  - RNL 不限制行長；宿主的限制由配接器處理。長敘述可在空白處斷成多行；記號與字串不得拆開（3.5）。產生器的建議見 2.2。
- 記錄結束後的同一行上若還有記號，構成錯誤：這些記號失效，而該筆記錄本身照常生效。唯獨新的 `@RNL` 例外，因此同一行可容納多筆記錄。
- 註解載體、入口 `@RNL` 與記錄標頭不隨語言版本改變，後續版本亦不更改它們（16.1）。本體的大括號在本版本中依上述方式配對。記錄標頭的欄位見 2.8。

### 2.5 停用記錄與宿主文字

- 記錄之外且不含 `@RNL` 的註解行即為宿主註解，整體略過。
- **停用記錄。** 在註解行中，若 `/*` 前方僅有空白字元或註解，或緊接在一筆記錄之後，則會開啟一段延續至 `*/` 的註解。其中的 `@RNL` 不視為記錄。
- 寫在註解行文字中間的 `/*`（例如 `models/*.lib`）僅為宿主文字。
- **宿主註解的結尾。** 載體是整行註解（2.2）：宿主註解於該行末尾結束，行內的任何內容均無法提前結束它，因此宿主註解的結尾不會與 RNL 文字衝突。

### 2.6 層級

- 層級依文字劃分；其階層關係見 6.1：
  - 主檔案的檔案層級：寫在主檔案中且位於所有 `.subckt … .ends` 之外的內容。這是電路的頂層。
  - 每個引入檔案的檔案層級。`.lib` 的區段亦依相同方式處理。
  - 每個 `.subckt … .ends`。
  - 網表引入的每個 Verilog-A 檔案的檔案層級，以及其中的每個模組（2.9）。
- 記錄屬於它所寫在的層級（原則 2.5）。
- **跨檔案順序。** 被引入的檔案自成一個層級，位於引入它的層級之下（6.1）。因此引入行寫在何處並不影響順序，這與 USE-PACKAGE 不同（16.2）；並列引入的檔案之間也不會彼此影響。在同一層級內，順序即為文字順序。
- **scope。** 記錄可透過 `@RNL(scope="name")` 指定目標層級。該名稱是一個子電路的名稱，代表該子電路的定義。在下例中，最後一筆記錄寫於主檔案中，並作用於子電路 `ota`：

  ```spice
  * A record written outside its subcircuit
  * @RNL(type="header") { @VERSION("0.4")}
  .model nch nmos level=1
  .subckt ota inp inn out tail vss
  M1 x inp tail vss nch
  M2 out inn tail vss nch
  .ends ota
  X1 vip vin vo vt 0 ota
  * @RNL(scope="ota") { #M1 @PLACE(10, 20)}
  .end
  ```

  - 每個子電路僅有一張原理圖（6.1），因此 scope 指定的是定義，而非實例。
  - scope 僅能向下作用：目標須為本層級在文字上包含的子電路，即定義於本檔案中，或定義於本層級直接或間接引入的檔案中的子電路。子電路內部不得寫 scope：子電路的 RNL 僅涵蓋其自身。寫在子電路內部記錄中的 `scope` 為錯誤，視同未寫（2.8）。當找不到目標或目標不位於本層級之下時，構成錯誤，該記錄的敘述由於沒有可供解析的層級而全部失效（第 7 章）。
  - 該記錄中的所有引用均在目標層級中解析。其敘述提交至目標層級，所綁定的名稱亦發布於該處並與目標層級自身的記錄共享（6.7）；若將目標層級已綁定給其他物件的名稱再次綁定，則為錯誤，而重複綁定至同一物件則屬允許（6.6）。scope 僅影響其自身所在的記錄，不改變宿主網表。
  - 順序：由 scope 帶入子電路的敘述排在其自身文字之後；當多處使用 scope 指向同一個子電路時，較外層者排在較後（8.3、8.5）。寫在外部的明確指定會覆寫內部所寫，如同外層用例的優先順序高於其定義本體（14.8）。
  - 求解器的輸出以及使用者在編輯器中所做的修改不得使用 scope；它們須寫入子電路自身的文字中（第 17 章）。scope 僅供作者選擇寫於外部的敘述使用。

### 2.7 套件檔案

套件可寫成獨立的套件檔案，供 USE-PACKAGE 查找（16.2）。套件檔案是純 RNL 檔案；建議副檔名為 `.rnl`，並以 UTF-8 編寫。它不是網表，也不透過 `.include` 載入。

- 套件檔案的**讀取**方式與網表載體（2.2、2.4）相同，唯獨每一行皆視為載體，且註解字元與其後的空格皆為空：
  - 行首的 `@` 視同前方已有空格（2.3），因此 `@RNL` 與關鍵字可從第 1 欄開始；
  - 空白行視同空註解行，記錄可跨越空白行繼續延伸；
  - 記錄之外的文字視為備註並予略過，如同宿主註解（2.5）；`/* */` 照常運作；
  - 第 1 行會被讀取：套件檔案不是網表，沒有標題行（2.2）。
- 套件檔案容納 `@RNL(…) {…}` 記錄，依 16.1 的順序剖析。第一筆記錄為不帶 `language` 的檔頭記錄，其中包含 VERSION 與 PACKAGE；套件檔案亦可為每種語言各寫一筆檔頭記錄（2.8）。套件可容納的內容（包含對其他套件的引用）見 16.2；別名套件同樣是套件檔案（16.5）。

以下為一份完整套件檔案的內容，不含註解前綴。第 3 行位於記錄之外，屬於備註。該套件未引用標準套件便直接使用了 `$NMOS`，因此它會在使用它的位置所生效的標準套件中尋找該符號，或在單獨檢查時於工具設定加入的標準套件中尋找（16.2、16.3）：

```rnl-file
@RNL(type="header") { @VERSION("0.4"); @PACKAGE(name="acme-style", version="1.2")}

ACME house style: NMOS symbol and its rule.
@RNL {
  $NMOS_ACME = @DEFINE-SYMBOL {
    $NMOS;
    ? @TEXT("${name}", key="name") => @PLACE(-2.5, 1.5)
  };
  # @SELECT-INSTANCE(type="nmos", recursive=true) => @SET-SYMBOL $NMOS_ACME
}
```

### 2.8 記錄標頭

`@RNL(…)` 括號中的欄位作用於該記錄的每一條敘述，且全部以名稱傳入。欄位名稱與 `type` 的值須依標準拼寫撰寫；它們區分大小寫且不得使用別名（3.6、16.5）。

```rnl
* @RNL(type="header") { @VERSION("0.4"); @USE-PACKAGE(name="rnl-std-all", version="0.4")}    /* the first record of the file: read as version 0.4 (16.1) */
* @RNL { %dp1 = #M1(left) #M2(right) #M5(tail) @AS $DIFFERENTIAL_PAIR_N}    /* no type: "authored" */
* @RNL(type="generated", priority="high", author="rnl-solver 0.3", hash="sig1:9f3a62c1") {
*   #M1 @PLACE(12, 20); #M2 @PLACE(28, 20)
* }
* @RNL(author="rnl-editor 0.1") { #M2 @PLACE(x=30, priority="high")}
```

| 欄位 | 含義 | 是否影響解譯 |
|---|---|---|
| `type` | 記錄的種類：`"authored"`（預設）、`"generated"`、`"header"` | 是 |
| `scope` | 目標子電路（2.6） | 是 |
| `priority` | 記錄中各敘述的預設優先順序；對 AS 與 ATTACH 僅接受 `"disabled"`（14.8） | 是 |
| `author` | 作者、工具及其版本、套件版本等；任意字串 | 否 |
| `hash` | 求解器輸入的雜湊值（第 17 章） | 否 |
| `numbering` | 該記錄所用編號的檢查碼（5.9）；僅可用於 `type="generated"` | 是 |
| `modified` | 最後變更時間，ISO 8601 字串 | 否 |
| `language` | 記錄所作用的網表語言區段：`"spice"` 或 `"spectre"`（見下文） | 是 |

- **type**：取值固定，各有定義明確的行為。
  - `"authored"`（預設值）：由手寫、編輯器或匯入工具寫出。
  - `"generated"`：求解器的結果。求解器進行求解時，解譯該層級會忽略所有 `type="generated"` 的記錄：它們不新增任何物件、名稱或事實，也不約束求解結果。求解器如何使用它們由其自行決定。求解完成後，無論原先作者為何、也不論求解器是否理解其中的敘述，它會將這些記錄整體替換：16.4 中「工具重寫自身記錄時保留無法理解的敘述」之規則不適用於此處的替換。須保留的內容應寫在其他類型的記錄中。拖曳器件時編輯器重新繪製的連線亦屬求解器結果（14.8、第 17 章）。`type` 本身不隱含優先順序：求解器會明確寫出 `priority="high"`。
  - `"header"`：檔案的設定（16.1）。檔頭記錄可以省略。若寫出，須位於檔案層級，不得寫在 `.subckt` 或 Verilog-A 模組之內（2.9），且不得帶有 `scope`；檔頭記錄須為檔案中最先出現的記錄，至多一筆不帶 `language` 且每種語言至多一筆（見下方 `language`）。其中容納 VERSION（16.1）、ALIAS 的別名與 USE-ALIASES 的別名套件（16.5）、DEVICE 的端子名稱與類型（6.12）、USE-PACKAGE 的根層級套件（16.3）以及 SOLVER-CONFIG 的求解器設定（14.10）；套件檔案亦於此寫入 PACKAGE（2.7、16.2）。檔頭記錄本身一律依標準拼寫讀取，不套用別名（16.5）。寫在其他記錄之後的檔頭記錄，或第二筆不帶 `language` 或重複同一語言的檔頭記錄，皆屬錯誤並整體忽略；已讀取的記錄不會重新處理。被讀取的 `.lib` 區段視同一份檔案（2.6）：其檔頭記錄即該區段的第一筆記錄。工具寫出檔頭記錄時，須使用寫入處所處語言模式的註解標記（2.2）。當檔案的第一條敘述位於 `simulator lang=` 行之後時，檔頭記錄可緊接在該行之後以檔案其餘部分的模式寫出，或寫在該行之前（例如第 2 行）以檔案起始的模式寫出；無論位於何處，它都是檔案的第一筆記錄。
- **language** 使記錄僅作用於該語言區段中的物件。
  - **區段**：配接器依 `simulator lang=` 將每個檔案劃分為不同語言模式的區段（2.2）。取值為 `"spice"`（涵蓋 SPICE 家族，包含 HSPICE 與其他 SPICE 方言）與 `"spectre"`；後續版本可能新增與這些不相容的語言。取值區分大小寫。
  - **名義作用域**：記錄所觸及的層級與不帶 `language` 時相同：寫在某層級的記錄會觸及該層級與其下各層級，而套件中的記錄會觸及使用該套件的層級（16.2）。在其所觸及的範圍內，帶有 `language` 的記錄僅作用於屬於該語言區段的物件；不帶 `language` 的記錄則作用於所有區段，因此在 Spectre 檔案中亦會作用於其中的 SPICE 區段。
  - **物件屬於哪個區段**：實例及其端子屬於該實例行所在的區段；子電路的連接埠（`#:port`）屬於開啟該子電路的定義行所在的區段；網路屬於所有寫及它的行所在的區段，因此同時寫在兩種區段中的網路會受到兩種語言記錄的作用；RNL 建立的物件（用例、點、圖形或文字）屬於它所附著或填入它的宿主物件所在的區段，例如附著於 `&vss` 的接地；層級本身以及不附著於任何宿主物件者，屬於該層級中有任何一行屬之的所有語言。
  - **跨區段敘述**：若一條敘述的物件有部分位於該記錄語言區段之外（例如約束、連線或 GROUP），則整條敘述不產生效果。引用該等區段之外的物件不產生效果且不算錯誤，依賴它的部分亦不產生效果；但若該層級包含該語言的區段，而該名稱完全找不到，則仍照常構成錯誤。若記錄所指定的語言在其觸及範圍內沒有任何區段，該記錄不作用於任何事物且不予檢查。
  - **定義不依區段劃分**：`$` 名稱、符號與樣式在名義作用域內照常可見（6.8）；僅作用於物件的敘述才會依區段篩選。
  - **檔頭記錄**：一份檔案可以有一筆不帶 `language` 的檔頭記錄，以及每種語言各一筆帶有該欄位的檔頭記錄。它們須寫在最前面、接連出現，且不帶 `language` 者須排在最前。VERSION、PACKAGE、ALIAS 與 USE-ALIASES 僅能寫在不帶 `language` 的檔頭記錄中；帶有 `language` 的檔頭記錄僅容納 USE-PACKAGE 與 DEVICE，且它們僅作用於該語言的區段（6.12、16.2）。所有檔頭記錄一起生效。在兩筆檔頭記錄中以不同版本或不同內嵌內容寫入同一個套件構成錯誤，因為單一層級可能同時包含兩種語言的區段，而同名套件僅能使用一次（16.2）：帶有 `language` 的檔頭記錄中的 USE-PACKAGE 失效，由不帶 `language` 的檔頭記錄中的該套件對所有區段生效；若是兩筆皆帶有 `language` 的檔頭記錄之間衝突，則較後者失效。
  - `type="generated"` 的記錄不得帶有 `language`：求解器會求解整個層級並整體替換其記錄。若寫於該處，`language` 構成錯誤並視同未寫。
  - 若填入本版本未列出的值，該記錄不作用於任何事物，並給出點名最接近值的警告；這是對下方「寫錯已知欄位視同未寫」規則的例外，否則會使該記錄作用於所有區段。寫出 `language` 的工具須在不帶 `language` 的檔頭記錄中寫出 `@VERSION("0.4")`（16.1）。工具新建的記錄不帶 `language`；既有帶有該欄位的記錄則原樣保留（16.4）。
- **中繼資料**：`author`、`hash` 與 `modified` 不影響解譯；刪除它們後繪製結果完全相同。工具使用它們來決定如何處理記錄（第 17 章）。`type` 與 `author` 皆不影響衝突解析的順序（8.3）。
- **錯誤處理**：
  - 未知欄位僅給出警告並予忽略，不影響該記錄或其他欄位。這為後續擴充預留空間。給出警告時須指明最接近的欄位名稱。附註：因此拼錯一個會影響解譯的欄位（例如 `priorty="low"`）只會得到警告，且該記錄會以優先順序 `"normal"` 生效；後續新增的這類欄位須依賴版本號（16.1）來通知舊工具其已過時。
  - 寫錯的已知欄位（例如值不合法、`numbering` 出現在 `type` 不是 `"generated"` 或帶有 `scope` 的記錄中，或同一欄位重複寫了兩次）構成錯誤，且該欄位視同未寫：`priority` 退回 `"normal"`，`type` 退回 `"authored"`，中繼資料則予捨棄。唯獨找不到目標的 `scope` 例外：該記錄的敘述沒有可供解析的層級，因此全部失效（2.6）。依位置傳入的欄位構成錯誤並予忽略。
- 記錄沒有識別碼。工具依 `type`、`author` 與敘述的 key 尋找自己的記錄（5.8）；來自另一筆記錄的物件則透過名稱引用，或在求解器記錄中透過編號引用（5.9）。其他備註請寫在註解中。
- 求解器結果並非有待採用的建議方案：它直接生效，而過時的結果僅給出提示（第 17 章）。

### 2.9 Verilog-A 檔案

子電路會為其實例指定方塊符號（block symbol）（9.2.6）。網表所引入的 Verilog-A 模組亦可在 Verilog-A 檔案本身以記錄做到相同的事：

```verilog
// @RNL(type="header") { @VERSION("0.4"); @USE-PACKAGE(name="rnl-std-all", version="0.4")}
`include "disciplines.vams"
module vco(vin, out, vdd, vss);
  inout vin, out, vdd, vss;
  electrical vin, out, vdd, vss;
  parameter real f0 = 1e9;
// @RNL {
//   %vco = @DEFINE-SYMBOL(box=[-3, -3, 3, 3]) {
//     @RECTANGLE {(-2, -2) (2, 2)};
//     (-3, 0) @PIN(terminal="vin", direction="left");
//     (3, 0) @PIN(terminal="out", direction="right");
//     (0, 3) @PIN(terminal="vdd", direction="up");
//     (0, -3) @PIN(terminal="vss", direction="down");
//     ? @TEXT("${name}", key="name") => @PLACE(0, 2.5);
//     ? @TEXT("f0=${f0}", key="value") => @PLACE(0, -2.5)
//   };
//   # @SET-SYMBOL %vco
// }
  analog begin
    V(out) <+ 0;
  end
endmodule
```

寫有 `ahdl_include "vco.va"` 與 `I1 (ctl out vdd 0) vco f0=2e9` 的 Spectre 網表不需任何自訂 RNL 即可以此符號繪製 I1。

- **適用檔案。** 由網表帶入的 Verilog-A 原始檔：在 Spectre 中以 `ahdl_include`（無論何種語言模式）帶入，在 HSPICE 中以 `.hdl` 帶入。這類檔案在其被帶入的位置讀取，如同引入檔案（6.1）。在 Spectre 中若使用 `ahdl_include … -master name`，該模組在網表中即以該名稱為人所知，其方塊符號亦套用至該名稱的實例。宿主以已編譯形式帶入的模型（如 ngspice 的 `.osdi` 檔案）沒有可供讀取的文字；其實例採用預設方塊符號，其所在行上的每個節點各有一個接腳（9.2.6），上層級可以規則為它們指定符號。
- **載體。** 整行註解 `//`，適用 2.2 的規則：`//` 位於第 1 欄，其後不接任何內容、僅接空白字元，或接一個空格與內容。行尾註解與 `/* */` 註解不予讀取，其中的 `@RNL` 會給出警告。第 1 行會被讀取：Verilog-A 檔案沒有標題行。Verilog-A 前處理器可能略過的文字（介於 `` `ifdef `` 或 `` `ifndef `` 與其 `` `endif `` 之間）不予讀取，其中的 `@RNL` 會給出警告，如同 2.2 中配接器無法分類的區域。
- **層級。** 位於所有 `module … endmodule`（與 `macromodule … endmodule`）之外的文字構成該 Verilog-A 檔案的檔案層級。每個模組自成一個層級，即模組層級（module level），位於該檔案層級之下，而該檔案層級又位於帶入此檔案的層級之下（6.1）。
  - 檔案層級僅容納檔頭記錄（2.8），須寫在第一個模組之前。寫在該處的任何其他記錄皆為錯誤並失效。
  - 模組層級沒有電路也沒有原理圖：其中不繪製也不求解任何內容，且沒有求解器的記錄。
- **模組層級可容納的內容。** DEFINE-SYMBOL 與 DEFINE-STYLE，以及一條將符號指定給 `#`（即模組本身）的 `# @SET-SYMBOL` 敘述。此 SET-SYMBOL 給出該模組的方塊符號，適用 9.2.6 對子電路方塊符號的所有規定：它作用於任何實例化該模組之處，且在符號佇列中的位置相同（8.3）。寫在模組層級中的其他任何內容皆為錯誤並失效：宿主引用、約束、PLACE、ORIENT、WIRE、寫在符號定義本體之外的 TEXT、`# @SET-SYMBOL` 以外的規則、AS 與 ATTACH、斷言、`scope`、DEVICE 與 SOLVER-CONFIG。USE-PACKAGE 僅能寫在檔案的檔頭記錄中。
- **端子。** 模組實例的端子是宿主在其行上讀取的節點，依模組連接埠列表中連接埠的順序排列，並以連接埠名稱命名。Verilog-A 區分名稱大小寫，因此連接埠名稱亦同。
  - 向量連接埠（vector port）依其宣告範圍從左邊界到右邊界的每個位元對應一個端子，因為向量是依位置連接的：連接埠 `inout [3:0] d` 會取用該行的接下來四個節點，依序為 `d[3]`、`d[2]`、`d[1]` 與 `d[0]`，而 `inout [0:2] e` 會取用三個，依序為 `e[0]`、`e[1]` 與 `e[2]`。這些即為它們的端子名稱，在引用中以帶有下標的形式寫出（6.11），例如 `#I1:d[3:0]`，在 PIN 的 `terminal=` 中則寫作字串，例如匯流排接腳 `terminal=["d[3]", "d[2]", "d[1]", "d[0]"]`（9.2.4）。
  - 模組本身不賦予其實例類型（6.12）；網表中的 DEVICE 可為它們指定類型，如同其他實例。
- **版本與套件。** Verilog-A 檔案的檔頭記錄遵循引入檔案的規則：若未寫檔頭記錄或未寫 VERSION，該檔案沿用帶入它的檔案的版本（16.1），而其 USE-PACKAGE 僅作用於該檔案及其模組（16.2）。
- **寫出。** 工具在 Verilog-A 檔案中僅寫出 `//`，且僅寫出檔頭記錄與方塊符號的記錄；不得於該處寫出求解器的輸出（第 17 章）。
