## 1 概述

### 1.1 範圍

RNL（Rich Netlist）寫在宿主網表的註解中。它描述網表所定義的電路如何被理解並呈現為原理圖：使用哪些符號、各部分擺放在何處、如何調整朝向、對齊、連線、標註標籤與設定樣式，以及各組部分代表什麼含義（原則 1）。

器件、類型、參數、連接關係與子電路介面僅由宿主網表定義。RNL 僅引用它們，不能加以修改。RNL 不檢查繪圖所暗示的電氣含義（原則 2.2）。

本標準定義：

- 如何從宿主網表的註解及其引入的 Verilog-A 檔案中擷取 RNL（第 2 章）；
- RNL 文字的詞法結構與語法（第 3、4 章）；
- 文字描述哪些物件、名稱如何解析、失效如何處理，以及各描述如何共同生效（第 5–8 章）；
- 各種描述的詞彙（第 9–17 章）；
- 標準詞彙表，隨本文以 `rnl-words-0.4.json` 發布（5.3、附錄 A）。

本標準不定義佈局演算法或唯一的渲染結果（原則 1），也不定義宿主網表的剖析方式（原則 2.1）。標準套件 `rnl-std-all` 與諸如 `alias-zh` 等別名套件均以 RNL 寫成；本標準定義套件的運作方式（16.2、16.3、16.5），其具體內容另行發布。

本文定義該語言的 0.4 版。0.x 各版本之間不保證彼此相容（16.1）。

### 1.2 本標準的結構

本標準由抽象模型與文字語法構成。抽象模型包含物件、事實、消耗輸入的方式與生效階段（第 5–8 章）；文字語法則是其書面形式（第 2–4 章）。工具之間透過文字交換資訊。

附錄 A 列出關鍵字的簽名，由詞彙表產生，具規範效力。附錄 B 提供標準例句，附錄 C 列出為後續版本保留的內容，附錄 D 列出與 0.3 版的差異；此三者均為參考資訊。附註與範例亦為參考資訊。其餘內容均具規範效力。

### 1.3 語言一覽

```spice
* Five-transistor OTA, input stage
* @RNL(type="header") { @VERSION("0.4"); @USE-PACKAGE(name="rnl-std-all", version="0.4")}
.model nch nmos level=1
.subckt ota5t inp inn out vdd vss vbias
M1 x    inp   tail vss nch W=2u L=0.5u
M2 out  inn   tail vss nch W=2u L=0.5u
M5 tail vbias vss  vss nch W=4u L=1u
* @RNL {
*   %dp1 = #M1(left), #M2(right) and #M5(tail) treated @AS $DIFFERENTIAL_PAIR_N;
*   {#M1 #M2} @ALIGN("y"), i.e., same y;
*   #M5 is at @PLACE(20, 6) => it @ORIENT("R0");
*   %g0 = $GROUND is @ATTACH to &vss;
*   net &vss, through {#M5:3 %g0::pin}, has a @WIRE
* }
.ends ota5t
.end
```

- `* ` 開始一條 SPICE 註解。`@RNL {…}` 是一筆記錄；大括號內是以 `;` 分隔的成員（第 2 章）。檔案開頭的檔頭記錄宣告語言版本（16.1）。
- `#M1`、`&vss` 與 `#M5:3` 分別引用宿主中的實例、網路與端子。`%dp1` 與 `%g0` 是本層級的 RNL 名稱。`$DIFFERENTIAL_PAIR_N` 與 `$GROUND` 是來自標準套件的一般定義（9.4），由檔頭記錄引入（16.3）。`%g0` 是套用 `$GROUND` 所建立的用例；標準套件為其指定了接地符號，因此它會繪製為接地（第 12 章）。
- `@AS`、`@ALIGN`、`@PLACE`、`@ORIENT`、`@ATTACH` 與 `@WIRE` 為關鍵字。參數寫在緊接關鍵字的括號內，且僅能容納字面量。AS 用寫在它前面的物件填入寫在它後面的定義角色；ATTACH 將寫在它前面的定義套用至寫在它後面的物件（9.4、第 12 章）。
- `(left)` 標記角色。`%dp1 =` 為敘述的結果命名。`=>` 將前一段的結果傳遞給下一段；若後方僅接一個名稱，則為前一段的結果命名（5.5）。
- `and`、`treated`、`, i.e., same y`、`is at`、`it`、`is … to`、`net`、`, through`、`, has a` 皆為自由文字，不改變含義（3.3）。標準例句會在記號之間加上這類詞語，使敘述讀起來像句子（4.5、附錄 B）。若去掉它們，該筆記錄讀作：

```rnl
%dp1 = #M1(left) #M2(right) #M5(tail) @AS $DIFFERENTIAL_PAIR_N;
{#M1 #M2} @ALIGN("y");
#M5 @PLACE(20, 6) => @ORIENT("R0");
%g0 = $GROUND @ATTACH &vss;
&vss {#M5:3 %g0::pin} @WIRE
```

### 1.4 術語與慣例

#### 1.4.1 要求用詞

- **須**（must）、**不得**（must not）：對文件或實作的強制要求。
- **應**（should）、**不應**（should not）：建議做法；可能有充分理由採取其他做法，但應先瞭解原因。
- **可以**（may）：允許的做法。

語言本身的語義以現在式陳述，例如：「該敘述失效」、「後寫者生效」。

#### 1.4.2 失效與診斷

- **失效**的項目（欄位、敘述、記錄或檔案；7.6）不產生效果；失效的敘述以一個失效物件作為其值（7.2）。無論原因為何，每次失效皆為一項**錯誤**（7.6）。
- **警告**標示一個合法但可能並非作者本意的項目；除非本標準另有規定（例如求解器在時間上限內無法判定的事實，8.5），否則照常生效。**違規**報告檔案對電路所做的陳述（如斷言）並不成立；不會有任何項目失效（15.3、15.4）。**提示**標示常見的覆寫、遮蔽或取捨結果，但也可能是誤寫。各種情況列於 7.6；凡本標準指出某事會給出警告或提示處，實作皆應予以回報。
- 當**解譯失效**時，不繪製任何內容，並回報一項錯誤（1.5 第 3 項、7.6）。

#### 1.4.3 標記法

- 在正文中，關鍵字以大寫且不帶 `@` 寫出：PLACE、SET-SYMBOL。在語法與範例中則帶有 `@`。
- 標準詞彙、名稱與字面量使用等寬字體：`priority`、`"high"`、`instance`、`$GROUND`。
- 括號內的章節編號指本標準：（9.4）。「原則 2.4」指 RNL 設計原則 `rich-netlist.md` 的第 2.4 節。
- 範例依標準寫法（4.3）撰寫，且不含自由文字，除非該範例正是在討論自由文字。標記為 error 的範例展示錯誤寫法。
- 範例預設使用標準套件：未寫出檔頭記錄的範例，視同其主檔案在檔頭記錄中寫了 `@USE-PACKAGE(name="rnl-std-all", version="0.4")`（16.3）。

| 用例 | usage | 單次套用所建立的物件。它記錄所用的定義以及填入各角色的物件；當它擁有符號時會被繪製出來（9.4、9.5）。在約束中，沒有符號的用例代表其成員（14.1） |
| 虛擬組件 | virtual part | 擁有符號的用例：會繪製出來，但不屬於網表，例如接地、電源、連接埠標記或交接圓點（第 12 章） |
| 詞彙表 | word list | 某一語言版本所有標準詞彙與關鍵字簽名的機器可讀列表，本版本為 `rnl-words-0.4.json`（5.3、附錄 A） |

### 1.5 核心原則

本標準的規則遵循以下原則。第 1–6 項細化了原則 2.9；第 7 項說明詞彙的劃分方式。

1. **一切皆為描述。** RNL 文字是一組描述。解譯器會先收集所有描述再給出結果。沒有任何東西會被「執行」，且名稱可以在綁定它的敘述之前使用。
2. **書寫位置僅作為排序資料。** 描述寫在何處（所在層級與文字中的先後位置）僅在三種情況下有影響：當描述彼此矛盾時，保留較後寫的（幾何事實先比較優先順序；8.3、8.4、8.5）；繪圖順序（11.6）；以及集合成員的順序（5.2）。其餘情況下，結果與書寫順序無關。管線的每一段各有其位置：較後段的寫作位置晚於較前段（5.5）。
3. **矛盾處理。**
   - 無法理解的描述（語法錯誤、找不到名稱、種類錯誤等）或自相矛盾的描述會失效（原則 2.4、2.9；第 7 章）。
   - 可以理解但彼此矛盾的描述，凡本標準給出明確處理方式者皆依該方式解決，例如依 key 覆寫（8.4）、外觀佇列（8.3）與幾何事實取捨（8.5）；可能給出提示。
   - 若尚未定義明確處理方式，則整份解譯失效（7.6）。本版本沒有這類情況（7.5）。後續版本可能會定義處理方式並改為容錯；目前可正常運作的檔案不受影響。
4. **每項描述看到的都是其生效前的狀態。** 一項描述讀取的是其所處階段開始時的狀態；它自身的效果以及同一階段中其他描述的效果皆未計入其中（8.2）。
5. **物件與名稱。** 每個帶有關鍵字的敘述與每個 `{…}` 都會建立一個新物件，由一個控制代碼與事實組成。引用本身不建立物件，唯獨依位置取成員會建立一個新集合（5.2.3）。名稱僅用於指向物件，在一個層級內只綁定一次。覆寫作用於事實，而非名稱（5.1、6.6）。
6. **不為可讀性設限。** 凡難讀但具明確含義的寫法皆屬允許；是否克制留給撰寫者自行決定。僅沒有明確含義的寫法才算錯誤。
7. **關鍵字與定義。** 凡實作本身必須理解、且無法以其他描述寫出的內容，皆為關鍵字。凡可在一般定義的定義本體內以既有描述寫出的內容，皆為定義，且其名稱僅作參考提示（9.5）。

### 1.6 相容性規範

**文件。** 當宿主網表的記錄依第 2–4 章讀取並依第 5–17 章解譯後不產生任何錯誤（7.6）——包含所使用套件內容中的錯誤——即符合 RNL 0.4 標準。警告、提示與違規不影響相容性：違規只表示電路並不符合檔案所陳述的條件，而非檔案寫錯。單獨檢查套件檔案時，亦依相同方式判定相容性（16.2）。檔頭記錄宣告其他語言版本的檔案不受本版本規範（16.1）。

**實作**指解譯器（僅用於檢查的解譯器亦稱 lint）、檢視器、求解器、編輯器以及其他讀寫 RNL 的工具。符合規範的實作：

1. 依第 2 章定義從宿主註解擷取 RNL，並依第 3、4 章讀取；
2. 依詞彙表（5.3）中的簽名，賦予每項描述第 5–17 章所定義的效果；
3. 回報每一項錯誤及其位置與原因（7.6）；不得將錯誤降級或關閉；
4. 應回報本標準列出的警告與提示，且須回報違規（7.6）；
5. 僅得以警告或提示的形式新增自訂檢查：不得使本標準允許生效的項目失效，也不得讓本標準使其失效的項目生效；
6. 可以提供中止或拒絕整份輸入的較嚴格模式，但不得作為預設模式；
7. 須讓使用者能看到診斷訊息；呈現方式由實作自行決定（7.6）；
8. 須宣告所支援的語言版本，並依 16.1 處理宣告不受支援版本的檔案；
9. 須將未知關鍵字、參數與值視為錯誤（16.4）；
10. 當檔案寫入標準套件時，須依 16.3 將其置於根層級；
11. 寫出 RNL 時，須依標準寫法輸出新敘述且不得重排使用者所寫的敘述（4.3）；儲存檔案時須寫入檔頭記錄與版本（16.1）；須原樣保留未知與失效的敘述、宿主文字、一般註解及不受支援版本的檔案（16.4）；且僅修改第 17 章允許修改的記錄；
12. 求解時，須依 8.5 解決衝突、寫回所做的每一項決定，且僅得以求解器記錄所能容納的形式將結果傳遞給其他工具（14.8）；
13. 可以對使用的資源設定上限，例如符號的巢狀深度（9.2.7）、用例展開深度（9.4）、引入檔案與子電路的深度，或物件數量。超出此類上限的輸入須給出錯誤，說明已達實作上限並標示位置；實作不得靜默截斷輸入，亦不得繪製或求解出與本標準定義不同的結果。實作須至少支援 64 層符號巢狀。求解過程中檢查事實的限制不屬於此類上限：它是求解器的選項，無法於該限制內判定的事實會附上警告並予捨棄（8.5）。

本標準不規定求解器如何在滿足約束的多組位置之間選擇，亦不規定檢視器如何繪製 RNL 未限定的細節；凡留待實作決定的部分皆已於文中說明（例如 13.1）。

**相容性測試**檢查錯誤（含位置與失效範圍）以及最終場景。警告可作為選用預期項目進行檢查；提示不列入檢查（7.6）。
