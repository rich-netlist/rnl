## 6 名稱與作用域

### 6.1 層級階層

- **層級依隨文字結構。** 某層級的 RNL 作用於該層級以及文字上被它包含的層級；哪個子電路實例化哪個子電路並不影響層級關係。
  - 檔案包含它所定義的子電路以及它所引入的檔案。
  - 寫在子電路內部的 `.include`，以及巢狀定義於子電路內部的 `.subckt`（SPICE3 與 ngspice 中的區域定義），位於該子電路之下。
- 由上而下，通往某個子電路的層級鏈依序為：根層級套件（檔頭記錄中 USE-PACKAGE 引入的套件，其中標準套件排在最前，16.3）→ 主檔案的檔案層級 → …（層層引入的檔案）→ 定義該子電路的檔案 → 該子電路本身。例如：

  ```text
  packages at the root (such as the standard package)
  └─ file level of tb.sp (the top level)
     ├─ load                    a subcircuit defined in tb.sp
     ├─ file level of ota.sp    a file included by tb.sp
     │  ├─ ota                  ota instantiates cell
     │  └─ cell
     └─ file level of bias.sp
        └─ bias                 also instantiates cell, but neither the RNL of bias.sp nor that of bias reaches cell
  ```

- **子電路的 RNL 僅涵蓋該子電路。** 在衝突取捨中，其敘述排在檔案層級的內容之後，因此優先於檔案層級（8.5）；但它們不會傳遞給它所實例化的子電路，唯獨定義於其內部的子電路除外。當 amp 實例化 cell 時，amp 的定義與規則不會觸及 cell。
- **被引入的檔案不會影響引入它的層級。** 其檔案層級中的定義、規則與 USE-PACKAGE 僅作用於它自身包含的子電路以及它進一步引入的檔案。在網表中，它寫在子電路之外的器件屬於引入它的層級，但其 RNL 無法修改它們。因此檔案絕不會被它所引入的檔案改變。
- **被引入檔案的檔案層級本身沒有電路。** 唯有主檔案的檔案層級才是電路。寫在被引入檔案之檔案層級中的宿主引用（`#M1`、`&vss`）會失效（6.3）；該處僅有定義、規則、USE-PACKAGE 與 `scope` 能生效。單獨開啟的檔案即為主檔案。
- **被引入的檔案會繼承引入它的層級。** 主檔案的風格體系（其規則及其 USE-PACKAGE 帶入的套件）會向下傳遞至程式庫檔案的子電路中。因此同一個程式庫檔案在不同的主檔案下、或單獨開啟時，可能會繪製出不同的樣貌，而其求解器結果仍僅儲存一份（第 17 章）。若要讓程式庫使用的符號不受上層級外觀規則的影響，須在該程式庫檔案或子電路中再次以 USE-PACKAGE 引入標準套件（16.2）。若僅要鎖定標準套件版本而仍允許上層風格體系覆寫它，則將 USE-PACKAGE 寫在該程式庫檔案的檔頭記錄中（16.3）。主檔案的規則除非其篩選寫明 `recursive=true`（10.1），否則僅作用於頂層；應觸及程式庫檔案的風格體系規則皆須寫上該參數。
- **Verilog-A 檔案。** 網表以 `ahdl_include` 或 `.hdl` 帶入的 Verilog-A 檔案位於帶入它之處，如同引入檔案；其每個模組各自成為其檔案層級之下的一個層級，該模組層級沒有電路也沒有原理圖，僅為該模組指定方塊符號（2.9）。
- **每個子電路各有一張原理圖。** 檢視器不會展開子電路：子電路的實例一律以其符號繪製，而子電路內部則分開繪製與求解。每個子電路僅有一條通往上層的層級鏈，因此在一份文件中，每個子電路恰好有一張原理圖。
- **套件。** 套件中的 `$` 定義在寫有 `@USE-PACKAGE` 的層級及其下方各層級生效；其規則視同寫於該層級，並透過 `recursive=true` 觸及下方層級（16.2、10.4）。寫在檔頭記錄中的 USE-PACKAGE 套件置於根層級，當檔案寫入標準套件或由工具設定加入時，標準套件位列其中（16.3）。引入檔案將該檔案置於本層級之下，由該檔案繼承本層級；USE-PACKAGE 則將套件置於本層級之上，由本層級繼承該套件。
- **規則預設僅作用於自身層級。** 寫在某層級中的規則僅在該層級評估。當它透過其中所寫篩選的 `recursive=true`——或若無篩選，則透過它所使用的集合（10.1）——觸及下方層級時，會在下方每個層級也各評估一次，每次僅檢視該層級（10.4）。這正符合原則 2.5 對規則的要求：規則可將效果限於當前層級，或讓下方層級繼承它，且預設僅作用於自身層級；而 `$` 定義則預設向下繼承（6.8）。

### 6.2 前綴

| 前綴 | 指向 | 解析範圍 |
|---|---|---|
| `#` | 宿主的實例；單獨的 `#` 代表本層級 | 本層級的宿主 |
| `&` | 宿主的網路；單獨的 `&` 代表空節點，即不連接任何網路（6.3） | 本層級的宿主 |
| `%` | 本層級給出的名稱：場景物件、既有物件（如 `%tail = #M5`），或僅在本層級使用的定義 | 本層級 |
| `$` | 定義或集合（6.6） | 綁定它的層級及其下方各層級 |
| `?` | 定義的角色或參數；單獨的 `?` 在符號定義本體中指使用該符號繪製的物件（13.3），在一般定義的定義本體中指正在展開的用例（9.4） | 一般定義或符號的定義本體 |

`$X` 與 `%X` 是兩個不同的名稱。

### 6.3 宿主引用

- `#M1` 與 `&vss` 僅在本層級的宿主中解析，絕不在其他層級中解析（原則 2.5）。不同子電路中的同名實例互不關聯。
- 找不到的宿主引用會失效（原則 2.4）。被引入檔案的檔案層級本身沒有電路，因此寫在該處的所有宿主引用皆會失效（6.1）。
- 名稱後方可直接緊接下標，代表一個或多個宿主名稱，例如 `&D<3>` 與 `#XI0<3:0>`（6.11）。
- 宿主配接器依宿主語義決定一個層級擁有哪些網路：
  - 區域網路：該層級的網表行所使用的節點，包含連接埠。
  - 全域網路：`0` 在所有 SPICE 方言中皆為全域接地。模擬器自身識別的接地別名（如 ngspice 中的 `gnd`，以及 HSPICE 中的 `GND`、`GND!`、`!GND` 與 `GROUND`）會由該方言的配接器合併為 `0`；合併之後，`&gnd` 與 `&0` 為同一個控制代碼。以 `.GLOBAL vdd`（Spectre 中為 `global vdd`）宣告的名稱在每個子電路中皆為同一節點。以 `!` 結尾的名稱（如 `vdd!`）是 Virtuoso 原理圖的慣例；真正作準的是宣告。
  - 全域網路在每個使用它的層級中各有一個控制代碼，即它在該層級中的複本。網表行未使用它的層級沒有該複本。因此 `&0` 指向寫出該引用之層級中的複本：每張原理圖繪製各自的那一份，事實屬於該層級，較低層級中的描述無法改動較上層級。
  - 若要指涉每個層級中的該全域網路，可在上層級中使用條件 `global=true` 依名稱篩選（10.1）。
- **空節點。** 單獨寫出且後方不帶名稱的 `&` 表示沒有網路：傳入它的對象未連接至電路的任何電氣節點。它寫在接收網路但實際上並無網路之處，例如繪製無網表行方塊圖時虛擬組件的接腳：`$INTEGRATOR @ATTACH &(in) &y(out)`、`& @WIRE {%sub1::y %int1::a}`。
  - 它不是物件：沒有控制代碼、無法綁定至名稱、不能成為集合的成員，且永遠不會被篩選選中。兩處寫出的 `&` 之間毫無關聯；檢視器醒目顯示空節點上的接腳或連線時，僅會醒目顯示該單一項目。
  - 有兩處會原樣接收它：種類為 `"net"` 的角色（9.4）與 WIRE 的網路槽位（13.1）。綁定至由它填入之角色的接腳不位於任何網路上，其 `::net` 為空節點（12.1）；它的 `${net}` 與 `${p}` 為空文字（13.6）。
  - 在其他任何接收網路的位置，它視同空網路集合：ROUTE-NET 不連接任何東西、ASSERT-NET 自動成立、以它為作用域的篩選選不出任何東西，且 ADD-TO 不新增任何東西（5.2.1）。在這些地方直接寫出它會給出警告，如同直接寫出空集合；但若透過角色傳入（如在定義本體中），則不給警告。因此使用角色網路的定義本體無須為它另寫特例。
  - 它不是宿主的網路，因此 `&` 後接宿主不存在的名稱仍照舊失效。

### 6.4 端子

- `object:terminal` 為端子，例如 `#M1:1`、`#M1:d`、`#XU1:inp`，以及疊畫的端子如 `%x:in`（11.8）。`#:inp` 是本層級的連接埠 inp。僅宿主實例、疊畫與層級的連接埠擁有端子；用例沒有端子（12.1）。
- 數字表示宿主的端子編號，從 1 開始計數。凡指定端子之處，僅由數字構成的端子（即使加了引號，4.1）一律視作編號：包含 `:` 引用中、PIN 的 `terminal=` 中、SET-SYMBOL 的 `terminals=` 中，以及篩選的 `terminal` 條件中。因此由純數字組成的連接埠名稱（如 `.subckt amp 3 1 2`）須依其位置存取，`#X1:1` 即指名為 3 的連接埠；僅由數字構成的 DEVICE 名稱則為錯誤（6.12）。
- 名稱表示宿主的端子名稱：由檔頭記錄中的 `@DEVICE` 給出的名稱（6.12），或子電路的連接埠名稱。無法不加引號寫出的名稱（3.6）須加引號，如 `#XU1:"in+"`。端子或連接埠名稱後方可直接緊接下標，如 `#X1:D<7:0>` 與 `#:D<7:0>`（6.11）。
- 大小寫：子電路的連接埠名稱與 DEVICE 給出的端子名稱遵循宿主規則：SPICE 忽略大小寫，故 `#M1:D` 亦可行；Spectre 則區分大小寫。
- 接腳的 `label=` 僅供顯示，不能用來引用端子：端子屬於網表，對端子的引用不取決於所使用的符號。
- **端子與接腳**：端子屬於網表；接腳屬於繪製物件的符號（9.2.4）。端子繪製在綁定它的接腳處，在需要接腳或點的位置，端子代表其接腳（5.2.4）。接腳透過其端子書寫，如 `#M1:d`；或當它在符號中有名字時，作為子物件以該名稱書寫，如 `#X1::vdd_t`（6.5）；數字絕不能作為接腳名稱。
- 找不到的端子會失效。某個端子在符號中是否有接腳，會在符號決定之後檢查（7.1）。
- 除子電路的連接埠名稱外，端子名稱由 DEVICE 給出；6.12 列出 SPICE 家族的標準名稱。
- 網表中未定義的子電路（例如 `XM1 … sky130_fd_pr__nfet_01v8` 中的 PDK 器件）僅在使用者於檔頭記錄中使用 DEVICE 給出端子名稱（6.12），或使用內含 DEVICE 敘述的套件（16.2）時，才擁有端子名稱；否則僅能使用編號。

### 6.5 子物件

- `object::name` 為子物件。它一律是物件，絕非數值。其控制代碼為父物件與該名稱，因此在賦予符號之前凡計數成員之處，兩個名稱皆計為兩個成員（5.2.4）：`{#R1::p #R1::q} @UNION` 有兩個成員，即使兩者最終指向同一個接腳亦然。
- 子物件包括：
  - 文字的 key：附著於物件上且帶有 `key=` 的 TEXT 在該物件上建立的子物件，如 `#M1::wl`。符號中帶有 key 的文字是每個以該符號繪製之物件的子物件（13.3）。`::name` 與 `::value` 並非標準子物件，僅是常見的 key（13.3）。
  - `::position`：物件的原點。`#M1::position @PLACE(…)` 等同 `#M1 @PLACE(…)`。對用例而言是其自身的點（14.1），即當它有符號時符號的原點（12.1）。對集合而言則是各成員 `::position` 所成的集合，巢狀集合向內展開：`{%dp1 %dp2}::position` 即 `{%dp1::position %dp2::position}`，為兩個自身的點，而約束中的 `{%dp1 %dp2}` 則代表那六顆電晶體（14.1）。對 TEXT 而言是文字自身的位置（13.3）；對以中心形式寫出的 RECTANGLE、CIRCLE 或 ELLIPSE 而言則是其中心（13.4）。
  - 端子的 `::net`：該端子所在的網路，如 `#M5:1::net` 即 `&tail`。疊畫端子的規定見 11.8：當各成員位於不同網路時，它為這些網路的集合。接腳的 `::net`：它所綁定端子的網路，或填入它所綁定角色的對象所屬的網路；對匯流排接腳而言為這些網路的集合；不綁定任何事物的接腳沒有對應網路。
  - 物件符號的具名接腳：`#X1::vdd_t` 是 X1 符號中名為 vdd_t 的接腳，`%g0::pin` 是用例 `%g0` 符號中名為 pin 的接腳（9.2.4）。
  - 用例的角色名稱：填入該角色的對象，如 `%dp1::left` 即 M1，而 `%g0::p` 即網路 vss。對集合角色而言即該集合。它指涉該物件本身而非第二個複本：`{%dp1::left #M1} @UNION` 僅有一個成員，而寫在 `%dp1::left` 上的 PLACE 具有 M1 的 key。
  - 用例定義本體中的具名區域物件，如 `%c1::mid`（9.4）。
- 標準子物件名稱為保留名稱：一般定義的角色名稱、參數名稱或區域名稱，以及文字的 key，均不得與標準子物件名稱相同（依書寫形式比較，3.6）。區域名稱不得與角色名稱相同，附著於用例上之文字的 key 也不得與該用例的角色名稱或區域名稱相同。區域名稱可以與參數名稱相同：參數是數值，而 `::` 不取數值。定義的參數亦不得名為 `priority`（14.8）。
- **`::` 後方的名稱依此順序查找**：該用例自身的角色名稱與區域名稱；它們的 `definition=` 別名；標準子物件名稱及其別名；物件符號的接腳名稱；文字的 key（別名見 16.5）。若接腳名稱與該用例的角色名稱、區域名稱或標準子物件名稱相同，則在將符號賦予該物件時構成錯誤；若文字的 key 與接腳名稱相同亦然。
  - key 排在最後，因此 key 的拼寫不得與排在它前面的名稱相同：標準子物件名稱或本檔案宣告的別名之一（如 `alias-zh` 的 `"位置"`）、該用例的角色名稱或區域名稱，或這些名稱的 `definition=` 別名。這類 key 構成錯誤，如同上述名稱衝突（13.3）。
- `::` 僅取用物件自身的部分；在場景中依條件尋找物件一律須使用篩選關鍵字。因此「某個定義的所有用例」應寫為篩選（10.1），而非寫成該定義的子物件。
- 端子使用 `:`，子物件使用 `::`，以確保後續版本新增的子物件名稱不會與網表的連接埠名稱衝突。
- **子物件名稱**：標準子物件名稱共有兩個，即 `position` 與 `net`，兩者皆為保留名稱。其他所有子物件名稱皆為動態產生：文字的 key、用例的角色名稱、定義本體中的區域名稱，以及接腳名稱。後續版本新增的標準子物件名稱依版本適用（16.1）：在舊版本的檔案中，同名的 key 依然有效。

### 6.6 命名

- `%name = statement` 與 `$name = statement` 為敘述的結果命名；在管線中，`=> %name` 與 `=> $name` 為其左側那一段的結果命名（5.5）。名稱僅是引用物件的另一種方式，不建立物件。
- `$name` 綁定定義或集合（包含篩選的結果）。在某層級評估的 `$` 集合僅包含該層級的成員（10.3）。其他場景物件屬於單一層級，無法使用 `$` 名稱。
- `%name` 可綁定本層級的任何物件：敘述建立的物件、既有物件（`%tail = #M5`）、集合（`%pair_set = {#M1 #M2}`），或僅在本層級使用的定義。
- **一個名稱在一個層級內僅綁定一次。** 將其再次綁定至同一個物件是允許的，例如寫兩次 `%x = #M1`；綁定至另一個物件則為錯誤，該名稱保留第一個有效綁定。綁定的對象依循 5.5。沿用輸入控制代碼的段（如 PLACE 或 ORIENT）會綁定該控制代碼，即使該段本身失效亦然；此類綁定是否有效完全取決於該控制代碼本身：當輸入本身已是失效物件時（例如在失效的 BUNDLE 之後），該綁定同樣無效（5.5）。建立新物件的段綁定該新物件，且當該段在讀取與建立層級階段（8.2 的步驟 1 至 3）未失效時，該綁定即為有效；若它之後在賦予符號後的檢查中失效（8.2），該名稱仍歸屬於它，較後的綁定無法接管，且該名稱自此指向該失效物件。僅當其所有綁定皆無效時，名稱才會綁定至失效物件（7.2）。無效的綁定不會佔用名稱，因此較後綁定至另一物件不構成重複綁定錯誤：在 5.5 失效的疊畫之後，`%s = #XI1` 會將 `%s` 綁定至 XI1。此規則同樣適用於建立物件的敘述、定義、集合與篩選結果。
- 覆寫作用於事實，而非名稱：若要修改 RNL 建立的物件，須寫一條修改它的敘述，例如 `%g0 @PLACE(40, 38)`（5.8）。

### 6.7 名稱的作用域

- `@RNL` 提交的名稱會發布至該層級：該層級的所有記錄共享它們，且名稱可以在綁定它的敘述之前使用（原則 2.9）。
- 巢狀集合中綁定的名稱僅在該集合內有效。
- 定義本體中綁定的名稱為該定義本體的區域名稱（6.9）。

### 6.8 繼承與遮蔽

- `$` 定義沿層級階層向下繼承（6.1），絕不向上繼承：向下傳入檔案中的子電路以及被引入的檔案。層級看不到它所引入檔案中的 `$` 定義；若要將定義提供給上層級使用，須將其製成套件並以 USE-PACKAGE 引入（16.2）。子電路的方塊符號是唯一會向上傳遞的例外（9.2.6）。
- 在較低層級中定義的 `$X` 若與繼承而來的定義同名，會在該層級及其下方各層級中遮蔽繼承而來的定義，並給出提示；上層級仍保有其自身的定義。
- 某層級中以 USE-PACKAGE 引入的套件，其 `$` 定義視同位於該層級上一層的層級（16.2）。當它們遮蔽更上層級或根層級套件中的定義時，會給出提示，如同任何遮蔽情況。當檔頭記錄中使用的套件定義了標準套件中的名稱，或定義了排在它之前的根層級套件中的名稱時，亦會給出提示（16.3）。
- `%` 名稱僅在自身層級內有效，不向下繼承：既不傳入檔案內的子電路，也不跨越引入邊界。套件中的 `%` 定義是該套件的私有輔助定義。

### 6.9 定義本體中的名稱

- 定義本體中的名稱是在編寫該定義之處解析，而非在套用該定義之處重新解析；唯一例外是一般定義本體中單獨的 `#`（見下文）。
- 因此，遮蔽一個定義僅會改變該名稱本身所指涉的對象：已寫在其他定義內部的定義保持不變。例如，在較低層級中遮蔽 `$DIFFERENTIAL_PAIR_N` 不會改變上層級所寫定義之定義本體中使用的差動對。
- 定義本體中的 `%name` 會先在該定義本體的區域名稱中查找，若無則在該層級的定義中查找。不得在定義本體中引用層級的場景物件（點、連線等）；這類引用為錯誤。層級中以 `%` 命名的集合或篩選結果亦屬這類物件，不論其評估時成員為何：若要與定義本體共享這類集合，須以 `$` 命名，定義本體即可引用它，且它會在每個用例所在的層級分別評估（6.6、10.3）。
- **定義本體中的標記法**：角色與參數寫作 `?name`。區域名稱以 `%name =`（或在管線中以 `=> %name`）綁定，並以 `%name` 引用。從外部則透過該用例存取區域名稱（9.4）。
- 定義本體看不到正在定義的該名稱本身：在 `$NMOS = @DEFINE-SYMBOL {$NMOS; …}` 中，定義本體內的 `$NMOS` 指的是外部（上層級或套件）中該名稱的定義。較低層級正是以此方式遮蔽並擴充上層定義；若外部沒有這樣的定義，則為錯誤。
- DEFINE-SYMBOL 與 DEFINE 的定義本體中出現宿主引用為錯誤：`#M1`、`&vss`、`#:inp` 與 `#M1:d` 皆不得寫於該處，符號定義本體中亦不得寫單獨的 `#`。在一般定義的定義本體中，單獨的 `#` 指的是用例所在的層級，僅於套用該定義時才得知（9.4）；在該處它作為篩選的作用域。不得從定義本體賦予方塊符號：該處的 `# @SET-SYMBOL` 為錯誤，因為層級的方塊符號在符號佇列中排在該層級的用例之前，而用例有可能在該階段之後才產生（8.3、9.2.6）。定義本體中的名稱於定義寫作處解析，但一般定義會在其他層級與其他檔案中被套用，若允許宿主引用，它仍會指向定義所在層級，含義便不唯一。需要宿主物件的一般定義須透過角色接收它們。
- **一般定義的定義本體何時檢查**：
  - 每個定義檢查一次：凡不依賴引數的部分皆於此時檢查，包含關鍵字、簽名（物件數量、參數名稱與類型）、`$` 與 `%` 名稱（在定義寫作處解析）、宿主引用、區域名稱衝突（9.4），以及宣告了種類的角色是否被正確使用：當角色 t 宣告為 `"instance"` 時，定義本體中的 `?t::net` 即為錯誤。簽名在讀取文字時檢查（7.1）；名稱僅在完整讀取該層級後才能解析，因此需要名稱的檢查在層級生效時進行。這兩類檢查對每個定義皆只執行一次，不論它被套用多少次。
  - 每次套用檢查：凡依賴引數的部分，例如未宣告種類的角色收到了什麼物件，或者符號是否擁有某支接腳，在每次套用時分別檢查，並於套用處回報錯誤，同時指向一般定義中的對應敘述。
  - 錯誤範圍：定義本體中發現錯誤的敘述（包含相衝突的區域名稱）會在定義處回報一次，並從每次展開中排除；定義本體的其餘部分照常運作（定義本體採容錯處理，9.1）。若角色列表或參數列表有誤（名稱重複、與標準子物件名稱衝突、未知種類名稱），則整個一般定義失效，連帶使所有使用它的套用全部失效。
  - 從未套用過的一般定義同樣會受檢查。由於這些檢查不依賴套用，因此能找出套件中未使用的定義裡的錯誤。

### 6.10 佔位符

- `?name` 僅能出現於一般定義的定義本體中，且該名稱須位於其角色列表或參數列表中；否則在讀取文字時即為錯誤。
- 出現在物件位置者為角色，例如 `?t` 或 `?t::net`；出現在字面量位置者為參數，例如 `min=?gap`、`[?w, 2]` 與 `(?x, 0)`（9.4）。將角色寫在字面量位置，或將參數寫在物件位置，在讀取文字時即為錯誤。角色名稱與參數名稱共用同一張名稱表，不得重複。
- 角色佔位符可帶路徑（如 `?t::net`），且集合角色的佔位符可取成員位置（如 `?ref{1}`，5.2.3）；參數佔位符兩者皆不可帶。

### 6.11 下標

| 寫法 | 代表 |
|---|---|
| `&D<3>` | 等同 `&"D<3>"` |
| `&D<7:0>` | 一個列表：`D<7>`、`D<6>`、…、`D<0>` |
| `&D<1,2:3>` | `D<1>`、`D<2>`、`D<3>` |
| `&D<0:6:2, 9>` | `D<0>`、`D<2>`、`D<4>`、`D<6>`、`D<9>` |
| `&D[3:0]` | `D[3]`、`D[2]`、`D[1]`、`D[0]` |
| `#XI0<3:0>` | 四個實例 |
| `#X1:D<7:0>` | X1 的八個端子 |
| `#:D<7:0>` | 本層級的八個連接埠 |
| `&"D"<1:0>` | `D<1>`、`D<0>` |
| `&"D<7:0>"` | 名稱為 `D<7:0>` 的節點：引號內的任何內容皆不剖析 |

- 網表本身沒有匯流排：當 Virtuoso 等工具寫出網表時，會將匯流排拆分成單一位元，例如 Spectre 網表中的 `D\<3\>`；子電路的匯流排連接埠與迭代實例亦會被拆分。下標是書寫這類單一或多個名稱的簡便方式。它僅負責構造名稱，不依賴宿主是否認識匯流排，因此其含義是唯一的。
- **形式**：宿主名稱（無論是否加引號）後方緊接 `<…>` 或 `[…]`，其內為以 `,` 分隔的項目。每項為 `i`、`a:b` 或 `a:b:s`，各形式可混用。數字 i、a、b 與 s 皆為無號十進位整數，且 s 至少為 1。名稱與括號之間不得有空白字元；括號內部允許空白字元與註解（3.5）。
- **展開**：各項目依書寫順序展開並串接；重複項予以保留。`a:b` 從 a 走到 b，`a:b:s` 則以步長 s 前進且不超過 b：`<7:0>` 為 7, 6, …, 0，`<0:7:2>` 為 0, 2, 4, 6。步長寫在最後，同 Virtuoso 與 Xschem 的慣例，而非 MATLAB 的 `a:s:b`。產生的名稱由括號前的名稱、左括號、不含前導零的十進位數字以及右括號組成，使用所書寫的括號種類：`&D<07>` 為 `D<7>`，`&D[3]` 為 `D[3]`。
- **單一或列表**：僅有一項且為單一數字時產生單一引用：`&D<3>` 即 `&"D<3>"`。其餘情況皆產生一個列表，即對集合的引用，如 `&D<3:3>` 與 `&D<3,5>`。列表在集合中展開一層（5.2）；作為敘述的唯一物件時會先拆開一層（5.2.1），故 `#XI0<3:0> @ALIGN("y")` 對齊四個實例；在接收單一物件的槽位中逐成員運作；在 WIRE 的網路槽位中則整體接收並構成一條匯流排（13.1）。
- **使用位置**：`#` 與 `&` 之後的宿主名稱，以及 `#` 引用中的端子名稱與連接埠名稱。RNL 名稱（`%`、`$` 與 `?` 之後）、角色名稱與子物件名稱不接受下標；緊接其後的 `<` 或 `[` 為錯誤。集合成員須改用大括號依位置取用（5.2.3）。
- **名稱後方不得緊接點**：緊接於名稱後的 `<` 或 `[` 一律開啟下標，若後方內容不符合形式則為語法錯誤；它絕不會被讀作點。若要在名稱後寫點，須以空白字元隔開，如 `&D (1, 2)`。
- **至多一次展開**：一個名稱至多有一個下標，因此 `A<1>[2]` 這類名稱須寫在引號中，`&"A<1>[2]"`。一筆引用中至多只能有一個下標會展開為列表：`#XI0<3:0>:a` 與 `#X1:D<7:0>` 允許，`#XI0<1:0>:D<1:0>` 為錯誤，而兩個各自僅為單一數字的下標則允許，如 `#XI0<3>:D<1>`。當展開為列表的引用後方接著 `::` 時，會為每個成員分別取得該子物件，如 `#XI0<3:0>::name`。
- **引號內不作剖析**：`&"D<7:0>"` 指向名為 `D<7:0>` 的節點；`&"D"<7:0>` 則會展開。若網表中的名稱包含並非用來標記匯流排位元的 `<` 或 `[`，請加引號以按原樣引用它。
- **比較的名稱為配接器所讀取的名稱**（3.6）：Spectre 網表中的 `D\<7\>`（其中的反斜線為 Spectre 的跳脫字元）經配接器讀取後為 `D<7>`，因此 `&D<7>` 可引用它。
- 每個成員各自獨立解析。找不到的成員為失效物件，依接收它的槽位規則嚴格或容錯處理（7.3）。
- 參數中的字串不展開，例如 PIN 的 `terminal=`（9.2.4）與篩選條件的 `name=`。
- 不支援以下寫法：Virtuoso 的重複寫法 `<*2>A` 與 `A<0:2*2>`，以及並列寫法 `A,B`（已有集合可用）；KiCad 與 Xschem 的 `D[0..7]`（其成員為不帶括號的 D0 … D7）。
- 迭代實例（例如 Virtuoso 的 `I0<3:0>`：多個宿主實例繪製為單一物件）須寫為疊畫：`#XI0<3:0> @BUNDLE`（11.8）。

### 6.12 端子名稱：DEVICE

```spice
* sky130 transistors, defined in the PDK and not in this netlist
* @RNL(type="header") {
*   @VERSION("0.4");
*   @DEVICE(name="X*", model="sky130_fd_pr__nfet_*", terminals=["d", "g", "s", "b"], type="nmos");
*   @DEVICE(name="X*", model="sky130_fd_pr__pfet_*", terminals=["d", "g", "s", "b"]);
*   @DEVICE(model="sky130_fd_pr__pfet_*", type="pmos")    /* adds the type to the names given above */
* }
XM1 out in 0 0 sky130_fd_pr__nfet_01v8 w=1 l=0.15
XM2 out in vdd vdd sky130_fd_pr__pfet_01v8 w=2 l=0.15
* @RNL { #XM1:d @CURRENT("in") /* XM1 is a sky130 NMOS; its terminal 1 is named d, and its type is nmos */}
.end
```

- **RNL 為端子命名並賦予類型。** `@DEVICE` 描述一類器件：`terminals` 依網表行上節點的順序列出各端子的名稱，而 `type` 給出其類型（見下文）。它僅為宿主的端子編號賦予名稱，既不改變端子順序，也不改變子電路的介面；它屬於顯示別名，這為原則 2.2 所允許。同一 `terminals` 列表中的名稱依宿主的大小寫規則須彼此不同，且不得僅由數字構成（6.4）；例如 `"d"` 與 `"D"` 在 SPICE 中視為相同。在可能被任一方言檔案使用的套件檔案檔頭記錄中，它們在不區分大小寫時亦須彼此不同。包含兩個相同名稱或純數字名稱的列表為錯誤，該條 DEVICE 敘述失效，而實例保留先前的 DEVICE 敘述與配接器給出的名稱。
- **僅限檔頭記錄**（2.8）：寫在任何其他處的 DEVICE 皆為錯誤。套件檔案的檔頭記錄亦計入（16.2）。內嵌套件不得容納 DEVICE；須將其寫在檔案的檔頭記錄中。
- **匹配方式**：`name` 與實例名稱比較，`model` 則與實例行上寫在模型位置或子電路名稱位置的名稱比較（在 Spectre 中為實例的 master，例如基本元件的 `resistor`）；兩者皆可使用萬用字元 `*`（任意數量的字元），並依宿主的大小寫規則比較。兩者可省略其一但不可同時省略，當寫出的條件皆相符時，該 DEVICE 即匹配該實例。DEVICE 可給出 `terminals`、`type` 或兩者皆給；既無 `name` 也無 `model`，或既無 `terminals` 也無 `type` 的 DEVICE 為錯誤並失效。比較名稱的篩選條件依相同規則支援 `*`（10.1）。
- **類型**：`type` 為字串，例如 `"nmos"`；下表中的詞彙為標準名稱。對於宿主未提供類型的實例（例如 X 實例，包含網表中未定義的 PDK 器件），這正是條件 `type`（10.1）、`${type}`（13.6）與斷言（15.3）所讀取的類型。來自模型卡的實例保留其模型的類型（見下文）：類型與之不同的 DEVICE 會給出警告且不修改它，如同子電路的連接埠名稱。
- **多筆匹配時，逐項以後寫者為準**：對於端子名稱與類型各自獨立判定，以最後一條寫出該項的匹配 DEVICE 為準，因此一條 DEVICE 可給出名稱，而較後一條可給出類型，且較後的 DEVICE 若省略某項則不會改動該項。順序依序為：配接器的預設值最先，接著是該層級所用套件中的 DEVICE 敘述（依套件位置順序，16.2），接著是外層檔案檔頭記錄中的，再來是引入檔案中的；同一筆檔頭記錄內依書寫順序，同一檔案的多筆檔頭記錄則以不帶 `language` 者優先，再依書寫順序取帶有 `language` 者，且各自僅作用於所屬語言區段中的實例（2.8）。因此檔案所寫會覆寫其套件、套件會覆寫配接器，而較具體的敘述應寫在較通用的敘述之後。所有套件的 DEVICE 敘述皆排在檔案的 DEVICE 敘述之前，不論其 USE-PACKAGE 寫於何處：因為檔頭記錄永遠位於檔案開頭，若依 USE-PACKAGE 位置排序，將使套件得以覆寫檔案自身所寫的內容。有寫 `model` 的 DEVICE 不會因此被排為更優先；沒有額外的明確度規則。
- **作用域**：寫在檔案檔頭記錄中的 DEVICE 作用於該檔案及其引入的檔案；被引入的檔案僅能更改其自身及其再引入的檔案（6.1）。寫在套件檔案檔頭記錄中的 DEVICE 作用於使用該套件的層級（16.2）。例如，一份 sky130 套件可容納 DEVICE 敘述、符號與選用符號的規則，使用者只要寫出 `@USE-PACKAGE(name="sky130-rnl")` 即可同時取得端子名稱、類型與符號。
- **配接器的預設值**：各方言的標準元素定義，視同寫於最外層。檔案中無須寫出它們，工具亦可將其寫出。支援同一方言的工具須給出相同的定義。它們依實例行所在檔案的版本套用該版本的預設值（16.1），如同寫於該檔案檔頭記錄中的 DEVICE。對於 SPICE 家族：

  ```rnl header
  @DEVICE(name="M*", terminals=["d", "g", "s", "b"]);
  @DEVICE(name="Q*", terminals=["c", "b", "e", "s"]);
  @DEVICE(name="J*", terminals=["d", "g", "s"]);
  @DEVICE(name="Z*", terminals=["d", "g", "s"]);
  @DEVICE(name="D*", terminals=["a", "k"]);
  @DEVICE(name="R*", terminals=["p", "n"]);             /* and one each like it for C, L, V, I, B, F, H, W */
  @DEVICE(name="E*", terminals=["p", "n", "cp", "cn"]);  /* and one each like it for G, S */
  @DEVICE(name="T*", terminals=["p1", "n1", "p2", "n2"]); /* and one like it for O */
  @DEVICE(name="U*", terminals=["a", "b", "ref"])
  ```

  Spectre 中的實例名稱不以元素字母開頭，因此預設值依 `model`（即實例的 master）匹配。對於 Spectre 的基本元件：

  ```rnl header
  @DEVICE(name="*", model="resistor", terminals=["p", "n"]);      /* and one each like it for capacitor, inductor, vsource, isource, ccvs, cccs, bsource, port */
  @DEVICE(name="*", model="diode", terminals=["a", "k"]);
  @DEVICE(name="*", model="vcvs", terminals=["p", "n", "cp", "cn"]); /* and one each like it for vccs, relay */
  @DEVICE(name="*", model="tline", terminals=["p1", "n1", "p2", "n2"]);       /* as T in SPICE */
  @DEVICE(name="*", model="transformer", terminals=["p1", "n1", "p2", "n2"])   /* as T in SPICE */
  ```

  - `switch` 對應其每個節點各有一個端子，依 Spectre 對位置的編號命名：`t0` 為共用端子，其後為 `t1` 至 `tn`（各切刀端）。
  - 模型卡的實例（其 master 為某條 `model` 敘述的名稱）採用該模型 master 所屬家族的端子名稱。其用於 `type` 條件（10.1）的類型則以 SPICE 的詞彙表示：

- **網表中定義的子電路**（包含透過 include 或 lib 引入的程式庫檔案中的子電路）：其端子名稱即該定義的連接埠名稱，這是宿主的事實（原則 2.2）。DEVICE 不會修改它們；若 DEVICE 匹配此類實例且給出不同名稱，會給出警告。DEVICE 僅為沒有端子名稱的器件命名：基本元件，以及網表中未定義的子電路（PDK 器件），後者由使用者或大型語言模型編寫 DEVICE。不帶 `terminals` 的 DEVICE 仍可為網表中定義的子電路指定類型。
- **名稱數量**：當實例的節點數多於 `terminals` 的名稱數時，多出的端子僅有編號；當實例節點數少於名稱數時，引用多出的名稱會失效。
- **大小寫**：DEVICE 給出的端子名稱依宿主規則比較（6.4）。
- 編號永遠有效，非純數字的子電路連接埠名稱以及 `#:port` 亦同。
