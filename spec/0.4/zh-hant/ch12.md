## 12 虛擬組件

### 12.1 概念

- 虛擬組件是僅存在於 RNL 中的組件，例如接地、電源、連接埠標記或未連接標記。它在電氣上並不存在：它僅用於繪圖，既不建立也不改變任何電氣事實。
- 虛擬組件就是擁有符號的用例；它沒有專屬的關鍵字或物件種類。`$GROUND @ATTACH &vss` 建立一個用例；標準套件為 `$GROUND` 的用例指派接地符號，因此它會被繪製出來。
- 規則：
  1. **接腳與角色。** 用例沒有端子。其符號的接腳依名稱存取，如 `%g0::pin`（6.5），而 `%g0::p` 仍為填入角色 p 的成員，即網路 vss。符號中以 `terminal=` 命名定義之角色（依名稱或依 `terminals=` 匹配，11.3）的接腳，會綁定至該角色：它繪製在填入該角色的對象上，因此該網路上的連線可止於該處，ROUTE-NET 亦會連接它（13.7），且該接腳的 `::net` 即為該網路。綁定角色的接腳會繪製於填入對象所在的網路上：即網路本身，或端子或接腳所屬的網路（5.2.4）。因此 `$GROUND @ATTACH #M5:3` 會在 M5:3 的網路上於自身獨立的位置繪製一個接地，而非繪製在該接腳上；若要在接腳上繪製接地，須使用定義本體有此作法的定義，例如 `$GROUND_STUB`（10.5）。當被綁定的角色填入空節點（6.3）時，該接腳不位於任何網路上，這是合法的：此時僅有寫在空節點上的連線會連接它（13.1），且標準套件的自動補齊不會為它加上任何東西。當被綁定的角色填入其他種類（如實例或點）時，該接腳沒有對應網路：此為種類錯誤，該用例的 SET-SYMBOL 失效且不予繪製，診斷亦會同時指向套用處。宣告種類為 `"net"` 的角色在套用定義時會將端子轉換為其網路（9.4），並在指派符號後將接腳轉換為其網路（5.2.4）。沒有接腳綁定的角色則接收其定義所宣告的種類，例如 `$NO_CONNECT` 的端子（12.6）。它不是電氣端子：SELECT-TERMINAL 不會選取它，ASSERT-TERMINAL 也不會檢查它；SELECT-PIN 則會選取它（10.1）。未綁定任何角色的接腳僅供繪製；它透過自身名稱以手工方式連線。接腳名稱不得與角色名稱相同（6.5）。
  2. 用例僅在被賦予符號時才會繪製；沒有符號的用例不會繪製。標準套件僅為用於繪製的定義指派符號，因此諸如差動對等語義用例不會被繪製出來。
  3. 沒有符號的用例自身不繪製任何內容：對它使用 ORIENT 會失效，連往其接腳名稱的連線亦會失效，因為它沒有接腳（9.2.4）；此項檢查在 8.2 的步驟 7 之後進行。它仍擁有自身的點 `%u::position`：PLACE 接收該點，寫在 `%u::position` 上的約束亦接收該點，而寫在該用例本身上的約束則接收其成員（14.1）；該點僅透過其定義本體綁定至該點的事物在圖面上顯現（14.1、9.4）。連線或圖形僅能透過 `::position` 止於該點，例如 `&n {%u::position %pt} @WIRE`：這是一個點而非接腳，因此該連線不建立連接（5.2.4、6.5）。為它指派樣式不算錯誤：該樣式會傳遞給其定義本體中所建立的可繪製物件（8.3），當定義本體未繪製任何內容時則不產生可見效果（11.3）。
  4. 被繪製的用例僅繪製它自身的符號。它既不包含也不移動其成員，且不是視覺上的容器。
  5. **繪製位置。** 其符號的原點即為該用例自身的點（14.1）：PLACE 與約束移動它，ORIENT 繞它旋轉符號（11.2），且它不會跟隨填入角色的物件移動，除非透過事實——例如連至其接腳的連線與定義本體中的事實。在接腳上或某一點上繪製標記的定義，會在其定義本體中將用例的點綁定至該處，例如 `{? ?t} @ALIGN("x"); {? ?t} @ALIGN("y")`（9.4）。未寫 ORIENT 時，求解器自行選擇其朝向並寫回（14.8），沒有求解結果的渲染器則繪為 `"R0"`（8.5）；它不會跟隨連線離開接腳的方向。填入第一個角色的物件為該用例的主物件；用例自身沒有名稱，文字透過該角色引用主物件，如 `${p}`（13.6）。
  6. 定義的定義本體一律會展開，因此虛擬組件的定義也可以擁有定義本體。
- 以原則 2.2 的術語而言，虛擬組件是角色填入宿主物件且帶有符號的用例；標準虛擬組件是標準套件中附帶預設符號指派規則的定義；使用者自訂虛擬組件則是使用者自己的定義，搭配一條符號規則或定義本體中賦予的符號。
- **定義虛擬組件。** 標準做法是一條一般定義，緊接在後寫出為其用例指派符號的規則：`$GROUND = @DEFINE(roles=[["p", "net"]]) {}; # @SELECT-USAGE(recursive=true) $GROUND => @SET-SYMBOL $GROUND_SYMBOL`。該規則依位置排入符號佇列（8.3），因此寫在較後方的風格體系套件或檔案規則可以用其他符號繪製相同的用例（如 `# @SELECT-USAGE(recursive=true) $GROUND => @SET-SYMBOL $EARTH`），包含在其他定義內部或由自動補齊建立的用例；若要只用不同符號繪製單一個用例，可直接點名該用例：`%g1 @SET-SYMBOL $EARTH`。定義本體中亦可直接指定符號，`? @SET-SYMBOL $X`，其中單獨的 `?` 即為該用例（9.4）：這屬於直接點名該用例（8.3），因此沒有規則能替換它，適合不打算以其他方式繪製的組件。改變繪圖方式不會改變端子或它們上面的連線。
- 一個用例是否為虛擬組件，僅取決於它是否擁有符號。
- 附註：一個理應繪製卻未被指派符號的定義，僅在其某個用例被設定朝向或連線、或作用於其上的約束未產生可見效果時才會回報（14.1）。

### 12.2 建立虛擬組件

```rnl id=g0
$GROUND @ATTACH &vss => @PLACE(24, 38) => %g0;
&vss @WIRE {#M5:3 %g0::pin}
```

- 在 `$D @ATTACH &net` 中，定義後方的物件依序對應定義的角色列表。此寫法使用 ATTACH，讀作「將此物加在該網路上」（9.4）。具有多個角色的虛擬組件寫法如同網表的實例行：若定義 `$DIFF_PORT` 具有角色 a 與 b，則寫作 `$DIFF_PORT @ATTACH &inp(a) &inn(b)`，或依順序寫作 `$DIFF_PORT @ATTACH &inp &inn`。
- 角色通常填入網路：綁定這些角色的虛擬組件接腳會繪製在這些網路上（12.1 第 1 項），而它與器件接腳之間的關係（繪於何處、連接何處）則由連線與約束給出（12.3）。綁定角色的接腳會繪製在填入對象的網路上（12.1 第 1 項）：`$GROUND @ATTACH #M5:3` 將一個接地附掛在 M5:3 所在的網路上，位置獨立，效果等同 `$GROUND @ATTACH #M5:3::net`。角色所接收的物件種類可在定義中宣告（9.4），例如 `roles=[["p", "net"]]`。
- 此關聯僅具描述性質：它不建立電氣連接，亦不予檢查（原則 2.2）。
- 同一條網路可擁有任意數量的虛擬組件，例如五個接地與兩個探針。用例沒有 key：每次套用皆會多建立一個用例（5.8）。
- 單一個虛擬組件可獲指派不同的符號，例如搭配自訂符號 `$EARTH` 寫出 `%g1 @SET-SYMBOL $EARTH`。
- ATTACH 本身除了 `priority`（14.8）之外沒有其他參數。連接埠的方向屬於標準套件的內容（12.4）；顯示的名稱取自主物件，若要顯示其他文字須撰寫標籤（13.3）。定義的參數照常透過 ATTACH 傳遞（9.4）。
- `%g0` 在一個層級內僅綁定一次（6.6）；若要更改其位置，須寫 `%g0 @PLACE(…)`。

### 12.3 相對於端子的位置

參數不能容納宿主引用，因此相對於端子的位置須寫成約束：

```rnl use=g0
{%g0::pin #M5:3} @ALIGN("x");
%g0::pin #M5:3 @DISTANCE("bottom-to-top", exact=2)    /* the pin of the ground 2 below the source of M5 */
```

若以 `@ALIGN("y")` 取代 DISTANCE，接地接腳便會落在 M5 的接腳上。兩支接腳之間長度為 0 的連線 `&vss @WIRE {#M5:3 %g0::pin}`（13.1）亦會使該接腳變為已連線，使得自動補齊不會在該處加上第二個接地（10.2、10.5）。

### 12.4 連接埠

```rnl
$IO_PORT @ATTACH &inp => @PLACE(0, 20) => %p_inp
```

- 子電路連接埠的名稱即為其內部網路的名稱，因此連接埠標記關聯至網路 `&inp`。
- 連接埠本身（`#:inp`）不會被繪製；它僅透過虛擬組件顯示。標準系列 0.4 的自動補齊透過集合 `$PORT_FILL_SET` 為每個連接埠網路加上連接埠標記（電源與接地網路亦然），略過已寫出連接埠標記的網路（10.5）；一個層級的標記排成一欄，各以 R0 擺放、接腳朝右，該欄與該層級每個實例保持至少 6 個單位的距離並位於其左側（從其自身的點量起），以優先順序為 `"low"` 的約束達成；其餘由求解器決定。檔案可從該集合中取出網路，使其不帶標記，例如 `# @SELECT-NET(name="vdd") => @REMOVE-FROM $PORT_FILL_SET`；以 `$IO_PORT @ATTACH` 寫出自行擺放的標記；或在一個層級中寫一次 `$PORT_LIST @ATTACH`，寫出同樣的那一欄，此時自動補齊在該層級不再加上任何標記。`$PORT_LIST` 自身的點位於其欄上（14.1），因此對該用例的約束會移動整欄。
- 連接埠的方向僅為顯示用途：網表沒有方向概念，由使用者決定繪製哪個符號。有哪些連接埠定義與符號屬於標準套件的內容。
- **連接埠標記的朝向。** 連接埠標記具有方向：例如標準套件中 `$IO_PORT_SYMBOL` 的接腳位於一端，標記則朝另一端延伸。未寫 ORIENT 時，求解器會根據連線的方向選擇朝向，力求減少轉折點。這是求解器的目標，不屬於語言規範（14.8），因此通常無須手工撰寫連接埠標記的 ORIENT。

### 12.5 標準虛擬組件

標準虛擬組件屬於標準套件，而非語言標準的一部分（16.3）。標準套件提供例如接地 `$GROUND`、電源 `$SUPPLY`、連接埠標記 `$IO_PORT` 與未連接標記 `$NO_CONNECT`（12.6），連同它們的符號、指派這些符號的規則，以及自動補齊（10.5）。

對同一條網路 vss，三種寫法會產生三種不同的繪圖：

1. `&vss @ADD-TO $GROUND_NET_SET`：vss 上每個沒有連線的端子都會在下方獲得一個帶有短連線的接地（標準套件的自動補齊，10.5）。這是教科書常見的畫法：每個接地端子下方各有一個接地符號。
2. `$GROUND @ATTACH &vss => %g`：整條網路共用一個接地，由求解器擺放。各端子透過連線連至其接腳，例如 `&vss @WIRE {#M5:3 %g::pin}`，或以 ROUTE-NET 連接整條網路（13.7）。
3. `$GROUND_STUB @ATTACH #M5:3`：僅在 M5 源極下方繪製一個帶有短連線的接地，如同自動補齊為個別接腳繪製的方式（10.5）。

- 電源以相同方式撰寫，使用集合 `$SUPPLY_NET_SET` 與定義 `$SUPPLY`。網路 0 預設位於 `$GROUND_NET_SET` 中（10.1）。
- 在第三種寫法中，短樁定義本體內的連線會使該接腳成為已連線，因此自動補齊不會在該處再加第二個接地（10.2、10.5）。
- 連接埠：自動補齊為子電路的每個連接埠網路加上連接埠標記（12.4）。若要擺放它、約束它或更改它顯示的名稱，須具名寫出：`$IO_PORT @ATTACH &out => %pout`，搭配連至 `%pout::pin` 的連線，並以 `%pout @TEXT("V_{OUT}", key="name")` 設定名稱（13.3）。不應有連接埠標記的網路須從 `$PORT_FILL_SET` 中取出。

### 12.6 未連接標記

```rnl
$NO_CONNECT @ATTACH #M1:4    /* terminal 4 of M1 is left unconnected on purpose */
```

- 未連接標記是標準套件的定義 `$NO_CONNECT`，其角色接收端子或接腳；沒有對應的關鍵字。端子會依其本身被採納，不作轉換（5.2.4），使得標在匯流排接腳單一成員上的標記（9.2.4），例如 `$NO_CONNECT @ATTACH #U1:d<3>`，能指明哪一個端子刻意懸空；同一支匯流排接腳上的多個標記會重疊繪製在該接腳處。該標記符號中沒有接腳綁定此角色（12.1 第 1 項）；該定義在定義本體中將用例的點綁定至填入該角色之對象的接腳（12.1 第 5 項），標準套件為其指派一個原點位於交叉中心且不含接腳的叉號符號。
- 該用例記錄該端子被刻意留空：`# @SELECT-USAGE $NO_CONNECT => @SELECT-TERMINAL` 可選出這些端子。
- 不要求檢查其他條件（例如該網路上是否有其他宿主端子，或是否有連線接觸該端子）（原則 2.4）；認識標準 `$NO_CONNECT` 的實作可以給出警告。
- 未連接標記不計為連線（10.2）：僅有此標記的接腳仍為 `wired=false`。若要讓依接腳執行的自動補齊略過這些接腳，須減去它們的接腳 `# @SELECT-USAGE $NO_CONNECT => @SELECT-TERMINAL => @SELECT-PIN`，如同 10.5 中的差集做法。
- 附註：未連接標記不是關鍵字，因為除了繪圖之外它對實作沒有其他用途：求解器不會讀取它，且其繪製方式可用定義與符號寫出（1.5 第 7 項）。
- 網路標籤不是虛擬組件；見 13.3。
