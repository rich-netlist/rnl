## 11 位置與外觀

### 11.1 位置：PLACE

```rnl
#M1 @PLACE(10, 20);
#M1 @PLACE(x=10)
```

- PLACE 為物件賦予位置；`x` 與 `y` 至少須寫出其中之一。PLACE 僅設定寫出的座標。每個座標最初皆為自由狀態，未寫出的座標保持自由，交由約束與求解器決定。
- PLACE 僅設定座標，不設定旋轉、鏡像、縮放或端子的方向；朝向以 ORIENT 設定（11.2）。
- 一個 PLACE 包含兩項幾何事實，x 與 y 各一項，發生衝突時可各自捨棄（8.5）。參數 `priority=` 指定其優先順序（14.8），例如 `#M1 @PLACE(12, 20, priority="high")`：依位置傳入的 x 與 y 排在前面，依名稱傳入的參數排在後方（4.2 第 9 項）。
- 接收的物件：實例、用例（依其自身的點，14.1）、疊畫（11.8）、點、TEXT（標註與標籤；PLACE 設定文字自身的位置，13.3），以及原點 `::position`（包含以中心形式寫出的 RECTANGLE、CIRCLE 或 ELLIPSE 之中心）。PLACE 不接收其他圖形；若要移動它們，須移動它們的點（13.4）。在一般定義的定義本體中，其座標為相對於用例自身之點的偏移量（9.4）。在符號定義本體中，PLACE 僅定位附著於 `?` 的 TEXT，使用區域座標（9.2.2）。
- 輸出沿用輸入的控制代碼（5.1）。
- 傳入集合作為物件時，會逐成員擺放（5.2.1）：`%pair_set @PLACE(10, 20)` 將兩個成員都擺放在 (10, 20)。集合沒有自身的位置（14.1）。
- 座標軸、單位、小數與容差的規定見 11.7。

### 11.2 朝向：ORIENT

```rnl
%pair_set = {#M3 #M4};
#M2 @ORIENT("MY");          /* flipped left-right */
%pair_set @ORIENT("R90");   /* each member turns about its own origin and stays where it is */
#M5 @ORIENT(["R0", "MY"])   /* not turned, or flipped left-right: the solver chooses */
#M6::g @ORIENT("left")      /* M6 is oriented so that its gate faces left */
```

- 接收的物件：實例、帶有符號的用例、疊畫，以及接腳（見下文）。對沒有符號的用例使用 ORIENT 會失效（12.1）；不接受點、標籤、圖形、連線與網路。
- 傳入集合作為物件時，會逐成員設定朝向（5.2.1）：每個成員繞自身原點轉動並停留在原處，且每個成員各為一項描述。集合不會作為一個整體旋轉。本語言不提供將整個集合一起旋轉的功能：集合沒有位置（14.1）。
- 帶有符號的用例繞其自身的點轉動；它擁有自身的朝向，不會隨填入其角色的物件一併轉動（12.1）。其定義本體所繪製或擺放的內容也不會隨它一併轉動（9.4）。
- **朝向代碼列表**（如 `["R0", "MY"]`）構成單一事實，當物件具有列表中的任一朝向時即成立。它整體保留或捨棄（8.5），並由求解器從列表中擇一。列表至少包含一個代碼；僅含一個代碼的列表等同於該代碼。求解器將它選定的朝向以單一代碼寫回其記錄（14.8）；撰寫者記錄中的列表保持不變，下次求解時重新選擇。不進行求解且沒有該物件求解結果的渲染器，依列表的第一個代碼繪製。
- 未寫 ORIENT 時沒有朝向約束，由求解器自行選擇；不進行求解的渲染器繪為 `"R0"`（8.5）。多個物件朝向之間的關係（相同朝向、互為鏡像）以 ORIENT-RELATION 撰寫（14.9）。
- ORIENT 為單一幾何事實並參與衝突取捨（8.5）；參數 `priority=` 指定其優先順序（14.8）。
- **朝向代碼。** 每個代碼代表一種朝向。僅接受下表中的八種拼寫與下方的四個方位詞，且區分大小寫（3.6）。這些名稱沿用 Virtuoso 的慣例，且在 y 軸向上（11.7）時其含義亦同。不接受等價拼寫（如等同 MY 的 `"MXR180"`）與任意角度，無論單獨寫出或寫在列表中皆然：它們屬於錯誤參數值，會使該 ORIENT 失效。工具僅寫回這八種代碼，每次寫回其中一個。沒有從目前朝向再進一步旋轉的相對形式（第 17 章）。

  | 代碼 | (x, y) 變為 | 含義 |
  |---|---|---|
  | `"R0"` | (x, y) | 不旋轉 |
  | `"R90"` | (−y, x) | 逆時針旋轉 90° |
  | `"R180"` | (−x, −y) | 旋轉 180° |
  | `"R270"` | (y, −x) | 逆時針旋轉 270°，即順時針旋轉 90° |
  | `"MY"` | (−x, y) | 沿 y 軸鏡像：左右翻轉 |
  | `"MX"` | (x, −y) | 沿 x 軸鏡像：上下翻轉 |
  | `"MYR90"` | (−y, −x) | 先 MY，再 R90 |
  | `"MXR90"` | (y, x) | 先 MX，再 R90 |

- **四種旋轉的方位詞。** 旋轉亦可寫成方向詞，代表相同的代碼：`"left"` 為 `"R0"`，`"down"` 為 `"R90"`，`"right"` 為 `"R180"`，`"up"` 為 `"R270"`，在列表中亦同。ORIENT-RELATION 僅接收代碼（14.9）。對物件而言，方位詞僅為另一種拼寫：`#M2 @ORIENT("left")` 即 `#M2 @ORIENT("R0")`。對接腳而言，它正照字面所言：該接腳在圖面上朝向的方向（以朝左為基準起算）。
- **接腳。** 給予接腳——或代表其接腳的端子（5.2.4）——的 ORIENT 會約束該接腳在繪圖中的方向：即符號中以 `direction=` 寫出的方向（9.2.4）經其所屬物件的朝向變換後所得的四個方向之一。當所屬物件具有能將該接腳轉至該方向的朝向之一（八種之中佔兩種）時即成立，因此它不會固定物件的單一朝向；傳入列表則允許列出的每個方向。給予接腳的鏡像代碼代表它將 left 轉往的方向：`"MY"` 即 `"right"`，`"MX"` 即 `"left"`。此類 ORIENT 是獨立的幾何事實，以該接腳為 key，獨立於所屬物件自身的 ORIENT 之外；兩者與任何兩項事實一樣進行衝突取捨（8.5）。未寫出 `direction=` 的接腳沒有可約束的方向：該接腳的 ORIENT 失效，同一敘述中的其他成員仍照常生效（5.2.1）。不進行求解且沒有該物件求解結果的渲染器，繪製時視同未寫出其接腳的 ORIENT。
- **組合順序。** MXR90 與 MYR90 先鏡像後旋轉；名稱依操作順序閱讀，與 Cadence 及 OpenROAD 的 OpenDB 一致。
- **作用方式。** 朝向作用於符號的區域座標，繞其原點變換，隨後將原點置於物件的位置上：符號上的某一點繪製於物件位置加上該朝向作用於其區域座標的結果。符號的圖形與接腳位置隨之剛體變換，連線離開接腳的方向亦隨之旋轉（9.2.4）。文字依 9.2.5 所述顯示；字形不會鏡像翻轉。
- **僅影響繪製位置。** 朝向僅改變接腳繪製的位置，不改變它們所屬的端子。當方塊符號上下翻轉時，inp 的接腳繪製於底部，連往 inp 的連線亦隨之移動。系統不會交換兩支接腳以將 inp 留在頂部：那樣會改變哪條連線連接至哪個端子，屬於網表範疇（原則 2.2）。若要在其他位置繪製 inp，須改用另一個符號（11.3）。

### 11.3 符號與樣式：SET-SYMBOL 與 SET-STYLE

```rnl
%w13 = &x @WIRE {#M1:1 #M3:1};
#M1 @SET-SYMBOL $NMOS;
# @SELECT-INSTANCE(model="nch") => @SET-SYMBOL $NMOS;
%w13 @SET-STYLE $signal;
# @SELECT-INSTANCE => @SET-STYLE $base
```

- SET-SYMBOL 為物件指派符號。物件可為實例、用例或疊畫，或它們的集合（包含篩選與逐一產生的結果）；每個成員僅指派一次符號（5.2.1）。在子電路中，`# @SET-SYMBOL` 指定該子電路的方塊符號（9.2.6）。
- 被賦予符號的用例會被繪製出來：它即為虛擬組件（第 12 章）。
- **端子與接腳的匹配。** 符號的端子名稱即其接腳所綁定的名稱（9.2.4）。當 SET-SYMBOL 為實例指派符號時，符號的每個端子名稱會匹配至實例上具有該名稱的端子（由 DEVICE 或子電路的連接埠給出，6.12）；編號則匹配至該順序位置的端子。實例上沒有接腳綁定的端子即無接腳，例如三端符號中的基體。符號上實例所沒有的端子名稱，會使其接腳不綁定任何端子，並給出警告。
  - `terminals=` 可更改此次 SET-SYMBOL 的匹配方式。其標準形式依實例行節點的順序（如同 DEVICE 的 `terminals`，6.12）列出符號的端子名稱：若某符號的接腳綁定 `"a"`、`"b"` 與 `"c"`，則 `#X1 @SET-SYMBOL(terminals=["b", "a", "c"]) $GATE` 將節點 1 綁定至 b 的接腳、節點 2 至 a 的接腳、節點 3 至 c 的接腳。它亦可列出成對映射，實例的端子在前、符號的端子在後：`terminals=[["d", "b"], ["g", "a"], ["s", "c"]]`；未列於成對映射中的端子仍依名稱匹配。既非上述兩種形式之一、或重複命名同一個端子的列表皆為錯誤參數，該 SET-SYMBOL 失效。
  - 對用例而言，符號的端子名稱會匹配至其定義的角色名稱。編號，或沒有任何角色擁有的名稱，不會綁定任何角色，並會給出警告。`terminals=` 依角色列表的順序寫出符號端子名稱，或寫成角色名稱與符號端子名稱的配對（12.1）。
- SET-STYLE 為物件指派樣式。物件可為實例、用例、疊畫、連線或圖形（含文字），或它們的集合（包含篩選與逐一產生的結果）。它不接收網路、層級、約束、定義或點。端子隨其所屬物件的符號繪製，並採用其所屬物件的樣式。給予用例的樣式會傳遞給它的符號以及在其定義本體中建立的可繪製物件（8.3），因此為沒有符號的語義用例指派樣式不算錯誤；當定義本體中未繪製任何內容時，它不產生可見效果。
  - 附註：否則標準套件的 `# @SELECT-USAGE => @SET-STYLE $base` 規則便會對每個語義用例都給出一條警告。
- 輸出沿用輸入的控制代碼；當物件為集合時，輸出即為該集合。
- 兩者皆透過外觀佇列生效，而非依 key 覆寫。佇列分為兩個層級（tier）：直接點名該物件的 SET-SYMBOL 或 SET-STYLE，優先於透過篩選觸及該物件或傳遞給該物件者（8.3）。
- 已有預設規則（標準套件，16.3）之處無須重複撰寫。
- **參數與樣式。** 直接寫在物件上的樣式參數（例如 TEXT 的 `size=`）屬於該物件的直接樣式，位階高於來自篩選或傳遞而來的樣式。直接點名該物件且寫在較後方的 SET-STYLE，則依位置覆寫這些樣式參數（8.3）；編輯器便是藉此修改單一物件。定義的參數若未傳入則視同未寫出，因此樣式會生效（9.4）。
- **標籤與交接圓點。** 物件的樣式會傳遞給附著於其上的文字。在篩選或傳遞取得的樣式層級中，它與選取該文字的規則（如 SELECT-LABEL）依位置比較；文字自身的參數與直接點名該文字的 SET-STYLE 則位於直接層級。因此當 `#M1 @SET-STYLE $signal` 寫在標籤規則之後時，M1 的名稱亦會採用該顏色，且拖曳該名稱不會改變其顏色。符號中附著於 `?` 的文字亦為標籤，SELECT-LABEL 會選取它們；附著於點的固定文字則屬於符號的圖形，採用所屬物件的樣式。附著於網路或點的文字不會從所附著的對象繼承樣式，僅使用自身的樣式。交接圓點是 `$JUNCTION` 的用例（13.2）；圓點為其符號，顏色跟隨該用例的樣式。

### 11.4 單一物件的多個繪圖

本標準不提供將同一個宿主物件繪製多次的方式：諸如 `#M1` 的宿主控制代碼一律指涉該物件唯一的那一份繪圖。若後續版本新增單一物件的多個繪圖，它們會成為各自擁有獨立名稱的不同物件，而宿主控制代碼仍保持原有含義（附錄 C）。

附註：多個實例繪製為單一物件則是疊畫（11.8）。

### 11.5 群組：GROUP

```rnl
%stage1_set = {#M1 #M2 #M5} @GROUP;
%stage2_set = {#M3 #M4} @GROUP(spacing_x=-1);
{%stage1_set %stage2_set} @GROUP;
%stage1_set %stage2_set @DISTANCE("left-to-right", min=1)
```

- GROUP 為一個集合加入一項事實：求解器將其成員當作一個區塊處理。它沿用該集合的控制代碼，因此 `%stage1_set` 仍為該集合。
- **群組不是物件。** 它沒有位置也沒有邊界框，且無法針對群組撰寫約束：在約束中傳入標記了群組的集合時，它仍是一個集合，容納它的位置代表其每個成員（14.1）。GROUP 亦不是第五種原子約束。標準套件中屬於群組的結構皆以匿名群組建立。
- **成員。** 群組的成員是其集合中的物件，巢狀集合會一路展開至最內層的物件。沒有符號的用例代表填入其角色的物件，依此類推向下至最底層物件；帶有符號繪製的用例本身即為一個成員。ROUTE-OBJECT 以相同方式追蹤用例的角色，並同時計入帶有符號繪製之用例自身的接腳（13.7）。
- **作用。** 群組僅以兩種方式引導求解器：將群組的成員排列在一起（排在剩餘物件之前或與之分開），並盡量在事實允許的範圍內將其他物件排除在群組的區域之外。兩者皆為求解器的評估準則，位階低於本語言的所有描述（8.5）：群組不保證任何幾何關係，若事實迫使某個物件進入群組的區域，該物件仍會繪製於該處。對位置的強制要求（例如不可交錯排列——如上例中的 DISTANCE——或置中對齊）須寫成原子約束。
- **群組樹歸求解器管理。** 群組依包含關係巢狀排列：`{%stage1_set %stage2_set}` 的成員是這五個實例，因此兩個級皆位於其內部。若兩個群組共用部分成員但互不包含，兩者不能同時作為完整區塊；求解器依自身規則保留其中之一，並以提示指出另一個。除此之外，群組如何影響搜尋與評分由實作自行決定。
- **間距。** `spacing_x` 與 `spacing_y` 為整數個格點單位（11.7），由求解器在 x 與 y 方向上加至群組內部的預設間距；兩者皆可省略，負值可使群組排列得更緊密。兩物件之間採用同時包含兩者的最內層群組的間距；未共用任何群組的物件之間採用該層級的間距，由 `@SOLVER-CONFIG` 以同名 key 設定（14.10）；群組與外部物件之間則採用包圍它的外層群組或該層級的間距。求解器可以限制數值範圍並予以說明。間距是求解器的準則，而非事實：它讓步於每一項保留的事實。
- GROUP 是關鍵字，而非標準套件的定義：其含義僅求解器知曉，無法在定義本體中寫出（1.5 第 7 項）。
- 檢視器可以繪製群組，例如加上外框；此由檢視器自行決定，本標準不作規定。
- GROUP 不是原子約束：它不參與衝突取捨（8.5）且沒有優先順序，僅有開啟與關閉。`%stage1_set @PRIORITY("disabled")` 會將該群組自求解器移除，從而取消該分組。當外層用例被停用時，其展開所得的群組亦隨之關閉，除非從外部透過 `::` 直接寫在某個群組上的 PRIORITY 重新開啟它（14.8）。定義展開所得的群組唯有本身為具名區域物件並從外部引用時，才能單獨關閉（9.4）。

### 11.6 繪圖順序與圖層：LAYER

```rnl
@RECTANGLE(fill="fillcolor") {(0, 0) (40, 30)} => @LAYER("bottom") => %f1;    /* a frame, drawn below everything */
(2, 28) @TEXT("input stage") => @LAYER("top") => %n1
```

- 圖層共有三層：`"bottom"`、`"middle"` 與 `"top"`。先繪製底層，其次中層，最後頂層。在同一圖層內，物件依位置順序繪製：較後方的物件繪製在較前方物件之上並將其覆蓋。
- `@LAYER(…)` 設定物件的圖層；未寫時物件位於 `"middle"`。每個物件有一個 key，較後寫的 LAYER 覆寫較早者（5.8）。LAYER 不改變物件在圖層內的位置。
- **位置**即書寫順序（1.5 第 2 項），與 8.3 及 8.5 的順序相同：在同一層級內為文字順序；套件的內容位於其 USE-PACKAGE 的位置，根層級套件排在最前（16.3）；以 `scope=` 寫入的敘述排在目標子電路自身文字之後。各類物件取以下位置：
  - 連線、圖形與文字（標註與標籤）：建立它的敘述；
  - 用例：生效的 SET-SYMBOL，若符號由規則指派，則為該規則（8.3）；
  - 由規則、定義展開或逐一產生建立的物件：建立它們的敘述，在同一次展開內依定義本體中的順序；
  - 實例：位於所屬圖層的最底端，彼此之間依網表順序排列；被置於另一圖層的實例位於該圖層的最底端。疊畫視同實例，依其第一個成員的網表順序排列。
- 修改物件的敘述（如 PLACE、ORIENT、SET-STYLE 與 LAYER）不會移動它的位置。
- 接收的物件：實例、帶有符號的用例、疊畫、連線、圖形與標籤；傳入集合時逐成員處理（5.2.1）。對沒有符號的用例使用 LAYER 不算錯誤但不產生效果（與 SET-STYLE 相同，11.3）；作用於點、網路、約束與定義則失效。
- 符號的成員沒有圖層：它們依成員順序（9.2.1）隨所屬物件一同繪製。
- 沒有數值型的 `z=`。覆寫（依事實的 key）與覆蓋（依圖層與位置）各自獨立。
- 此處的「圖層」指繪圖順序，與宿主的「層級」（2.6）無關。

### 11.7 座標與單位

- **座標軸。** x 向右、y 向上；較大的 y 位於較上方。因此 ORDER 與 DISTANCE 的 `"bottom-to-top"` 指向正上方（14.3、14.5），而 R90 為逆時針旋轉（11.2）。SVG、部分其他格式與某些編輯器的 y 軸向下；實作於繪圖、匯入與匯出時自行翻轉 y 軸。
- **單位。** 單位沒有實體尺寸。一個單位在螢幕上或列印時繪製多大，由檢視器決定。
- **小數。** 座標與長度可寫成小數（3.7）；無須為整數，且位數不設上限。座標依書寫數值繪製，不會自動貼齊整數。
- **格點。** 接腳應位於整數點上（9.2.4）；符號中的圖形不受此限。當實例置於整數點並採用八種朝向之一時，整數接腳位置經變換後仍為整數，因此連線亦會落在整數點上：整數點即為慣用的格點。語言本身沒有格點概念。求解器是否將自由座標四捨五入至整數為其自身規則，位階低於所有語言描述（8.5）；當約束迫使產生小數時，便採用該小數。走線模式計算出的轉折點保留計算結果，不予四捨五入（13.1）。
- **容差。** 檢查約束是否成立以及判定衝突時（8.5），容差範圍內的差異視作滿足。容差是求解器可供使用者設定的選項；本標準不固定其數值，但它大於 0，以確保無法寫成有限小數的數值能寫回檔案（見下文）。不進行求解的檢視器在檢查時使用自身設定。因此兩款工具在恰好處於容差邊界的案例上可能意見不同。求解器寫回座標時須使用讀回後仍為同一數值的小數，不得進一步截斷；沒有有限小數表示的數值（如 1/3）須寫出足夠的位數，以確保在讀回記錄時其所滿足的事實仍在容差內成立（第 17 章）。
- **符號座標。** DEFINE-SYMBOL 定義本體中的區域座標與場景採用相同的單位與座標軸；其原點即為符號的原點（9.2.1、6.5）。不支援縮放：符號不接收縮放參數，實例亦無法縮放。匯入器負責將其他工具的符號轉換為 RNL 單位。
- **其他長度。** 語言中所有長度皆以座標單位計量並隨繪圖一同縮放：DISTANCE 的 `min`、`max` 與 `exact`、CIRCLE 的 `radius=`、RECTANGLE 與 ELLIPSE 的 `width=` 與 `height=`、文字字級 `size`（等同 SVG 的 `font-size`）、線寬 `linewidth`、箭頭長度 `arrowsize`（9.3），以及作為長度使用的定義參數（如 `gap=3`）。線寬為 0 是唯一例外：代表極細線，在任何縮放倍率下皆保持同等細度，這也是預設值（9.3）。
- **原點與紙張。** 場景的原點沒有特殊含義。每個子電路各是一張原理圖（6.1）並擁有各自座標；檢視器依內容範圍調整檢視框。RNL 既不記錄紙張大小，也不記錄編輯器的貼齊格點。

### 11.8 疊畫：BUNDLE

Virtuoso 中的迭代實例（如 `I0<3:0>`）在圖面上是一個符號，在網表中卻是四行：

```spice
* A unit cell repeated four times
* @RNL(type="header") { @VERSION("0.4")}
.subckt unit in out vdd vss
R1 in out 1k
.ends unit
XI0<3> D<3> out vdd vss unit
XI0<2> D<2> out vdd vss unit
XI0<1> D<1> out vdd vss unit
XI0<0> D<0> out vdd vss unit
* @RNL {
*   #XI0<3:0> @BUNDLE => @PLACE(30, 10) => %x;   /* four instances drawn as one symbol */
*   &D<3:0> @WIRE {(20, 10) %x:in};              /* a bus to the in pin of the bundle */
*   &out @WIRE {%x:out (40, 10)};                /* all four members are on out: an ordinary pin */
*   %x @TEXT("I0<3:0>", key="name")              /* the name, written out */
* }
.end
```

- **新物件。** BUNDLE 接收一組宿主實例並建立一個疊畫，在原處繪製為單一符號以取代這些實例。成員依書寫順序排列，第一個成員決定接腳與符號。
- **接腳與符號。** 端子名稱與端子數量取自第一個成員。外觀佇列將疊畫視同其第一個成員：篩選依第一個成員的條件觸及該疊畫（10.1），且子電路的方塊符號同樣適用。直接寫在疊畫上的 SET-SYMBOL、樣式、PLACE、ORIENT、LAYER、約束與文字皆歸屬該疊畫。
- **端子。** 疊畫的端子（如 `%x:in`）代表所有成員的同名端子：它是一支匯流排接腳。
  - **依名稱對應**：疊畫的端子代表各成員具有該名稱的端子，無論該端子在各成員中的順序為何；沒有該名稱端子的成員不參與其中。
  - `::net`：當所有成員皆位於同一網路時，為該網路，例如 `%x:out::net` 即為 `&out`；否則為依成員順序排列的網路集合，例如 `%x:in::net` 為 D<3>、D<2>、D<1>、D<0>。因此定義中的 `?t::net @WIRE {…}` 在取得集合時繪製匯流排，取得單一網路時則繪製一般連線（13.1）。
  - 連至疊畫端子的連線會連接每個成員的該端子（10.2）。
- **屬性**（13.6）：當某屬性在所有成員上的值相同時為該值；否則為以 `,` 連接的各值。當所有成員的 w 皆為 1u 時，`${w}` 顯示 1u；`${name}` 則為 `XI0<3>,XI0<2>,XI0<1>,XI0<0>`，若要顯示 `I0<3:0>`，須寫出帶有相同 key 的文字，如上例所示。端子的 `${net}` 亦依相同方式運作，例如 `D<3>,D<2>,D<1>,D<0>`。
- **篩選。** 成員無法被選出；選中的會是疊畫本身（10.1）。因此諸如「為每個未連線接腳加上網路名稱」的規則只會為疊畫加上一個標籤，顯示整條匯流排。接收實例的定義角色亦接收疊畫，接收端子的角色亦接收疊畫的端子（9.4）。
- **成員不單獨繪製。** 直接寫在成員或成員端子上的繪圖相關描述（位置、朝向、符號、樣式、圖層、約束、連線或文字）皆會失效：成員僅透過疊畫繪製。與繪圖無關的描述仍照常運作，例如 CURRENT 以及語義用例的角色。
- **成員須屬同一種類。** 成員應具有相同的模型或子電路名稱，以及相同數量、名稱與順序的端子名稱。若不相同會給出警告；它們仍會組成疊畫，並採用第一個成員的接腳與符號。僅在參數上不同的成員不給出警告：它們的屬性會顯示連接後的值（見上文）。
- **每個實例僅屬於一個疊畫。** 出現在多條 BUNDLE 中的實例屬於較後寫出的那一條（1.5 第 2 項）；較早的一條保留其餘成員，且可以給出提示。成員全被取走的較早疊畫成為空疊畫且不會繪製，並給出警告。
- BUNDLE 僅接收明確寫出的物件：傳入篩選結果或依賴篩選的集合（10.4）會失效，因為疊畫須在指派符號之前便已存在（8.2、10.4）。基於相同理由，寫在步驟 6 產生內容中的 BUNDLE 亦會失效。傳入空集合的 BUNDLE 會失效（5.2.1）。包含非宿主實例之成員會失效（種類錯誤）。若有成員找不到，則整條敘述失效（嚴格輸入，7.3）。
