## 14 佈局意圖

### 14.1 通用規則

- 約束建立一個約束物件。具名約束可被引用，便於查找與編輯，如 `%row1 = {#M1 #M2} @ALIGN("y")`；約束亦可為匿名。
- **詞彙**：位置上的原子約束僅有 ALIGN、ORDER、DISTRIBUTE 與 DISTANCE，此外還有 PLACE、ORIENT、GROUP 以及寫成表格形式的有序排列 TABLE（14.11）。其他關係皆寫作一般定義：對稱（14.7）、置中（三個成員的 DISTRIBUTE）、列與欄（ALIGN 搭配 ORDER）、訊號流（14.6）、鏡像對、成比例間距（多個精確 DISTANCE）。沒有 LEFT 或 ABOVE（它們是帶有方向的 ORDER 或 DISTANCE），也沒有 RATIO、NEAR 或 INSIDE。相對朝向（相同朝向、互為鏡像）是 ORIENT-RELATION（14.9）；一對電晶體的閘極究竟相向還是背向仍須以 ORIENT 或對端子寫 ORDER（14.3）固定。符號不重疊、間距常數與格點皆歸求解器管理（11.7），不屬於約束詞彙。
- **沒有相對於整張圖面的位置**：沒有表示「最左」、「最右」或「最上」的關鍵字，也沒有整張圖面或符號輪廓的範圍概念。請改寫相對於一組物件的 ORDER 或 DISTANCE，由求解器據此求出佈局。若要將連接埠置於最右側：`{#M6 #M7 #CL} %pout @DISTANCE("left-to-right", min=2)`，或在 M7 本就位於最右側時寫 `{#M7 %pout} @ORDER("left-to-right")`。
- **成員須是最底層物件**：實例、疊畫、端子與接腳、點、TEXT（依其自身位置，13.3）、以中心形式寫出的 RECTANGLE、CIRCLE 或 ELLIPSE 之中心，以及帶有符號繪製的用例（各依其自身的點）。沒有符號的用例本身不是成員，而是代表其成員：填入其角色的物件，其中身為無符號用例的成員如同 GROUP（11.5）向內展開至最底層物件，並略去其中的網路。其自身的點寫作 `%u::position`（6.5）。連線、網路、約束與定義不得作為成員：傳入其中之一會使該約束失效。連線上的某個位置須先寫成一個點（13.1）。集合不是成員：它沒有自身的位置（見下文）。
- **採計哪一個點**：實例採計其原點，即其符號的原點，亦即 PLACE 所擺放之處；端子或接腳採計接腳的位置，即器件位置加上符號中接腳位置的剛體變換，無法單獨移動；點即其自身；有符號的用例或任意用例的 `::position` 採計其自身的點（見下文）；TEXT 採計其自身位置；以中心形式寫出的 RECTANGLE、CIRCLE 或 ELLIPSE 採計其中心。不採用符號邊界框的中心：三端與四端 MOS 符號的邊界框不同，排成一列時會無法對齊。若要依接腳對齊，請寫出端子。視覺對稱要求原點位於符號的對稱軸上，這取決於符號庫。
- **用例自身的點**：每個用例各自擁有一個點，沒有符號的用例亦同。該點最初為自由狀態，如同 `(_, _)`，並由事實綁定：PLACE、約束、連至其符號接腳的連線，以及其定義本體寫在它上面的事實；剩餘自由的部分由求解器擺放。帶有符號的用例以其符號的原點置於該點上進行繪製（12.1），且作用於它的約束即作用於該點。作用於無符號用例的約束則作用於其成員（見上文）；若要約束其點，請寫 `%u::position`：`{%dp::position #X1} @ALIGN("y")` 會將 X1 置於差動對中心的高度，而 `{%dp #X1} @ALIGN("y")` 則會將 X1 與差動對的三顆電晶體置於同一高度。其定義本體在對單獨的 `?` 寫出事實之處將該點綁定至其成員（9.4），如 `{?members::position ?} @ALIGN("y")`。當一個用例的點未透過任何事實綁定至任何可繪製事物時，作用於 `%u::position` 的約束不產生可見效果，且會給出一條提示。
- **集合沒有位置**：集合僅是一個成員列表，沒有中心也沒有範圍。在 ALIGN、ORDER 或 DISTRIBUTE 的成員列表中，作為集合的項目——直接寫出的 `{…}` 或對集合的引用（5.2）——在該位置代表其每個最內層成員：該敘述代表從每個這類項目各取一個成員的每種組合，每種組合各為一條約束。`{#M1 {#M2 #M3} #M4} @ORDER("top-to-bottom")` 即 `{#M1 #M2 #M4}` 與 `{#M1 #M3 #M4}`，使 M2 與 M3 各自位於 M1 與 M4 之間，而 M2 與 M3 彼此之間不排出順序。身為無符號用例的項目亦以相同方式代表其成員（見上文）。DISTANCE 槽位中的集合則代表其每個成員，每對組合各為一條約束（14.5）。作為空集合的項目會被略去。將同一物件取兩次的組合會被略去：共用一顆器件的兩個結構以 `{%stage1 %stage2} @ORDER("left-to-right")` 排序時，會對其餘每對成員排序，而不會讓該共用器件與自身排序。
  - 由此建立的約束擁有原敘述的優先順序、名稱與位置（8.5、14.8）；名稱會綁定由它們組成的集合。成員數過少而未陳述任何條件的組合會給出一條提示。
  - 實作可以限制單一條敘述所能代表的約束數量；超出實作上限時該敘述失效，並回報錯誤說明已達實作上限（1.6）。
  - 作為唯一物件傳入的集合會先拆開一層（5.2.1）：`%row_set @ORDER("left-to-right")` 與 `{%row_set} @ORDER("left-to-right")` 皆依序排列該集合的成員。
- **方向須明確寫出。** ALIGN 接收一個投影軸 `"x"` 或 `"y"`（14.2）；ORDER、DISTRIBUTE 與 DISTANCE 接收四個方向之一（14.3）。沒有將方向留待未定的形式：可朝任一方向繪製的關係須為一個方向寫出一項事實，若要讓定義同時支援兩種畫法須寫成兩個定義，例如標準套件的 `$BRANCH` 與 `$BRANCH_HORIZONTAL`。唯一提供選擇的事實是 ORIENT（11.2）與 ORIENT-RELATION（14.9）的朝向列表。
- 約束不改變網表。發生衝突時，每條原子約束整體保留或整體捨棄（8.5）。
- 四種原子約束、ORIENT-RELATION 與 TABLE 皆接收參數 `priority=`（14.8）。

### 14.2 ALIGN

`{…} @ALIGN("y")`：各成員在投影軸 `axis` 上相等：`"y"` 使它們具有相同 y（排成一列），`"x"` 使它們具有相同 x（排成一欄）。`axis` 為必填，可依位置傳入，且僅能是單一投影軸：傳入投影軸列表屬於錯誤參數值，會使該約束失效。少於兩個成員時，該約束自動成立而不失效：撰寫敘述時並不知道篩選或集合會有多少成員。

### 14.3 ORDER

```rnl
%rc_set = {#R2 #C2};
{#M1 #M1:2 #M2:2 #M2} @ORDER("left-to-right");  /* M1 on the left, the two gates face each other */
{#R1 {%rc_set} #M1} @ORDER("left-to-right")     /* R2 and C2 each between R1 and M1 */
```

- `{…} @ORDER(direction)`：各成員在該方向的投影軸上嚴格單調排列。少於兩個成員時自動成立。
- **方向**：參數 `direction` 為必填，依位置第一個傳入。其取值為：
  - `"left-to-right"`、`"right-to-left"`：x 遞增、x 遞減；
  - `"bottom-to-top"`、`"top-to-bottom"`：y 遞增、y 遞減（y 軸向上，11.7）。

  DISTRIBUTE 與 DISTANCE 採用相同的取值。沒有僅固定座標軸的取值：`"x"` 與 `"y"` 屬於錯誤參數值，會使該約束失效。
- 作為集合的項目代表其每個成員（14.1）：第二個範例依序排列 R1、R2、M1 與 R1、C2、M1；R2 與 C2 彼此之間不排出順序。
- ORDER 是關於點的事實：它比較成員的點，而非邊界框。沿著 ORDER 使符號的邊界框彼此分開是求解器的準則，位階低於每項事實（8.5）；當事實迫使邊界框重疊時，它們就會重疊，且可以有提示說明此事。
- ORDER 是嚴格的：相鄰成員至少相差一個座標單位（11.7）。它是每對相鄰成員之間沿該方向 `min=1` 的 DISTANCE 之簡寫（14.5）。若要座標相等，請使用 ALIGN。

### 14.4 DISTRIBUTE

```rnl
{#R1 #R2 #R3} @DISTRIBUTE("left-to-right")     /* R1, R2 and R3 from left to right, in equal steps */
```

- `{…} @DISTRIBUTE(direction)`：各成員依該方向嚴格前後相隨（同 ORDER，14.3），且相鄰成員在該投影軸上的差值相等。等距間距計算的是成員之點之間的距離，而非邊界框之間的空隙；作為集合的項目代表其每個成員（14.1）。
- **方向**：參數 `direction` 為必填，依位置第一個傳入，取值同 ORDER（14.3）。
- 僅有兩個成員時，DISTRIBUTE 等同 ORDER；少於兩個時自動成立。

### 14.5 DISTANCE

```rnl
#M1:2 #M1 @DISTANCE("left-to-right", min=1);      /* the gate is on the left */
#R1 #R2 @DISTANCE("left-to-right", exact=8)       /* R2 exactly 8 units to the right of R1 */
```

```rnl
%stage1_set = {#M1 #M2 #M5};
%stage2_set = {#M3 #M4};
%stage1_set %stage2_set @DISTANCE("left-to-right", min=1)     /* all of stage 2 is to the right of all of stage 1 */
```

- `A B @DISTANCE(direction, min=…, max=…)`：A 填入槽位 `from`，B 填入槽位 `to`；兩者各為一個物件或一個集合。
- **方向**：參數 `direction` 為必填，依位置第一個傳入，取值同 ORDER（14.3）。僅約束該座標軸；這不是歐氏距離。
  - 遞增方向（`"left-to-right"`、`"bottom-to-top"`）約束 B − A；
  - 遞減方向（`"right-to-left"`、`"top-to-bottom"`）約束 A − B。
- **集合**：槽位中的集合代表其每個成員（14.1），沒有符號的用例亦同，且該 DISTANCE 對 A 的每個成員到 B 的每個成員皆成立，每對組合各為一條約束；同一物件與自身的配對會被略去。因此 `%stage1_set %stage2_set @DISTANCE("left-to-right", min=1)` 使第 2 級全體皆位於第 1 級全體之右側，不可交錯的兩個集合即以此方式撰寫。當任一側為空集合時沒有任何配對，不產生效果。
- `min`、`max` 與 `exact` 至少須寫出其中之一；`min` 不得大於 `max`。DISTANCE 同時陳述順序：B 在該方向上絕不會排在 A 之前。因此界限不得為負，負的 `min`、`max` 或 `exact` 屬於錯誤參數值，會使該約束失效；未寫出的 `min` 為 0，因此 `max=10` 在距離為 0 至 10 時皆成立。
- `exact=` 為精確距離，是 `min` 與 `max` 相等時的簡寫：遞增方向為 B − A = exact，遞減方向為 A − B = exact。它不得與 `min` 或 `max` 一同寫出：那屬於無效參數，會使該敘述失效。工具以 `exact` 寫出精確距離（4.3）。

### 14.6 訊號流

訊號流（原則 2.4）寫成一般定義的用例；沒有專屬關鍵字。標準套件是否提供此類定義以及使用何種名稱，由標準套件決定（16.3）；以下範例使用標準系列 0.4 的 `$SIGNAL_FLOW`，它命名一條以集合給出的路徑，並可在其前方寫出來源、在其後方寫出負載。它是語義定義：不擺放任何位置。

```rnl
%rc_set = {#R2 #C2} @GROUP;
{#R1 {%rc_set} #M1} @AS $SIGNAL_FLOW                                    /* the signal goes from R1 through the block of R2 and C2 to M1 */
{#:inp #:inn}(source) {#R1 {%rc_set} #M1}(path) #CL(load) @AS $SIGNAL_FLOW   /* from the two inputs of the level to the load CL */
```

- 訊號流是柔性概念：並非所有電路皆有嚴格單向流向。求解器可以將它讀作偏好；若要在繪圖中將各級依序排列，須撰寫 ORDER 或 TABLE（14.3、14.11）。
- 路徑中由多個物件組成的級寫成獨立的 `{…}`，如 `{%rc_set}`。GROUP（11.5）僅使求解器將其視為一個區塊，可以省略。
- 來源與負載各自組成一個無順序之分組，例如差動訊號的兩個輸入。它們可以是實例、結構、該層級的連接埠（如 `#:inp`，6.4）、其他端子或網路。未標記角色時，寫出的物件即為該路徑，如第一行所示。
- 功率流——從電源經過轉換或切換它的各級流向使用它的各部分——以 `$POWER_FLOW` 按相同方式撰寫。

### 14.7 對稱

對稱寫成一般定義的用例。對稱軸僅是一個自由點，無須專屬關鍵字。標準系列 0.4 提供 `$MIRRORED_LAYOUT`（角色為 `left`、`right` 與 `axis`：left 與 right 等高，axis 位於兩者正中央，且 right 朝向為 left 的左右翻轉）以及 `$MIRRORED_VERTICAL_LAYOUT`（角色為 `top`、`bottom` 與 `axis`，為直立旋轉後之相同關係）。這兩種用例自身的點皆位於兩側之間的中心（14.1），因此對用例施加約束即可移動整對物件。如同標準套件中的每個定義，這些約束的優先順序皆為 `"low"`（9.5）。對稱軸是單一物件：當多個器件位於對稱軸上時，須先將它們組成一個用例並採計該用例自身的點（14.1），或指定其中一個器件。

```rnl
%ax = (_, _);
%sym12 = #M1(left) #M2(right) %ax(axis) @AS $MIRRORED_LAYOUT
```

- `$MIRRORED_LAYOUT` 不固定實際朝向：閘極究竟向內或向外仍須在其中一側寫出 ORIENT（14.9）。對於兩側朝向相同的對稱對，須另寫一個不含該 ORIENT-RELATION 的一般定義。

### 14.8 優先順序：PRIORITY

```rnl id=dpl
$DP_LAYOUT = @DEFINE(roles=["in_p", "in_n"]) {
  {?in_p ?in_n} @ALIGN("y", priority="low")                    /* a default layout, the first to give way */
};
%dp2 = #M1(in_p) #M2(in_n) @AS(priority="high") $DP_LAYOUT;     /* this pair keeps the default layout strictly */
#M1 @PLACE(12, 20, priority="high")                             /* fixes the position of M1 */
```

```rnl use=dpl
# @SELECT-USAGE(recursive=true) $DP_LAYOUT => @PRIORITY("disabled")    /* a house-style package turns the default layout off, to apply its own */
```

- **四個值**：`"disabled"`、`"low"`、`"normal"`、`"high"`。未寫出優先順序的事實為 `"normal"`，無論它寫在使用者記錄、套件或定義本體中。
- **分級而非加權**：衝突時先比較優先順序，保留較高者；優先順序相同時，保留較後寫出者（8.5）。約束不會以權重加總。

  附註：若採加權方式，十條低優先順序的約束便可能壓過一條高優先順序的約束，且不同求解器衡量約束違背程度的方式各異。
- **每項保留的事實皆為硬性要求**：`"low"` 的含義是「衝突時最先捨棄」，而非「盡量接近」。無論優先順序為何，求解器都必須滿足每一項保留的事實；實作自身追求圖面美觀的目標僅在滿足所有保留事實的前提下、於語言所有描述之後才進行最佳化。
- **`"disabled"`**：該事實於排序前移除，不交給求解器。這不是失效：該物件依然存在，依賴它的描述不受影響，不給出警告，且較後寫出的優先順序可將其重新開啟。
- **書寫方式**：
  - PLACE、ORIENT、四種原子約束、ORIENT-RELATION、TABLE、ROUTE-NET、ROUTE-OBJECT、UNROUTE-NET、UNROUTE-OBJECT、AS 與 ATTACH 皆接收參數 `priority=`，優先順序隨該事實一併生效。`priority` 是 AS 與 ATTACH 唯一的標準參數；定義自身的參數不得使用此名稱。
  - PRIORITY 敘述事後修改優先順序。它僅接收擁有自身控制代碼的物件：約束、用例，以及帶有 GROUP 的集合（僅限開啟與關閉，11.5）。帶有 GROUP 的集合視為該群組本身；其他任何集合皆逐成員處理（5.2.1）。傳入實例或其他物件會失效（種類錯誤）：`#M1 @PLACE(…) => @PRIORITY(…)` 是錯誤，因為 PLACE 傳遞的是 M1 的控制代碼；請將優先順序寫作 PLACE 的參數。
  - 記錄標頭 `@RNL(priority=…)` 為該記錄中接收此參數且未自行寫出的敘述提供預設值，亦為 TEXT 的 `dx` 與 `dy` 提供預設值（13.3）。對於 AS 與 ATTACH，它僅給予 `"disabled"`，使得停用的記錄連同其用例及定義本體一併關閉，與其他敘述一致。在帶有 `"high"`、`"normal"` 或 `"low"` 的標頭下，用例僅當自身敘述或 PRIORITY 敘述給予優先順序時才擁有該優先順序，否則保留其定義本體原本的優先順序（如同規則所建立者），確保求解器寫出的用例（10.5）與當初產生的用例含義相同。寫在用例上的優先順序仍會覆寫其定義本體（見下文）。
- **覆寫順序**（由低至高）：記錄標頭的預設值；敘述自身的參數；PRIORITY 敘述（多條之中較後者勝出；位於套件中者依 USE-PACKAGE 的位置排序）；外層包圍用例的優先順序；從用例外部透過 `::` 直接寫在某個區域物件上的 PRIORITY 敘述（多條之中較後者勝出）。上述皆未給出時，優先順序為 `"normal"`。
- **用例的優先順序向下傳遞**：用例的優先順序（其自身參數或作用於它的 PRIORITY 敘述）適用於它展開出的所有事實，包含巢狀用例的事實，並覆寫它們自身的優先順序；巢狀時由帶有優先順序的最外層用例決定。若要僅調整內部某一部分，須從外部透過 `::` 直接寫在該區域物件上（9.4）：這比用例的優先順序更具體並將其覆寫——較具體者勝出。寫在外層定義的定義本體中的此類敘述，仍受外層用例優先順序的管轄。記錄中的每條敘述皆可被直接修改，因此記錄標頭僅提供預設值。
  - 完整規則：用例的優先順序管轄其定義本體中所寫的每條 PRIORITY 敘述，使後者不產生效果。從外部透過 `::` 直接寫在某個區域用例上的 PRIORITY 以相同方式管轄：該用例視同帶有優先順序的最外層用例，該敘述決定該用例展開出的一切。在不受任何管轄的敘述中，寫在最內層物件上者勝出；在同一個物件上，寫在建立該物件之定義本體外部者勝過寫在該定義本體內部者；其次較後寫者勝出。
  - 例如，當 `%o1` 被停用、頂層寫有 `%o1::in @PRIORITY("high")`，而 `%o1` 的定義本體中寫有 `%in::row @PRIORITY("low")` 時，`row` 的事實為 `"high"`：定義本體中的敘述受 `%o1` 優先順序管轄，而頂層的敘述為 `in` 覆寫了它。若 `%o1` 未設優先順序，則它們會是 `"low"`，因為該敘述寫在更內層的物件上。若要在兩種情況下皆為 `"low"`，須從外部寫 `%o1::in::row @PRIORITY("low")`。
- **求解器的輸出**：求解器將結果寫成帶有 `"high"` 的 PLACE、ORIENT 等敘述，置於該層級自身文字的最後一筆記錄中，例如 `@RNL(type="generated", priority="high") {…}`。對子電路而言，這位於其 `.subckt … .ends` 內部，即使該子電路位於引入檔案中亦同；對頂層而言，則位於主檔案的檔案層級（第 17 章）。求解器求解時，會在不計入 `type="generated"` 記錄的情況下解譯該層級（2.8），使舊結果不約束下次求解；求解完成後移除舊記錄並於末尾寫入新結果。
  - 在兩次求解之間，與求解器結果衝突的 normal 優先順序新敘述會被捨棄，直到下次求解後才生效。檢視器可依記錄標頭中的雜湊值提示重新求解；此類捨棄無須逐一報告。
  - 在編輯器中拖曳會寫成一條 `"high"` 的 PLACE，同樣位於該層級自身的文字中、求解器記錄之後。這會固定位置：之後每次求解皆將它視作硬性約束。若要解除固定，須刪除該敘述。
- **求解器寫出的內容。** 求解器記錄必須包含所有由求解器決定且原文留空的每個位置、朝向與走線路徑：有名字或 key 的物件依名稱或 key 引用，其餘依編號引用（5.9），連線路徑以 WIRE 寫出（13.1），規則產生的物件則寫成明確敘述（10.5）。未寫入該處的決定不算是結果：該物件保持自由，如同該層級尚未求解一般。如此一來，不進行求解的檢視器便能完全照求解器的結果繪製該層級。求解器不決定它無法引用的事物，例如產生規則直接建立的無 key 文字之位置；這類文字由檢視器擺放（13.3）。規則所建立之用例若無法寫出——例如其定義為套件私有（16.2）、沒有符號也沒有文字，且沒有其他物件或連線依其點定位——其自身的點亦不寫出：這類點僅協助求解器求解，沒有任何繪出事物立於其上，保持自由不會改變任何圖面，亦不算漏寫的決定。
- **求解器的結果即為 RNL。** 當求解器以其他形式將結果傳遞給其他工具（例如求解器與檢視器之間的訊息）時，該形式僅能容納求解器記錄所能容納的內容，以確保每項結果皆能儲存為這類記錄。
- **求解器的目標**僅在滿足每項保留事實的佈局之間進行選擇；每項保留的事實皆為硬性要求，無論其優先順序為何。目標不屬於語言規範：不同求解器的目標種類與順序各不相同，本標準無法為它們定義統一詞彙。僅訂定一項預設：沿途無阻礙且未與其他連線合併的 `"auto"` 連線，須求解為其預設路徑（13.1），先計算轉折點數、再計算長度。求解器選項屬於雜湊值所涵蓋輸入的一部分（第 17 章）；檔案以 SOLVER-CONFIG 保存它們，使結果得以重現（14.10）。

### 14.9 朝向關係：ORIENT-RELATION

```rnl
#M1 #M2 @ORIENT-RELATION("MY");                  /* M2 is drawn as M1 flipped left-right */
#M5 {#M7 #M8} @ORIENT-RELATION("R0");            /* two facts: M7 and M8 each have the orientation of M5 */
#M3 #M4 @ORIENT-RELATION(["R0", "MY"])           /* M4 as M3, or as M3 flipped left-right */
#M1::g #M2::g @ORIENT-RELATION("R180")           /* the gates of M1 and M2 face opposite ways */
```

- `A B @ORIENT-RELATION(relation)`：兩個槽位 `from` 與 `to`，各接收一個物件。關係為 ORIENT 的八種朝向代碼之一（11.2）或它們的列表，依位置傳入。B 的朝向等於 A 的朝向再接續該關係的變換。變換在繪圖座標中進行，因此 `"MY"` 永遠沿垂直線左右翻轉，不論 A 本身是否旋轉。
- **關係列表**（如 `["R0", "MY"]`）構成單一事實，當 A 與 B 之間成立列表中任一關係時即成立。它整體保留或捨棄（8.5），由求解器選擇繪製哪一種關係。列表至少包含一個代碼；僅含一個代碼的列表等同於該代碼。
- **一物件對一物件。** 其中一個槽位傳入集合時，逐成員處理（5.2.1），每個成員各為一項事實：`#M5 {#M7 #M8} @ORIENT-RELATION("R0")` 使 M7 與 M8 各自具有與 M5 相同的朝向，從而三者皆相同。兩個槽位皆傳入超過一位成員的集合屬於錯誤：依序兩兩配對與建立笛卡兒積配對兩種解讀皆有道理（5.2.1）。
- 不存在「單一集合、所有成員朝向相同」的形式：該關鍵字命名的是兩者之間的關係，僅有一個集合時無法明確該關係作用於誰。傳入單一物件不符合簽名，屬於錯誤。單一集合依 5.2.1 先拆開一層，因此 `{#M1 #M2} @ORIENT-RELATION("MY")` 等同 `#M1 #M2 @ORIENT-RELATION("MY")`；若拆開後不是兩個物件，則為錯誤。
- 成員須為具有朝向的物件，與 ORIENT 相同（11.2）：實例、疊畫與帶有符號的用例；或者兩者皆為接腳（見下文），端子代表其接腳（5.2.4）。傳入點、網路、連線或無符號用例屬於錯誤，將接腳關聯至一般物件亦同：該約束失效。若其中一個槽位收到空集合，沒有可建立關係的對象，不產生任何效果（5.2.1）。
- **接腳。** 兩個槽位皆傳入接腳時，該關係成立於兩支接腳在圖面上的方向之間（11.2）：B 的方向為 A 的方向經該關係旋轉後的結果，例如 `"R180"` 表示兩支接腳朝相反方向，而鏡像代碼旋轉方向的方式與旋轉點相同。該關係僅能以朝向代碼撰寫：11.2 的方位詞命名的是方向而非旋轉變換，寫在此處屬於錯誤參數值，會使該約束失效。未寫出 `direction=` 的接腳會使該事實失效（9.2.4）。
- 它是一項約束：建立一個約束物件、可命名、接收 `priority=` 並可用 PRIORITY 修改（14.8）；衝突時作為單一單位保留或捨棄（8.5）。逐成員處理時為每個成員建立一條約束，名稱則綁定它們所組成的集合（5.2.1）。若其中一個成員已有單一代碼的 ORIENT，其朝向已固定；其餘成員由求解器在滿足該關係及其自身 ORIENT 列表（11.2）的朝向之中選擇。
- 它不固定實際朝向：當兩顆 MOS 電晶體互為鏡像時，閘極相向與閘極背向皆滿足 `"MY"`。若要確定，須同時寫出一條 ORIENT，或在端子上寫一條 ORDER（14.3）；若要縮小範圍而不完全定死，則寫出帶列表的 ORIENT（11.2）。

### 14.10 求解器設定：SOLVER-CONFIG

```rnl header
@SOLVER-CONFIG(spacing_x=2, spacing_y=1, layout="lines", lines_weights=[1, 4])    /* the default of the file */
```

```rnl
@SOLVER-CONFIG(spacing_x=1)                                                       /* this level: overrides the key spacing_x */
```

- SOLVER-CONFIG 為求解器提供設定，使檔案得以使用相同設定重新求解。它不建立事實：求解器僅用這些設定在滿足所有保留事實的佈局之間進行選擇（14.8）。
- **形式**：以 RNL 字面量給出的具名參數：數字、字串、`true` 與 `false`，以及這些類型的陣列（3.7）。沒有巢狀設定。除了本標準命名的 key（見下文）之外，其餘 key 不屬於標準詞彙：各求解器自行定義。核心將參數讀作 RNL 字面量並按下述順序原樣傳遞給求解器，且不合併任何一項；對於數值，核心僅檢查本標準所命名 key 的值。求解器判斷其他 key 與數值：不認識的 key 會給出警告並予忽略。求解器亦可僅在其自身的某些設定下接受某個 key，例如其中一種佈局使用而另一種佈局不使用的目標；在不使用該 key 的設定下，該 key 同樣被忽略，並給出警告。
- **本標準命名的 key**：`spacing_x` 與 `spacing_y`，該層級以格點單位計算的間距，加至求解器的預設間距上，與群組相同（11.5）；以及 `junction`，求解器在分支點繪製圓點所用的定義，寫成字串形式的 `$` 名稱，如 `"$JUNCTION"`；在層級記錄的 SOLVER-CONFIG 中亦可寫成 `%` 名稱，於該層級中查找（6.6），使為單一子電路定義的變體僅限該子電路使用；或寫為 `""` 表示不畫圓點（13.2）。每個求解器皆接收 `junction`。本版本僅命名這幾個 key，但不限於求解器只能接收這些 key：求解器還支援哪些 key（如範例中的 `layout` 與 `lines_weights`）及其含義，由各求解器自行決定並寫入其文件。凡支援層級間距的求解器須以這兩個名稱接收。
- **書寫位置**：寫在不帶 `language` 的檔頭記錄中時，作用於該檔案及它引入之檔案的所有層級，與 DEVICE 相同（2.8、6.12）；寫在套件檔案的檔頭記錄中時，作用於使用該套件的層級（16.2）；寫在某層級的記錄中時，作用於該層級。它沒有物件。若寫在套件內容、內嵌套件、帶有 `language` 的記錄或求解器記錄中，則不產生效果並給出警告；因此僅透過帶有 `language` 的檔頭記錄使用的套件不會提供任何設定。
- **順序**：設定逐個 key 覆寫，較後者覆寫較早者：求解器預設值 → 該層級所使用套件的檔頭記錄，依其位置順序（同 DEVICE，6.12）→ 外層檔案的檔頭記錄 → 被引入檔案的檔頭記錄 → 該層級自身的記錄 → 傳給工具的設定（例如命令列參數或檢視器介面中的設定）。工具接收的設定文字格式應與括號內相同，以便雙向複製。
- **不被接受的值**（例如應為數字之處卻給出字串）僅使該 key 出錯（16.4）：該 key 視為在該處未寫出，因此先前的值仍然有效，同一敘述的其他 key 照常套用。值在其所適用的每個層級中分別判斷：檔頭記錄中的 `junction` 若在某個層級未指名任何定義，僅在該層級不被接受，其他層級仍使用它。核心判斷本標準所命名 key 的值，並略去其不接受者；求解器判斷其自身 key 的值。因此求解器收到的設定是依上述順序排列的清單，其中同一 key 可出現多次，對每個 key，求解器取其接受的最後一個值。
- **時間或工作量預算**（8.5）僅由工具提供，例如命令列或檢視器的頁面，絕不由檔案提供：預算取決於求解的機器。求解器中設定預算的 key，如內建求解器的 `limit`、`seconds` 與 `work`，是其工具專用 key：寫在 SOLVER-CONFIG 中（無論在哪種記錄裡），這類 key 會被忽略並給出警告，如同未知 key 一樣，仍然生效的是工具所給的預算或求解器的預設值。
- 某層級實際生效的設定（含套件的設定）屬於求解器雜湊值所涵蓋輸入的一部分（第 17 章）。

### 14.11 佈局表：TABLE

```rnl
@TABLE layout: {
  {#M1 #M2 #M3}
  {#M4 {#M5 #M6} #M7}
}
```

- TABLE 將物件擺放為以巢狀 `{…}` 寫出的表格：範例共有由上而下的兩列；第一列由左而右為 M1、M2 與 M3；第二列由左而右為 M4、M5 與 M6 所在的儲存格，以及 M7；該儲存格內則是 M5 位於 M6 上方。表格可跨越多行撰寫。標準寫法將關鍵字置於最前，讀作「@TABLE layout: {…}」（4.3）；此處的 `layout:` 為自由文字（3.3），TABLE 接收表格的槽位名稱為 `rows`（附錄 A）。
- **解讀方式**：最外層列表由上而下排列，每個項目為一列；巢狀於其中的每個列表皆與容納它的列表成直角方向排列——在由上而下的列表中由左而右排列，在由左而右的列表中則由上而下排列。`transpose=true` 使最外層列表改為由左而右排列。傳給 TABLE 的集合即為照字面寫出的最外層列表，不會先拆開（5.2.1 第 2 項），因此 `@TABLE layout: {{#M1 #M2 #M3}}` 為一列，而 `@TABLE layout: %port_set` 則將該集合的每個項目各自置於獨立的一列。
- **項目**：若項目是物件，它即為一個儲存格；若項目是集合（直接寫在表格中的 `{…}` 或對集合的引用），它即為再往內一層的列表。這是 TABLE 的專屬規則：其中的集合不是代表其每個成員的項目（14.1）。帶有符號繪製的用例依其自身的點自成一個儲存格；沒有符號的用例則是容納其所有成員的一個儲存格（14.1），其中每個成員皆位於下一個項目之前；寫作 `%u::position` 則使其自身的點成為一個儲存格。
- **事實**：TABLE 是單一幾何事實，衝突時整體保留或整體捨棄（8.5）。當表格的每個列表中、前一項目的每個點皆嚴格位於下一項目每個點之前（沿該列表的方向至少早一個座標單位，同 ORDER，14.3）時，該 TABLE 成立。檢查器可將它展開為多個這類順序約束；交給求解器時則將整個表格作為單一項目傳入，連同最外層列表與各內層列表的方向。
- **群組**：整個表格中的所有物件構成一個群組，等同於對該集合套用 `@GROUP`（11.5）；其列與欄並不各自成為獨立群組。
- TABLE 不進行對齊：同一列不要求等高，同一欄也不要求同一 x 座標。若要對齊須寫 ALIGN。單一儲存格不能跨越多列或多欄。
- 表格中的空列表會被略去，其相鄰項目隨即成為彼此相鄰的項目（14.1）。只有單一儲存格的表格自動成立且不建立群組。若同一個物件出現在同一張表格的兩個儲存格中，它將必須排在自己之前，因此該 TABLE 失效；當中有無法定位的成員（如網路或沒有接腳的端子，14.1）時亦同。
- TABLE 接收 `priority=`（14.8）並建立一個約束物件，可為其命名。
