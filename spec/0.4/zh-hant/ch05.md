## 5 物件與敘述

### 5.1 物件

- 每個帶有關鍵字的敘述皆會建立一個新的 RNL 物件，由一個控制代碼與多項事實構成。`{…}` 同樣會建立一個新物件，即集合（5.2）。
- 引用（`#M1`、`&vss`、`%x`、`$X`、端子或子物件）不建立物件；它取得一個既有的控制代碼。取得多個成員的成員位置則會建立一個新集合（5.2.3）。單獨的 `#M1` 也是一條敘述：它給出沒有任何事實的 M1。單獨的 `#` 給出沒有任何事實的本層級。
- 控制代碼即所描述的事物本身：宿主的實例、網路或端子，或本層級；或是由 RNL 建立的點、連線、集合、用例、約束等。控制代碼絕不會是另一個 RNL 物件。
- 敘述所產生的物件，要嘛擁有新的控制代碼（該敘述為建立型，例如 WIRE、圖形、`{…}`、篩選、AS、ATTACH 與約束），要嘛沿用其輸入的控制代碼並為其新增事實（該敘述為修改型，例如 PLACE、ORIENT、SET-SYMBOL、SET-STYLE、GROUP 與 CURRENT；ADD-TO 與 REMOVE-FROM 沿用目標集合的控制代碼）。簽名會標明屬於哪一種（5.3）；WIRE 在接收網路時建立新物件，接收連線時則修改該連線（13.1）。
- 兩條內容相同的敘述是兩個不同的物件，例如兩條 `#M1 @PLACE(1, 2)`。它們的事實互不矛盾，並一起生效。
- 事實在建立它的敘述處提交一次（5.4）。當層級生效時，關於同一個控制代碼的所有事實會合併；矛盾依 1.5 第 3 項處理。
- 屬性即事實：位置、朝向、符號與樣式皆為關於該物件的事實，並沒有可被覆寫的屬性欄位。當層級生效時，關於同一個控制代碼的事實會合併為最終值：PLACE 的 x 與 y 作為幾何事實處理（5.8、8.5），符號與樣式則透過外觀佇列處理（8.3）。
- 控制代碼的種類由其來源決定：宿主物件取自宿主，RNL 物件取自建立它的敘述。簽名說明每個槽位接收哪些種類（附錄 A）；收到錯誤種類物件的描述會失效。凡在讀取文字時即可檢查的項目會於當時檢查；唯有在層級生效時才得知的項目（例如用例是否有符號、定義的角色）則於層級生效時檢查（7.1）。

物件種類：

| 種類 | 建立來源 | 是否繪製 |
|---|---|---|
| 層級 | 宿主；`#` | 否 |
| 實例 | 宿主；`#M1` | 以其符號繪製 |
| 端子 | 宿主；`#M1:d`、`#:inp`（6.4）。用例沒有端子 | 繪製於綁定它的接腳處（9.2.4） |
| 接腳 | 繪製物件所屬符號中的 PIN（9.2.4）；當接腳有名稱時為 `#X1::vdd_t` | 作為符號上的一個點 |
| 網路 | 宿主；`&vss` | 否；連線與標籤是各自獨立的物件 |
| 點 | `(x, y)` | 否；交接圓點是套用至點的 `$JUNCTION`（13.2） |
| 連線 | 接收網路的 WIRE；網路槽位接收集合的連線為匯流排。接收連線的 WIRE 則重寫該連線（13.1） | 是 |
| 標籤 | 附著於物件的 TEXT；帶有 key 時為該物件的子物件 `object::key`（13.3） | 是 |
| 疊畫 | BUNDLE（11.8） | 繪製一次，取代其各成員的位置 |
| 標註（annotation） | 場景中的圖形（LINE、RECTANGLE、CIRCLE、ELLIPSE、ARC、BEZIER）、附著於點的 TEXT（13.4），或由 ANNOTATION 繪製的符號（13.5） | 是 |
| 用例 | AS、ATTACH（9.4） | 僅在擁有符號時繪製；此時即為虛擬組件（第 12 章） |
| 約束 | ALIGN、ORDER、DISTRIBUTE、DISTANCE、ORIENT-RELATION、TABLE（第 14 章） | 否 |
| 集合 | `{…}`、篩選、UNION、逐一產生的結果（5.2、第 10 章） | 本身不繪製；其成員各自繪製 |
| 定義 | DEFINE-SYMBOL、DEFINE-STYLE、DEFINE（第 9 章） | 否；僅於使用時才生效 |

在這些種類中，instance、terminal、pin、net、point、wire、label、bundle、annotation 與 usage 具有種類名稱（5.3），`text` 亦同，涵蓋所有 TEXT（無論是標籤或標註）；其餘種類在簽名中的命名方式見附錄 A。

此外還有子物件（6.5），其控制代碼為父物件加上名稱；以及失效物件（第 7 章）。

### 5.2 集合

- `{…}` 建立一個集合物件。其成員具有順序。集合可以命名（`%pair_set = {#M1 #M2}`），且其他敘述可對具名集合新增或移除成員（5.2.2）。
- 集合會保留重複成員以及書寫順序，例如 `{#M1 #M2 #M3 #M1}`。兩個成員是否為同一成員依控制代碼判定：分開寫的兩個 `{…}` 是兩個不同的控制代碼，即使內容相同也不算同一成員。
- **引用會展開一層**：在集合中引用另一個集合的引用，會將該集合的成員放在原處，因此 `{%a_set %b_set}` 即為 a_set 的成員接續 b_set 的成員。結果為集合的敘述（如篩選）以及下標展開所得的引用列表（如 `&D<7:0>`，6.11）亦同。若要去除重複項，須寫 `%a_set %b_set @UNION`（5.2.2）。
- **直接寫出的 `{…}` 會保留**：直接寫在集合中的 `{…}` 會保留為單一成員，因此 `{{%a_set} {%b_set}}` 是包含兩個集合的集合。
- **散落物件亦會展開**：當僅有一個槽位的關鍵字收到多個不帶大括號寫出的物件時，它們會完全比照寫在 `{…}` 中般組合起來（5.2.1 第 3 項），因此其中的集合會被展開。若已有 `%bias_set = {#R1 #R2 #R3}` 與文字 `%lbl`：
  - `%bias_set %lbl @ALIGN("x")` 等同 `{%bias_set %lbl} @ALIGN("x")`；
  - 集合若為唯一物件則以其自身傳入：`%bias_set @ALIGN("x")` 會對齊 R1、R2 與 R3。
- **項目**：集合亦會依序保留其中書寫的項目：直接寫入的物件、直接寫出的 `{…}`，或對集合的引用。凡本標準計數項目之處（ALIGN、ORDER 與 DISTRIBUTE 的成員列表 14.1、ASSERT-TOPOLOGY 的成員 15.4，以及 5.2.1 第 2 項的拆分），單一物件為一個項目，而作為項目的 `{…}` 或對集合的引用則代表該項目處的所有最內層成員；在 ASSERT-TOPOLOGY 中則代表由它們構成的單一黑盒。ADD-TO 會在末尾新增一個項目，REMOVE-FROM 會從每個項目中移除指定物件（5.2.2）；由篩選、UNION 或逐一產生所建立的集合中每個成員各為一個項目，下標展開所得的列表（6.11）與成員位置所取的集合（5.2.3）亦同。其餘所有場合中，集合一律代表其依前述展開一層後的成員。因此 `{%bias_set %lbl} @ALIGN("x")` 有兩個項目：R1–R3 為第一項，文字為第二項，使 R1、R2 與 R3 各自取得該文字的 x 座標（14.1）。
- 集合的內容於使用它的階段才計算，與篩選相同：其初始內容以及增減成員敘述中的篩選，皆在該階段開始時的狀態上評估，並依書寫順序（其位置，8.5）套用新增與移除。因此寫在較前方的使用處同樣會看到所有新增與移除（1.5 第 1 項），且同一個集合在不同階段的內容可以不同：產生物件的規則看到的是不含產生物件時的集合，樣式規則看到的則是包含它們之後的集合（8.2）。

  附註：不在單一步驟一次性計算內容的原因，在於否則為篩選命名就會改變其結果：`%g_set = # @SELECT-USAGE $GROUND; %g_set @SET-STYLE $grey` 將會漏掉產生的接地，而未命名的同一篩選卻能找到它們；名稱僅是引用物件的另一種方式（1.5 第 5 項）。

#### 5.2.1 物件與槽位

敘述中書寫的物件依以下規則匹配至簽名的槽位：

1. **已標記角色**：標記了角色的物件會整體進入該角色，不作拆分。同一條敘述中，要嘛所有物件皆標記，要嘛全不標記。
2. **先拆分一層**：當未標記角色且整條敘述僅有單一物件、而該物件為集合時，會先將該集合拆開一層，成為其各個項目（5.2）。TABLE 為例外：其槽位直接接收該集合本身，作為表格的外層列表（14.11）。定義以及由管線傳入的結果皆計為物件。因此 `{#M1 #M2} @DISTANCE(…)` 等同 `#M1 #M2 @DISTANCE(…)`，而 `{#M1 #M2} @SET-SYMBOL $X` 則有兩個物件（集合與定義），故不拆分。
3. **依簽名匹配**：
   - 具有多個槽位的關鍵字（定義亦佔一個槽位）：物件數量須等於槽位數量，並依序一對一匹配；否則該敘述失效。對於 AS 與 ATTACH，位於角色列表末尾的集合角色可以不填入物件（9.4）。
   - 具有一個槽位的關鍵字（如 PLACE、ORIENT、ALIGN、ORDER、DISTRIBUTE、GROUP、SELECT-USAGE 與 SELECT-ANCESTOR-USAGE 以外的篩選——此二者亦接收定義 5.6——以及以定義本體為槽位的定義關鍵字）：單一物件直接進入該槽位；多個物件則會組合成一個集合，其中的引用集合會展開一層，而直接寫出的 `{…}` 保留為單一成員。當這些物件是經第 2 項拆開唯一集合所得的項目時，槽位接收該集合本身。
   - 當唯一物件是空集合時：
     - 接收單一物件的槽位會執行零次：什麼都不會發生，也不會失效。名稱照常綁定至該空集合，而使用該名稱的敘述則不做事。
     - 為接收單一物件的槽位直接寫出空集合時會給出警告，例如 `{} @PLACE(1, 2)`。來自篩選或規則的空集合則不給警告：帶有 `recursive=true` 的規則會在下方每個層級各評估一次，某個層級沒有該種類的物件實屬正常。若使用者所寫的篩選在所有評估層級中均未選中任何物件，實作可以給出一條警告；條件可能寫錯了。
     - 接收集合的槽位接受空集合，例如 `@DEFINE(roles=["a"]) {}` 的空定義本體，或無成員的約束（會自動滿足）。例外是 BUNDLE 與 WIRE 的網路槽位：它們須從該集合建立新物件，不能無中生有，因此該敘述失效（11.8、13.1）。
     - 不帶任何物件的敘述（如單獨的 `@PLACE(1, 2)`）不符合簽名，會失效。
4. **槽位中的集合**：
   - 接收單一物件的槽位會對每個成員各作用一次。每個成員各為一項獨立描述，結果為各項結果所成的集合。若某個成員本身又是集合，則再次拆開並逐成員處理。唯一例外是 PRIORITY：當接收標記了 GROUP 的集合時，它作用於該群組本身（11.5、14.8）。
   - 接收集合的槽位會整體接收它，且將單一物件視為只含該物件的集合：`#M3 @ROUTE-OBJECT` 等同 `{#M3} @ROUTE-OBJECT`。
   - DISTANCE 的兩個槽位皆可接收物件或集合；集合代表其每個成員，DISTANCE 會將其中一個槽位的每個成員與另一個槽位的每個成員兩兩建立關聯，每對各產生一條約束（14.5）。這是唯一允許兩個槽位同時接收集合的關鍵字。
   - 在同一條敘述中，至多只能有一個接收單一物件的槽位收到多於一個成員的集合。若超過一個這類槽位如此，該敘述失效：因為依序配對與取所有組合皆言之成理，含義便不唯一。

| 寫法 | 結果 |
|---|---|
| `{#M1 #M2} @SET-SYMBOL $X` | 兩個物件，不拆分。實例槽位收到集合：M1 與 M2 各自取得該符號 |
| `#M1 #M2 @SET-SYMBOL $X` | 兩個槽位卻有三個物件：該敘述失效 |
| `{#M1 #M2} @DISTANCE(…)`、`%pair_set @DISTANCE(…)` | 唯一物件是集合，予以拆分：從 M1 到 M2 |
| `%a_set %b_set @DISTANCE(…)` | 兩個物件，各自為集合：從 a_set 的每個成員到 b_set 的每個成員（14.5） |
| `{#M1 #M2} @ALIGN("y")`、`#M1 #M2 @ALIGN("y")` | ALIGN 只有一個槽位，接收 {M1 M2} |
| `%bias_set %lbl @ALIGN("x")`，其中 `%bias_set = {#R1 #R2 #R3}` | 散落物件組合成 `{%bias_set %lbl}`：兩個項目，R1–R3 為第一項，文字為第二項；R1、R2 與 R3 各自取得該文字的 x 座標（14.1） |
| `{%bias_set} %lbl @ALIGN("x")` | 同樣的兩個項目：R1、R2 與 R3 各自取得該文字的 x 座標 |
| `{%bias_set} @ALIGN("x")`、`{{#M1 #M2 #M3}} @ALIGN("y")` | 唯一物件是集合，拆開一層成為其唯一的項目（第 2 項）；該項目本身是個集合，原樣進入槽位：對齊 R1、R2 與 R3，或對齊 M1、M2 與 M3 |
| `%pair_set @PLACE(10, 20)` | 槽位直接接收 pair_set 並逐成員放置：兩個成員皆位於 (10, 20)。集合本身沒有位置（14.1） |
| `%a_set %b_set @PRIORITY("disabled")`，兩者皆為帶 GROUP 的集合 | 散落物件依 `{…}` 規則展開：PRIORITY 收到個別成員，因種類錯誤而失效。若要關閉兩個群組，須各寫一條 PRIORITY（11.5、14.8） |
| `{#M1 #M2} @SET-SYMBOL $X => @ALIGN("y")` | 管線的結果作為唯一物件傳入 ALIGN：對齊 M1 與 M2 |
| `{#M1 #M2} @SET-SYMBOL $X => #M3 @DISTANCE(…)` | 兩個物件，不拆分。槽位 `from` 收到集合：從 M1 到 M3 與從 M2 到 M3（14.5） |
| `# @SELECT-NET(…) => $PULL_DOWN @ATTACH &vss` | 三個槽位對應三個物件（兩個角色與定義）。第一個角色為單一角色，因此會對每個選出的網路套用一次該定義，且每次的第二個角色皆為 vss |
| `# @SELECT-INSTANCE(type="nmos") => @ORIENT("MY")` | 逐一鏡像；若無 NMOS 則執行零次，什麼都不會發生 |
| `# @SELECT-INSTANCE(name="Q*") => @SET-SYMBOL $NPN` | 兩個物件，不拆分；若無 BJT 則執行零次，什麼都不會發生 |
| `#R1 {#R2 #R3} #R4 @AS $CHAIN_ROW` | 四個槽位對應四個物件（三個角色與定義）；集合角色 `chain` 收到 {R2 R3}（9.4） |
| `&D<7:0> @WIRE {…}` | 兩個物件，不拆分。網路槽位整體接收網路列表：構成一條匯流排（13.1） |
| `#XI0<3:0> @ALIGN("y")` | 唯一物件是下標展開而成的列表，予以拆分：對齊這四個實例（6.11） |

- 成員過少的約束自動滿足且不會失效，例如僅有一個成員的 ALIGN（第 14 章）。
- 集合本身沒有位置（14.1）；其 `::position` 是各成員位置的集合（6.5）。約束中沒有符號的用例代表其成員（14.1）。若要將一組物件作為單一位置與其他物件建立關係，可將它們作為一個用例的成員，在其定義本體中將它們繫於該用例自身的點（9.4），再對 `%u::position` 施加約束；若要讓集合整體維持在其他物件的一側，可將其傳給 DISTANCE（14.5）。
- 定義的角色分為單一角色或集合角色（9.4）。在角色列表中寫作 `"{name}"` 的是集合角色，整體接收集合；其餘皆為單一角色，收到集合時會對每個成員各套用一次該定義。

#### 5.2.2 新增與移除成員，以及重複項

- `X @ADD-TO S` 將 X 附加至集合 S 末尾（當 X 為集合時附加其成員）；`X @REMOVE-FROM S` 從 S 中移除這些成員的所有出現位置。目標寫在最後，以便透過管線傳入篩選結果：`# @SELECT-NET(name="vss") => @ADD-TO %gnd_set`。
- 目標須為集合，不會自動包裝為集合。在 `%tail = #M5` 之後，`#M3 @ADD-TO %tail` 會失效，因為 M5 不是集合。
- 新增與移除依位置順序套用（1.5 第 2 項）。在某層級評估的集合僅包含該層級的成員（10.3）。
- `%a_set %b_set @UNION` 建立一個不重複的新集合，依首次出現的順序排列；兩個成員是否相同依控制代碼判定。
- 若要建立新集合而不改動舊集合：串接為 `{%a_set %b_set}`；聯集為 `%a_set %b_set @UNION`；差集為 `%c_set = {%a_set}; %b_set @REMOVE-FROM %c_set`。
- 集合依賴於建立它的敘述中所寫的集合（其大括號內、UNION 中，或作為篩選的作用域），以及 ADD-TO 與 REMOVE-FROM 對它進行增減時所使用的集合。形成循環的依賴關係為錯誤（無論是否包含移除操作）：依位置順序檢視各敘述（8.5），使循環閉合的那條敘述失效，其診斷會列出整個循環；其餘敘述照常生效。因此 `%a_set @ADD-TO %b_set; %b_set @ADD-TO %a_set` 在第二條敘述失效，而 `%b_set = {%a_set}; %b_set @REMOVE-FROM %a_set` 因移除結果無確定含義，在移除處失效。

#### 5.2.3 成員位置

```rnl
%row_set = {#M1 #M2 #M3 #M4};
%row_set{1} @PLACE(0, 0);                                         /* M1 */
%row_set{1} %row_set{end} @DISTANCE("left-to-right", exact=12);   /* from M1 to M4 */
%row_set{2:end} @ALIGN("y")                                       /* M2, M3 and M4 */
```

- 對集合的引用後方緊接 `{…}` 可依位置取得集合成員，例如 `%a{1}`、`%a{end}`、`%a{end-1}` 與 `%a{2:end}`。此寫法用於綁定至集合的 `%` 與 `$` 名稱之後，以及一般定義的定義本體中集合角色的佔位符之後，例如 `?ref{1}`（9.4）。
- **形式**：大括號內為以 `,` 分隔的項目；每項為 `i`、`a:b` 或 `a:b:s`，各形式可混用，如同下標（6.11）。位置可為正整數、`end` 或 `end-k`，其中 k 為無號整數；s 為大於或等於 1 的無號整數。大括號內允許空白字元與註解。
- **計數**：在集合完成所有新增與移除（5.2）——包括寫在該引用之後的新增與移除——之後，依成員順序從 1 開始計數，故在 `%a = {#M1}; #M2 @ADD-TO %a` 之後 `%a{2}` 是 M2；依 5.2 所述成員會展開一層，而非依項目計數：在 `%a = {%b_set %lbl}` 之後，`%a{2}` 是 b_set 的第二個成員，或在 b_set 僅有一名成員時為該文字。`end` 為最後一個成員。各項目依書寫順序展開並串接；重複項予以保留。`a:b` 從 a 到 b（當 a 大於 b 時反向遞減），`a:b:s` 則以步長 s 前進且不超過 b。
- **單一成員或集合**：若僅有一項且為單一位置，則回傳該成員本身。其他情況皆回傳一個由該等位置成員依序構成的新集合：這是一個新的集合物件，也是引用會建立物件的唯一情況（5.1）。若某成員本身為集合（直接寫出的 `{…}`，5.2），則原樣取出。
- **超出成員範圍**：集合中不存在的位置不取出任何內容：單一位置寫成這樣會得到空集合，在列表中則略過該項。這不算錯誤，因為撰寫敘述時未必知道集合共有多少成員（如單成員 ALIGN，14.2）。
- **僅限位置**：緊接在引用後的大括號僅能容納位置。`%a{#b}` 是語法錯誤；若要在引用後接著寫集合，須以空白字元隔開，如 `%a {#b}`（3.5）。
- **錯誤**：
  - 對非集合的物件（如實例）取位置會失效（種類錯誤）。
  - 用例不是集合：其成員依角色取得，例如 `%dp1::left`（6.5），對用例寫成員位置為錯誤。
  - 對篩選結果取位置為錯誤（無論篩選直接寫於該處或綁定於該名稱），對透過項目、UNION、ADD-TO 或 REMOVE-FROM 依賴篩選的任何集合取位置亦然（10.4），例如當 `%s` 為篩選時在 `%a = {%s}` 之後寫 `%a{1}`：因為它們的成員僅在使用它們的階段進行評估時才得知（5.2、8.2）。

#### 5.2.4 以物件代入另一種類

當槽位接收某一種而收到另一種類的物件時，僅依下表進行轉換；任何其他不匹配在讀取文字時即為種類錯誤（5.1、7.1），不論語義上看似如何。物件僅往「無須選擇即可唯一代表的目標」轉換：往繪圖方向，從端子到其接腳再進而到點，以及從繪製物件到其位置；往電路方向，從接腳到它綁定的端子，以及從接腳或端子到其網路。其餘情況皆須寫出子物件（`::position`，6.5）或篩選（10.1）。

| 傳入 \ 槽位接收 | 點（圖形） | 點或接腳（連線） | 位置（約束成員） | 接腳 | 端子 | 網路 |
|---|---|---|---|---|---|---|
| 點 | = | = | = | 否 | 否 | 否 |
| 接腳 | 1 | = | 1 | = | 8 | 9 |
| 端子 | 2 | 3 | 2 | 3 | = | 10 |
| 實例、疊畫 | 否 | 否 | 4 | 否 | 否 | 否 |
| 用例 | 否 | 否 | 5 | 否 | 否 | 否 |
| 文字 | 否 | 否 | 6 | 否 | 否 | 否 |
| 以中心寫出的圖形 | 否 | 否 | 7 | 否 | 否 | 否 |
| 其他圖形、連線 | 否 | 否 | 否 | 否 | 否 | 否 |
| 網路 | 否 | 否 | 否 | 否 | 否 | = |

「=」為相同種類；「否」為種類錯誤；數字對應下方轉換規則。涉及接腳的轉換需要物件的符號，因此會在賦予符號之後進行（8.2）；在此之前的步驟看到的仍是原樣寫出的物件。若槽位或角色接收單一物件，但此類轉換的結果卻是一個集合（例如由匯流排接腳轉換而來），該敘述會在該項檢查時失效（7.1）：該敘述建立時只接收單一物件，之後不會再行拆分。接收接腳的連線終止於該接腳並與之相接（10.2、13.1），並非僅取該接腳的座標。

1. **接腳轉點或位置**：該接腳的位置。
2. **端子轉點或位置**：其接腳的位置，同第 3 項。
3. **端子轉接腳**：該物件符號中綁定該端子的接腳（9.2.4）。若無此接腳則敘述失效（9.2.4）；若有多個，則為符號中最後寫出的那一個。對於疊畫的端子，則為疊畫符號的接腳（11.8）。
4. **實例或疊畫轉位置**：其原點 `::position`（6.5）。實例不會轉換為連線或圖形的點：若要在原點結束連線或繪製圖形，須寫 `#M1::position`。
5. **用例轉位置**：其自身的點（14.1）。用例不會轉換為連線或圖形的點：若要在其點處結束連線或繪製圖形，須寫 `%u::position`（6.5）。
6. **文字轉位置**：文字自身的位置（13.3）。
7. **以中心寫出的圖形轉位置**：其中心（13.4）。以兩點寫出的圖形、LINE、ARC 與 BEZIER 擁有多個點，故不進行轉換。
8. **接腳轉端子**：該接腳綁定的端子（9.2.4）；對於匯流排接腳，則為其端子的集合。不綁定任何端子的接腳（如用例的接腳或僅供繪圖的接腳）沒有對應端子，該敘述失效。
9. **接腳轉網路**：其 `::net`（6.5），即它所綁定端子的網路或填入它所綁定角色的網路；對於匯流排接腳，則為這些網路的集合。不綁定任何事物的接腳沒有對應網路，該敘述失效。
10. **端子轉網路**：其 `::net`（6.5）；對於成員位於不同網路上的疊畫端子，則為這些網路的集合（11.8）。

- PLACE 僅接收 11.1 列出的物件：端子或接腳僅隨所屬物件移動，不得單獨擺放（14.1）。
- 集合不進行轉換：接收單一物件的槽位會對每個成員分別運作（5.2.1），而在約束中，填入集合的位置代表其中的每個成員（14.1）。
- 空節點，即單獨的 `&`（6.3），亦不轉換：種類為 `"net"` 的角色與 WIRE 的網路槽位原樣接收它，其餘所有接收網路的位置皆視之為空網路集合。
- 網路不轉換為任何其他種類：它沒有位置、沒有接腳，也不代表單一端子。物件亦不會轉換為另一個種類的多個物件：實例不會自動變成其端子。此類需求須寫出篩選，如 `#M1 @SELECT-TERMINAL` 或 `&en @SELECT-PIN`（10.1）。
- 不屬於轉換而於他處說明者：TEXT 所附著的對象（13.3）、篩選的作用域如何引出所選種類（10.1），以及接收連線的 WIRE（13.1）。

### 5.3 敘述與簽名

- 一條敘述由至多一個關鍵字、若干物件與一個參數列表構成。
- 每個關鍵字皆有一個簽名，宣告以下內容：
  - 物件數量、每個槽位的名稱與所接收的物件種類。對於 AS 與 ATTACH，物件數量為該定義的角色列表長度加上定義本身所佔的 1 個位置（AS 寫在最後，ATTACH 寫在最前），而各種類即角色所宣告的種類（9.4）；
  - 參數：名稱、類型、是否必填、允許的值，以及可依位置傳入的順序；
  - 輸出：新物件、沿用輸入的控制代碼、子物件、定義或無控制代碼；WIRE 在接收網路時給出新連線，接收連線時給出傳入的該連線（13.1）；
  - 每個輸入的消耗方式（5.4），以及對失效採嚴格或容錯處理（7.3）；
  - 該關鍵字可寫於何處（見下方詞彙表）。
- 物件數量固定；數量可變的物件須以集合傳入。沒有可選槽位，唯有以下例外：AS 與 ATTACH 未填入的集合角色視為空集合（9.4）；SELECT-USAGE 的定義可省略（10.1）；USE-PACKAGE 的定義本體可省略（16.2）。定義亦佔用一個槽位。
- 物件依角色或依順序匹配至槽位，全部標記或全不標記；每個角色僅可標記一次。由管線傳入的物件填入第一個物件位置；AS 與 ATTACH 依角色進行匹配，且該物件不會填入定義槽位（5.5）。物件如何匹配至槽位見 5.2.1。
- 敘述中書寫的物件皆可標記角色，無論使用何種關鍵字。角色名稱即為簽名中的槽位名稱：`#M5:3(to) #M1:3(from) @DISTANCE("left-to-right", min=1)` 即為依序寫出的 `#M1:3 #M5:3 @DISTANCE("left-to-right", min=1)`。不屬於該關鍵字槽位名稱的角色名稱會使敘述失效，不會被忽略（原則 2.3、2.8）。僅有一個槽位的關鍵字的物件亦可標記角色，但標記與否並無差別。
- AS 與 ATTACH 的參數為該定義參數列表中的參數（9.4）再加上一個標準參數 `priority`（14.8）；定義本身不得有名為 `priority` 的參數。
- **標準詞彙表**：每個語言版本皆發布一份機器可讀的標準詞彙表，作為本標準的一部分。每個關鍵字接收什麼以及有哪些參數僅在該詞彙表中給出；正文則說明其含義。附錄 A 由該詞彙表產生，兩者若有衝突則為勘誤。解譯器的檢查、文件、編輯器自動補全、相容性測試骨架與供大型語言模型使用的撰寫參考，皆由該詞彙表產生。對於 0.4 版，詞彙表以 `rnl-words-0.4.json` 發布。
  - 該詞彙表收錄所有標準詞彙：關鍵字及其簽名、槽位名稱、參數名稱與值、記錄標頭欄位、種類名稱、子物件名稱、`${…}` 讀取的屬性名稱、樣式屬性，以及 `true` 與 `false`。別名（16.5）是針對詞彙表中的詞彙宣告的，版本檢查與最接近名稱建議亦在其中查詢。
  - 該詞彙表是一份 JSON 檔案，而 JSON Schema `rnl-words-0.4.schema.json` 描述詞彙表本身的結構。讀寫它的是工具與本標準維護者，而非撰寫電路者。每個詞彙皆帶有 `since`，即新增它的版本；保留字亦有標記（0.4 版未保留任何關鍵字）。詞彙表在 `removed` 下列出較早版本存在而本版本不再保留的標準詞彙，並註明取代說明所在的章節，以便診斷給予提示。不在檔案所宣告版本中的詞彙視同未知詞彙，診斷會說明所需的版本（16.1）。
  - 詞彙表對每個關鍵字記錄：
    - 每個槽位：名稱、接收的種類、接收單一物件或集合（5.2.1）、消耗方式（5.4，這決定其嚴格或容錯性 7.3）；定義的槽位；對 AS 與 ATTACH 而言，槽位依定義的角色列表排列；
    - 每個參數：名稱、類型（數字、字串、真假值，或帶有元素類型的陣列；若值固定則列出所有值）、是否必填、預設值、可依位置傳入的參數順序（其餘僅限依名稱傳入），以及組合條件（例如 PLACE 至少須有 `x` 與 `y` 之一，或 RECTANGLE 的中心形式與兩角形式僅能擇一）；
    - 輸出：新物件及其種類、沿用輸入、沿用目標（ADD-TO）、定義、子物件（帶 `key=` 的 TEXT）或無輸出；對 WIRE 而言，亦包含接收連線時其所重寫的物件種類（13.1）；
    - 可寫於何處：在層級中；僅在符號定義本體中（PIN）；僅在檔頭記錄中（如 VERSION、ALIAS、DEVICE）；僅在套件檔案的檔頭記錄中（PACKAGE）；
    - 其事實如何被覆寫（5.8）：依 key（含該 key）、作為幾何事實（8.5）、透過外觀佇列（8.3），或累積疊加；
    - 其標準寫法與標準例句（4.3、4.5、附錄 B）；
    - 一行簡述與正文對應章節。

- **內建關鍵字的槽位名稱**：每個槽位皆有名稱，即可標記的角色名稱。槽位名稱屬於標準詞彙並與關鍵字一同受版本控管：重新命名槽位屬於不相容變更；同一關鍵字的各槽位名稱彼此相異。定義槽位亦有名稱，用於詞彙表與診斷中，但不得標記（4.2 第 7 項）。簽名與定義的角色宣告（9.4）共用同一組種類名稱：`instance`、`terminal`、`pin`、`net`、`point`、`wire`、`usage`、`bundle`、`text`、`annotation` 與 `label`（附錄 A）。

### 5.4 消耗輸入的方式

| 方式 | 關鍵字 | 輸入的事實 | 失效處理（預設） | 名稱 |
|---|---|---|---|---|
| 吸收（absorb） | 多數關鍵字 | 帶往輸出 | 嚴格 | 巢狀集合中的名稱僅在該集合內有效 |
| 封裝（enclose） | DEFINE、DEFINE-SYMBOL、DEFINE-STYLE | 成為定義的內容，不向下傳遞 | 容錯 | 區域性；每次套用時重新命名，使每個用例各有自己的一份（9.4） |
| 提交（commit） | 記錄、`@RNL` | 依序併入層級 | 容錯 | 發布至該層級並為所有記錄共享；可在綁定前使用 |

- 一個成員產生的結果是其所有段以及巢狀集合建立的所有事實，不僅限於末尾的控制代碼。它們隨包含它們的頂層成員一同提交。
- 記錄中的每條敘述無論是否命名皆會提交。提交後的作用取決於物件本身：場景中的描述會被繪製或參與求解；定義變為可用，本身不繪製任何東西；引用以及僅由引用構成的集合不產生效果。普通 `{…}` 中的敘述會隨包含它的成員一同提交，因此 `{ @LINE {…}}` 中的線段會被繪製（13.4）。
- 定義的定義本體中的敘述不會提交；它們成為定義的內容。一般定義僅在被套用時才展開（9.4）。
- 帶有定義本體的 USE-PACKAGE 同樣以封裝方式取得該定義本體：本體中的敘述成為套件內容，不提交至層級。套件名稱的可見範圍見 16.2。

### 5.5 管線與巢狀

- `a => @K(…)` 使 `a` 的結果成為 K 的第一個物件；AS 與 ATTACH 會將其放入第一個角色，而非定義槽位。若結果為集合，它仍是一個物件（5.2.1）。`=>` 之後的段僅依位置接收此物件，不得為其標記角色。
- 管線並非逐步「執行」。它會展開為多項以控制代碼相連的描述：每段描述前一段所產生的控制代碼，而逐成員運作的段則展開為一組平行描述（1.5 第 1 項）。
- **段的順序。** 每段各有其書寫位置，凡書寫位置有所影響之處（1.5 第 2 項），較後段皆視同寫於較前段之後：包括依 key 覆寫（8.4）、外觀佇列（8.3）、衝突解析順序（8.5）、繪圖順序（11.6）以及連線重寫（13.1）。因此在 `#M1 @SET-SYMBOL $A => @SET-SYMBOL $B` 中，M1 以 `$B` 繪製。
- **失效僅波及依賴它的描述。** 描述失效僅有兩種可能原因：本身無法理解或自相矛盾；或是它使用的控制代碼應由一條已失效的描述建立卻未建立。
  - 在 `$GROUND @ATTACH &vss => @PLACE("20", 38) => @ORIENT("R90") => %g1` 中，僅 PLACE 失效（PLACE 接收數字卻傳入字串，5.3）；接地依然建立，且 ORIENT 依然生效。
  - 在 `#XI0<3:0> @BUNDLE(bad=1) => @PLACE(10, 20) => %s` 中，疊畫未建立（BUNDLE 沒有參數 `bad`），因此 PLACE 沒有可描述的物件而連帶失效。
- 名稱所綁定的對象：開頭的 `%x =` 綁定整條管線的最後一個控制代碼；`=> %x` 綁定其左側那一段的結果，寫於末尾時即為最後一個控制代碼，寫於中間時即為該段的結果，如 `#M1 @AS $A => %a => @AS $B => %b`。PLACE、ORIENT、SET-SYMBOL、SET-STYLE 與 GROUP 沿用輸入的控制代碼，因此在 `$GROUND @ATTACH &vss => @PLACE(24, 38) => %g0` 中，名稱 `%g0` 即此套用所產生的用例，亦即這個接地。AS 與 ATTACH 則建立新的控制代碼：`#M1 @AS $A => @AS $B` 的第二段是將 `$B` 套用至第一段建立的用例（巢狀套用），而非 M1。若要對 M1 套用兩個定義，須寫兩條敘述。當名稱左側的段失效時：若該段原本會沿用輸入的控制代碼，該名稱仍指向該控制代碼（上例中的 `%g1` 即為該接地）；若該段原本會建立新物件，該名稱便指向失效物件（上例中的 `%s`）。
- 物件可寫為內含敘述的集合（巢狀）。巢狀集合中綁定的名稱僅在該集合內有效。每條巢狀敘述各自為獨立描述：在 `{%a = #M1 @PLACE(1, 2); #M9} @ALIGN("y")` 中，若宿主沒有 M9，ALIGN 會失效，但 M1 的座標依然生效。
- 標準寫法將敘述扁平撰寫：先為物件命名，再於其他敘述中引用它。單一敘述以開頭 `%x =` 命名，管線則以 `=> %x` 命名（4.3）。

### 5.6 作為物件的定義

使用定義的關鍵字會將定義作為其物件之一接收，並由關鍵字固定哪個槽位容納該定義：對 ATTACH 而言是寫在最前面的第一個物件；對 SET-SYMBOL、SET-STYLE、AS、SELECT-USAGE 與 SELECT-ANCESTOR-USAGE 而言是最後一個物件，而 SELECT-USAGE 可以省略它（10.1）。

```rnl
%ax = (_, _);
%w13 = &x @WIRE {#M1:1 #M3:1};
#M1 @SET-SYMBOL $NMOS;
%w13 @SET-STYLE $signal;
#M1(left) #M2(right) %ax(axis) @AS $MIRRORED_LAYOUT;
$GROUND @ATTACH &vss;
# @SELECT-USAGE $GROUND => @SET-SYMBOL $GROUND_SYMBOL
```

- 定義不標記角色，且不計入「全部標記或全不標記」。它是一個物件並佔用一個槽位，故 `{#M1 #M2} @SET-SYMBOL $X` 為兩個物件（5.2.1）。
- 由於關鍵字固定了定義的槽位，剖析敘述時無須事先知道 `$` 名稱指向定義還是集合：在 `$GROUND_STUB @ATTACH $GROUND_FILL_SET` 中，前者是定義，後者是集合。
- 定義不得由管線傳入：管線傳入的物件會填入第一個槽位，而 AS 與 ATTACH 會將其依角色匹配，位於定義槽位之外（5.5）。因此 `$GROUND @ATTACH &vss` 不能寫作 `$GROUND => @ATTACH &vss`。
- 定義可以是巢狀的匿名定義：`#M1 @SET-SYMBOL { @DEFINE-SYMBOL {…}}`。
- 一般定義可能寫在較後方或其他層級中，因此 AS 與 ATTACH 的物件數量、角色名稱與參數會在層級生效時才檢查（7.1）。

### 5.7 控制代碼與名稱

- 宿主給出宿主物件的控制代碼：實例名稱與網路名稱。端子為實例加上端子編號，因此 `#M1:1` 與 `#M1:d` 是同一個端子。
- 對於 RNL 建立的內容，控制代碼來自建立它的敘述。另一條敘述唯有透過名稱才能引用它：名稱是找到它的唯一途徑，唯獨求解器的記錄除外——它透過編號引用沒有名稱的物件（5.9）。沒有名稱的物件其餘時候僅能於自身敘述內部使用（透過管線或巢狀）。
- 一個名稱絕不指向兩個事物：它在一個層級內僅綁定一次（6.6）。
- 子物件的控制代碼是其父物件加上自身名稱；它本身不需要額外命名。
- 展開一般定義所建立之區域物件的控制代碼，是其用例加上區域名稱，從外部寫作 `%c1::mid`（9.4）。未命名用例的區域物件在診斷中僅依其位置顯示；唯有求解器記錄能透過該用例的編號引用它們，例如 `%#5::mid`（5.9）。
- 產生集合中的單一物件沒有名稱且無法單獨引用：物件並不由其種類與所關聯的物件來識別（沒有天然鍵），而集合也不提供依索引引用。

### 5.8 事實的 key

- 帶有 key 的事實會依 key 覆寫：同一個 key 由較後寫的事實生效；當較後者失效時，保留較早的有效值。
- 幾何事實是例外：PLACE 的 x 與 y（每個座標各有一個 key）以及 ORIENT（每個物件一個 key，且每個接腳一個 key，11.2）。對同一個 key 寫入兩個不同值會產生衝突並依 8.5 取捨：優先順序相同時保留較後者，結果與依 key 覆寫相同；優先順序不同時保留較高者。PLACE 僅修改它給出的座標；未給出的座標保持自由。
- 用已綁定的名稱建立物件並非依 key 覆寫：名稱在一個層級內僅綁定一次（6.6）。若要修改 RNL 建立的物件，須寫一條修改它的敘述，例如 `%g0 @PLACE(40, 38)`。
- 沒有 key 的事實會累積疊加：互不矛盾者共同成立，發生衝突者依 8.5 取捨。
- SET-SYMBOL 與 SET-STYLE 不依 key 覆寫；它們透過外觀佇列生效（8.3）。
- VERSION 與 PACKAGE 僅能於檔頭記錄中寫一次（16.1、16.2），故從不覆寫：寫出第二條是錯誤，該條失效，由第一條生效。
- CURRENT 對每個端子各有一個 key（15.2），LAYER 則對每個物件各有一個 key（11.6）。
- 用例沒有 key：多次套用同一定義會建立多個用例，彼此不會覆寫。兩次相同的套用建立兩個用例，故寫兩次 `$GROUND @ATTACH &vss` 會繪製兩個接地。至於在單一用例上以修改型敘述（如 PLACE）寫入的事實則具有 key，依上述規則處理。
- 物件的優先順序是帶有 key 的事實；優先順序彼此覆寫的順序見 14.8。
- 帶有 key（`key=`）的 TEXT 對每個附著物件與每個 key 而言為同一段文字，較後者會逐參數覆寫較前者（13.3）。不帶 key 的 TEXT 不依 key 覆寫：每多寫一條就多一段文字（13.3）。
- 連線沒有 key：寫兩次就是兩條連線（13.1）。接收連線的 WIRE 會重寫該連線；重寫帶有 key（即該連線本身），故較後的重寫會取代較早的重寫（13.1）。
- 約束沒有 key。若要更改約束，須將其停用（`"disabled"`，14.8）並寫一條新約束，或直接編輯文字。

### 5.9 無名物件的編號

```spice fragment
* @RNL(type="header") { @VERSION("0.4"); @USE-PACKAGE(name="rnl-std-all", version="0.4")}
.model nch nmos level=1
.subckt amp in out vdd vss
M1 out in vss vss nch
R1 vdd out 10k
* @RNL {
*   #M1 #R1 @ALIGN("x");
*   &out @WIRE {#M1:1 (_, _) #R1:2};         /* %#1: the wire; %#2: the free point */
*   {#M1 #R1} @TEXT("${name}")               /* %#3: the label of M1; %#4: that of R1 */
* }
* @RNL(type="generated", priority="high", author="rnl-solver 0.1", hash="sig1:…", numbering="…") {
*   #M1 @PLACE(10, 0); #R1 @PLACE(10, 8);
*   %#2 @PLACE(12, 4);
*   %#1 @WIRE(mode="straight") {#M1:1 (12, 2) %#2 (12, 6) #R1:2};
*   %#3 @PLACE(13, 1); %#4 @PLACE(13, 9)
* }
.ends amp
```

- 求解器記錄透過編號引用無法以名稱觸及的物件，以便寫回每項決定（14.8）。編號寫作 `%#` 後接無號整數，例如 `%#3`，其使用方式與名稱相同：`%#5::pin` 是用例 `%#5` 之符號的接腳，而 `%#5::mid` 是其區域物件之一。編號僅用於引用其物件，不像名稱那樣可供綁定，故 `%#3 = …` 與 `=> %#3` 皆為語法錯誤（4.1）。
- **哪些物件有編號。** 凡沒有自身名稱且無法從具有名稱或編號的物件透過 `::` 觸及的點、連線、標籤、疊畫、標註與用例（6.5、9.4）。僅在巢狀集合中綁定的名稱（6.7）不計入，因為求解器記錄無法使用該名稱。對於單一求解器記錄，物件依以下順序編號：
  1. 該層級所有手寫記錄（`type="authored"`，2.8）的成員所建立的物件，以及這些成員所建立的用例定義本體內的物件。它們在求解器所見的層級上計數——亦即不包含 `type="generated"` 記錄（2.8）——且當層級連同這些記錄一起解譯時仍保留其編號；
  2. 該記錄自身成員所建立的物件，以及它們所建立的用例定義本體內的物件。它們依該記錄所寫的內容計數，視同其中的每個編號皆能解析；下方檢查碼是否相符不影響其編號。

  約束與集合不予編號。規則逐一產生的物件（10.5）亦不編號：求解器會將它們寫為明確敘述，因而歸入第 2 項。每筆求解器記錄各有其編號：第 1 項對所有記錄皆相同，而第 2 項僅計數該記錄自身的成員。
- **順序。** 手寫記錄依 2.6 的順序取用：先取層級自身的文字，再取從外部以 `scope` 寫入該層級的記錄。在同一成員內，物件依建立它的記號順序編號：點為 `(`，其餘為關鍵字。當單一記號為集合的每個成員各建立一個物件時（5.2.1），每個物件各自獲得一個編號，依集合成員順序排列。用例定義本體內的物件緊接在該用例之後依定義本體順序編號，並如此逐層向下計入巢狀用例。編號從 1 開始。
- **使用位置。** 編號僅得寫在帶有 `numbering` 欄位且無 `scope` 的 `type="generated"` 記錄中（2.6、2.8）。寫在其他任何地方皆為錯誤：手寫記錄須以名稱引用物件。在其所屬記錄之內，編號可在建立該物件的成員之前使用，如同名稱一樣（6.7）。
- **檢查碼。** `numbering` 存放一份關於無名物件如何建立的檢查碼。依序對每個編號產生一行：
  - 建立該物件之記錄成員或定義本體成員的記號，包含其所有段（4.1），不含自由文字與註解，各記號間以一個空格分隔。此處的記號指詞法單元：關鍵字；引用（含其端子、子物件與下標，中間不留空白）；依原樣書寫的字串或數字；名稱；`_`；或 `{ } ( ) [ ] , = ; =>` 之一，或成員位置的一部分（`:`、`end`、`-`，5.2.3）。因此 `&out @WIRE {#M1:1 (_, _) #R1:2}` 給出 `&out @WIRE { #M1:1 ( _ , _ ) #R1:2 }`；
  - 對於用例定義本體內的物件，該用例那一行寫在前面（不論該用例本身是否有編號，皆依相同方式構成），接著是一個 TAB，再接該定義本體成員的記號（依定義本身所寫）；
  - 當該記號為集合的每個成員各建立一個物件時，後方接著一個 TAB 與該成員的控制代碼，寫作引用形式：宿主實例或網路以其名稱表示；端子以其實例與端子編號表示，如 `#M1:1`；接腳以其物件與接腳名稱表示，如 `#X1::vdd_t`，若無名稱則以其端子表示；物件的位置或帶 key 的文字以該物件接上 `::position`，或接上 `::` 與該 key 表示；RNL 物件以本層級綁定給它的 `%` 名稱表示（若有多個，則依 2.6 順序取最先綁定者，不論該集合當初以何名稱寫出）；沒有這類名稱的物件以其編號表示，或若為用例的區域物件，則以依相同規則構成的該用例引用接上 `::` 與其區域名稱表示（若定義本體內綁定了多個名稱，取最先綁定者，同一成員內亦然——在 `%p = (0, 0) => %q` 中為 `p`——不論該集合以何名稱寫出；若該物件屬於多個用例的區域物件，則透過最先套用的用例表示）。名稱若僅由 ASCII 字母、數字與 `_` 組成則依原樣書寫，否則置於雙引號內並將每個 `"` 重寫兩次（3.6）。例如在 `%p = (0, 0); %q = %p; %s = {%q}` 之後，`%s @TEXT("x")` 所建立的標註其對應行為 `%s @TEXT ( "x" )`、一個 TAB 與 `%p`，檢查碼為 `675df5171032726d`。在 `$D = @DEFINE(roles=["x"]) { %p = (0, 0) => %q }; %u = #M1 @AS $D; %s = {%u::q}` 中，`%s @TEXT("x")` 該行末尾為一個 TAB 與 `%u::p`，檢查碼為 `a8c9571193175903`。

  檢查碼為這些行以 UTF-8 編碼、每行以換行符（LF）結尾後所計算之 SHA-256 的前 16 個小寫十六進位數字。
- 當記錄的檢查碼與該層級不符時，該記錄中使用編號的敘述不生效，且若有任何此類敘述，該記錄會給出一條提示：無名物件的求解結果已過時。未使用任何編號的記錄不需要 `numbering`。該記錄中的其餘敘述照常生效（第 17 章）。超出最後一個編號物件的編號為錯誤。
- 在上述範例中，檢查碼為六個編號各含一行：WIRE 成員兩次（一次為連線，一次為點），TEXT 成員兩次（依序接上 `#M1` 與 `#R1`），以及重寫的 WIRE 再兩次，因為其中以座標寫出的兩個點是該記錄自身的物件，編號為 5 與 6。不進行求解的檢視器會依求解器選定的位置繪製自由點、連線走線與兩個標籤。
- 若改寫為 `{#R1 #M1}`，標籤 3 與 4 的順序會對調：檢查碼不再相符，帶編號的敘述在重新求解前不生效，而 M1 與 R1 則保留其位置。改寫 ALIGN 或移動 M1 則不影響編號。
- 附註：檢查碼僅涵蓋無名物件的建立方式。移動器件或修改未建立無名物件的敘述不會改變編號；插入、移除、修改或重排會建立此類物件的成員，則會使它們過時直到重新求解該層級為止。求解器記錄通常不包含更改集合或定義的敘述；無論如何，第 1 項一律不計入這類記錄。
