## 15 電氣語義

### 15.1 套用語義定義

```rnl
%dp1 = #M1(left) #M2(right) #M5(tail) @AS $DIFFERENTIAL_PAIR_N;
%cm1 = {#M3 #M9}(ref) {#M4 #M6}(out) @AS $CURRENT_MIRROR_P;
%in = {#M8 #M5} @AS $MATCHED
```

- 物件代表什麼含義是透過 AS 套用語義定義來標記的（9.5）：套用會建立一個用例，而物件填入該定義之角色列表中的各個角色。標記含義與陳述佈局關係屬於同一種敘述。
- 用例可以成為另一個用例的成員（巢狀結構），如 9.4 與 10.1 的範例所示。
- 在角色列表中寫作 `"{name}"` 的集合角色（如範例中 `$MATCHED` 的 `"{members}"`，以及 `$CURRENT_MIRROR_P` 的 `"{ref}"` 與 `"{out}"`），接收單一集合，用於數量不固定的成員（9.4）。
- 角色可宣告其接收的物件種類，例如 `roles=[["in_p", "instance"], ["in_n", "instance"]]`；傳入錯誤種類的物件會使整次套用失效（9.4）。定義本體為空的定義不會檢查填入角色的內容，因此若未作此類宣告，該處便無法偵測到錯誤的物件。
- 用例的角色名稱即其子物件，例如 `%dp1::left`。
- 套用定義會展開其定義本體，定義本體內可包含約束，例如優先順序為 `"low"` 的預設繪圖方式，而用例的優先順序可將其關閉（9.5、14.8）。
- 不予檢查：所標記的含義是否與網表的連接關係、類型或參數一致，不予檢查（原則 2.4）。例如對於 `#M3(ref) #M4(out) @AS $MY_MIRROR`，語言本身不會檢查 M3 的閘極與汲極是否相連；定義須透過定義本體中的斷言來檢查其所宣稱的條件（15.3、15.4）。
- 特定含義的用例以 SELECT-USAGE 選取，包含特定物件的用例則以 SELECT-ANCESTOR-USAGE 選取；用例的成員則透過以該用例為作用域的篩選取得（10.1）。
- 語義定義的詞彙屬於標準套件（9.5），例如標準套件提供的 `$DIFFERENTIAL_PAIR_N`。
- 單一描述的基本有效性（原則 2.4）為：其引用皆找得到、其角色收到正確種類的物件、單一物件角色皆已填入，且展開出的每條敘述自身皆有效（9.5）。兩個角色是否填入同一個物件不予檢查。

### 15.2 電流方向：CURRENT

```rnl
#M5:1 @CURRENT("in");                 /* drain: the current flows in */
#M5:3 @CURRENT("out")                 /* source: the current flows out */
```

- CURRENT 設定某個端子的靜態電流方向：`"in"`（流入）、`"out"`（流出）或 `"unspecified"`（用於覆寫套件規則給出的值）。參數為 `direction`。CURRENT 規則於步驟 6 評估（10.4）。以接腳為物件的 CURRENT——無論直接寫成接腳或透過角色取得——需要符號才能找出其端子（5.2.4）：它不是規則，而是在物件被賦予符號後於步驟 4 生效（步驟 6 產生的物件則於步驟 7 生效）。在步驟 6 以前，篩選的 `current` 條件僅讀取寫在端子上的 CURRENT 敘述；自步驟 7 起（如在樣式佇列中），該條件讀取所有方向，下述幾何與檢查亦然。
- 它是關於端子的事實，而非幾何事實：它不參與衝突取捨（8.5），求解器僅將它作為提示使用，例如用於決定嘗試朝向的順序。與 ORIENT 相同，它是修改性敘述並沿用輸入控制代碼。它具有一個 key，每個端子一個，較後寫者勝出。未曾寫過 CURRENT 的端子為未指定（unspecified）。
- 它僅能指定在端子上。多端器件內部的電流無法清楚拆解：對三端器件而言，「a 流向 b、b 流向 c」並未說明 b 處的電流究竟是流入還是流出，而端子上的靜態電流方向則永遠具有明確含義。
- 它僅接收宿主端子，包含本層級的連接埠：`#:inp @CURRENT("in")` 表示電流自該處流入子電路。器件的接腳會轉換為其端子，如 `#M1::d @CURRENT("in")`；虛擬組件沒有端子，因此其接腳不予轉換（5.2.4）。沒有接腳的端子亦屬允許（與連線不同）。
- 不對照網表檢查（原則 2.4）。同一條網路上的所有 CURRENT 敘述共同構成一項斷言（15.3）：當該網路上的每個端子（含本層級的連接埠）皆設有 `"in"` 或 `"out"` 的 CURRENT，且所有端子相對於該網路的電流流向皆相同時，會給出一項違規（7.6）並列出該網路及其端子，因為電流無處可去。器件端子的 `"in"` 將電流抽離該網路，而本層級連接埠的 `"in"` 則將電流送入該網路。若網路上存在未設 CURRENT 或設為 `"unspecified"` 的端子，則不檢查該網路。全域網路（6.3，如 `0`）亦不檢查：它在每個層級中皆為同一節點，因此電流可經由其他層級的端子流出。位於優先順序為 `"disabled"` 之記錄中或該優先順序之用例定義本體中的 CURRENT 不計入。此項檢查與其他斷言一同於 8.2 步驟 7 之後執行，且與它們一樣僅為回報，報告中會列出該網路、其端子以及它們的 CURRENT 敘述；CURRENT 事實本身依然有效。
- 用途：當電流流出時，端子處的電流沿連線離開接腳的方向（9.2.4，隨符號朝向一併旋轉）流動；流入時則沿反方向流動。求解器可據此選擇佈局，例如偏好讓電流由上往下流（14.8）；向上或向下屬於風格體系範疇。未設 CURRENT、設為 `"unspecified"`，或接腳未寫出 `direction=`（9.2.4）的端子不給出方向；實作自行從圖形推斷的方向不在此列。規則可透過 SELECT-TERMINAL 的 `current` 條件依電流方向選取端子（10.1）。
- **箭頭**：CURRENT 不繪製任何東西。是否以及如何根據 CURRENT 繪製箭頭屬於檢視器的偏好設定（其風格體系的一部分），如同顯示哪些網路名稱一般（13.3）。自行繪製箭頭的檢視器會略過已有標準電流箭頭用例的端子，如同它辨識標準 `$NO_CONNECT`（12.6）。須保留的箭頭（來自匯入的原理圖，或由撰寫者決定）須寫成明確物件：

  ```rnl
  $CURRENT_ARROW @ATTACH #M5:1 => @ORIENT("R270") => @TEXT("I_{SS}", dx=1);   /* on the drain pin, with I_SS beside it */
  $CURRENT_ARROW @ATTACH (12, 20) => @ORIENT("R270")                           /* in the middle of a wire, at absolute coordinates */
  ```

  - 繪製在端子上的箭頭是一個用例，其定義將自身的點綁定至該端子的接腳（12.1 第 5 項）。它不隨接腳旋轉，因此須寫出朝向；一旁的文字則附著於該用例上（13.3）。
  - 繪製在連線中段的箭頭不錨定於連線：它以絕對座標繪製在某一點上。
  - 如何區分指向內與指向外的箭頭，以及箭頭的定義與符號如何繪製，屬於標準套件的內容。符號可以僅是一條線段於端點加上箭頭（9.2.5）。
  - 繪製出的箭頭與 CURRENT 保持分離：若兩者為同一件事，匯出一個箭頭便會改變佈局的目標。

### 15.3 斷言：ASSERT-INSTANCE、ASSERT-TERMINAL、ASSERT-NET、ASSERT-USAGE、ASSERT-IN

```rnl
$MATCHED_PAIR = @DEFINE(roles=[["left", "instance"], ["right", "instance"]]) {
  {?left ?right} @ASSERT-INSTANCE(same=["model", "w", "l"], different=["name"]);
  {?left ?right} @SELECT-TERMINAL(terminal="s") => @ASSERT-TERMINAL(same=["net"], message="the sources of a pair share a net")
};
# @SELECT-INSTANCE(name="MD*") => @ASSERT-INSTANCE(type="nmos");
%dp1 @ASSERT-USAGE $DIFFERENTIAL_PAIR_N;                      /* %dp1 is a usage of this definition */
#M5:s @SELECT-NET => @ASSERT-IN $GROUND_NET_SET              /* the source of M5 is on a ground net */
```

- 斷言檢查檔案或定義的陳述是否與電路事實相符，例如對偶兩側是否具有相同的模型與尺寸，或虛設器件是否屬於同一類型。它僅作回報：不建立事實、不改變繪圖內容，且不參與衝突取捨（8.5）。
- **每種物件一個關鍵字**，與篩選相同（10.1）：ASSERT-INSTANCE 檢查實例（疊畫則依其第一個成員，11.8），ASSERT-TERMINAL 檢查端子，ASSERT-NET 檢查網路，ASSERT-USAGE 檢查用例。單一槽位接收該種類物件的集合；單一物件視作單一成員的集合。物件的種類在讀取文字時即已確定，種類錯誤於該處即為錯誤（5.2.4），因此沒有檢查種類的斷言。
- **條件**的名稱與含義與同種類篩選關鍵字的條件相同（10.1），如 `type="nmos"`、`terminals=4`、`net="vss"` 或 `port=true`：每個成員皆須滿足寫出的每項條件。
- **`same=[…]`**：對於列表中的每項屬性，所有成員的值皆須相同。**`different=[…]`**：對於列表中的每項屬性，任兩個成員的值皆須不同。屬性名稱即 `${…}` 的屬性名稱（13.6）：實例為 `name`、`value`、`model`、`type` 及各參數名稱；端子為 `net`；網路為 `name`；用例為 `definition`。對端子、網路與用例而言僅此而已：其他任何名稱皆為錯誤參數值，會使該斷言失效（7.1）。對實例而言參數名稱為開放集合，因此任何名稱皆可接受，而成員缺少某個屬性時視同擁有一個獨立的值「缺席（absent）」：缺少該屬性的成員彼此相等，並與每個寫出的值不同。因此當沒有成員寫出 `nf` 時，`same=["nf"]` 成立；當部分成員寫了而部分未寫時則給出違規；器件不具備該參數的製程無須另外撰寫專屬斷言。沒有類型的實例（10.1）缺少 `type`。數值依宿主所寫的文字比較，不進行求值（本語言沒有運算式，3.7）。
- **`has=[…]`**：用於 ASSERT-INSTANCE，每個成員皆須擁有列表中的每項屬性，如 `has=["w", "l"]`；缺少其中之一即給出違規。`same` 不要求寫出屬性；`has` 則要求。
- **ASSERT-USAGE** 以最後一個物件接收一個定義，如同 SELECT-USAGE（5.6、10.1）；可省略。寫出定義時，每個成員皆須為該定義的用例，依名稱解析後的對象識別（9.5），而非依名稱拼寫識別。其條件為 `symbol` 與 `drawn`（10.1）。當所有成員皆為同一個定義的用例時 `same=["definition"]` 成立；當任兩個成員皆非同一定義的用例時 `different=["definition"]` 成立。
- **ASSERT-IN**：`X @ASSERT-IN S` 檢查 X 的每個成員是否皆為集合 S 的成員；S 寫在最後，如同 ADD-TO（5.2.2），且 S 必須是一個集合，不會被自動包成集合。兩個成員是否相同依控制代碼判定（5.2）。成員可為任意種類，且 S 可以依賴篩選（10.4）。它沒有條件，僅有 `message`，違規時會列出不在 S 中的 X 成員。搭配集合的差集（5.2.2），它亦可表達某個集合必須為空。
- `different=["name"]` 檢查實例或網路是否為不同的物件，例如兩個角色不得填入同一個物件時；端子沒有 `name`，因此對端子而言 `name` 無論在 `different` 或 `same` 中皆為錯誤參數值。
- **報告**：不成立的檢查給出一項違規（7.6），列出相關成員與屬性；**`message`** 為該違規加上一段文字。不會有任何項目失效，繪圖結果亦與沒有該斷言時完全相同：斷言僅供撰寫者與 `rnl check` 等工具參考回報。
- **書寫位置與檢查時機**：任何層級以及一般定義的定義本體中皆可撰寫；在定義本體中會於每次套用時檢查（9.4）。斷言在 8.2 步驟 7 之後檢查，此時所有條件皆可讀取，包含 `drawn` 與 `symbol`（10.1）。沒有成員的集合自動成立，傳入空節點的斷言亦同（6.3）。
- 斷言沒有優先順序；在 `priority="disabled"` 的記錄中以及在優先順序為 `"disabled"` 之用例的定義本體中（14.8），不進行檢查。

### 15.4 拓撲斷言：ASSERT-TOPOLOGY

```rnl
{#R1 #R2 #R3} @ASSERT-TOPOLOGY("series");                  /* a chain: R1 to R2 to R3 */
{#M3 #M4} @ASSERT-TOPOLOGY("parallel", exclude=[["nmos", "g"], ["nmos", "b"]]);   /* drains on one net, sources on one net */
{#L1 #C1 #L2} @ASSERT-TOPOLOGY("star");                    /* a T network: three branches meet at one net */
{#C1 #L1 #C2} @ASSERT-TOPOLOGY("loop");                    /* a pi network: C1, L1 and C2 go round */
{%branch1 %branch2} @ASSERT-TOPOLOGY("parallel")           /* two branches, each a usage or a set taken as a black box, between the same nets */
```

- ASSERT-TOPOLOGY 檢查成員是否以指定方式連接：串聯、並聯、星形或單一迴路。它是與 15.3 相同的斷言，15.3 關於斷言的規定同樣適用於此：僅作回報、不成立時給出違規（7.6）、`message` 可附加說明文字，且書寫位置、檢查時機與優先順序處理皆相同。
- **成員**：單一槽位接收按順序排列的成員集合，依項目計數（5.2）：單一物件為一個成員，而作為 `{…}` 或集合引用的項目則視為一個黑盒成員。作為唯一物件傳入的集合會先拆開一層（5.2.1），因此 `%chain @ASSERT-TOPOLOGY("series")` 檢查串鏈中的項目，而 `{%branch1 %branch2}` 有兩個成員。因此每個成員可以是實例（或疊畫，依其第一個成員，11.8）、用例或集合。若傳入篩選結果（每個成員各佔一項），成員順序即為篩選結果的順序（10.3）。少於兩個成員時檢查自動成立。
- **成員的網路**：
  - 實例：其未被 `exclude` 排除的端子所在的網路；
  - 用例或集合：作為黑盒，是由它所帶入的端子組成的單一元素。用例（不論有無符號）代表填入其角色的對象，集合則代表其成員，一路向內展開至最內層：實例帶入其所有端子，端子僅帶入自身，接腳帶入它綁定的端子，網路與點不帶入任何端子，疊畫依其第一個成員計數。黑盒的網路為：其帶入且未被 `exclude` 排除的端子所在、同時也在黑盒外部使用的網路——即被未帶入該黑盒的端子（含疊畫其他成員的端子）使用，或作為該層級的連接埠。僅被黑盒內部端子使用的網路不計入。附註：兩個成員共用的網路，會被各自的對方在外部使用，因此網路是否為連接埠，只對帶入相同端子的成員改變判定結果；否則只改變哪些網路屬於黑盒，如工具所可能顯示者。
- **`exclude=[[type, terminal], …]`**：不予計入的端子，寫成「類型」與「端子名稱或編號」的配對，例如 `exclude=[["nmos", "g"], ["nmos", "b"]]`，其中類型依條件 `type` 比較（10.1）。配對中的端子依 SELECT-TERMINAL 的 `terminal` 條件比較（10.1）：編號依位置、名稱依宿主大小寫規則；實例沒有該名稱的端子則不匹配任何項目。沒有類型的實例或類型未列於此列表中的實例，其端子仍計入。未寫出 `exclude` 時，所有端子皆計入。若某個配對不是兩個字串（或一個字串與一個整數）的陣列，屬於錯誤參數值，會使該斷言失效（7.1）。
- **拓撲類型**為第一個參數，依位置傳入，為以下四者之一：
  - `"series"`：依序相鄰的任兩個成員恰好共用一條網路，不相鄰的任兩個成員不共用任何網路。共用網路上是否還連有其他東西不予檢查：分壓器中點可以連往他處。
  - `"parallel"`：至少有兩條網路（兩端）為所有成員共同擁有。成員的其他網路（例如某個分支拉出的分接）不予檢查，如同 `"series"` 不檢查共用網路上的其他連線。
  - `"star"`：有一條網路為所有成員共同擁有，且任兩個成員之間不共用其他任何網路。
  - `"loop"`：至少須有三個成員。依序繞行一圈（包含最後一個與第一個之間），相鄰的任兩個成員恰好共用一條網路，這些網路互不相同，且不相鄰的任兩個成員不共用任何網路。僅有兩個成員時，`"loop"` 會給出違規；請改寫 `"parallel"`。
