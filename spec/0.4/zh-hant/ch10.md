## 10 篩選、規則與逐一產生

本章涵蓋篩選關鍵字、使用它們的規則，以及逐一產生。

### 10.1 篩選關鍵字

每種要選取的物件種類各有一個篩選關鍵字，各自具備一組固定的條件。篩選的結果是一個集合（5.2）。

每個篩選關鍵字接收一個作用域物件。`#` 是評估該篩選的層級（10.3）。當給定一個物件或一個集合時，篩選在這些物件中查找：例如給定一組網路時，SELECT-TERMINAL 會選出這些網路上的端子（作用域如何引出所選種類見表格後方說明）。作用域不得省略，因此簡單的篩選亦須寫出 `#`：`# @SELECT-INSTANCE(name="R*") => @SET-SYMBOL $RESISTOR`。

| 關鍵字 | 選取對象 | 條件 |
|---|---|---|
| SELECT-INSTANCE | 宿主實例。當作用域為端子時，為其所屬實例；當作用域為網路時，為有端子連於其上的實例 | `name`（實例名稱，如 `name="R*"`）；`model`（實例行模型位置上的名稱：`.model` 名稱或子電路名稱）；`type`（實例的類型，來自其 `.model` 或 DEVICE，如 `"nmos"`；支援 `*`）；`terminals`（實例的端子數，如 `terminals=3`）；`symbol` 與 `drawn`（見下文） |
| SELECT-TERMINAL | 宿主實例的端子，不論是否有接腳：電路的篩選 | 實例的 `name`、`model` 與 `type`；`terminal`（端子名稱或編號）；`net`（所在網路的名稱）；`current`（電流方向，15.2：`"in"`、`"out"` 或 `"unspecified"`） |
| SELECT-PIN | 繪製物件的接腳：繪圖的篩選（9.2.4） | 所屬物件的 `name`、`model` 與 `type`；`terminal`（接腳綁定的端子或角色名稱）；`net`（其 `::net` 的名稱）；`wired`（10.2） |
| SELECT-NET | 網路。當作用域為實例、端子或連線時，為它們所連的網路 | `name`；`port`（是否為本層級的連接埠）；`wired`（10.2）；`global`（是否為全域網路，6.3） |
| SELECT-WIRE | 連線。當作用域為網路時，為繪製在這些網路上的連線 | `net`（連線所屬網路的名稱；匯流排只要其中任一網路符合即符合）；`bus`（`true`：僅限匯流排，13.1；`false`：僅限非匯流排的連線，即其網路槽位接收單一網路而非集合者） |
| SELECT-LABEL | 標籤，即附著於物件上的 TEXT（13.3）。當作用域為物件時，為附著在它們上的標籤 | `key`（文字的 key；支援 `*` 且區分大小寫；沒有 key 的標籤不符合任何 `key=`） |
| SELECT-ANNOTATION | 標註，即場景中的圖形與附著於點的 TEXT（13.4） | 除 `role` 與 `recursive` 外無其他條件 |
| SELECT-USAGE | `scope @SELECT-USAGE $D`：作用域中定義 `$D` 的用例，向內查找。作用域為 `#` 時，為本層級的用例；作用域為用例時，為這些用例本身及其內部的用例。省略 `$D` 時，為任何定義的用例 | 定義為最後一個物件（5.6），可省略。`symbol` 與 `drawn`（見下文） |
| SELECT-ANCESTOR-USAGE | `objects @SELECT-ANCESTOR-USAGE $D`：以這些物件為成員的 `$D` 用例，向外查找；間接成員亦計入 | 定義為最後一個物件（5.6），為必填。除 `recursive` 外無其他條件 |

除此之外，每個篩選關鍵字皆接受條件 `recursive`，而前七個接受 `role`，後者僅在作用域包含用例時才有意義（兩者皆見下文）。

- **每種物件一個關鍵字。** 每個篩選關鍵字皆依其選取的種類命名，例如 `&clk @SELECT-WIRE => @SET-STYLE $signal` 選取某條網路的連線，或 `#M1 @SELECT-LABEL` 選取 M1 的標籤。沒有涵蓋所有種類的篩選：若要涵蓋所有種類，須為每種各自寫一條規則，如同標準套件為每個物件賦予基礎樣式的做法。
- **作用域如何引出所選種類。** 作用域中的每個物件往所選種類跨出一步；沒有這一步可跨的物件選不出任何內容，這不算錯誤：
  - SELECT-INSTANCE：實例即自身；端子引至其所屬實例；網路引至有端子連於其上的實例。
  - SELECT-TERMINAL：實例引至其端子；網路引至其上的端子；端子即自身；接腳引至它綁定的端子。
  - SELECT-PIN：繪製物件（實例、疊畫、有符號的用例）引至其自身符號的接腳，若帶 `role` 則用例改為引至填入該角色的接腳（如同其他篩選取成員的方式，見下文）；沒有符號的用例引至填入其角色的物件中的接腳；端子引至綁定它的接腳；網路引至其 `::net` 為該網路的接腳（包含綁定至由該網路填入之角色的接腳）；接腳即自身。作用域為 `#` 時，選出本層級的每支接腳。
  - SELECT-NET：網路即自身；實例引至其端子的網路；端子引至其網路；連線引至它所繪製於上的網路。
  - SELECT-WIRE：網路引至繪製在其上的連線；連線即自身。SELECT-LABEL：物件引至附著在其上的標籤；標籤即自身。SELECT-ANNOTATION 僅選取作用域內的標註。
  - 經由端子的這一步會計入所有端子，不論有無接腳：端子屬於電路。欲選取繪製出的內容，須透過接腳選取。因此 `&vss @SELECT-INSTANCE` 會包含僅有符號未繪製之基體端子連於 vss 的 NMOS。本層級的連接埠（如 `#:inp`）引至其網路。
  - 以用例作為作用域時，僅取其中屬於所選種類的成員；成員不會再次作為作用域展開（見下文）。
  - 例如，受時脈控制的電晶體為 `&clk @SELECT-INSTANCE`；僅選取閘極連於 clk 者為 `&clk @SELECT-TERMINAL(terminal="g") => @SELECT-INSTANCE`；M1 的網路為 `#M1 @SELECT-NET`。
  - 附註：為繪圖新增接地、連線、標籤或樣式的規則應選取接腳（SELECT-PIN），如此新增的內容才會符合實際繪出的接腳；檢查電路的規則則選取端子。
- **依符號篩選：`symbol` 與 `drawn`。** SELECT-INSTANCE 與 SELECT-USAGE 接受字串 `symbol="$X"`：表示該物件以透過該 `$` 名稱賦予的符號繪製（即在賦予它的 SET-SYMBOL 中所寫的名稱），依書寫形式比較並支援萬用字元 `*`，例如 `symbol="$IO_PORT*"`；透過 `%` 名稱賦予或匿名寫出的符號不符合任何 `symbol=`。該 SET-SYMBOL 中 `$` 名稱的別名會讀作原名（16.5），因此比較的是原名；`symbol=` 的字串不予轉譯（16.5），須以原名寫出。與 SELECT-USAGE 中依名稱解析結果識別的定義不同（9.5），此處是名稱字串的比較；參數僅能容納字面量（3.7），因此名稱須寫作字串，與其他篩選條件寫法相同。這兩個關鍵字亦接受 `drawn`（`true`：該物件已繪製，即擁有敘述、規則、方塊符號或預設方塊符號（9.2.6）所賦予的符號；`false`：沒有，如沒有符號的用例）。每個實例都會被繪製。這些條件讀取符號資訊，因此適用於產生規則與樣式佇列，因為兩者位於賦予符號之後（8.2）；若寫在 SET-SYMBOL 的篩選中則為錯誤，因為符號佇列無法依它正在賦予的符號進行篩選。SELECT-PIN 同樣讀取符號資訊，受相同限制；任何以接腳為作用域或經由接腳跨步的篩選（如 `#R1::p @SELECT-TERMINAL`）亦同：寫在 SET-SYMBOL 的篩選中皆為錯誤。寫有 `::` 且後方名稱並非該物件的角色名稱、區域名稱或標準子物件名稱的作用域（如 `#X1::k`）亦同：它究竟命名符號所帶來的接腳還是文字的 key，唯有在賦予符號之後才得知（6.5）。
- **僅本層級，或亦包含下方各層級。** 每個篩選關鍵字皆有條件 `recursive`，預設為 `false`。規則在它所寫在的層級進行評估，其向下觸及的範圍依以下規則決定；每次評估時，其中的每個篩選與每個集合皆在該層級評估，並僅包含該層級的成員（10.3）。
  - **直接寫有篩選的規則**（寫在規則自身的管線中或規則中寫出的 `{…}` 內），當且僅當其中任一篩選寫了 `recursive=true` 時才觸及下方層級；它所使用的集合不改變此範圍。因此 `# @SELECT-INSTANCE(recursive=true) => @SELECT-PIN(net="vss", wired=false) => $GROUND_STUB @ATTACH` 會在本層級及其下方每個層級加上接地，而 `# @SELECT-NET(name="vdd") => @REMOVE-FROM $PORT_FILL_SET` 僅在本層級作用。
  - **未寫有篩選的規則**（即使用依賴篩選的集合者，10.4）觸及那些集合所觸及的本層級下方各層級。集合觸及自身層級以及將篩選結果加入該集合的敘述所觸及的層級：包括它所綁定的敘述、其項目中的集合，以及對它新增成員的 ADD-TO 敘述（其中未寫篩選的 ADD-TO 依它所加入的集合觸及多遠來計算，而非依目標集合計算）。在集合未觸及的層級中，該集合沒有任何成員，即使有觸及該處的規則使用它亦然。因此若 `$GROUND_NET_SET = # @SELECT-NET(name="0", recursive=true)`，該集合擁有每個層級的 0 號網路，`%g_set = {$GROUND_NET_SET}` 觸及相同範圍，而 `$IO_PORT @ATTACH $PORT_FILL_SET` 或 `$SUPPLY_NET_SET @REMOVE-FROM $PORT_FILL_SET` 會在這些集合觸及的每個層級作用。
  - 單一宿主物件只是直接引用（如 `&vss`）：宿主引用僅在自身層級解析，由它們構成的集合（如 `{&vss}`）不觸及下方層級。
- **SELECT-USAGE 與 SELECT-ANCESTOR-USAGE。** 兩者皆依名稱解析後的對象識別定義（9.5），一律選取用例，且都沒有 `role=`。
  - SELECT-USAGE 向內查找，與其他篩選關鍵字相同。作用域為 `#` 時，選出受評估層級的用例；作用域為單一或一組用例時，選出這些用例本身及其內部的用例，直到最內層。作用域中的實例、網路與端子不是用例，選不出任何東西；警告會提示若要找它們所屬的用例須使用 SELECT-ANCESTOR-USAGE。
  - SELECT-ANCESTOR-USAGE 向外查找：選出直接或間接以作用域中物件為成員的用例（見下例）。作用域中的用例本身不包含在內。以 `#` 為作用域為錯誤：層級不是任何事物的成員。
- **以用例作為作用域。** 以用例作為作用域時，其他篩選關鍵字會選出這些用例中屬於該種類的成員，而 `role=` 僅取該角色的成員。唯獨 SELECT-PIN 在作用域為有符號且不帶 `role` 的用例時不同，此時選出該用例自身符號的接腳（見上文）。本身也是用例的成員會繼續向內追蹤，直到最內層：

  ```rnl
  $OTA = @DEFINE(roles=[["pair", "usage"], ["load", "usage"]]) {};
  %dp1 = #M1(left) #M2(right) #M5(tail) @AS $DIFFERENTIAL_PAIR_N;
  %cm1 = #M3(ref) #M4(out) @AS $CURRENT_MIRROR_P;
  %ota1 = %dp1(pair) %cm1(load) @AS $OTA;
  %all_set = %ota1 @SELECT-INSTANCE;                 /* {#M1 #M2 #M5 #M3 #M4} */
  %pair_set = %ota1 @SELECT-INSTANCE(role="pair");   /* {#M1 #M2 #M5} */
  %up_set = #M1 @SELECT-ANCESTOR-USAGE $OTA          /* {%ota1} */
  ```

  - `role=` 的值亦接受該用例定義的 `definition=` 別名（16.5）。若僅要取直接成員，須使用角色作為子物件，如 `%dp1::tail`。追蹤遇到已走訪過的用例即停止。所謂成員是指填入角色的物件，不包含定義本體的區域物件（9.4）。
  - **僅限所選種類的成員。** 不會將成員再次作為作用域往下追查，也不計入其他種類的成員。SELECT-TERMINAL 僅取端子成員：在 `$GROUND @ATTACH &0; $CURRENT_ARROW @ATTACH #M5:1` 之後，`# @SELECT-USAGE => @SELECT-TERMINAL` 僅為 {#M5:1}，不包含網路 0 上的端子。差動對 %dp1 的成員是實例，因此 `%dp1 @SELECT-TERMINAL` 為空。若要取成員實例的端子，須寫 `%dp1 @SELECT-INSTANCE => @SELECT-TERMINAL(terminal=2)`（所有三顆電晶體的閘極，含尾端電晶體）；若要取成員網路上的端子，須寫 `… => @SELECT-NET => @SELECT-TERMINAL`。每段只做一件事；若要往下走一步，再接一段即可。直接寫在作用域中的物件依循前述規則：網路給出其上的端子，實例給出其端子。
  - **透過轉換填入的角色**（5.2.4），例如種類為 `"pin"` 的角色傳入了一個端子，在賦予符號前保留原樣寫出的物件，賦予符號後則成為轉換後的物件。因此在產生規則與後續階段中，`@SELECT-PIN(role="t")` 會選出該接腳，不論該角色當初傳入的是接腳名稱還是代表該接腳的端子。
- 若要在場景中依條件尋找物件，一律須使用篩選關鍵字；`::` 僅取用物件自身的部分（6.5）。
- **疊畫。** 疊畫的成員無法被選出；選中的會是該疊畫本身（11.8）。SELECT-INSTANCE 依第一個成員的條件選取疊畫本身，每個疊畫僅選取一次。SELECT-TERMINAL 選取疊畫的端子，且只要 `net=` 符合任一成員的網路即符合。
- **條件**依名稱寫出，如 `name=value`；唯有寫出的所有條件皆成立時，物件才會被選中。若要表達「或」，須寫多條規則。比較名稱的條件（`name`、`model`、`net`）支援萬用字元 `*`（匹配任意數量的字元），並依宿主的大小寫規則比較，與 DEVICE 相同（6.12）。欲依元素字母選取，須寫 `name="R*"`。Spectre 的實例名稱不以元素字母開頭，須依 `model` 選取，如 `model="resistor"`（6.12）。
- **`model`** 比較實例行模型位置上寫的名稱：對 M、Q、D 等元素為 `.model` 名稱；對 X 實例為子電路名稱，含網表中未定義的 PDK 器件，如 `# @SELECT-INSTANCE(model="sky130_fd_pr__nfet_01v8")`；在 Spectre 中為 master。它與 DEVICE 的 `model=` 相同（6.12）。`type` 比較實例的類型：其 `.model` 的類型，或對於宿主未給出類型的實例（如 X 實例）由 DEVICE 給出的類型（6.12）；兩者皆無時，該實例沒有類型且不符合任何 `type=`。`type` 同比較名稱的條件一樣支援萬用字元 `*`：`type="*mos"` 匹配 nmos 與 pmos 類型，而 `type="*"` 選出擁有任何類型的實例，這正是規則或斷言排除未知類型器件的做法。
- **`terminals`** 比較實例的端子數量（整數）：宿主在其行上讀取的節點數，編號為 1, 2, …（6.12），不論 DEVICE 給了多少名稱。因此 `terminals=3` 會選出 `Q1 c b e qn` 而不會選出 `Q2 c b e s qn`。對於 X 實例，它計算該行的節點數，即子電路的連接埠數；在 Spectre 中計算括號內的節點數，故 `S1 (com t1 t2) switch` 為 3。它與其他條件一樣可組合使用，如 `# @SELECT-INSTANCE(type="nmos", terminals=4) => @SET-SYMBOL $NMOS_4TERM`；疊畫依第一個成員計數（11.8）。
- 比較規則遵循 3.6：條件名稱與標準列舉值區分大小寫；指涉宿主事物的值（名稱、模型名稱、網路名稱）遵循宿主規則。
- 網路可依名稱選取：`# @SELECT-NET(name="0")` 選出該網路，`# @SELECT-TERMINAL(net="0")` 選出其上的端子。物件亦可依語義選取：`# @SELECT-USAGE $DIFFERENTIAL_PAIR_N => @SELECT-INSTANCE(role="left")` 選出每個差動對的左側電晶體。
- 沒有交集關鍵字（例如選出某集合中同時屬於某個用例的成員）；須寫兩次 REMOVE-FROM 達成（5.2.2）：

  ```rnl
  %s_set = {#M1 #M3 #M5};
  %s_set @SELECT-ANCESTOR-USAGE $DIFFERENTIAL_PAIR_N => @SELECT-INSTANCE => %dp_m_set;
  %out_set = {%s_set};
  %dp_m_set @REMOVE-FROM %out_set;    /* the members of %s_set in no differential pair */
  %in_set = {%s_set};
  %out_set @REMOVE-FROM %in_set       /* the members of %s_set in a differential pair */
  ```

- **接地與電源網路**由標準套件提供的集合給出：`$GROUND_NET_SET`（預設為網路 0）與 `$SUPPLY_NET_SET`（預設為空）。沒有網路類別（net class）機制。
  - 套件不得包含宿主引用（16.2），因此這類集合的預設內容僅能寫成篩選，例如 `# @SELECT-NET(name="0", recursive=true)`。
  - 使用者以 ADD-TO 與 REMOVE-FROM 新增與移除網路：

    ```rnl
    &vss @ADD-TO $GROUND_NET_SET;                                       /* the vss of this level */
    # @SELECT-NET(name="vss", recursive=true) => @ADD-TO $GROUND_NET_SET;   /* the nets named vss of every level */
    # @SELECT-NET(name="vdd!", global=true, recursive=true) => @ADD-TO $SUPPLY_NET_SET  /* only the global vdd! */
    ```

    第二條敘述亦會加入子電路中名為 vss 的區域網路。若要在單一位置略過某個網路，須複製該集合並從複本中移除該網路：`%g_set = {$GROUND_NET_SET}; &vss2 @REMOVE-FROM %g_set`。
  - 自動補齊規則以這類集合作為作用域，例如 `$GROUND_NET_SET @SELECT-PIN(wired=false, recursive=true) => $GROUND_STUB @ATTACH`，這同時也會選中虛擬組件位於這些網路上的接腳；標準套件隨後會將其自身所放置零件的接腳（如接地的接腳）移除。
  - 在自身層級寫出 `$GROUND_NET_SET = …` 會遮蔽套件的集合，套件的規則看不到新集合（6.8）。
  - 系統不會從網路名稱猜測接地與電源。匯入器須將編輯器檔案中網路的電源域（如 `powerDomain`）寫作 ADD-TO。
  - 求解器可以將標準集合讀作提示（如電源朝上、接地朝下），如同它可讀取標準套件的定義；這並非強制要求。
  - 附註：沒有專門用於接地與電源網路的關鍵字（1.5 第 7 項）：這些集合的所有用途（如選取端子以加入接地或更換符號）皆可寫作套件中的規則。
- **空節點**（6.3）不是網路：SELECT-NET 絕不會選出它；位於其上的接腳僅能透過其所屬物件或 `#` 由 SELECT-PIN 選出，不能透過網路或 `net=` 選出；位於其上的連線僅能由不帶 `net=` 的 SELECT-WIRE 選出。
- **全域網路。** SELECT-NET 的條件 `global=true` 僅選取全域網路（6.3）。不同層級中同名的區域網路是不同的節點，依名稱篩選會選出全部；若要僅取全域者，須加上此條件。

### 10.2 條件 `wired`

- 當接腳不是任何明確連線（無論端點或中間點；寫至端子的連線止於該端子的接腳，5.2.4）的點，且不位於 ROUTE-NET 或 ROUTE-OBJECT 的走線樹中（13.7，因為求解器會繪製走線樹的連線）時，該接腳為 `wired=false`。匯流排接腳是單一支接腳，只要有任何一條連線透過其任一端子止於該接腳，即視為已連線（9.2.4）。匯流排連線亦屬明確連線（13.1）。連至疊畫端子的連線會連接每個成員的該端子（11.8）。
- 當網路上沒有任何宿主實例的端子被明確連線觸及，且沒有 ROUTE-NET 或 ROUTE-OBJECT 的走線樹位於該網路上時，該網路為 `wired=false`；虛擬組件的接腳不計入。
- 哪些接腳位於走線樹中在 8.2 的兩個階段確定。在步驟 4 之後（一旦指派符號），由步驟 3 的敘述確定：於步驟 5 評估的 ROUTE-NET、ROUTE-OBJECT、UNROUTE-NET 與 UNROUTE-OBJECT 規則（10.4）讀取這些走線樹（例如 `{&a &b} @SELECT-NET(wired=false) => @ROUTE-NET`），且彼此互不可見，因此規則絕不會讀取自己建立的走線樹。在步驟 5 之後，由這些規則建立與修改的走線樹確定：步驟 6 與後續步驟的條件讀取這些結果。因此產生規則（如標準套件的自動補齊，16.3）會將 ROUTE 規則連接的接腳計為已連線，而將 UNROUTE 規則移除的接腳計為未連線（除非有書寫的連線觸及它們）。步驟 6 產生內容中的走線敘述（如產生用例的定義本體內）同樣會建立與修改走線樹，但沒有條件看得到它們。
- 寫在空節點上的連線（13.1）與其他連線一視同仁：它所止於的接腳皆視為已連線。
- 僅計入明確寫出的連線，不計入產生出的連線。是否存在虛擬組件並無影響。
- 連線依書寫狀態從 8.2 步驟 3 起即計入，即使該連線後來因端子沒有接腳而失效亦同（7.1、9.2.4）。對於經重寫的連線，以最後一次重寫為準（13.1）。

### 10.3 評估篩選

- 篩選不會在書寫處展開，每次評估僅檢視單一層級。規則（10.4）在寫作它的層級評估一次，並在它觸及的下方每個層級各評估一次（10.1）；每次評估時，`#` 即代表該層級，篩選亦僅選取該層級的物件。因此寫在頂層的 `# @SELECT-INSTANCE(model="nch", recursive=true) => @ALIGN("y")` 會在每張圖面內部分別對齊，不會跨圖面互相對齊實例。
- 篩選在使用它的階段進行評估：外觀規則於符號佇列與樣式佇列、走線關鍵字的規則於步驟 5、產生規則於產生階段（8.2）。集合亦同（5.2）。
- 篩選所選取的種類在讀取時即已知。將其傳入不接收該種類的槽位時會立即構成錯誤，即使位於集合內亦同，如 `# @SELECT-TERMINAL(net="vss") => @SET-SYMBOL $NMOS`。
- SELECT-USAGE 與 SELECT-ANCESTOR-USAGE 一律選取用例；當篩選從用例進而選取其成員時，所選種類由其關鍵字決定。因此每個篩選的種類在讀取時皆已確定。
- 篩選的結果是集合，可以用 `%` 或 `$` 命名。在某層級評估的集合僅取該層級的成員：寫在頂層的 `&vss @ADD-TO $GROUND_NET_SET` 僅加入頂層的 vss，當在子電路中評估該集合時，頂層的 vss 不在其中（6.6）。
- **結果的順序。** 篩選結果的成員依以下順序排列，凡集合順序有影響處皆依此為準，例如 ORDER、DISTRIBUTE、TABLE 與 LINE，以及逐一運作規則的結果順序（5.2.1）：
  - 以 `#` 為作用域時，依場景中物件的順序：
    - 實例依網表中各行的順序（疊畫位於其第一個成員所在行）；端子先依實例或疊畫，再依編號；
    - 網路：本層級的連接埠依子電路行順序，其餘網路則依首次出現在實例行上的順序；
    - 接腳依其所屬物件排列：先排實例與疊畫（依行順序，疊畫位於其第一個成員所在行），再排用例（依其順序）；同一物件內依其符號中 PIN 敘述的順序；
    - 用例、連線、文字與圖形：先排在 8.2 步驟 3 建立者，依其位置順序（8.5），用例定義本體建立的內容緊接在該用例之後依定義本體順序排列；再依步驟順序排較後步驟建立者。同一步驟內，依建立它們的敘述或規則的位置順序，單條規則產生的結果則依其輸入順序（5.2.1），而符號帶來的文字依所屬物件順序（物件順序同接腳所述）再依符號內順序排列。場景中依 key 覆寫符號文字的文字（13.3）算作同一段文字，位於最先寫出它的敘述所在位置。
  - 以任何其他物件為作用域時，作用域的每個成員依序給出各自的結果，各自遵循上述順序，且已給出的物件不重複給出。這適用於每個篩選關鍵字，含 SELECT-ANCESTOR-USAGE。
  - 集合保留成員寫入與加入的順序（5.2、5.2.2）：ADD-TO 附加於末尾並保留重複，UNION 則移除重複。
- 當篩選的作用域寫為本層級的宿主物件時（例如在頂層寫 `&Q<0:3:2, 1> @SELECT-TERMINAL(name="R*", recursive=true) => @TEXT("${net}", key="netname")`），在較低層級評估該規則時這些物件並不存在：篩選在該處為空且不做事，不給出警告，如同集合僅取該層級的成員。10.5 的警告僅針對產生規則的其他角色給出。

### 10.4 規則

- 直接接收篩選結果，或透過依賴篩選的集合接收篩選結果的敘述，即為規則。當集合綁定至篩選、其項目中包含篩選或依賴篩選的集合、由這類集合經 UNION 構成，或 ADD-TO / REMOVE-FROM 以篩選結果或這類集合修改它（5.2.2）時，該集合即依賴篩選：此時它的成員僅在使用它的階段才得知。在用例的定義本體中，當填入集合角色的集合依賴篩選時，該集合角色亦依賴篩選。
- 除了 BUNDLE（11.8）、WIRE（13.1）以及兩點形式的 RECTANGLE、CIRCLE 與 ELLIPSE（9.2.5）之外，任何關鍵字皆可接收篩選結果，依 5.2.1 逐一運作或整體運作：`# @SELECT-INSTANCE(type="nmos") => @ORIENT("MY")`、`# @SELECT-INSTANCE(model="nch") => @ALIGN("y")`。
- 以篩選結果為物件的 SET-SYMBOL 與 SET-STYLE 是外觀規則，進入外觀佇列（8.3）。AS 與 ATTACH 是產生規則（10.5），附著於篩選結果的 TEXT（13.3）、以尺寸寫出且點為篩選結果的 RECTANGLE、CIRCLE 與 ELLIPSE（9.2.5），以及建立繪製物件的 LINE、ARC 與 BEZIER 規則亦同；後者槽位接收集合，因此這類規則會依結果順序繪製貫穿整個結果的單一圖形（5.2.1、10.3）。ROUTE-NET、ROUTE-OBJECT、UNROUTE-NET 與 UNROUTE-OBJECT 的規則在它們之前的步驟 5 評估：它們的條件讀取步驟 3 敘述的走線樹，產生規則則看到它們建立的走線樹（10.2）。CURRENT 的規則與產生規則一同在步驟 6 評估；兩者合稱步驟 6 的規則：電流方向依步驟 3 的敘述確定，步驟 6 的條件看不到這些規則所做的修改（15.2）。BUNDLE 不接收篩選結果：疊畫須在賦予符號之前即存在（11.8）。其他關鍵字（如約束、PLACE 與 ORIENT）的規則在各自關鍵字的階段生效，並能看到產生的物件。對於其他任何關鍵字，規則等價於對每個選出物件各寫一條敘述，或對全部選出物件寫一條敘述，並在其關鍵字的階段生效。
- 規則作用於寫作它的層級，並透過自身篩選中的 `recursive=true`——或若無篩選，透過所使用的集合——觸及下方層級（10.1），在每個層級各評估一次並僅檢視該層級（10.3）。套件中的規則視同寫在引入該套件之 USE-PACKAGE 所在的層級，根層級套件則視同用於檔案頂層（16.2），因此它僅依 10.1 向下觸及，這正是標準套件在其篩選中寫 `recursive=true` 的原因。一般定義定義本體中的規則視同寫在該用例所在的層級（9.4）。
- **觸及下方層級的規則中的本層級宿主物件**：若觸及下方層級的規則在其他槽位點名了自身層級的宿主物件——例如 `%clk_set %rest_set @DISTANCE("bottom-to-top", min=3)`，其中 `%clk_set = {#VP1 #VP2}` 且 `%rest_set` 綁定至帶有 `recursive=true` 的篩選——在較低層級中找不到這些物件，該敘述在該處不產生效果且不給出警告。唯有產生規則會發出警告，如 10.5 所述。

### 10.5 逐一產生

「對於每個位於 vss 上且未連線的端子，放置一個接地並以連線相連」：

```rnl
$GROUND_STUB = @DEFINE(roles=[["t", "pin"]], parameters=[["gap", 2]]) {
  %g = $GROUND @ATTACH ?t::net;
  ?t::net @WIRE {?t %g::pin};
  {?t %g::pin} @ALIGN("x");
  %g::pin ?t @DISTANCE("bottom-to-top", exact=?gap)
};
# @SELECT-INSTANCE => @SELECT-PIN(net="vss", wired=false) => $GROUND_STUB @ATTACH => %stubs_set
```

標準套件提供一個與此類似的 `$GROUND_STUB`，差別在於其預設 gap 為 1、僅給出最小距離（`min=?gap`，以便求解器在對齊不同長度器件的接地時可將連線拉長）、使接地朝下（`@ORIENT("R0")`），且其約束優先順序為 `"low"`；此處的定義遮蔽了它（6.8）。

- 當 AS 或 ATTACH 的單一角色接收篩選結果時，會對每個選出的物件各套用一次該定義，其餘角色在每次套用中皆相同（5.2.1、9.4）。集合角色則整體接收篩選結果，定義僅套用一次；當其角色皆為集合角色時，僅在其中某個角色有內容的層級套用（9.4）。
- 虛擬組件以相同方式逐一建立：`# @SELECT-NET(port=true) => $IO_PORT @ATTACH` 為每個連接埠網路加上一個連接埠標記；若有繪為電阻、具兩個角色的定義 `$RLOAD`，`# @SELECT-NET(name="out*", recursive=true) => $RLOAD @ATTACH &vss` 會在每個選出的網路與 vss 之間加上一個；由於 `&vss` 屬於本層級，該規則僅在此層級生效，並給出下文所述的警告。
- 標準套件的自動補齊會加上帶有連線的接地與電源（`$GROUND_STUB`、`$SUPPLY_STUB`）：一旦寫回，該連線便使接腳不再處於 `wired=false`，自動補齊就會略過它。若僅以約束將接地擺放在接腳上而未畫連線，該接腳仍維持 `wired=false`，自動補齊仍會補上一個；在兩支接腳之間寫一條長度為 0 的連線（13.1）即可使接腳成為已連線。
- 配對發生在每次套用內部：定義的區域名稱在每次套用中皆為新建，因此某次套用的 `%g` 即為該次套用所建立的接地。
- 結果是一個產生集合。它可以命名並整體傳給 SET-SYMBOL 或 SET-STYLE（如 `%stubs_set @SET-STYLE $grey`），但無法單獨引用其個別成員（5.7）。
- **手動撰寫。** 若要單獨描述其中一個，請手動建立並連線。其接腳便不再為 `wired=false`，自動補齊亦會略過它。沒有單獨取消某項產生的機制。
- **快照。** 所有產生規則看到的都是同一份快照——8.2 步驟 3 至 5 的結果（經依 key 覆寫後，帶有所有物件的符號與步驟 5 的走線樹），彼此看不到對方產生的結果。因此同一條規則寫兩次會產生兩份。
- 產生的事實在衝突取捨中佔用其產生規則的位置（8.5）。
- 沒有位置的產生物件由求解器擺放；若要指定擺放方式，須使用內含約束的定義。
- **寫回。** 單一產生物件無法引用（5.7）。求解器寫回它們時，會將其寫作明確敘述，例如 `$IO_PORT @ATTACH &out => @PLACE(40, 20) => %p_out` 及其連線。唯有當規則會略過已書寫的項目時（如同標準套件的自動補齊僅選取未連線的接腳 10.1，以及按網路自動補齊以兩個集合的差集寫出，見下文），明確物件才會取代產生物件；否則規則會在明確物件旁再產生一個沒有位置的物件。因此，凡由求解器擺放物件的規則皆應以上述兩種方式之一略過已書寫的項目。以此方式寫出的明確用例定義本體中若有無區域名稱的物件，則以編號引用（5.9）。該用例會帶上規則在套用處所寫的優先順序，或寫上 `"disabled"`（當它從規則的記錄標頭繼承該值時，14.8）；否則不寫優先順序，使其定義本體保留原有的優先順序，且記錄標頭不再寫入其他優先順序。
- 產生不會遞迴：當產生規則展開的內容包含步驟 5 或步驟 6 的規則（10.4）時，這些規則會失效，因為這兩個步驟各自只執行一次。其中的其他規則在後續階段照常生效：SET-SYMBOL 於步驟 7 的符號佇列；PLACE、ORIENT、LAYER、PRIORITY 與約束於步驟 8，使所產生用例的定義本體能擺放與定向其角色收到的物件；SET-STYLE 於樣式佇列；斷言於檢查時（8.2、15.3）。
- 當觸及下方層級的產生規則（10.1）的另一個角色填入了一個屬於該層級的物件（場景物件或宿主物件）時，該規則僅在寫作它的層級生效，並給出警告：這些物件屬於該層級，下方層級沒有它們。填入定義的角色不受此限。
- 產生所建立的 SET-SYMBOL 或 SET-STYLE 屬於產生它的規則所在的組別，位於該規則的位置（8.3）。
- 綁定至篩選或產生集合的名稱不得再次綁定（6.6）。
- **按網路自動補齊。** 沒有內建的「已存在則不新增」規則。自動補齊以兩個集合的差集寫出；會加上連接埠標記的套件寫作：

  ```rnl
  $PORT_FILL_SET = # @SELECT-NET(port=true, recursive=true);                                /* the nets that get a port tag */
  # @SELECT-USAGE(recursive=true) $IO_PORT => @SELECT-NET => @REMOVE-FROM $PORT_FILL_SET;   /* less those that have one */
  $IO_PORT @ATTACH $PORT_FILL_SET
  ```

  - 標準系列 0.4 的自動補齊即以此方式寫成，其集合位於 `rnl-std-basic`，並且還將每個層級的標記排成一欄（12.4）。它讓電源與接地網路留在集合中；若檔案不想在其短樁所在之處加上標記，須寫 `$SUPPLY_NET_SET @REMOVE-FROM $PORT_FILL_SET; $GROUND_NET_SET @REMOVE-FROM $PORT_FILL_SET`。
  - 手動寫出的連接埠標記會取代產生的標記：寫了 `$IO_PORT @ATTACH &inp => @PLACE(0, 20) => %p` 之後，inp 不會再獲得產生的連接埠標記。使用者亦可從 `$PORT_FILL_SET` 移除網路（如 `# @SELECT-NET(name="vdd") => @REMOVE-FROM $PORT_FILL_SET`），或計入使用者自身連接埠定義的用例：`# @SELECT-USAGE $MY_PORT => @SELECT-NET => @REMOVE-FROM $PORT_FILL_SET`。
  - 產生的連接埠標記不計入：產生規則在步驟 6 使用 `$PORT_FILL_SET`，而差集中的篩選是在步驟 6 之前的狀態上評估的（5.2）。
  - 附註：不內建「已存在一個」判斷的原因，在於對於具有多個角色的定義其含義並不明確、使用者自訂的連接埠定義將不會計入，且重複的佈局定義只不過重複產生約束，而這本就由衝突取捨與優先順序處理（8.5、14.8）。
- 在按端子自動補齊中，取代產生物件的依然是手動寫出物件的連線：一旦接腳有連線，即不再是 `wired=false`。同樣沒有單獨取消某項產生的機制：從集合移除網路僅改變該集合本身。
