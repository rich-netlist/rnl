## 13 連線與文字

### 13.1 連線：WIRE

```rnl id=w13
&x @WIRE(mode="straight") {#M1:1 (10, 37) #M3:1} => @SET-STYLE $signal => %w13;
&out @WIRE(mode="manhattan") {#M2:1 #M4:1};
&tail @WIRE {#M1:3 #M5:1}                    /* no mode: "auto", routed freely */
```

- WIRE 接收一條網路（或一組網路的集合，藉此構成匯流排；見下文）與一個至少包含兩個點的有序列表。點可以是點物件或接腳，包含虛擬組件的接腳；端子代表其接腳（5.2.4）。點可以重複；當第一個點與最後一個點相同時，該連線構成迴路。
- WIRE 不接收篩選結果，也不接收依賴篩選的集合（10.4）：傳入這類集合會失效。求解器會將連線連同其轉折點以該條連線的身份寫回記錄（14.8），而由篩選建立的連線沒有對象可供寫回；若要將篩選所得的接腳繪製為連線，須使用 ROUTE-OBJECT（13.7）。
- **走線模式**：連線依序通過列表中的每個點；相鄰兩點之間的走線方式由參數 `mode=` 決定。對於相鄰兩點 A(x1, y1) 與 B(x2, y2)，設 dx = x2 − x1 且 dy = y2 − y1：

  | `mode` | 自 A 至 B |
  |---|---|
  | `"auto"`（預設） | 由求解器決定，求解器可依情況最佳化並將路徑寫回記錄（見下文，14.8）；在連線求解前，依下述預設路徑繪製，當沿途無阻礙時求解器亦採用該路徑 |
  | `"straight"` | 一條直線線段 |
  | `"horizontal-vertical"` | A → (x2, y1) → B |
  | `"vertical-horizontal"` | A → (x1, y2) → B |
  | `"manhattan"` | 若 \|dx\| ≥ \|dy\|：先水平走一半 dx、再垂直走完整段 dy、最後水平走另一半 dx：A → (x1 + dx/2, y1) → (x1 + dx/2, y2) → B；否則將 x 與 y 互換 |
  | `"manhattan45"` | 若 \|dx\| ≥ \|dy\|：先水平走 (\|dx\| − \|dy\|)/2、再走一段 45° 斜線（兩軸各走 \|dy\|）、最後水平走完剩餘距離；否則將 x 與 y 互換 |

  - 除 `"auto"` 外的每種模式皆為嚴格規則，檢視器依定義繪製。當 dx 或 dy 為 0 時，所有模式皆給出一條直線線段。當 |dx| = |dy| 時，`"manhattan"` 採用 |dx| ≥ |dy| 的分支，而 `"manhattan45"` 則是一條斜線線段。走線模式計算出的轉折點保留其精確數值而不予四捨五入；它們可能落在半個單位上（11.7）。
  - **`"auto"` 的預設路徑**：相鄰兩點之間的每段線皆以水平與垂直方向行進。具有方向（9.2.4）的接腳端點（經所屬物件朝向變換後）為有向端點：線段沿該方向或與其成直角離開它，並逆該方向或與其成直角抵達它，絕不反向；以直角離開或抵達計為一個轉折。無方向的接腳與點則為無向端點，不構成方向約束。線段不會穿過自身任一端點，也不會與自身重疊。在滿足上述條件的所有路徑中，預設採用轉折點最少者；其次最短者，其中只為折返而向外延伸的一段長度為 1；再其次為在較少有向端點處轉彎者，並優先保持第一個端點的方向，其次才是最後一個端點的方向；再其次為中間段位於兩端點正中央者（與 `"manhattan"` 相同）；在兩個無向端點之間，採用先水平行進者（僅有一個轉折點的 L 形）；繞道時則偏向第一個有向端點的左側（將其方向逆時針旋轉 90 度）。包含中間點的連線作為整體統一決定：中間點均為無向端點，在中間點處轉彎計為一個轉折，且連線不得在中間點處折返，因此能在中間點直行通過時便會直行。其轉折點同樣保持其精確值，可落在半個單位上（11.7），例如其中間段位於相距一個單位的兩端點正中央時。
  - 由模式自動產生的轉折點不是物件：無法對其引用，也無法在其上放置交接點。若要在轉折點處分接分支或繪製交接圓點，須將該轉折點寫成明確的點。自由點 `(_, _)` 會先由求解器決定其座標，再依所選模式連線。
  - 未列於上表的 `mode` 值屬於無效參數值，會使該連線失效。
- **樣式參數**：WIRE 亦可將線條樣式屬性作為參數傳入：`linecolor`、`linestyle`、`linewidth`、`cap`、`join`（9.3）。這些參數構成該連線的直接樣式（8.3），例如以 `@WIRE(linestyle="bold")` 繪製電源軌，或以 `@WIRE(linestyle="dashed")` 繪製基底連接。
- **改寫連線。** 若在網路槽位傳入一條連線而非網路，WIRE 不會建立新連線，而是改寫該連線。該敘述依新建 WIRE 的方式讀取，其點列表與模式會取代原連線的點列表與模式；原連線的網路保持不變。樣式參數成為該連線的直接樣式（8.3）。
  - 改寫具有一個 key，即該連線本身：較後寫的改寫會取代較早寫的點列表與模式（8.4）；同一條管線的兩段中，較後段即為較後者（5.5）。每次改寫中的樣式參數皆保留為該連線的直接樣式，並依 8.3 逐屬性解析。改寫不是幾何事實（8.5）。
  - 失效的改寫（例如列出沒有接腳的端子，9.2.4）是一項錯誤且不產生任何效果，包含其樣式參數在內；該連線維持先前有效的點列表與模式，即前一次改寫或建立該連線時所用的內容（5.8）。每條失效的改寫皆會回報，即使被較後者取代亦同。
  - 與新建連線相同，改寫自 8.2 的步驟 3 起生效：`wired=`（10.2）讀取最後一次改寫的點列表，即使該改寫在步驟 7 之後才失效亦然（7.1）。
  - 網路槽位接收一條網路、一組網路的集合，或一條連線；包含連線的集合屬於種類錯誤。
  - 求解器即透過此方式將它為每條 `"auto"` 連線選定的走線路徑寫回記錄（14.8）。它應按順序保留該連線在撰寫者記錄中（經最後一次改寫後）的點，僅在點與點之間加入以座標寫出的轉折點，並寫出 `mode="straight"`：連線的連接關係由撰寫者寫定，求解器僅決定其幾何形狀。
  - **拆分連線。** 在由 ROUTE-NET 或 ROUTE-OBJECT 之走線樹所連接的網路上（13.7），求解器可以從撰寫者所寫連線的中途分出分支。此時求解器會在其自身的記錄中改寫該連線（依名稱或編號，5.9），按順序保留撰寫者的點並將分支點作為獨立的點插入其中，再將分支連接至該點。對於其他連線，求解器僅依前項所述修改。這是改寫而非刪除：撰寫者原本的敘述保持不變。
  - 當使用者在編輯器中重塑連線形狀時，編輯器亦會在自身記錄中寫出相同的改寫；求解器隨後保留該改寫後的連線。
  - 若要在敘述本身固定路徑，須將轉折點寫成明確的點並使用 `"auto"` 以外的模式；保留精確形狀的匯出器會寫出 `mode="straight"` 並列出每個轉折點。
- **同一條網路上的多個端子**（原則 2.6）透過共用點的多條連線相互連接。唯有共用同一個點物件（具名點）或同一個端子時，連線才彼此相連；座標相同並不會將它們連接起來（原則 2.2）。本標準沒有直接寫出一棵樹的敘述，也沒有圖形（graph）物件。
- **T 型交接**：貫穿的連線將交接點列為其中一個中間點即可，無須拆成兩條；分支則自該點出發（見 13.2 範例）。沒有「連線線段上的點」這種概念。
- **彼此接觸的接腳**：當兩支接腳繪製在同一點上且之間沒有線段時，仍須寫出一條連線來連接兩個端子，例如直接繪於電容接腳上的接地符號：`&0 @WIRE(mode="straight") {#C1:2 %g3::pin}`。其兩端點重合且長度為 0，因此不會繪製出線段，但它聲明了連接關係：兩支接腳皆成為已連線（10.2），標準套件也不會再加第二個接地。僅座標相同不會建立連接（原則 2.2）。將「依位置連接接腳」的原理圖轉換為 RNL 的匯出器須寫出此類連線；當一條連線直穿過一支接腳或一個交接點時，須將該點列為中間點（T 型交接）；當一個交接點僅連有一條連線且恰好位於一支接腳上時，須將該連線直接連至該端子。
- **網路僅為聲明**，且必須寫出。端點實際所屬的網路無須與之相符，且不予檢查（原則 2.2）；網路亦不會從端點推導而來，端點之間甚至可以屬於不同網路。
  - 當點列表中的某個端子或接腳不位於該連線所屬的網路上（對匯流排連線而言：不在其網路集合中）時，會給出警告：多半是端子寫錯，例如將 `#R1:2` 誤寫為 `#R1:1`。端子或接腳所屬的網路是已知的（虛擬組件的接腳位於填入它所綁定角色的網路上，12.1）；點以及未綁定任何事物的接腳沒有所屬網路，不予檢查。該連線本身仍屬合法並會照常繪製（原則 2.2、7.6）。
- **無網路的連線**：網路槽位亦接收空節點，如 `& @WIRE {%sub1::y %int1::a}`（6.3）。該連線會如同其他連線般繪製與求解，且其端點所在的接腳成為已連線（10.2），但它不屬於任何網路：兩條此類連線即使共用一點而繪製成相連，仍不屬於同一網路；ROUTE-NET 與 ROUTE-OBJECT 的走線樹皆不會採納它們；且該連線的 `${net}` 為空文字。若其列表中出現位於某條網路上的端子或接腳，會給出前述警告；若在某條網路之連線的列表中出現位於空節點上的接腳亦同：否則圖面上將顯示電路中並不存在的連接。空節點不得作為匯流排集合的成員。
- **匯流排**：網路槽位接收單一網路，或將一組網路的集合視為整體。當傳入集合時，該連線即為匯流排連線，即使該集合僅有一位成員亦然。網表中沒有匯流排（6.11）；匯流排僅是將多條網路繪製為一條線的繪圖方式。

  ```spice
  * A 4-bit bus between two blocks, with two taps
  * @RNL(type="header") { @VERSION("0.4"); @USE-PACKAGE(name="rnl-std-all", version="0.4")}
  .subckt blk D<3> D<2> D<1> D<0>
  RL D<3> D<0> 1k
  * @RNL {
  *   $BLK_SYM = @DEFINE-SYMBOL {
  *     (-3, 0) @PIN(terminal=["D<3>", "D<2>", "D<1>", "D<0>"], label="D<3:0>", direction="left");
  *     @RECTANGLE {(-3, -2) (3, 2)}
  *   };
  *   # @SET-SYMBOL $BLK_SYM                                             /* one bus pin for four ports (9.2.4) */
  * }
  .ends blk
  XA D<3> D<2> D<1> D<0> blk
  XB D<3> D<2> D<1> D<0> blk
  RT3 D<3> 0 1k
  RT2 D<2> 0 1k
  * @RNL {
  *   %t3 = (20, 10); %t2 = (24, 10);
  *   %bus = &D<3:0> @WIRE(linestyle="bold") {#XA:D<3> %t3 %t2 #XB:D<3>};   /* a bus between the bus pins of XA and XB */
  *   %bus @TEXT("D<3:0>");                                                /* the name of the bus, written out */
  *   &D<3> @WIRE {%t3 #RT3:1};                                            /* a tap: a single wire that shares %t3 with the bus */
  *   &D<2> @WIRE(mode="straight") {#RT2:1 (23, 9) %t2}                    /* its last stretch enters the bus at 45° */
  * }
  .end
  ```

  - 集合的順序即為各位元的順序，且保留重複項；直接寫在該集合內部的集合會依序展開至最內層成員。出現非網路的成員會使連線失效（種類錯誤）。空集合亦會失效：連線至少須承載一條網路（5.2.1）。
  - 網路槽位屬嚴格輸入（7.3）：當其中一個位元找不到時，整條連線失效，如同找不到單一網路一般。
  - 點、`mode=`、樣式參數、交接圓點與 T 型交接皆與一般連線相同。沒有 BUS 關鍵字：實作以繪製連線的方式繪製匯流排，將其畫粗僅為樣式問題（1.5 第 7 項）。匯入器可以直接寫出 `linestyle="bold"`；標準套件則預設透過 SELECT-WIRE 的 `bus=true` 條件將匯流排連線設為粗線（10.1、16.3）。
  - **分接（tap）**無須專屬機制：與匯流排共用一點的單一連線即為分接，而匯流排將該分接點列為中間點（T 型交接）。進入匯流排前的 45° 短斜線僅是該單一連線最後一段的走法。分接符號則是套用在分接點上的定義，屬於標準套件（16.3）。位元名稱透過單一連線上的標籤 `${net}` 顯示（13.3）。單一連線的網路是否屬於該匯流排不予檢查（原則 2.2）；實作可以給出提示。
  - 分接亦可從匯流排的端點出發：止於某一點的匯流排可以從該點延續為多條匯流排或單一連線，例如一條主幹（trunk）`BOT<10:0>` 止於該處，並分出 `BOT<10:3>` 與 `BOT<2:0>`，該處帶有一個交接圓點（13.2）。主幹將該點列為端點，各分支各自承載其位元。凡從一條承載了它們所有網路的連線所經過或終止之點出發的連線——此處即主幹——皆為該連線的分接，彼此之間並不相連：若某實作會在「一條連線止於另一條不同網路的連線」時發出看似相連的警告，不應對這些分接發出警告。
  - 匯流排連線的屬性 `net` 為按順序以 `,` 連接（不加空格）的網路名稱，如 `D<3>,D<2>,D<1>,D<0>`；若要顯示 `D<3:0>`，須直接寫出該文字。實作不會自行縮寫列表：縮寫取決於宿主命名習慣，沒有唯一結果。
  - 因此 `{&a &b} @WIRE {…}` 是一條匯流排連線，而非兩條重疊繪製的連線。
  - 多個宿主實例繪製為單一符號（迭代實例）應寫成疊畫（11.8）。
- 連線所連接的端子在其符號中必須擁有接腳；否則該連線失效（9.2.4）。
- 彼此接觸、交叉或重疊的線段僅為幾何圖形，不建立任何連接（原則 2.2）。未共用點而交叉的連線不繪製圓點；交叉處的小跨弧等畫法屬於樣式與實作細節。
- 每條給予網路的 WIRE 都是不帶 key 的新物件：寫兩次即建立兩條連線（5.8）。若要在其他敘述中引用一條連線，須為其命名；求解器的記錄則透過編號引用未命名的連線（5.9）。以端子為端點的連線會隨其器件移動；以座標寫出的點不會移動；具名點則可被約束。
- **未繪製的連接**：在 RNL 中沒有連線的連接如何呈現（由求解器走線並寫回為 WIRE、以飛線或標籤顯示），由求解器與檢視器的風格體系以及所使用的風格體系套件決定；本語言對此不作規定。風格體系套件可透過規則產生標籤或連線，這些屬於 RNL。若要將某條網路繪製為連線並將走線路徑交給求解器決定，須撰寫 ROUTE-NET 或 ROUTE-OBJECT（13.7）。

### 13.2 交接圓點

```rnl
%j1 = (10, 30);
&x @WIRE {#M1:1 %j1 #M3:1};          /* the through wire passes %j1 */
&x @WIRE {%j1 (30, 30) #M4:2};       /* the branch starts at %j1 */
$JUNCTION @ATTACH %j1                /* draws the dot */
```

- 分支是多條共用同一個點的連線（13.1）。
- 交接圓點須明確寫出：僅在套用了繪製圓點的定義（例如標準套件的 `$JUNCTION`）之處才會繪製圓點；渲染器不會自行加上圓點。
- 圓點是一個用例，而非關鍵字。`$JUNCTION` 是標準套件中的定義，具有一個接收點或端子的角色；其定義本體將該用例的點綁定至該點或該端子的接腳（12.1 第 5 項），如同 `$NO_CONNECT`（12.6）與電流箭頭（15.2）。當兩條連線在某個端子的接腳處相會時，它亦可套用於該端子。標準套件為這些用例指派實心圓點作為符號：圓點大小取自符號，顏色取自該用例樣式的 `linecolor`；圓點大小沒有獨立的設定項。
  - 對同一點套用兩次 `$JUNCTION` 會產生兩個上下重疊的圓點，外觀上仍如一個。
  - 所有交接圓點皆可以 `# @SELECT-USAGE $JUNCTION` 選出。
  - 繪圖順序跟隨指派符號的規則位置（11.6）。標準套件的規則排在最前，因此圓點繪製於連線之前；圓點與連線同色且比連線更寬，因此視覺上毫無差別，無須使用 LAYER。
- 圓點不會依共用點相會的連線數量自動推導：實際原理圖中存在僅兩條連線相會卻繪有圓點的分支點，而自動推導的圓點還需要額外機制才能移除。匯出器須寫出原圖所顯示的圓點。當三條以上連線在共用點相會卻沒有圓點時，實作可以給出提示；本標準對此不作強制要求。
- **求解器加入的圓點**：求解器的輸出同樣是 RNL，且可以包含圓點。它所使用的定義由 SOLVER-CONFIG 的 `junction` key 指定（14.10），為寫成字串的 `$` 名稱，如 `junction="$JUNCTION"`，或在層級記錄的 SOLVER-CONFIG 中為該層級的 `%` 名稱，如 `junction="%BIG_DOT"` 以繪製僅限該子電路使用的較大圓點；標準套件為使用它的層級設定了 `$JUNCTION`（16.3）。設有該 key 時，求解器會將該定義套用至 ROUTE-NET 與 ROUTE-OBJECT 走線樹（13.7）的每個分支點；若使用者所寫的連線有三條以上在某個共用點相會且尚未有該定義的用例，求解器亦可在其輸出中加上一個圓點。未設該 key 時不寫出圓點，且 `junction=""` 可在套件已設定時將其關閉。該名稱依「寫在該層級之求解器記錄中的名稱」方式查找（6.8）；其他任何值若未指向該處的定義，或其第一個角色不接收點，則為該層級中不被接受的值（14.10）：這是錯誤，且該 key 視為在該處未寫出，因此沿用先前的值；若沒有先前的值，求解器不寫出圓點。共用點必定是具名點或端子（座標相同不計），因此圓點一定能寫出。其他會加入圓點的工具（如編輯器）從同一個 key 取得定義。
- 圓點僅供繪圖：它不建立任何連接，亦不予檢查（原則 2.2）。只有 `$JUNCTION` 而沒有連線的點仍會繪製出圓點。

### 13.3 文字：TEXT

```rnl use=w13
(50, 18) @TEXT("5T OTA testbench");                         /* an annotation: attached to a point */
(1, 1) @TEXT("see here") => @PLACE(2, 2);                   /* attached to (1, 1); the text itself is at (2, 2) */
#M1 @TEXT("W/L=${w}/${l}", key="wl") => @PLACE(12, 18);     /* a label: attached to M1, with the key wl, so it is #M1::wl */
#R1 @TEXT("R_{D}", key="name");                             /* a key the symbol has: new content, the position still from the symbol */
#M1::name @PLACE(13, 18);                                   /* the name of M1, dragged in an editor */
%w13 @TEXT("${net}");                                       /* the net name on a wire; no key; placed by the implementation */
&out @TEXT("${name}");                                      /* shows the name of the net out; placed by the implementation */
# @SELECT-INSTANCE => @SELECT-PIN(wired=false) => @TEXT("${net}", key="netname")    /* net names on pins without wires */
```

- **空文字**：內容為空字串的 TEXT 不繪製任何內容。帶有 key 時，它會取代符號上具有該 key 的標籤，從而將其隱藏。標準套件 `rnl-std-no-labels` 改用樣式 `textvisible=false` 來隱藏預設標籤（9.3、16.3），這會保留標籤內容，因此帶有相同 key 與 `textvisible=true` 的 TEXT 能讓該標籤重新顯示。
- **附著**：TEXT 接收一個點或一個被繪製的物件，並附著於其上。它所附著的對象決定三件事：`${…}` 讀取誰的屬性（13.6）；未給定位置時文字擺放在何處；以及當它帶有 key 時，該文字屬於哪個物件的子物件。
  - 點（`(x, y)`、具名點、`::position`）：該文字是一條標註（13.4）。它僅能引用該點的 `x` 與 `y` 屬性。
  - 物件：該文字是一個標籤。該物件可為實例、被繪製的用例、疊畫、接腳、端子（位於其接腳處，5.2.4）、連線或圖形。它亦可為一條網路：網路本身不被繪製，實作會將附著於網路的文字擺放在其某條連線或某個端子旁。檔案便是藉此指明哪些網路要顯示名稱。
  - 沒有符號的用例或沒有接腳的端子在繪圖上沒有意義：傳入此類對象會使 TEXT 失效（12.1、9.2.4）。
  - 傳入集合時，TEXT 為每個成員附著一條文字（5.2.1），如範例最後一行所示。
  - 在符號定義本體中，附著於點的文字是符號的固定文字；附著於單獨 `?` 的文字則附著於使用該符號繪製的物件（見下文）。
- **內容**：`text` 為必填，即使給了 key 亦同；未寫出則 TEXT 失效。它可依位置第一個傳入，如 `@TEXT("${name}", key="name")`。沒有預設內容：若要顯示名稱，須寫出 `"${name}"`。文字標記與屬性引用見 13.6。
- **位置**：文字擁有自身的位置，並非它所附著的點或物件。
  - 文字的位置最初為自由狀態，如同 `(_, _)`。若沒有 PLACE、`dx`、`dy` 或約束固定它，求解器會決定並寫回該位置（14.8）；沒有求解結果時由檢視器決定：附著於點的文字通常置於該點上，附著於物件的文字則置於該物件旁；兩者皆可移開以避免重疊。
  - PLACE 設定文字自身的位置。因此 `(1, 1) @TEXT(…) => @PLACE(2, 2)` 並不矛盾：前段將文字附著於 (1, 1)，後段將文字置於 (2, 2)。若要將標註精確置於某處，須寫出 PLACE。
  - `dx`、`dy`：偏移量，僅 TEXT 接收。當文字所附著的對象具有座標點（點、實例原點、用例繪製的點、端子的接腳）時，文字位於該點加上 (dx, dy) 處。連線與網路沒有座標點：附著於這兩者之一的文字若寫出偏移量會使該 TEXT 失效。
    - 文字依然只有一個位置，即加上偏移量後的位置；約束與求解器皆使用該位置，不存在「偏移前的位置」。當附著物件被求解器移動或擺放時，文字隨之移動；當其他約束移動文字時，附著物件亦隨之移動。偏移量等同於寫在文字上的兩個精確 DISTANCE（x 與 y 各一）：正偏移朝遞增方向（`"left-to-right"`、`"bottom-to-top"`），負偏移朝遞減方向，大小寫為 `exact`（14.5）。
    - 偏移量沿著場景的座標軸計算，不會隨附著物件的朝向旋轉，因為場景中的文字不隨物件旋轉。在符號定義本體中亦可寫出偏移量；該處採用區域座標，會如同以 `=> @PLACE(…)` 寫出的區域位置般隨實例變換。
    - **偏移量與 PLACE 互相取代**：在每條座標軸上，文字的位置要嘛是絕對位置（PLACE 的 x 或 y），要嘛是偏移量（`dx` 或 `dy`），絕不同時存在。在同一個文字的同一條軸上，較後寫出的一種（依 8.5 的位置順序）生效，較早寫出的一種完全失效：若後寫偏移量，該軸上的絕對位置變為自由並依偏移量計算；若後寫 PLACE，該軸上的偏移量不再適用。這是取代，而非衝突：優先順序不參與其中，且不給出提示。例如，在寫了 `dx` 與 `dy` 之後，較後寫的 `#M1::name @PLACE(x=13)` 會使 x 變為絕對座標 13，`dx` 不再適用，而 y 仍遵循 `dy`；當以偏移量定位的文字被拖曳時，編輯器便是寫出這條敘述。符號中給出的位置排在最前（見下文），場景中的 PLACE 或偏移量會取代它。
    - 實際生效者是一項普通的幾何事實：偏移量的 x 與 y 各為一個單位，其位置即為寫出該偏移量的 TEXT 敘述的位置，其優先順序為記錄標頭的預設值（14.8）；它們依 8.5 與其他事實一同解決衝突。同一軸上的多個 PLACE 之間亦依 8.5 相互取捨。對帶有 key 的文字而言，`dx` 與 `dy` 分別覆寫（8.4）。
  - 文字可透過自身的位置成為約束的成員（14.1）。文字的 `::position` 即其自身的位置：`%n1::position @PLACE(…)` 等同 `%n1 @PLACE(…)`。
  - 場景中的文字不會隨其附著對象的朝向旋轉；若要旋轉文字，須寫出 `rotate=`。當場景透過 PLACE 或偏移量同時給出文字位置的兩條軸時，兩軸皆不再使用符號的區域位置：該文字不繼承附著物件的朝向，且 `halign` 與 `valign` 皆依場景方向解譯。
  - 求解器將它選定的位置寫回記錄（14.8）：透過 key（見下文）或文字名稱，否則透過編號（5.9）。由產生規則直接建立且不帶 key 的文字（13.3、10.5）無法被引用：求解器將其位置交由檢視器決定。在規則所建立用例的定義本體中的文字，一旦求解器將該用例寫成明確敘述（10.5、5.9），即可透過編號引用。
- **Key `key=`**：
  - 不帶 key 時，該文字是附著物件上一個無 key 的文字；寫兩次即為兩條文字，如同連線（13.1）。它可用 `%x =` 命名並在所屬層級中引用與修改。規則建立的無 key 文字沒有控制代碼，因此求解器無法寫回其位置。
  - 帶有 key 時，該文字是附著物件的子物件 `object::key`，例如 `#M1::wl`。同一物件搭配相同 key 即為同一條文字，較後寫出的敘述會逐參數覆寫它：字級、對齊、旋轉等各自獨立覆寫，未寫出的參數維持原狀（8.4）。每條敘述都須寫出內容（`text` 為必填），較後的內容一律取代較早者；若只想更改對齊或旋轉，須再次寫出內容，如 `#M1 @TEXT("${name}", key="name", halign="end")`。位置則遵循 PLACE 的規則（8.5）。其他記錄、編輯器與求解器透過此控制代碼尋找該文字。
  - 附著於點的文字不接收 `key=`，因為點沒有子物件：寫出 key 會使該 TEXT 失效。
  - `::` 後方的名稱依固定順序查找，key 排在最後（6.5）：用例的角色名稱與區域名稱、其次它們的 `definition=` 別名、其次標準子物件名稱及其別名、其次物件符號的接腳名稱、最後文字的 key。因此 key 不得拼寫成任何排在它前面的名稱：標準子物件名稱（`position`、`net`）或本檔案宣告的標準子物件別名（如 `alias-zh` 的 `位置`）；該文字所附著用例的角色名稱或區域名稱；或這些名稱的 `definition=` 別名。這類 key 是錯誤，如同 6.5 的名稱衝突。寫在符號中的文字，其別名依撰寫該符號之檔案的別名檢查。`name` 與 `value` 不是標準子物件名稱，僅是常見的 key。
- **符號中的文字**：
  - 在符號定義本體中，單獨的 `?` 指使用該符號繪製的物件：繪製 M1 時即為 M1，繪製用例 `%g0` 時即為 `%g0`。它僅能作為 TEXT 的物件；在其他任何地方使用皆會失效，例如符號中的 `? @PLACE(…)` 毫無意義。
  - `? @TEXT("${name}", key="name") => @PLACE(1.5, 1.5)`：文字附著於以該符號繪製的物件，`${…}` 讀取該物件的屬性。此 PLACE 採用區域座標並隨實例一併變換（見 9.2.5 中的文字方向）。未寫 PLACE 時，實作將文字擺放在該物件旁。
  - 帶有 key 的文字是以該符號繪製之物件的子物件，例如 `#M1::name`。符號中的文字排在最前，場景中帶有相同 key 的文字逐參數覆寫它：`#R1 @TEXT("R_{D}", key="name")` 僅更改內容並保留符號中的位置；`#M1::name @PLACE(13, 18)` 僅更改位置並保留符號中的內容。場景中給出的位置採用場景座標，不再隨實例轉動。
  - 由符號帶入的 key 唯有在指派符號之後才會存在（8.2 步驟 4 與步驟 7）。當 M1 的符號沒有 key 為 `name` 的文字且場景中也未寫出時，`#M1::name` 失效。若要不依賴符號，須在場景中寫出帶有該 key 的 TEXT。
  - 符號中附著於點的文字為固定文字（例如運算放大器符號中的 `(-2, 2) @TEXT("+")`），無法針對單一實例修改。
- **規則**：諸如 `# @SELECT-INSTANCE => @SELECT-PIN(wired=false) => @TEXT(…)` 的規則選取來自符號的接腳，因此會在步驟 6 隨逐一產生一併評估（8.2）。當實作自行加上飛線或標籤時，會略過已有標籤的接腳。
- 預設情況下顯示哪些網路名稱、顯示於何處，以及沒有連線的連接以標籤還是飛線顯示，皆由實作決定：這屬於它的風格體系（原則 2.7）。以標籤代替連線會改變佈局，因此求解器與渲染器須採用相同設定。RNL 僅在需要時才寫出它們：用以表達設計意圖（不寫位置），或用以保留已決定的位置。
- 沿著連線沒有位置概念：連線本身的座標不是固定物件。
- **`fix_rotate`**：布林值，預設為 `false`。設為 `true` 時，文字的 `rotate` 依場景計算：無論文字附著物件的朝向為何，字元皆保持該方向。文字的錨點仍跟隨該物件，文字方塊位於錨點哪一側亦同。對齊方式決定方塊相對於錨點的位置：`start` 在右、`end` 在左、`bottom` 與 `baseline` 在上、`top` 在下、`middle` 則不偏任一側。該方向隨物件的朝向一併變換，文字依變換結果對齊。因此寫在符號上方且 `halign="middle"`、`valign="bottom"` 的名稱，當符號旋轉 `"R90"` 時會位於錨點左側並以 `end` 與 `middle` 對齊，在 `"MX"` 時則位於錨點下方並以 `top` 對齊；它在各種朝向下皆維持水平閱讀且留在符號外側。若方塊仍位於錨點上方，則保留原本寫出的 `bottom` 或 `baseline`。
- **`upright`**：布林值，預設為 `true`：當文字原本會上下顛倒閱讀時，將其旋轉 180 度，且字形不鏡像翻轉。設為 `false` 時，字元直接依原樣跟隨旋轉與鏡像（9.2.5）。
- 參數：`text`（必填；可依位置傳入）、`key`、`dx`、`dy`、`halign`、`valign`、`rotate`、`fix_rotate`、`upright`，以及文字樣式屬性 `textcolor`、`size`、`font`、`bold`、`italic`、`textvisible`（9.3）；附著於點的文字沒有 `key`。`halign`、`valign` 與 `rotate` 見 9.2.5。樣式參數是文字的直接樣式（8.3）；文字如何取得樣式見 11.3。

### 13.4 標註：場景中的圖形

```rnl
(50, 18) @TEXT("5T OTA testbench") => @SET-STYLE $note => %n1;
%f1 = @RECTANGLE {(0, 0) (40, 30)};
%n1 @PLACE(60, 18)                            /* moves the text; may also be written in another record */
```

- LINE、RECTANGLE、CIRCLE、ELLIPSE、ARC、BEZIER 與 TEXT 可直接寫在場景中，因此亦可寫在一般定義的定義本體中。在符號定義本體中它們使用區域座標；在場景中則使用場景座標。書寫位置決定座標系；關鍵字相同。
- 原則 2.2 中的註記物件（自由文字、圖形、外框與其他僅供繪製、沒有端子也沒有電氣含義的物件）即為本標準的標註：寫在場景中的圖形、附著於點的 TEXT，以及由 ANNOTATION 繪製的符號（13.5）。
- PIN 僅能寫在 DEFINE-SYMBOL 的定義本體中：接腳綁定以該符號繪製之物件的端子，而場景中沒有這類物件。
- 附著於點的 TEXT 是一條標註（13.3）：它僅能引用該點的 `x` 與 `y` 屬性，且不接收 `key=`，因為點沒有子物件（寫出 key 會使該 TEXT 失效）。若要顯示物件的名稱或數值，須將 TEXT 附著於該物件，使其成為標籤。
- 圖形的位置由它的點決定。點可以是任何點物件：具名點、帶有約束的自由點，或跟隨器件移動的 `#M1::position`。在一般定義的定義本體中，字面點是相對於用例自身之點的偏移量（9.4）。PLACE 不接收圖形本身：若要從另一筆記錄移動以中心形式寫出的 RECTANGLE、CIRCLE 或 ELLIPSE，須移動其 `::position`；LINE、ARC、BEZIER 以及以兩點寫出的圖形擁有多個點，因此須為這些點命名再移動它們。TEXT 是例外：它有自身的位置，所附著的點僅提供預設位置，PLACE 直接設定文字的位置（13.3）。
- 外觀：圖形可直接接收樣式參數（9.2.5），亦接收 SET-STYLE，並適用 8.3 的兩個層級；兩者皆未給定的屬性採用渲染器的預設值。
- 外框是一個 RECTANGLE，或最後一點與第一點相同的 LINE。沒有能直接框住一組物件的圖形：須繪製一個 RECTANGLE 並約束其角點位於該群組外側，例如 `%tl %stage1_set @DISTANCE("left-to-right", min=1)` 會使該角點至少位於每個成員左側 1 個單位處（14.5）；框住的範圍是成員的點加上邊距。檢視器可以將 GROUP 繪製成外框；此由檢視器決定（11.5）。沒有 `::box`。
- 繪圖順序跟隨圖層與位置（11.6）。
- **分類**：某物件是否為標註取決於其物件種類：場景中的圖形即為標註，因此渲染器可將它們作為一類顯示或隱藏。SELECT-ANNOTATION 選取場景中的所有圖形以及 ANNOTATION 所繪製的內容（13.5），包含從一般定義之定義本體展開而來的圖形（例如風格體系套件繪製的外框）；符號內的圖形、標籤、連線與用例（含交接圓點）皆非標註。更細的分類（說明文字、圖框標題欄、套件繪製的裝飾）以具名集合表示，單一圖形可屬於多個集合。顯示與隱藏由檢視器決定；本語言沒有 `visible`。
- 器件上的文字是附著於該器件的 TEXT，亦即標籤（13.3）。附著於 `#M1::position` 的 TEXT 則是標註；預設情況下它同樣跟隨該器件，但僅能引用該點的座標，且沒有 key。

### 13.5 繪製為標註的符號：ANNOTATION

```rnl
%a1 = (40, 20) @ANNOTATION(rotate=30) $ARROW_SYMBOL;     /* an arrow at any angle */
#M1 @ANNOTATION(rotate=-45, mirror=true) $ARROW_SYMBOL;   /* follows M1 */
%a1::position @PLACE(44, 20)                             /* moves the first one */
```

- ANNOTATION 收集傳入對象的圖形並將它們繪製為單一標註（13.4），可旋轉任意角度。兩個槽位：寫在前面的 `at`，接收一個可定位物件：一個點，或該標註所跟隨其位置的物件；以及寫在最後的 `source`，接收以下三者之一：
  - 符號（DEFINE-SYMBOL）：其定義本體中的圖形與 TEXT；
  - 一般定義（DEFINE），不論有無角色：直接寫在其定義本體中且所有點皆為字面點（相對於用例之點的偏移量，9.4）的圖形，以及附著於這類點或附著於 `?` 的 TEXT。該定義不會被套用：不建立任何用例，因此不會繪製兩次；
  - 用例：當它擁有符號時（一旦賦予符號，8.2）其符號的圖形，加上其定義本體中僅使用字面點繪製的圖形（與定義相同），繞該用例的點擺放。該用例本身仍照常繪製在原處。
- 其餘內容一律略去：PIN、`box=`、約束、定義本體中建立的用例，以及定義本體中任一點落在其他物件上的圖形（例如連至某個角色的線段，移動旋轉後便毫無意義）。因此被略去的圖形會給出提示；其餘內容則靜默略去，以便帶接腳的符號能重用於標記。沒有任何東西會填入角色；該標註沒有接腳、不能作為連線端點，且不屬於 13.7 的任何走線樹。
- **參數**：`rotate`，逆時針角度（度），任意數字，預設為 `0`；`mirror`，布林值，預設為 `false`，在旋轉前先將符號沿垂直軸鏡像翻轉；以及樣式屬性，如同 SET-STYLE（11.3）賦予其圖形與文字。它亦依名稱接收作為 `source` 傳入之符號或一般定義的參數，如同 AS（9.4），例如 `(0, 0) @ANNOTATION(rotate=30, w=5) $D`：未傳入的參數取預設值，沒有預設值者視同未寫出（9.4）。當來源的參數與 ANNOTATION 自身的參數（如 `rotate` 或 `mirror`）同名時，取用 ANNOTATION 的參數，並給出提示。傳入用例作為 `source` 時，該用例保留自身的參數值，若在 ANNOTATION 上寫出其定義的參數則屬於無效參數。符號中的文字隨標註一併旋轉，方式與符號文字隨實例旋轉相同，依循文字自身的 `rotate`、`fix_rotate` 與 `upright`（9.2.5）。
- 在符號的文字中，`?` 指該標註本身，它僅擁有 `x` 與 `y` 屬性（如同點，13.4）；其他屬性引用一律繪製為空文字。
- **結果**：一個新的標註，擁有子物件 `::position` 作為其錨點。傳入寫出的點時，錨點起初位於該點並可透過 `::position` 移動，如同以中心形式寫出的圖形（13.4）；傳入物件時，錨點跟隨該物件的位置。SELECT-ANNOTATION 選取它，SET-STYLE 為它設定樣式，`textvisible` 隱藏它的文字。
- 其種類在讀取書寫位置時即已確定：在 `source` 槽位傳入符號、一般定義或用例以外的任何東西皆為錯誤；沒有任何可繪圖形的來源會給出警告且不繪製任何內容。
- **與其他項目的比較**：寫在場景中的圖形（13.4）各有自身的點；帶有符號的用例（如標準套件中的圖示）以 11.2 的八種朝向繪製，可擁有接腳並可連線。ANNOTATION 則以任意角度繪製符號且不具任何電氣含義。

### 13.6 文字標記與屬性引用

```rnl
#R1 @TEXT("R_{D}", key="name");                              /* subscript */
(50, 18) @TEXT("\textbf{5T OTA} testbench\\VDD = 1.8 V");    /* bold, two lines */
#M1 @TEXT("W/L=${w}/${l}", key="wl");                        /* host parameters */
$NMOS_M = @DEFINE-SYMBOL {
  $NMOS;
  ? @TEXT("${model}", key="model") => @PLACE(1.5, -1.5)      /* the model name, in a symbol */
}
```

- **標記語法**是 LaTeX 文字模式的子集，而非完整 TeX：

  | 標記 | 含義 |
  |---|---|
  | `_{…}`, `^{…}` | 下標、上標 |
  | `\textbf{…}`, `\textit{…}` | 粗體、斜體 |
  | `\overline{…}` | 上劃線，如低態有效的 `\overline{RST}` |
  | `\subrest{…}` | 第一個字元按原樣，其餘作為下標：`\subrest{${name}}` 將 M1 顯示為 M₁、VDD 顯示為 V 搭配下標 DD |
  | `\subdigits{…}` | 末尾的數字作為下標：R12 顯示為 R₁₂、Vout1 顯示為 Vout₁；末尾不含數字的內容按原樣顯示 |
  | `\(…\)` | 數學模式（math mode，見下文） |
  | `\frac{…}{…}` | 分數：分子在上、分母在下、中間一條分數線，如 `\frac{${w}}{${l}}`；無法上下堆疊的檢視器顯示「分子/分母」 |
  | `\alpha` … `\omega`, `\Gamma` … `\Omega` | 希臘字母，名稱同 LaTeX |
  | `\pm`, `\times`, `\cdot`, `\infty`, `\approx`, `\neq`, `\leq`, `\geq`, `\ll`, `\gg`, `\propto`, `\parallel`, `\angle`, `\circ`, `\to`, `\uparrow`, `\downarrow` | 常用符號 |
  | `\\` | 換行 |
  | `\_`, `\{`, `\}`, `\$`, `\%`, `\&`, `\#`, `\textbackslash` | 字元 `_`、`{`、`}`、`$`、`%`、`&`、`#`、`\` 本身 |

- 希臘字母：小寫 `\alpha` 至 `\omega`（LaTeX 沒有 `\omicron`，請寫 o），以及變體 `\varepsilon`、`\vartheta`、`\varpi`、`\varrho`、`\varsigma`、`\varphi`；大寫僅限與拉丁字母不同者：`\Gamma`、`\Delta`、`\Theta`、`\Lambda`、`\Xi`、`\Pi`、`\Sigma`、`\Upsilon`、`\Phi`、`\Psi`、`\Omega`。未列於表中的符號直接以 Unicode 字元寫出（字串可容納非 ASCII 字元，3.7）。
- 標記可以巢狀，如 `\textit{V}_{\textit{DD}}` 與 `I_{D_{1}}`。`V_{in}^{+}` 等上下標的排版方式（上下堆疊或前後排列）由檢視器決定。
- **上下標必須加上大括號**：單獨的 `_` 或 `^` 是一般字元。這與 LaTeX 不同——在 LaTeX 中 `g_m` 的 m 會成為下標，但名稱與描述常包含 `vin_1` 或 `bias_ctrl`，該規則會破壞這類名稱。因此 `g_m` 會按原樣顯示。
- 其他字元皆按原樣顯示，包含在 LaTeX 中另有含義的單獨 `{`、`}`、`$`、`~`、`%`、`&` 或 `#`。
- **反斜線**：`\\` 是換行，與 LaTeX 相同；反斜線本身寫作 `\textbackslash`。後接非已知命令的反斜線會按原樣顯示並給出警告，例如 `C:\temp`（`\temp` 是未知命令；見下一項）；若要避免警告，須寫 `C:\textbackslash{}temp`。僅當反斜線緊接 `\`、`{`、`}`、`_`、`^`、`$`、`%`、`&`、`#` 或已知命令名稱時，才需要使用 `\textbackslash`。RNL 字串沒有反斜線跳脫（3.7）：`"\textbf{V}"` 直接照此寫出，而非寫作 `\\textbf`。
- 未知命令（`\` 後接不在表中的字母，如 `\sqrt` 或 `\alpah`）與未配對的大括號會按原樣顯示並給出警告；該文字仍屬有效。
- **命令名稱之後**：命令名稱是緊接 `\` 之後的一串字母。已知命令名稱之後的空格會被捨棄而不顯示，緊接其後的空 `{}` 亦僅作分隔而不顯示。因此 `10 \mu A` 與 `10 \mu{}A` 皆顯示 10 μA；若要保留空格，須寫 `\mu{} A`；`\textbackslash{}temp` 顯示 \temp。跳脫字元（如 `\_` 與 `\{`）之後的空格則會保留。

  附註：後續版本若支援更多 TeX 語法，僅能作為擴充。數學模式寫作 `\(…\)` 而非 `$…$`，因為 `$` 用於屬性引用。
- **名稱格式化**：`\subrest{…}` 與 `\subdigits{…}` 僅改變其內容的顯示方式：將顯示出的字元拆分為一般部分與下標部分。內容可包含屬性引用，如 `\subrest{${name}}`；其內容仍不作為標記解讀（見下文）。兩者可巢狀於其他標記中，如 `\textit{\subrest{${name}}}`。
- **數學模式**：`\(…\)` 容納一條公式，採用 LaTeX 數學模式的子集：
  - 字母為變數，以斜體顯示；數字與上表中的符號為正體，且不顯示空格；
  - `_` 與 `^` 接收單一字元或大括號分組，與 LaTeX 相同，因此 `g_m` 在 `\(…\)` 內會顯示為 g 帶下標 m；
  - `\frac{…}{…}`、`\sqrt{…}`、上表中的希臘字母與常用符號，以及關係符號 `=`、`<`、`>`；
  - `\mathrm{…}` 將其內容設為正體，用於單位與名稱，如 `\(V_\mathrm{DD}\)`；
  - 其中的屬性引用按原樣以正體顯示。

  不在此子集中的命令會按原樣顯示並給出警告。
- **分數**：`\frac` 後方須緊接兩個大括號分組；缺少其一時視作未知標記，按原樣顯示並給出警告。分子與分母可包含標記與 `${…}`。
- 上下標與分數的升降距離及縮小比例由檢視器決定。整段文字的字型、粗體與斜體取自樣式或參數 `font`、`bold`、`italic`（9.3）。
- 標記語法僅在 TEXT 的 `text` 與 PIN 的 `label`（如 `\overline{CS}`）中解讀。其他字串參數（`key`、列舉值、篩選條件）不解讀標記。
- 附註：在匯入與匯出時，KiCad 的 `_{…}` 與 `^{…}` 寫法相同，其 `~{…}` 對應 `\overline{…}`；Altium 在每個字元後加 `\` 的上劃線則改寫為 `\overline{…}`。
- **屬性引用** `${name}` 顯示文字所附著物件的某項屬性。若要寫出 `${` 本身，須寫 `\${`；從 `\${` 到與之配對的 `}` 之間的所有內容皆按原樣顯示，且該 `}` 不計為未配對大括號。各類物件的屬性如下：
  - 實例：`name`；`value`，宿主行上寫出的數值，按原樣顯示，沒有則為空（不會退回使用模型名稱）；`model` 與 `type`，同篩選條件（10.1），因此 X 實例的 `${model}` 顯示子電路名稱；以及宿主參數，如 `w`。與標準屬性同名的宿主參數寫作 `${#…}`（見下文）。
  - 端子、接腳與連線：`net`，它們所在的網路，顯示其名稱；對接腳而言即 `::net` 的網路（6.5），不綁定任何事物的接腳沒有 `net`。在空節點（6.3）上，`net` 為空文字，填入空節點的角色亦同，如 `${p}`：不繪製任何內容（13.3）。匯流排連線的 `net` 為按順序以 `,` 連接（不加空格）的網路名稱（13.1）。對疊畫的端子而言，當所有成員皆位於同一網路時為該網路的名稱，否則為以 `,` 連接的各名稱（11.8）。
  - 網路：`name`。
  - 用例：其定義的角色與參數。`${p}` 是填入角色 p 的物件，依下述規則顯示。用例沒有自身的名稱：接地、電源與連接埠的符號寫出 `${p}`，當 p 為網路時顯示該網路的名稱；填入端子或接腳的角色（如 `$GROUND_STUB` 的 t）同樣顯示其網路的名稱。
  - 疊畫：若某屬性在所有成員上的值相同，為該值；否則為以 `,` 連接的各值（11.8）。
  - 點：`x`、`y`，最終座標，亦即求解後的座標。
  - 圖形：無屬性。
- **屬性路徑**：在 `${a::b::c}` 中，第一個名稱取附著物件的屬性，後方每個 `::name` 取前一項結果的屬性，如 `${p::x}`（當角色 p 為點時取其 x）與 `${pair::left::w}`。
  - 屬性的值可為物件（用例的角色；端子或連線的 `net`）或文字（`name`、`value`、宿主參數等）。文字沒有屬性，因此後方不得再接 `::`。
  - 路徑上的值亦可為集合，例如集合角色。此時路徑的剩餘部分會依集合順序從每個成員取得，若其中包含集合則取其自身成員；數值依集合的顯示方式呈現（見下文）；當任一成員缺少該屬性時，該文字失效。因此若一個用例的集合角色 `pairs` 容納兩個差動對，`${pairs::left::w}` 會顯示兩個 `left` 電晶體的 `w`，如 `1u,2u`。
  - 在 `${…}` 中，`::` 僅取屬性，不同於敘述中的 `::` 取子物件（6.5）：`${m::name}` 是實例 m 的名稱，而敘述中的 `#M1::name` 則是 M1 上 key 為 `name` 的文字（13.3）。
  - `${m::#type}` 僅查找宿主參數，如同 `${#type}`（見下文）。
- **顯示方式**：當路徑最後的值為文字時，按原樣顯示。當最後的值為物件時：實例與網路顯示其名稱；端子、接腳與連線顯示其網路的名稱，匯流排連線則顯示以 `,` 連接的網路名稱；疊畫如前所述；集合（如集合角色）按上述方式顯示每個成員並以 `,` 連接。點、用例與圖形無法顯示：該文字失效。因此當角色 p 為點時，須寫 `${p::x}`，而非 `${p}`。
- 引用提供網表中寫出的原始文字，不進行求值：`w=1u` 顯示 1u。各種方言提供哪些屬性由其宿主配接器定義；例如在 Spectre 中，電阻的數值是參數 `r`。
- 上述列出的屬性必定存在；無值者為空。引用不存在的屬性名稱會使該文字失效。
- 引用取得的內容按原樣顯示，不作為標記解讀：宿主名稱與數值不以本標記語法撰寫。
- 引用僅能從附著物件的屬性向下查找；無法觸及任意其他物件。本標準不提供類似 KiCad `${R3:VALUE}` 的跨物件引用。
- **別名**：`${…}` 中的屬性名稱亦接受檔案所宣告的別名，查找順序為：標準屬性優先，其次別名，其次宿主參數；`${#name}` 僅查找宿主參數（16.5）。用例的角色與參數名稱為 RNL 名稱：它們僅接受該定義的 `definition=` 別名，在每一步依該步用例所屬的定義查找，例如 `${输入对::左管::w}`（16.5）。
- **與標準名稱同名的宿主參數**：標準屬性優先，與標準屬性同名的宿主參數須寫作 `${#type}`（`#` 在 RNL 中代表宿主）。任何宿主參數皆可如此撰寫；在沒有同名標準屬性與別名之處，`${w}` 即為 `${#w}` 的簡寫。標準屬性名稱嚴格按字面比較，宿主參數名稱則依宿主規則比較：在 SPICE 宿主中，`${Type}` 不是標準屬性，因此它就是宿主參數 type。
- **名稱格式化**：引用內容僅能作為整體進行格式化，方式是在外層加上標記，如 `\textit{${name}}`，或使用 `\subrest{…}` 與 `\subdigits{…}` 將名稱的其餘部分或末尾數字顯示為下標。對單一字元的其他格式化須直接寫成文字，如 `#M1 @TEXT("M_{1}", key="name")`，這種寫法不會隨重新命名而更新；檢視器更進一步的慣例則屬於其風格體系。

### 13.7 將連接繪製為連線：ROUTE-NET、ROUTE-OBJECT、UNROUTE-NET、UNROUTE-OBJECT

```rnl
&x @ROUTE-NET;                                /* x is drawn as wires; the solver decides the branches and paths */
%jo = (_, _);
&out @WIRE {#M2:1 %jo};
&out @ROUTE-NET;                              /* this wire is drawn as written; the solver adds the rest */
{#M1 #M2 #M5} @ROUTE-OBJECT;                  /* on each net that two or more of their pins share, those pins are joined */
&vdd @UNROUTE-NET(priority="high");           /* the pins of vdd are not joined, whatever asks for it at a lower priority */
# @SELECT-NET(name="clk*", recursive=true) => @ROUTE-NET   /* as a house-style package writes it, with nets chosen by a rule */
```

- 這些關鍵字指定哪些連接要繪製為連線，而不指定何處分接以及圓點擺放在何處；由求解器決定。
- **ROUTE-NET** 將一條網路上的接腳連成一棵樹：包含該網路上各器件的接腳，以及 `::net` 為該網路的虛擬組件接腳——亦即綁定至由該網路填入之角色的接腳（12.1）。一個槽位，接收網路；傳入集合時逐成員處理（5.2.1），不構成匯流排。
- **ROUTE-OBJECT** 連接數個物件的接腳：對於有兩支以上屬於這些物件的接腳共用的每條網路，將這些接腳連成一棵樹。一個槽位，接收物件集合；它將輸入向下傳遞。實例或疊畫代表其接腳，端子代表其接腳，用例則代表填入其角色的物件並一路向下至最底層物件，與群組的成員相同（11.5）；帶有符號的用例亦同時包含其自身的接腳，各位於它所綁定角色的網路上（12.1）。沒有接腳的物件（如填入角色的網路或點）不加入任何接腳：整條網路須用 ROUTE-NET 繪製。因此標準套件的定義可藉此繪製結構內部的連接，如 `{?left ?right ?tail} @ROUTE-OBJECT(priority="low")`，而不必連接這些網路的其餘部分。
- **UNROUTE-NET** 與 **UNROUTE-OBJECT** 將接腳排除：使某條網路的接腳或某些物件的接腳（計入方式同 ROUTE-OBJECT）不被 ROUTE-NET 與 ROUTE-OBJECT 的走線樹連接。
- **每支接腳與每棵樹各自判定**：凡被某條 ROUTE-NET 或 ROUTE-OBJECT 涵蓋的接腳皆屬於該敘述的走線樹，除非另有一條涵蓋該接腳的 UNROUTE-NET 或 UNROUTE-OBJECT 勝過該敘述：即擁有更高的優先順序（14.8），或優先順序相同但寫在較後方（依 8.5 的位置順序）。此比較針對每條 ROUTE 敘述分別進行，因此某支接腳可被 `"normal"` 優先順序的 UNROUTE 從 `"low"` 優先順序的 ROUTE-OBJECT 走線樹中排除，同時仍留在 `"high"` 優先順序的 ROUTE-NET 走線樹中。`"disabled"` 的敘述不計入。這些敘述不是幾何事實，不參與衝突取捨（8.5）；它們僅決定求解器要連接哪些接腳。
- **生效時機**：這些關鍵字的敘述自 8.2 的步驟 3 起生效。它們的規則（如範例最後一行）在步驟 5（逐一產生之前）評估：其條件讀取步驟 3 敘述建立的走線樹，而逐一產生（如標準套件的自動補齊）會看到這些規則建立的走線樹（10.2、10.4）。
- **明確寫出的連線不受影響**：明確的 WIRE 會照原樣繪製，即使在被 UNROUTE 排除的網路或接腳上亦同。既有的連線屬於它所接觸之走線樹的一部分，其餘部分由求解器補上。
- **走線樹**：每條 ROUTE-NET 在其網路上建立一棵樹，每條 ROUTE-OBJECT 則在它連接的每條網路上各建立一棵樹。同一條網路上共用接腳、或由明確寫出的連線連接在一起的樹合併為一棵樹；它採用位置順序最靠前之敘述的樣式，若樣式不同則給出提示。一條網路上可以有多棵互不相連的樹，例如分別寫在距離甚遠之器件上的兩條 ROUTE-OBJECT。
- 僅接腳會被連接：沒有接腳的端子不屬於任何樹（9.2.4）。位於空節點上的接腳不在任何網路上（6.3），因此 ROUTE-OBJECT 不連接它；它僅能透過寫在空節點上的連線連接（13.1）。待連接點少於兩個的樹不執行任何操作。接腳是否已連線（10.2）在產生之前決定，依據的是不含產生所加入之虛擬組件的樹：只有一個自己的接腳的網路，例如只驅動一個閘極的輸入，會構成只有一個點的樹，因此該接腳未連線，自動補齊給它的是給沒有連線之接腳的東西，即使該網路被連接到其所在層級的連接埠亦然。若要將這樣的網路連接到它的連接埠，須在檔案中寫出連接埠標記，例如標準套件的 `$IO_PORT @ATTACH &x` 或 `$IO_PORT_STUB`（12.4、16.3）：自動補齊所加入的連接埠標記不算。
- **參數**：ROUTE-NET 與 ROUTE-OBJECT 接收 `mode`（給求解器的提示，取值同 WIRE，預設為 `"auto"`）、連線的樣式參數（13.1）與 `priority`；UNROUTE-NET 與 UNROUTE-OBJECT 接收 `priority`。
- 附註：傳入空點列表的 WIRE 並不代表 ROUTE-NET。點列表可能來自恰好為空的集合，若空列表表示全部相連，將會靜默把一切都連起來；因此這裡獨立設立關鍵字；本版本亦不支援可選槽位（5.3）。
- **求解器寫回內容**：具體的 WIRE（含轉折點與 `mode="straight"`）、分支處的具名點、以及設定了 `junction` 時的圓點（13.2），連同走線樹的樣式參數，皆寫入求解器自身的記錄。ROUTE-NET 與 ROUTE-OBJECT 敘述代表使用者的意圖並保留在原處；下次求解時會重新計算（第 17 章）。若要從撰寫者所寫連線的中途分接，求解器會拆分該連線（13.1）。
- **不進行求解的檢視器**依檢視器自行決定繪製飛線或不繪製任何內容（原則 2.7）。
- 風格體系套件透過集合與規則選擇哪些網路繪製為連線，如範例所示；沒有專門規定網路顯示方式的關鍵字。
