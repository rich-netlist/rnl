## 5 对象与语句

### 5.1 对象

- 每条带关键字的语句产生一个新的 RNL 对象，由句柄和事实组成。`{…}` 也产生一个新对象，即集合（5.2）。
- 引用（`#M1`、`&vss`、`%x`、`$X`，以及端子、子对象）不产生对象，只取已有的句柄。给出多个成员的**成员位置（member places）**产生一个新集合（5.2.3）。单独的 `#M1` 也是语句，得到 M1，不带事实；单独的 `#` 得到本层，不带事实。
- 句柄是被描述的那个东西：宿主的元件、网络、端子，或本层；或由 RNL 创建的点、导线、集合、用例、约束等。句柄不会是另一个 RNL 对象。
- 一条语句的对象，要么用新的句柄（语句创建，如 WIRE、图元、`{…}`、筛选、AS、ATTACH、约束），要么沿用输入的句柄、再加上新的事实（语句修改，如 PLACE、ORIENT、SET-SYMBOL、SET-STYLE、GROUP、CURRENT；ADD-TO、REMOVE-FROM 沿用目标集合的句柄）。是哪一种写在签名里（5.3）；WIRE 收到网络时创建，收到导线时修改（13.1）。
- 两条内容相同的语句是两个对象，如两句 `#M1 @PLACE(1, 2)`。它们的事实不矛盾，一起生效。
- 事实只在产生它的语句处提交一次（5.4）。本层生效时，同一个句柄的全部事实合在一起，矛盾按 1.5 第 3 条处理。
- 属性就是事实：位置、朝向、符号、样式都是对象上的事实，没有可以改写的属性字段。本层生效时，把同一个句柄的事实合起来算出最终的值：PLACE 的 x、y 按几何事实（5.8、8.5），符号、样式按外观队列（8.3）。
- 句柄的种类由它的来历决定：宿主对象由宿主给出，RNL 对象由创建它的语句决定。签名规定每个对象槽位收哪些种类（附录 A），收到种类不对的对象时，这条描述失效。能在读入时查的读入时查；要到后面才知道的（用例有没有符号、定义的角色）在本层生效时查（7.1）。

对象的种类：

| 种类 | 怎样产生 | 画不画 |
|---|---|---|
| 层 | 宿主；`#` | 不画 |
| 元件 | 宿主；`#M1` | 用它的符号画 |
| 端子 | 宿主；`#M1:d`、`#:inp`（6.4）。用例没有端子 | 在绑定它的引脚处画（9.2.4） |
| 引脚 | 绘出对象的符号里的 PIN（9.2.4）；引脚有名字时写作 `#X1::vdd_t` | 作为符号上的一个点 |
| 网络 | 宿主；`&vss` | 不画；导线、标签是另外的对象 |
| 点 | `(x, y)` | 不画；交汇圆点是套在点上的 `$JUNCTION`（13.2） |
| 导线 | 收到网络的 WIRE；网络槽位收到集合的导线是总线。WIRE 收到导线时改写它（13.1） | 画 |
| 标签 | 附着在对象上的 TEXT；带有 key 时，是那个对象的子对象 `object::key`（13.3） | 画 |
| 叠画 | BUNDLE（11.8） | 代替各成员画一次 |
| 标注 | 场景里的图元（LINE、RECTANGLE、CIRCLE、ELLIPSE、ARC、BEZIER）、附着在点上的 TEXT（13.4），或由 ANNOTATION 画出的符号（13.5） | 画 |
| 用例 | AS、ATTACH（9.4） | 有符号才画，这时它是虚拟元件（第 12 章） |
| 约束 | ALIGN、ORDER、DISTRIBUTE、DISTANCE、ORIENT-RELATION、TABLE（第 14 章） | 不画 |
| 集合 | `{…}`、筛选、UNION、逐个生成的结果（5.2、第 10 章） | 本身不画，成员各自画 |
| 定义 | DEFINE-SYMBOL、DEFINE-STYLE、DEFINE（第 9 章） | 不画，被用到时才起作用 |

这些种类里，元件、端子、引脚、网络、点、导线、标签、叠画、标注、用例有种类名（5.3），`text` 也是种类名，指任何 TEXT，不论标签还是标注；其余几种在签名里怎样写见附录 A。

另有子对象（6.5），句柄是父对象和名字；以及失效对象（第 7 章）。

### 5.2 集合

- `{…}` 产生一个集合对象，成员有序。集合可以命名（`%pair_set = {#M1 #M2}`），有名字的集合可以被别的语句增删成员（5.2.2）。
- 集合保留重复的成员和写出的次序，如 `{#M1 #M2 #M3 #M1}`。是不是同一个成员按句柄判断：分别写出的两个 `{…}` 是两个句柄，内容相同也不是同一个成员。
- **引用打散一层**：集合里写的引用如果指向一个集合，就在原处放进那个集合的成员，所以 `{%a_set %b_set}` 是 a_set 的成员接着 b_set 的成员。结果是集合的语句（如筛选）同样打散；下标展开的一组引用（如 `&D<7:0>`，6.11）也一样。要去重，写 `%a_set %b_set @UNION`（5.2.2）。
- **直接写的 `{…}` 保留**：集合里直接写的 `{…}` 作为一个成员保留，所以 `{{%a_set} {%b_set}}` 是由两个集合组成的集合。
- **散写的对象也打散**：只有一个槽位的关键字收到几个不加花括号写的对象时，把它们合在一起，与写在 `{…}` 里完全相同（5.2.1 第 3 条），所以其中的集合打散。设 `%bias_set = {#R1 #R2 #R3}`，`%lbl` 是一段文字：
  - `%bias_set %lbl @ALIGN("x")` 就是 `{%bias_set %lbl} @ALIGN("x")`；
  - 集合是唯一的对象时，用的就是它本身：`%bias_set @ALIGN("x")` 对齐 R1、R2、R3。
- **项**：集合也按写出的次序保留它的各个项：写在其中的一个对象、直接写出的一个 `{…}`，或指向一个集合的引用。本标准在需要数出"项"的地方（ALIGN、ORDER、DISTRIBUTE 的成员列表（14.1），ASSERT-TOPOLOGY 的成员（15.4），以及 5.2.1 第 2 条的拆开），一个对象是一项，而作为一项的 `{…}` 或集合引用代表该项中最里层的各个成员；在 ASSERT-TOPOLOGY 里，它代表由这些成员构成的一个**黑盒（black box）**。ADD-TO 在末尾增加一项，REMOVE-FROM 从每一项中去掉相应对象（5.2.2）；由筛选、UNION 或逐个生成得到的集合，每个成员各占一项，下标展开的一组引用（6.11）和成员位置取出的集合（5.2.3）也是如此。在其他所有地方，集合都指按上文打散一层后的各个成员。所以 `{%bias_set %lbl} @ALIGN("x")` 有两项，第一项是 R1–R3，第二项是文字，于是把文字的 x 赋给 R1、R2、R3 中的每一个（14.1）。
- 集合的内容在用到它的阶段求出，与筛选一样：初始内容和各条增删语句里的筛选，都按这个阶段开始之前的状态求值，增删按写的次序（它们的位置，8.5）处理。所以写在前面的使用也看到全部增删（1.5 第 1 条）；同一个集合在不同阶段可以不同：生成对象的规则看到的不含生成的对象，样式规则看到的含（8.2）。

  注：内容不在某一步一次算完，因为那样给筛选起个名字就会改变结果：`%g_set = # @SELECT-USAGE $GROUND; %g_set @SET-STYLE $grey` 会漏掉生成的地，而不起名的同一个筛选能找到；名字只是引用对象的另一种写法（1.5 第 5 条）。

#### 5.2.1 对象与对象槽位

一条语句写出的对象按以下规则对到签名的对象槽位。

1. **标了角色**：标了角色的对象整个填进它的角色，不拆开。一条语句里要么全标，要么全不标。
2. **先拆一层**：没标角色时，如果整条语句只有一个对象，而且它是集合，先把它拆开一层，成为它的各项（5.2）。TABLE 是例外：它的槽位照原样收下这个集合，作为表格的外层列表（14.11）。定义、管道送来的结果都算对象。所以 `{#M1 #M2} @DISTANCE(…)` 等于 `#M1 #M2 @DISTANCE(…)`；`{#M1 #M2} @SET-SYMBOL $X` 是两个对象（集合和定义），不拆。
3. **按签名配位**：
   - 有多个槽位的关键字（定义也占一个槽位）：对象个数应与槽位个数相等，按顺序一一对应；不等时这条语句失效。AS、ATTACH 角色表末尾的集合角色可以不给对象（9.4）。
   - 只有一个槽位的关键字（如 PLACE、ORIENT、ALIGN、ORDER、DISTRIBUTE、GROUP、除 SELECT-USAGE、SELECT-ANCESTOR-USAGE 以外的各筛选关键字（这两个还收定义，5.6），以及定义关键字，它们的槽位是定义体）：一个对象直接放入；多个对象合成一个集合放入，引用的集合在其中打散一层，直接写的每个 `{…}` 保留为成员。这些对象正是由唯一的集合按第 2 条拆开的时，放入的就是那个集合本身。
   - 唯一的对象是空集合时：
     - 要单个对象的槽位做零次：什么也不发生，也不失效。名字照常绑定到这个空集合，用这个名字的语句什么都不做。
     - 要单个对象的槽位收到直接写出的空集合时给警告，如 `{} @PLACE(1, 2)`。由筛选、规则得到的空集合不警告：带 `recursive=true` 的规则会在下面每一层各求一次，某一层没有这类对象是常态。用户自己写的筛选在它求值的每一层都没选中东西时，实现可以给一次警告；条件多半写错了。
     - 要集合的槽位收空集合，如空的定义体 `@DEFINE(roles=["a"]) {}`，或没有成员的约束（自然成立）。例外是 BUNDLE 和 WIRE 的网络槽位：它们要用这个集合造一个新对象，空的造不出来，这条语句失效（11.8、13.1）。
     - 一个对象也没写的语句，如单独的 `@PLACE(1, 2)`，与签名不符，失效。
4. **对象槽位收到集合**：
   - 要单个对象的槽位对每个成员各做一次。每个成员各自是一条描述，结果是这些结果组成的集合。成员本身还是集合时，再拆开逐个做。唯一的例外是 PRIORITY：收到 GROUP 标过的集合时，作用于这个分组本身（11.5、14.8）。
   - 要集合的槽位整个收下；收到单个对象时，视作只含这一个对象的集合：`#M3 @ROUTE-OBJECT` 就是 `{#M3} @ROUTE-OBJECT`。
   - DISTANCE 的两个槽位各收一个对象或集合；集合代表它的每一个成员，DISTANCE 把一个槽位的每个成员与另一个槽位的每个成员配对，每一对各成一条约束（14.5）。这是唯一两个槽位都可以收集合的关键字。
   - 一条语句里至多一个要单个对象的槽位可以收到多成员的集合。超过一个时这条语句失效：按顺序配对和取全部组合都说得通，含义不唯一。

| 写法 | 结果 |
|---|---|
| `{#M1 #M2} @SET-SYMBOL $X` | 两个对象，不拆。元件槽位收到集合：M1、M2 各得到这个符号 |
| `#M1 #M2 @SET-SYMBOL $X` | 三个对象对两个槽位：这条语句失效 |
| `{#M1 #M2} @DISTANCE(…)`、`%pair_set @DISTANCE(…)` | 唯一的对象是集合，拆开：从 M1 到 M2 |
| `%a_set %b_set @DISTANCE(…)` | 两个对象，各是一个集合：从 a_set 的每个成员到 b_set 的每个成员（14.5） |
| `{#M1 #M2} @ALIGN("y")`、`#M1 #M2 @ALIGN("y")` | ALIGN 只有一个槽位，收到 {M1 M2} |
| `%bias_set %lbl @ALIGN("x")`，其中 `%bias_set = {#R1 #R2 #R3}` | 散写的对象合成 `{%bias_set %lbl}`：两项，第一项是 R1–R3，第二项是文字；R1、R2、R3 各自得到文字的 x（14.1） |
| `{%bias_set} %lbl @ALIGN("x")` | 同样的两项：R1、R2、R3 各自得到文字的 x |
| `{%bias_set} @ALIGN("x")`、`{{#M1 #M2 #M3}} @ALIGN("y")` | 唯一的对象是集合，拆开一层得到它的唯一一项（第 2 条）；该项是一个集合，原样放入槽位：对齐 R1、R2、R3，或对齐 M1、M2、M3 |
| `%pair_set @PLACE(10, 20)` | 槽位收到的是 pair_set 本身，逐个成员放：两个成员都在 (10, 20)。集合本身没有位置（14.1） |
| `%a_set %b_set @PRIORITY("disabled")`，两个集合都带 GROUP | 散写的对象与写在 `{…}` 里一样打散：PRIORITY 收到的是成员，在它们上面失效（种类不对）。要关两个分组，每个分组写一条 PRIORITY（11.5、14.8） |
| `{#M1 #M2} @SET-SYMBOL $X => @ALIGN("y")` | 管道的结果是唯一的对象，放入 ALIGN：对齐 M1、M2 |
| `{#M1 #M2} @SET-SYMBOL $X => #M3 @DISTANCE(…)` | 两个对象，不拆。槽位 `from` 收到集合：从 M1 到 M3、从 M2 到 M3（14.5） |
| `# @SELECT-NET(…) => $PULL_DOWN @ATTACH &vss` | 三个对象对三个槽位（两个角色和定义）。第一个角色是单个角色，所以对每个选中的网络各套用一次定义，每次第二个角色都是 vss |
| `# @SELECT-INSTANCE(type="nmos") => @ORIENT("MY")` | 逐个镜像；没有 NMOS 时做零次，什么也不发生 |
| `# @SELECT-INSTANCE(name="Q*") => @SET-SYMBOL $NPN` | 两个对象，不拆；没有 BJT 时做零次，什么也不发生 |
| `#R1 {#R2 #R3} #R4 @AS $CHAIN_ROW` | 四个对象对四个槽位（三个角色和定义）；集合角色 `chain` 收到 {R2 R3}（9.4） |
| `&D<7:0> @WIRE {…}` | 两个对象，不拆。网络槽位整个收下这组网络：一根总线（13.1） |
| `#XI0<3:0> @ALIGN("y")` | 唯一的对象是下标展开的一组，拆开：对齐四个元件（6.11） |

- 成员不够的约束自然成立，不失效，如只有一个成员的 ALIGN（第 14 章）。
- 集合本身没有位置（14.1）；它的 `::position` 是各成员位置的集合（6.5）。约束里没有符号的用例代表它的成员（14.1）。要把一组对象当作一个点去关联别的对象，就把它们做成一个用例的成员，并在定义体里把它们绑到用例自身的点上（9.4），再约束 `%u::position`；要把一个集合放在别的对象的一侧，就把它交给 DISTANCE（14.5）。
- 定义的角色分单个角色和集合角色（9.4）。角色表里写成 `"{name}"` 的是集合角色，整个收下集合；其余是单个角色，收到集合时对每个成员各套用一次定义。

#### 5.2.2 增删成员与去重

- `X @ADD-TO S` 在集合 S 的末尾追加 X（X 是集合时追加它的各成员）；`X @REMOVE-FROM S` 去掉 S 里这些成员的所有出现。目标写在最后，所以筛选可以用管道送入：`# @SELECT-NET(name="vss") => @ADD-TO %gnd_set`。
- 目标应是集合，不自动包装成集合。`%tail = #M5` 之后，`#M3 @ADD-TO %tail` 失效，因为 M5 不是集合。
- 几条增删按位置的次序处理（1.5 第 2 条）。集合在某层求值时只含这一层的成员（10.3）。
- `%a_set %b_set @UNION` 产生一个去重的新集合，次序取第一次出现处；是不是同一个成员按句柄判断。
- 产生新集合而不改动原来的：拼接写 `{%a_set %b_set}`；并集写 `%a_set %b_set @UNION`；差集写 `%c_set = {%a_set}; %b_set @REMOVE-FROM %c_set`。
- 一个集合依赖于产生它的语句里写到的集合（花括号里、UNION 里，或作为筛选的范围），以及用 ADD-TO、REMOVE-FROM 加进它或从它去掉的集合。依赖成环就是错误，不论有没有删除：按位置的次序（8.5）逐条看，依赖闭合这个环的那条语句失效，诊断列出整个环；其余照常生效。所以 `%a_set @ADD-TO %b_set; %b_set @ADD-TO %a_set` 在第二条失效；`%b_set = {%a_set}; %b_set @REMOVE-FROM %a_set` 这样删除没有确定结果的，在删除那条失效。

#### 5.2.3 成员位置

```rnl
%row_set = {#M1 #M2 #M3 #M4};
%row_set{1} @PLACE(0, 0);                                         /* M1 */
%row_set{1} %row_set{end} @DISTANCE("left-to-right", exact=12);   /* from M1 to M4 */
%row_set{2:end} @ALIGN("y")                                       /* M2, M3 and M4 */
```

- 集合引用后面紧跟 `{…}` 时，按成员在集合中的位置取成员，如 `%a{1}`、`%a{end}`、`%a{end-1}`、`%a{2:end}`。可以写在绑定了集合的 `%` 名字和 `$` 名字之后，也可以写在普通定义体里集合角色的空位之后，如 `?ref{1}`（9.4）。
- **写法**：花括号里面是用 `,` 分开的若干项；每项是 `i`、`a:b` 或 `a:b:s`，几种写法可以混用，与下标（6.11）相同。位置可以是正整数、`end` 或 `end-k`（其中 k 是不带符号的整数）；步长 s 是至少为 1 的不带符号的整数。花括号里面可以写空白和注释。
- **计数**：完成该集合的全部增删（5.2）之后（写在引用后面的增删也算在内），按成员先后从 1 开始计数，所以 `%a = {#M1}; #M2 @ADD-TO %a` 之后 `%a{2}` 是 M2；按 5.2 打散一层后的成员来数，不按项来数：在 `%a = {%b_set %lbl}` 之后，`%a{2}` 是 b_set 的第二个成员，或当 b_set 只有一个成员时是那段文字。`end` 是最后一个成员。各项按写出的次序展开并拼接，重复的照留。`a:b` 从 a 到 b（a 大于 b 时倒序），`a:b:s` 以步长 s 前进、不越过 b。
- **一个或集合**：只有一项且是单个位置时，得到这个成员本身。其余写法都得到按这些位置及次序组成的新集合：这是一个新的集合对象，是唯一一种由引用造出对象的情形（5.1）。成员本身是一个集合（直接写出的 `{…}`，5.2）时，照原样取出。
- **超出范围**：集合没有那个位置时什么也不取：单个这样的位置得到一个空集合，列表里的这种位置略过。这不算错误，因为写语句时未必知道集合有多少成员（就像单成员 ALIGN 一样，14.2）。
- **只写位置**：紧跟引用后面的花括号里只能写位置。`%a{#b}` 是语法错误；要写一个引用再写一个集合，中间用空白隔开，如 `%a {#b}`（3.5）。
- **错误**：
  - 对不是集合的对象（如元件）取成员位置，失效（种类不对）。
  - 用例不是集合：用例的成员按角色取，如 `%dp1::left`（6.5），用例后面写成员位置是错误。
  - 对筛选的结果取成员位置是错误，不论筛选直接写在那里还是先起了名；依赖筛选的集合（通过其项、UNION、ADD-TO 或 REMOVE-FROM，10.4）同样如此，如 `%s` 为筛选时 `%a = {%s}` 之后的 `%a{1}`：它们的成员要到使用它们的阶段求值时才知道（5.2、8.2）。

#### 5.2.4 传入异类对象

当一个槽位要一种对象、却收到另一种对象时，只按下表做转换；除此之外的种类不符，在读入文本时即报错（5.1、7.1），不论语义上是否说得通。对象只向着它所明确代表的东西转换：往作图一侧，从端子转到它的引脚、再转到点，以及从画出的对象转到它的位置；往电路一侧，从引脚转到它绑定的端子，从引脚或端子转到它的网络。其余情况写子对象（`::position`，6.5）或写筛选（10.1）。

| 传入 \ 槽位要 | 点（图元） | 点或引脚（导线） | 位置（约束成员） | 引脚 | 端子 | 网络 |
|---|---|---|---|---|---|---|
| 点 | = | = | = | 否 | 否 | 否 |
| 引脚 | 1 | = | 1 | = | 8 | 9 |
| 端子 | 2 | 3 | 2 | 3 | = | 10 |
| 元件、叠画 | 否 | 否 | 4 | 否 | 否 | 否 |
| 用例 | 否 | 否 | 5 | 否 | 否 | 否 |
| 文字 | 否 | 否 | 6 | 否 | 否 | 否 |
| 按中心写出的图元 | 否 | 否 | 7 | 否 | 否 | 否 |
| 其余图元、导线 | 否 | 否 | 否 | 否 | 否 | 否 |
| 网络 | 否 | 否 | 否 | 否 | 否 | = |

"=" 表示同类；"否" 表示种类错误；数字对应下面一条转换规则。涉及引脚的转换需要用到对象的符号，所以在定好符号之后再做（8.2）；此前的步骤看到的是原本写出的对象。凡是槽位或角色要单个对象的，如果这类转换给出一个集合（例如来自总线引脚），条文在该次检查时失效（7.1）：该语句是按单个对象建成的，事后不再拆开。导线收到引脚时终结在这个引脚上，因此连上了电路（10.2、13.1），不只是取了引脚的坐标。

1. **引脚转点或位置**：该引脚的位置。
2. **端子转点或位置**：按第 3 条转成它的引脚的位置。
3. **端子转引脚**：在它所属对象的符号里绑定该端子的引脚（9.2.4）。没有这样的引脚时，语句失效（9.2.4）；有几个引脚绑定同一个端子时，取符号里最后写出的那个。对叠画的端子，取叠画符号里的引脚（11.8）。
4. **元件或叠画转位置**：它的原点 `::position`（6.5）。元件不会转成导线或图元的点：要在原点处收住导线或画图元，写 `#M1::position`。
5. **用例转位置**：它自身的点（14.1）。用例不会转成导线或图元的点：要在它的点处收住导线或画图元，写 `%u::position`（6.5）。
6. **文字转位置**：文字自身的位置（13.3）。
7. **按中心写出的图元转位置**：它的中心（13.4）。按两点写出的图元、LINE、ARC 和 BEZIER 有多个点，不转换。
8. **引脚转端子**：该引脚绑定的端子（9.2.4）；对总线引脚，是它绑定的那组端子的集合。不绑定端子的引脚（如用例的引脚或仅作绘制的引脚）没有端子，语句失效。
9. **引脚转网络**：它的 `::net`（6.5），即它绑定的端子所在的网络，或填进它绑定的角色的那个网络；对总线引脚，是这些网络的集合。什么都不绑定的引脚没有网络，语句失效。
10. **端子转网络**：它的 `::net`（6.5）；对叠画的端子，若各成员接在不同网络上，是这些网络的集合（11.8）。

- PLACE 只收 11.1 列出的对象：端子和引脚只随所属对象移动，不能单独摆放（14.1）。
- 集合不做转换：要单个对象的槽位对每个成员各做一次（5.2.1）；约束里写集合的项，代表其中的各个成员（14.1）。
- 空节点（单独的 `&`，6.3）也不转换：种类为 `"net"` 的角色和 WIRE 的网络槽位按原样收下它，其余收网络的地方都把它当作空网络集合。
- 网络不转成任何东西：网络没有位置也没有引脚，也不代表单个端子。对象也不会转成另一类的多个对象：元件不会自动变成它的端子集合。遇到这类需求，请写筛选，如 `#M1 @SELECT-TERMINAL` 或 `&en @SELECT-PIN`（10.1）。
- 另有别处规定、不属此处转换的情况：TEXT 附着在什么对象上（13.3）、筛选的作用域怎样导出被筛选的种类（10.1），以及收到导线的 WIRE（13.1）。

### 5.3 语句与签名

- 语句由至多一个关键字、若干对象和一组参数组成。
- 每个关键字有签名，声明：
  - 对象的个数，每个对象槽位的名字和它收的种类。AS、ATTACH 的个数是定义的角色表的长度，再加定义本身（AS 写在最后，ATTACH 写在最前），种类是角色声明的种类（9.4）；
  - 参数：名字、类型、是否必需、可选值，以及按位置写时的顺序；
  - 输出：新对象、输入的句柄、子对象、定义，或没有句柄；WIRE 收到网络时给出新导线，收到导线时给出这条导线（13.1）；
  - 每个输入的消费方式（5.4），以及对失效严格还是容错（7.3）；
  - 关键字能写在哪里（见下面的标准词表）。
- 对象个数固定，个数不定的用集合。没有可选槽位，例外是：AS、ATTACH 没填的集合角色是空集合（9.4）；SELECT-USAGE 的定义可以省略（10.1）；USE-PACKAGE 的体可以省略（16.2）。定义也占一个槽位。
- 对象按角色或按顺序对到槽位，全标或全不标；同一个角色只能标一次。管道送来的对象算第一个对象；AS、ATTACH 按角色配它，它不占定义的槽位（5.5）。对象怎样对到槽位，见 5.2.1。
- 不论什么关键字，语句里写出的对象都能标角色。角色名就是签名里的槽位名：`#M5:3(to) #M1:3(from) @DISTANCE("left-to-right", min=1)` 与按顺序写的 `#M1:3 #M5:3 @DISTANCE("left-to-right", min=1)` 相同。角色名不是这个关键字的槽位名时，这条语句失效，不会被忽略（原则 2.3、2.8）。只有一个槽位的关键字，对象也能标角色，但标了不增加什么。
- AS、ATTACH 的参数是定义的参数表里的参数（9.4），另有一个标准参数 `priority`（14.8）；定义的参数不能叫 `priority`。
- **标准词表**：每个语言版本发布一份机器可读的标准词表，是标准的一部分。各关键字收什么、有哪些参数只写在表里，正文写它们的含义。附录 A 由表生成，两者矛盾算勘误。解释器的检查、文档、编辑器的补全、一致性测试的骨架、给 LLM 的写作参考都从表生成。0.4 版的表发布为 `rnl-words-0.4.json`。
  - 表里收全部标准词：关键字及其签名、槽位名、参数名和取值、记录头的字段、种类名、子对象名、`${…}` 读的属性名、样式属性，以及 `true`、`false`。代称（16.5）是给表里的词声明的，版本检查和"最接近的名字"都查这张表。
  - 表是 JSON 文件，JSON Schema `rnl-words-0.4.schema.json` 说明表本身的结构。读写它的是工具和标准的维护者，不是描述电路的人。每个词带 `since`，即加它的版本；预留的词标出来（0.4 版没有预留的关键字）。表的 `removed` 下列出早先版本有、这一版不再保留的标准词，并注明改用哪一节的内容，以便诊断提示。文件声明的版本里还没有的词，按不认识的词处理，诊断说明要哪个版本（16.1）。
  - 表里为每个关键字写：
    - 每个槽位：名字、收哪些种类、要单个对象还是要集合（5.2.1）、消费方式（5.4，严格或容错由它决定，7.3）；定义的槽位；AS、ATTACH 的槽位按定义的角色表；
    - 每个参数：名字；类型（数、字符串、真假值，或数组及元素的类型；取值固定的列出取值）；必需与否；默认值；能按位置写的参数的次序（其余的只能写名字）；以及组合条件，如 PLACE 的 `x`、`y` 至少写一个，RECTANGLE 的中心写法和对角写法只能写一种；
    - 输出：新对象及其种类、沿用输入、沿用目标（ADD-TO）、定义、子对象（写了 `key=` 的 TEXT），或没有；WIRE 另记它收到哪种对象时改写这个对象（13.1）；

    - 事实怎样覆盖（5.8）：按键覆盖，及其键；按几何事实（8.5）；按外观队列（8.3）；或累加；
    - 标准写法和标准例句（4.3、4.5、附录 B）；
    - 一句说明和正文的节号。
  - 不进表的：含义（关键字产生什么事实、在哪个阶段、怎样冲突）写在正文。包里普通定义的签名就是它的角色表和参数表（9.4）。

- **内置关键字的槽位名**：每个槽位都有名字，就是能标的角色名。槽位名是标准词，与关键字一样随版本，改名就是不兼容的改动；同一关键字的各槽位不重名。定义的槽位也有名字，表里、诊断里用，但不能标（4.2 第 7 条）。种类名只有一套，签名和定义的角色声明（9.4）共用：`instance`、`terminal`、`pin`、`net`、`point`、`wire`、`usage`、`bundle`、`text`、`annotation`、`label`（附录 A）。

### 5.4 消费方式

| 方式 | 关键字 | 输入的事实 | 失效（默认） | 名字 |
|---|---|---|---|---|
| 吸收 | 大多数关键字 | 带到输出 | 严格 | 嵌套集合里的名字只在该集合内有效 |
| 封装 | DEFINE、DEFINE-SYMBOL、DEFINE-STYLE | 成为定义的内容，不外传 | 容错 | 局部；每次套用时改名，每个用例有自己的一份（9.4） |
| 提交 | 记录，`@RNL` | 按顺序并入本层 | 容错 | 发布到本层，本层各记录共享；可以先用后绑定 |

- 一个成员的产物是它各段、各嵌套集合产生的全部事实，不只是最后的句柄。它们随所在的顶层成员一起提交。
- 记录里的每条语句都提交，有没有名字都一样。提交后起什么作用，看对象是什么：场景里的描述画出来或参与求解；定义可以被使用，本身不画；引用和只由引用组成的集合不起作用。普通 `{…}` 里的语句随所在的成员提交，所以 `{ @LINE {…}}` 的线会画出来（13.4）。
- 定义体里的语句不提交，只成为定义的内容。普通定义在套用时才展开（9.4）。
- 带体的 USE-PACKAGE 也按封装方式收体：体里的语句是包的内容，不提交到本层。包里的名字怎样可见，见 16.2。

### 5.5 管道与嵌套

- `a => @K(…)` 把 `a` 的结果作为 K 的第一个对象；AS、ATTACH 把它填进第一个角色，不填进定义的槽位。结果是集合也只算一个对象（5.2.1）。`=>` 后面的段只能按位置收这个对象，不能给它标角色。
- 管道不是逐步执行的，而是展开成用句柄连起来的几条描述：每一段描述的是前一段结果的句柄；逐个成员做的一段展开成多条平行的描述（1.5 第 1 条）。
- **各段的先后**。每一段有自己的位置；凡是书写位置起作用的地方（1.5 第 2 条），后面的段都算比前面的段后写：按键覆盖（8.4）、外观队列（8.3）、取舍次序（8.5）、绘制顺序（11.6），以及导线的改写（13.1）。所以在 `#M1 @SET-SYMBOL $A => @SET-SYMBOL $B` 里，M1 用 `$B` 画。
- **失效只波及依赖它的描述。** 一条描述失效，只有两种原因：它自己读不懂或自相矛盾；或者它要用的句柄本该由一条失效的描述创建。
  - `$GROUND @ATTACH &vss => @PLACE("20", 38) => @ORIENT("R90") => %g1` 里只有 PLACE 失效（PLACE 要数的地方写了字符串，5.3）；地照样创建，ORIENT 照样生效。
  - `#XI0<3:0> @BUNDLE(bad=1) => @PLACE(10, 20) => %s` 里叠画没建成（BUNDLE 没有参数 `bad`），PLACE 没有要描述的对象，也跟着失效。
- 名字绑定什么：写在开头的 `%x =` 绑定整条管道最后的句柄；`=> %x` 绑定它左边那一段的结果，写在末尾就是最后的句柄，写在中间就是那一段的结果，如 `#M1 @AS $A => %a => @AS $B => %b`。PLACE、ORIENT、SET-SYMBOL、SET-STYLE、GROUP 沿用输入的句柄，所以 `$GROUND @ATTACH &vss => @PLACE(24, 38) => %g0` 里的名字 `%g0` 是这次套用的用例，也就是这个地。AS、ATTACH 产生新句柄：`#M1 @AS $A => @AS $B` 的第二段把 `$B` 套用到第一段产生的用例上（嵌套），不是 M1。要给 M1 套用两个定义，写成两条语句。名字左边那一段失效时：它本来沿用输入的句柄，名字仍指这个句柄（上例的 `%g1` 是那个地）；它本来要创建新对象，名字指失效对象（上例的 `%s`）。
- 对象可以写成一个集合，集合里是语句（嵌套）。嵌套集合里绑定的名字只在该集合内有效。嵌套的语句各是一条描述：`{%a = #M1 @PLACE(1, 2); #M9} @ALIGN("y")` 在宿主没有 M9 时 ALIGN 失效，M1 的坐标照常生效。
- 标准写法是平铺的：给对象起名，再在别的语句里引用它。单条语句在开头写 `%x =` 起名，管道用 `=> %x`（4.3）。

### 5.6 定义作为对象

用到定义的关键字把定义作为它的一个对象，定义在哪个槽位由关键字定：ATTACH 的定义是写出的第一个对象；SET-SYMBOL、SET-STYLE、AS、SELECT-USAGE、SELECT-ANCESTOR-USAGE 的定义是最后一个对象，SELECT-USAGE 的可以省略（10.1）。

```rnl
%ax = (_, _);
%w13 = &x @WIRE {#M1:1 #M3:1};
#M1 @SET-SYMBOL $NMOS;
%w13 @SET-STYLE $signal;
#M1(left) #M2(right) %ax(axis) @AS $MIRRORED_LAYOUT;
$GROUND @ATTACH &vss;
# @SELECT-USAGE $GROUND => @SET-SYMBOL $GROUND_SYMBOL
```

- 定义不标角色，也不计入"全标或全不标"。定义也是对象、占一个槽位，所以 `{#M1 #M2} @SET-SYMBOL $X` 是两个对象（5.2.1）。
- 定义的槽位由关键字固定，所以解析语句时不用知道一个 `$` 名字指的是定义还是集合：`$GROUND_STUB @ATTACH $GROUND_FILL_SET` 里前一个是定义，后一个是集合。
- 定义不能经管道送入：送来的对象填第一个槽位，AS、ATTACH 按角色配它，不占定义的槽位（5.5）。所以 `$GROUND @ATTACH &vss` 不能写成 `$GROUND => @ATTACH &vss`。
- 定义可以是嵌套的匿名定义：`#M1 @SET-SYMBOL { @DEFINE-SYMBOL {…}}`。
- 普通定义可能写在后面或别的层里，所以 AS、ATTACH 的对象个数、角色名和参数在本层生效时核对（7.1）。

### 5.7 句柄与名字

- 宿主对象的句柄由宿主给出：元件名、网络名。端子是元件加端子序号，所以 `#M1:1` 与 `#M1:d` 是同一个端子。
- RNL 创建的东西，句柄由创建它的语句产生。别的语句只能通过名字引用它：名字是找到它的唯一办法；例外是求解器的记录，它用编号引用没有名字的对象（5.9）。除此以外，没有名字的对象只能在它自己的语句里使用（管道、嵌套）。
- 一个名字不会指两个东西：同一层里只绑定一次（6.6）。
- 子对象的句柄是父对象和它的名字，不必另起名字。
- 普通定义展开出的局部对象，句柄是用例和局部名，从外面写作 `%c1::mid`（9.4）。没有名字的用例，它的局部对象只在诊断里按位置显示；只有求解器的记录能经用例的编号引用它们，如 `%#5::mid`（5.9）。
- 生成集里的单个对象没有名字，不能单独引用：不按种类和关联的对象认对象（没有自然键），集合也不提供按下标引用。

### 5.8 事实的键

- 有键的事实按键覆盖：同一个键，后写的生效；后写的失效时，保留较早的有效值。
- 几何事实例外：PLACE 的 x、y（每个坐标一个键）和 ORIENT（每个对象一个键，每个引脚也是一个键，11.2）。同一个键写了两个不同的值就是冲突，按 8.5 取舍：优先级相同时保留后写的，与按键覆盖结果相同；优先级不同时保留高的。PLACE 只改它写出的坐标，从没写过的坐标是自由的。
- 用已经绑定的名字再创建对象，不是按键覆盖：名字同一层只绑定一次（6.6）。要改 RNL 创建的对象，写修改它的语句，如 `%g0 @PLACE(40, 38)`。
- 没有键的事实累加：不冲突的并存，冲突的按 8.5 取舍。
- SET-SYMBOL、SET-STYLE 不按键覆盖，按外观队列生效（8.3）。
- VERSION 和 PACKAGE 只在头段记录里写一次（16.1、16.2），所以从不覆盖：写第二条是错误，它失效，第一条生效。
- CURRENT 每个端子一个键（15.2），LAYER 每个对象一个键（11.6）。
- 用例没有键：一个定义套用几次就是几个用例，互不覆盖。两句相同的套用产生两个用例，所以 `$GROUND @ATTACH &vss` 写两次就画两个地。对一个用例写的修改语句（如 PLACE），其事实是有键的，照上面的规则处理。
- 对象的优先级是一条有键的事实；优先级之间按什么次序覆盖，见 14.8。
- 写了 key（`key=`）的 TEXT，每个附着对象、每个 key 是一段文字，后写的按参数覆盖它（13.3）。没写 key 的 TEXT 不按键覆盖：每写一次就多一段文字（13.3）。
- 导线没有键：写两次就是两条导线（13.1）。WIRE 收到导线时改写它；改写有键，键是这条导线，后写的改写换掉先写的（13.1）。
- 约束没有键。要改一条约束，就把它关掉（`"disabled"`，14.8）再写新的，或者直接改文本。

### 5.9 没有名字的对象的编号

```spice fragment
* @RNL(type="header") { @VERSION("0.4"); @USE-PACKAGE(name="rnl-std-all", version="0.4")}
.model nch nmos level=1
.subckt amp in out vdd vss
M1 out in vss vss nch
R1 vdd out 10k
* @RNL {
*   #M1 #R1 @ALIGN("x");
*   &out @WIRE {#M1:1 (_, _) #R1:2};         /* %#1: the wire; %#2: the free point */
*   {#M1 #R1} @TEXT("${name}")               /* %#3: the label of M1; %#4: that of R1 */
* }
* @RNL(type="generated", priority="high", author="rnl-solver 0.1", hash="sig1:…", numbering="…") {
*   #M1 @PLACE(10, 0); #R1 @PLACE(10, 8);
*   %#2 @PLACE(12, 4);
*   %#1 @WIRE(mode="straight") {#M1:1 (12, 2) %#2 (12, 6) #R1:2};
*   %#3 @PLACE(13, 1); %#4 @PLACE(13, 9)
* }
.ends amp
```

- 求解器的记录用编号引用经名字找不到的对象，以便写回它的每个决定（14.8）。编号写作 `%#` 加一个无符号整数，如 `%#3`，用法同名字：`%#5::pin` 是用例 `%#5` 的符号上的引脚，`%#5::mid` 是它的一个局部对象。编号只用来引用它的对象，不像名字那样绑定，所以 `%#3 = …` 和 `=> %#3` 是语法错误（4.1）。
- **哪些对象**：没有自己的名字、也不能经 `::` 从有名字或有编号的对象找到的点、导线、标签、叠画、标注和用例（6.5、9.4）。只在嵌套集合里绑定的名字（6.7）不算，因为求解器的记录用不了它。对求解器的一条记录，这些对象依次是：
  1. 本层作者记录（`type="authored"`，2.8）的成员产生的，以及这些成员产生的用例的定义体里产生的。它们按求解器看到的那样数，即不带 `type="generated"` 的记录来解释这一层（2.8）；带上这些记录解释时，编号不变；
  2. 这条记录自己的成员产生的，以及它们产生的用例的定义体里产生的。它们按记录写出的文本数，当作其中的编号都能解析；下面的校验和对不对得上，不改变它们。

  约束和集合不编号。规则逐个生成的对象（10.5）也不编号：求解器把它们写成显式语句，落在第 2 项里。求解器的每条记录各有自己的编号：第 1 项对每条记录都一样，第 2 项只数这条记录自己的成员。
- **次序**：作者记录按 2.6 的次序取：本层自己的文本，再是从外面用 `scope` 写进本层的记录。一个成员里，按产生对象的记号的先后编号：点是它的 `(`，其余对象是关键字。一个记号为集合的每个成员各产生一个对象时（5.2.1），每个对象各有一个编号，按集合成员的次序。用例定义体里的对象紧接在用例之后编号，按定义体的次序，嵌套的用例照此一层层往下。编号从 1 起。
- **写在哪**：编号只能写在 `type="generated"`、带字段 `numbering`、不带 `scope` 的记录里（2.6、2.8）。写在别处是错误：作者记录用名字引用对象。在它所在的记录里，编号可以用在产生其对象的成员之前，名字也是这样（6.7）。
- **校验和**：`numbering` 存放编号对象生成方式的校验和。按编号的次序，每个编号一行：
  - 产生这个对象的那个成员（记录或定义体里的成员，连同它的各段，4.1）的记号，去掉自由文本和注释，记号之间隔一个空格。这里的记号指词法单位：关键字；引用，连同它的端子、子对象和下标，中间不留空白；照原样写的字符串或数；名字；`_`；`{ } ( ) [ ] , = ; =>` 中的一个，或成员位置的一部分（`:`、`end`、`-`，5.2.3）。所以 `&out @WIRE {#M1:1 (_, _) #R1:2}` 写成 `&out @WIRE { #M1:1 ( _ , _ ) #R1:2 }`；
  - 对象在用例的定义体里时，先写这个用例的那一行（用例本身有没有编号，都照样写），再接一个制表符和定义体里那个成员的记号，照定义里的写法；
  - 那个记号为集合的每个成员各产生一个对象时，后面接一个制表符和这个成员的句柄，写成引用：宿主元件或网络写名字；端子写元件和端子号，如 `#M1:1`；引脚写它的对象和引脚名，如 `#X1::vdd_t`，没有名字时写它的端子；对象的位置或某个 key 上的文字，写对象后接 `::position`，或 `::` 和该 key；RNL 对象写本层绑定给它的 `%` 名字，有几个时取按 2.6 的次序最先绑定的那个，不管集合里写的是哪个名字；没有这样的名字的对象写编号，或作为用例的局部对象，写用例的引用（照这几条写）、`::` 和局部名字：有几个局部名字时，取定义体里最先绑定的那个，同一个成员里也一样（`%p = (0, 0) => %q` 里取 `p`），不管集合里写的是哪个名字；几个用例都把它当作局部对象时，经最先套用的那个用例写。名字只由 ASCII 字母、数字和 `_` 组成时照写，否则写在双引号里，`"` 写两个（3.6）。例如在 `%p = (0, 0); %q = %p; %s = {%q}` 之后，`%s @TEXT("x")` 产生的标注那一行是 `%s @TEXT ( "x" )`、一个制表符和 `%p`，校验和是 `675df5171032726d`。用 `$D = @DEFINE(roles=["x"]) { %p = (0, 0) => %q }; %u = #M1 @AS $D; %s = {%u::q}` 时，`%s @TEXT("x")` 那一行末尾是一个制表符和 `%u::p`，校验和是 `a8c9571193175903`。

  校验和是这些行（每行以换行符结束）的 UTF-8 文本的 SHA-256 散列值的前 16 位十六进制，小写。
- 一条记录的校验和与本层对不上时，记录里用到编号的语句都不生效；有这样的语句时，整条记录给一个提示：求解结果对没有名字的对象已经过时。不用编号的记录可以不写 `numbering`。记录里的其他语句照常生效（第 17 章）。编号超过最后一个编号对象是错误。
- 例子里，校验和对六个编号各有一行：WIRE 那个成员两行（先是导线，再是点），TEXT 那个成员两行，后面分别接 `#M1` 和 `#R1`；改写导线的 WIRE 里写成坐标的两个点是这条记录自己的对象，编号 5 和 6，再占两行。不求解的查看器照求解器选定的样子画出自由点、导线的走法和两个标签。
- 改写成 `{#R1 #M1}`，标签 3、4 就对调了：校验和对不上，用到编号的语句在这一层重新求解之前都不生效，M1、R1 的位置照旧。改动 ALIGN，或移动 M1，编号都不变。
- 注：校验和只看编号对象是怎样产生的。移动器件、改不产生无名对象的语句，编号都不变；增、删、改、调换产生这类对象的成员，编号就过时，直到这一层重新求解。求解器的记录一般不含改集合或定义的语句；不论有没有，第 1 项都不带这些记录来数。
