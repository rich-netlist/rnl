## 16 文件、版本、包与代称

本章讲文件的语言版本、包和包文件、标准包、未知内容，以及代称。

### 16.1 版本

```rnl
* @RNL(type="header") { @VERSION("0.4")}
```

- **一个文件一种语言版本**。不同版本的 RNL 写在不同的文件里，用引入连起来（6.1）。
- **写在头段记录里**。VERSION 只能写在头段记录（`type="header"`）里，这条记录是文件的第一条记录（2.8）。版本只能声明一次，所以一个文件不会有两个版本值。写在别处的 VERSION 是错误，并被忽略。
- **读的次序**：
  1. 宿主适配器给出注释；
  2. 按记录的外层写法切出全部记录，读出它们的记录头；这一步与版本无关；
  3. 第一条记录是头段记录时，读出它的 VERSION；
  4. 其余记录按这个版本解析。
- **与版本无关的部分**。注释载体、`@RNL` 入口、记录头的写法，以及头段记录里 VERSION 的写法，以后的版本都不改；否则解析器找不到版本。支持新的宿主时只增加载体，不改已有的（2.2）。头段记录里别的内容按声明的版本读。
- **没写头段记录**。头段记录可以不写，头段记录里的 VERSION 也可以不写。这时被引入的文件取引入它的文件的版本；主文件取工具默认的版本，并给提示。工具保存文件时应写上头段记录和版本，所以手写的文件可以省略，工具写过的文件都有。包文件应有头段记录（16.2）；没写 VERSION 时，与主文件一样取工具默认的版本。内嵌的包与它所在的文件是同一个版本（16.2）。
- **不支持的版本**。工具不支持某个文件的版本时，这个文件的 RNL 都不解释，报错，保存时原样保留；别的文件照常解释。
- 实现应声明它支持的版本（原则 2.3）。语言版本、包的版本（USE-PACKAGE 的 `version=`）、宿主的版本是三回事。包的版本怎样写、怎样对上，见 16.2。本版的文件只用本版的包：若一个包文件或代称包声明了别的语言版本，或因没声明而按更早的版本读入，就会在直接或通过其他包触及它的 USE-PACKAGE 或 USE-ALIASES 处报错（16.2、16.5）。
- **版本号**。版本写成 `"major.minor"`：两个不带符号的十进制整数，如 `"1.0"`、`"1.2"`。没有补丁号、日期或 profile。`"1.0"` 之前的版本是草案，写成 `"0.minor"`；0.x 之间不承诺兼容，各算一个大版本。写错的版本（如 `"1"`、`"v1.2"`）按不支持的版本处理，不当作没写，免得文件按别的版本误读。
- **文件按它声明的版本读**。工具应知道每个标准词是哪个版本加的：在声明了较早版本的文件里，后来才加的词不算标准词。所以以后新增的标准子对象名不影响旧文件里拼写相同的 key（6.5），新的属性名不影响同名的宿主参数（13.6），AS、ATTACH 新的标准参数不影响同名的定义参数（9.4）。
- **同一大版本里，新的小版本只增加、不改义**。
  - 可以：加关键字、参数、取值、标准词、子对象名、属性名；给原来失效的写法一个含义。附录 C 的各条，以及本标准说是纯放宽的地方，都属于这一类；把整个解释失败的情形（1.5 第 3 条）改为容错也是。
  - 不升大版本就不可以：改变合法写法的含义；删掉任何东西；改默认值；把合法的写法变成错误。
  - 旧文件在新工具里含义不变。新文件在旧工具里，旧版本已有的部分照常读，新增的部分是未知内容（16.4），并给警告，说文件的版本比工具支持的新。工具也可以选择不画这个文件，但不应假装读懂。
- **大版本不同**。工具不支持的大版本的文件，不解释，原样保留（见上）。它的包也不用：这个文件的 RNL 都不解释，查看器按自己的默认外观画网表，并报告版本不受支持。工具可以支持几个大版本。把文件升到新的大版本是显式的迁移，由工具改写文件和它的头段记录；工具不应悄悄按新大版本的规则读旧文件。本标准的每个新大版本都附迁移说明。
- **支持的版本**。工具按大版本说明支持到哪个小版本，如 `"1.0"`–`"1.3"`。支持 `"1.3"` 就是也能读 `"1.0"` 到 `"1.2"`。
- **升版本**。工具往文件里写只有较新版本才有的写法时，把头段记录里的版本升上去。升之前，检查中间新加的标准词是否与文件里已有的名字（文字的 key、角色名、定义参数、宿主参数）拼写相同，每个这样的名字给一个警告，因为一升版本，它们的含义就可能变；版本照样升。
- **0.3 版和 0.2 版**。本版取代 0.3 版。0.3 版和 0.2 版的文件属于别的大版本的文件（见上），本标准不作描述。它们通过读取 0.3 版的升级工具升到 0.4 版：工具把版本号升上去，把文件迁到 0.4 标准系列并在头段记录里写 `@USE-PACKAGE(name="rnl-std-all", version="0.4")` 来取代原来钉在头段记录里的任何版本的标准包，按附录 D 改写文件，并报告无法改写的地方（例如用到了 0.4 系列已不再有的定义）。

### 16.2 包与 USE-PACKAGE

```rnl fragment
@USE-PACKAGE(name="acme-style", version="1.2");                               /* looked up in the package directories of the tool */
@USE-PACKAGE(name="acme-style", version="1.2", path="lib/acme-style.rnl");    /* reads this package file */
@USE-PACKAGE(name="acme-style", version="1.2") {…}                            /* an inline package */
```

**包在哪里生效**。

- 包的 `$` 定义在写它的 USE-PACKAGE 的那一层及以下各层生效。它的规则视作写在那一层：在那里起作用，而传到下面各层，则仅当规则里写的筛选带 `recursive=true`，或者（如果规则里没有筛选）经由它用到的集合触及下层（10.1、10.4）。本版没有只用于本层的 USE-PACKAGE。写在子电路里，包只管这个子电路；写在文件层，管本文件的子电路和它引入的文件（6.1）；写在头段记录里，范围与写在文件层相同，但排在根上（16.3）。
- 根上的包，不论写在头段记录里还是由工具的设置加上（16.3），都算作在文件顶层使用：在主文件里，就是在它的顶层。因此写在头段记录里的风格包的规则，必须像标准包那样带 `recursive=true` 才能管到子电路。
- **排序位置**。包的内容排在它的 USE-PACKAGE 所在的位置，包内再按包的文本先后，与定义展开出的事实取 AS 或 ATTACH 语句的位置同理。冲突的取舍（8.5）和外观队列（8.3）都按这个位置。USE-PACKAGE 写在一层的语句之前，包就是一组默认值；写在它们之后，包里的规则能盖过前面的语句。头段记录里的 USE-PACKAGE 排在根上（16.3）。

**包里的名字**。只有排序位置跟着 USE-PACKAGE；包里的名字照旧是包自己的。

- 包里的名字先在包自己的定义里找，再在它引用的包里找（见下面的"包引用包"），再在 USE-PACKAGE 那一层生效的标准包里找。不在那一层或上层的用户定义里找，也不在别的包里找；与定义体一样（6.9），USE-PACKAGE 那一层的同名定义不会截走它。所以内嵌的包与同样内容的包文件含义相同，文本可以直接搬出去做成包文件；而包文件可以单独检查，这时用工具设置加上的标准包（16.3）。标准包和它直接、间接引用的包只看自己和自己引用的包，不看标准包，免得查找又绕回它们自己。
- 包的 `$` 定义是公开的，按 USE-PACKAGE 那一层的上面一层对待：那一层写了同名的定义就遮蔽包里的，并给提示（6.8）；这不算一层里的第二次绑定。包的 `$` 定义遮蔽上面各层或根上的包的定义时，也给提示（6.8）。
- 包的 `%` 定义是包内私有的。

**包里有什么**。

- 包里有定义、`$` 集合和规则。包文件的头段记录里写 VERSION 和 PACKAGE，还可以写 USE-PACKAGE、DEVICE（6.12）和 SOLVER-CONFIG（14.10），它们作用于用到这个包的各层，以及只管本文件的 ALIAS 和 USE-ALIASES（16.5）。USE-PACKAGE 引用其他包（见下文），也可以出现在只针对一种语言的头段记录里（2.8）。代称包是只有头段记录的包文件，由 USE-ALIASES 加载（16.5）。
- 包没有自己的电路，与被引入的文件的文件层一样（6.1）：
  - 写具体宿主对象的语句（`#M1`、`&vss`、`#:inp`）失效；单独的 `#` 照旧是规则求值的那一层，在普通定义的体里也一样（9.4）；
  - 不是规则、只画一个场景对象的语句，如 `(0, 0) @RECTANGLE …`，没有层可画，是错误；
  - 记录头的 `scope=` 和 `type="generated"` 是错误（2.8）；
  - 在包的头段记录以外的记录里写 USE-PACKAGE 是错误：引用别的包只写在头段记录里。
- 内嵌的包的体照这些规则，只是没有头段记录：包名和版本是它的 USE-PACKAGE 的参数，DEVICE 和 SOLVER-CONFIG 写在文件自己的头段记录里。内嵌的包不能引用别的包；要把一个包集合冻结进文件，就把它展开后的内容按先后写进体里，并作保持其含义所需的改动（16.3）。

**包文件**。包文件怎样读见 2.7，那里有例子。它的头段记录用 `@PACKAGE(name=…, version=…)` 声明这个文件是哪个包、哪个版本；没写 PACKAGE 的文件不是包，用 USE-PACKAGE 加载它是错误。一个包一个文件：分在几个文件里就要在它们之间定先后，本版没有这种规定。包文件用 VERSION 声明自己的语言版本，它必须与用它的文件的语言版本相同（16.1）；否则 USE-PACKAGE 是错误，用到包里名字的语句按找不到名字而失效。

**查找**。

- 带体的 USE-PACKAGE 是内嵌的包，不查找。
- 写了 `path=` 就读那个文件。路径相对于写这条 USE-PACKAGE 的文件所在的目录，用 `/` 分隔；它指本地文件，不是网址。文件不存在，或它的 PACKAGE 指名了别的包，或者版本不符合下面那条规则，就按名字找，并给警告。文件存在但根本不是包（没有 PACKAGE，或者 PACKAGE 的 `version=` 写错），则这条 USE-PACKAGE 失效，就像对任何不是包的文件那样（见上）。
- 否则到工具设置的包目录里，按 PACKAGE 的名字和版本找。标准包由工具自带，或装在包目录里。包目录是工具的设置，不写进文件；同一个版本有几份时，按这项设置里目录的先后。
- 诊断说出用的是哪个文件、哪个版本。
- 找不到包时，这条 USE-PACKAGE 失效（错误），用到包里名字的语句随之失效（7.3）；诊断给出的原因是缺这个包。
- `name=` 必写。它按整个字符串比较，区分大小写；包名建议只用小写字母、数字和 `-`。
- 有了 `path=`，网表和它的包文件可以放在一起，整体搬走；本版没有给它们用的清单格式。

**包的版本**。

- 包的版本写法与语言版本相同，`"major.minor"`；每个 0.x 各算一个大版本（16.1）。
- 有写的那个版本就用它。没有时，用同一大版本里比它新的版本中最小的一个，并警告包的版本不同、画面可能不同；同一大版本里只有更旧的版本，或者一个也没有，就是没找到。不用更旧的版本，因为里面可能缺名字。`path=` 指的文件也按这条核对。
- 不写 `version=` 时，用找到的最新版本，并给提示。在 USE-PACKAGE、USE-ALIASES 或 PACKAGE 里写得不符合 16.1 规范的 `version=` 是错误，不会再去查找：那条 USE-PACKAGE 或 USE-ALIASES 失效，而 PACKAGE 写错的包文件不算包（见上）。内嵌包的 `version=` 只标识版本，不查找；写错了同样是错误，这个内嵌包失效。
- 按名字和版本找到的包，整份文档里只读一次：同一个版本在用到的各处是同一组定义。包在它被使用的地方查找它引用的包和当前生效的标准包的名字：它们的版本和内嵌内容按下面决定——对文件用到的包，取离这一层最近的 USE-PACKAGE；对仅经其他包带进来的包，取同一条层链上的最新版本。同一包被用到的两处若在这方面不同，包就对两处各自读一遍，两份读出来的就是两组不同的定义，如同两个版本一样（9.5）。每个内嵌的包各是一份：即使文本相同，两个内嵌的包也不一样，所以从两处看到它们的包也会各读一遍。不同版本里的同名定义是两个定义（9.5）；见 16.3 的例子。
- 建议包的作者照语言的规矩（16.1）：同一大版本里不删、不改已有的名字、角色、参数和引脚；画法可以改。这是约定，工具查不了。
- 本版没有包的内容摘要（如 USE-PACKAGE 的 `digest=` 参数）。要画面完全不变，就钉住版本，或把包内嵌进文件。记录头的 `hash` 怎样算归工具（第 17 章）。

**包引用包**。包可以引用别的包，这样大的包可以拆成几块，再按几种大小组合起来；标准包就是这样构成的（16.3）。文件里只有头段记录、只引用别的包的包，叫作*包集合（package collection）*；本标准平时就叫它包。

- **写法**。在包文件的头段记录里，为引用的每个包写一条 `@USE-PACKAGE(name=…, version=…)`。`path=` 相对于这个包文件所在的目录；查找和版本同上。引用不带体；带体的是错误，因为内嵌的内容没有版本，参加不了取最新版本的比较（见下）。
- **排序**。用一个包时，先按它的头段记录里引用的先后，把引用的包展开，放在它前面；引用的包又引用别的包的，同样先展开。然后放这个包自己的内容。在一次展开里，每个包只放一次，放在它第一次出现的位置。所以包集合的内容就是它引用的各包的内容按先后接起来。
- **名字**。引用的包的 `$` 名字在引用它的包里看得到，也转给这个包的使用者；与这个包自己的 `$` 名字一样，按 USE-PACKAGE 那一层的上面一层对待。几个引用的包都定义了 `$X` 时，后引用的遮蔽先引用的，包自己的定义又遮蔽它们全部；每一处遮蔽都给提示，与一层里用了几个包时相同。本版不区分只给包自己用的引用和转给使用者的引用。`%` 名字照旧是各包私有的。
- **只生效一份**。包按名字认，照下面的"哪个 USE-PACKAGE 生效"，经别的包带进来的也算，位置是它展开时所在的位置。
  - 文件直接用的包：照下面的"哪个 USE-PACKAGE 生效"，写在文件里、离这一层最近的 USE-PACKAGE 生效，版本和内嵌的内容都取它的；别的包引用这个包的地方也是这样。它的大版本与引用它的包要求的不同时，给警告：引用它的包可能用到它没有的名字。
  - 只经别的包带进来的包：在同一条层链上的全部引用里，取同一大版本中最新的版本，版本不同时给提示；同一大版本里新版本只增加，所以也能满足较旧的引用。不同大版本的引用是错误：后展开的那条引用失效，用到它的名字的语句随之失效（7.3）。
- **换掉、去掉其中一个**由"只生效一份"推出，不另加规则。写同名的空内嵌包就去掉它，如 `@USE-PACKAGE(name="rnl-std-fill") {}`，它关掉自动补位；写同名的另一个版本或别的内嵌内容就换掉它。被去掉的包若被别的包用到，那些包里用到它的名字的语句失效。
- **成环**。引用成环是错误，闭合这个环的那条引用失效。哪条引用闭合环，取决于展开从哪里开始；环上的几个包都被直接用到时，每个各报一次这个环。
- **诊断报在哪里**。版本不同的提示和大版本不同的警告，报在文件里写的那条 USE-PACKAGE 上（包里的提示和警告不给用户看，7.6）。引用失效的错误报在那条引用上，并说明是文件里哪条 USE-PACKAGE 把它带进来的。
- 代称包不能被引用（16.5）。包文件头段记录里的 USE-ALIASES 照旧只管这个文件。

**几个包里的同一个 `$` 名字**。

- 一层里用了几个包，都定义了 `$X` 时，后用的遮蔽先用的，并给提示。
- 查名字的次序：本层 → 本层用的包（后写的先查）→ 上一层 → 上一层用的包（后写的先查）→ …… → 根上的包（排在后面的先查）。
- 本版没有包限定的名字、给包另起的名字或层级标签（如 `$acme.DIFFERENTIAL_PAIR`、`as=`）。注：以后的版本要加它们，需要名字后面加 `.` 以外的写法，因为名字后面紧跟一个点在句末很常见（`align #M1 and #M2.`）。

**哪个 USE-PACKAGE 生效**。从根往下到一层的层链上，一个包只生效一份。写在离这一层最近的那一层的 USE-PACKAGE 生效，版本和内嵌的内容也取它的；同一层里后写的算近，头段记录里的算写在文件层的最前面。经别的包带进来的包，算写在带它进来的那条 USE-PACKAGE 处，版本按上面"包引用包"选。包排在那条 USE-PACKAGE 的位置；那条 USE-PACKAGE 在头段记录里时，排在根上。

注：否则包里的生成规则（如接地补位）会在下层再跑一遍，把它们的对象生成两份。

**重新使用包**。子电路或库文件可以在它的文件层或子电路里重新使用标准包。这时标准包的外观规则排在上层（如主文件）流下来的规则之后，重新盖过它们；包的 `$` 名字按那条 USE-PACKAGE 的上面一层对待，遮蔽上层的同名定义。这一层用到的符号就不受上层外观规则的影响（6.1）。

- 它只影响符号和名字。上层流下来的几何规则和生成规则照样作用；求解结果因此过时时，给提示，建议重新求解（第 17 章）。
- 只想钉住版本、仍让上层的风格盖过包，就把 USE-PACKAGE 写在头段记录里（16.3）。

**内嵌的包**。USE-PACKAGE 可以带一个体，体就是包的内容。这时文件自带这个包，不查找：

```rnl
@USE-PACKAGE(name="acme-style", version="1.2") {
  $NMOS_ACME = @DEFINE-SYMBOL {$NMOS; (-1, 0) @CIRCLE(radius=2.5)};
  # @SELECT-INSTANCE(type="nmos", recursive=true) => @SET-SYMBOL $NMOS_ACME
}
```

- 内嵌的包与不带体的 USE-PACKAGE 含义相同：包名和包的版本、排在 USE-PACKAGE 的位置、名字照"包里的名字"查找、`$` 名字按上一层对待、`%` 名字私有、按包名认的"只生效一份"，都照上面。体按封装方式收（5.4）。内嵌的包与所在的文件是同一个语言版本（16.1）。
- 内嵌的包与包文件的区别只在：内容写在网表里，没有头段记录。所以它的语言版本跟所在的文件，`version=` 只标识版本，不能声明 DEVICE、SOLVER-CONFIG 或 ALIAS，也不能引用别的包。每个内嵌的包各是一份。所以把内嵌的包搬出去时查找名字的方式不变，但哪个定义是哪个定义未必不变：如果别处已经用过同名同版本的包文件，两者就会合成同一组定义（见上），于是按定义筛选的规则（如 SELECT-USAGE，9.5）就可能选到更多用例。
- 内嵌的包通常只用于两件事：去掉一个包，写同名的空内嵌包（16.3）；把整套包冻结进文件，体里是它们展开后的全部内容，自身是完整的。
- 要扩展标准包，或换掉其中一块，就写一个包文件，在它的头段记录里引用它要用的包（见上面的"包引用包"），再在网表里用 `path=` 指向它。用带内容的内嵌包顶替标准包的一个子包时，它算标准包的一部分，只看自己：用不到标准包别的子包里的名字。

**其他规则**。

- 处理包时不应执行代码，也不应隐式访问网络（原则 2.7）。
- 查看器怎样显示画面，能不能按用户的偏好（如暗色背景、打印）改外观，不归本标准。没有任何样式或参数给值的属性，取渲染器的默认值（9.3，原则 2.7）。

### 16.3 标准包

- 标准包不属于本标准。它与别的包一样用 RNL 写成，单独发布；它的语义定义、虚拟元件和别的内容由包自己定义。
- 标准包里的名字没有强制前缀，如 `$DIFFERENTIAL_PAIR_N`。用户可以写同名的定义，按遮蔽取代标准包的（6.8）。
- **包集合**。标准包 `rnl-std-all` 只有头段记录：它是这个系列唯一的包集合，引用除下面两个可选包以外的其余全部包。文件要么使用整套集合，要么把自己要用的包逐个写出。
  - `rnl-std-style`（样式和默认的样式规则）、`rnl-std-basic` 和 `rnl-std-semiconductors`（符号和定义，包括虚拟元件，如地、电源和端口标签，以及地网、电源网和偏置网的集合），以及两种方言的规则包，它们给元件配符号：`rnl-std-spice` 按元件字母和模型类型，`rnl-std-spectre` 按 master 和模型类型（见下文的方言）。它们把网表画出来，不加东西。`rnl-std-basic` 的头段记录里写有 `@SOLVER-CONFIG(junction="$JUNCTION")`，让求解器用标准定义画圆点（13.2、14.10）。
  - `rnl-std-fill` 里有给没接导线的引脚补上地、电源、偏置标记和网络标签的规则，各画在一段短桩上（10.5）；它引用 `rnl-std-basic`。它筛选引脚，因此虚拟元件落在网络上的引脚也会补位，唯独它自己放置的那些元件的引脚除外。在 0.4 系列里，它给 `$PORT_FILL_SET` 里的每个端口网络补一个端口标签，每一层排成一列（12.4）；除非文件或包用 ROUTE-NET 或 ROUTE-OBJECT 写了出来，否则没有任何网络画成导线；地网、电源网和偏置网用 `@UNROUTE-NET(priority="high")` 排除在外，要把它们画成导线的文件可以写 `@ROUTE-NET(priority="high")` 或 WIRE（13.7）。手写导线接上的引脚，以及由语句或规则形式的 ROUTE-NET、ROUTE-OBJECT 画上导线的引脚，补位不再给它配地或电源符号；要加的文件自己贴上去（10.5）。布线关键字的规则在补位之前求值，补位看得到它们建出来的树（8.2、10.2）。集合 `$GROUND_FILL_SET`、`$SUPPLY_FILL_SET`、`$BIAS_FILL_SET`、`$LABEL_FILL_SET` 和 `$PORT_FILL_SET` 里放的是补位还要加的东西：一次求解把它的短桩和标签写回之后（14.8），它们就不再含有那些引脚和网络，所以文件不要在它们之上另建别的规则，如对它们的引脚写 TEXT。
  - `rnl-std-semantics` 里有电路结构的定义（如差分对、电流镜、信号流与功率流）和布局的定义（如 `$MIRRORED_LAYOUT`）；它们体里的约束，优先级都是 `"low"`（9.5、14.8）。只管摆位置、不作断言也不管布线的定义，对电路本身什么也不说明，名字以 `_LAYOUT` 结尾，如 `$MIRRORED_LAYOUT`。结构名字末尾的 `_N` 和 `_P`（如 `$DIFFERENTIAL_PAIR_N` 和 `$CURRENT_MIRROR_P`）标明晶体管的极性，结构会对类型已知的管子断言这一极性（15.3），并给出与之相配的画法：n 型管源极或发射极朝下，p 型管源极或发射极朝上。
  - 特定领域的包有 `rnl-std-functional`（放大器、比较器、转换器等）、`rnl-std-rf`、`rnl-std-logic` 和 `rnl-std-signal-flow`。
  - 各个包里的名字互不重复，所以用户不必知道一个名字来自哪个包。
  - 可选的 `rnl-std-45deg` 里有按 45 度画的符号，如电桥、交叉耦合对和对角绕组；它不在包集合里，要用的文件写它的 USE-PACKAGE。
  - 可选的 `rnl-std-no-labels` 关掉标准符号的默认标签，给自己写全部标签的文件用；它不在包集合里。在 0.4 系列里，它只筛选画出来的对象（`drawn=true`，10.1），并给它们的名字、值和模型标签，以及用例的符号画出的网络名，指派样式 `textvisible=false`（9.3）；文件只要对其中某一个写上 `textvisible=true` 就能再次显示它（13.3）。可选的 `rnl-std-no-instance-labels` 只对画出来的元件这样做，所以用例的标签保留，例如地、电源、端口标签和网络标签画出的网络名；它同样不在包集合里。以后还可以加别的包。整个标准系列一起发布，用同一个版本号；包集合钉住它的各个包的版本。
  - 这就是标准系列 0.4 的结构；它的 `rnl-std-all` 对每种语言各有一条头段记录（2.8）。
- **不隐式加载**。0.4 版的文件只有写出了 USE-PACKAGE 时才使用标准包 `rnl-std-all`，与别的包一样（16.2）。工具可以提供一条设置，当主文件的头段记录没有以任何形式写 `rnl-std-all` 时帮着加上它，例如命令行的 `--include-std` 选项或查看器里可以默认打开的设置。这项设置打开时，工具在读文件时视同它不带 `language` 的头段记录最前面写了 `@USE-PACKAGE(name="rnl-std-all", version="…")`，版本取工具手头用文件声明的语言版本写的最新标准系列；而当工具往主文件写入时，它会把这条 USE-PACKAGE 写进头段记录，使任何工具画出来的都一样。文件头段记录里钉住的版本对这个文件和它引入的文件有效（见下）。
  - 注：标准包与别的包一样。不是为 RNL 写的网表只有通过这样的设置才会用标准符号画出来；使用了标准包定义（如 `$GROUND`）的文件若不写 USE-PACKAGE，这些名字就会找不到。每个找不到的名字照常报错；若未启用的标准系列某个包定义了这个名字，就给整份文件发一条提示，点出那个包，并提示写 USE-PACKAGE 或启用工具设置。
- **另一种方言的规则包**。两种方言里元件的名字意思不同：在 SPICE 里，`I0` 是电流源；在 Spectre 里，元件的名字不说明什么，Virtuoso 把子电路的实例叫作 `I0`。标准系列 0.4 用 `language` 来写明这一点：它的包集合 `rnl-std-all` 有一条不带 `language` 的头段记录管两种语言共有的部分，一条带 `language="spice"` 的头段记录用 `rnl-std-spice`，还有一条带 `language="spectre"` 的头段记录用 `rnl-std-spectre`（2.8）。因此 Spectre 文件里的 SPICE 段落按 SPICE 的规则找符号，Spectre 段落按 Spectre 的规则。
  - 冻结 0.4 系列的工具会把每种语言的那部分写成对应语言头段记录里的内嵌包，把共有部分写在不带 `language` 的头段记录里：内嵌包里写的是语句而不是记录，自己不能带 `language`。
- **根上的包**。主文件或被引入的文件（其中包括 Verilog-A 文件，2.9）的头段记录里可以写 USE-PACKAGE：

  ```rnl
  * @RNL(type="header") { @VERSION("0.4"); @USE-PACKAGE(name="rnl-std-all", version="0.4")}
  ```

  - 它的范围与文件层的 USE-PACKAGE 相同：写它的文件和这个文件引入的文件。写在被引入的文件里的，管这个文件和它再引入的文件，不管引入它的文件（6.1）。
  - 它排在根上：在所有层的规则之前，也在子电路符号之前（8.3 第 1 组）。它的 `$` 名字也在根上，所以一层里（如主文件里）的同名定义照样遮蔽它。文件层的 USE-PACKAGE 则排在它自己的位置：那是重新使用这个包（16.2），所以它盖过流下来的规则，它的 `$` 名字按上面一层对待。写在头段记录里，包的意思是"这个文件依赖这个版本，上层的风格照样可以盖过它"；写在文件层，意思是"这个文件用这个包定自己的画法"。
  - 哪个 USE-PACKAGE 生效照 16.2：写在离这一层最近的那一层的生效，头段记录里的算写在文件层的最前面。
  - 根上几个包的先后：标准包 `rnl-std-all` 在最前，不论是头段记录里写的还是工具设置加上的；其余按最先写它的文件（由外到内）和那个文件头段记录里的先后。里层文件的头段记录再写同一个包，只改变那个文件的各层用的版本或内嵌内容；位置不变，所以钉版本不改变先后。
  - 头段记录里的包定义了标准包里的、或排在它前面的根上的包里的 `$` 名字时，遮蔽那个定义，并给提示（6.8）。
  - 钉不钉版本由作者选择。建议主文件钉住版本。被引入的文件不钉就跟随引入它的文件；建议它只在依赖某个版本时才钉。工具不应自己给被引入的文件加版本，只有把旧版本文件升级时写的版本钉住除外（16.1）。
  - 建议不要用主文件文件层的 USE-PACKAGE 钉版本：那里的包排在子电路符号之后，而且文件在别处被引入时，这条 USE-PACKAGE 就是重新使用包（16.2），改变了文件的含义。
- **例**。`tb.sp` 的头段记录写 `@USE-PACKAGE(name="rnl-std-all", version="1.2")`，`tb.sp` 引入的 `ota.sp` 的头段记录写版本 `"1.0"`。
  - `tb.sp` 的顶层和 `tb.sp` 里定义的子电路用 `"1.2"`，`ota.sp` 里的子电路用 `"1.0"`。`tb.sp` 的风格规则照样流到 `ota.sp`，盖过 `"1.0"` 的默认。
  - 默认的选法是标准包里的规则做的，如给 `$GROUND` 的用例配地符号的规则。每个版本在用它的各层里选自己的 `$GROUND`，所以 `ota.sp` 照常画。
  - 两个版本里的同名定义是两个定义（16.2）。所以 `tb.sp` 里按定义筛选的规则，如 `# @SELECT-USAGE(recursive=true) $GROUND => @SET-SYMBOL $MY_GND`，只选得到 `"1.2"` 的 `$GROUND` 的用例；`ota.sp` 不钉自己的版本，才会跟着这条规则。按宿主属性筛选的规则，如 `# @SELECT-INSTANCE(type="nmos", recursive=true) => …`，不受影响。
  - `ota.sp` 要让自己的符号不受 `tb.sp` 的规则影响，就在文件层使用这个包（16.2）。
- **少用一点标准包**。工具的设置只加上包名 `rnl-std-all`。
  - 要去掉其中一些包，写同名的空内嵌包去掉它：`@USE-PACKAGE(name="rnl-std-fill") {}` 关掉自动补位。同名包只生效一份，不会生效两份。
  - 只用其中几个时，把它们逐个写出，并写一个空的 `rnl-std-all`，免得工具设置把整套包集合也加上：

  ```rnl
  * @RNL(type="header") {
  *   @VERSION("0.4");
  *   @USE-PACKAGE(name="rnl-std-all") {};
  *   @USE-PACKAGE(name="rnl-std-style", version="0.4");
  *   @USE-PACKAGE(name="rnl-std-basic", version="0.4");
  *   @USE-PACKAGE(name="rnl-std-spice", version="0.4")
  * }
  ```

- **扩展标准包，或换掉其中一块**。写一个包文件，在它的头段记录里引用要用的标准包，再加自己的内容（16.2，内嵌的包）。只添加到标准包上的定义和规则，也可以直接写在网表里；标准包已有的规则，只有同名的包才能去掉或换掉。
- **冻结或不要整个标准包**。在头段记录里写同名的内嵌包。这由按包名认的"只生效一份"推出，不另加规则：
  - `@USE-PACKAGE(name="rnl-std-all", version="1.2") {…}` 把标准包冻结进文件，文件就自包含了；体是各包展开后的内容，按展开的先后接起来（16.2）。并到一个体里之后，两个包可能撞名：两边都用到的私有 `%` 名字，或者一个包遮蔽了另一个包的 `$` 名字。做冻结的工具会把撞名的改名，让每个引用仍找到各自包里原来找到的定义；并把被冻结各包头段记录里的 DEVICE 和 SOLVER-CONFIG 语句按次序写进文件自己的头段记录，排在文件自己的之前（2.8、6.12、14.10），因为内嵌包里不能写它们：通过某种语言用到那个包的，写进那种语言的头段记录，未指定语言用到的，写进不带 `language` 的头段记录；只经由带 `language` 的头段记录用到的包，它的 SOLVER-CONFIG 不抄过来，因为它不起作用（14.10）。抄过来的这些语句，接着排在跟在被冻结包后面的那些包之后。如果排在后面的那个包写了跟抄过来的某一条一样的 SOLVER-CONFIG 键，或者写了跟抄过来的某条 DEVICE 匹配同样元件的 DEVICE 项（端子名或类型），当那个包写在同一文件的头段记录里时，工具就把那条语句写进放了冲突副本的那条头段记录里（排在副本之后、文件自己的之前）；当那个包用在被引入的文件或某一层里时，报告这个冲突。除所报告的冲突外，冻结后的包含义不变；
  - `@USE-PACKAGE(name="rnl-std-all") {}` 不用标准包，哪怕工具的设置本会加上它；这时每个元件都用默认框图符号（9.2.6），其余外观就交给渲染器的默认（原则 2.7）。
- 加粗的总线、总线的分接符号、标总线位宽的标记等约定，也是标准包的内容。没有标准包时，每个元件都用默认框图符号（9.2.6），由渲染器决定绘图风格（原则 2.7）。

### 16.4 扩展与未知内容

- **未知内容**（原则 2.3）。不认识的关键字、参数和取值是错误：这条语句失效，依赖它的语句随之失效（5.5、7.3），其余照常解释（7.6）。记录头的未知字段例外，只给警告（2.8）。SOLVER-CONFIG 里，求解器不认识的键给警告，取不上的值只使它的键失效（14.10）。画面可能因此不完整，诊断应说出这一点。
- **保存时保留**。原则 2.3 建议原样保留这样的内容；本标准把它定为要求：
  - 不是工具自己的记录不改（第 17 章），宿主正文和普通注释也原样不动；
  - 工具改写自己的记录时，里面它不认识的、失效的语句连同它们的自由文本原样保留，次序不变；
  - 版本不受支持的文件整个原样保留（16.1）；
  - 工具改写的记录不必逐字节不变。
- **本版没有扩展机制**。新的语义、虚拟元件和画法写成包里的定义、符号和样式（1.5 第 7 条），不用新的关键字；要实现必须懂的新机制，等本标准的新版本。工具私有的数据，如编辑器的锁定或视图状态，不写进 RNL 记录；放在工具自己的文件里，或记录之外的普通注释里。
  - 注：本版先让各工具读同一种 RNL；这么早就有厂商方言，会把语言分裂，而新的语义已经能写进包里。
  - 注：以后的版本可以把扩展做成带厂商前缀和 `.` 的关键字，如 `@ACME.ROUTE`，在头段记录里声明：工具不认识的必需扩展会让整个文件不解释，可选扩展则跳过并给提示。这样的关键字现在是不认识的关键字，是错误，所以以后加是纯放宽（16.1）；厂商前缀不能用标准关键字的名字。
- 不为扩展预留写法：标准关键字后面紧跟的 `.` 是自由文本，所以 `@BUNDLE.LOCK` 是 BUNDLE 加自由文本 `.LOCK`，句末的 `{#M1 #M2} @GROUP.` 也合法（3.5）。
- **识别但不解释**。本版这类内容只有记录头的未知字段（2.8），以及求解器不认识的 SOLVER-CONFIG 键（14.10）。以后的版本若加扩展，可选扩展是第二种。

### 16.5 代称

```rnl
* @RNL(type="header") {
*   @VERSION("0.4");
*   @USE-PACKAGE(name="rnl-std-all", version="0.4");
*   @USE-ALIASES(name="alias-zh");
*   @ALIAS("@at", "@PLACE")
* }
* @RNL {#M1 @位于(10, 20); {#M1 #M2} @对齐("y"); #M3 @at(x=4); #M1(左管) #M2(右管) #M5(尾管) @视作 $"差分对"}
```

- 代称给标准词另起写法，用来兼容别的大小写用法，或按中文等别的自然语言的习惯写 RNL。
- **代称从哪里来**：
  - 直接写在头段记录里的 ALIAS 语句，用于自己起几个代称；
  - 代称包，在头段记录里用 `@USE-ALIASES(name=…, version=…, path=…)` 加载。一种语言的代称做成一个包，各文件不用重写，用词也处处一致。标准的中文代称包是 `alias-zh`；它随标准包发布，由工具自带（16.3）。
  - 两种可以并用，代称包也可以加载几个；合起来照下面的对应关系检查。
  - 代称只管声明它的文件，不随引入继承；被引入的文件或包文件要用代称，各自在自己的头段记录里声明。同一个标准词在不同文件里可以有不同的代称。写在符号里的文字，它的 key 对照写这个符号的文件的代称检查（6.5、13.3）。
  - 头段记录本身永远按标准写法读，不认代称：读到 USE-ALIASES 和 ALIAS 以前还不知道有哪些代称，而且头段记录多由工具写。所以只能写在头段记录里的关键字（VERSION、ALIAS、USE-ALIASES、DEVICE、PACKAGE）起代称没有用。
- **代称包**：
  - 代称包是一个包文件（16.2），它的头段记录里只有 VERSION、PACKAGE 和一串 ALIAS 语句，此外没有别的记录。它的查找和版本的选择照 16.2。
  - 用 USE-ALIASES 加载不是代称包的文件，或用 USE-PACKAGE 加载代称包，是错误。找不到代称包时，它的 USE-ALIASES 是错误，用到它的代称的语句随之失效（7.3）；诊断给出的原因是缺这个代称包。
  - 注：代称包不用 USE-PACKAGE 加载，因为 USE-PACKAGE 可以写在任何一层，管的是定义和规则，按位置排序；而代称管的是怎样读文件的文字，只能按文件算。两者分开，风格包就改不了文字的读法。
  - 代称包的内容随它所指的东西变：标准包里的名字改了，`alias-zh` 跟着改，版本也升上去。
- **写法**。`@ALIAS("alias", "original")`：代称在前。两个参数是 `alias` 和 `original`，平时按位置写；第三个参数 `definition` 只能写名字（见下）。
- **原名**：
  - 本标准规定的关键字或标准词，按标准的写法。关键字连 `@` 写，如 `"@PLACE"`；别的词不带，如 `"axis"`、`"low"`。代称也这样写：关键字的代称带 `@`，别的代称不带。带不带 `@` 把关键字和拼写相同的标准词分开，代称在正文里的样子也与声明的完全一样。
  - `$` 名字。代称和原名都带 `$`，如 `@ALIAS("$接地补位集", "$GROUND_FILL_SET")`；正文里写 `$"接地补位集"`（`$` 后面的非 ASCII 名字要加引号，3.6），读作 `$GROUND_FILL_SET`。`%` 名字没有代称：写的人可以直接起别的语言的名字，包里的 `%` 名字又是包内私有的。
  - 定义里的名字，用 `definition=` 声明，如 `@ALIAS("左管", "left", definition="$DIFFERENTIAL_PAIR_N")` 或 `@ALIAS("间距", "gap", definition="$GROUND_STUB")`。这种代称只在那个定义里查：套用它时的角色名（`#M1(左管) #M2(right) #M5(tail) @AS $DIFFERENTIAL_PAIR_N`）、AS 和 ATTACH 传给它的参数名（`$GROUND_STUB @ATTACH(间距=3) …`）、经 `::` 从它的用例取的局部名（`%c1::"中点"`）。`definition` 的值本身也可以写成代称。标准词的代称不用于这些位置，只有 AS、ATTACH 自己的参数 `priority` 除外。
    - 代称按名字认：它们跟着这个 `$` 名字走，在下层用同名定义遮蔽了它的地方也适用，就像 `$` 名字的代称换的是拼写一样。
    - 声明代称时不查原名在不在那个定义里；套用定义时找不到的名字，照常是错误（如"没有角色 in_p"）。
    - `::` 后面的名字按 6.5 的次序找：用例自己的名字、它们的 `definition=` 代称、标准子对象名和它们的代称、对象符号里的引脚名、文字的 key。
    - 筛选条件 `role=` 的值，和 `${…}` 里沿角色往下取的路径，也认这些代称，每一步在那一步的用例的定义里查，如 `%dp1 @SELECT-INSTANCE(role="左管")` 或 `${左管::w}`，其中 `%dp1` 是 `$DIFFERENTIAL_PAIR_N` 的用例。范围里有几种定义的用例时，各按各的定义查；原名照样能用。
- **能起代称的**：词表里除下一条所列以外的全部词，即关键字、内置关键字的槽位名、参数名和取值、种类名、子对象名、属性名、样式属性、`true` 和 `false`（5.3）；以及上面说的 `$` 名字和定义里的名字。
- **不能起代称的**：外层写法，即 `@RNL`、记录头的字段名和 `type` 的值、`@VERSION`；以及 `@ALIAS` 和 `@USE-ALIASES` 本身。
- **另起名字**。名字本来就是对象的另一个名字：`$"差分对" = $DIFFERENTIAL_PAIR_N` 之后，`$"差分对"` 就是同一个定义。这种名字是正文的一部分，去不掉，也管不到角色名、参数名；要一整套别的语言的名字，用代称。
- **对应关系**：
  - 一个原名可以有几个代称；同一个范围里，一个代称只代表一个原名。每个定义的 `definition=` 代称各是一个范围。
  - 代称不应与文件声明的版本里的任何标准词拼写相同，也不应再声明给别的原名。`definition=` 代称不应与那个定义的角色名、参数名、局部名拼写相同，也不应与 AS、ATTACH 自己的参数 `priority` 的代称拼写相同。
  - 代称不能当原名用，也不能与它的原名相同。文件升版本时，新加的标准词与某个代称拼写相同，给警告，版本照样升（16.1）；升了以后，这个代称与新版本的标准词同拼写，照上面的规则是错误。
  - 代称包必须声明用这个包的文件的语言版本（16.1）；否则它的 USE-ALIASES 是错误。
- **代称只增加写法**。标准写法始终有效，同一文件里可以混写。
- **代称只换整个记号**：
  - 代称换的是整个记号，不是文本宏，所以位置和诊断都对得上；
  - 不带 `@` 的标准词按拼写起代称，所以拼写相同的词（如参数名 `x` 和取值 `"x"`）共用代称；
  - `$` 名字的代称换的是拼写：写 `$"接地补位集" = {…}` 的人，就是在那一层定义 `$GROUND_FILL_SET`，它遮蔽标准包的那个，并给提示（6.8）。
- **词法**：
  - 关键字的代称是 `@` 后面紧跟的字母（任何文字）、数字和下划线，不含 `-`；它们组成一个记号，`@` 前面应有空格（2.3），中文标点后面也一样：`对 &b，@选出元件` 是错误，应写成 `对 &b， @选出元件`。任何不是字母、数字或下划线的字符都结束这个代称：空格，或者任何文字的标点，如 `，` 或 `。`。所以 `@对齐两个器件` 是一个不认识的关键字，是错误，它的诊断应问 `@对齐` 后面是不是漏了空格。没有针对某一种语言的规则：任何文字里不是字母、数字或下划线的字符都结束代称，括号外的非 ASCII 字符则是自由文本（3.3）。记号不按已声明的代称切分，所以读出记号不用先看声明。
  - 不加引号的非 ASCII 词只出现在两处：`@` 后面，和括号里。在 `@` 后面，这个词应是声明过的代称，否则是错误（"非 ASCII 的名字要加引号"）。在括号里（参数名、内置关键字的槽位名、`true` 和 `false`、角色名），声明过的代称就是代称；在角色名或定义的参数名的位置上，不是代称的词就是名字本身（3.6）；在别的位置上，不是代称的词是错误。别处照 3.6：宿主名字、RNL 名字、端子名和 `::` 后面的名字不加引号时只有 ASCII 字符，用在 `::` 后面的代称也要加引号，如 `#M1::"位置"`。
  - 括号里不加引号的代称，与同一位置上可用的某个定义的参数名或角色名拼写相同时，是错误，因为含义不唯一。括号里加了引号的词永远是名字，不是代称。`$` 名字的代称和 `::` 后面的代称本来就写在引号里（3.6）。
  - 枚举取值的代称写在字符串里，只在取值是枚举的参数里起作用。`${…}` 里的属性名也认代称（13.6）。别的字符串，如 TEXT 的 `text`，不换。
- **诊断与翻译**：
  - 诊断照文件里写的样子显示词，并附上它们的标准写法。
  - 翻译器两个方向都是机械的。翻成代称写法时，它在头段记录里写 USE-ALIASES；要文件自包含时，改为把用到的代称写成 ALIAS 语句。一个原名有几个代称时，取第一个声明的。翻回标准写法时去掉 USE-ALIASES 和 ALIAS，不丢信息。
  - 自由文本、注释和字符串不翻译，枚举取值和 `${…}` 里的属性名除外。
  - LLM、求解器和编辑器写标准写法。它们改用代称写的文件时，加的语句也用标准写法；混写是合法的。
