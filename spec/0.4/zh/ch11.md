## 11 放置与外观

### 11.1 位置：PLACE

```rnl
#M1 @PLACE(10, 20);
#M1 @PLACE(x=10)
```

- PLACE 给对象的位置赋值，`x`、`y` 至少应写一个。PLACE 只设定写出的坐标。每个坐标起初是自由的，没写过的一直自由，由约束和求解器决定。
- PLACE 只管坐标，不管旋转、镜像、缩放和端子的方向；朝向由 ORIENT 设置（11.2）。
- 一条 PLACE 是两个几何事实，x、y 各一个，冲突时可以各自丢弃（8.5）。参数 `priority=` 给它的优先级（14.8），如 `#M1 @PLACE(12, 20, priority="high")`：按位置写的 x、y 在前，写名字的参数在后（4.2 第 9 条）。
- 对象：元件、用例（按它自身的点，14.1）、叠画（11.8）、点、TEXT（标注和标签；PLACE 定的是文字自己的位置，13.3），以及原点 `::position`（含中心写法的 RECTANGLE、CIRCLE、ELLIPSE 的中心）。PLACE 不收别的图元；要移动它们，就移动它们的点（13.4）。在普通定义的体里，它的坐标是相对于用例自身的点的偏移量（9.4）。符号体里的 PLACE 只给附着在 `?` 上的 TEXT 定位置，坐标是局部的（9.2.2）。
- 输出沿用输入的句柄（5.1）。
- 对象是集合时逐个放（5.2.1）：`%pair_set @PLACE(10, 20)` 把两个成员都放在 (10, 20)。集合本身没有位置（14.1）。
- 坐标的轴向、单位、小数和容差见 11.7。

### 11.2 朝向：ORIENT

```rnl
%pair_set = {#M3 #M4};
#M2 @ORIENT("MY");          /* flipped left-right */
%pair_set @ORIENT("R90");   /* each member turns about its own origin and stays where it is */
#M5 @ORIENT(["R0", "MY"])   /* not turned, or flipped left-right: the solver chooses */
#M6::g @ORIENT("left")      /* M6 is oriented so that its gate faces left */
```

- 对象：元件、有符号的用例、叠画，以及引脚（见下）。没有符号的用例收到 ORIENT 时失效（12.1）；点、标签、图元、导线、网络不收。
- 对象是集合时逐个做（5.2.1）：每个成员绕自己的原点转，位置不变，每个成员是一条描述。不是把整个集合当一块转。不提供整个集合一起转：集合没有位置（14.1）。
- 有符号的用例绕它自身的点转；它有自己的朝向，不跟着填它角色的对象转（12.1）。它定义体里画的或摆的东西也不跟着它转（9.4）。
- **朝向码列表**，如 `["R0", "MY"]`，构成一条事实：当对象取所列朝向之一时成立。冲突时作为整体保留或丢弃（8.5），由求解器在所列的码里挑选。列表至少含一个朝向码；只有一个码的列表与直接写那个码相同。求解器在它的记录里把自己选定的朝向写回成单个朝向码（14.8）；作者记录里的列表留在原地，下次求解会重新挑选。不求解且对这个对象没有求解结果的渲染器按列表第一个码画。
- 没写 ORIENT 就是没有约束，由求解器选；不求解的渲染器按 `"R0"` 画（8.5）。几个对象的朝向之间的关系（同向、互为镜像）写 ORIENT-RELATION（14.9）。
- ORIENT 是一个几何事实，参加冲突的取舍（8.5）；参数 `priority=` 给它的优先级（14.8）。
- **朝向码**：一个码表示一种朝向。只认下表的八个写法以及下文四个表示方向的词，区分大小写（3.6）。名字与 Virtuoso 相同，y 向上（11.7）时含义也相同。等价的别的写法（如 `"MXR180"`，就是 MY）、任意角度都不认，单独写和写在列表里都一样：它们是写错的参数值，这条 ORIENT 失效。工具写回时只写这八个，每次写一个。没有"在现在的朝向上再转"的相对写法（第 17 章）。

  | 码 | (x, y) 变成 | 含义 |
  |---|---|---|
  | `"R0"` | (x, y) | 不转 |
  | `"R90"` | (−y, x) | 逆时针转 90° |
  | `"R180"` | (−x, −y) | 转 180° |
  | `"R270"` | (y, −x) | 逆时针转 270°，即顺时针转 90° |
  | `"MY"` | (−x, y) | 关于 y 轴镜像，左右翻 |
  | `"MX"` | (x, −y) | 关于 x 轴镜像，上下翻 |
  | `"MYR90"` | (−y, −x) | 先 MY 再 R90 |
  | `"MXR90"` | (y, x) | 先 MX 再 R90 |

- **四个旋转朝向的方向词。** 旋转朝向也可以写成方向词，含义对应表中的朝向码：`"left"` 是 `"R0"`、`"down"` 是 `"R90"`、`"right"` 是 `"R180"`、`"up"` 是 `"R270"`，列表里也可以这样写。ORIENT-RELATION 只收朝向码（14.9）。写在对象上时，这几个词只是另一种拼写：`#M2 @ORIENT("left")` 就是 `#M2 @ORIENT("R0")`。写在引脚上时则照字面读：引脚面向的方向（以左向为基准计算）。
- **引脚。** 对引脚（或者代表它引脚的端子，5.2.4）写 ORIENT，是约束引脚在图上的方向：符号里用 `direction=` 写出的方向（9.2.4）随所属对象的朝向（八种之一）旋转、镜像后的方向。当对象具有能把该引脚转到这个方向（或所列方向之一）的朝向（八种中有两种）时成立，所以这并不把对象的朝向唯一固定；写成列表时允许所列的每一个方向。传给引脚的镜像码，代表它把 left 转过去的方向：`"MY"` 是 `"right"`，`"MX"` 是 `"left"`。这样写出的 ORIENT 是它自己的一条几何事实，以该引脚为键，独立于对所属对象写的 ORIENT；两条事实按冲突规则一起取舍（8.5）。没有写 `direction=` 的引脚没有什么可约束的：那个引脚上的 ORIENT 失效，同一语句的其他成员照常生效（5.2.1）。不求解且没有求解结果的渲染器，画图时当作没写引脚上的 ORIENT。
- **合成次序**：MXR90、MYR90 先镜像再转；名字按动作的先后读，与 Cadence、OpenROAD 的 OpenDB 相同。
- **怎样作用**：朝向绕符号的原点作用于局部坐标，再把原点放到对象的位置上：符号上一点画出的位置 = 对象的位置 + 朝向作用于这一点的局部坐标。符号里的图元、引脚位置都随之刚性变换，引脚的出线方向也跟着转（9.2.4）。文字按 9.2.5 的规定显示；字形不镜像。
- **只改变画在哪里**：朝向只改变引脚画在哪里，不改变引脚属于哪个端子。子电路符号上下翻以后，inp 的引脚画到了下面，接 inp 的导线跟着过去。不会为了让 inp 留在上面而把两个引脚对调：那等于改了哪根导线接哪个端子，是网表的事（原则 2.2）。要 inp 画在别处，换一个符号（11.3）。

### 11.3 符号与样式：SET-SYMBOL 与 SET-STYLE

```rnl
%w13 = &x @WIRE {#M1:1 #M3:1};
#M1 @SET-SYMBOL $NMOS;
# @SELECT-INSTANCE(model="nch") => @SET-SYMBOL $NMOS;
%w13 @SET-STYLE $signal;
# @SELECT-INSTANCE => @SET-STYLE $base
```

- SET-SYMBOL 给对象指派符号。对象可以是元件、用例、叠画，或它们的集合（含筛选和逐个生成的结果），对每个成员各指派一次（5.2.1）。在子电路里，`# @SET-SYMBOL` 给的是子电路符号（9.2.6）。
- 用例被指派了符号就画出来：它就是虚拟元件（第 12 章）。
- **把端子对应到引脚。** 符号的端子名就是它的引脚绑定的名字（9.2.4）。SET-SYMBOL 给元件指派符号时，符号里的每个端子名对应元件上由 DEVICE 或子电路端口给出的同名端子（6.12）；序号则对应那个位置上的端子。元件上没有被任何引脚绑定的端子没有引脚，如三端符号里的衬底。元件没有的符号端子名，它的引脚什么都不绑定，给警告。
  - `terminals=` 改变这一次 SET-SYMBOL 的对应方式。标准写法按元件行上结点的顺序列出符号的端子名（与 DEVICE 的 `terminals` 相同，6.12）：例如符号的引脚绑定了 `"a"`、`"b"`、`"c"` 时，`#X1 @SET-SYMBOL(terminals=["b", "a", "c"]) $GATE` 把结点 1 绑到 b 的引脚、结点 2 绑到 a 的引脚、结点 3 绑到 c 的引脚。也可以写成二元组列表，元件端子在前、符号端子在后：`terminals=[["d", "b"], ["g", "a"], ["s", "c"]]`；未在二元组中列出的端子仍按名字对应。既不是这种顺序列表也不是二元组列表，或者把同一个端子写了两次时，是参数错误，这条 SET-SYMBOL 失效。
  - 对于用例，符号的端子名对应它定义的角色名。序号、或者没有对应角色的名字，不绑定任何角色，给警告。`terminals=` 按角色表的顺序列出符号端子名，或者写角色名与符号端子名的二元组（12.1）。
- SET-STYLE 给对象指派样式。对象可以是元件、用例、叠画、导线、图元（含文字），或它们的集合（含筛选和逐个生成的结果）。不收网络、层、约束、定义、点。端子随所属对象的符号画，跟所属对象的样式。用例收到的样式传给它的符号和它体里创建的可画对象（8.3），所以没有符号的语义用例收到样式不出错；体里没画东西时，看不出效果。
  - 注：否则标准包的规则 `# @SELECT-USAGE => @SET-STYLE $base` 会对每个语义用例给警告。
- 输出沿用输入的句柄；对象是集合时，输出就是这个集合。
- 两者都经外观队列生效，不按键覆盖。分两级：直接指明对象的 SET-SYMBOL 或 SET-STYLE，高于经筛选到达对象的和传给对象的（8.3）。
- 有默认规则时（标准包，16.3），可以不写。
- **参数与样式**：写在对象上的样式参数，如 TEXT 的 `size=`，是这个对象直接的样式，高于筛选来的、传来的样式。之后写的、直接指明这个对象的 SET-STYLE 按位置盖过它们（8.3）；编辑器就靠这个单独改一个对象。定义的参数没传时当作没写，样式随之生效（9.4）。
- **标签与交汇圆点**：对象的样式传给附着在它上面的文字。在"筛选来的、传来的"这一级里，它与选这段文字的规则（如 SELECT-LABEL）按位置比；文字自己的参数和直接指明这段文字的 SET-STYLE 在直接的一级。所以 `#M1 @SET-STYLE $signal` 写在标签规则之后时，M1 的名字也取这个颜色，拖动名字也不会换颜色。符号里附着在 `?` 上的文字也是标签，SELECT-LABEL 选得到；附着在点上的固定文字是符号的图元，用所属对象的样式。附着在网络或点上的文字不从附着的东西得到样式，只用自己的。交汇圆点是 `$JUNCTION` 的用例（13.2）；圆点是它的符号，颜色跟用例的样式。

### 11.4 一物多画

没有办法把一个宿主对象画几次：宿主句柄如 `#M1` 总是指这个对象唯一的那一次画出。以后的版本若加一物多画，多出的画法会是另外的对象，有自己的名字，宿主句柄的含义不变（附录 C）。

注：几个元件画成一个，是叠画（11.8）。

### 11.5 分组：GROUP

```rnl
%stage1_set = {#M1 #M2 #M5} @GROUP;
%stage2_set = {#M3 #M4} @GROUP(spacing_x=-1);
{%stage1_set %stage2_set} @GROUP;
%stage1_set %stage2_set @DISTANCE("left-to-right", min=1)
```

- GROUP 给一个集合加一条事实：求解器把它的成员当作一块处理。它沿用集合的句柄，所以 `%stage1_set` 仍然是那个集合。
- **组不是对象。** 组没有位置也没有边界框，不能对组写约束：传进约束里的带组集合只是集合，写它的槽位代表里面的每一个成员（14.1）。GROUP 也不是第五种原子约束。标准包里成组的结构带的是匿名组。
- **成员。** 组的成员是它集合里的对象，嵌套的集合一直向下跟踪到最里层的对象。没有符号的用例代表填它角色的各个对象，一直向下到最底层的对象；有符号的用例本身就是一个成员。ROUTE-OBJECT 以同样方式跟踪角色的成员，同时把有符号的用例自身的引脚也计入（13.7）。
- **作用。** 组只从两方面引导求解器：把一组的成员摆在一块（先于其余器件或与之分开），并在事实允许的范围内让别的器件排到这个组的区域外面。两者都是求解器的准则，排在全部语言描述之后（8.5）：组不保证任何几何关系，被事实逼进组区域里的对象仍画在那里。位置上的要求，如不穿插（例子里的 DISTANCE）或居中，写成原子约束。
- **组的树形结构归求解器。** 组按包含关系嵌套：`{%stage1_set %stage2_set}` 的成员是五个元件，所以两级都包含在里面。两个共用一部分成员、但谁也不包含谁的组不能都作为整体块：求解器按自己的规则保留其中一个，并在提示中指出另一个。在此之外，组如何影响搜索与打分由实现决定。
- **间距（spacing）。** `spacing_x` 和 `spacing_y` 是整数个网格单位（11.7），由求解器加到组内的默认间距上，分别用于 x 和 y 方向；两个参数各自可省，负值把组摆得更紧。两个对象之间，采用同时包含两者的最内层组的间距；不在同一个组里的对象之间，采用这一层的间距，由 `@SOLVER-CONFIG` 用同名键设定（14.10）；组与组外对象之间，采用外层组或这一层的间距。求解器可以对取值范围设限，并说明所设限制。间距是求解器的准则，不是事实：它让位于每一条保留下来的事实。
- GROUP 是关键字，不是标准包里的定义：它的含义只有求解器懂，写不进定义的体（1.5 第 7 条）。
- 查看器可以把分组画出来，如画一个框；这是查看器的事，本标准不规定。
- GROUP 不是原子约束：它不参加冲突的取舍（8.5），也没有优先级，只有开和关。`%stage1_set @PRIORITY("disabled")` 让求解器收不到这个组，也就是取消分组。外层用例为 disabled 时，它展开出的分组也关掉，除非从外面经 `::` 直接写在某个分组上的 PRIORITY 把它重新打开（14.8）。定义展开里的分组，只有是命名的局部对象、从外面引用时，才能单独关掉（9.4）。

### 11.6 绘制顺序与图层：LAYER

```rnl
@RECTANGLE(fill="fillcolor") {(0, 0) (40, 30)} => @LAYER("bottom") => %f1;    /* a frame, drawn below everything */
(2, 28) @TEXT("input stage") => @LAYER("top") => %n1
```

- 有三个图层：`"bottom"`、`"middle"`、`"top"`。先画 bottom，再画 middle，最后画 top。同一图层里按位置先后画：后面的对象画在前面的上面，盖住它。
- `@LAYER(…)` 设对象所在的图层；不写就在 `"middle"`。每个对象一个键，后写的 LAYER 覆盖（5.8）。LAYER 不改变对象在图层里的位置。
- **位置**按书写的次序（1.5 第 2 条），与 8.3、8.5 用的次序相同：同一层里按文本先后；包的内容在它的 USE-PACKAGE 的位置，根上的包在最前（16.3）；用 `scope=` 写进来的语句排在目标子电路自己的文字之后。各类对象取下面的位置：
  - 导线、图元、文字（标注和标签）：创建它的语句；
  - 用例：实际生效的那条 SET-SYMBOL；符号由规则指派的，取规则的位置（8.3）；
  - 规则、定义展开、逐个生成产生的对象：产生它的那条语句，同一次展开里按体内的先后；
  - 元件：在所在图层的最底下，元件之间按网表顺序；放进别的图层的元件在那一层的最底下。叠画当作元件，取它第一个成员的网表顺序。
- 改变对象的语句，如 PLACE、ORIENT、SET-STYLE、LAYER，不移动它的位置。
- 对象：元件、有符号的用例、叠画、导线、图元、标签；集合逐个做（5.2.1）。没有符号的用例收到 LAYER 不出错，只是没有效果（与 SET-STYLE 相同，11.3）；点、网络、约束、定义收到时失效。
- 符号里的成员没有图层：按成员顺序（9.2.1）跟着所在的对象一起画。
- 不设数字的 `z=`。覆盖（按事实的键）和遮挡（按图层和位置）是两回事。
- "图层"在这里指绘制的先后，与宿主的层（2.6）无关。

### 11.7 坐标与单位

- **轴向**：x 向右，y 向上；y 越大越靠上。所以 ORDER、DISTANCE 的 `"bottom-to-top"` 是从下往上（14.3、14.5），R90 是逆时针（11.2）。SVG 等格式和一些编辑器是 y 向下，画出、导入、导出时由实现把 y 取反。
- **单位**：单位没有物理尺寸。一个单位画多大、打印多大，由查看器决定。
- **小数**：坐标和长度都可以写小数（3.7），不必是整数，位数不设上限。坐标照写的值画，不吸附到整数上。
- **网格**：建议引脚放在整数点上（9.2.4）；符号里的图元不受此限。元件放在整数点上、朝向是八种之一时，整数的引脚位置变换以后仍是整数，导线也就落在整数点上：整数点就是通常说的网格。语言没有自己的网格。求解器给自由坐标取不取整数是它自己的规则，排在全部语言描述之后（8.5）；约束逼出小数时就用小数。走线方式算出的拐点照算出的值，不取整（13.1）。
- **容差**：检查约束是否满足、判断冲突时（8.5），差在容差以内就算满足。容差是求解器的选项，用户可以设定；本标准不规定它的值，但它大于 0，这样写不成有限小数的值也能写回（见下）。不求解的查看器检查时用自己的设置。所以恰好卡在容差边上的情况，两个工具的结论可能不同。求解器写回坐标时，写成读回来还是同一个值的十进制小数，不另外截短；写不成有限小数的值，如 1/3，写足够多的位数，使记录读回时，它满足的事实仍在容差内成立（第 17 章）。
- **符号的坐标**：DEFINE-SYMBOL 体里的局部坐标与场景同单位、同轴向，原点就是符号的原点（9.2.1、6.5）。没有缩放：符号不带缩放参数，元件也不能缩放。导入器把别的工具的符号换算成 RNL 的单位。
- **其他长度**：语言里的长度都按坐标单位算，随图一起缩放：DISTANCE 的 `min`、`max`、`exact`，CIRCLE 的 `radius=`，RECTANGLE、ELLIPSE 的 `width=`、`height=`，字号 `size`（同 SVG 的 `font-size`），线宽 `linewidth`，箭头长度 `arrowsize`（9.3），以及定义里当长度用的参数（如 `gap=3`）。线宽 0 是例外：在任何缩放下都一样细的细线，也是默认（9.3）。
- **原点与纸面**：场景的原点没有特别的含义。每个子电路一张图（6.1），各有自己的坐标；查看器按内容的范围取景。RNL 不记纸面大小，也不记编辑器的吸附网格。

### 11.8 叠画：BUNDLE

Virtuoso 的叠合元件，如 `I0<3:0>`，是一个符号，网表里却是四行：

```spice
* A unit cell repeated four times
* @RNL(type="header") { @VERSION("0.4")}
.subckt unit in out vdd vss
R1 in out 1k
.ends unit
XI0<3> D<3> out vdd vss unit
XI0<2> D<2> out vdd vss unit
XI0<1> D<1> out vdd vss unit
XI0<0> D<0> out vdd vss unit
* @RNL {
*   #XI0<3:0> @BUNDLE => @PLACE(30, 10) => %x;   /* four instances drawn as one symbol */
*   &D<3:0> @WIRE {(20, 10) %x:in};              /* a bus to the in pin of the bundle */
*   &out @WIRE {%x:out (40, 10)};                /* all four members are on out: an ordinary pin */
*   %x @TEXT("I0<3:0>", key="name")              /* the name, written out */
* }
.end
```

- **新的对象**：BUNDLE 收一个宿主元件的集合，产生一个叠画，代替这些元件画一次。成员按写的次序，第一个成员决定引脚和符号。
- **引脚和符号**：端子名、端子个数照第一个成员。外观队列把叠画当作它的第一个成员：筛选按第一个成员的条件选到叠画（10.1），子电路符号照用。直接写在叠画上的 SET-SYMBOL、样式、PLACE、ORIENT、LAYER、约束、文字都是叠画的。
- **端子**：叠画的端子，如 `%x:in`，代表各成员的同名端子：它是一个总线引脚。
  - **按名字**：叠画的端子代表各成员的同名端子，不管这个名字在各个成员的端子顺序里排在第几；没有这个端子名的成员不计入其中。
  - `::net`：各成员接同一个网络时就是这个网络，如 `%x:out::net` 是 `&out`；否则是按成员次序的网络集合，如 `%x:in::net` 是 D<3>、D<2>、D<1>、D<0>。所以定义里的 `?t::net @WIRE {…}` 收到集合时画成总线，收到单个网络时是普通导线（13.1）。
  - 导线接到叠画的端子，就是接了各成员的这个端子（10.2）。
- **属性**（13.6）：各成员相同时就是这个值，否则用 `,` 把各值连起来。`${w}` 都是 1u 时显示 1u；`${name}` 是 `XI0<3>,XI0<2>,XI0<1>,XI0<0>`，要显示 `I0<3:0>`，就写同 key 的文字，如上例。端子的 `${net}` 同理，如 `D<3>,D<2>,D<1>,D<0>`。
- **筛选**：成员选不到，选到的是叠画（10.1）。所以"给每个没接线的引脚补一个网名"这类规则在叠画上只补一个标签，显示整条总线。定义里收元件的角色也收叠画，收端子的角色也收叠画的端子（9.4）。
- **成员不单独画**：关于画图的描述（位置、朝向、符号、样式、图层、约束、导线、文字）直接写在成员或成员的端子上时失效：成员只通过叠画画出。不涉及画图的描述照常，如 CURRENT 和语义用例的角色。
- **都是同一种**：建议各成员的模型名或子电路名相同，且端子名的个数、名字和顺序也都相同。不同时给警告；照样叠画，引脚和符号照第一个成员。只是参数不同的成员不给警告：它们的属性把各值接起来显示（见上）。
- **一个元件只在一个叠画里**：一个元件写进几个 BUNDLE 时，归后写的那个（1.5 第 2 条）；先写的保留其余成员，可以给提示。先写的叠画成员都被拿走时是空的，不画，给警告。
- BUNDLE 只收直接写出的对象：收到筛选的结果，或者依赖筛选的集合（10.4）时失效，因为叠画在定符号前就要存在（8.2、10.4）。同理，第 6 步生成的内容里的 BUNDLE 失效。BUNDLE 收到空集合时失效（5.2.1）。成员不是宿主元件时失效（种类不对）。找不到的成员使整条语句失效（严格，7.3）。
