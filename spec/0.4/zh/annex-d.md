## 附录 D 与 0.3 版相比的改动（说明性）

0.4 版把每一条关于位置的事实都连方向一起写出来，使一条事实只表示一种摆法，而不是几种之间的备选。0.x 各版本之间不承诺兼容（16.1）；本附录列出改了什么，以及文件怎样迁到 0.4 版。本标准只描述 0.4 版；0.3 版的文件由读取 0.3 版的升级工具迁到 0.4 版，该工具按本附录最后所列的各项作改动（16.1）。

| 改动 | 见 |
|---|---|
| 方向全部明确写出。ORDER 和 DISTANCE 只收四个方向；留空方向的 `"x"` 和 `"y"` 是错误的参数值。DISTRIBUTE 改用参数 `direction`（不再用 `axis`），收方向而不是轴：它的成员沿这个方向严格依次排列，步长相等，两个成员时就是 ORDER。ALIGN 收一个投影，不收列表 | 14.1–14.5、8.5 |
| ORIENT 和 ORIENT-RELATION 收朝向码的列表，如 `["R0", "MY"]`：一条事实，当其中之一满足时即成立；求解器从中选用一个并写回单个朝向码。只有朝向这类事实才提供这种备选 | 11.2、14.9、8.5 |
| ORIENT-RELATION 关联一个对象与一个对象。一个槽位里的集合逐个成员处理，每个成员一条事实；两个槽位同时出现多于一个成员的集合是错误。0.3 版把两个集合当作整体来关联 | 14.9、5.2.1 |
| 成员位置：集合引用后紧跟 `{…}` 时按位置取成员，在拆开一层的成员上计数，如 `%a{1}`、`%a{end}`、`%a{2:end}`；用例按角色取成员，对筛选取成员位置是错误。在 0.3 版里，`%a{#b}` 是两个对象 | 5.2.3、3.2、3.3、3.5、4.1、6.10 |
| 约束只收最底层的对象。集合没有位置：没有中心，也没有范围，它的 `::position` 是各成员位置的集合。集合照所写的样子保留它的各项；在 ALIGN、ORDER 和 DISTRIBUTE 的成员列表里，作为集合的项（`{…}` 或集合引用）分别代表它的每一个成员，每种组合一条约束，各自作冲突取舍的单位；DISTANCE 使一个槽位的每个成员与另一个槽位的每个成员配对。在 0.3 版里，集合里的引用会打散，`{%x}` 按中心算，DISTANCE 比的是范围 | 14.1、14.3–14.5、5.2、5.2.1、6.5、8.5、11.1、11.2 |
| 用例不再画在填它第一个角色的对象的坐标点上：它的符号画在它自身的点上，而在引脚上画记号的定义在定义体里把它的点绑到那个引脚。绑定角色的引脚画在填该角色之对象的网络上，因此 `$GROUND @ATTACH #M5:3` 是把一个地挂在 M5:3 所在的网络上，处于它自己的位置；用例符号里的编号不再绑定角色。在 0.3 版里，那样的用例画在引脚上，没有自己的位置 | 12.1、12.2、12.5、12.6、6.5、8.2、9.2.7、11.2、11.3、13.2、14.1、15.2 |
| 普通定义可以没有角色（`roles=[]`），写成 `$PORT_LIST @ATTACH` 来套用。它的体里可以写规则：这些规则当作写在用例所在层、处于其语句位置上的规则，体里的 `#` 就是那一层。普通定义里单独的 `?` 后可以接路径，如 `?::position` | 9.4、8.2、10.4、4.1 |
| 本标准只描述 0.4 版：0.3 版和 0.2 版的文件属于别的大版本的文件，由读取 0.3 版的升级工具迁到 0.4 语言和 0.4 标准系列。0.3 标准曾描述工具怎样读取 0.2 版文件 | 16.1 |
| 标准包不再隐式使用：文件写出 `@USE-PACKAGE(name="rnl-std-all", …)`，或者由工具按设置（如 `--include-std` 或查看器设置）加上并在写文件时写进文件。在 0.3 版里，它用在每个文件的根上 | 16.3、16.1、16.2、6.1 |
| 普通定义体里点与 PLACE 的字面量坐标，是相对用例自身的点的偏移，而且用例的 ORIENT 不旋转它们。在 0.3 版里，它们是层的坐标 | 9.4、11.1、11.2、13.4 |
| DISTANCE 同时也定下顺序：它的界限不能为负，没写 `min` 时为 0。在 0.3 版里，带方向的 DISTANCE 的界限可正可负 | 14.5 |
| 规则与阶段：WIRE 的规则已去掉，而且 BUNDLE、WIRE 以及两点写法的 RECTANGLE、CIRCLE 和 ELLIPSE 不收筛选的结果，也不收依赖筛选的集合；四个布线关键字的规则在单独的一步（第 5 步）求值，在生成之前，生成看得到它们的树；LINE、ARC、BEZIER 和 CURRENT 的规则在第 6 步随生成规则一起求值；写在引脚上的 CURRENT 在指派符号后生效。在 0.3 版里，这些规则在各自关键字所处的阶段生效 | 10.4、8.2、11.8、13.1、9.2.5、15.2 |
| 每个用例都有自身的点，没有符号的也一样，写作 `%u::position`：PLACE 收它，带符号画出的用例上的约束也收它。在约束的成员列表里，没有符号的用例代表它的成员，同 GROUP 一样一直向下到最底层的对象，同一对象取两次的组合略去。普通定义体里单独的 `?` 指正在展开的用例。用例被约束的点没有绑在任何画出来的东西上时，给一条提示。在 0.3 版里，没有符号的用例传给 PLACE 和约束会失效 | 14.1、9.4、12.1、6.2、6.5、3.3、7.1、8.2、11.1 |
| 选择性布线（selective routing）：ROUTE 由 ROUTE-NET（整条网络，如过去的 ROUTE）、ROUTE-OBJECT（一些对象的引脚，按网络分别连）、UNROUTE-NET 和 UNROUTE-OBJECT（排除引脚）取代。每个引脚由覆盖它的最高优先级语句决定，再比后写的。同一网络上共用引脚或由写出导线连起来的树合为一棵树。树里的引脚算作 `wired` | 13.7、10.1、10.2、附录 A |
| 在由树连起来的网络上，求解器可以拆分作者写的导线，从中间分叉；求解器在自己的记录里改写这根导线，按次序保留作者的点 | 13.1、13.7 |
| 分组不是对象：没有位置，不能对分组加约束。分组的成员是它集合里的对象，一直到最里层；用符号画出的用例本身算一个成员；ROUTE-OBJECT 既顺着它的角色找，也算入它自身的引脚。分组的树以及把非成员挡在分组区域之外，归求解器，是排在全部事实之后的准则。GROUP 收 `spacing_x` 和 `spacing_y`，即分组内部的网格单位间距 | 11.5、13.7 |
| SELECT-INSTANCE 收条件 `terminals`（元件的端子数），例如使三端与四端 MOS 管配不同的符号 | 10.1、附录 A |
| Spectre 内置器件 `tline` 有默认端子名 `p1`、`n1`、`p2`、`n2`，与 SPICE 的 T 相同；模型族表增加了 master 和 MESFET 族 | 6.12 |
| 没有任何语句或规则给符号的元件用默认框图符号：以原点为中心的方形框，每个端口一个引脚，定义没有读到的元件则每个节点一个引脚；没有元件会不画出，查看器也不再自己画替用图形 | 9.2.6、9.2.8 |
| 记录头字段 `language` 使一条记录只作用于那种网表语言段落里的对象；文件除了共用的头段记录外，还可以为每种语言各写一条头段记录。0.4 标准系列用它让 Spectre 文件里的 SPICE 段落适用 SPICE 的规则；0.4 系列不再像 0.3 系列那样隐式去掉另一种方言的包 | 2.8、2.2、6.12、16.3、附录 C |
| 文件起始的语言是工具的输入，默认取自文件名后缀，用户也可以按文件更改 | 2.2 |
| 规则默认只作用于本层：`recursive` 默认为 `false`，写了筛选的规则只有至少一个筛选带 `recursive=true` 时才传到下层，没有筛选的规则传到它用到的集合所及之处；于是规则里的每条筛选和每个集合各自在每一层里选。在 0.3 版里，每条筛选各有各的 `recursive`。包里的规则视作写在它的 USE-PACKAGE 那一层，根上的包视作写在文件顶层，因此标准包的规则写 `recursive=true`；只有触及下层的生成规则，才会就写到本层具体对象给出警告。触及下层、且其余槽位写了本层宿主对象的规则，在下层没有效果，不给警告 | 10.1、10.3、10.4、10.5、6.1、8.3、16.2、4.5、附录 B、原则 2.5 |
| SOLVER-CONFIG 把求解器的设置保存在文件里，或保存在包文件的头段记录里供使用该包的各层用：它是求解器定义其键的命名参数，其中本标准只点名了 `spacing_x`、`spacing_y` 和每个求解器都用的圆点定义 `junction`；后写的设置按键覆盖先写的；核心把设置按次序原样传给求解器；取不上的值只使它的键失效，此前的值保留；时间或工作量预算只由工具给出 | 14.10、14.8、附录 C |
| CURRENT 不是几何事实，只给求解器作提示；ORDER 比较点，把符号外框分开是求解器的准则；ORDER 是相邻成员间 `min=1` 的 DISTANCE 的简写；没有求解结果的渲染器按 ORIENT 列表的第一个朝向码画 | 15.2、14.3、11.2 |
| 澄清：空内容的 TEXT 什么也不画；求解器整条换掉生成的记录，不论是否懂其中的语句；叠画的端子按名字对应，端子名或模型不同的成员给警告 | 13.3、2.8、11.8 |
| 引脚是对象，种类是 `pin`，与端子分开。引脚由符号里的 PIN 产生，用局部名（如 `#X1::vdd_t`）指名；`terminal=` 可以省略。一个端子可以有几个引脚；需要引脚的地方，端子代表它的引脚（最后写的那个）。引脚不再按端子互相取代。引脚名不能与角色名、局部名、标准子对象名或文字的 key 相同；`::` 先于文字的 key 查找引脚名 | 9.2.4、9.2.7、5.1、6.4、6.5、13.3 |
| SET-SYMBOL 把符号的端子名按名字对上对象的端子（编号按位置）；`terminals=` 改变对应方式，按节点次序或配对表列出 | 11.3 |
| 用例没有端子：0.3 版的 `%g:p` 现在是命名的引脚，如 `%g::pin`。用例的引脚按名字绑定角色，画在填该角色的对象上；它们不是电气端子 | 12.1、6.4 |
| 给错种类的对象只按表转换：往绘图方向，端子转引脚转点、画出的对象转位置；往电路方向，引脚转端子、引脚或端子转网络 | 5.2.4 |
| SELECT-PIN 选引脚；`wired` 属于引脚和网络；SELECT-TERMINAL 选出每个端子（不管有没有引脚），经过端子的步骤都算上全部端子。SELECT-INSTANCE 和 SELECT-USAGE 收 `symbol` 和 `drawn`。按尺寸写的 RECTANGLE、CIRCLE 和 ELLIPSE 逐个接收筛选的结果；条件 `type` 收通配符 `*`，`type="*"` 选出有类型的元件 | 10.1、10.2、8.2、9.2.5、13.3 |
| 断言：ASSERT-INSTANCE、ASSERT-TERMINAL、ASSERT-NET 和 ASSERT-USAGE 检查成员是否满足对应种类筛选的条件，ASSERT-USAGE 还检查是否属于某定义的用例；ASSERT-IN 检查成员是否都在某个集合里。它们还检查属性是否写全（`has`）、是否相同（`same`）或互不相同（`different`）；ASSERT-TOPOLOGY 检查成员是否按串联、并联、星形或单回路连接，用例或集合当作黑盒；不成立的检查给一条违例（在错误、警告和提示之外的第四种报告），不使任何语句失效。同一网络上的 CURRENT 语句合起来检查电流是否全朝一个方向流动；在 0.3 版里什么也不检查 | 15.2、15.3、15.4、7.6、附录 C |
| TABLE 用嵌套的 `{…}` 把对象摆成一张表格，各行从上到下（或带 `transpose=true` 时各列从左到右），每层嵌套列表与外层垂直；它是一条事实，里面的对象组成一个分组 | 14.11 |

**把文件从 0.3 版迁到 0.4 版**。本标准不描述 0.3 版的文件；由读取 0.3 版的升级工具来迁移它们（16.1）。工具把头段记录里的版本升上去，把文件迁到 0.4 标准系列，并做下面这些改动；改不了的报告给作者：

- ORDER 或 DISTANCE 的方向写了 `"x"` 或 `"y"`，以及 DISTRIBUTE 写了 `axis=`：选用一个方向。
- Spectre `transformer` 的端子名 `p_plus`、`p_minus`、`s_plus`、`s_minus`：改写成 `p1`、`n1`、`p2`、`n2`。
- ORIENT-RELATION 两边都写了集合：为每一对写一条事实。
- 没写 `recursive` 的规则：工具在文件、它自己的包文件和内嵌包里为这些规则的筛选写上 `recursive=true`，使它们照旧触及下层。一部分筛选写了 `recursive=false`、另一些没写的规则会报出来：在 0.4 版里，只要有一个 `true` 就让整条规则触及下层。
- ROUTE：工具改写成 ROUTE-NET。
- 传了筛选结果的 WIRE 或 BUNDLE：WIRE 改写成 ROUTE-OBJECT，BUNDLE 把成员逐个写出。
- `%g:p` 以及别的用例端子：改写成符号里命名的引脚，如 `%g::pin`。0.3 系列的符号按编号绑定用例的角色，0.4 版不这样（11.3）。
- `$GROUND @ATTACH #M5:3` 以及别的第一个角色是端子或引脚的虚拟元件：现在它们以自己的位置站在那个网络上；要留在引脚上，改写短桩 `$GROUND_STUB @ATTACH #M5:3`，或者加约束把地的引脚放到 M5 的引脚上（12.3）。
- SELECT-TERMINAL 上的 `wired=`：改写成 SELECT-PIN，如 `# @SELECT-INSTANCE => @SELECT-PIN(wired=false)`。
- 按中心算的 `{%x}` 和原指集合中心的 `::position`：集合在 0.4 版没有位置，它的 `::position` 是各成员位置的集合；升级工具留下这类语句待人工核查。要把这些对象当作一个整体来放，就把它们做成一个用例的成员，让定义体把它们绑在用例自身的点上，再约束 `%u::position`（14.1）。
- 约束成员列表里原按一个点算的用例：对没有符号的用例，升级工具改写成 `%u::position`，否则它会代表它的成员（14.1）。
- 两个集合之间的 DISTANCE：现在它对每一对成立，因此 `max` 限定的不再是两个范围之间的间隙，而是每一对。
- 普通定义体里的字面量坐标：它们是相对用例自身的点的偏移；原本指层坐标的定义，把它的用例放在 `(0, 0)`，如 `$TITLE @ATTACH => @PLACE(0, 0)`。
- 标准包：写上 `@USE-PACKAGE(name="rnl-std-all", version="0.4")`，并按下面的"0.4 标准系列"改写 0.3 系列的用例：新名字与新角色、为 0.3 补位曾加过标签的每个端口网络写端口标签 `$IO_PORT @ATTACH`，并对已去掉的定义的每次使用各发一条报告。

**0.4 标准系列**。标准包不属于本标准（16.3）；下面是文件从 0.3 系列迁到 0.4 系列时要注意的变化。

- **使用它**：文件在头段记录里写 `@USE-PACKAGE(name="rnl-std-all", version="0.4")`，或者在会加上它的工具设置下读取（16.3）。
- **端口**：补位给每个端口网络加一个端口标签，电源网络和地网络也不例外，在这一层元件左边至少 6 个单位处排成一列，每个标签是 R0；文件可以把网络从 `$PORT_FILL_SET` 里去掉，为自己的标签写 `$IO_PORT @ATTACH`，或为写出来的这一列写 `$PORT_LIST @ATTACH`（12.4）。
- **补位**：它给没有导线的引脚补上网络标签，各画成一段短桩；除非文件或包用 ROUTE-NET 或 ROUTE-OBJECT 写了出来，否则没有任何网络画成导线；地网和电源网用 `@UNROUTE-NET(priority="high")` 排除在外，要把它们画成导线的文件写 `@ROUTE-NET(priority="high")` 或 WIRE。凡是有导线的引脚——无论是手写导线还是以语句或规则形式的 ROUTE-NET、ROUTE-OBJECT 画出来的——补位都不再补地或电源符号；要加的文件自己贴上去，如整网画线的写 `$GROUND @ATTACH &vss`，单个引脚写 `$GROUND_STUB @ATTACH #R1:2`。它的规则写 `recursive=true`，且筛选引脚（包括虚拟元件的引脚）。`$BIAS_NET_SET` 里的网络像地网和电源网那样获得偏置标记。
- **包**：唯一的包集合是 `rnl-std-all`，它引用该系列的每个包，且对每种语言各有一条头段记录（2.8、16.3）；0.3 系列的集合 `rnl-std`、`rnl-std-core`、`rnl-std-full` 已去掉，`rnl-std-structures` 改名 `rnl-std-semantics`。`rnl-std-no-labels` 用 `drawn=true` 筛选，并用样式 `textvisible=false` 而不是空文字来隐藏标签，因此文件可以用 `textvisible=true` 重新显示某个标签。新增可选包 `rnl-std-45deg`。
- **改名或改义的**：`$DIFFERENTIAL_PAIR` 分成 `$DIFFERENTIAL_PAIR_N` 和 `$DIFFERENTIAL_PAIR_P`，角色是 `left`、`right`、`tail`；`$MIRRORED` 改名为 `$MIRRORED_LAYOUT`，角色是 `left`、`right` 和一个 `axis`，新增 `$MIRRORED_VERTICAL_LAYOUT`，角色是 `top`、`bottom`、`axis`，因为只管摆位置的定义以 `_LAYOUT` 结尾；带 `_N` 和 `_P` 的结构会断言其晶体管的极性；`$FLOW` 改名为 `$SIGNAL_FLOW`，它不摆位置、也不收方向，并可在路径上点出来源和负载，新增 `$POWER_FLOW` 和 `$BIAS_CIRCUIT`；`$CURRENT_MIRROR` 分成 `$CURRENT_MIRROR_N` 和 `$CURRENT_MIRROR_P`；`$NO_CONNECT` 的角色收端子或引脚。本系列改名、合并、拆分或去掉的定义的完整清单在标准包说明里；RNL 核心工具 0.5.x 最后一个发布版（这是工具的版本号，不是本语言的版本号）中的命令 `rnl upgrade` 按此改写文件。结构中每条位置事实都写出方向，另一方向的画法做成单独的变体，如 `$BRANCH_HORIZONTAL`。
- **去掉的**：`$CHAIN`、`$SUPPLY_HIGH` 和 `$SUPPLY_LOW`。
