## 6 名字与作用域

### 6.1 层级

- **层级按文字的包含关系。** 一个层的 RNL 作用于本层，以及它在文字上包含的各层；谁实例化谁不起作用。
  - 文件包含它定义的子电路和它引入的文件。
  - 写在子电路里的 `.include`，和嵌套在子电路里的 `.subckt` 定义（SPICE3、ngspice 的局部定义），挂在那个子电路下面。
- 从上往下，到一个子电路的层级链是：根上的包（头段记录里 USE-PACKAGE 的包，标准包排在最前，16.3）→ 主文件的文件层 → ……（逐级引入的文件）→ 定义这个子电路的文件 → 子电路自己。例如：

  ```text
  packages at the root (such as the standard package)
  └─ file level of tb.sp (the top level)
     ├─ load                    a subcircuit defined in tb.sp
     ├─ file level of ota.sp    a file included by tb.sp
     │  ├─ ota                  ota instantiates cell
     │  └─ cell
     └─ file level of bias.sp
        └─ bias                 also instantiates cell, but neither the RNL of bias.sp nor that of bias reaches cell
  ```

- **子电路的 RNL 只管它自己。** 取舍时它的语句排在各文件层的内容之后，因而优先于它们（8.5）；但不传给它实例化的子电路，嵌套定义在它里面的除外。amp 实例化了 cell，amp 的定义和规则到不了 cell。
- **被引入的文件影响不到引入它的层。** 它的文件层的定义、规则、USE-PACKAGE 只作用于它的子电路和它再引入的文件。从网表看，它写在子电路之外的器件属于引入它的那一层，但它的 RNL 改不到这些器件。所以一个文件不会被它引入的文件改动。
- **被引入的文件的文件层没有自己的电路。** 只有主文件的文件层是电路。被引入的文件在文件层写的宿主引用（`#M1`、`&vss`）失效（6.3），在那里起作用的只有定义、规则、USE-PACKAGE 和 `scope`。单独打开的文件就是主文件。
- **被引入的文件继承引入它的层。** 主文件的风格体系（它的规则和 USE-PACKAGE 的包）一直传到库文件的子电路里。所以同一个库文件在不同的主文件下，或单独打开时，可能画得不同，而它的求解结果只存一份（第 17 章）。要让库里用到的符号不受上层外观规则的影响，在库文件或子电路里用 USE-PACKAGE 再用一次标准包（16.2）。只想钉住标准包的版本、仍让上层的风格体系盖过它，就把 USE-PACKAGE 写在库文件的头段记录里（16.3）。主文件的规则只在筛选写了 `recursive=true` 时才传到下层（10.1）；需要传到库文件的风格体系规则写明它。
- **Verilog-A 文件。** 网表用 `ahdl_include` 或 `.hdl` 引入的 Verilog-A 文件与被引入的文件一样，位于引入它的位置；其中的每个模块是该文件层下面的一层，没有电路也没有原理图，只为该模块给出框图符号（2.9）。
- **一个子电路一张图。** 查看器不展开子电路：子电路的元件总是用它的符号画，子电路内部单独画、单独求解。每个子电路只有一条上层链，所以一份文档里每个子电路恰好一张图。
- **包。** `@USE-PACKAGE` 写在哪层，包的 `$` 定义就在那层及以下生效，规则也算写在那一层，并在写了 `recursive=true` 时传到下层（16.2、10.4）。头段记录里 USE-PACKAGE 的包放在根上，写了标准包或按工具设置附加了标准包时，标准包在其中（16.3）。引入文件把文件放在本层下面，文件继承本层；USE-PACKAGE 把包放在本层上面，本层继承包。
- **规则默认只作用于本层。** 写在一层里的规则只在该层求值。如果通过它里面写的筛选上的 `recursive=true`，或（没有直接写筛选时）通过它用到的集合到达下层（10.1），规则也会在下面每一层各求一次值，每次只看那一层的对象（10.4）。这正符合原则 2.5 对规则的要求：规则可以把效果限制在当前层，也可以让下层继承，默认只作用于所在层；`$` 定义则默认继承（6.8）。

### 6.2 前缀

| 前缀 | 指什么 | 在哪里解析 |
|---|---|---|
| `#` | 宿主的元件；单独的 `#` 是本层 | 本层的宿主 |
| `&` | 宿主的网络；单独的 `&` 是空节点，即没有任何网络（6.3） | 本层的宿主 |
| `%` | 在本层起的名字：场景对象的，已有对象的（如 `%tail = #M5`），或只在本层用的定义的 | 本层 |
| `$` | 定义，或集合（6.6） | 绑定它的层及其下层 |
| `?` | 定义的角色或参数；单独的 `?` 在符号体里是用这个符号画出的对象（13.3），在普通定义的体里是正在展开的用例（9.4） | 普通定义或符号的定义体 |

`$X` 与 `%X` 是两个不同的名字。

### 6.3 宿主引用

- `#M1`、`&vss` 只在本层的宿主里解析，不跨层（原则 2.5）。不同子电路里的同名元件互不相关。
- 找不到的宿主引用失效（原则 2.4）。被引入的文件的文件层没有自己的电路，所以那里的宿主引用都失效（6.1）。
- 名字后面可以紧跟下标，表示一个或一组宿主名字，如 `&D<3>`、`#XI0<3:0>`（6.11）。
- 某一层有哪些网络，由宿主适配器按宿主的语义决定：
  - 局部网络：这一层的网表行用到的结点，含端口。
  - 全局网络：`0` 在各种 SPICE 方言里都是全局地。仿真器自己认的地的别名（如 ngspice 的 `gnd`，HSPICE 的 `GND`、`GND!`、`!GND`、`GROUND`）由这种方言的适配器并到 `0`；并入后 `&gnd` 与 `&0` 是同一个句柄。`.GLOBAL vdd`（Spectre 写 `global vdd`）声明的名字，在任何子电路里都是同一个结点。名字以 `!` 结尾（如 `vdd!`）是 Virtuoso 原理图的习惯，起作用的是声明。
  - 全局网络在用到它的每一层各有一个句柄，即这一层里的那一份；网表行没有用到它的层没有这一份。所以 `&0` 指写它的那一层的那一份：每张图各画各的，事实属于那一层，下层的描述改不到上层。
  - 要指每一层里的那个全局网络，在上层按名字筛选，加条件 `global=true`（10.1）。
- **空节点。** 单独写的 `&`（后面不带名字）表示没有网络：传给它的东西不连到电路的任何电气结点上。它写在需要网络但又没有网络的地方，例如没有网表行时画框图用的虚拟元件的引脚：`$INTEGRATOR @ATTACH &(in) &y(out)`、`& @WIRE {%sub1::y %int1::a}`。
  - 它不是对象：没有句柄，不能绑定名字，不能作为集合成员，也不会被筛选到。两处写的 `&` 没有任何共同之处；查看器高亮空节点上的某个引脚或某条导线时，只高亮那一个。
  - 有两处原样收下它：种类为 `"net"` 的角色（9.4）和 WIRE 的网络槽位（13.1）。绑定到由它填上的角色的引脚不在任何网络上，其 `::net` 是空节点（12.1），其 `${net}` 和 `${p}` 为空文字（13.6）。
  - 其余需要网络的地方，都把它当作空网络集合：ROUTE-NET 不连任何东西，ASSERT-NET 自然成立，以它为作用域的筛选什么都不选，ADD-TO 什么都不加（5.2.1）。直接写在这些地方会给警告，与直接写出空集合一样；经角色传进来的（如在定义体里）不给警告。这样，用到角色网络的定义体不用单独为它写特殊情况。
  - 它不是宿主的网络，所以 `&` 后面跟着宿主里没有的名字，仍照常失效。

### 6.4 端子

- `object:terminal` 是端子：`#M1:1`、`#M1:d`、`#XU1:inp`，以及叠画的端子如 `%x:in`（11.8）。`#:inp` 是本层的端口 inp。只有宿主元件、叠画和本层的端口有端子；用例没有端子（12.1）。
- 数字是宿主的端子序号，从 1 起。凡是写端子的地方——包括 `:` 引用、PIN 的 `terminal=`、SET-SYMBOL 的 `terminals=` 以及筛选的 `terminal` 条件——只由数字组成的端子都被当作序号，加了引号也一样（4.1）。所以 `.subckt amp 3 1 2` 中全由数字组成的端口名只能按位置访问，`#X1:1` 指的是名为 3 的那个端口；DEVICE 里写全由数字组成的名字是错误（6.12）。
- 名字是宿主的端子名：头段记录里 `@DEVICE` 给的名字（6.12），或子电路的端口名。不能不加引号写的名字（3.6）要加引号，如 `#XU1:"in+"`。端子名、端口名后面可以紧跟下标，如 `#X1:D<7:0>`、`#:D<7:0>`（6.11）。
- 大小写：子电路的端口名和 DEVICE 给的端子名都按宿主的规则：SPICE 不分大小写，`#M1:D` 也行；Spectre 区分。
- 引脚的 `label=` 只用于显示，不能用来引用端子：端子属于网表，引用端子不取决于用的是哪个符号。
- **端子与引脚**：端子属于网表；引脚属于绘出对象的符号（9.2.4）。端子画在绑定它的引脚处；需要引脚或点的地方，端子可以代表它的引脚（5.2.4）。引脚通过它的端子来写（如 `#M1:d`），或者在它的符号里有名字时，作为子对象按名字来写（如 `#X1::vdd_t`，6.5）；数字绝不是引脚名。
- 找不到的端子失效。端子在符号里有没有引脚，在定了符号之后检查（7.1）。
- 除了子电路的端口名，端子名由 DEVICE 给出；SPICE 系的标准名字见 6.12。
- 网表里没有定义的子电路（如 `XM1 … sky130_fd_pr__nfet_01v8` 里的 PDK 器件），只有用户在头段记录里用 DEVICE 给出端子名（6.12），或用了写有 DEVICE 语句的包（16.2）时，才有端子名；否则只能写序号。

### 6.5 子对象

- `object::name` 是子对象。它总是对象，不是数值。它的句柄是父对象和名字，因此在符号定下之前凡是数成员的地方，两个不同的名字算作两个成员（5.2.4）：`{#R1::p #R1::q} @UNION` 有两个成员，即使后来两个名字指的其实是同一个引脚也如此。
- 子对象有：
  - 文字的 key：写了 `key=` 的 TEXT 在它附着的对象上产生的子对象，如 `#M1::wl`。符号里写了 key 的文字，是用这个符号画出的每个对象的子对象（13.3）。`::name`、`::value` 不是标准子对象，只是常用的 key（13.3）。
  - `::position`：对象的原点。`#M1::position @PLACE(…)` 等于 `#M1 @PLACE(…)`。对用例，它是用例自身的点（14.1），有符号时就是符号的原点（12.1）。对集合，它是各成员 `::position` 的集合，嵌套的集合向里展开：`{%dp1 %dp2}::position` 就是 `{%dp1::position %dp2::position}`，即两个自身的点，而约束里的 `{%dp1 %dp2}` 代表那六个晶体管（14.1）。对 TEXT，它是文字自己的位置（13.3）；对中心写法的 RECTANGLE、CIRCLE、ELLIPSE，它是中心（13.4）。
  - 端子的 `::net`：它所在的网络，如 `#M5:1::net` 就是 `&tail`。叠画的端子见 11.8：成员接在不同网络上时，是这些网络的集合。引脚的 `::net`：它绑定的端子或它绑定的角色所填对象所在的网络（12.1）；对总线引脚，是这些网络的集合；什么都不绑定的引脚没有该子对象。
  - 对象符号里起了名字的引脚：`#X1::vdd_t` 是 X1 的符号里名为 vdd_t 的引脚，`%g0::pin` 是用例 `%g0` 的符号里名为 pin 的引脚（9.2.4）。
  - 用例的角色名：填进这个角色的对象，如 `%dp1::left` 是 M1，`%g0::p` 是网络 vss。集合角色取到的是那个集合。它就是那个对象本身，而不是第二个对象：`{%dp1::left #M1} @UNION` 只有一个成员，对 `%dp1::left` 写的 PLACE 带的是 M1 的键。
  - 用例体里起了名的局部对象，如 `%c1::mid`（9.4）。
- 标准子对象名保留：普通定义的角色名、参数名、局部名，以及文字的 key，都不能与它们相同（按原样比较，3.6）。局部名不能与角色名相同，文字的 key 也不能与它所附着的用例的角色名、局部名相同。局部名可以与参数名相同：参数是值，`::` 不取值。定义的参数也不能叫 `priority`（14.8）。
- **`::` 后面的名字按这个次序找**：用例自己的角色名和局部名；它们的 `definition=` 代称；标准子对象名和它们的代称；对象符号的引脚名；文字的 key（代称见 16.5）。与用例的角色名或局部名同名、或与标准子对象名同名的引脚名，在把符号赋给对象时是错误；与引脚名同名的文字 key 也是错误。
  - key 排在最后，所以不能与排在它前面的名字拼写相同：本文件声明的标准子对象名或其代称（如 `alias-zh` 的 `"位置"`）、用例的角色名和局部名，或这些名字的 `definition=` 代称。这样的 key 是错误，与上面的撞名一样（13.3）。
- `::` 只取对象自己的部分；在场景里按条件找对象，一律用筛选关键字。所以"某个定义的全部用例"写成筛选（10.1），不写成定义的子对象。
- 端子用 `:`、子对象用 `::`，免得以后的版本新增的子对象名与网表的端口名冲突。
- **子对象名**：标准子对象名有两个，`position` 和 `net`，都保留。其余子对象名都是动态的：文字的 key、用例的角色名、定义体里的局部名，以及引脚名。以后的版本新增的标准子对象名按版本区分（16.1）：旧版本的文件里，同名的 key 照旧有效。

### 6.6 命名

- `%name = statement`、`$name = statement` 给语句的结果起名；管道里 `=> %name`、`=> $name` 给它们左边那一段的结果起名（5.5）。名字只是引用对象的另一种写法，不产生对象。
- `$name` 绑定定义或集合，含筛选的结果。`$` 集合在某层求值时只含这一层的成员（10.3）。其他场景对象属于某一层，不能有 `$` 名字。
- `%name` 可以绑定本层的任何对象：本条语句创建的对象、已有的对象（`%tail = #M5`）、集合（`%pair_set = {#M1 #M2}`），或只在本层用的定义。
- **同一层里一个名字只绑定一次。** 再绑定同一个对象可以，如 `%x = #M1` 写两次；绑定别的对象是错误，名字保留第一个有效的绑定。具体绑定什么按 5.5。沿用输入句柄的段（如 PLACE、ORIENT）就绑定那个句柄，即使该段自身失效也如此，因此这个绑定是否有效正好取决于输入句柄是否有效：输入本身是失效对象时（如失败的 BUNDLE 之后），绑定也就无效（5.5）。创建新对象的段在读入与创建阶段（8.2 第 1–3 步）没有失效时，绑定就有效；若它后来在定好符号后的检查（8.2）才失效，它仍占着这个名字，后面的绑定不能接手，名字从那时起指向失效对象。只有全部绑定都失效时，名字才绑定到失效对象（7.2）。无效的绑定不占名字，所以后面再绑定别的对象不算重绑两遍的错误：前面 5.5 失败的叠画之后，`%s = #XI1` 就把 `%s` 绑到 XI1。创建对象的语句、定义、集合、筛选的结果都一样。
- 覆盖针对事实，不针对名字：要改 RNL 创建的对象，写修改它的语句，如 `%g0 @PLACE(40, 38)`（5.8）。

### 6.7 名字的范围

- `@RNL` 提交的名字发布到本层：本层的所有记录共享，名字可以在绑定它的语句之前使用（原则 2.9）。
- 嵌套集合里绑定的名字只在该集合内有效。
- 定义体里绑定的名字是体内局部的（6.9）。

### 6.8 继承与遮蔽

- `$` 定义沿层级（6.1）向下继承，绝不向上：进本文件的子电路，也进被引入的文件。一个层看不到它引入的文件里的 `$` 定义；要给上层提供定义，做成包，用 USE-PACKAGE 使用（16.2）。子电路符号是唯一向上的例外（9.2.6）。
- 下层定义了与继承来的同名的 `$X`，就在这一层及其下层遮蔽继承来的定义，并给提示；上层看到的仍是自己的。
- 一层里 USE-PACKAGE 的包，它的 `$` 定义算作这一层上面的一层（16.2）。它们遮蔽上面各层或根上的包的定义时，与任何遮蔽一样给提示。头段记录里使用的包定义了标准包里的名字，或排在它前面、放在根上的包里的名字时，也给提示（16.3）。
- `%` 名字只在本层有效，不继承：不进本文件的子电路，也不跨引入边界。包里的 `%` 定义是包内私有的辅助定义。

### 6.9 定义体里的名字

- 定义体里的名字在写定义的地方解析，套用处不重新解析；唯一的例外是普通定义体里单独的 `#`（见下）。
- 所以遮蔽一个定义只改变这个名字指什么：别的定义内部已经用到的定义不变。例如在下层遮蔽 `$DIFFERENTIAL_PAIR_N`，不会改变上层写的定义体内用到的差分对。
- 体内的 `%name` 先在体内的局部名里找，再在本层的定义里找。本层的场景对象（点、导线等）不能从体内引用，这样的引用是错误。本层用 `%` 命名的集合或筛选结果也属于场景对象，不论求值时的成员是什么：要与定义体共用一个集合或筛选，就用 `$` 给它起名，定义体可以引用该名字，并在每个用例所在的层里对它求值（6.6、10.3）。
- **体内的写法**：角色和参数写 `?name`。局部名用 `%name =`（管道里用 `=> %name`）绑定，用 `%name` 引用。从外面经用例引用局部名（9.4）。
- 定义体看不到正在定义的名字：`$NMOS = @DEFINE-SYMBOL {$NMOS; …}` 里，体内的 `$NMOS` 是外面（上层或包里）这个名字的定义。下层就是这样遮蔽并扩展上层定义的；外面没有这样的定义时是错误。
- DEFINE-SYMBOL、DEFINE 体里的宿主引用是错误：`#M1`、`&vss`、`#:inp`、`#M1:d` 都不能写在那里，符号体里也不能写单独的 `#`。普通定义体里单独的 `#` 指用例所在的层，这要在套用处才知道（9.4）；在定义体里用作筛选的作用域。不能从定义体里指定框图符号：定义体里写 `# @SET-SYMBOL` 是错误，因为层的框图符号要在该层用例之前排进符号队列，而用例还可以是在这之后生成的（8.3、9.2.6）。体里的名字在写定义的地方解析，普通定义却会在别的层、别的文件里套用，在那里宿主引用仍会指到定义所在的那一层，含义不唯一。普通定义要用宿主对象，经角色传进来。
- **普通定义的体什么时候检查**：
  - 按定义查一次：不依赖实参的都在这时查，包括关键字、签名（对象个数、参数名和类型）、`$` 和 `%` 名字（在写定义的地方解析）、宿主引用、局部名的撞名（9.4），以及声明了种类的角色用得对不对：角色 t 声明为 `"instance"` 时，体里写 `?t::net` 是错误。签名在读入时查（7.1）；名字要整层读完才能解析，所以要用到名字的检查在本层生效时做。两者每个定义都只做一次，与套用几次无关。
  - 按套用查：依赖实参的，如没声明种类的角色收到的对象、符号里有没有那个引脚，每次套用时查，报在套用处，并指出普通定义里的原句。
  - 错误的范围：体里查出错的语句（含撞名的局部名）在定义处报一次，每次展开都不含它，体的其余部分照常（体是容错的，9.1）。角色表、参数表写错（重名、与标准子对象名撞名、不认识的种类名），整个普通定义失效，用到它的套用也都随之失效。
  - 从没被套用的普通定义也查。这些检查与套用无关，所以能查出包里没用到的定义的错误。

### 6.10 空位

- `?name` 只出现在普通定义的体里，名字应在角色表或参数表里；否则读入时就是错误。
- 写在对象的位置是角色，如 `?t`、`?t::net`；写在字面量的位置是参数，如 `min=?gap`、`[?w, 2]`、`(?x, 0)`（9.4）。角色写在字面量的位置，或参数写在对象的位置，读入时就是错误。角色名和参数名在同一张表里，不能重名。
- 角色的空位可以带路径，如 `?t::net`，集合角色的空位可以带成员位置，如 `?ref{1}`（5.2.3）；参数的空位两者都不带。

### 6.11 下标

| 写法 | 表示 |
|---|---|
| `&D<3>` | 与 `&"D<3>"` 相同 |
| `&D<7:0>` | 一组：`D<7>`、`D<6>`、…、`D<0>` |
| `&D<1,2:3>` | `D<1>`、`D<2>`、`D<3>` |
| `&D<0:6:2, 9>` | `D<0>`、`D<2>`、`D<4>`、`D<6>`、`D<9>` |
| `&D[3:0]` | `D[3]`、`D[2]`、`D[1]`、`D[0]` |
| `#XI0<3:0>` | 四个元件 |
| `#X1:D<7:0>` | X1 的八个端子 |
| `#:D<7:0>` | 本层的八个端口 |
| `&"D"<1:0>` | `D<1>`、`D<0>` |
| `&"D<7:0>"` | 名字就叫 `D<7:0>` 的结点：引号里的不解析 |

- 网表里没有总线：Virtuoso 等工具出网表时把总线拆成单个的位，如 Spectre 网表里的 `D\<3\>`；子电路的总线端口、叠合元件也拆开。下标是写一个或一组这类名字的简写。它只是拼名字，不靠宿主认总线，所以含义唯一。
- **写法**：宿主名字（加不加引号都行）后面紧跟 `<…>` 或 `[…]`，里面是用 `,` 分开的若干项。每项是 `i`、`a:b` 或 `a:b:s`，几种可以混写。i、a、b、s 都是不带符号的十进制整数，s 至少为 1。名字与括号之间没有空白；括号里可以有空白和注释（3.5）。
- **展开**：各项按写的次序展开、拼接，重复的照留。`a:b` 从 a 到 b，`a:b:s` 每次走 s，不越过 b：`<7:0>` 是 7、6、…、0，`<0:7:2>` 是 0、2、4、6。步长写在最后，与 Virtuoso、Xschem 相同，与 MATLAB 的 `a:s:b` 不同。生成的名字是括号前的名字、左括号、不带前导零的十进制数和右括号，括号照写的那一种：`&D<07>` 是 `D<7>`，`&D[3]` 是 `D[3]`。
- **一个还是一组**：只有一项且是单个数时，是一个引用：`&D<3>` 就是 `&"D<3>"`。否则是一组，即对一个集合的引用，如 `&D<3:3>`、`&D<3,5>`。一组放进集合时打散一层（5.2）；作语句唯一的对象时先拆一层（5.2.1），所以 `#XI0<3:0> @ALIGN("y")` 对齐四个元件；放在要单个对象的槽位时逐个成员做；放在 WIRE 的网络槽位时整个收下，是一根总线（13.1）。
- **用在哪里**：`#`、`&` 之后的宿主名字，以及 `#` 引用里的端子名、端口名。RNL 名字（`%`、`$`、`?` 之后的）、角色名和子对象名不收下标，后面紧跟 `<`、`[` 是错误。取集合里的成员改用花括号写成员位置（5.2.3）。
- **名字后面不能直接写点**：名字后紧跟的 `<`、`[` 一律开始一个下标，后面不合写法就是语法错误，不会读成点。要在名字后面写点，就隔开，如 `&D (1, 2)`。
- **一处展开**：一个名字后面至多一个下标，所以 `A<1>[2]` 这样的名字加引号写，`&"A<1>[2]"`。一个引用里至多一处下标展开成一组：`#XI0<3:0>:a`、`#X1:D<7:0>` 可以，`#XI0<1:0>:D<1:0>` 是错误；两处都是单个数的可以，如 `#XI0<3>:D<1>`。展开成一组的引用后面接 `::` 时，对每个成员各取子对象，如 `#XI0<3:0>::name`。
- **引号里的不解析**：`&"D<7:0>"` 指名字就叫 `D<7:0>` 的结点；`&"D"<7:0>` 才展开。网表里的名字含有不表示总线位的 `<`、`[` 时，加引号照原样引用。
- **比的是适配器读出的名字**（3.6）：Spectre 网表里的 `D\<7\>`（反斜杠是 Spectre 的转义）由适配器读成 `D<7>`，所以 `&D<7>` 能引用它。
- 每个成员各自解析。找不到的成员是失效对象，按收它的槽位的规定严格或容错处理（7.3）。
- 参数里的字符串不展开，如 PIN 的 `terminal=`（9.2.4）、筛选的条件 `name=`。
- 不收：Virtuoso 的重复 `<*2>A`、`A<0:2*2>` 和并列 `A,B`（集合已经能写）；KiCad、Xschem 的 `D[0..7]`，它的成员是不带括号的 D0 … D7。
- 叠合元件（如 Virtuoso 的 `I0<3:0>`：几个宿主元件画成一个）写成叠画：`#XI0<3:0> @BUNDLE`（11.8）。

### 6.12 端子名：DEVICE

```spice
* sky130 transistors, defined in the PDK and not in this netlist
* @RNL(type="header") {
*   @VERSION("0.4");
*   @DEVICE(name="X*", model="sky130_fd_pr__nfet_*", terminals=["d", "g", "s", "b"], type="nmos");
*   @DEVICE(name="X*", model="sky130_fd_pr__pfet_*", terminals=["d", "g", "s", "b"]);
*   @DEVICE(model="sky130_fd_pr__pfet_*", type="pmos")    /* adds the type to the names given above */
* }
XM1 out in 0 0 sky130_fd_pr__nfet_01v8 w=1 l=0.15
XM2 out in vdd vdd sky130_fd_pr__pfet_01v8 w=2 l=0.15
* @RNL { #XM1:d @CURRENT("in") /* XM1 is a sky130 NMOS; its terminal 1 is named d, and its type is nmos */}
.end
```

- **端子名和类型由 RNL 给出。** `@DEVICE` 描述一类器件：`terminals` 按网表行上结点的顺序列出端子名，`type` 给出它们的类型（见下）。它只给宿主的端子序号起名，不改端子的顺序，也不改子电路的接口；它是原则 2.2 允许的显示别名。同一 `terminals` 列表里的名字按宿主的大小写规则必须各不相同，且不能全由数字组成（6.4）；例如在 SPICE 里 `"d"` 和 `"D"` 判作相同。包文件的头段记录可能被两种方言的文件使用，因此里面的名字须不区分大小写仍各不相同。列表里有两个相同的名字，或者有全由数字组成的名字时，是错误，那条 DEVICE 语句失效，各元件保留先前 DEVICE 语句和适配器给出的名字。
- **只写在头段记录里**（2.8）：DEVICE 写在别处是错误。包文件的头段记录也算（16.2）。内联包里不能写 DEVICE，要写在文件的头段记录里。
- **匹配**：`name` 比元件名，`model` 比元件行上写的模型名或子电路名（Spectre 里是元件的 master，内置器件如 `resistor`）；两项都可以用通配符 `*`（任意多个字符），按宿主的大小写规则比较。两项可以省去其中一项，但不能两项都省；写出的项都对上时，DEVICE 与元件匹配。DEVICE 给出 `terminals`、`type` 或两者兼写；既没有 `name` 也没有 `model`，或者既没有 `terminals` 也没有 `type` 的，是错误，该语句失效。筛选中比较名字的条件也用 `*`，规则相同（10.1）。
- **类型**：`type` 是字符串，如 `"nmos"`；下面表格里的词是标准写法。对于宿主没有给出类型的元件，如 X 元件（包括网表未定义的 PDK 器件），筛选条件 `type`（10.1）、`${type}`（13.6）和断言（15.3）都读取它。模型卡元件保留其模型的类型（见下）：DEVICE 给出不同类型时给警告且不改变原类型，就像子电路的端口名一样。
- **几条都匹配时后写的生效，逐项各自算**：端子名和类型分别取最后写出了该项且匹配的 DEVICE，因此一条 DEVICE 可以给端子名、另一条后面的给类型，后面没写出某一项的 DEVICE 不改这一项。适配器的默认在最前，然后是这一层用到的包里的 DEVICE 语句（按包的排序位置，16.2），再是外层文件的头段记录里的，再是被引入的文件的；同一条头段记录里按写的先后；一个文件有多条头段记录时，不带 `language` 的在先，带 `language` 的按写的先后，各自只作用于所在语言段落的元件（2.8）。所以文件自己写的盖过它的包，包盖过适配器；具体的语句建议写在通用的后面。所有包的 DEVICE 语句都排在各文件的之前，不论它们的 USE-PACKAGE 写在哪里：头段记录总在文件最前面，要是按 USE-PACKAGE 的位置排包，包反倒会盖过文件自己写的。写了 `model` 的 DEVICE 不算更具体，不另设特异性规则。
- **范围**：文件的头段记录里的 DEVICE，作用于这个文件和它引入的文件；被引入的文件只能改它自己和它再引入的文件（6.1）。包文件的头段记录里的 DEVICE，作用于用到这个包的各层（16.2）。例如一个 sky130 的包可以写 DEVICE 语句、符号和选符号的规则，用户写一条 `@USE-PACKAGE(name="sky130-rnl")` 就既有端子名、类型又有符号。
- **适配器的默认**：每种方言的标准元件定义，算作写在最外层。不用写进文件，工具也可以把它们写出来。同一种方言的工具应给出相同的定义。它们是元件那一行所在文件的版本的默认（16.1），与那个文件头段记录里的 DEVICE 一样。SPICE 系：

  ```rnl header
  @DEVICE(name="M*", terminals=["d", "g", "s", "b"]);
  @DEVICE(name="Q*", terminals=["c", "b", "e", "s"]);
  @DEVICE(name="J*", terminals=["d", "g", "s"]);
  @DEVICE(name="Z*", terminals=["d", "g", "s"]);
  @DEVICE(name="D*", terminals=["a", "k"]);
  @DEVICE(name="R*", terminals=["p", "n"]);             /* and one each like it for C, L, V, I, B, F, H, W */
  @DEVICE(name="E*", terminals=["p", "n", "cp", "cn"]);  /* and one each like it for G, S */
  @DEVICE(name="T*", terminals=["p1", "n1", "p2", "n2"]); /* and one like it for O */
  @DEVICE(name="U*", terminals=["a", "b", "ref"])
  ```

  Spectre 的元件名不以元件字母开头，所以默认的定义按 `model`，即元件的 master 来认。Spectre 的内置器件：

  ```rnl header
  @DEVICE(name="*", model="resistor", terminals=["p", "n"]);      /* and one each like it for capacitor, inductor, vsource, isource, ccvs, cccs, bsource, port */
  @DEVICE(name="*", model="diode", terminals=["a", "k"]);
  @DEVICE(name="*", model="vcvs", terminals=["p", "n", "cp", "cn"]); /* and one each like it for vccs, relay */
  @DEVICE(name="*", model="tline", terminals=["p1", "n1", "p2", "n2"]);       /* as T in SPICE */
  @DEVICE(name="*", model="transformer", terminals=["p1", "n1", "p2", "n2"])   /* as T in SPICE */
  ```

  - `switch` 每个结点一个端子，按 Spectre 给位置的编号命名：`t0` 是公共端，`t1` 到 `tn` 是各个掷点。
  - 模型卡的元件，master 是一条 `model` 语句的名字，端子名按那个模型的 master 所属的器件族取。它的类型（用于筛选条件 `type`，10.1）用 SPICE 的写法：

  | 器件族 | 模型的 master | 端子 | 类型 |
  |---|---|---|---|
  | MOS | `bsim1`、`bsim2`、`bsim3`、`bsim3v3`、`bsim4`、`bsim6`、`bsimbulk`、`bsimsoi`、`bsimcmg`、`bsimimg`、`b3soipd`、`mos0`、`mos1`、`mos2`、`mos3`、`mos9`、`mos11`、`mos705`、`mos902`、`mos903`、`psp102`、`psp103`、`psp104`、`pspnqs102`、`pspnqs103`、`ekv`、`hisim`、`hisim2`、`hisimhv`、`hvmos`、`bta_soi`、`ucsd_hvmos`、`hisim_hv`、`utsoi`、`letisoi`、`bsimcmg_va` | `d g s b` | `nmos`；模型的 `type` 是 `p` 或 `pmos` 时为 `pmos` |
  | 双极晶体管 | `bjt`、`bjt500`、`bjt503`、`bjt504`、`bjt504t`、`bjt3500`、`bjt301`、`vbic`、`hicum`、`hicum0`、`hicum2`、`mextram` | `c b e s` | `npn`；模型的 `type` 是 `pnp` 时为 `pnp` |
  | 二极管 | `diode`、`juncap`、`juncap200`、`dio500`、`junb` | `a k` | `d` |
  | JFET | `jfet` | `d g s` | `njf`；模型的 `type` 是 `p` 或 `pjf` 时为 `pjf` |
  | MESFET | `gaas`、`angelov`、`tom2`、`tom3` | `d g s` | `nmf`；模型的 `type` 是 `p` 或 `pmf` 时为 `pmf` |
  | 电阻 | `resistor`、`rdiff`、`r3` | `p n` | `r` |
  | 电容 | `capacitor` | `p n` | `c` |
  | 电感 | `inductor` | `p n` | `l` |
  | 继电器 | `relay` | `p n cp cn` | `sw` |
- **网表里有定义的子电路**（含引入的库文件里的）：端口名照定义，这是宿主的事实（原则 2.2）。DEVICE 不改它们；与这样的元件匹配而名字不同的 DEVICE 给警告。DEVICE 只给没有端子名的器件起名：内置器件，以及网表里没有定义的子电路（PDK 器件），后者由用户或 LLM 写 DEVICE。不带 `terminals` 的 DEVICE 仍能给网表里有定义的子电路指定类型。
- **名字的个数**：元件的结点比 `terminals` 的名字多时，多出的端子只有序号；比它少时，引用多出的名字失效。
- **大小写**：DEVICE 给的端子名按宿主的规则比（6.4）。
- 序号总能用，不纯由数字组成的子电路端口名和 `#:port` 也一样。
