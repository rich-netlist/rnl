## 12 虚拟元件

### 12.1 概念

- 虚拟元件是只存在于 RNL 里的元件，如地、电源、端口标签、无连接标记。它在电气上不存在：只用于画出，不产生也不改变电气事实。
- 虚拟元件就是有符号的用例，没有单独的关键字或对象种类。`$GROUND @ATTACH &vss` 产生一个用例；标准包的一条规则给 `$GROUND` 的用例指派地符号，它就画出来。
- 规则：
  1. **引脚与角色。** 用例没有端子。它符号里的引脚按名字访问，如 `%g0::pin`（6.5），而 `%g0::p` 仍然是填进角色 p 的成员，即网络 vss。引脚的 `terminal=` 写了定义的角色名时，按名字或按 `terminals=` 对应（11.3）后绑定到那个角色：这个引脚画在填这个角色的对象上，因此该网络上的导线可以终结在那里，ROUTE-NET 也会把它连进去（13.7），引脚的 `::net` 就是那个网络。绑定了角色的引脚画在填该角色之物所在的网络上：一个网络，或者一个端子或引脚所在的网络（5.2.4）。所以 `$GROUND @ATTACH #M5:3` 在 M5:3 所在的网络上放一个地，有它自己的位置，并不画在那个引脚上；要在引脚处画地，用定义体里那样画的定义，如 `$GROUND_STUB`（10.5）。绑定的角色填入空节点（6.3）时，引脚不在任何网络上，这也是合法的：它随后只与写在空节点上的导线相接（13.1），标准包的补位也不给它补东西。绑定的角色填入别种对象（如元件或点）时，引脚没有网络：属于种类错误，使该用例的 SET-SYMBOL 失效，该用例不画出，诊断同时指出套用处。声明为 `"net"` 种类的角色在套用定义时把端子转成它的网络（9.4），并在定好符号后把引脚转成它的网络（5.2.4）。没有任何引脚绑定的角色收定义声明的种类，如 `$NO_CONNECT` 的端子（12.6）。它不是电气端子：SELECT-TERMINAL 选不到它，ASSERT-TERMINAL 也不查它；SELECT-PIN 才选得到它（10.1）。不绑定任何角色的引脚仅作绘制，需要连线时按它的名字手动连。引脚名不能与角色名相同（6.5）。
  2. 用例被指派了符号才画出来；没有符号的用例不画。标准包只给要画出来的定义配符号，所以差分对这类语义用例不画。
  3. 没有符号的用例本身什么也不画：写在它上面的 ORIENT 失效，接到它某引脚名的导线也失效，因为它没有引脚（9.2.4）；这在 8.2 第 7 步之后检查。它仍有自身的点 `%u::position`：PLACE 取这个点，写在 `%u::position` 上的约束也取这个点，而直接写在这个用例上的约束取它的成员（14.1）；这个点只在定义体里把它和别的东西绑到一起时才会在图上体现出来（14.1、9.4）。导线或图元只能通过 `::position` 结束在那个点上，如 `&n {%u::position %pt} @WIRE`：那是点，不是引脚，所以导线什么都不接（5.2.4、6.5）。收到样式不出错：样式传给它体里创建的可画对象（8.3），体里没画东西时看不出效果（11.3）。
  4. 画出来的用例只画它自己的符号。它不包含、也不带动它的成员，不是视觉容器。
  5. **画在哪里。** 它符号的原点就是用例自身的点（14.1）：PLACE 和约束移动它，ORIENT 绕它旋转符号（11.2），而且它不跟着填角色的对象移动，除非通过事实，例如连向它引脚的导线，以及定义体里的事实。在引脚上或某点上画标记的定义，在自己体里把用例的点和那里绑起来，如 `{? ?t} @ALIGN("x"); {? ?t} @ALIGN("y")`（9.4）。没写 ORIENT 时由求解器选它的朝向并写回（14.8），没有求解结果的渲染器按 `"R0"` 画（8.5）；它不跟着引脚的出线方向。填第一个角色的对象是用例的主对象；用例没有自己的名字，文字经角色引用主对象，如 `${p}`（13.6）。
  6. 定义体一律展开，所以虚拟元件的定义也可以带体。
- 按原则 2.2 的说法，虚拟元件是有符号、角色填宿主对象的用例；标准虚拟元件是标准包里的定义，带一条给它默认符号的规则；用户自定义的虚拟元件是用户自己的定义，加上一条符号规则或体里给出的符号。
- **定义虚拟元件。** 标准的做法是写出普通定义，紧接着写一条规则给它的用例指派符号：`$GROUND = @DEFINE(roles=[["p", "net"]]) {}; # @SELECT-USAGE(recursive=true) $GROUND => @SET-SYMBOL $GROUND_SYMBOL`。这条规则按位置排进符号队列（8.3），所以风格体系包或文件里后写的规则（如 `# @SELECT-USAGE(recursive=true) $GROUND => @SET-SYMBOL $EARTH`）能换掉这些用例的符号，包括在别的定义体里造出的或补位造出的用例；只给一个用例换画法时，直接指名改它，`%g1 @SET-SYMBOL $EARTH`。定义体里也可以给出符号：`? @SET-SYMBOL $X`，其中单独的 `?` 是用例（9.4）：这算直接指明该用例（8.3），不会被规则盖掉，适合不打算另换画法的元件。换画法不改变端子和接在上面的导线。
- 一个用例是不是虚拟元件，只看它有没有符号。
- 注：该画出来却没配符号的定义，只有它的某个用例受到朝向或接线时，或者对它写的约束看不出效果时才会报出来（14.1）。

### 12.2 创建虚拟元件

```rnl id=g0
$GROUND @ATTACH &vss => @PLACE(24, 38) => %g0;
&vss @WIRE {#M5:3 %g0::pin}
```

- 在 `$D @ATTACH &net` 里，定义后面的对象按定义的角色表配位。它用 ATTACH 写，读作"把这个添在网络上"（9.4）。多角色的虚拟元件就像网表里的一行元件：定义 `$DIFF_PORT` 有角色 a、b 时，写 `$DIFF_PORT @ATTACH &inp(a) &inn(b)`，或按顺序写 `$DIFF_PORT @ATTACH &inp &inn`。
- 角色一般填网络：虚拟元件绑定了角色的引脚就画在这些网络上（12.1 第 1 条），它和某个器件引脚的关系（画在哪、接谁）由导线和约束表达（12.3）。绑定了角色的引脚画在填这个角色之物所在的网络上（12.1 第 1 条）：`$GROUND @ATTACH #M5:3` 在 M5:3 所在的网络上附一个地，与 `$GROUND @ATTACH #M5:3::net` 一样，有它自己的位置。角色收哪几种对象可以在定义里声明（9.4），如 `roles=[["p", "net"]]`。
- 这种关联只是描述，不建立电气连接，也不校验（原则 2.2）。
- 同一个网络可以有任意多个虚拟元件，如五个地、两个探针。用例没有键：每套用一次就多一个用例（5.8）。
- 个别虚拟元件可以另换符号，如用自己的符号 `$EARTH` 写 `%g1 @SET-SYMBOL $EARTH`。
- ATTACH 除 `priority`（14.8）外没有自己的参数。端口的方向归标准包的内容（12.4）；显示的名字是主对象的名字，要显示别的文字就写标签（13.3）。定义的参数照常经 ATTACH 传入（9.4）。
- 同一层里 `%g0` 只绑定一次（6.6）；要改它的位置，写 `%g0 @PLACE(…)`。

### 12.3 相对端子的位置

参数里不能放宿主引用，所以相对端子的位置写成约束：

```rnl use=g0
{%g0::pin #M5:3} @ALIGN("x");
%g0::pin #M5:3 @DISTANCE("bottom-to-top", exact=2)    /* the pin of the ground 2 below the source of M5 */
```

把 DISTANCE 换成 `@ALIGN("y")`，地的引脚就叠在 M5 的引脚上。在两个引脚之间写一条长度为 0 的导线 `&vss @WIRE {#M5:3 %g0::pin}`（13.1），也能使引脚算作已接线，这样补位就不会再在那里补第二个地（10.2、10.5）。

### 12.4 端口

```rnl
$IO_PORT @ATTACH &inp => @PLACE(0, 20) => %p_inp
```

- 子电路的端口名就是它内部的网络名，所以端口标签关联的是网络 `&inp`。
- 端口本身（`#:inp`）不画，只靠虚拟元件显示。标准系列 0.4 的补位通过集合 `$PORT_FILL_SET` 给每个端口网络加一个端口标签，电源网络和地网络也不例外，已经写出端口标签的网络排除在外（10.5）；一层的端口标签排成一列，每个都是 R0，引脚朝右；这一列始终在这一层每个元件的左边至少 6 个单位处，从它自身的点量起，靠优先级为 `"low"` 的约束做到；其余由求解器定。文件把某个网络从集合里去掉，它就没有端口标签，如 `# @SELECT-NET(name="vdd") => @REMOVE-FROM $PORT_FILL_SET`；想自己放端口标签的，写 `$IO_PORT @ATTACH`；或者在层里写一句 `$PORT_LIST @ATTACH`，得到同样的一列，但是写了出来，这一层的补位就不再加。`$PORT_LIST` 自身的点落在这一列上（14.1），所以对这个用例的约束会移动这一列。
- 端口的方向只是显示上的事：网表里没有方向，画哪种符号由用户决定。有哪些端口定义和符号，归标准包的内容。
- **端口标签的朝向**：端口标签有方向，如标准包的 `$IO_PORT_SYMBOL` 引脚在一端，标签往另一边伸出。没写 ORIENT 时，由求解器按导线的方向选朝向，以拐点少为目标。这是求解器的目标，不属于语言（14.8），所以手写时一般不写端口标签的 ORIENT。

### 12.5 标准虚拟元件

标准虚拟元件归标准包，标准包不属于语言标准（16.3）。例如，标准包提供地 `$GROUND`、电源 `$SUPPLY`、端口标签 `$IO_PORT` 和无连接标记 `$NO_CONNECT`（12.6），以及它们的符号、指派这些符号的规则和补位（10.5）。

同一个网络 vss，三种写法画出来不同：

1. `&vss @ADD-TO $GROUND_NET_SET`：vss 上每个没接导线的引脚下面各补一个地，带短导线（标准包的补位，10.5）。教科书多这样画：每个接地的端子下面各一个地符号。
2. `$GROUND @ATTACH &vss => %g`：整个网络只有一个地，由求解器摆。各端子用导线接到它的引脚，如 `&vss @WIRE {#M5:3 %g::pin}`，或整个网络写 ROUTE-NET（13.7）。
3. `$GROUND_STUB @ATTACH #M5:3`：只在 M5 源极下面画一个带短导线的地，与补位给每个引脚画的一样（10.5）。

- 电源同样写，集合是 `$SUPPLY_NET_SET`，定义是 `$SUPPLY`。网络 0 默认就在 `$GROUND_NET_SET` 里（10.1）。
- 第三种写法里短桩体内的导线使那个引脚算作已接线，标准包的补位不会再在那里补第二个地（10.2、10.5）。
- 端口：补位给子电路的每个端口网络加一个端口标签（12.4）。要放置它、约束它或改它显示的名字，就写出来：`$IO_PORT @ATTACH &out => %pout`，导线接 `%pout::pin`，名字写 `%pout @TEXT("V_{OUT}", key="name")`（13.3）。不需要端口标签的网络，从 `$PORT_FILL_SET` 里去掉。

### 12.6 无连接标记

```rnl
$NO_CONNECT @ATTACH #M1:4    /* terminal 4 of M1 is left unconnected on purpose */
```

- 无连接标记是标准包里的定义 `$NO_CONNECT`，它的角色收端子或引脚；不另设关键字。端子按它自己收下，不做转换（5.2.4），所以写在总线引脚的某一位上（9.2.4），如 `$NO_CONNECT @ATTACH #U1:d<3>`，就说明哪一个端子特意悬空；同一个总线引脚上的几个标记叠画在那个引脚处。标记的符号没有任何引脚绑定这个角色（12.1 第 1 条）；定义在体里把用例的点和填角色的引脚绑在一起（12.1 第 5 条），标准包给它一个叉的符号，原点在叉的中心、没有引脚。
- 用例记下这个端子是故意不接的：`# @SELECT-USAGE $NO_CONNECT => @SELECT-TERMINAL` 选出这些端子。
- 检查（网络上还有别的宿主端子、有导线碰到这个端子）不作要求（原则 2.4）；认得标准 `$NO_CONNECT` 的实现可以给警告。
- 无连接标记不算导线（10.2）：只有这个标记的引脚仍是 `wired=false`。按引脚补位要跳过它们，就减去它们的引脚 `# @SELECT-USAGE $NO_CONNECT => @SELECT-TERMINAL => @SELECT-PIN`，写法同 10.5 的差集。
- 注：无连接标记不做关键字，因为它对实现没有画图以外的用处：求解器不读它，画法能写进定义和符号（1.5 第 7 条）。
- 网络标签不是虚拟元件，见 13.3。
