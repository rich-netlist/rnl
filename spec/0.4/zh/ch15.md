## 15 电气语义

### 15.1 语义套用

```rnl
%dp1 = #M1(left) #M2(right) #M5(tail) @AS $DIFFERENTIAL_PAIR_N;
%cm1 = {#M3 #M9}(ref) {#M4 #M6}(out) @AS $CURRENT_MIRROR_P;
%in = {#M8 #M5} @AS $MATCHED
```

- 对象的含义用 AS 套用语义定义来标记（9.5）：套用产生一个用例，对象填进定义的角色表里的各个角色。标记含义与写布局关系是同一种语句。
- 用例可以作为别的用例的成员（嵌套），见 9.4、10.1 的例子。
- 集合角色在角色表里写成 `"{name}"`（如例子里 `$MATCHED` 的 `"{members}"`，`$CURRENT_MIRROR_P` 的 `"{ref}"` 和 `"{out}"`），收一个集合，表达个数不定的成员（9.4）。
- 角色可以声明收哪种对象，如 `roles=[["in_p", "instance"], ["in_n", "instance"]]`；填了种类不对的对象，整个套用失效（9.4）。体为空的定义不检查角色填的是什么，不声明就查不出填错。
- 用例的角色名是它的子对象，如 `%dp1::left`。
- 套用定义时展开它的体，体里可以有约束，如优先级为 `"low"` 的默认画法，用例的优先级能关掉它（9.5、14.8）。
- 不校验：不检查含义是否符合网表的连接、类型或参数（原则 2.4）。如 `#M3(ref) #M4(out) @AS $MY_MIRROR` 不检查 M3 的栅极和漏极是否相连；定义通过体里的断言来检查它声称的内容（15.3、15.4）。
- 选出某种含义的用例用 SELECT-USAGE，选出含有某个对象的用例用 SELECT-ANCESTOR-USAGE；用例的成员用以用例为范围的筛选取到（10.1）。
- 语义定义的词汇归标准包（9.5），标准包提供 `$DIFFERENTIAL_PAIR_N` 等定义。
- 单条描述的基本合法性（原则 2.4）是：它的引用找得到，它的角色收到种类正确的对象，它的单个角色都填了，它展开出的每条语句自身合法（9.5）。不检查两个角色是否填了同一个对象。

### 15.2 电流方向：CURRENT

```rnl
#M5:1 @CURRENT("in");                 /* drain: the current flows in */
#M5:3 @CURRENT("out")                 /* source: the current flows out */
```

- CURRENT 设定端子上静态电流的方向：`"in"`（流入）、`"out"`（流出）或 `"unspecified"`（不定，用来覆盖包里规则给的值）。参数是 `direction`。CURRENT 规则在第 6 步求值（10.4）。对象写的是引脚（或经角色到达引脚）的 CURRENT，需要符号才能找到它的端子（5.2.4）：它不是规则，在它对象的符号定下来后生效，即第 4 步，或者第 6 步生成的对象在第 7 步生效。到第 6 步为止，筛选的 `current` 条件只读直接写在端子上的 CURRENT 语句；从第 7 步起（包括样式队列里），则读全部方向，下面的几何与检查也一样。
- 它是关于端子的事实，不是几何事实：不参加冲突（8.5），求解器只把它当作提示，例如决定按什么顺序试朝向。它与 ORIENT 一样是修改语句，沿用输入的句柄。它有键，每个端子一个，后写的生效。从没写过它的端子就是不定。
- 它只给在端子上。多端子器件内部的电流拆不清楚：三端器件说"a 流向 b、b 流向 c"，b 处是流入还是流出说不清；而端子上静态电流的方向总有确定的含义。
- 它只收宿主的端子，含本层的端口：`#:inp @CURRENT("in")` 的意思是电流从这里流进子电路。器件的引脚转为它的端子，如 `#M1::d @CURRENT("in")`；虚拟元件没有端子，所以它们的引脚不能转换（5.2.4）。没有引脚的端子也可以（与导线不同）。
- 不照网表校验（原则 2.4）。同一个网络上的所有 CURRENT 语句合起来构成一条断言（15.3）：当网络上的每一个端子（包括本层的端口）都写了 `"in"` 或 `"out"` 的 CURRENT，且它们相对该网络都朝同一个方向输送电流时，给一条违例（violation，7.6），点出这个网络和它的各端子，因为电流无处可去。器件的端子写 `"in"` 是把电流从网络抽走，本层的端口写 `"in"` 是把电流送进网络。网络上有没写 CURRENT 或写了 `"unspecified"` 的端子时，这个网络不查。全局网络（6.3），如 `0`，也不查：它在每一层都是同一个节点，电流可以从别的层的端子流走。位于优先级为 `"disabled"` 的记录或用例体里的 CURRENT 不算数。这条断言在 8.2 第 7 步之后与其余断言一起检查，和它们一样只作报告，点出网络、各端子及其 CURRENT 语句；CURRENT 事实本身继续生效。
- 用途：电流流出时，端子上电流的走向就是导线离开引脚的方向（9.2.4，随符号的朝向转）；流入时反过来。求解器可以用它在摆法里挑，比如尽量让电流朝下（14.8）；朝上还是朝下是风格。没有写 CURRENT、写的是 `"unspecified"`，或者引脚没写 `direction=`（9.2.4）的端子，不给出方向；实现从图形推断出来的方向，在这里不算。规则可以按端子的电流方向筛选端子，用 SELECT-TERMINAL 的条件 `current`（10.1）。
- **箭头**：CURRENT 不画东西。按 CURRENT 画不画箭头、怎样画，是查看器的偏好（属于它的风格），与显示哪些网名同类（13.3）。查看器自己画时，跳过已有标准电流箭头用例的端子，就像它认得标准的 `$NO_CONNECT`（12.6）。要保留的箭头（导入的原图里的，或作者定下的）写成显式的对象：

  ```rnl
  $CURRENT_ARROW @ATTACH #M5:1 => @ORIENT("R270") => @TEXT("I_{SS}", dx=1);   /* on the drain pin, with I_SS beside it */
  $CURRENT_ARROW @ATTACH (12, 20) => @ORIENT("R270")                           /* in the middle of a wire, at absolute coordinates */
  ```

  - 画在端子上的箭头，它的定义的点绑在这个端子的引脚上（12.1 第 5 条）。它不跟着引脚转，所以朝向要写出来；旁边的文字附着在这个用例上（13.3）。
  - 导线中间的箭头不锚定在导线上：它画在一个点上，用绝对坐标。
  - 指向内还是指向外的箭头怎样区分，箭头的定义和符号怎样画，归标准包。符号可以只是一条末端带箭头的线（9.2.5）。
  - 画出来的箭头与 CURRENT 分开：两者若是一回事，导出一个箭头就会改变布局的目标。

### 15.3 断言（assertions）：ASSERT-INSTANCE、ASSERT-TERMINAL、ASSERT-NET、ASSERT-USAGE、ASSERT-IN

```rnl
$MATCHED_PAIR = @DEFINE(roles=[["left", "instance"], ["right", "instance"]]) {
  {?left ?right} @ASSERT-INSTANCE(same=["model", "w", "l"], different=["name"]);
  {?left ?right} @SELECT-TERMINAL(terminal="s") => @ASSERT-TERMINAL(same=["net"], message="the sources of a pair share a net")
};
# @SELECT-INSTANCE(name="MD*") => @ASSERT-INSTANCE(type="nmos");
%dp1 @ASSERT-USAGE $DIFFERENTIAL_PAIR_N;                      /* %dp1 is a usage of this definition */
#M5:s @SELECT-NET => @ASSERT-IN $GROUND_NET_SET              /* the source of M5 is on a ground net */
```

- 断言用来检查文件或定义所写的与电路的事实是否一致，比如一对管子是否同模型、同尺寸，或哑元器件是否同一种类型。它只作报告：不产生事实，不改变图面上的任何东西，也不参加冲突取舍（8.5）。
- **每种对象一个关键字**，与筛选相同（10.1）：ASSERT-INSTANCE 检查元件（含叠画，按第一个成员，11.8），ASSERT-TERMINAL 检查端子，ASSERT-NET 检查网络，ASSERT-USAGE 检查用例。唯一的那一个槽位收该种对象的集合；单个对象看成只有一个成员的集合。对象的种类在读文本时就已经知道，种类不对在那里就是错误（5.2.4），所以没有检查种类的断言。
- **条件**的名字和含义与同一种类筛选关键字的条件相同（10.1），如 `type="nmos"`、`terminals=4`、`net="vss"`、`port=true`：每一个成员都必须满足所写的每条条件。
- **`same=[…]`**：对列表里的每一个属性，所有成员取相同的值。**`different=[…]`**：对列表里的每一个属性，任意两个成员取值都不同。属性名就是 `${…}` 的属性名（13.6）：元件是 `name`、`value`、`model`、`type` 和它的参数名；端子是 `net`；网络是 `name`；用例是 `definition`。端子、网络、用例只有这些：其余任何名字都是错误的参数值，会让断言失效（7.1）。元件的参数名是开放的，什么名字都收；成员没有的那个属性自成一格，当作"缺省值"：都没有这个属性的成员彼此相等，且与任何写出的值都不同。所以 `same=["nf"]` 在没有成员写 `nf` 时成立，在有的写了、有的没写时给违例；某种工艺的器件没有这个参数时，不必单另再写一条断言。没有类型的元件（10.1）算缺少 `type`。比较按宿主所写的原文进行，不求值（没有表达式，3.7）。
- **`has=[…]`**，用于 ASSERT-INSTANCE：每个成员都带有列表里的每一个属性，如 `has=["w", "l"]`；缺少其中一个的成员给一条违例。`same` 不要求写过某个属性，`has` 才要求。
- **ASSERT-USAGE** 在最后收一个定义作为对象，与 SELECT-USAGE 相同（5.6、10.1）；这个定义可以省略。写了这个定义时，每个成员都必须是这个定义的用例——按名字实际指向哪个定义来认（9.5），不按名字的拼写。它的条件是 `symbol` 和 `drawn`（10.1）。当全部成员都是同一个定义的用例时 `same=["definition"]` 成立，任意两个成员都不是时 `different=["definition"]` 成立。
- **ASSERT-IN**：`X @ASSERT-IN S` 检查 X 的每一个成员都在集合 S 里；S 写在最后，与 ADD-TO 相同（5.2.2），S 必须是集合且不会被先拆开一层。两个成员是否相同按句柄判定（5.2）。成员可以是任何种类，S 也可以依赖筛选（10.4）。它没有条件，只有 `message`，违例会点出 S 里没有包含的那些 X 的成员。配合集合的差（5.2.2），它还能用来断言一个集合为空。
- `different=["name"]` 检查元件或网络彼此不是同一个对象，例如两个角色不能填同一个对象；端子没有 `name`，所以对端子来说 `name` 是错误的参数值，无论写在 `different` 还是 `same` 里都一样。
- **报告**：不成立的检查给一条违例（7.6），点出成员和属性；**`message`** 往这条报告里加上一段话。什么也不会因此失效，图面与没有断言时一模一样：断言只是一份给作者和 `rnl check` 这类工具看的报告。
- **写在哪里、何时检查**：写在任意一层里，或写在普通定义的体里——这时对每次套用分别检查（9.4）。断言在 8.2 第 7 步之后检查，这时所有条件都能读到，包括 `drawn` 和 `symbol`（10.1）。没有成员的集合自然成立，收到空节点（6.3）的断言也自然成立。
- 断言没有优先级；在 `priority="disabled"` 的记录里，以及在优先级为 `"disabled"` 的用例体里（14.8），断言不检查。

### 15.4 拓扑断言（topology assertion）：ASSERT-TOPOLOGY

```rnl
{#R1 #R2 #R3} @ASSERT-TOPOLOGY("series");                  /* a chain: R1 to R2 to R3 */
{#M3 #M4} @ASSERT-TOPOLOGY("parallel", exclude=[["nmos", "g"], ["nmos", "b"]]);   /* drains on one net, sources on one net */
{#L1 #C1 #L2} @ASSERT-TOPOLOGY("star");                    /* a T network: three branches meet at one net */
{#C1 #L1 #C2} @ASSERT-TOPOLOGY("loop");                    /* a pi network: C1, L1 and C2 go round */
{%branch1 %branch2} @ASSERT-TOPOLOGY("parallel")           /* two branches, each a usage or a set taken as a black box, between the same nets */
```

- ASSERT-TOPOLOGY 检查若干成员是否按给定方式连接：串联、并联、星形或单回路。它与 15.3 的断言是同一种断言，15.3 对断言说的一切对它也同样成立：它只作报告，检查不成立时给违例（7.6），`message` 往里加一段话，写在哪里、何时检查、在什么优先级下检查都相同。
- **成员**：唯一的那一个槽位收一列有序的成员，按项计数（5.2）：一个对象算一个成员，而直接写的 `{…}` 或集合引用算作一个成员，即一个黑盒（black box）。当集合是唯一的对象时先拆开一层（5.2.1），所以 `%chain @ASSERT-TOPOLOGY("series")` 检查那条链的各项，而 `{%branch1 %branch2}` 有两个成员。因此成员可以是元件（或叠画，按第一个成员，11.8）、用例或集合。若传入筛选的结果——它的每一个成员各占一项——成员就按筛选结果的次序（10.3）。不到两个成员时自然成立。
- **成员的网络**：
  - 元件：它没有被 `exclude` 拿掉的那些端子所在的网络；
  - 用例或集合：一个黑盒，即由它带进来的端子组成的整体。用例（不论有没有符号）代表填它角色的东西，集合代表它的成员，一直往下追到最里层；一个元件带来它的全部端子，一个端子只带来它自己，一个引脚带来它绑定的端子，网络和点什么也不带；叠画按第一个成员算。黑盒的网络，是它带进来的、没有被 `exclude` 拿掉的端子所在的网络里，同时在黑盒外面也被用到的那些网络：被它没有带进来的某个端子用到（包括叠画其余成员的端子），或者作这一层的端口。只被它带进来的端子用到的网络不算。注：两个成员共用的网络，对其中每个成员来说都被另一个成员用在外面，所以网络是否为端口，只对带进同一个端子的成员才改变判定；否则只改变哪些网络算黑盒的网络，如工具所显示的。
- **`exclude=[[type, terminal], …]`**：不计入的端子，每一项是一对类型与端子名或端子序号，类型照筛选条件 `type` 比较（10.1），如 `exclude=[["nmos", "g"], ["nmos", "b"]]`。一对里的端子按 SELECT-TERMINAL 的条件 `terminal` 比较（10.1）：数按位置，名字按宿主的大小写规则；元件没有这个名字的端子就什么也不匹配。没有类型的元件，或者类型不在列表里的元件，它的端子照算。不写 `exclude` 时每个端子都算。若某一项不是两个字符串、或一个字符串加一个非负整数的数组，就是错误的参数值，会让断言失效（7.1）。
- **四种拓扑**，第一个参数，按位置写，四选一：
  - `"series"`：按顺序相邻的两个成员恰共用一个网络，不相邻的两个成员不共用任何网络。共用的网络上还接了什么不查：分压器的中间点可以通往别处。
  - `"parallel"`：至少有两个网络（两端）被全部成员共用。成员的别的网络（比如一条支路引出的分接）不查，正如 `"series"` 里共用的网络上还接了什么也不查。
  - `"star"`：有一个网络被全部成员共用，任意两个成员不再共用别的任何网络。
  - `"loop"`：至少有三个成员。按次序绕一圈（包括最后一个与第一个），相邻的两个成员恰共用一个网络，这些网络各不相同，不相邻的两个成员不共用任何网络。只有两个成员时，`"loop"` 给违例；这时写 `"parallel"`。
