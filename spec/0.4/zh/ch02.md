## 2 宿主嵌入

### 2.1 两层解析

- 宿主适配器：
  - 识别宿主合法的普通注释，判断哪些行是载体（2.2）；
  - 确定每段注释属于哪一层，以及每条记录、每个子电路来自哪个文件、哪一次引入（6.1）；
  - 给出源位置和文本的顺序；
  - 提供宿主对象：元件、网络、端子、子电路端口和模型类型。
- RNL 核心只在这些注释里找记录。它不应对整个网表做不看上下文的 `@RNL` 搜索：宿主语句、宿主字符串里出现的同样字符不是 RNL。
- 解释器先解析完整的宿主网表，再处理 RNL（原则 2.9）。

### 2.2 载体

记录写在宿主的整行注释里，这样的注释行叫载体。宿主适配器逐行判断哪些行是载体，去掉注释符和它后面的一个空格，把其余内容交给 RNL 核心（2.1）。

- **只用整行注释。** 行尾注释（`$`、`;`、`//`、`!` 等）不读也不写，也不用块注释。
  - 行尾注释里的 `@RNL` 只是宿主文字，给警告。
  - 注：行尾那段算不算注释，随方言、模式和选项而变：HSPICE 的 `$` 可以紧跟在数后面（`1k$x`），ngspice 的 `ps` 方式里 `$` 是普通字符，Eldo 可以用 `.COMCHAR` 改；CDL 里 `$SUB=` 这类写法是数据。写进行尾还要改宿主语句那一行（原则 2.1）。SPICE 和 Spectre 都没有块注释（Spectre 只在 `reliability{}` 里有）。
- **各宿主的注释符。**

  | 宿主 | 注释符 |
  |---|---|
  | SPICE 系：SPICE3、ngspice、HSPICE、Xyce、LTspice、PSpice、WRspice、Eldo，以及 CDL 网表 | `*` |
  | Spectre 语言方式的段落：`.scs` 文件，或 `simulator lang=spectre` 之后的文字 | `//` 或 `*` |
  | Spectre 里 SPICE 语言方式的段落，包括没有 `.scs` 后缀、开头也没写 `simulator lang=spectre` 的被引入的文件 | `*` |

  - `*` 在 Spectre 的两种语言方式里都是注释。`//` 只在 Spectre 语言方式里有文档，在 Eldo 和 CDL 的文档里没有。
  - 一条记录的几行可以混用 `//` 和 `*`。工具写入记录时应跟随本文件已有的记录；没有记录时，SPICE 方式写 `*`，Spectre 方式写 `//`。
  - 载体属于外层写法，外层写法不改（16.1）。以后支持新的宿主时只增加载体，不改已有的。
- **载体行。** 记录的每一行都应满足下面两条：
  - 注释符写在第 1 列，前面没有空白。
  - 注释符后面要么什么都没有，或者只有空白，这是空注释行；要么先是一个 ASCII 空格，再写内容。所以 `*@RNL`、`*#M1`、`//@RNL` 都不是载体行。

    注：HSPICE、PSpice 要求 `*` 在第 1 列；有缩进的行，各家处理不同。紧贴注释符的文字在别的工具里有含义：ngspice、WRspice 把 `*#` 行当命令执行，WRspice 对 `*@` 行也是这样；`*.` 开始一条 CDL 指令（如 `*.PININFO`），`*|` 开始 DSPF 的数据，`//pragma` 是 Spectre 的加密封套。
  - 记录还没写完时遇到不合这两条的注释行（如 `*#M1 …`、`** …`、有缩进的 `* …`），记录被截断：整条记录失效（2.4）。记录之外，这样的行里的 `@RNL` 不是入口，给警告。
  - 写 RNL 的行建议不要以 `\` 结尾。这样的行给警告，工具不应写出这样的行。RNL 照常读，没有东西失效；危及的是宿主网表。注：WRspice 会把下一行接进这行注释；Spectre 用 `-E` 运行（先过 C 预处理器）、Eldo 开了 `SLASHCONT` 时也可能这样；下一行若是宿主语句，就被吞进注释了。
- **不读 RNL 的位置。** 这些位置的 `@RNL` 给警告，工具不应往这些位置写：
  - 每个宿主文件的第 1 行，以及宿主当作标题的别的行（如 WRspice 里 `.newjob` 的下一行）。主文件的第 1 行是它的标题，被引入时却不是标题；第 1 行一律不读，同一个文件作主文件和被引入的文件时读起来就一样。所以头段记录最早写在第 2 行（2.8）。
  - 主文件 `.end` 之后的文字。注：`.end` 之后，ngspice 接着读，Xyce 停下，HSPICE、PSpice 可能当作下一个电路。
  - 宿主不当作网表注释的区域：控制脚本（ngspice 会执行 `.control … .endc` 里的 `*#` 行）、别的语言的块和文件（WRspice 的 `.verilog`、Spectre 的 `reliability{}`；用 `ahdl_include` 或 `.hdl` 引入的 Verilog-A 文件只按 2.9 的规定读取）、密文、预处理去掉的部分、没选中的 `.lib` 段。适配器说不准的区域按不读处理，并给警告。
- **照读但给警告的位置：**
  - 语句和它的续行（`+` 行）之间的注释行。它们对 RNL 的含义是唯一的，所以照读；但宿主处理不同（PSpice 报错，SPICE 3f4 会把后面的 `+` 行接到注释上）。这些行给警告，工具不应往这里写。
  - 写成明文的加密区（`.prot … .unprot`、`protect … unprotect`）。照读，给警告：加密以后记录就没了。
- **文件起始时的语言**是交给工具的一项输入。默认由后缀名决定：`.scs` 为 Spectre 方式，其余文件为 SPICE 方式，与 Spectre 本身一致；用户也可以为每个文件分别指定，包括被引入的文件。起始之后，每一行按上述规则跟随 `simulator lang=` 切换。哪些行属于 SPICE 方式、哪些行属于 Spectre 方式，决定了带 `language` 的记录作用于哪些对象（2.8），因此工具按用户所选的语言读取每个文件；工具怎样让用户选择，不属于本标准的范围。
- **写入建议：**
  - RNL 不限制行长（2.4）。建议生成器在空白处换行，每行不超过 132 个字符：这是 PSpice 旧版的上限，在常见的宿主里最严（HSPICE 是 1024，Eldo 是 2000）。知道宿主上限的适配器按宿主的上限。一个记号在一行里放不下时，工具应报错，不应写出（字符串不能续到下一行，3.7）。
  - 编码见 3.1。

### 2.3 入口

- 记录以 `@RNL` 开始。入口只认大写。
- 各宿主都用同一个入口 `@RNL`；它就是原则 2.1 的子标签。
- `@RNL` 可以写在注释中间；同一行上它之前的文字属于宿主注释。
- **`@` 前的空格。** 入口 `@RNL` 和关键字的 `@`，紧前一个字符应是 ASCII 空格（U+0020）；TAB、换行、行首都不算。载体行上，注释符后面的那个空格算作 `@` 前的空格，如 `* @RNL`。字符串、加引号的名字、`/* */` 注释里的 `@` 不受限制。
  - 所以 `{`、`=>`、`=`、`;` 后面的关键字前也要留空格：`#M1 @SET-SYMBOL { @DEFINE-SYMBOL {…}}`、`%x = @DEFINE(…)`、`#M2 @PLACE(30, 20) => @ORIENT("MY")`。
  - 注：宿主注释里常有 `@`，如邮箱地址、`@param`；有了这条，这类文字不会被当作 RNL。WRspice 还会执行以 `*@` 开头的行（2.2）。
  - 记录外的 `x@RNL` 不是入口，只是宿主注释。记录里前面没有空格的 `@` 既不是关键字，也不是自由文本的字符：它是语法错误，所在的成员失效（7.4）。

### 2.4 记录的范围

- 记录写作 `@RNL(…) {…}`。括号里的记录头可以省；花括号不能省，单句也要写花括号。记录头的括号紧贴 `@RNL`，与关键字的参数括号紧贴关键字一样（3.5）：`@RNL (type="header") {…}` 是错误，整条记录失效。
- 记录从 `@RNL` 开始，到与它的第一个 `{` 相配的 `}` 结束。找相配的 `}` 时跳过字符串和 `/* */` 注释。记录头括号里的内容也跳过；第一个 `{` 之后，每一个花括号都计入配对，参数括号里面的花括号也不例外，这样没闭合的括号只会让它所在的成员失效（7.4）。字符串不能跨行（3.7）：没有在同行闭合的字符串到行尾结束，记录就此不完整（7.4）。
- **跨行的记录。** 一条记录可以写在连续的几行注释（载体，2.2）里。去掉每行的注释前缀，把各行内容接起来；换行是空白（3.5）。
  - 只有 `*`（或 `*` 和空白）的空注释行是空白，记录照常继续。
  - 还没写到收尾的 `}`，就遇到不是载体的行（宿主语句，`.subckt`、`.ends`、`.include` 这类行，完全空白的行，或不按载体写法写的注释行，2.2），或者文件结束，记录就不完整，整条失效。所以记录不会跨子电路和文件引入的边界。记录里要留空行，就写一个只有 `*` 的行。
  - 记录还没结束时，在字符串和注释之外又出现入口 `@RNL`：前一条记录不完整，整条失效，从新的入口重新读。这样，漏写一个 `}` 只丢一条记录。
  - 不完整的记录是错误，诊断说明记录不完整，并指出在哪里截断。多打一个空行就让整条记录失效，这很容易发生，不应静默放过（7.6）。
  - 记录里的每一行注释都是 RNL。中间夹一行普通说明，如 `* the next line is for M2`，会当作自由文本读，含有不能作自由文本的字符时是错误。记录里的说明写在 `/* */` 里（3.4）。
  - RNL 不限制行长；宿主的限制归适配器。长语句可以在空白处拆到几行；记号和字符串不能拆开（3.5）。给生成器的建议见 2.2。
- 记录结束后，同一行上再出现记号是错误：这些记号失效，记录本身照常生效。新的 `@RNL` 除外，所以一行可以写几条记录。
- 注释载体、入口 `@RNL` 和记录头与语言版本无关，以后的版本都不改（16.1）。体里的花括号在本版按上述方式配对。记录头的字段见 2.8。

### 2.5 停用记录与宿主文字

- 记录之外、不含 `@RNL` 的注释行是宿主注释，整行忽略。
- **停用记录。** 注释行里的 `/*`，如果前面只有空白或注释，或者紧跟在一条记录之后，就开始一段注释，到 `*/` 为止。其间的 `@RNL` 不是记录。
- 注释行中间文字里的 `/*`（如 `models/*.lib`）只是宿主文字。
- **宿主注释的结束。** 载体是整行注释（2.2）：宿主注释到行尾结束，行内没有东西能提前结束它，所以宿主注释的结束与 RNL 文字没有冲突。

### 2.6 层

- 层按文字划分，上下级见 6.1：
  - 主文件的文件层：写在主文件里、不在任何 `.subckt … .ends` 之内的部分。它就是电路的顶层。
  - 每个被引入的文件的文件层。`.lib` 的段同样处理。
  - 每个 `.subckt … .ends`。
  - 网表引入的每个 Verilog-A 文件的文件层，以及其中的各个模块（2.9）。
- 记录属于它所在的层（原则 2.5）。
- **多文件的顺序。** 被引入的文件自成一层，排在引入它的那一层之下（6.1）。所以引入行写在哪里不影响顺序，这一点与 USE-PACKAGE 不同（16.2）；并列的几个被引入的文件互不影响。同一层里按文本先后。
- **scope。** 记录可以用 `@RNL(scope="name")` 指定目标层。写的是子电路名，指那个子电路的定义。下面的文件里，最后一条记录写在主文件里，作用于子电路 `ota`：

  ```spice
  * A record written outside its subcircuit
  * @RNL(type="header") { @VERSION("0.4")}
  .model nch nmos level=1
  .subckt ota inp inn out tail vss
  M1 x inp tail vss nch
  M2 out inn tail vss nch
  .ends ota
  X1 vip vin vo vt 0 ota
  * @RNL(scope="ota") { #M1 @PLACE(10, 20)}
  .end
  ```

  - 每个子电路只有一张图（6.1），所以 scope 指定义，不指某一个元件。
  - scope 只能向下：目标应是本层在文字上包含的子电路，即本文件里定义的，或本层直接或逐级引入的文件里定义的。子电路里不写 scope：子电路的 RNL 只管它自己。子电路里的记录写了 `scope` 是错误，当作没写（2.8）。目标找不到或不在本层之下时是错误；记录里的语句没有层可以解析，都失效（第 7 章）。
  - 记录里的引用都在目标层解析。它的语句提交到目标层，绑定的名字也发布到目标层，与目标层自己的记录共享（6.7）；目标层已经把这个名字绑定到别的对象时，再绑定是错误；绑定到同一个对象则可以（6.6）。scope 只影响它自己的记录，不改变宿主网表。
  - 顺序：scope 带进一个子电路的语句排在这个子电路自己的文字之后；几处都 scope 到同一个子电路时，外层的排在后面（8.3、8.5）。外面明确写的覆盖里面写的，与外层用例的优先级盖过它的体同理（14.8）。
  - 求解器的输出和用户在编辑器里做的修改不应使用 scope；它们写进子电路自己的文字（第 17 章）。scope 只用于作者自己选择写在外面的语句。

### 2.7 包文件

包可以写成单独的包文件，由 USE-PACKAGE 找到（16.2）。包文件是纯 RNL 文件，建议扩展名 `.rnl`，用 UTF-8 写。它不是网表，不用 `.include` 加载。

- 包文件的**读法**与网表里的载体相同（2.2、2.4），只是每一行都是载体，注释符和它后面那个空格都算空的：
  - 行首的 `@` 算前面有空格（2.3），所以 `@RNL` 和关键字可以从第 1 列写起；
  - 空行是空注释行，记录照常继续；
  - 记录之外的文字是说明，忽略，与宿主注释相同（2.5）；`/* */` 照常起作用；
  - 第 1 行照读：包文件不是网表，没有标题行（2.2）。
- 包文件里写 `@RNL(…) {…}` 记录，按 16.1 的顺序解析。第一条记录是不带 `language` 的头段记录，里面写 VERSION 和 PACKAGE；包文件也可以为每种语言各写一条头段记录（2.8）。包里能写什么，包括引用别的包，见 16.2；代称包也是包文件（16.5）。

下面是一个包文件的全文，没有注释前缀。第三行在记录之外，是说明。该包未引用标准包而直接使用 `$NMOS`，因此在它被用到的地方生效的标准包中寻找它；单独检查该包时，则在工具按设置附加的标准包中寻找（16.2、16.3）：

```rnl-file
@RNL(type="header") { @VERSION("0.4"); @PACKAGE(name="acme-style", version="1.2")}

ACME house style: NMOS symbol and its rule.
@RNL {
  $NMOS_ACME = @DEFINE-SYMBOL {
    $NMOS;
    ? @TEXT("${name}", key="name") => @PLACE(-2.5, 1.5)
  };
  # @SELECT-INSTANCE(type="nmos", recursive=true) => @SET-SYMBOL $NMOS_ACME
}
```

### 2.8 记录头

`@RNL(…)` 括号里的字段作用于记录里的每条语句，都写名字。字段名和 `type` 的值按标准的拼写写，区分大小写，不能有代称（3.6、16.5）。

```rnl
* @RNL(type="header") { @VERSION("0.4"); @USE-PACKAGE(name="rnl-std-all", version="0.4")}    /* the first record of the file: read as version 0.4 (16.1) */
* @RNL { %dp1 = #M1(left) #M2(right) #M5(tail) @AS $DIFFERENTIAL_PAIR_N}    /* no type: "authored" */
* @RNL(type="generated", priority="high", author="rnl-solver 0.3", hash="sig1:9f3a62c1") {
*   #M1 @PLACE(12, 20); #M2 @PLACE(28, 20)
* }
* @RNL(author="rnl-editor 0.1") { #M2 @PLACE(x=30, priority="high")}
```

| 字段 | 含义 | 影响解释 |
|---|---|---|
| `type` | 记录的种类：`"authored"`（默认）、`"generated"`、`"header"` | 是 |
| `scope` | 目标子电路（2.6） | 是 |
| `priority` | 记录里语句的默认优先级；给 AS、ATTACH 的只有 `"disabled"`（14.8） | 是 |
| `author` | 作者、工具及其版本、包的版本等；任意字符串 | 否 |
| `hash` | 求解器输入的散列值（第 17 章） | 否 |
| `numbering` | 记录所用编号的校验和（5.9）；只用于 `type="generated"` | 是 |
| `modified` | 最后修改的时间，ISO 8601 字符串 | 否 |
| `language` | 记录所作用段落的**网表语言（netlist language）**：`"spice"` 或 `"spectre"`（见下） | 是 |

- **type**：取值固定，各有确定的行为。
  - `"authored"`，默认：手写的、编辑器写的或导入的。
  - `"generated"`：求解器的结果。求解器求解时，按不含 `type="generated"` 记录的方式解释该层：它们不带来对象、名字或事实，也不约束结果；此外怎样用它们，由求解器自己决定。求完后求解器把它们整条换掉，不论作者是谁，也不论自己是否认得里面的语句：16.4 中"工具重写自己的记录时保留不认识的语句"这一条不适用于此处的替换。需要保留的内容写在其他种类的记录里。编辑器拖动器件时重画的导线也算求解结果（14.8、第 17 章）。`type` 不隐含优先级：求解器明确写出 `priority="high"`。
  - `"header"`：文件的设置（16.1）。头段记录可以不写。写的话，它在文件层，不在 `.subckt` 或 Verilog-A 的模块里面（2.9），不带 `scope`；头段记录是文件最前面的记录，不带 `language` 的至多一条，每种语言至多一条（见下文 `language`）。里面写 VERSION（16.1）、ALIAS 的代称和 USE-ALIASES 的代称包（16.5）、DEVICE 的端子名和类型（6.12）、USE-PACKAGE 的根上的包（16.3）以及 SOLVER-CONFIG 的**求解器设置（solver settings）**（14.10）；包文件还在这里写 PACKAGE（2.7、16.2）。头段记录本身按标准拼写读，不认代称（16.5）。写在其他记录后面的头段记录，或者第二条不带 `language` 的头段记录、同一种语言的头段记录，是错误，整条忽略；已经读过的记录不回头改。经 `.lib` 读入的一节，按一个文件算（2.6）：它的头段记录是节里的第一条记录。工具写头段记录时，使用所在位置语言方式的注释符（2.2）。当文件的第一条语句写在 `simulator lang=` 行之后时，头段记录既可以紧跟在该行之后、按文件其余部分的语言方式写，也可以写在该行之前（例如第 2 行）、按文件起始时的语言方式写；不论写在哪里，它都是文件的第一条记录。
- **language** 使记录只作用于该语言段落里的对象。
  - **段落**：适配器按语言方式把每个文件划分为段落，依据是 `simulator lang=`（2.2）。取值为 `"spice"`（涵盖 SPICE 系以及 HSPICE 等各 SPICE 方言）和 `"spectre"`；后续版本可以增加与这些不兼容的语言。取值区分大小写。
  - **名义作用域**：一条记录能到达的层与不写 `language` 时相同：写在某层里的记录到达该层及其下各层，写在包里的记录到达使用该包的各层（16.2）。在它到达的对象中，带 `language` 的记录只作用于其所属语言段落里的对象；不带 `language` 的记录作用于所有段落，因此在 Spectre 文件里也作用于其中的 SPICE 段落。
  - **对象属于哪一段**：元件及其端子，属于写出该元件行的那一段；子电路的端口（`#:port`），属于开始该子电路的那一行的那一段；网络，属于所有写了它的行所在的段落，因此同时写在两种段落里的网络能被两种语言的记录共同作用；RNL 造出的对象（用例、点、图形或文字），属于它所附着或填入的宿主对象所在的段落，例如附着在 `&vss` 上的地；层本身以及不附着于任何宿主对象的对象，属于该层中有行存在的所有语言。
  - **跨段语句**：如果一条语句的对象有一部分落在该记录所属语言的段落之外（例如约束、导线或 GROUP），这条语句整体不起作用。对这些段落之外的对象的引用不起作用也不算错误，依赖它的语句同样不起作用；当该层存在该语言的段落时，完全找不到的名字照常报错。在其所及范围内没有任何对应语言段落的记录不作用于任何对象，也不做检查。
  - **定义不按段划分**：`$` 名字、符号和样式照常在名义作用域内可见（6.8）；只有作用于对象的语句才按段筛选。
  - **头段记录**：一个文件可以有一条不带 `language` 的头段记录，以及每种语言各一条带该字段的头段记录。它们写在最前面，一条紧接一条，不带 `language` 的写在最前。VERSION、PACKAGE、ALIAS 和 USE-ALIASES 只写在不带 `language` 的头段记录里；带 `language` 的头段记录只写 USE-PACKAGE 和 DEVICE，它们随后只作用于该语言的段落（6.12、16.2）。所有头段记录一起生效。两条头段记录以不同版本或不同内嵌内容写出同一个包是错误，因为同一层可能包含两种语言的段落，且同名包只能使用一次（16.2）：带 `language` 的头段记录里的 USE-PACKAGE 失效，不带 `language` 的头段记录里的那条对所有段落生效；两条带 `language` 的头段记录之间，后者失效。
  - `type="generated"` 的记录不能带 `language`：求解器对整层求解，并把生成记录整条替换。写在这里的 `language` 是错误，当作没写处理。
  - 若写入了本版本未列出的值，记录不作用于任何对象，并给警告指出最接近的取值；这是下述规则的一个例外——通常认识的字段写错会当作没写，那样会使记录作用于所有段落。写出 `language` 的工具须在不带 `language` 的头段记录里写明 `@VERSION("0.4")`（16.1）。工具新写出的记录不带 `language`；已带该字段的记录原样保留（16.4）。
- **元数据**：`author`、`hash`、`modified` 不影响解释；删掉它们，画出来的结果不变。工具拿它们判断怎样处理一条记录（第 17 章）。`type`、`author` 都不影响取舍次序（8.3）。
- **出错**：
  - 不认识的字段只给警告，忽略；它不影响这条记录和别的字段。这给以后的扩展留了位置。给这个警告时，应指出最接近的字段名。注：这样一来，影响解释的字段拼错了（如 `priorty="low"`）也只得到警告，记录按优先级 `"normal"` 生效；以后新增的这类字段，要靠版本（16.1）让旧工具知道自己过时了。
  - 认识的字段写错（值不对，`numbering` 写在 `type` 不是 `"generated"` 或带 `scope` 的记录里，或同一字段写了两次）是错误，按没写这个字段处理：`priority` 回到 `"normal"`，`type` 回到 `"authored"`，元数据丢掉。例外是目标找不到的 `scope`：记录里的语句没有层可以解析，都失效（2.6）。按位置写的字段是错误，忽略。
- 记录没有标识。工具按 `type`、`author` 和语句的 key（5.8）找自己的记录；在另一条记录里引用一个对象靠它的名字，求解器的记录还可以用编号（5.9）。别的说明写在注释里。
- 求解结果不是要采纳的提案：它直接生效，过时的结果只给提示（第 17 章）。

### 2.9 Verilog-A 文件

子电路为它的元件给出框图符号（block symbol）（9.2.6）。网表引入的 Verilog-A 模块也可以这样做，在 Verilog-A 文件自身里写出记录：

```verilog
// @RNL(type="header") { @VERSION("0.4"); @USE-PACKAGE(name="rnl-std-all", version="0.4")}
`include "disciplines.vams"
module vco(vin, out, vdd, vss);
  inout vin, out, vdd, vss;
  electrical vin, out, vdd, vss;
  parameter real f0 = 1e9;
// @RNL {
//   %vco = @DEFINE-SYMBOL(box=[-3, -3, 3, 3]) {
//     @RECTANGLE {(-2, -2) (2, 2)};
//     (-3, 0) @PIN(terminal="vin", direction="left");
//     (3, 0) @PIN(terminal="out", direction="right");
//     (0, 3) @PIN(terminal="vdd", direction="up");
//     (0, -3) @PIN(terminal="vss", direction="down");
//     ? @TEXT("${name}", key="name") => @PLACE(0, 2.5);
//     ? @TEXT("f0=${f0}", key="value") => @PLACE(0, -2.5)
//   };
//   # @SET-SYMBOL %vco
// }
  analog begin
    V(out) <+ 0;
  end
endmodule
```

写有 `ahdl_include "vco.va"` 与 `I1 (ctl out vdd 0) vco f0=2e9` 的 Spectre 网表会用这个符号画出 I1，自身不必写任何 RNL。

- **哪些文件。** 网表引入的 Verilog-A 源文件：在 Spectre 的两种语言方式里用 `ahdl_include` 引入，在 HSPICE 里用 `.hdl` 引入。这类文件在引入处读取，与被引入的文件相同（6.1）。使用 Spectre 的 `ahdl_include … -master name` 时，该模块在网表里以这个名字为人所知，它的框图符号就配给这个名字的元件。宿主以已编译形式引入的模型（如 ngspice 的 `.osdi` 文件）没有文本可读；它的元件使用默认的框图符号，元件行上有几个节点就配几个引脚（9.2.6），上层也可以用规则给它们配符号。
- **载体。** 整行注释 `//`，规则同 2.2：`//` 在第 1 列，后面什么都不接、只接空白，或者接一个空格再接正文。行尾注释和 `/* */` 注释不读，其中的 `@RNL` 给警告。第 1 行照读：Verilog-A 文件没有标题行。Verilog-A 预处理器可能略去的文本——写在 `` `ifdef `` 或 `` `ifndef `` 与其配对的 `` `endif `` 之间的文本——不读，其中的 `@RNL` 给警告，与 2.2 中适配器无法确定分类的区域相同。
- **层。** 写在所有 `module … endmodule`（及 `macromodule … endmodule`）之外的文本是该 Verilog-A 文件的文件层。每个模块各自成一层，即模块层（module level），排在该文件层之下，而该文件层排在引入它的文本所在层之下（6.1）。
  - 文件层只放头段记录（2.8），写在第一个模块之前。写在文件层的其他任何记录都是错误，失效。
  - 模块层没有电路，也没有原理图：里面什么都不画、不求解，也没有求解器的记录。
- **模块层里放什么。** DEFINE-SYMBOL 和 DEFINE-STYLE，以及一条给符号的 `# @SET-SYMBOL` 语句，其中的 `#` 指该模块自身。这条 SET-SYMBOL 给出该模块的框图符号，具备 9.2.6 对子电路框图符号所说的一切性质：它作用于实例化该模块的各个位置，在符号队列里的位置也相同（8.3）。模块层里写的其余任何内容都是错误，失效：宿主引用、约束、PLACE、ORIENT、WIRE、写在符号体外的 TEXT、`# @SET-SYMBOL` 以外的规则、AS 和 ATTACH、断言、`scope`、DEVICE 以及 SOLVER-CONFIG。USE-PACKAGE 只写在文件头段记录里。
- **端子。** 模块元件的端子是宿主在它的这一行里读到的节点，按模块端口表里各端口的次序排列，并以端口命名。Verilog-A 比较名字时区分大小写，因此端口名也区分大小写。
  - 向量端口（vector port）的每一位对应一个端子，按它声明范围的左界到右界的次序排列，与向量按位置连接一致：端口 `inout [3:0] d` 取该行紧接的四个节点，依次为 `d[3]`、`d[2]`、`d[1]` 和 `d[0]`，而 `inout [0:2] e` 取三个节点，依次为 `e[0]`、`e[1]` 和 `e[2]`。这些就是它们的端子名，在引用里带下标写法（6.11），如 `#I1:d[3:0]`，在 PIN 的 `terminal=` 里写成字符串，如总线引脚写 `terminal=["d[3]", "d[2]", "d[1]", "d[0]"]`（9.2.4）。
  - 模块不给它的元件设定类型（6.12）；网表里的 DEVICE 可以给它们设类型，与其他元件相同。
- **版本与包。** Verilog-A 文件的头段记录与被引入的文件相同：不写头段记录或不写 VERSION 时，该文件取引入它的文件的版本（16.1），其中的 USE-PACKAGE 只作用于该文件及其模块（16.2）。
- **写回。** 工具在 Verilog-A 文件里写 `//`，且只写头段记录和框图符号的记录；不在那里写求解器的输出（第 17 章）。
