## 1 概述

### 1.1 范围

RNL（Rich Netlist）写在宿主网表的注释里。它描述网表所定义的电路怎样理解、怎样画成原理图：用哪些符号、各部分放在哪里，怎样朝向、对齐、连线、加标签、设样式，以及一组组元件是什么含义（原则 1）。

器件、类型、参数、连接和子电路接口只由宿主网表定义。RNL 引用它们，不能改变它们。RNL 不检查作图所表达的电气含义（原则 2.2）。

本标准定义：

- 怎样从宿主网表的注释里，以及从它引入的 Verilog-A 文件里取出 RNL（第 2 章）；
- RNL 文本的词法和语法（第 3、4 章）；
- 文本描述哪些对象，名字怎样解析，出错怎样处理，以及各项描述怎样一起生效（第 5–8 章）；
- 各类描述的词表（第 9–17 章）；
- 标准词表，与本正文一同以 `rnl-words-0.4.json` 发布（5.3、附录 A）。

本标准不定义布局算法，也不规定唯一的画法（原则 1），也不定义宿主网表怎样解析（原则 2.1）。标准包 `rnl-std-all` 和 `alias-zh` 等代称包用 RNL 写成；本标准定义包怎样工作（16.2、16.3、16.5），包的内容另行发布。

本正文定义这一语言的 0.4 版。0.x 各版之间不保证彼此兼容（16.1）。

### 1.2 本标准的结构

本标准由抽象模型和文本语法两部分组成。抽象模型包括对象、事实、读取方式和生效阶段（第 5–8 章）；文本语法是它的书面写法（第 2–4 章）。工具之间交换文本。

附录 A 列出关键字的签名；它由词表生成，具有规范性。附录 B 给出标准例句，附录 C 列出留待后续版本的内容，附录 D 列出相对 0.3 版的变更；这三个附录为资料性内容。注和示例均为资料性内容。其余全部具有规范性。

### 1.3 概览

```spice
* Five-transistor OTA, input stage
* @RNL(type="header") { @VERSION("0.4"); @USE-PACKAGE(name="rnl-std-all", version="0.4")}
.model nch nmos level=1
.subckt ota5t inp inn out vdd vss vbias
M1 x    inp   tail vss nch W=2u L=0.5u
M2 out  inn   tail vss nch W=2u L=0.5u
M5 tail vbias vss  vss nch W=4u L=1u
* @RNL {
*   %dp1 = #M1(left), #M2(right) and #M5(tail) treated @AS $DIFFERENTIAL_PAIR_N;
*   {#M1 #M2} @ALIGN("y"), i.e., same y;
*   #M5 is at @PLACE(20, 6) => it @ORIENT("R0");
*   %g0 = $GROUND is @ATTACH to &vss;
*   net &vss, through {#M5:3 %g0::pin}, has a @WIRE
* }
.ends ota5t
.end
```

- `* ` 开始一行 SPICE 注释。`@RNL {…}` 是一条记录；花括号里面是用 `;` 分开的成员（第 2 章）。文件开头的头段记录声明语言版本（16.1）。
- `#M1`、`&vss`、`#M5:3` 指宿主的一个元件、一个网络和一个端子。`%dp1` 和 `%g0` 是这一层的 RNL 名字。`$DIFFERENTIAL_PAIR_N` 和 `$GROUND` 是来自标准包的普通定义（9.4），头段记录引入了标准包（16.3）。`%g0` 是套用 `$GROUND` 造出的用例；标准包给它配了地符号，所以它画作地（第 12 章）。
- `@AS`、`@ALIGN`、`@PLACE`、`@ORIENT`、`@ATTACH`、`@WIRE` 是关键字。参数写在紧贴关键字的括号里，只写字面量。AS 用前面写出的对象填后面写出的定义的角色；ATTACH 把前面写出的定义添到后面写出的对象上（9.4、第 12 章）。
- `(left)` 标出角色。`%dp1 =` 为语句的结果起名。`=>` 把上一段的结果传给下一段；后面只跟一个名字时，为上一段的结果起名（5.5）。
- `and`、`treated`、`, i.e., same y`、`is at`、`it`、`is … to`、`net`、`, through`、`, has a` 是自由文本，不改变含义（3.3）。标准例句在记号之间加上这类词，让语句读起来像一句话（4.5、附录 B）。去掉它们，这条记录写成：

```rnl
%dp1 = #M1(left) #M2(right) #M5(tail) @AS $DIFFERENTIAL_PAIR_N;
{#M1 #M2} @ALIGN("y");
#M5 @PLACE(20, 6) => @ORIENT("R0");
%g0 = $GROUND @ATTACH &vss;
&vss {#M5:3 %g0::pin} @WIRE
```

### 1.4 术语与惯例

#### 1.4.1 要求用词

- **应**（或**须**、**必须**）、**不应**（或**不得**）（must, must not）：对文件或实现的要求。
- **建议**、**建议不要**（should, should not）：推荐的做法；有理由时可以例外，但建议先弄清缘由。
- **可以**（may）：允许的做法。

语言本身的含义用一般陈述语气表述："语句失效"、"后者覆盖前者"。

#### 1.4.2 失效与诊断

- 某一条目（记录头的字段、语句、记录或文件；7.6）**失效**，就是不起作用；一条失效的语句以一个失效对象作为它的值（7.2）。无论由什么原因引起，每一次失效都是**错误**（7.6）。
- **警告**标出写法合法但可能不是作者本意的情况；除本标准另有规定外（例如求解器在限时内未能判定的事实，8.5），条目照常生效。**违例（violation）**报告文件中关于电路的某条陈述（例如**断言（assertion）**）不成立；没有任何条目失效（15.3、15.4）。**提示**标出常见的覆盖、遮蔽或取舍，这些情况也可能是误写。各类情况列在 7.6；本标准说某情况给警告或提示时，建议实现报告它。
- **整份解释失败**时，什么都不画，并报告错误（1.5 第 3 条、7.6）。

#### 1.4.3 记法

- 正文里，关键字大写、不带 `@`：PLACE、SET-SYMBOL。语法和示例里带 `@`。
- 标准词、名字和字面量用代码字体：`priority`、`"high"`、`instance`、`$GROUND`。
- 括号里的章节号指本标准：（9.4）。"原则 2.4"指 RNL 原则 `rich-netlist.md` 的第 2.4 节。
- 示例按标准写法写出（4.3），不带自由文本，专门讨论自由文本的示例除外。标作 error 的示例展示错误写法。
- 示例使用标准包：没有写出头段记录的示例，按主文件头段记录写了 `@USE-PACKAGE(name="rnl-std-all", version="0.4")` 来读（16.3）。

### 1.5 核心原则

本标准的规定遵循以下原则。第 1–6 条细化了原则 2.9；第 7 条说明词表怎样划分。

1. **一切都是描述。** RNL 文本是一组描述。解释器把全部描述收齐，再给出结果。这里没有"执行"，一个名字可以在绑定它的语句之前使用。
2. **书写位置只作顺序用。** 描述写在哪里（哪一层、文本里的先后）只在三种情况下影响结果：两条描述互相矛盾时保留后一条（几何事实先比优先级；8.3、8.4、8.5）、绘制顺序（11.6），以及集合里成员的先后（5.2）。除此之外，结果与书写顺序无关。管道的每一段各有自己的位置：后一段算作写在前面一段之后（5.5）。
3. **矛盾的处理。**
   - 读不通的描述（语法错误、找不到名字、种类不对等）或者自相矛盾的描述各自失效（原则 2.4、2.9；第 7 章）。
   - 各自都读得通、但互相矛盾的描述，凡本标准给出明确取舍办法的，按办法解决，如按键覆盖（8.4）、外观队列（8.3）和几何事实的取舍（8.5）；可以给提示。
   - 本标准还没定出明确办法的地方，整份解释失败（7.6）。这一版没有这种情形（7.5）。以后版本如果定出了办法而放宽，现在能过的文件不会受影响。
4. **描述只看生效前的状态。** 每一条描述读取它所在阶段开始时的状态，不计入它自己的效果和同一阶段里别的描述的效果（8.2）。
5. **对象与名字。** 每条带关键字的语句和每一个 `{…}` 各造出一个新对象，由一个句柄和若干事实组成。引用不造对象，但按成员位置取成员会造出一个新集合（5.2.3）。名字只用来指称一个对象，在一层里只能绑定一次。覆盖只针对事实，不针对名字（5.1、6.6）。
6. **不设方便阅读的禁令。** 写法难读但含义唯一时允许；克制自己留给作者。只把含义不唯一的写法定为错误。
7. **关键字与定义。** 需要实现本身理解、用现有描述写不出来的，才设为关键字。用已有描述在普通定义体里能写出来的，都放进定义，定义的名字只是提示（9.5）。

### 1.6 一致性

**文件。** 一份宿主网表的各条记录按第 2–4 章读取、按第 5–17 章解释时没有错误（7.6），包括它用到的包的内容也没有错误，就符合 RNL 0.4。警告、提示和违例不影响一致性：违例说明电路并不符合文件中的陈述，而非文件写法有误。单独检查包文件时，按同样方式判定一致性（16.2）。头段记录声明了其他语言版本的文件不受本版本约束（16.1）。

**实现**指读取或写出 RNL 的解释器（只做检查的解释器也叫 lint）、查看器、求解器、编辑器等工具。符合本标准的实现须做到：

1. 按第 2 章从宿主的注释里取出 RNL，按第 3、4 章读它；
2. 按第 5–17 章给每条描述应有的效果，使用词表里的签名（5.3）；
3. 报告每个错误，给出位置和原因（7.6）；错误不能调低，也不能关掉；
4. 建议报告本标准列出的警告和提示，并须报告违例（7.6）；
5. 可以另加自己的检查，但只能是警告或提示：不应让本标准允许生效的条目失效，也不应让本标准规定失效的条目生效；
6. 可以提供更严的模式，停下或拒绝整份输入，但不作为默认；
7. 让用户能看到诊断；怎样呈现由实现决定（7.6）；
8. 声明自己支持哪些语言版本，对不支持的版本的文件按 16.1 处理；
9. 把不认识的关键字、参数和取值当作错误（16.4）；
10. 文件写出标准包时，按 16.3 把标准包放在根上；
11. 写 RNL 时，新语句用标准写法写，不重排用户写的语句（4.3）；保存文件时写头段记录和版本（16.1）；不认识的语句、失效的语句、宿主文字、普通注释和不支持的版本的文件都原样保留（16.4）；只改第 17 章允许它改的记录；
12. 求解时，按 8.5 取舍冲突，把自己定下的每个决定都写回，交给别的工具的结果也只用求解器的记录能含有的形式（14.8）；
13. 可以对所用资源设置上限，例如符号嵌套深度（9.2.7）、用例展开深度（9.4）、被引入的文件及子电路的嵌套深度，或对象数量。输入超出此上限时须报告错误，说明已达**实现上限（limit of the implementation）**并给出位置；实现不得静默截断输入，也不得按异于本标准规定的方式作图或求解。实现应至少支持 64 层符号嵌套。求解时检查事实的上限不属此类限制：它是求解器的一项选项，未及判定的事实连同警告一并丢弃（8.5）。

本标准不规定求解器在满足约束的各种位置中怎样选，也不规定查看器怎样画 RNL 没有定下的部分；留给它们决定的地方在正文里写明（如 13.1）。

**一致性测试**查错误（连同位置和每处失效的范围）和得到的场景。警告可以作为可选的期望来查；提示不查（7.6）。
