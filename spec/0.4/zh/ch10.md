## 10 筛选、规则与逐个生成

本章讲筛选关键字、用到它们的规则，以及逐个生成。

### 10.1 筛选关键字

选出的每种对象各有一个筛选关键字，每个的条件固定。筛选的结果是集合（5.2）。

每个筛选关键字收一个范围对象。`#` 表示求值时所在的那一层（10.3）。给一个对象或集合，就在这些对象里选：比如给网络的集合时，SELECT-TERMINAL 选接在这些网络上的端子（怎样从范围走到要选的种类，见表后）。范围不能省略，所以简单的筛选也写 `#`：`# @SELECT-INSTANCE(name="R*") => @SET-SYMBOL $RESISTOR`。

| 关键字 | 选出 | 条件 |
|---|---|---|
| SELECT-INSTANCE | 宿主元件。范围里给端子时，选它们所属的元件；给网络时，选在上面有端子的元件 | `name`（元件名，如 `name="R*"`）；`model`（元件行上写在模型位置的名字：`.model` 名或子电路名）；`type`（元件的类型，来自它的 `.model` 或 DEVICE，如 `"nmos"`；收 `*`）；`terminals`（元件的端子数，如 `terminals=3`）；`symbol` 和 `drawn`（见下） |
| SELECT-TERMINAL | 宿主元件的端子，不论有没有引脚：针对电路的筛选 | 所属元件的 `name`、`model`、`type`；`terminal`（端子名或序号）；`net`（所在网络的名字）；`current`（电流方向，15.2：`"in"`、`"out"` 或 `"unspecified"`） |
| SELECT-PIN | 绘出对象的引脚：针对作图的筛选（9.2.4） | 所属对象的 `name`、`model`、`type`；`terminal`（引脚绑定的端子名或角色名）；`net`（它 `::net` 的名字）；`wired`（10.2） |
| SELECT-NET | 网络。范围里给元件、端子或导线时，选它们所在的网络 | `name`；`port`（是否本层的端口）；`wired`（10.2）；`global`（是否全局网络，6.3） |
| SELECT-WIRE | 导线。范围里给网络时，选画在这些网络上的导线 | `net`（导线所在网络的名字；总线有一个网络对上就算）；`bus`（`true`：只选总线，13.1；`false`：只选不是总线的导线，即网络槽位收到的是一个网络、不是集合） |
| SELECT-LABEL | 标签，即附着在对象上的 TEXT（13.3）。范围里给对象时，选附着在它们上面的标签 | `key`（文字的 key；收 `*`，区分大小写；没有 key 的标签对不上任何 `key=`） |
| SELECT-ANNOTATION | 标注，即场景里的图元和附着在点上的 TEXT（13.4） | 除 `role` 和 `recursive` 外没有别的条件 |
| SELECT-USAGE | `scope @SELECT-USAGE $D`：范围里定义 `$D` 的用例，往里找。给 `#` 时是本层的用例；给用例时是这些用例本身和它们里面的用例。不写 `$D` 时是任何定义的用例 | 定义是最后一个对象（5.6），可以省略。`symbol` 和 `drawn`（见下） |
| SELECT-ANCESTOR-USAGE | `objects @SELECT-ANCESTOR-USAGE $D`：把这些对象当成员的 `$D` 的用例，往外找；间接的成员也算 | 定义是最后一个对象（5.6），不能省略。除 `recursive` 外没有别的条件 |

除此之外，每个筛选关键字都收条件 `recursive`，前七个还收 `role`，它只在范围里有用例时才有意义（两者都见下）。

- **每种一个关键字。** 每个筛选关键字按它选出的种类命名，如某个网络的导线写 `&clk @SELECT-WIRE => @SET-STYLE $signal`，M1 的标签写 `#M1 @SELECT-LABEL`。没有一种筛选能选出所有种类的对象：要覆盖每一种，就每种写一条规则，标准包给每个对象配基础样式就是这样做的。
- **范围怎样走到要选的种类。** 范围里的每个对象朝要选的种类走一步；走不到的对象不选出东西，这不是错误：
  - SELECT-INSTANCE：元件就是它自己；端子走到所属的元件；网络走到在上面有端子的元件。
  - SELECT-TERMINAL：元件走到它的端子；网络走到接在上面的端子；端子就是它自己；引脚走到它绑定的端子。
  - SELECT-PIN：绘出对象（元件、叠画、有符号的用例）走到它自己符号里的引脚，写 `role` 时，用例改走去取填那个角色的引脚，与别的筛选取成员一样（见下）；没有符号的用例走到填它各个角色的引脚；端子走到绑定它的引脚；网络走到 `::net` 是它的引脚，包括绑定到由它所填角色的引脚；引脚就是它自己。范围给 `#` 时，是这一层的全部引脚。
  - SELECT-NET：网络就是它自己；元件走到它各个端子所在的网络；端子走到它所在的网络；导线走到它所在的网络。
  - SELECT-WIRE：网络走到画在上面的导线；导线就是它自己。SELECT-LABEL：对象走到附着在它上面的标签；标签就是它自己。SELECT-ANNOTATION 只取范围里的标注。
  - 经过端子的一步把每一个端子都算在内，不管有没有引脚：端子属于电路。画出来的部分通过引脚来选。所以 `&vss @SELECT-INSTANCE` 也会选到只在 vss 上接了衬底、而符号里没画衬底脚的 NMOS。本层的端口，如 `#:inp`，走到它的网络。
  - 以用例为范围时，只取要选种类的成员；成员不再当作范围（见下）。
  - 例：受时钟控制的管子是 `&clk @SELECT-INSTANCE`；只要栅极接 clk 的，是 `&clk @SELECT-TERMINAL(terminal="g") => @SELECT-INSTANCE`；M1 接的网络是 `#M1 @SELECT-NET`。
  - 注：给图上补地、导线、标签或样式的规则选的是引脚（SELECT-PIN），这样补上的东西才与画出的相合；检查电路的规则选的是端子。
- **按符号选：`symbol` 与 `drawn`。** SELECT-INSTANCE 和 SELECT-USAGE 收 `symbol="$X"`（字符串）：对象是用经由那个 `$` 名字给出的符号画出的，也就是指派它的 SET-SYMBOL 里写出的那个名字，按原文并支持通配符 `*` 来比，例如 `symbol="$IO_PORT*"`；经由 `%` 名字或匿名给出的符号对不上任何 `symbol=`。SET-SYMBOL 里写了 `$` 名字的代称时，按原名读（16.5），所以比的是原名；`symbol=` 里的字符串不做替换（16.5），直接写原名。与按名字解析到的定义来认的 SELECT-USAGE（9.5）不同，这里比的是名字；参数里只写字面量（3.7），所以像别的条件写名字一样写成字符串。这两个关键字还收 `drawn`（`true`：对象被画出来，符号由语句、规则、子电路符号或默认框图符号（9.2.6）给出；`false`：没有，如没有符号的用例）。每个元件都是画出的。这些条件读的是符号，所以在定好符号之后进行的生成规则和样式队列里都能用（8.2）；写在 SET-SYMBOL 的筛选里则是错误，因为符号队列不能按自己正在指派的符号来选。SELECT-PIN 同样读符号，有同样的限制；以引脚为范围、或经过引脚的筛选也是如此，如 `#R1::p @SELECT-TERMINAL`：写在 SET-SYMBOL 的筛选里是错误。用 `::` 写出的范围，若后面的名字不是对象的角色名、局部名或标准子对象名（如 `#X1::k`），也一样是错误：它是不是符号带来的引脚或文字的 key，要等定好符号才知道（6.5）。
- **只选本层，还是也到下层。** 每个筛选关键字都有条件 `recursive`，默认 `false`。规则在写它的那一层求值，能往下到达多远按下面决定；每次求值时，里面的每个筛选和每个集合都在那一层的环境里求值，只含那一层的成员（10.3）。
  - **直接写了筛选的规则**（无论写在自身、管道里还是写在它写出的 `{…}` 里），仅当这些筛选中有哪一个写了 `recursive=true` 时才到达下层；它用到的集合不改变这一点。所以 `# @SELECT-INSTANCE(recursive=true) => @SELECT-PIN(net="vss", wired=false) => $GROUND_STUB @ATTACH` 会在本层及下面每一层补地，而 `# @SELECT-NET(name="vdd") => @REMOVE-FROM $PORT_FILL_SET` 只作用于它自己这一层。
  - **没有直接写筛选的规则**（用的是依赖筛选的集合，10.4），如果它用到的集合里有一个到达下层，它就到达那下面每一层。一个集合到达它自己那一层，以及把筛选结果加进它的那些语句所能到达的各层：绑定给它的语句、它各项里的集合，以及往它里面添东西的 ADD-TO 语句；其中没有直接写筛选的 ADD-TO，到达深度算作它所添加的那个集合能到达的深度，不算它添往的集合的深度。在某个集合到不了的一层里，那个集合没有成员，即使使用它的规则到了那一层也一样。所以有了 `$GROUND_NET_SET = # @SELECT-NET(name="0", recursive=true)`，这个集合在每一层都含那一层的网络 0，`%g_set = {$GROUND_NET_SET}` 也到达同样远，而 `$IO_PORT @ATTACH $PORT_FILL_SET` 或 `$SUPPLY_NET_SET @REMOVE-FROM $PORT_FILL_SET` 会在这些集合到达的每一层里生效。
  - 单个宿主对象只是直接引用，如 `&vss`：宿主引用只在本层解析，由它们组成的集合（如 `{&vss}`）不到下层。
- **SELECT-USAGE 和 SELECT-ANCESTOR-USAGE。** 两个都按名字解析到的定义认定义（9.5），选出的总是用例，都没有 `role=`。
  - SELECT-USAGE 往里找，与别的筛选关键字一样。范围给 `#` 时，选求值那一层的用例；给用例或用例的集合时，选这些用例本身和它们里面的用例，一直到最里层。范围里的元件、网络和端子不是用例，选不出东西；这时给警告，提示要找它们所在的用例用 SELECT-ANCESTOR-USAGE。
  - SELECT-ANCESTOR-USAGE 往外找：选出把范围里的对象当成员的用例，直接的、间接的都算（见下例）。范围里的用例本身不算在内。范围写 `#` 是错误：一层不是任何东西的成员。
- **以用例为范围。** 以用例为范围时，别的筛选关键字选出这些用例里本种类的成员，`role=` 只取那个角色的成员。只在有符号且没写 `role` 的用例上 SELECT-PIN 不同，这时它给的是用例自己符号里的引脚（见上）。是用例的成员继续往里走，一直到最里层：

  ```rnl
  $OTA = @DEFINE(roles=[["pair", "usage"], ["load", "usage"]]) {};
  %dp1 = #M1(left) #M2(right) #M5(tail) @AS $DIFFERENTIAL_PAIR_N;
  %cm1 = #M3(ref) #M4(out) @AS $CURRENT_MIRROR_P;
  %ota1 = %dp1(pair) %cm1(load) @AS $OTA;
  %all_set = %ota1 @SELECT-INSTANCE;                 /* {#M1 #M2 #M5 #M3 #M4} */
  %pair_set = %ota1 @SELECT-INSTANCE(role="pair");   /* {#M1 #M2 #M5} */
  %up_set = #M1 @SELECT-ANCESTOR-USAGE $OTA          /* {%ota1} */
  ```

  - `role=` 的值也认这个用例的定义的 `definition=` 代称（16.5）。只要直接成员，就把角色当子对象用，如 `%dp1::tail`。遇到已经走过的用例就停。成员指填进角色的对象，不含体里的局部对象（9.4）。
  - **只取本种类的成员。** 成员不再当作范围往下走，别的种类的成员不算。SELECT-TERMINAL 只取端子成员：`$GROUND @ATTACH &0; $CURRENT_ARROW @ATTACH #M5:1` 之后，`# @SELECT-USAGE => @SELECT-TERMINAL` 只是 {#M5:1}，不含网络 0 上的其他端子。差分对 %dp1 的成员是元件，所以 `%dp1 @SELECT-TERMINAL` 是空集合。要成员元件的端子，写 `%dp1 @SELECT-INSTANCE => @SELECT-TERMINAL(terminal=2)`（三个管子的栅极，尾管也在内）；要成员网络上的端子，写 `… => @SELECT-NET => @SELECT-TERMINAL`。每一段只做一件事；要往下走，就多写一段。范围里直接给的对象照前面的规则：网络给出它上面的端子，元件给出它的端子。
  - **经转换填上的角色**（5.2.4），例如种类为 `"pin"` 的角色收到端子时，在定好符号前存着原样写出的对象，定好符号后存着转换后的对象。所以在生成规则及更后的步骤里，无论那个角色当时收到的是按名字写的引脚还是代表它的端子，`@SELECT-PIN(role="t")` 都能选中那个引脚。
- 在场景里按条件找对象，一律用筛选关键字；`::` 只取对象自身的部分（6.5）。
- **叠画。** 叠画的成员选不到，选到的是叠画（11.8）。SELECT-INSTANCE 按叠画第一个成员的条件选到叠画本身，每个叠画只算一次。SELECT-TERMINAL 选到叠画的端子，`net=` 对上其中任何一个成员的网络就算对上。
- **条件**写名字，形如 `name=value`；写出的条件都满足时才选中。要"或"，就写几条规则。比较名字的条件（`name`、`model`、`net`）收通配符 `*`，它匹配任意多个字符，与 DEVICE 一样按宿主的大小写规则比较（6.12）。按元件字母选，写 `name="R*"`。Spectre 的元件名不以元件字母开头，按 `model` 选，如 `model="resistor"`（6.12）。
- **`model`** 比较元件行上写在模型位置的名字：M、Q、D 等元件是 `.model` 名；X 元件是子电路名，包括网表里没有定义的 PDK 器件，如 `# @SELECT-INSTANCE(model="sky130_fd_pr__nfet_01v8")`；Spectre 里是 master。它与 DEVICE 的 `model=` 相同（6.12）。`type` 比较元件的类型：它的 `.model` 的类型，或者对于宿主没给类型的元件（如 X 元件），DEVICE 给出的类型（6.12）；两者都没有时，元件没有类型，匹配不上任何 `type=`。`type` 与比较名字的条件一样收通配符 `*`：`type="*mos"` 匹配 nmos 和 pmos 这两种类型，`type="*"` 选出有类型（不管是哪一种）的元件，规则和断言正是靠这样避开类型未知的器件。
- **`terminals`** 比较元件的端子数，是一个整数：宿主在它的行上读出的结点个数，编号 1、2、…（6.12），不管 DEVICE 给它们起了多少名字。所以 `terminals=3` 选中 `Q1 c b e qn`，不选 `Q2 c b e s qn`。对 X 元件，数的是它那一行上的结点个数，即子电路的端口数；在 Spectre 里是括号里的结点个数，所以 `S1 (com t1 t2) switch` 是 3 个。它照样能与别的条件并用，如 `# @SELECT-INSTANCE(type="nmos", terminals=4) => @SET-SYMBOL $NMOS_4TERM`；叠画按它的第一个成员算（11.8）。
- 比较照 3.6：条件名和标准的枚举值区分大小写；指宿主东西的值（名字、模型名、网络名）按宿主的规则。
- 网络可以按名字选：`# @SELECT-NET(name="0")` 选这个网络，`# @SELECT-TERMINAL(net="0")` 选接在它上面的端子。对象也可以按语义选：`# @SELECT-USAGE $DIFFERENTIAL_PAIR_N => @SELECT-INSTANCE(role="left")` 选出每个差分对的左管。
- 没有求交集的关键字，如求一个集合里属于某个用例的成员；用两次 REMOVE-FROM 写（5.2.2）：

  ```rnl
  %s_set = {#M1 #M3 #M5};
  %s_set @SELECT-ANCESTOR-USAGE $DIFFERENTIAL_PAIR_N => @SELECT-INSTANCE => %dp_m_set;
  %out_set = {%s_set};
  %dp_m_set @REMOVE-FROM %out_set;    /* the members of %s_set in no differential pair */
  %in_set = {%s_set};
  %out_set @REMOVE-FROM %in_set       /* the members of %s_set in a differential pair */
  ```

- **地和电源网络**由标准包提供的集合给出：`$GROUND_NET_SET`（默认是网络 0）和 `$SUPPLY_NET_SET`（默认为空）。没有网络类别。
  - 包里不能写宿主引用（16.2），所以这种集合的默认内容只能写成筛选，如 `# @SELECT-NET(name="0", recursive=true)`。
  - 用户用 ADD-TO 和 REMOVE-FROM 增删网络：

    ```rnl
    &vss @ADD-TO $GROUND_NET_SET;                                       /* the vss of this level */
    # @SELECT-NET(name="vss", recursive=true) => @ADD-TO $GROUND_NET_SET;   /* the nets named vss of every level */
    # @SELECT-NET(name="vdd!", global=true, recursive=true) => @ADD-TO $SUPPLY_NET_SET  /* only the global vdd! */
    ```

    第二条语句也会加上子电路里叫 vss 的局部网络。只在某处不算某个网络，就复制一份集合，再从副本里删掉它：`%g_set = {$GROUND_NET_SET}; &vss2 @REMOVE-FROM %g_set`。
  - 补位规则用这样的集合作范围，如 `$GROUND_NET_SET @SELECT-PIN(wired=false, recursive=true) => $GROUND_STUB @ATTACH`，它也会选中虚拟元件在这些网络上的引脚；标准包随后去掉它自己所放元件的引脚，例如地符号的引脚。
  - 在自己的层里写 `$GROUND_NET_SET = …` 会遮蔽包里的集合，包里的规则看不到新的这个（6.8）。
  - 不按网络名猜哪些是地和电源。导入器把编辑器文件里网络的电源域（如 `powerDomain`）写成 ADD-TO。
  - 求解器可以把标准集合当提示读（如电源在上、地在下），与它可以读标准包里的定义一样；这不作要求。
  - 注：地和电源网络没有关键字（1.5 第 7 条）：这些集合的用处，如选引脚补地、换符号，都能写成包里的规则。
- **空节点**（6.3）不是网络：SELECT-NET 从不选出它，上面的引脚只能通过它的对象或 `#` 被 SELECT-PIN 选中（不能经网络或 `net=`），上面的导线只能通过不写 `net=` 的 SELECT-WIRE 选中。
- **全局网络。** SELECT-NET 的条件 `global=true` 只选全局网络（6.3）。不同层里同名的局部网络是不同的结点，按名字选会都选上；只要全局的那一个，就加这个条件。

### 10.2 条件 `wired`

- 当一个引脚既不是任何显式导线上的点（端点或中间点；写到端子的导线终结在该端子的引脚上，5.2.4），也不在任何 ROUTE-NET 或 ROUTE-OBJECT 的布线树（13.7）里（因为布线树的导线由求解器画出）时，它是 `wired=false`。总线引脚是一个引脚，经由它任何一个端子有导线终结在它上面时都算已接线（9.2.4）。总线导线也是显式导线（13.1）。导线接到叠画的端子，就是接了每个成员的这个端子（11.8）。
- 接在网络上的宿主元件的端子都没被显式导线接触，且网络上没有 ROUTE-NET 或 ROUTE-OBJECT 的布线树时，网络是 `wired=false`；虚拟元件的引脚不算。
- 哪些引脚在布线树里，在 8.2 的两个阶段定下。第 4 步之后、符号定好时，先按第 3 步的语句定下：在第 5 步求值的 ROUTE-NET、ROUTE-OBJECT、UNROUTE-NET、UNROUTE-OBJECT 规则（10.4）读这些布线树，例如 `{&a &b} @SELECT-NET(wired=false) => @ROUTE-NET`，而且它们彼此看不见对方，因此一条规则从不读它自己造出的树。第 5 步之后，加上这些规则造出和改动的树：第 6 步及之后步骤的条件读这时的状态。因此生成规则（如标准包的补位，16.3）把被 ROUTE 规则连上的引脚算作已接线，把被 UNROUTE 规则拿出的引脚算作未接线（除非有显式写出的导线碰着它）。第 6 步生成的内容（如生成的用例体）里的布线语句也会造出和改动布线树，但没有条件会去读它们。
- 写在空节点上的导线（13.1）与别的导线一样计数：它终结在其上的引脚算已接线。
- 只算显式写出的导线，不算生成的。有没有虚拟元件没有影响。
- 导线按写出的样子算，从 8.2 第 3 步起就算数，后来因为端子没有引脚而失效的也算（7.1、9.2.4）。导线被改写过的，算最后那次改写（13.1）。

### 10.3 筛选的求值

- 筛选不在写它的地方展开，每次求值只看一层。规则（10.4）在写它的那一层求一次，在它到达的下面每一层各求一次（10.1）；每次求值时 `#` 就是那一层，筛选只选这一层的对象。所以顶层写的 `# @SELECT-INSTANCE(model="nch", recursive=true) => @ALIGN("y")` 在每张图里各对齐一次，不会把不同图里的元件放在一起对齐。
- 筛选在用到它的阶段求值：外观规则在符号队列和样式队列里，布线关键字的规则在第 5 步，生成规则在生成阶段（8.2）。集合也一样（5.2）。
- 筛选选出的种类在读入时就知道。把它交给收不了这种对象的槽位，当即是错误，放在集合里也一样，如 `# @SELECT-TERMINAL(net="vss") => @SET-SYMBOL $NMOS`。
- SELECT-USAGE 和 SELECT-ANCESTOR-USAGE 选出的总是用例；从用例走到成员时，选出的种类由关键字决定。所以每个筛选选出的种类都在读入时就知道。
- 筛选的结果是集合，可以用 `%` 或 `$` 命名。集合在某层求值时只取这一层的成员：顶层写的 `&vss @ADD-TO $GROUND_NET_SET` 只加顶层的 vss，集合在子电路里求值时不含它（6.6）。
- **结果的次序。** 筛选的结果中各成员按下面的次序排列，凡是集合次序起作用的地方都照这个次序，如 ORDER、DISTRIBUTE、TABLE、LINE，以及逐个套用的规则的结果（5.2.1）：
  - 以 `#` 为范围时，按这一层在场景里的次序：
    - 元件按它们在网表中的行序，叠画排在它第一个成员的行位置；端子先按元件或叠画、再按序号；
    - 网络先是这一层的端口、按子电路行上的顺次，然后是其余网络按在元件行上首次出现的先后；
    - 引脚先按所属对象——先是按行序排的元件和叠画（叠画排在第一个成员的行位置），再是按自身次序排的用例——在一个对象之内按它符号里的 PIN 语句顺次；
    - 用例、导线、文字和图元：先是 8.2 第 3 步创建的，按位置次序（8.5），用例体里创建的紧跟在这个用例之后、按体里的顺次；再是后面各步创建的，一步接一步。在同一步之内，按创建它们的语句或规则的位置先后，同一条规则的几个结果按它输入的顺次（5.2.1）；符号带来的文字按所属对象（顺序同上面引脚的对象顺序）、再按符号里的先后。场景里按 key 覆盖符号中文字的那段文字（13.3）算一段文字，位置在第一次写出它的语句处。
  - 以别的作范围时，范围里的每个成员依次按上述次序给出各自的结果，已经给过的对象不再重给。这对每个筛选关键字都成立，包括 SELECT-ANCESTOR-USAGE。
  - 集合保持成员写入和加入的次序（5.2、5.2.2）：ADD-TO 在末尾追加并保留重复，UNION 去重。
- 筛选的范围写成本层的宿主对象时，如顶层的 `&Q<0:3:2, 1> @SELECT-TERMINAL(name="R*", recursive=true) => @TEXT("${net}", key="netname")`，规则在下层求值时这些对象不存在：筛选在那里为空，什么也不做，不给警告，正如集合只取这一层的成员。10.5 的警告只针对生成规则的其余角色。

### 10.4 规则

- 直接或通过依赖筛选的集合来接收筛选结果的语句是规则。一个集合如果绑定给一个筛选、它的项里有筛选或这种集合、由这种集合经 UNION 造出，或被 ADD-TO、REMOVE-FROM 用筛选结果或这种集合改过（5.2.2），就依赖筛选：它的成员要到用到它的阶段才知道。在用例的定义体里，集合角色在填它的东西依赖筛选时也算依赖筛选。
- 除了 BUNDLE（11.8）、WIRE（13.1）以及两点写法的 RECTANGLE、CIRCLE、ELLIPSE（9.2.5），任何关键字都能收筛选的结果，按 5.2.1 的规定逐个做或整个收：`# @SELECT-INSTANCE(type="nmos") => @ORIENT("MY")`、`# @SELECT-INSTANCE(model="nch") => @ALIGN("y")`。
- 以筛选的结果为对象的 SET-SYMBOL 和 SET-STYLE 是外观规则，进外观队列（8.3）。AS 和 ATTACH 是生成规则（10.5）；附着在筛选结果上的 TEXT（13.3）、点为筛选结果且按尺寸写出的 RECTANGLE、CIRCLE、ELLIPSE（9.2.5），以及造出绘出对象的 LINE、ARC、BEZIER 规则也是生成规则——后三者的槽位收集合，所以这样的一条规则按次序穿过整个结果画出一条图形（5.2.1、10.3）。在它们之前，在第 5 步求值的是 ROUTE-NET、ROUTE-OBJECT、UNROUTE-NET 和 UNROUTE-OBJECT 规则：它们的条件读第 3 步语句构成的布线树，而生成规则看得到它们造出的树（10.2）。CURRENT 规则与生成规则一起在第 6 步求值；它们合起来是第 6 步的规则：电流方向由第 3 步的语句定下，第 6 步的条件看不到这些规则改了什么（15.2）。BUNDLE 不收筛选的结果：叠画在定符号前就要存在（11.8）。其余关键字的规则（如约束、PLACE、ORIENT）在各自关键字的那一步生效，看得到生成的对象；对这些关键字，一条规则就等同于给选出的每个对象（或全体一起）写了一句，并在该关键字的阶段生效。
- 规则作用于写它的层，以及通过里面写的筛选上的 `recursive=true`、或（没有直接写筛选时）通过用到的集合到达的下面各层（10.1），在每一层各求一次，只看那一层（10.3）；包里的规则算作写在它的 USE-PACKAGE 那一层，根上的包算作写在文件的顶层（16.2），因此只按 10.1 的规定到达下层，标准包才在筛选里写 `recursive=true`。普通定义体里的规则算作写在用例所在层（9.4）。
- **到达下层的规则里写了本层的宿主对象**：规则到达下层而别的槽位写了本层的宿主对象，如 `%clk_set = {#VP1 #VP2}` 且 `%rest_set` 绑定了带 `recursive=true` 的筛选时写 `%clk_set %rest_set @DISTANCE("bottom-to-top", min=3)`，下层没有这些对象：这条语句在下层不起作用，不给警告。只有生成规则按 10.5 给警告。

### 10.5 逐个生成

"对所有没接导线的 vss 引脚，各放一个地并用导线接上"：

```rnl
$GROUND_STUB = @DEFINE(roles=[["t", "pin"]], parameters=[["gap", 2]]) {
  %g = $GROUND @ATTACH ?t::net;
  ?t::net @WIRE {?t %g::pin};
  {?t %g::pin} @ALIGN("x");
  %g::pin ?t @DISTANCE("bottom-to-top", exact=?gap)
};
# @SELECT-INSTANCE => @SELECT-PIN(net="vss", wired=false) => $GROUND_STUB @ATTACH => %stubs_set
```

标准包提供一个这样的 `$GROUND_STUB`，只是它的 gap 默认是 1，且只给最小距离（`min=?gap`），求解器可以把导线画得更长，如把长短不同的元件的地排齐；它还让地朝下（`@ORIENT("R0")`），约束的优先级都是 `"low"`；这里的定义遮蔽了它（6.8）。

- AS 或 ATTACH 的单个角色收到筛选的结果时，对选中的每个对象各套用一次定义，其余角色在每次套用中都相同（5.2.1、9.4）。集合角色把筛选的结果整个收下，定义只套用一次；当它的角色全是集合角色时，只在其中某个角色里有东西的层里套用（9.4）。
- 虚拟元件也这样逐个创建：`# @SELECT-NET(port=true) => $IO_PORT @ATTACH` 给每个端口网络一个端口标签；`$RLOAD` 是一个画成电阻的两角色定义，`# @SELECT-NET(name="out*", recursive=true) => $RLOAD @ATTACH &vss` 在每个选中的网络与 vss 之间接一个；因为 `&vss` 属于本层，这条规则只在本层生效，并给下面说的警告。
- 标准包的补位用带导线的定义补地和电源（`$GROUND_STUB`、`$SUPPLY_STUB`）：写回以后，导线让引脚不再是 `wired=false`，补位就跳过它。只靠约束放到引脚上的地因为没有导线，引脚仍是 `wired=false`，补位仍会加一个；两个引脚之间连一条长度为 0 的导线（13.1）能让引脚算作已接线。
- 配对在每次套用的内部：定义的局部名每次套用都是新的，所以一次套用里的 `%g` 就是这次套用建的那个地。
- 结果是一个生成集。它可以命名，可以整个交给 SET-SYMBOL 或 SET-STYLE（如 `%stubs_set @SET-STYLE $grey`），但不能引用其中单个成员（5.7）。
- **手写一个。** 要单独描述其中某一个，就手动创建它并接上线。它的引脚就不再是 `wired=false`，补位跳过它。没有另外取消生成的办法。
- **快照。** 所有生成规则看同一个快照，即 8.2 第 3 到第 5 步的结果（按键覆盖之后，含全部对象的符号和第 5 步的布线树），彼此看不到对方的结果。所以同一条规则写两次，就生成两份。
- 生成的事实在冲突取舍时取生成规则的位置（8.5）。
- 生成的对象没有位置时由求解器摆放；要说明怎样摆，就用带约束的定义。
- **写回。** 单个生成的对象不能被引用（5.7）。求解器写回它们时，写成显式的语句，如 `$IO_PORT @ATTACH &out => @PLACE(40, 20) => %p_out`，加上接到它的导线。只有规则把已经写出的去掉时，显式的对象才取代生成的对象，标准包的补位就是这样，它只选没有导线的引脚（10.1），按网络补位时则写两个集合的差集（见下）；别的写法的规则会在显式对象旁边再生成一个，没有位置。所以要由求解器摆放其对象的规则，建议按这两种方式之一去掉已经写出的。这样写出的显式用例，定义体里没有局部名字的对象用编号引用（5.9）。写出的用例照原样带上规则在套用上明写的优先级，或者它从规则所在记录的记录头继承的 `"disabled"`（14.8）；此外什么都不写，它的体保持原来的优先级，记录头别的优先级不写。
- 生成不递归：生成规则展开出的内容里有第 5 步或第 6 步的规则时（10.4），这些规则失效，因为这两步各只走一次。其余规则照常在后续步骤生效：SET-SYMBOL 在第 7 步的符号队列；PLACE、ORIENT、LAYER、PRIORITY 和约束在第 8 步，使生成的用例的定义体可以放置和定向它角色收到的对象；SET-STYLE 在样式队列；断言在检查时（8.2、15.3）。
- 到达下层的生成规则（10.1）里，其余角色填的是本层的对象（场景对象或宿主对象）时，规则只在写它的那一层生效，并给警告：这些对象属于那一层，下层没有。填定义的角色没有这个限制。
- 生成产生的 SET-SYMBOL 或 SET-STYLE 归入产生它的规则所在的组，位置取规则的位置（8.3）。
- 绑定到筛选或生成集的名字不能重新绑定（6.6）。
- **按网络补位。** 没有内置的"已有就不补"规则。补位写两个集合的差集；要补端口标签的包写的是：

  ```rnl
  $PORT_FILL_SET = # @SELECT-NET(port=true, recursive=true);                                /* the nets that get a port tag */
  # @SELECT-USAGE(recursive=true) $IO_PORT => @SELECT-NET => @REMOVE-FROM $PORT_FILL_SET;   /* less those that have one */
  $IO_PORT @ATTACH $PORT_FILL_SET
  ```

  - 标准系列 0.4 的补位就是这样写的，集合在 `rnl-std-basic` 里；它还把每一层级的端口标签放在同一列（12.4）。它让电源网络和地网络留在集合里；不想在短桩处放端口标签的文件，写 `$SUPPLY_NET_SET @REMOVE-FROM $PORT_FILL_SET; $GROUND_NET_SET @REMOVE-FROM $PORT_FILL_SET`。
  - 手写的端口标签会取代生成的端口标签：在 `$IO_PORT @ATTACH &inp => @PLACE(0, 20) => %p` 之后，inp 不会再得到生成的端口标签。用户也可以把网络从 `$PORT_FILL_SET` 里去掉（如 `# @SELECT-NET(name="vdd") => @REMOVE-FROM $PORT_FILL_SET`），或者把自己的端口定义的用例也算上去（`# @SELECT-USAGE $MY_PORT => @SELECT-NET => @REMOVE-FROM $PORT_FILL_SET`）。
  - 生成的端口标签不算在内：生成规则在第 6 步用到 `$PORT_FILL_SET`，差集里的筛选按第 6 步之前的状态求值（5.2）。
  - 注：不内置"已有就不补"，是因为有多个角色的定义说不清什么算"已有"，用户自己的端口定义也算不上，而且重复的布局定义只是重复约束，冲突取舍和优先级本来就会处理（8.5、14.8）。
- 按端子补位时，取代生成对象的仍然是手写对象的导线：有了导线的引脚就不再是 `wired=false`。仍然没有办法单独取消一次生成：从集合里去掉一个网络只改变集合。
