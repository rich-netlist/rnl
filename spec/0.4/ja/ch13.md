## 13 配線とテキスト

### 13.1 配線：WIRE

```rnl id=w13
&x @WIRE(mode="straight") {#M1:1 (10, 37) #M3:1} => @SET-STYLE $signal => %w13;
&out @WIRE(mode="manhattan") {#M2:1 #M4:1};
&tail @WIRE {#M1:3 #M5:1}                    /* no mode: "auto", routed freely */
```

- WIREは1つのネット（またはバスを作るネットのセット；下記）と、2点以上の順序付き点リストを受け取る。点とは点オブジェクトまたはピン（仮想部品のピンを含む）であり、端子はそのピンを表す（5.2.4）。点は重複してもよい。最初と最後の点が同じであるとき、その配線はループとなる。
- WIREは選択の結果、またはそれに依存するセットをとらない（10.4）：それらを渡すと失敗する。配線はソルバーによってその折れ曲がり点とともにその配線として書き戻される（14.8）が、選択から作られた配線には書き戻し先が存在しないためである。選択のピンを配線として描画するにはROUTE-OBJECTを用いる（13.7）。
- **配線モード**：配線はリストのすべての点を通過する。隣接する2点間をどのように結ぶかはパラメータ `mode=` で指定する。隣接する点 A(x1, y1) と B(x2, y2) に対し、dx = x2 − x1、dy = y2 − y1 とするとき：

  | `mode` | AからBへ |
  |---|---|
  | `"auto"`（デフォルト） | ソルバーが決定する。ソルバーは状況に応じて最適化し、その経路を書き戻す（下記、14.8）。求解前の配線は下記のデフォルト経路で描画され、妨げるものがない場合にソルバーが与える経路もこれと同じである |
  | `"straight"` | 1本の直線分 |
  | `"horizontal-vertical"` | A → (x2, y1) → B |
  | `"vertical-horizontal"` | A → (x1, y2) → B |
  | `"manhattan"` | \|dx\| ≥ \|dy\| のとき：dxの半分を水平に進み、dyの全体を上下に進み、残りの半分を水平に進む（A → (x1 + dx/2, y1) → (x1 + dx/2, y2) → B）。それ以外のときはxとyを入れ替えて同様 |
  | `"manhattan45"` | \|dx\| ≥ \|dy\| のとき：(\|dx\| − \|dy\|)/2 を水平に進み、次に45°の斜線（各軸方向に \|dy\|）、次に残りを水平に進む。それ以外のときはxとyを入れ替えて同様 |

  - `"auto"` 以外のすべてのモードは厳密な規則であり、ビューアは定義どおりに描画する。dxまたはdyが0のときは、どのモードでも1本の直線分となる。|dx| = |dy| のとき、`"manhattan"` は |dx| ≥ |dy| の場合をとり、`"manhattan45"` は1本の斜め線分となる。モードが計算した折れ曲がり点は正確な値を保ち、丸められることはない。0.5単位上に落ちる場合もある（11.7）。
  - **`"auto"` のデフォルト経路**：隣接する2点間の各区間は水平および垂直に走る。向きを持つピン（9.2.4；オブジェクトの向きを適用した後）である端点は有向である：区間はその向きに沿って（またはそれに直角に）ピンから出て、その向きに逆らって（またはそれに直角に）ピンへ入り、それとは逆の向きでは出入りしない。直角に出入りすることは折れ曲がり点として数えられる。向きを持たないピンと点は無向であり、何も制約しない。区間はその両端のいずれの点も通過せず、自身と重ならない。これらを満たす経路のうち、デフォルトとなるのは折れ曲がり点が最も少ないもの、次に最も短いもの（戻るためだけに外へ出る1辺の長さは1とする）、次に有向の端点で曲がる数がより少ないもの（最後の端点の向きより先頭の端点の向きを保つ）、次に `"manhattan"` と同様に中間区間が両端の中央にあるもの、無向の2端点間では先に水平へ進むもの（1回折れるL字）であり、迂回は最初の有向端点の左側（その向きを反時計回りに90度回した方向）へ回る。中間に点を持つ配線は全体として選ばれる：中間点は無向であり、中間点での曲がりは折れ曲がり点として数えられ、配線は中間点で折り返してはならないため、可能な箇所では中間点を直進する。その折れ曲がり点も正確な値を保ち、0.5単位上に落ちることがある（11.7）。例えば中間区間が1単位離れた2つの端点の中央にある場合である。
  - モードによって追加された折れ曲がり点はオブジェクトではない：参照することはできず、そこに接続点の黒丸を置くこともできない。折れ曲がり点で分岐したりそこに黒丸を描いたりするには、その折れ曲がり点を点として記述する。自由な点 `(_, _)` は最初にソルバーから座標を得て、その後モードに従って接続される。
  - 表にない `mode` 値は不正なパラメータ値であり、その配線は失敗する。
- **スタイルパラメータ**：WIREは線のスタイルプロパティ `linecolor`、`linestyle`、`linewidth`、`cap`、`join` もパラメータとしてとる（9.3）。これらは配線の直接スタイルとなり（8.3）、電源レール用の `@WIRE(linestyle="bold")` や基板接続用の `@WIRE(linestyle="dashed")` のように用いる。
- **配線の書き換え。** ネットの代わりに配線を与えると、WIREは新しい配線を作らず、その配線を書き換える。文は新しいWIREと同様に読み取られ、その点リストとモードがその配線の点リストとモードを置き換える。配線のネットは維持される。スタイルパラメータは配線の直接スタイルとなる（8.3）。
  - 書き換えはその配線をkeyとする：後のものが前のもののリストとモードを置き換える（8.4）。1つのパイプの2つのセグメントのうちでは、後のセグメントが後のものとなる（5.5）。すべての書き換えのスタイルパラメータは配線の直接スタイルとして残り、8.3によってプロパティごとに解決される。書き換えは幾何的事実ではない（8.5）。
  - ピンのない端子を列挙する（9.2.4）などして失敗した書き換えはエラーとなり、スタイルパラメータを含めて効力を持たない。その配線は以前のリストとモード（以前の書き換え、または作成時のもの；5.8）を保持する。失敗した各書き換えは、後の書き換えがそれを置き換える場合であっても報告される。
  - 新しい配線と同様に、書き換えは8.2のステップ3から数えられる：`wired=`（10.2）は、後のステップ7以降に失敗する書き換えであっても、最後の書き換えの点を読み取る（7.1）。
  - netスロットはネット、ネットのセット、または1本の配線をとる。配線を含むセットは種別の誤りである。
  - ソルバーは各 `"auto"` 配線に対して選択した経路をこの方法で書き戻す（14.8）。ソルバーは作成者のレコードにある配線が（最後の書き換え後に）持つ点を順序どおり保持し、その間に座標として書かれた折れ曲がり点のみを追加し、`mode="straight"` を書くべきである：配線の接続は作成者が書くものであり、ソルバーはその形状のみを決定する。
  - **配線の分割。** ROUTE-NETまたはROUTE-OBJECTのツリーが結ぶネット上では（13.7）、ソルバーは作成者が書いた配線の途中から分岐させてもよい。その場合、ソルバーは自身のレコード内で名前または番号（5.9）によってその配線を書き換え、作成者の点を順序どおり保持したまま分岐点を独立した点としてその間に挿入し、分岐をそこに接続する。それ以外の配線については上項目で述べた変更のみを行う。これは削除ではなく書き換えであり、作成者の文はそのまま残る。
  - ユーザーが配線を整形するエディタも自身のレコードに同様に書き出し、ソルバーはその書き換えられたとおりに配線を保持する。
  - 文自体の中で経路を固定するには、折れ曲がり点を点として記述し、`"auto"` 以外のモードを使用する。正確な形状を保持するエクスポータは `mode="straight"` と書いてすべての折れ曲がり点を列挙する。
- **1つのネット上の複数の端子**（原則 2.6）は、点を共有する複数の配線によって接続される。配線同士が接続されるのは同じ点オブジェクト（名前付きの点）または同じ端子を共有するときのみであり、座標が等しいだけでは接続されない（原則 2.2）。ツリーを記述する文はなく、グラフオブジェクトも存在しない。
- **T字分岐**：貫通する配線は分岐点を自身の中間点の1つとして列挙すればよく、2つに分割する必要はない。分岐はその点から始まる（13.2の例を参照）。「配線の線分上の点」という概念はない。
- **接触するピン**：2つのピンが同じ点に描かれ間に配線がない場合でも、キャパシタのピン上に直接描かれたグラウンドシンボルの場合のように2つの端子を接続するために配線を記述する（`&0 @WIRE(mode="straight") {#C1:2 %g3::pin}`）。両端が一致し長さが0であるため何も描画されないが、接続を表明する：両方のピンが配線済みとなり（10.2）、標準パッケージが別のグラウンドを追加しない。座標が等しいだけでは接続にならない（原則 2.2）。ピン同士が位置で接続する回路図を変換するエクスポータはそのような配線を書き出し、配線がピンや接続点の黒丸を直進する箇所ではその点を中間点として列挙し（T字分岐）、接続点の黒丸に配線が1本しかなくピン上に直接重なっている箇所では配線をその端子に直接接続する。
- **ネットは明示されるのみ**であり、必ず記述しなければならない。端点が実際に属するネットがそれと一致する必要はなく、その検査も行われない（原則 2.2）。ネットが端点から導出されることもなく、両端点が異なるネット上にあってもよい。
  - リスト内の端子またはピンがその配線のネット上にない場合（バス配線の場合はそのネットのセットに含まれない場合）、警告が出される：`#R1:2` のつもりが `#R1:1` になったような端子の誤記である可能性が高い。端子またはピンのネットは既知である（仮想部品のピンは、それが束縛するロールを埋めるネット上にある；12.1）。点、および何も束縛しないピンはネットを持たず、検査されない。配線自体は妥当であり描画される（原則 2.2、7.6）。
- **ネットのない配線**：netスロットは `& @WIRE {%sub1::y %int1::a}` のように空ノードもとる（6.3）。その配線は他の配線と同様に描画・求解され、終端するピンは配線済みとなる（10.2）が、どのネットにも属さない：点を共有する2本のそのような配線は結ばれて描かれても1つのネットにはならず、ROUTE-NETやROUTE-OBJECTのどのツリーにも取り込まれず、配線の `${net}` は空テキストとなる。そのリスト内にあるネット上の端子やピンは上記の警告を出し、あるネットの配線のリスト内にある空ノード上のピンも同様に警告を出す：回路に存在しない接続を図面が示すことになるためである。空ノードはバスのセットの項目にはなれない。
- **バス**：netスロットは1つのネット、または全体としてのネットのセットをとる。セットが与えられた場合、そのセットのメンバーが1つであってもその配線はバス配線となる。ネットリスト自体にバスはなく（6.11）、バスは複数のネットを1本の線として描画する方法にすぎない。

  ```spice
  * A 4-bit bus between two blocks, with two taps
  * @RNL(type="header") { @VERSION("0.4"); @USE-PACKAGE(name="rnl-std-all", version="0.4")}
  .subckt blk D<3> D<2> D<1> D<0>
  RL D<3> D<0> 1k
  * @RNL {
  *   $BLK_SYM = @DEFINE-SYMBOL {
  *     (-3, 0) @PIN(terminal=["D<3>", "D<2>", "D<1>", "D<0>"], label="D<3:0>", direction="left");
  *     @RECTANGLE {(-3, -2) (3, 2)}
  *   };
  *   # @SET-SYMBOL $BLK_SYM                                             /* one bus pin for four ports (9.2.4) */
  * }
  .ends blk
  XA D<3> D<2> D<1> D<0> blk
  XB D<3> D<2> D<1> D<0> blk
  RT3 D<3> 0 1k
  RT2 D<2> 0 1k
  * @RNL {
  *   %t3 = (20, 10); %t2 = (24, 10);
  *   %bus = &D<3:0> @WIRE(linestyle="bold") {#XA:D<3> %t3 %t2 #XB:D<3>};   /* a bus between the bus pins of XA and XB */
  *   %bus @TEXT("D<3:0>");                                                /* the name of the bus, written out */
  *   &D<3> @WIRE {%t3 #RT3:1};                                            /* a tap: a single wire that shares %t3 with the bus */
  *   &D<2> @WIRE(mode="straight") {#RT2:1 (23, 9) %t2}                    /* its last stretch enters the bus at 45° */
  * }
  .end
  ```

  - セットの順序はビットの順序であり、重複は保持される。セットの中に直接書かれたセットは、最も内側のメンバーまで順に展開される。ネットでないメンバーがあると配線は失敗する（種別の誤り）。空のセットも失敗する：配線は少なくとも1つのネットを担う（5.2.1）。
  - netスロットは厳格である（7.3）：単一のネットが見つからないときと同様に、1つのビットでも見つからなければ配線全体が失敗する。
  - 点、`mode=`、スタイルパラメータ、接続点の黒丸、T字分岐は他の配線と同じである。BUSキーワードは存在しない：実装は配線を描くのと同様にバスを描き、太線で描くことはスタイルの問題である（1.5項目7）。インポータが `linestyle="bold"` を直接書き出してもよく、標準パッケージはSELECT-WIREの条件 `bus=true` を用いてデフォルトでバス配線を太線にする（10.1、16.3）。
  - **タップ**に仕組みは不要である：バスと点を共有する単一の配線がタップであり、バスはそのタップ点を中間点として列挙する（T字分岐）。バスへ入る短い45°の区間は単一の配線の最後の区間がそう走るだけである。タップシンボルはタップ点に適用される定義であり、標準パッケージに属する（16.3）。ビットの名前は単一の配線上のラベル `${net}` である（13.3）。単一の配線のネットがバスに含まれるかは検査されない（原則 2.2）が、実装はヒントを出してもよい。
  - タップはバスの端から始めることもできる：ある点で終わるバスは、その点から始まる複数のバスや単一の配線として先へ続くことができる（幹線 `BOT<10:0>` が終わった点から `BOT<10:3>` と `BOT<2:0>` が分岐し、そこに接続点の黒丸があるなど；13.2）。幹線はその点を端点として列挙し、各枝が自身のビットをとる。それらのネットすべてを担う配線（ここでは幹線）が通過または終端する1つの点から始まる配線同士は、その配線のタップであって互いに結合してはいない：ある配線が別ネットの配線上で終わる場合に結合しているかのように警告を出す実装は、これらについて警告を出さない。
  - バス配線の属性 `net` はそのネットの名前を順に `,`（空白なし）で連結したものである（`D<3>,D<2>,D<1>,D<0>` など）。`D<3:0>` を表示するにはそのテキストを書く。実装はリストを短縮しない：短縮方法はホストが名前をどう記述するかに依存し、一意な結果にならないためである。
  - したがって `{&a &b} @WIRE {…}` は重なった2本の配線ではなく1本のバス配線である。
  - 1つとして描画される複数のホストインスタンス（反復インスタンス）はバンドルとして記述される（11.8）。
- 配線が接続する端子はそのシンボル内にピンを持たなければならない。さもなければ配線は失敗する（9.2.4）。
- 接する、交差する、または重なる線分は幾何形状にすぎず、接続を作らない（原則 2.2）。点を共有せずに交差する配線には黒丸が付かない。交差箇所に小さな弧を描くなどはスタイルと実装の問題である。
- ネットが与えられた各WIREはkeyを持たない新しいオブジェクトであり、2度書けば2本の配線となる（5.8）。別の文からある配線を参照するにはそれに名前を付ける。ソルバーのレコードは名前のない配線を番号で参照する（5.9）。端子である端点は素子とともに動き、座標で書かれた点は動かず、名前付きの点は制約できる。
- **描画されない接続**：RNLに配線がない接続をどのように表示するか（ソルバーで配線してWIREとして書き戻すか、フライラインか、ラベルか）は、ソルバーおよびビューアのハウススタイルと使用中のハウススタイルパッケージによって決まり、本言語は規定しない。ハウススタイルパッケージはルールでラベルや配線を作ることができ、それらはRNLである。配線をソルバーに任せてネットを配線として描かせるにはROUTE-NETまたはROUTE-OBJECTを書く（13.7）。

### 13.2 接続点の黒丸

```rnl
%j1 = (10, 30);
&x @WIRE {#M1:1 %j1 #M3:1};          /* the through wire passes %j1 */
&x @WIRE {%j1 (30, 30) #M4:2};       /* the branch starts at %j1 */
$JUNCTION @ATTACH %j1                /* draws the dot */
```

- 分岐とは、1つの点を共有する複数の配線である（13.1）。
- 接続点の黒丸は明示的に書かれる：黒丸が描画されるのは、標準パッケージの `$JUNCTION` のような黒丸を描く定義が適用された箇所のみであり、レンダラが独自に黒丸を追加することはない。
- 黒丸はキーワードではなく適用オブジェクトである。`$JUNCTION` は点または端子をとる1ロールの標準パッケージの定義である。その定義は `$NO_CONNECT`（12.6）や電流矢印（15.2）と同様に、適用オブジェクトの点をその点または端子のピンに結び付ける（12.1項目5）。2本の配線がある端子のピンで出会うとき、その端子に適用できる。標準パッケージはこれらの適用オブジェクトにシンボルとして塗りつぶされた黒丸を与える：黒丸の大きさはそのシンボルから、色は適用オブジェクトのスタイルの `linecolor` からとられ、黒丸の大きさの独立した設定はない。
  - 同じ点に `$JUNCTION` を2度適用すると黒丸が2つ重なり、1つのように見える。
  - すべての接続点の黒丸は `# @SELECT-USAGE $JUNCTION` で選択される。
  - 描画順はシンボルを割り当てるルールの位置に従う（11.6）。標準パッケージのルールが先に来るため黒丸は配線より先に描画されるが、黒丸は配線と同じ色で配線より太いため見た目に違いはなく、LAYERは不要である。
- 黒丸は共有点に出会う配線の本数から導出されるものではない：実際の回路図には2本しか配線のない分岐点に黒丸が描かれることがあり、導出される仕組みにするとそれを消す別の手段が必要になるためである。エクスポータは元の回路図が示す黒丸を書き出す。実装は3本以上の配線が黒丸なしで1つの共有点に出会う箇所でヒントを出してもよいが、本標準はこれを必須としない。
- **ソルバーが追加する黒丸**：ソルバーの出力もRNLであり、黒丸を含めてよい。ソルバーが使用する定義はSOLVER-CONFIGのkey `junction` によって与えられる（14.10）：文字列として書かれた `$` 名（`junction="$JUNCTION"` など）、あるいはレベルレコードのSOLVER-CONFIGではそのレベルの `%` 名（そのサブサーキット専用の大きな黒丸を定義する `junction="%BIG_DOT"` など）である。標準パッケージはそれを用いるレベルに対して `$JUNCTION` を設定する（16.3）。このkeyがある場合、ソルバーはROUTE-NETおよびROUTE-OBJECTのツリーの各分岐点にその定義を適用し（13.7）、ユーザーが書いた配線が3本以上その定義の適用オブジェクトなしで1つの共有点に出会う箇所でも出力に1つ追加してよい。このkeyがない場合は黒丸を書かず、パッケージが設定した箇所で `junction=""` と書けば無効になる。この名前はそのレベルのソルバーのレコードに書かれた名前として探索される（6.8）。そこで定義を指さない他の値や、第1ロールが点をとらない定義を指す値は、そのレベルで採用されない値であり（14.10）、エラーとなる。そのレベルではkeyは書かれなかったものとして扱われ、それ以前の値があればそれが適用され、なければソルバーは黒丸を書かない。共有点は常に名前付きの点または端子である（等しい座標は数えない）ため、黒丸を書き出すことができる。エディタなど黒丸を追加する他のツールも同じkeyから定義を取得する。
- 黒丸は描画のみである：接続を作らず、検査もされない（原則 2.2）。配線のない点に `$JUNCTION` があっても黒丸は描かれる。

### 13.3 テキスト：TEXT

```rnl use=w13
(50, 18) @TEXT("5T OTA testbench");                         /* an annotation: attached to a point */
(1, 1) @TEXT("see here") => @PLACE(2, 2);                   /* attached to (1, 1); the text itself is at (2, 2) */
#M1 @TEXT("W/L=${w}/${l}", key="wl") => @PLACE(12, 18);     /* a label: attached to M1, with the key wl, so it is #M1::wl */
#R1 @TEXT("R_{D}", key="name");                             /* a key the symbol has: new content, the position still from the symbol */
#M1::name @PLACE(13, 18);                                   /* the name of M1, dragged in an editor */
%w13 @TEXT("${net}");                                       /* the net name on a wire; no key; placed by the implementation */
&out @TEXT("${name}");                                      /* shows the name of the net out; placed by the implementation */
# @SELECT-INSTANCE => @SELECT-PIN(wired=false) => @TEXT("${net}", key="netname")    /* net names on pins without wires */
```

- **空テキスト**：内容が空文字列のTEXTは何も描画しない。keyがある場合は、そのkeyを持つシンボルのラベルを置き換えて非表示にする。標準パッケージ `rnl-std-no-labels` はその代わりにスタイル `textvisible=false` でデフォルトラベルを隠す（9.3、16.3）。この方法では内容が保持されるため、同じkeyで `textvisible=true` を持つTEXTにより再び表示できる。
- **取り付け**：TEXTは1つの点または描画されるオブジェクトを受け取り、テキストはそれに取り付けられる。何に取り付けられるかは次の3つを決める：`${…}` が誰の属性を読むか（13.6）、位置が指定されないときにテキストがどこへ行くか、そしてkeyを持つときにテキストがどのオブジェクトのサブオブジェクトになるか。
  - 点（`(x, y)`、名前付きの点、`::position`）：テキストは注釈である（13.4）。点の属性 `x` と `y` のみを参照できる。
  - オブジェクト：テキストはラベルである。オブジェクトはインスタンス、描画される適用オブジェクト、バンドル、ピン、端子（そのピンの位置、5.2.4）、配線、または図形であり得る。ネットであってもよい：ネット自体は描画されないが、実装はネットに取り付けられたテキストをその配線または端子の1つの横に配置する。ファイルがどのネットの名前を表示するかを示すのはこの方法による。
  - シンボルのない適用オブジェクト、またはピンのない端子は描画上の意味を持たない：それらを渡すとTEXTは失敗する（12.1、9.2.4）。
  - セットが渡された場合、TEXTは各メンバーに1つのテキストを取り付ける（5.2.1；例の最終行）。
  - シンボル定義本体内では、点に取り付けられたテキストはシンボルの固定テキストであり、単独の `?` に取り付けられたテキストはそのシンボルで描画されるオブジェクトに取り付けられる（下記）。
- **内容**：`text` は必須であり、keyを与える場合も同様である。これがないとTEXTは失敗する。`@TEXT("${name}", key="name")` のように位置指定の1番目で与えてもよい。デフォルトの内容はないため、名前を表示するには `"${name}"` と書く。マークアップと属性参照については13.6を参照。
- **位置**：テキストは自身が取り付けられた点やオブジェクトとは別の、自身の位置を持つ。
  - テキストの位置は `(_, _)` のように自由な状態で始まる。PLACE、`dx`、`dy`、または制約が固定しない場合、ソルバーが位置を決めて書き戻す（14.8）。解がない場合、ビューアが決定する：点に取り付けられたテキストは通常その点に、オブジェクトに取り付けられたテキストはそのオブジェクトの横に置かれ、どちらも重なりを避けるために動かされることがある。
  - PLACEはテキスト自身の位置を設定する。したがって `(1, 1) @TEXT(…) => @PLACE(2, 2)` は矛盾ではない：前半がテキストを (1, 1) に取り付け、後半がテキストを (2, 2) に置く。注釈を正確な位置に置くにはPLACEを書く。
  - `dx`、`dy`：TEXTのみがとるオフセット。テキストが取り付けられた対象が座標点（点、インスタンスの原点、適用オブジェクトが描画される点、端子のピン）を持つとき、テキストはその点に (dx, dy) を加えた位置に行く。配線とネットは座標点を持たないため、それらに取り付けられたテキストにオフセットを書くとTEXTは失敗する。
    - テキストは依然として1つの位置（オフセットを加えた位置）のみを持ち、制約とソルバーはそれを用い、「オフセット前の位置」は存在しない。取り付けられたオブジェクトが動かされたりソルバーに配置されたりするとテキストもそれとともに動き、他の制約がテキストを動かすと取り付けられたオブジェクトもそれとともに動く。オフセットはテキスト上に書かれたx用とy用の各1つのexactなDISTANCEと同じである：正のオフセットは増加方向（`"left-to-right"`、`"bottom-to-top"`）、負のオフセットは減少方向に、その大きさを `exact` とする（14.5）。
    - シーン内のテキストはオブジェクトとともに回転しないため、オフセットはシーンの軸に沿い、取り付けられたオブジェクトの向きによって回転しない。シンボル定義本体内でも記述でき、そこではローカル座標となり `=> @PLACE(…)` で書かれたローカル位置と同様にインスタンスとともに変換される。
    - **オフセットとPLACEは互いに置き換わる**：各軸上で、テキストの位置は絶対値（PLACEのxまたはy）かオフセット（`dx` または `dy`）のいずれか一方であり、両方になることはない。同じテキストの同じ軸上では、後に書かれた方（8.5の位置による）が有効になり、先に書かれた方は一切効力を持たない：オフセットの後に書かれたPLACEでは絶対位置がその軸を決め、オフセットの後にPLACEがなければその軸の絶対位置は自由でオフセットに従う。逆にオフセットがPLACEの後に書かれればPLACEは効力を失う。これは競合ではなく置き換えである：優先度は関与せず、ヒントも出されない。例えば `dx` と `dy` の後に `#M1::name @PLACE(x=13)` が続くと、xは絶対座標13となり `dx` はもはや適用されず、yは引き続き `dy` に従う。オフセットで配置されたテキストをドラッグしたとき、エディタはこのように書き出す。シンボル内で与えられた位置が先に来て（下記）、シーン内のPLACEまたはオフセットがそれを置き換える。
    - 有効になる方はいずれも通常の幾何的事実である：オフセットのxとyはそれぞれ1つの単位であり、その位置はそれを書くTEXT文の位置であり、優先度はレコードヘッダーのデフォルトである（14.8）。それらは他の事実と8.5によって解決される。同じ軸上の複数のPLACE同士は8.5で解決される。keyを持つテキストでは `dx` と `dy` は別々に上書きされる（8.4）。
  - テキストは自身の位置によって制約のメンバーになり得る（14.1）。テキストの `::position` は自身の位置である：`%n1::position @PLACE(…)` は `%n1 @PLACE(…)` と同じである。
  - シーン内のテキストは取り付けられた対象の向きとともに回転しない。回転させるには `rotate=` を書く。シーンがPLACEまたはオフセットによってテキストの位置の両軸を与えた場合、どちらの軸もシンボルのローカル位置を使わない：テキストは取り付けられたオブジェクトの向きを継承せず、`halign` と `valign` はシーンの向きで解釈される。
  - ソルバーは選択した位置を書き戻す（14.8）：key（下記）またはテキストの名前によって、あるいは番号によって参照する（5.9）。生成ルールが直接作るkeyのないテキスト（13.3、10.5）は参照できないため、ソルバーはその位置をビューアに委ねる。ルールが作る適用オブジェクトの定義本体内のテキストは、ソルバーがその適用オブジェクトを明示的な文として書き出せば番号で参照される（10.5、5.9）。
- **key `key=`**：
  - keyがなければ、そのテキストは取り付けられたオブジェクトのkeyなしテキストであり、再び書けば配線（13.1）と同様に別のテキストとなる。`%x =` で名前を付けてそのレベル内で参照・変更できる。ルールがkeyなしで作ったテキストはハンドルを持たないため、ソルバーはその位置を書き戻せない。
  - keyがある場合、そのテキストは取り付けられたオブジェクトのサブオブジェクト `object::key`（`#M1::wl` など）である。同じオブジェクトと同じkeyは同じテキストを指し、後の文がパラメータごとに上書きする：サイズ、揃え方、回転などはそれぞれ単独で上書きされ、書かれなかったパラメータは元のまま残る（8.4）。内容はすべての文で記述する（`text` は必須）ため、後の内容が常に前の内容を置き換える。揃え方や回転だけを変えたい場合は `#M1 @TEXT("${name}", key="name", halign="end")` のように内容を再度記述する。位置はPLACEの規則に従う（8.5）。他のレコード、エディタ、ソルバーはこのハンドルによってテキストを見つける。
  - 点に取り付けられたテキストは `key=` をとらない：点はサブオブジェクトを持たないため、keyがあるとTEXTは失敗する。
  - `::` の後の名前は固定された順序で探索され、keyは最後に来る（6.5）：適用オブジェクトのロール名とローカル名、次にそれらの `definition=` 別名、次に標準サブオブジェクト名とその別名、次にオブジェクトのシンボルのピン名、最後にテキストのkeyである。したがってkeyは自身の前に来るいずれの名前とも同じ綴りであってはならない：標準サブオブジェクト名（`position`、`net`）またはそのファイルで宣言された別名（`alias-zh` の `位置` など）、テキストが取り付けられた適用オブジェクトのロール名またはローカル名、あるいはそれらの `definition=` 別名である。そのようなkeyは6.5の名前の衝突と同様にエラーとなる。シンボル内で書かれたテキストに対しては、別名はそのシンボルが書かれたファイルの別名である。`name` と `value` は標準サブオブジェクト名ではなく、よく使われるkeyにすぎない。
- **シンボル内のテキスト**：
  - シンボル定義本体内では、単独の `?` はそのシンボルで描画されるオブジェクトを表す：M1が描画されるときはM1、適用オブジェクト `%g0` が描画されるときは `%g0` である。これはTEXTのオブジェクトとしてのみ書ける。シンボル内でそれ以外の場所に書くと（`? @PLACE(…)` など）意味を持たないため失敗する。
  - `? @TEXT("${name}", key="name") => @PLACE(1.5, 1.5)`：テキストはそのシンボルで描画されるオブジェクトに取り付けられ、`${…}` はその属性を読み取る。このPLACEはローカル座標であり、インスタンスとともに変換される（9.2.5のテキストの向きを参照）。PLACEがなければ、実装はテキストをオブジェクトの横に置く。
  - keyを持つテキストは、`#M1::name` のようにそのシンボルで描画されるオブジェクトのサブオブジェクトである。シンボル内のテキストが先に来て、シーン内の同じkeyのテキストがパラメータごとにそれを上書きする：`#R1 @TEXT("R_{D}", key="name")` は内容のみを変えてシンボルからの位置を保ち、`#M1::name @PLACE(13, 18)` は位置のみを変えてシンボルからの内容を保つ。シーン内で与えられた位置はシーン座標であり、もはやインスタンスとともに回転しない。
  - シンボルが与えるkeyは、シンボルが割り当てられた後にのみ存在する（8.2ステップ4および7）。M1のシンボルがkey `name` のテキストを持たず、シーンもそれを書かない場合、`#M1::name` は失敗する。シンボルに依存しないようにするには、シーン内でそのkeyを持つTEXTを書く。
  - オペアンプシンボル内の `(-2, 2) @TEXT("+")` のようにシンボル内の点に取り付けられたテキストは固定テキストであり、1つのインスタンスのために変更することはできない。
- **ルール**：`# @SELECT-INSTANCE => @SELECT-PIN(wired=false) => @TEXT(…)` のようなルールはシンボルに由来するピンを選択するため、ステップ6で1つずつの生成とともに評価される（8.2）。実装が独自にフライラインやラベルを追加する場合、すでにラベルを持つピンはスキップする。
- どのネット名を表示してどこに置くか、および配線のない接続をラベルとフライラインのどちらで示すかは、デフォルトでは実装によって決定される：それらはハウススタイルの一部である（原則 2.7）。配線の代わりにラベルを表示するとレイアウトが変わるため、ソルバーとレンダラは同じ設定を使用する。RNLはこれらを必要なとき（位置なしで意図を述べるとき、または決定済みの位置を保持するとき）にのみ記述する。
- 配線上の途中の位置というものは存在しない：配線の座標自体は固定されない。
- **`fix_rotate`**：真偽値で、デフォルトは `false` である。`true` のとき、テキストの `rotate` はシーン基準でとられる：取り付けられたオブジェクトの向きが何であっても、文字はその向きを保つ。ただしアンカーは依然としてオブジェクトに追従し、テキストボックスがアンカーのどちら側に置かれるかも同様に追従する。揃え方はアンカーから見てボックスがどこにあるかを示す：`start` なら右側、`end` なら左側、`bottom` と `baseline` なら上側、`top` なら下側、`middle` ならどちら側でもない。この方向がオブジェクトの向きによって変換され、テキストはその結果が示す向きに揃えられる。したがって、シンボルの真上に `halign="middle"`、`valign="bottom"` で書かれた名前は、シンボルが `"R90"` で回転されるとアンカーの左側に `end` と `middle` 揃えで置かれ、`"MX"` では下側に `top` 揃えで置かれ、どの向きでも水平に読め、シンボルの外側に留まる。アンカーの上側に留まるボックスは、書かれたとおり `bottom` または `baseline` を保つ。
- **`upright`**：真偽値で、デフォルトは `true` である：そうしないと逆さまに読めてしまうときにテキストが180度回転され、字形は鏡像反転されない。`false` のとき、文字は回転と鏡像反転にそのまま従う（9.2.5）。
- パラメータ：`text`（必須；位置指定で与えてもよい）、`key`、`dx`、`dy`、`halign`、`valign`、`rotate`、`fix_rotate`、`upright`、およびテキストのスタイルプロパティ `textcolor`、`size`、`font`、`bold`、`italic`、`textvisible`（9.3）。点に取り付けられたテキストは `key` を持たない。`halign`、`valign`、`rotate` については9.2.5を参照。スタイルパラメータはテキストの直接スタイルとなる（8.3）。テキストがどのようにスタイルを得るかは11.3にある。

### 13.4 注釈：シーン内の図形

```rnl
(50, 18) @TEXT("5T OTA testbench") => @SET-STYLE $note => %n1;
%f1 = @RECTANGLE {(0, 0) (40, 30)};
%n1 @PLACE(60, 18)                            /* moves the text; may also be written in another record */
```

- LINE、RECTANGLE、CIRCLE、ELLIPSE、ARC、BEZIERおよびTEXTはシーン内に直接書くことができ、したがって一般定義の定義本体内にも書ける。シンボル定義本体内では座標はローカル座標であり、シーン内ではシーン座標である。どこに書かれるかがこれを決め、キーワードは同じである。
- 原則 2.2の注記オブジェクト（自由テキスト、図形、枠、その他端子も電気的意味も持たず描画のみされるオブジェクト）が本標準の注釈（annotation）である：シーン内に書かれた図形、点に取り付けられたTEXT、およびANNOTATIONが描くシンボルである（13.5）。
- PINはDEFINE-SYMBOLの定義本体内にのみ書ける：ピンはそのシンボルで描画されるオブジェクトの端子を束縛するものであり、シーンにはそのようなオブジェクトがないためである。
- 点に取り付けられたTEXTは注釈である（13.3）：その点の属性 `x` と `y` のみを参照でき、点はサブオブジェクトを持たないため `key=` をとらない（keyがあるとTEXTは失敗する）。オブジェクトの名前や値を表示するには、そのオブジェクトにTEXTを取り付けてラベルにする。
- 図形の位置はその点によって与えられる。点は任意の点オブジェクトであり得る：名前付きの点、制約付きの自由な点、または素子に追従する `#M1::position` である。一般定義の定義本体内では、リテラル点は適用オブジェクト自身の点からのオフセットである（9.4）。PLACEは図形自身をとらない：別のレコードから中心で書かれたRECTANGLE、CIRCLE、ELLIPSEを動かすにはその `::position` を動かす。LINE、ARC、BEZIERおよび2点で書かれた図形は複数の点を持つため、点に名前を付けてそれらを動かす。TEXTは例外である：自身の位置を持ち、取り付け先の点はデフォルトの場所を与えるだけで、PLACEはテキストの位置を直接設定する（13.3）。
- 外観：図形はスタイルパラメータを直接とることができ（9.2.5）、8.3の2つのティアでSET-STYLEもとる。どちらによっても与えられないプロパティはレンダラのデフォルトをとる。
- 枠はRECTANGLE、または最後の点が最初の点であるLINEである。オブジェクトのグループを囲む専用の図形はない：RECTANGLEを描き、その角がグループの外側に来るよう `%tl %stage1_set @DISTANCE("left-to-right", min=1)` のように制約する（これにより角はすべてのメンバーの少なくとも1左に保たれる；14.5）。囲まれるのはメンバーの点に余白を加えた範囲である。ビューアがGROUPを枠として描画してもよいが、それはビューア次第である（11.5）。`::box` は存在しない。
- 描画順はレイヤーと位置に従う（11.6）。
- **分類**：ある要素が注釈であるか否かはそのオブジェクトの種別から決まる：シーン内の図形は注釈であるため、レンダラは1つの分類としてまとめて表示・非表示を切り替えられる。SELECT-ANNOTATIONはシーン内のすべての図形とANNOTATIONが描くもの（13.5）を選択し、これには一般定義の定義本体から展開されたもの（ハウススタイルパッケージが描く枠など）も含まれる。シンボル内の図形、ラベル、配線、および適用オブジェクト（接続点の黒丸を含む）は注釈ではない。より細かい分類（説明、表題欄、パッケージが描く装飾など）は名前付きのセットであり、1つの図形が複数のセットに属してもよい。表示・非表示の切り替えはビューア次第であり、本言語に `visible` はない。
- 素子上のテキストは素子に取り付けられたTEXTであり、ラベルである（13.3）。`#M1::position` に取り付けられたTEXTは注釈である。デフォルトではそれも素子に追従するが、その点の座標のみを参照でき、keyを持たない。

### 13.5 注釈として描画されるシンボル：ANNOTATION

```rnl
%a1 = (40, 20) @ANNOTATION(rotate=30) $ARROW_SYMBOL;     /* an arrow at any angle */
#M1 @ANNOTATION(rotate=-45, mirror=true) $ARROW_SYMBOL;   /* follows M1 */
%a1::position @PLACE(44, 20)                             /* moves the first one */
```

- ANNOTATIONは与えられたものの図形を集め、任意の角度に回転させた1つの注釈（13.4）として描画する。2つのスロットがある：最初に書かれる `at` は位置特定可能な1つのオブジェクト（点、または注釈がその位置に追従するオブジェクト）、最後に書かれる `source` は次のいずれかである：
  - シンボル（DEFINE-SYMBOL）：その定義本体の図形およびTEXT；
  - 一般定義（DEFINE）、ロールの有無は問わない：その定義本体内に直接書かれた図形のうち、すべての点がリテラル点（適用オブジェクトの点からのオフセット；9.4）であるもの、およびそのような点または `?` に取り付けられたTEXT。定義は適用されない：適用オブジェクトは作られないため、2重に描画されることはない；
  - 適用オブジェクト：シンボルを持つ場合は（シンボルが与えられた後に；8.2）そのシンボルの図形、およびその定義本体がリテラル点のみで描いた図形（定義の場合と同様に適用オブジェクトの点を中心に）。適用オブジェクト自体は元の場所に描かれたまま残る。
- それ以外のものはすべて除外される：PIN、`box=`、制約、定義本体内で作られた適用オブジェクト、および他のオブジェクト上の点を持つ定義本体の図形（ロールに向かって引かれた線など、動かして回転させると意味を失うもの）。その理由で除外された図形はヒントを出すが、残りはヒントなしで除外されるため、ピン付きのシンボルを標識として再利用できる。どのロールも埋められず、この注釈はピンを持たず、配線の端点になれず、13.7のどのツリーにも含まれない。
- **パラメータ**：`rotate`（反時計回りの角度（度）、任意の数値、デフォルト `0`）、`mirror`（真偽値、デフォルト `false`；回転の前に垂直軸に対してシンボルを鏡像反転する）、およびスタイルプロパティ（SET-STYLEと同様にその図形とテキストに与えられる；11.3）。またASと同様に、`source` として与えられたシンボルまたは一般定義のパラメータも名前でとる（`(0, 0) @ANNOTATION(rotate=30, w=5) $D` など、9.4）：与えられなかったパラメータはデフォルト値をとり、デフォルトのないパラメータは書かれなかったものとして数えられる（9.4）。sourceのパラメータが `rotate` や `mirror` のようにANNOTATION自身のパラメータ名を持つ場合、ANNOTATIONのパラメータが意図されたものとみなされヒントが出される。`source` として与えられた適用オブジェクトは自身のパラメータ値を保持し、ANNOTATIONにその定義のパラメータを書くと不正なパラメータとなる。シンボルのテキストは、シンボルのテキストがインスタンスとともに回転するのと同様に、自身の `rotate`、`fix_rotate`、`upright` に従ってそれとともに回転する（9.2.5）。
- シンボルのテキスト内では `?` はその注釈を表し、点と同様に属性 `x` と `y` のみを持つ（13.4）。そこでの他の属性参照は空テキストとして描画される。
- **結果**：サブオブジェクト `::position`（そのアンカー）を持つ新しい注釈。書かれた点が与えられた場合、アンカーはそこから始まり、中心で書かれた図形と同様にその `::position` で動かせる（13.4）。オブジェクトが与えられた場合、そのオブジェクトの位置に追従する。SELECT-ANNOTATIONがそれを選択し、SET-STYLEがそれをスタイル設定し、`textvisible` がそのテキストを隠す。
- それが何であるかは記述位置で判明する：スロット `source` にシンボル、一般定義、または適用オブジェクト以外のものがあるとエラーとなる。描画する図形のないsourceは警告を出して何も描画しない。
- **他との比較**：シーン内に書かれた図形（13.4）はそれぞれ自身の点を持つ。標準パッケージの図のようなシンボルを持つ適用オブジェクトは11.2の8通りの向きで描画され、ピンを持つことができ配線できる。ANNOTATIONはシンボルを任意の角度で描画し、電気的意味を持たない。

### 13.6 テキストマークアップと属性参照

```rnl
#R1 @TEXT("R_{D}", key="name");                              /* subscript */
(50, 18) @TEXT("\textbf{5T OTA} testbench\\VDD = 1.8 V");    /* bold, two lines */
#M1 @TEXT("W/L=${w}/${l}", key="wl");                        /* host parameters */
$NMOS_M = @DEFINE-SYMBOL {
  $NMOS;
  ? @TEXT("${model}", key="model") => @PLACE(1.5, -1.5)      /* the model name, in a symbol */
}
```

- **マークアップ**はLaTeXのテキストモードの部分集合であり、完全なTeXではない：

  | マークアップ | 意味 |
  |---|---|
  | `_{…}`, `^{…}` | 下付き文字、上付き文字 |
  | `\textbf{…}`, `\textit{…}` | 太字、斜体 |
  | `\overline{…}` | 上線（負論理の `\overline{RST}` など） |
  | `\subrest{…}` | 最初の文字をそのまま、残りを下付き文字にする：`\subrest{${name}}` はM1をM₁、VDDをVの下にDDを付けて表示する |
  | `\subdigits{…}` | 末尾の数字を下付き文字にする：R12はR₁₂、Vout1はVout₁。末尾に数字のない内容はそのまま表示される |
  | `\(…\)` | 数式モード（下記） |
  | `\frac{…}{…}` | 分数：上に分子、下に分母、間に横線（`\frac{${w}}{${l}}` など）。上下に積めないビューアは「分子/分母」と表示する |
  | `\alpha` … `\omega`, `\Gamma` … `\Omega` | ギリシャ文字（LaTeXの名前を用いる） |
  | `\pm`, `\times`, `\cdot`, `\infty`, `\approx`, `\neq`, `\leq`, `\geq`, `\ll`, `\gg`, `\propto`, `\parallel`, `\angle`, `\circ`, `\to`, `\uparrow`, `\downarrow` | 一般的な記号 |
  | `\\` | 改行 |
  | `\_`, `\{`, `\}`, `\$`, `\%`, `\&`, `\#`, `\textbackslash` | `_`、`{`、`}`、`$`、`%`、`&`、`#`、`\` の文字そのもの |

- ギリシャ文字：小文字は `\alpha` から `\omega` まで（LaTeXに `\omicron` はないためoと書く）および異体字 `\varepsilon`、`\vartheta`、`\varpi`、`\varrho`、`\varsigma`、`\varphi`。大文字はラテン文字と異なる文字のみ：`\Gamma`、`\Delta`、`\Theta`、`\Lambda`、`\Xi`、`\Pi`、`\Sigma`、`\Upsilon`、`\Phi`、`\Psi`、`\Omega`。表にない記号はUnicode文字として直接書く（文字列は非ASCII文字を含めてよい；3.7）。
- マークアップは `\textit{V}_{\textit{DD}}` や `I_{D_{1}}` のように入れ子にできる。`V_{in}^{+}` の上下付き文字を上下に重ねるか前後に並べるかはビューア次第である。
- **下付き・上付きには波括弧が必要**：単独の `_` や `^` は通常の文字である。これは `g_m` のmが下付きになるLaTeXとは異なる：名前や説明には `vin_1` や `bias_ctrl` がよく含まれ、その規則では壊れてしまうためである。その代わり `g_m` は書かれたまま表示される。
- 他の文字は書かれたまま表示され、LaTeXでは別の意味を持つ単独の `{`、`}`、`$`、`~`、`%`、`&`、`#` も含まれる。
- **バックスラッシュ**：`\\` はLaTeXと同様に改行であり、バックスラッシュ自体は `\textbackslash` と書く。既知のコマンドが続かないバックスラッシュは `C:\temp`（`\temp` は未知のコマンド；次項目参照）のように書かれたまま表示されて警告が出る。警告を避けるには `C:\textbackslash{}temp` と書く。`\textbackslash` が必要になるのは、バックスラッシュの直後に `\`、`{`、`}`、`_`、`^`、`$`、`%`、`&`、`#` または既知のコマンド名が続く場合のみである。RNL文字列にはバックスラッシュエスケープがない（3.7）ため、`"\textbf{V}"` は `\\textbf` ではなくそのまま書く。
- 未知のコマンド（`\` の後に表にない文字が続くもの、`\sqrt` や `\alpah` など）および対応の取れていない波括弧は、書かれたまま表示されて警告が出るが、テキストは依然として妥当である。
- **コマンド名の後**：コマンド名とは `\` の直後に続く文字の連なりである。既知のコマンド名の後の空白は落とされて表示されず、その直後の空の `{}` は区切りになるのみでやはり表示されない。したがって `10 \mu A` と `10 \mu{}A` はいずれも 10 μA を表示し、空白を残すには `\mu{} A` と書き、`\textbackslash{}temp` は \temp を表示する。`\_` や `\{` などのエスケープされた文字の後の空白は保持される。

  注記：将来のバージョンでTeXのさらなる機能に対応しても許容範囲が広がるだけである。数式モードに `$…$` ではなく `\(…\)` を用いるのは、`$` が属性参照で使われるためである。
- **名前の書式**：`\subrest{…}` と `\subdigits{…}` はその内容の表示方法のみを変え、表示される文字を通常部分と下付き部分に分ける。内容は `\subrest{${name}}` のように参照されてもよく、その場合もマークアップとしては読まれない（下記）。また `\textit{\subrest{${name}}}` のように他のマークアップの中に入れ子にできる。
- **数式モード**：`\(…\)` はLaTeXの数式モードの部分集合による数式を保持する：
  - 文字は変数として斜体にされ、数字と表の記号は立体となり、空白は表示されない；
  - `_` と `^` はLaTeXと同様に1文字または波括弧内のグループをとるため、`\(…\)` の中では `g_m` は下付きmを持つgとなる；
  - `\frac{…}{…}`、`\sqrt{…}`、表のギリシャ文字と一般的な記号、および関係記号 `=`、`<`、`>`；
  - `\mathrm{…}` は `\(V_\mathrm{DD}\)` のように単位や名前のためその内容を立体にする；
  - 内部の属性参照は書かれたまま立体で表示される。

  この部分集合にないコマンドは書かれたまま表示され、警告が出る。
- **分数**：`\frac` は直後に波括弧のグループを2つとる。一方が欠けている場合は未知のマークアップとなり、警告付きで書かれたまま表示される。分子と分母はマークアップおよび `${…}` を含んでよい。
- 下付き・上付きや分数をどれだけ上下にずらしどれだけ小さくするかはビューア次第である。テキスト全体のフォント、太字、斜体はスタイルまたはパラメータ `font`、`bold`、`italic` に由来する（9.3）。
- マークアップはTEXTの `text` とPINの `label`（`\overline{CS}` など）で読み取られる。他の文字列パラメータ（`key`、列挙値、選択条件）ではマークアップは読み取られない。
- 注記：インポートとエクスポートでは、KiCadの `_{…}` と `^{…}` は同じであり、その `~{…}` は `\overline{…}` である。Altiumが各文字の後に `\` を付けて書く上線は `\overline{…}` に書き換えられる。
- **属性参照** `${name}` はテキストが取り付けられたオブジェクトの属性を表示する。`${` 自体を書くには `\${` と書く。`\${` から対応する `}` までは書かれたまま表示され、その `}` は不均衡な波括弧として数えられない。属性は次のとおりである：
  - インスタンス：`name`、`value`（ホスト行に書かれた値そのもの。なければ空となり、モデル名へフォールバックしない）、`model` と `type`（選択条件と同様、10.1；したがってXインスタンスの `${model}` はサブサーキット名を示す）、および `w` などのホストパラメータ。標準属性と同名のホストパラメータは `${#…}` と書く（下記）。
  - 端子、ピンおよび配線：`net`（それらが乗っているネットの名前；ピンでは `::net` のネット（6.5）であり、何も束縛しないピンは `net` を持たない）。空ノード（6.3）上では `net` は空テキストであり、それで埋められたロール（`${p}` など）も同様に何も描かれない（13.3）。バス配線の `net` はそのネットの名前を順に `,`（空白なし）で連結したものである（13.1）。バンドルの端子では、すべてのメンバーが同じネット上にあるときはそのネット名、そうでなければ `,` で連結された名前である（11.8）。
  - ネット：`name`。
  - 適用オブジェクト：定義のロールおよびパラメータ。`${p}` はロールpを埋めるオブジェクトであり、下記の規則で表示される。適用オブジェクトは自身の名前を持たない：グラウンド、電源、ポートのシンボルは `${p}` と書き、pがネットのときネットの名前を表示する。`$GROUND_STUB` のtのように端子またはピンで埋められたロールもそのネットの名前を表示する。
  - バンドル：すべてのメンバーで同じ属性値であればその値、そうでなければ値を `,` で連結したもの（11.8）。
  - 点：`x`、`y`（最終的な座標、すなわち求解後の値）。
  - 図形：属性なし。
- **属性パス**：`${a::b::c}` では、最初の名前が取り付け先オブジェクトの属性をとり、それに続く各 `::name` が前の値の属性をとる（`${p::x}`：ロールpが点のときのそのx、や `${pair::left::w}` など）。
  - 属性の値はオブジェクト（適用オブジェクトのロール；端子や配線の `net`）またはテキスト（`name`、`value`、ホストパラメータなど）であり得る。テキストは属性を持たないため、その後に `::` を続けることはできない。
  - パス上の値は、セットロールなどのセットであってもよい。その場合、パスの残りは各メンバーから（その中のセットは自身のメンバーから）セットの順に取り出され、値はセットと同様に（下記）表示される。1つのメンバーでもその属性を欠いている場合、テキストは失敗する。したがってセットロール `pairs` が2つの差動対を保持する適用オブジェクトでは、`${pairs::left::w}` は両方の `left` トランジスタの `w` を `1u,2u` のように表示する。
  - `${…}` 内の `::` は属性のみをとる点で、サブオブジェクトをとる文中の `::` と異なる（6.5）：`${m::name}` はインスタンスmの名前であるのに対し、文中の `#M1::name` はM1上のkey `name` を持つテキストである（13.3）。
  - `${m::#type}` は `${#type}` と同様にホストパラメータのみを探す（下記）。
- **表示**：パスの最後の値がテキストのとき、書かれたまま表示される。オブジェクトのとき：インスタンスとネットはその名前を表示し、端子・ピン・配線はそのネットの名前（バス配線はそのネットの名前を `,` で連結したもの）を表示し、バンドルは上記のとおりであり、セット（セットロールなど）はそのメンバーそれぞれをこの方法で表示して `,` で連結する。点、適用オブジェクト、図形は表示できないためテキストは失敗する。したがってロールpが点のときは `${p}` ではなく `${p::x}` と書く。
- 参照はネットリストに書かれたテキストを評価せずにそのまま与える：`w=1u` は 1u を表示する。各方言が何を提供するかはそのホストアダプタが定義する。例えばSpectreでは抵抗の値はパラメータ `r` である。
- 上に列挙した属性は常に存在し、値を持たないものは空である。存在しない属性名への参照はテキストを失敗させる。
- 参照された内容は書かれたまま表示され、マークアップとして読まれることはない：ホスト名や値はマークアップで書かれていないためである。
- 参照は取り付け先オブジェクトの属性から下方向にのみたどれ、任意のオブジェクトに到達することはできない。KiCadの `${R3:VALUE}` のような他オブジェクトへの参照はない。
- **別名**：`${…}` 内の属性名はそのファイルに宣言された別名も受け入れ、最初に標準属性、次に別名、次にホストパラメータの順で探索される。`${#name}` はホストパラメータのみを探す（16.5）。適用オブジェクトのロール名とパラメータ名はRNL名である：それらは定義の `definition=` 別名のみを受け入れ、各ステップでそのステップの適用オブジェクトの定義内で `${输入对::左管::w}` のように探索される（16.5）。
- **標準名を持つホストパラメータ**：標準属性が優先され、同じ名前を持つホストパラメータは `${#type}` のように書く（RNLにおいて `#` はホストを表す）。どのホストパラメータもこの方法で書くことができる。標準属性にも別名にもその名前がない場所では、`${w}` は `${#w}` の短縮形である。標準属性名は書かれたとおりに厳密に比較され、ホストパラメータ名はホストの規則で比較される：SPICEホストでは `${Type}` は標準属性ではないためホストパラメータtypeとなる。
- **名前の書式設定**：参照された内容は全体としてのみ書式設定でき（`\textit{${name}}` のように周囲にマークアップを置く）、また名前の残りの部分や末尾の数字を下付き文字として表示する2つのコマンド `\subrest{…}` と `\subdigits{…}` によって書式設定できる。単一文字のその他の書式はテキストとして直接書く（`#M1 @TEXT("M_{1}", key="name")` など、リネームには追従しない）。ビューアのさらなる慣習はそのハウススタイルである。

### 13.7 接続の配線としての描画：ROUTE-NET、ROUTE-OBJECT、UNROUTE-NET、UNROUTE-OBJECT

```rnl
&x @ROUTE-NET;                                /* x is drawn as wires; the solver decides the branches and paths */
%jo = (_, _);
&out @WIRE {#M2:1 %jo};
&out @ROUTE-NET;                              /* this wire is drawn as written; the solver adds the rest */
{#M1 #M2 #M5} @ROUTE-OBJECT;                  /* on each net that two or more of their pins share, those pins are joined */
&vdd @UNROUTE-NET(priority="high");           /* the pins of vdd are not joined, whatever asks for it at a lower priority */
# @SELECT-NET(name="clk*", recursive=true) => @ROUTE-NET   /* as a house-style package writes it, with nets chosen by a rule */
```

- これらのキーワードはどの接続を配線として描画するかを指定し、どこで分岐しどこに黒丸を置くかは指定しない。それを決めるのはソルバーである。
- **ROUTE-NET** は1つのネットのピンを1つのツリーに結ぶ：そのネット上の素子のピン、および `::net` がそのネットである仮想部品のピン（すなわちそれで埋められたロールに束縛されたピン；12.1）である。1つのスロットがありネットをとる。セットが渡された場合はメンバーごとに処理され（5.2.1）、バスにはならない。
- **ROUTE-OBJECT** はいくつかのオブジェクトのピンを結ぶ：それらのピンのうち2つ以上が共有する各ネット上で、それらのピンを1つのツリーに結ぶ。1つのスロットがありオブジェクトのセットをとり、その入力をそのまま次へ渡す。インスタンスまたはバンドルはそのピンを表し、端子はそのピンを表し、適用オブジェクトはそのロールを埋めるオブジェクトを（グループのメンバーと同様に最も下位のオブジェクトまで；11.5）表し、シンボルを持つ適用オブジェクトはさらに自身のピンも表す（各ピンはその束縛するロールのネット上；12.1）。ロールを埋めるネットや点のようにピンを持たないオブジェクトは何も追加しない：ネット全体を描くにはROUTE-NETを用いる。したがって標準パッケージの定義は `{?left ?right ?tail} @ROUTE-OBJECT(priority="low")` のように、ネットの残りの部分を結ばずに自身の構造内の接続を描画できる。
- **UNROUTE-NET** と **UNROUTE-OBJECT** はピンを除外する：あるネットのピン、またはいくつかのオブジェクトのピン（ROUTE-OBJECTと同様に数える）が、ROUTE-NETおよびROUTE-OBJECTのツリーによって結ばれないようにする。
- **各ピンと各ツリーを個別に**：ROUTE-NETまたはROUTE-OBJECTが対象とするピンは、そのピンを対象とするUNROUTE-NETまたはUNROUTE-OBJECTがその文に勝たない限り（より高い優先度を持つか（14.8）、同じ優先度で8.5の位置順において後に書かれている場合でない限り）、その文のツリーに入る。比較は各ROUTE文ごとに行われるため、あるピンが `"low"` 優先度のROUTE-OBJECTのツリーから `"normal"` 優先度のUNROUTEによって除外されつつ、`"high"` 優先度のROUTE-NETのツリーには留まることができる。`"disabled"` を持つ文は除外される。これらの文は幾何的事実ではなく競合に参加しない（8.5）。それらはソルバーがどのピンを結ぶかのみを決める。
- **いつ**：これらのキーワードの文は8.2のステップ3から有効になる。例最後の行のようなそれらのルールは生成より前のステップ5で評価される：その条件は文のツリーを読み取り、標準パッケージの自動補完などの生成はそのルールが作ったツリーを参照する（10.2、10.4）。
- **書かれた配線は影響を受けない**：明示的なWIREはUNROUTEで除外されたネット上やピン上であっても書かれたとおりに描画される。すでに書かれた配線はそれらが触れるツリーの一部となり、ソルバーが残りを追加する。
- **ツリー**：各ROUTE-NETはそのネット上に1つのツリーを作り、各ROUTE-OBJECTはそれが結ぶ各ネット上に1つのツリーを作る。1つのネット上でピンを共有するツリー同士、または書かれた配線によって結ばれたツリー同士は1つのツリーとなる。そのツリーは位置順で最初の文のスタイルをとり、それらのスタイルが異なる場合はヒントが出される。離れた素子上の2つのROUTE-OBJECTのように、何も結ばない複数のツリーが1つのネット上にあってもよい。
- ピンのみが結ばれる：ピンのない端子はどのツリーにも含まれない（9.2.4）。空ノード上のピンはどのネット上にもないため（6.3）ROUTE-OBJECTはそれを結ばず、空ノード上に書かれた配線によってのみ接続される（13.1）。接続すべき点が2つ未満のツリーは何もしない。ピンが配線済みかどうか（10.2）は生成の前に、生成が加える仮想部品を含まないツリーから決まる。自分のピンを1つだけ持つネット、たとえば1つのゲートを駆動する入力は、点が1つのツリーとなるため、そのピンは配線済みではなく、自動補完は配線のないピンに与えるものをそれに与える。そのネットがそのレベルのポートへ結ばれる場合も同じである。そのようなネットをポートへ結ぶには、標準パッケージの `$IO_PORT @ATTACH &x` や `$IO_PORT_STUB` のようにポートタグをファイルに書く（12.4、16.3）。自動補完が加えるポートタグは数えない。
- **パラメータ**：ROUTE-NETとROUTE-OBJECTは `mode`（ソルバーへのヒント、WIREの値、デフォルト `"auto"`）、配線のスタイルパラメータ（13.1）、および `priority` をとる。UNROUTE-NETとUNROUTE-OBJECTは `priority` をとる。
- 注記：空の点リストを持つWIREがROUTE-NETを意味することはない。点リストはたまたま空になるセットに由来する可能性があり、空リストにすると意図せずすべてを接続してしまうため、これらは独立したキーワードとなっている。また本バージョンには省略可能なスロットもない（5.3）。
- **ソルバーによる書き戻し**：具体的なWIRE（その折れ曲がり点と `mode="straight"` 付き）、それらが分岐する名前付きの点、および `junction` が設定されているときは黒丸（13.2）が、ツリーのスタイルパラメータとともにソルバー自身のレコードに書き出される。ROUTE-NETおよびROUTE-OBJECTの文はユーザーの意図としてそのまま残り、次回の求解で再度計算される（第17章）。作成者が書いた配線の途中から分岐させるため、ソルバーはその配線を分割する（13.1）。
- **求解を行わないビューア**はビューアの判断によりフライラインを描くか何も描かない（原則 2.7）。
- ハウススタイルパッケージは例のようにセットとルールを用いてどのネットを配線として描くかを選択する。ネットをどう表示するかを決める専用のキーワードはない。
