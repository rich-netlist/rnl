## 4 構文

### 4.1 文法

レコードの文法をEBNFで示す。各生成規則は `name = expression ;` と書き、`|` は選択、`[ … ]` は省略可能、`{ … }` は0回以上の繰り返し、`( … )` はグループ化、二重引用符内のテキストはリテラル表記、`(* … *)` はコメントを表す。

```ebnf
record         = "@RNL" [ parameters ] set ;          (* the bracket touches "@RNL" *)
set            = "{" [ member ] { ";" [ member ] } "}" ;
member         = [ front-naming ] segment { naming } { "=>" segment { naming } } ;
front-naming   = ( "%" rnl-name | "$" rnl-name ) "=" ;
naming         = "=>" ( "%" rnl-name | "$" rnl-name ) ;
segment        = argument { argument } [ call { argument } ]
               | call { argument } ;
call           = keyword [ parameters ] ;          (* the bracket touches the keyword *)
keyword        = "@" keyword-name ;                (* upper case, or a declared alias *)
argument       = object [ "(" role-label ")" ] ;   (* the bracket touches the object *)
object         = reference | placeholder | point | set ;
reference      = "#" [ host-name [ subscript ] ] path
               | "&" host-name [ subscript ] path
               | "%" rnl-name [ places ] path
               | "%#" integer path                (* a number, in a record of the solver, 5.9 *)
               | "$" rnl-name [ places ] ;
placeholder    = "?" rnl-name [ places ] path
               | "?" path ;                        (* alone: in a symbol body, or in a general definition, 9.4; a path only in a general definition *)
places         = "{" place-item { "," place-item } "}" ;    (* touching the name, 5.2.3 *)
place-item     = place [ ":" place [ ":" integer ] ] ;
place          = integer | "end" [ "-" integer ] ;
path           = { ":" terminal-name [ subscript ] | "::" rnl-name } ;
subscript      = "<" subscript-item { "," subscript-item } ">"
               | "[" subscript-item { "," subscript-item } "]" ;
subscript-item = integer [ ":" integer [ ":" integer ] ] ;   (* unsigned, 6.11 *)
host-name      = name | string ;
rnl-name       = name | string ;
terminal-name  = name | string ;
role-label     = bracket-name | string ;
point          = "(" coordinate "," coordinate ")" ;   (* after white space, a comment, "{", ";", "=>" or "=", 3.8 *)
coordinate     = number | "_" | parameter-placeholder ;
parameters     = "(" [ value { "," value } [ "," named-value { "," named-value } ]
                     | named-value { "," named-value } ] ")" ;
named-value    = parameter-name "=" value ;
parameter-name = bracket-name | string ;
value          = number | string | "true" | "false"
               | "[" [ value { "," value } ] "]"
               | parameter-placeholder ;
parameter-placeholder = "?" rnl-name ;
```

- `name`、`bracket-name`、`keyword-name`、`string`、`number`、`integer` は第3章の定めに従って記述される。`name` はクォートなしの名前である（3.6）。`bracket-name` はロールの括弧内またはパラメータの `=` の前に置かれるクォートなしの名前であり、ASCII英字、数字、`_` および任意の非ASCII文字からなり、ASCII数字で始まらない（3.6）。`keyword-name` は文字、数字、`_` からなり、単語を `-` で連結する。`-` がそれに属するのは後に文字が続く場合のみである（3.3）。標準キーワードは大文字であり（3.6）、別名は任意の用字系の文字、数字、`_` からなり `-` を含まない（16.5）。`string` と `number` は3.7に定められており、`integer` は符号なし10進整数である。
- `rnl-name`、`host-name`、`terminal-name`、`role-label`、`parameter-name` はクォートしてもよく意味は同じであるが、ロールおよびパラメータ名の位置ではクォートされた名前は決して別名とならない（3.6）。キーワード、パラメータ名、ロール括弧内のスロット名、サブオブジェクト名、`true`、`false` は宣言済みの別名として記述してもよい。クォートなしの非ASCII別名は `@` の直後および括弧内でのみ用いられ、`::` の後の別名はクォートされる（16.5）。
- 添字はホスト名または端子名の直後に空白なしで続く。添字の内部には空白およびコメントを記述してよい（3.5、6.11）。どの名前が添字をとるかは4.2項目10に示す。
- パラメータ括弧はキーワードに密着し、ロール括弧はオブジェクトに密着する。空白またはコメントの後の `(` は点を開始する（3.5）。
- `=>` は、その後に何が続くかに応じてパイプまたは命名となる（4.2項目3）。
- 名前付きのプレースホルダは一般定義の定義本体内でのみ記述される（6.10）。オブジェクトの位置ではロールでありパスを持つことができ、リテラルをとる位置（パラメータ値、配列要素、点の座標）ではその定義のパラメータでありパスを持たない（6.10、9.4）。単独の `?` はシンボル定義本体（13.3）および一般定義の定義本体（9.4）に記述され、一般定義においてのみ `?::position` のようなパスを持つことができる。
- 括弧の外の任意の2つのトークンの間、およびメンバーの先頭には自由テキストおよびコメントを記述してもよい（3.3、3.4）。括弧の内部にも空白およびコメントを記述してよい。上記の文法にはこれらを省略している。
- 空のメンバー（`;;` など）は無視される。最後のメンバーの後の `;` は省略してもよい。

### 4.2 文法外の制約

1. セグメントは空であってはならない。
2. 1つのセグメントは最大1つのキーワードを持つ。`@RNL` はレコードの先頭にのみ現れる。
3. `=>` の直後に `%` 名または `$` 名が続き、その後に `=>`、`;`、`}`、またはメンバー末尾が来る場合、それは命名である。それ以外の `=>` は次のセグメントを開始する。そのセグメントはちょうど1つのキーワードを持ち、そこに書かれた名前はそのセグメントのオブジェクトとなる。パイプの最初のセグメントはキーワードを持たなくてもよく、その場合はちょうど1つのオブジェクトを持つ。したがって、結果に名前を付けてパイプを継続するには `=> %g0 => @PLACE(1, 2)` と書く。`=> %g0 @PLACE(1, 2)` では、`%g0` はPLACEのオブジェクトとなり、通常は未束縛であるため `%g0` が見つからないとして文が失敗する。診断では `=>` が抜けていないか尋ねる場合がある。
4. キーワードを持たないセグメントでは、各引数がそれぞれ独立した文となる：`{#M1 #M2}` 内の `#M1 #M2` は2つの文である。そのようなセグメントに名前を付ける場合（`%p =` または `=> %p`）、オブジェクトは1つだけでなければならない：`%p = #M1 #M2` ではなく `%p = {#M1 #M2}` と書く。
5. ロールはキーワードを持つセグメントの引数にのみ付与できる。パイプの後のセグメントではロールを付与できない。
6. 1つのセグメント内では、すべての引数にロールを付与するか、まったく付与しないかのいずれかでなければならない。同じロールを2度付与してはならない。
7. 定義をとるキーワードでは、キーワードが定義のスロット位置を固定する：ATTACHでは最初に書かれたオブジェクトであり、AS、SET-SYMBOL、SET-STYLE、SELECT-USAGE、SELECT-ANCESTOR-USAGEでは最後のオブジェクトである。SELECT-USAGEでは定義を省略してもよく、最後のオブジェクトが定義である場合にのみ定義スロットを埋める（10.1）。定義にはロールを付与せず、規則6の対象にもカウントしない（5.6）。
8. 命名には2通りの方法があり、併用してもよい。`name =` はメンバーの最初のトークンとしてのみ（前に自由テキストが来てもよい）記述でき、1つのメンバーに最大1回現れる。`=> name` はセグメントの後に、メンバーの末尾または次のセグメントの `=>` の前に記述し、1つのメンバーに複数個あってもよい。規則3がこれをパイプと区別する。
9. 位置指定のパラメータを先に書き、名前指定のパラメータを後に書く：1つでも `name=value` を書いたら、それ以降のパラメータはすべて名前指定でなければならない。位置指定できるのはシグネチャに位置順が記載されているパラメータのみであり、その順序に従う。同じパラメータを2度指定してはならない。
10. 添字が後続できるのは、`#` または `&` の後のホスト名、あるいは `#` 参照内の端子名またはポート名のみである。RNL名、ロール名、サブオブジェクト名は添字をとらない（6.11）。
11. 1つの参照の中で名前のリストに展開される添字は最大1つである（6.11）。

### 4.3 語順

- キーワードとそのパラメータは、オブジェクト群の中のどこに置いてもよい。オブジェクト同士の順序は意味を持つ。`#M1 #M2 @DISTANCE(…)`、`#M1 @DISTANCE(…) #M2`、`@DISTANCE(…) #M1 #M2` はすべて同じである。
- 各キーワードには1つの標準形式があり、ツールはその形式のみを書き出さなければならない。標準形式は標準語リストに記録されている（5.3）：キーワードの位置、どのパラメータを位置指定としどれを名前指定とするか、およびロールを明記するか否か。
- デフォルトの標準形式は、まずオブジェクト群、次にキーワードとそのパラメータ、最後に定義である。ATTACHは定義を最初に書き、次にキーワード、次にオブジェクト群を書く：`$GROUND @ATTACH &vss`。TABLEはキーワードを最初に書き、その後にテーブルを書く：`@TABLE layout: {…}`（14.11）。シグネチャに位置順が記載されているパラメータは位置指定で先に書き、その他は標準語リストの順序で名前指定で書く：`@PLACE(10, 20)`、`@ORIENT("R90")`、`@DISTANCE("bottom-to-top", min=4)`、`@TEXT("W/L", key="wl")`。PLACEは両軸が書かれた場合にのみxとyを位置指定とし、片軸のみの場合は `@PLACE(x=10)` のように名前指定で書く。WIREの `mode="auto"` のように取り除いても意味が変わらないパラメータは書かない。組み込みキーワードはロールなしで書き、ASとATTACHは一般定義が2つ以上のロールを持つ場合にすべてのロールを明記する。
- レイアウト書式：括弧内の各コンマの後に1つの空白を置く、パラメータの `=` の前後に空白を置かない、命名の `=` および `=>` の前後に1つの空白を置く、キーワードは括弧に密着させる、`{` とキーワードの間には `{ @…` のように空白を置く（2.3）、数値は同じ値として読み戻せる最短の10進表記で書く。
- **命名の標準形式。** パイプのないメンバーは先頭で命名し（`%x = statement`）、パイプのあるメンバーは末尾で命名して（`statement => … => %x`）命名対象のセグメントの直後に名前を置く。これにより、先頭の名前は常にメンバー全体を指すことになり、読み手がパイプのどのセグメントに名前が付いているのか推測する必要がなくなる。構文自体はどちらの形式も受け入れる。
- 「その形式のみ」が適用されるのは、ツールが新規に書き出す文に対してである。既存のレコードを書き換える際、ツールはユーザーが書いた文の順序を変更してはならない（16.4）。ユーザーが整形を求めた場合にのみ標準形式へ整える。
- 標準文については4.5に示す。

### 4.4 エラー例

以下はいずれもエラーである。コメントに理由を示す。

```rnl error
#M1 @PLACE (10, 20)    /* a bracket after white space is a point, and PLACE has no parameters (3.5) */
```

```rnl error
#M1 (left) #M2 (right) #M5 (tail) @AS $DIFFERENTIAL_PAIR_N    /* role brackets touch the object; a separate bracket is a point (3.5) */
```

```rnl error
#M2 @PLACE(62, 40) (MY)    /* the second bracket is a point, and its content is not a point */
```

```rnl error
&vss @ATTACH $GROUND    /* the definition of ATTACH is written first: $GROUND @ATTACH &vss */
```

```rnl error
R1 -> R2 {#R1 #R2} @ORDER("left-to-right")    /* ">" cannot be free text (3.3) */
```

```rnl error
#M1 @PLACE(1, 2), #M2 @PLACE(3, 4)    /* a comma does not separate statements: two keywords in one segment */
```

```rnl error
#M1 #M2 @SET-SYMBOL $NMOS    /* three objects, and SET-SYMBOL has two slots (5.2.1); write {#M1 #M2} @SET-SYMBOL $NMOS */
```

```rnl error
#M1 => #M2    /* the segment after a pipe has no keyword */
```

```rnl error
#M1 #M2 #M3 @DISTANCE("left-to-right", min=1)    /* three objects for two slots */
```

```rnl error
#M1 @PLACE(x=10, 20)    /* a parameter given by position after one given by name (4.2 item 9) */
```

```rnl error
{#M1 #M2} @ORDER(axis="x", direction="increasing")
/* ORDER has no axis: the axis and the direction are one parameter, direction, as in @ORDER("left-to-right") (14.3) */
```

```rnl error
#M1 @SET-SYMBOL($NMOS)    /* brackets hold only literals */
```

```rnl error
{#M1 #M2} @ALIGN(axis=y)    /* enumerations are written as strings */
```

```rnl error
%ax = (_, _);
#M1(left) #M2 %ax @AS $MIRRORED_LAYOUT /* roles are marked on all objects or on none */
```

```rnl error
$NMOS(symbol) #M1(target) @SET-SYMBOL    /* the definition is written last and is not marked with a role */
```

```rnl error
#R1(source) #R2(chain) #R3(chain) #R4(load) @AS $CHAIN_ROW    /* the same role is marked twice */
```

```rnl error
(0, 0) @PIN(terminal=1)    /* a pin cannot be written in the scene (13.4) */
```

```rnl error
#M1 @CURRENT("in")    /* CURRENT takes only terminals (15.2) */
```

```rnl error
&D<1:0>[1:0]    /* a name has at most one subscript (6.11) */
```

```rnl error
#XI0<1:0>:D<1:0>    /* one reference has at most one expansion (6.11) */
```

```rnl error
&D<_, 1>    /* a "<" directly after a name starts a subscript, and its content is not a subscript (3.5) */
```

```rnl error
%p<1, 2>    /* RNL names take no subscript; a point is written (1, 2) (6.11) */
```

### 4.5 標準文

標準文とは、標準形式の文のトークン間に自由テキストを補い、文章として読めるようにしたものである。標準文は記述ガイドや、文に語句を追加・削除する整形ツールで使用される。自由テキストは意味に影響しないため（3.3）、これらの文はあくまで提案であり、ユーザーや言語モデルはこれを使っても、使わなくても、他の語句を書いてもよい。

- **事実。** 文は実行すべき操作ではなく、図面において成り立つ事実を述べる。主語としてオブジェクトが先頭に来て、キーワードが述語（動詞または名詞）として働き、パラメータがその値を表す。追加されるのは `is`、`are`、`has`、`is at`、`there is` のようなつなぎの語句のみである。`#M1 @SET-SYMBOL to $NMOS` のように、一部の文は操作のように読める形となる。
- **語句は文のみから決まる。** ツールが生成する語句は、キーワード、パラメータ、オブジェクトの数と種別、および文が書かれたレベルのみに依存し、回路の意味には依存しない。例えば `is` と `are` の使い分けはオブジェクトの数に従い、片軸のみが指定された場合は `the x of` が書かれ、選択の候補の言い回しはスコープと選択される種別に従う（付録 B）。これはツールが文を生成する仕組みであり、ユーザーを制約するものではない。
- **文が意味しないことを表す語句は書かない。** `must`、`required`、`only` といった語は書かず、向きを表す語はパラメータがその向きを持つ場合にのみ書く。読み手は文中の語句を額面どおりに信じやすいため、記述ガイドはこの点について注意喚起すべきである。
- **補足説明。** 読み手は向きコードや軸を知らない場合がある。キーワードの後ろに `, i.e., …` を添えて、`#M2 @ORIENT("MX"), i.e., flipped upside down` のようにそのコード自体の意味を説明してもよい。
- **ORIENT-RELATIONとDISTANCE** は2つのスロットを持ち、`from A to B` のように読む。
- **選択**は常に候補から選ぶ形で `among <candidates>, @SELECT-…` と読む。スコープが `#` のとき、候補は `the <kind> in # only` となり、文が下位レベルに到達するときは `the <kind> at each level in # and below` となって、ルールが各レベルで評価されることを示す（10.1、10.4）。種別が特定できない場合は `for X,` と読む。
- **ASとATTACH。** ASはオブジェクト群が一体となってあるものを構成するときに用いる：`#M1(left), #M2(right) and #M5(tail) are treated @AS $DIFFERENTIAL_PAIR_N`。ATTACHはオブジェクトにあるものを付け加えるときに用いる：`$GROUND is @ATTACH to &vss`（9.4）。
- **パイプ。** 次のセグメントは直前のセグメントの結果を参照する。英語では（AS、ATTACH、または単一オブジェクトの後は）`it`、（選択の後は）`they` を用いる。パイプ内の名前には `… => named %pout` のように `named` を前置するが、構文上は依然として命名である（4.2項目3）。
- **命名。** 単一文の名前は先頭に書く（4.3）。AS文に名前が付く場合、英語では `are` を省く：`%dp = #M1(left), #M2(right) and #M5(tail) treated @AS $DIFFERENTIAL_PAIR_N`。
- **セットの名前。** セットを参照する名前は、`$` 名なら `_SET`、`%` 名なら `_set` で終わるようにすべきである（`$GROUND_FILL_SET`、`%bias_set` など）。標準パッケージもこれに従っている。
- **`each` は使わない。** `each` のような語は書かない。セットが全体として適用されるかメンバーごとに適用されるかは定義のロールリストに依存するため、標準文ではどちらであるかを明示しない。
- **他の言語。** 本標準は標準文を英語で示す。他言語での文は、`alias-zh`（中国語用）のようなその言語の別名パッケージの別名を用い、そのドキュメントに従う（16.5）。その言語の句読点の後ろであっても、`@` の前には依然として半角空白が必要である（2.3）。

各キーワードの標準文は付録 B に一覧を示す。
