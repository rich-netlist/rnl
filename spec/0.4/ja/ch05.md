## 5 オブジェクトと文

### 5.1 オブジェクト

- キーワードを持つすべての文は、1つのハンドルと複数の事実からなる新しいRNLオブジェクトを作る。`{…}` もまた新しいオブジェクトであるセットを作る（5.2）。
- 参照（`#M1`、`&vss`、`%x`、`$X`、端子、またはサブオブジェクト）はオブジェクトを作らず、既存のハンドルを取り出す。複数のメンバーを返すメンバー位置指定は新しいセットを作る（5.2.3）。単独の `#M1` も1つの文であり、事実を持たないM1を与える。単独の `#` は事実を持たないこのレベルを与える。
- ハンドルとは記述される実体そのものである：ホストのインスタンス・ネット・端子・レベル、あるいはRNLが作った点・配線・セット・適用オブジェクト・制約など。ハンドルが別のRNLオブジェクトになることはない。
- 文のオブジェクトは、新しいハンドルを持つ（WIRE、図形、`{…}`、選択、AS、ATTACH、制約など、文が生成する場合）か、入力のハンドルを保持してそれに新しい事実を追加する（PLACE、ORIENT、SET-SYMBOL、SET-STYLE、GROUP、CURRENTなど、文が変更する場合。ADD-TOとREMOVE-FROMは対象セットのハンドルを保持する）。どちらであるかはシグネチャが定める（5.3）。WIREはネットを受け取ったときは生成し、配線を受け取ったときは変更する（13.1）。
- 同じ内容の2つの文（2つの `#M1 @PLACE(1, 2)` など）は2つのオブジェクトである。それらの事実は互いに矛盾せず、ともに有効になる。
- 事実はそれを作る文において1度だけコミットされる（5.4）。レベルが有効になるとき、1つのハンドルに関するすべての事実が統合され、矛盾は1.5項目3に従って処理される。
- プロパティは事実である：位置、向き、シンボル、スタイルはそのオブジェクトに関する事実であり、上書きされる固定のプロパティ欄があるわけではない。レベルが有効になるとき、1つのハンドルに関する事実は最終的な値へと統合される：PLACEのxとyは幾何的事実として（5.8、8.5）、シンボルとスタイルは外観キューを通じて（8.3）。
- ハンドルの種別はそれがどこから来たかによって決まる：ホストオブジェクトはホストから、RNLオブジェクトはそれを作る文から種別を得る。各スロットが受け取る種別はシグネチャが定める（付録 A）。誤った種別のオブジェクトを受け取った記述は失敗する。テキスト読み込み時に検査できるものはその時点で検査され、後になって初めて判明するもの（適用オブジェクトがシンボルを持つか、定義のロールなど）はレベルが有効になるときに検査される（7.1）。

オブジェクトの種別：

| 種別 | 生成元 | 描画 |
|---|---|---|
| level（レベル） | ホスト、`#` | しない |
| instance（インスタンス） | ホスト、`#M1` | 自身のシンボルで描画 |
| terminal（端子） | ホスト、`#M1:d`、`#:inp`（6.4）。適用オブジェクトは端子を持たない | それを束縛するピン位置に描画（9.2.4） |
| pin（ピン） | 描画されるオブジェクトのシンボルのPIN（9.2.4）。ピンに名前がある場合は `#X1::vdd_t` | シンボル上の1点として描画 |
| net（ネット） | ホスト、`&vss` | しない。配線とラベルは独立したオブジェクト |
| point（点） | `(x, y)` | しない。接続点の黒丸は点に適用した `$JUNCTION`（13.2） |
| wire（配線） | ネットを受け取ったWIRE。netスロットがセットを受け取った配線はバス。配線を受け取ったWIREはそれを書き換える（13.1） | する |
| label（ラベル） | オブジェクトに取り付けられたTEXT。keyがある場合はそのオブジェクトのサブオブジェクト `object::key`（13.3） | する |
| bundle（バンドル） | BUNDLE（11.8） | メンバーの代わりに1つとして描画 |
| annotation（注釈） | シーン内の図形（LINE、RECTANGLE、CIRCLE、ELLIPSE、ARC、BEZIER）、点に取り付けられたTEXT（13.4）、またはANNOTATIONで描画されるシンボル（13.5） | する |
| usage（適用オブジェクト） | AS、ATTACH（9.4） | シンボルを持つ場合のみ（その場合は仮想部品；第12章） |
| constraint（制約） | ALIGN、ORDER、DISTRIBUTE、DISTANCE、ORIENT-RELATION、TABLE（第14章） | しない |
| set（セット） | `{…}`、選択、UNION、1つずつの生成の結果（5.2、第10章） | それ自体は描画しない。メンバーは個別に描画 |
| definition（定義） | DEFINE-SYMBOL、DEFINE-STYLE、DEFINE（第9章） | しない。使用された箇所でのみ作用 |

これらの種別のうち、instance、terminal、pin、net、point、wire、label、bundle、annotation、usage には種別名があり（5.3）、ラベルと注釈を問わずすべてのTEXTを包含する `text` にも種別名がある。シグネチャがその他をどう名指すかは付録 A に示す。

このほか、親オブジェクトと名前をハンドルとするサブオブジェクト（6.5）、および失敗オブジェクト（第7章）がある。

### 5.2 セット

- `{…}` はセットオブジェクトを作る。そのメンバーは順序を持つ。セットには名前を付けることができ（`%pair_set = {#M1 #M2}`）、他の文から名前付きセットへメンバーを追加したり削除したりできる（5.2.2）。
- セットは重複するメンバーおよび記述された順序を保持する（`{#M1 #M2 #M3 #M1}` など）。2つのメンバーが同じメンバーであるかはハンドルで判定される：別々に書かれた2つの `{…}` は、内容が等しくても2つの異なるハンドルであり同じメンバーではない。
- **参照は1段階展開される**：セット内の参照がセットを指す場合、その場所にそのセットのメンバーが展開される。したがって `{%a_set %b_set}` はa_setのメンバーの後にb_setのメンバーが続く。結果がセットになる文（選択など）や、添字が展開する参照のリスト（`&D<7:0>` など；6.11）についても同様である。重複を除くには `%a_set %b_set @UNION` と書く（5.2.2）。
- **直接書かれた `{…}` はそのまま保持される**：セット内に直接書かれた `{…}` は1つのメンバーとして保持される。したがって `{{%a_set} {%b_set}}` は2つのセットからなるセットである。
- **裸で並べたオブジェクトも展開される**：1つのスロットを持つキーワードが波括弧なしで複数のオブジェクトを受け取った場合、それらは `{…}` に書かれたのとまったく同じようにまとめられるため（5.2.1項目3）、その中にセットがあれば展開される。`%bias_set = {#R1 #R2 #R3}` とテキスト `%lbl` の後で：
  - `%bias_set %lbl @ALIGN("x")` は `{%bias_set %lbl} @ALIGN("x")` と同じである。
  - 唯一のオブジェクトであるセットはそれ自体として使用される：`%bias_set @ALIGN("x")` はR1、R2、R3を整列させる。
- **項目（item）**：セットは記述された順序でその項目も保持する（セット内に書かれた1つのオブジェクト、直接書かれた `{…}`、またはセットへの参照）。本標準が項目数を数える箇所（ALIGN・ORDER・DISTRIBUTEのメンバーリスト（14.1）、ASSERT-TOPOLOGYのメンバー（15.4）、および5.2.1項目2の分解）では、1つのオブジェクトは1項目となり、1つの項目としての `{…}` またはセットへの参照はその項目位置における最内メンバーのそれぞれを表す（ASSERT-TOPOLOGYではそれらからなる1つのブラックボックスを表す）。ADD-TOは末尾に1項目を追加し、REMOVE-FROMはすべての項目から該当オブジェクトを削除する（5.2.2）。選択、UNION、または1つずつの生成によって作られたセットはメンバーごとに1項目を持ち、添字が展開するリスト（6.11）およびメンバー位置指定がとるセット（5.2.3）も同様である。それ以外のすべての箇所では、セットは上記のとおり1段階展開されたメンバー列を意味する。したがって `{%bias_set %lbl} @ALIGN("x")` は2項目（1項目目がR1〜R3、2項目目がテキスト）を持ち、R1、R2、R3のそれぞれにテキストのx座標を与える（14.1）。
- セットの内容は、選択と同様にそれを使用するフェーズで計算される：初期内容、およびメンバーを追加・削除する文の中の選択は、そのフェーズが始まる前の状態で評価され、追加と削除は記述順（位置順；8.5）に適用される。そのため、前方に書かれた使用箇所もすべての追加・削除の結果を参照する（1.5項目1）。また、同じセットがフェーズ間で異なる内容を持つことがある：オブジェクトを生成するルールはそのセットを生成オブジェクトなしで参照し、スタイルルールは生成オブジェクトを含んだ状態で参照する（8.2）。

  注記：内容を単一のステップで1度だけ計算しないのは、もしそうすると選択に名前を付けただけで結果が変わってしまうためである：`%g_set = # @SELECT-USAGE $GROUND; %g_set @SET-STYLE $grey` は生成されたグラウンドを取り逃すが、名前を付けずに同じ選択を書けば見つかってしまう。名前は単にオブジェクトを指す別名にすぎない（1.5項目5）。

#### 5.2.1 オブジェクトとスロット

文に書かれたオブジェクトは以下のようにシグネチャのスロットに対応付けられる。

1. **ロールが付与されている場合**：ロールを付与されたオブジェクトは分解されず、そのままそのロールに入る。1つの文内ではすべてのオブジェクトにロールを付与するか、まったく付与しないかのいずれかである。
2. **単一セットの場合はまず1段階分解する**：ロールが付与されておらず、文全体でオブジェクトが1つだけあり、それがセットである場合、そのセットはまず1段階だけその項目群へ分解される（5.2）。TABLEは例外であり、そのスロットはテーブルの外側のリストとしてセットをそのまま受け取る（14.11）。定義およびパイプから渡された結果もオブジェクトの1つに数える。したがって `{#M1 #M2} @DISTANCE(…)` は `#M1 #M2 @DISTANCE(…)` になる一方、`{#M1 #M2} @SET-SYMBOL $X` は2つのオブジェクト（セットと定義）であるため分解されない。
3. **シグネチャとの照合**：
   - 複数のスロットを持つキーワード（定義も1つのスロットをとる）：オブジェクト数はスロット数と等しくなければならず、順に対応する。そうでなければ文は失敗する。ASとATTACHでは、ロールリスト末尾のセットロールを未指定のまま残すことができる（9.4）。
   - 1つのスロットを持つキーワード（PLACE、ORIENT、ALIGN、ORDER、DISTRIBUTE、GROUP、定義をとるSELECT-USAGEおよびSELECT-ANCESTOR-USAGEを除く各選択（5.6）、および定義本体をスロットとする各定義キーワード）：単一のオブジェクトはそのままスロットに入り、複数のオブジェクトは1つのセットにまとめられる（その際、参照されたセットは1段階展開され、直接書かれた各 `{…}` は1メンバーとして保持される）。オブジェクトが項目2によって分解された唯一のセットの項目群である場合、スロットはそのセット自体を受け取る。
   - 唯一のオブジェクトが空セットである場合：
     - 単一オブジェクトをとるスロットはその処理を0回行う：何も起きず、何も失敗しない。名前は通常どおり空セットに束縛され、その名前を使う文も何もしない。
     - 単一オブジェクトをとるスロットに対して空セットを直接記述すると（`{} @PLACE(1, 2)` など）、警告が出る。選択やルールから得られた空セットには警告が出ない：`recursive=true` のルールは下位の各レベルでも評価されるため、その種別のオブジェクトを持たないレベルがあるのは正常だからである。ユーザーが書いた選択がいずれの評価レベルでも何も選択しなかった場合、実装は1回警告を出してもよい（条件が誤っている可能性が高い）。
     - セットをとるスロットは空セットを受け入れる（`@DEFINE(roles=["a"]) {}` の空の定義本体や、メンバーのない制約など。後者は自明に満たされる）。例外はBUNDLEとWIREのnetスロットであり、これらはセットから新しいオブジェクトを作るため、空からは作れず文が失敗する（11.8、13.1）。
     - オブジェクトを1つも持たない文（単独の `@PLACE(1, 2)` など）はシグネチャに一致せず失敗する。
4. **スロット内のセット**：
   - 単一オブジェクトをとるスロットは、メンバーごとに1回ずつその処理を行う。各メンバーが独立した記述となり、結果はその結果のセットになる。メンバー自体がセットである場合、さらに分解されてメンバーごとに処理される。唯一の例外はPRIORITYであり、GROUPが付与されたセットが渡された場合はそのグループ自体に作用する（11.5、14.8）。
   - セットをとるスロットはセット全体をそのまま受け取り、単一オブジェクトは要素1つのセットとして受け取る：`#M3 @ROUTE-OBJECT` は `{#M3} @ROUTE-OBJECT` である。
   - DISTANCEの各スロットはオブジェクトまたはセットを受け取る。セットはその各メンバーを表し、DISTANCEは一方のスロットの各メンバーを他方のスロットの各メンバーと関連付け、各ペアにつき1つの制約を作る（14.5）。両方のスロットがともにセットを受け取れるのはこのキーワードだけである。
   - 1つの文において、単一オブジェクトをとるスロットのうち2つ以上が複数メンバーを持つセットを受け取ることはできない。2つ以上が受け取った場合、文は失敗する（メンバーを順に対にする解釈と全組み合わせをとる解釈の双方が成立し、意味が一意にならないため）。

| 記述例 | 結果 |
|---|---|
| `{#M1 #M2} @SET-SYMBOL $X` | 2オブジェクトであり分解されない。instanceスロットがセットを受け取り、M1とM2のそれぞれにシンボルが設定される |
| `#M1 #M2 @SET-SYMBOL $X` | 2スロットに対して3オブジェクト：文は失敗する |
| `{#M1 #M2} @DISTANCE(…)`、`%pair_set @DISTANCE(…)` | 唯一のオブジェクトがセットであり分解される：M1からM2への距離 |
| `%a_set %b_set @DISTANCE(…)` | 各々がセットである2オブジェクト：a_setの各メンバーからb_setの各メンバーへの距離（14.5） |
| `{#M1 #M2} @ALIGN("y")`、`#M1 #M2 @ALIGN("y")` | ALIGNは1スロットを持ち、{M1 M2} を受け取る |
| `%bias_set %lbl @ALIGN("x")`（`%bias_set = {#R1 #R2 #R3}` のとき） | 裸のオブジェクト群が `{%bias_set %lbl}` としてまとめられる：2項目（1項目目がR1〜R3、2項目目がテキスト）であり、R1、R2、R3のそれぞれがテキストのx座標を得る（14.1） |
| `{%bias_set} %lbl @ALIGN("x")` | 同じ2項目：R1、R2、R3のそれぞれがテキストのx座標を得る |
| `{%bias_set} @ALIGN("x")`、`{{#M1 #M2 #M3}} @ALIGN("y")` | 唯一のオブジェクトがセットであり、その1項目へ1段階分解される（項目2）。その項目がセットであるためそのままスロットに入り、R1・R2・R3、またはM1・M2・M3を整列させる |
| `%pair_set @PLACE(10, 20)` | スロットがpair_set自体を受け取り、メンバーごとに配置する：両メンバーとも (10, 20) になる。セット自体には位置がない（14.1） |
| `%a_set %b_set @PRIORITY("disabled")`（両セットともGROUP付き） | 裸のオブジェクト群が `{…}` 同様に展開される：PRIORITYは各メンバーを受け取り（種別誤りで）失敗する。2つのグループを無効化するには、それぞれにPRIORITYを書く（11.5、14.8） |
| `{#M1 #M2} @SET-SYMBOL $X => @ALIGN("y")` | パイプの結果が唯一のオブジェクトとなってALIGNに入り、M1とM2を整列させる |
| `{#M1 #M2} @SET-SYMBOL $X => #M3 @DISTANCE(…)` | 2オブジェクトであり分解されない。`from` スロットがセットを受け取り、M1からM3、およびM2からM3への距離となる（14.5） |
| `# @SELECT-NET(…) => $PULL_DOWN @ATTACH &vss` | 3スロット（2ロールと定義）に対して3オブジェクト。第1ロールが単一ロールであるため、選択されたネットごとに1回ずつ、毎回第2ロールにvssを入れて定義が適用される |
| `# @SELECT-INSTANCE(type="nmos") => @ORIENT("MY")` | 1つずつ鏡像反転される。NMOSがなければ0回実行され、何も起きない |
| `# @SELECT-INSTANCE(name="Q*") => @SET-SYMBOL $NPN` | 2オブジェクトであり分解されない。BJTがなければ0回実行され、何も起きない |
| `#R1 {#R2 #R3} #R4 @AS $CHAIN_ROW` | 4スロット（3ロールと定義）に対して4オブジェクト。セットロール `chain` が {R2 R3} を受け取る（9.4） |
| `&D<7:0> @WIRE {…}` | 2オブジェクトであり分解されない。netスロットはネットのリスト全体を受け取り、1本のバスを作る（13.1） |
| `#XI0<3:0> @ALIGN("y")` | 唯一のオブジェクトが添字の展開リストであり、分解される：4つのインスタンスを整列させる（6.11） |

- メンバーが少なすぎる制約は自明に満たされ、失敗しない（1メンバーのALIGNなど；第14章）。
- セット自体には位置がない（14.1）。その `::position` はメンバーの位置のセットである（6.5）。制約内のシンボルを持たない適用オブジェクトはそのメンバーを表す（14.1）。オブジェクト群を1つの場所として他のオブジェクトと関連付けるには、定義本体内でそれらを適用オブジェクト自身の点に結びつける定義のメンバーにして（9.4）、`%u::position` を制約する。セットを他のオブジェクトの片側に保つにはDISTANCEに渡す（14.5）。
- 定義のロールには単一ロールとセットロールがある（9.4）。ロールリストに `"{name}"` と書かれたロールはセットロールであり、セット全体を受け取る。その他のロールは単一ロールであり、セットが渡された場合はメンバーごとに1回ずつ定義が適用される。

#### 5.2.2 メンバーの追加・削除、および重複

- `X @ADD-TO S` はセットSの末尾にXを追加し（XがセットのときはXのメンバーを追加）、`X @REMOVE-FROM S` はSからそれらのメンバーのすべての出現を削除する。対象が末尾に書かれるため、パイプで選択を渡すことができる：`# @SELECT-NET(name="vss") => @ADD-TO %gnd_set`。
- 対象はセットでなければならず、単一オブジェクトがセットに包まれることはない。`%tail = #M5` の後で `#M3 @ADD-TO %tail` と書くと、M5はセットではないため失敗する。
- 追加と削除は位置の順序で適用される（1.5項目2）。あるレベルで評価されるセットはそのレベルのメンバーのみを保持する（10.3）。
- `%a_set %b_set @UNION` は重複のない新しいセットを、初出順に作る。2つのメンバーが同じであるかはハンドルで判定される。
- 元のセットを変更せずに新しいセットを作るには：連結は `{%a_set %b_set}`、和集合は `%a_set %b_set @UNION`、差集合は `%c_set = {%a_set}; %b_set @REMOVE-FROM %c_set` とする。
- セットは、それを作る文（波括弧内、UNION内、または選択のスコープ）に書かれたセット、およびADD-TOとREMOVE-FROMでそれに追加・削除するセットに依存する。依存関係が循環（サイクル）をなす場合、削除の有無にかかわらずエラーとなる：文を位置順（8.5）にたどり、循環を閉じる依存を持つ文が失敗し、その診断に循環全体が列挙され、他の文は通常どおり有効になる。したがって `%a_set @ADD-TO %b_set; %b_set @ADD-TO %a_set` は2番目の文が失敗し、一意な結果を持たない `%b_set = {%a_set}; %b_set @REMOVE-FROM %a_set` は削除文で失敗する。

#### 5.2.3 メンバー位置指定

```rnl
%row_set = {#M1 #M2 #M3 #M4};
%row_set{1} @PLACE(0, 0);                                         /* M1 */
%row_set{1} %row_set{end} @DISTANCE("left-to-right", exact=12);   /* from M1 to M4 */
%row_set{2:end} @ALIGN("y")                                       /* M2, M3 and M4 */
```

- セットへの参照の直後に `{…}` を続けると、位置によってセットのメンバーを取り出す（`%a{1}`、`%a{end}`、`%a{end-1}`、`%a{2:end}` など）。これはセットに束縛された `%` 名および `$` 名の後ろ、ならびに一般定義の定義本体内のセットロールのプレースホルダの後ろ（`?ref{1}` など；9.4）に記述できる。
- **形式**：波括弧内には `,` で区切られた項目が並ぶ。各項目は `i`、`a:b`、または `a:b:s` であり、添字と同様に混在させてよい（6.11）。位置は正の整数、`end`、または `end-k`（kは符号なし整数）であり、sは1以上の符号なし整数である。波括弧内には空白およびコメントを記述してよい。
- **数え方**：位置は、そのセットに対するすべての追加と削除（参照より後に書かれたものも含む）の後のメンバー順序において1から数える（5.2）。したがって `%a = {#M1}; #M2 @ADD-TO %a` の後の `%a{2}` はM2である。メンバーは5.2のとおり1段階展開された上で数えられ、項目単位ではない：`%a = {%b_set %lbl}` の後の `%a{2}` は、b_setの2番目のメンバー、あるいはb_setが1メンバーのみならテキストである。`end` は最後のメンバーである。項目は記述順に展開されて連結され、重複は保持される。`a:b` はaからbまで（aがbより大きければ逆順）進み、`a:b:s` はbを超えない範囲で刻み幅sで進む。
- **単一またはセット**：単一の位置のみからなる1つの項目はそのメンバー自体を返す。それ以外はすべて、指定された位置のメンバーをその順に含む新しいセット（新しいセットオブジェクトであり、参照がオブジェクトを作る唯一の例；5.1）を返す。メンバー自体がセット（直接書かれた `{…}`；5.2）である場合はそのまま取り出される。
- **範囲外の位置**：セットに存在しない位置は何も返さない：単一のそのような位置は空セットを返し、リスト内では省略される。セットのメンバー数が記述時に未知である場合もあるため（1メンバーのALIGNなど；14.2）、これはエラーではない。
- **位置のみ**：参照の直後の波括弧は位置指定のみを保持する。`%a{#b}` は構文エラーである。参照の後にセットを書くには、`%a {#b}` のように間に空白を入れる（3.5）。
- **エラー**：
  - セットではないオブジェクト（インスタンスなど）に対する位置指定は（種別誤りで）失敗する。
  - 適用オブジェクトはセットではない：そのメンバーは `%dp1::left` のようにロールで取り出すため（6.5）、適用オブジェクトの後ろの位置指定はエラーとなる。
  - 選択の結果に対する位置指定は（選択が直接書かれていても名前に束縛されていても）エラーであり、項目・UNION・ADD-TO・REMOVE-FROMを通じて選択に依存するセットに対する位置指定もエラーである（10.4）。例えば `%s` が選択のときの `%a = {%s}` に対する `%a{1}` など。これらのメンバーはそれを使用するフェーズで評価されるまで判明しないためである（5.2、8.2）。

#### 5.2.4 別種別として渡されたオブジェクト

あるスロットがある種別を要求し、別の種別のオブジェクトが渡された場合、オブジェクトは次の表が定める場合にのみ変換される。それ以外の不一致は、たとえ意味が通じそうであっても、テキスト読み込み時の種別誤りエラーとなる（5.1、7.1）。オブジェクトは選択の余地なくそれが表すものへのみ変換される：描画側へ向かっては端子からそのピンへ、さらにそこから点へ、また描画されるオブジェクトからその位置へ。回路側へ向かってはピンからそれが束縛する端子へ、またピンまたは端子からそのネットへ。それ以外の取得には、サブオブジェクト（`::position`；6.5）または選択（10.1）を記述する。

| 渡されたもの ＼ スロットがとるもの | 点（図形） | 点またはピン（配線） | 位置（制約のメンバー） | ピン | 端子 | ネット |
|---|---|---|---|---|---|---|
| point（点） | = | = | = | 不可 | 不可 | 不可 |
| pin（ピン） | 1 | = | 1 | = | 8 | 9 |
| terminal（端子） | 2 | 3 | 2 | 3 | = | 10 |
| instance（インスタンス）、bundle（バンドル） | 不可 | 不可 | 4 | 不可 | 不可 | 不可 |
| usage（適用オブジェクト） | 不可 | 不可 | 5 | 不可 | 不可 | 不可 |
| text（テキスト） | 不可 | 不可 | 6 | 不可 | 不可 | 不可 |
| 中心指定で書かれた図形 | 不可 | 不可 | 7 | 不可 | 不可 | 不可 |
| その他の図形、wire（配線） | 不可 | 不可 | 不可 | 不可 | 不可 | 不可 |
| net（ネット） | 不可 | 不可 | 不可 | 不可 | 不可 | = |

「=」は同じ種別、「不可」は種別誤りエラー、数字は以下の変換を表す。ピンから、またはピンへの変換はオブジェクトのシンボルを必要とするため、シンボルが与えられた後に行われる（8.2）。それより前のステップでは記述されたとおりのオブジェクトが見えている。単一オブジェクトをとるスロットまたはロールにおいて、バスピンからの変換のようにセットを与える変換が生じた場合、その検査時点で文が失敗する（7.1）：その文は1つのオブジェクトで作られており、後から分解されることはない。ピンを受け取った配線はそのピン上で終端して接続され（10.2、13.1）、単にピンの座標を取得するわけではない。

1. **ピンから点または位置へ**：そのピンの位置。
2. **端子から点または位置へ**：項目3におけるそのピンの位置。
3. **端子からピンへ**：そのオブジェクトのシンボル内でその端子を束縛するピン（9.2.4）。該当するピンがない場合は文が失敗する（9.2.4）。複数ある場合はシンボル内で最後に書かれたピン。バンドルの端子については、バンドルのシンボルのピン（11.8）。
4. **インスタンスまたはバンドルから位置へ**：その原点 `::position`（6.5）。インスタンスは配線や図形の点には変換されない：原点で配線を終えたり図形を描いたりするには `#M1::position` と書く。
5. **適用オブジェクトから位置へ**：それ自身の点（14.1）。適用オブジェクトは配線や図形の点には変換されない：その点で配線を終えたり図形を描いたりするには `%u::position` と書く（6.5）。
6. **テキストから位置へ**：テキスト自身の位置（13.3）。
7. **中心指定で書かれた図形から位置へ**：その中心（13.4）。2点指定で書かれた図形、LINE、ARC、BEZIERは複数の点を持つため変換されない。
8. **ピンから端子へ**：そのピンが束縛する端子（9.2.4）。バスピンの場合はその端子群のセット。適用オブジェクトのピンや描画専用ピンのように端子を束縛しないピンはこれを持たず、文は失敗する。
9. **ピンからネットへ**：その `::net`（6.5）。束縛する端子のネット、または束縛するロールを埋めるネット。バスピンの場合はそれらのネットのセット。何も束縛しないピンはこれを持たず、文は失敗する。
10. **端子からネットへ**：その `::net`（6.5）。メンバーが異なるネットに接続されたバンドルの端子の場合は、それらのネットのセット（11.8）。

- PLACEは11.1が列挙するオブジェクトのみをとる：端子やピンはそのオブジェクトと一緒にのみ移動し、単独で配置することはできない（14.1）。
- セット自体は変換されない：単一オブジェクトをとるスロットはメンバーごとに処理を行い（5.2.1）、制約においてセットを保持する場所は各メンバーを表す（14.1）。
- 空ノード、すなわち単独の `&`（6.3）も変換されない：種別 `"net"` のロールおよびWIREのnetスロットはそれをそのまま受け取り、ネットをとる他のすべての場所はそれをネットの空セットとして受け取る。
- ネットは何にも変換されない：位置もピンも持たず、単一の端子を表すこともない。また、1つのオブジェクトが他種別の複数オブジェクトに変換されることもない：インスタンスが自身の端子群になることはない。これらには `#M1 @SELECT-TERMINAL` や `&en @SELECT-PIN` のような選択を書く（10.1）。
- 変換ではなく他所で規定されるもの：TEXTの取り付け先（13.3）、選択のスコープが選択種別へどう導かれるか（10.1）、および配線を受け取ったWIRE（13.1）。

### 5.3 文とシグネチャ

- 文は最大1つのキーワード、いくつかのオブジェクト、およびパラメータリストから構成される。
- 各キーワードはシグネチャを持ち、以下を宣言する：
  - オブジェクトの数、および各スロットの名前と受け取るオブジェクト種別。ASとATTACHでは、数は定義のロールリストの長さに定義自体のための1を加えたもの（ASでは末尾、ATTACHでは先頭）であり、種別はロールに宣言されたものである（9.4）。
  - パラメータ：その名前、型、必須か否か、許容される値、および位置指定で渡せる場合の順序。
  - 出力：新しいオブジェクト、入力のハンドル、サブオブジェクト、定義、またはハンドルなし。WIREはネットが渡されたときは新しい配線を返し、配線が渡されたときはその渡された配線を返す（13.1）。
  - 各入力がどのように取り込まれるか（5.4）、および失敗に対して厳格か許容的か（7.3）。
  - そのキーワードがどこに書けるか（下記の標準語リストを参照）。
- オブジェクト数は固定であり、可変個のオブジェクトはセットとして渡す。省略可能なスロットは存在しないが、以下の例外がある：ASとATTACHのセットロールは埋められなければ空セットになる（9.4）、SELECT-USAGEは定義を省略してもよい（10.1）、USE-PACKAGEは定義本体を省略してもよい（16.2）。定義も1つのスロットをとる。
- オブジェクトはロールまたは出現順によってスロットに対応付けられる（全員に付与するか、誰にも付与しないか）。同じロールは1度しか付与できない。パイプで渡されたオブジェクトは最初のオブジェクトとなる。ASとATTACHはそれをロール対応で照合し、定義のスロットには入れない（5.5）。スロットへの対応付けの詳細は5.2.1に示す。
- キーワードを問わず、文に書かれたオブジェクトにはロールを付与できる。ロール名はシグネチャ内のスロット名である：`#M5:3(to) #M1:3(from) @DISTANCE("left-to-right", min=1)` は順序どおりに書いた `#M1:3 #M5:3 @DISTANCE("left-to-right", min=1)` と同じである。キーワードのスロット名ではないロール名を書くと文は失敗し、無視はされない（原則 2.3、2.8）。1スロットのみのキーワードのオブジェクトにもロールを付与できるが、意味上の効果はない。
- ASとATTACHのパラメータは、定義のパラメータリストにあるもの（9.4）に加えて、1つの標準パラメータ `priority` である（14.8）。定義のパラメータに `priority` という名前を付けることはできない。
- **標準語リスト**：各言語バージョンは標準語の機械可読な一覧を公開しており、これは本標準の一部である。各キーワードが何を受け取りどのパラメータを持つかはこの一覧でのみ規定され、本文はその意味を説明する。付録 A はこの一覧から生成され、両者に矛盾がある場合は正誤表（erratum）の対象となる。インタプリタの検査、ドキュメント、エディタの補完、適合性テストの骨格、およびLLM向けの記述リファレンスはこの一覧から生成される。バージョン0.4では `rnl-words-0.4.json` として公開される。
  - この一覧はすべての標準語を保持する：シグネチャ付きのキーワード、スロット名、パラメータ名と値、レコードヘッダーのフィールド、種別名、サブオブジェクト名、`${…}` が読み取る属性名、スタイルプロパティ、および `true` と `false`。別名（16.5）はこの一覧の語に対して宣言され、バージョン検査および最も近い名前のサジェストもこの一覧を参照する。
  - この一覧はJSONファイルであり、JSON Schema `rnl-words-0.4.schema.json` が一覧自体の構造を記述する。ツールと本標準の保守者がこれを読み書きし、回路を記述する者が扱うものではない。すべての語にはそれを追加したバージョン `since` が付され、予約語も印付けられる（バージョン0.4では予約キーワードはない）。`removed` の下には、旧バージョンにあって本バージョンで廃止された標準語とその代替を説明する節番号が記載され、診断でそれを案内できるようにしている。ファイルが宣言するバージョンに存在しない語は未知の語として扱われ、診断はどのバージョンが必要かを示す（16.1）。
  - 一覧は各キーワードについて以下を記録する：
    - 各スロット：その名前、受け取る種別、単一オブジェクトかセットのどちらをとるか（5.2.1）、および取り込み方（5.4；これにより厳格か許容的かが決まる；7.3）。定義のスロット。ASとATTACHでは定義のロールリストに従う。
    - 各パラメータ：その名前、型（数値、文字列、真偽値、または要素型付きの配列。値が固定の場合はその値一覧）、必須か否か、デフォルト値、位置指定可能なパラメータの順序（それ以外は名前指定のみ）、および組み合わせ条件（PLACEの `x` と `y` の少なくとも一方が必須、RECTANGLEは中心形式と対角形式のどちらか一方のみ、など）。

    - 記述可能な場所：レベル内、シンボル定義本体内のみ（PIN）、ヘッダーレコード内のみ（VERSION、ALIAS、DEVICEなど）、パッケージファイルのヘッダーレコード内のみ（PACKAGE）。
    - 事実がどのように上書きされるか（5.8）：キーによる上書き（そのキーとともに）、幾何的事実として（8.5）、外観キューを通じて（8.3）、または加算。

- **組み込みキーワードのスロット名**：すべてのスロットには名前があり、それが付与可能なロール名となる。スロット名は標準語であり、キーワードと同様にバージョン管理される（名前の変更は非互換変更となる）。1つのキーワードのスロット同士は異なる名前を持つ。定義のスロットにも一覧および診断用の名前があるが、ロールとして付与することはできない（4.2項目7）。シグネチャと定義のロール宣言（9.4）の双方で使われる種別名は共通の1組であり、`instance`、`terminal`、`pin`、`net`、`point`、`wire`、`usage`、`bundle`、`text`、`annotation`、`label` である（付録 A）。

### 5.4 入力の取り込み方

| 取り込み方 | キーワード | 入力の事実 | 失敗扱い（デフォルト） | 名前 |
|---|---|---|---|---|
| 吸収（absorb） | 大半のキーワード | 出力へ引き継がれる | 厳格（strict） | 入れ子セット内の名前はそのセット内でのみ有効 |
| 封入（enclose） | DEFINE、DEFINE-SYMBOL、DEFINE-STYLE | 定義の内容となり、外へ渡されない | 許容的（tolerant） | ローカル。適用のたびにリネームされ、各適用オブジェクトが固有のものを持つ（9.4） |
| コミット（commit） | レコード `@RNL` | レベルに順次統合される | 許容的（tolerant） | レベルに公開され全レコードで共有される。束縛より前で参照可 |

- 1つのメンバーが生成するものは、その末尾のハンドルだけではなく、そのセグメント群および内部に入れ子になったセット群が作ったすべての事実である。それらはそれらを含むトップレベルのメンバーとともにコミットされる。
- レコード内のすべての文は、名前付きか否かにかかわらずコミットされる。その後に何をするかはオブジェクトに依存する：シーン内の記述は描画されるか求解に関与し、定義は利用可能になるだけでそれ自体は描画されず、参照および参照のみからなるセットは何の効果も持たない。通常の `{…}` 内の文もそれを含むメンバーとともにコミットされるため、`{ @LINE {…}}` の線分は描画される（13.4）。
- 定義の定義本体内の文はコミットされず、定義の内容となる。一般定義は適用されたときにのみ展開される（9.4）。
- 定義本体を持つUSE-PACKAGEも封入によって定義本体を取り込む：定義本体の文はパッケージの内容となり、レベルにはコミットされない。パッケージの名前がどう参照されるかは16.2に示す。

### 5.5 パイプと入れ子

- `a => @K(…)` は `a` の結果をKの最初のオブジェクトとする。ASとATTACHでは定義のスロットではなく最初のロールに入れる。結果がセットであっても依然として1つのオブジェクトである（5.2.1）。`=>` の後のセグメントはこのオブジェクトを位置でのみ受け取り、ロールを付与することはできない。
- パイプは逐次実行されるものではない。ハンドルによって連結された複数の記述へと展開される：各セグメントは直前のセグメントから生じたハンドルを記述し、メンバーごとに作用するセグメントは並列な複数の記述へと展開される（1.5項目1）。
- **セグメントの順序。** 各セグメントはそれぞれ固有の位置を持ち、記述位置が影響するあらゆる場面（1.5項目2）で、後のセグメントは前のセグメントより後に書かれたものとみなされる：キーによる上書き（8.4）、外観キュー（8.3）、解決順序（8.5）、描画順（11.6）、および配線の書き換え（13.1）。したがって `#M1 @SET-SYMBOL $A => @SET-SYMBOL $B` では、M1は `$B` で描画される。
- **失敗はそれに依存する記述にのみ波及する。** 記述が失敗する理由は2つだけである：それ自体が解釈できないか自己矛盾している、またはそれが使うハンドルが失敗した記述によって作られるはずだった。
  - `$GROUND @ATTACH &vss => @PLACE("20", 38) => @ORIENT("R90") => %g1` ではPLACEのみが失敗し（PLACEが数値をとるところに文字列を渡した；5.3）、グラウンド自体は作られ、ORIENTも通常どおり有効になる。
  - `#XI0<3:0> @BUNDLE(bad=1) => @PLACE(10, 20) => %s` ではバンドルが作られないため（BUNDLEにパラメータ `bad` はない）、PLACEは記述対象を失い同様に失敗する。
- 名前が何を束縛するか：先頭の `%x =` はパイプ全体の最後のハンドルを束縛し、`=> %x` はその左側のセグメントの結果（末尾なら最後のハンドル、途中なら `#M1 @AS $A => %a => @AS $B => %b` のようにそのセグメントの結果）を束縛する。PLACE、ORIENT、SET-SYMBOL、SET-STYLE、GROUPは入力のハンドルを保持するため、`$GROUND @ATTACH &vss => @PLACE(24, 38) => %g0` では名前 `%g0` はこの適用の適用オブジェクト、すなわちこのグラウンドとなる。ASとATTACHは新しいハンドルを作る：`#M1 @AS $A => @AS $B` の第2セグメントはM1ではなく第1セグメントが作った適用オブジェクトに対して `$B` を適用する（入れ子）。M1に2つの定義を適用するには2つの文を書く。名前の左側のセグメントが失敗したとき：それが入力ハンドルを保持する種別であれば名前は依然としてそのハンドルを指し（上記の `%g1` はグラウンド）、新しいオブジェクトを作る種別であれば名前は失敗オブジェクトを指す（上記の `%s`）。
- オブジェクトとして、文を保持するセットを記述することもできる（入れ子）。入れ子になったセット内で束縛された名前はそのセット内でのみ有効である。入れ子内の各文はそれぞれ独立した記述である：`{%a = #M1 @PLACE(1, 2); #M9} @ALIGN("y")` においてホストにM9が存在しない場合、ALIGNは失敗するがM1の座標はそのまま有効になる。
- 標準形式では文を平坦に書く：まずオブジェクトに名前を付け、他の文からそれを参照する。単一の文は先頭で `%x =` と命名し、パイプは `=> %x` と命名する（4.3）。

### 5.6 オブジェクトとしての定義

定義を使用するキーワードは定義をオブジェクトの1つとして受け取り、どのスロットがそれを保持するかはキーワードが固定する：ATTACHでは最初に書かれたオブジェクトであり、SET-SYMBOL、SET-STYLE、AS、SELECT-USAGE、SELECT-ANCESTOR-USAGEでは最後のオブジェクトである（SELECT-USAGEは省略可；10.1）。

```rnl
%ax = (_, _);
%w13 = &x @WIRE {#M1:1 #M3:1};
#M1 @SET-SYMBOL $NMOS;
%w13 @SET-STYLE $signal;
#M1(left) #M2(right) %ax(axis) @AS $MIRRORED_LAYOUT;
$GROUND @ATTACH &vss;
# @SELECT-USAGE $GROUND => @SET-SYMBOL $GROUND_SYMBOL
```

- 定義にはロールを付与せず、「全員に付与するか誰にも付与しないか」の対象にもカウントしない。定義もオブジェクトとして1つのスロットを占めるため、`{#M1 #M2} @SET-SYMBOL $X` は2オブジェクトである（5.2.1）。
- キーワードが定義のスロットを固定するため、`$` 名が定義とセットのどちらを指すかを知らなくても文を構文解析できる：`$GROUND_STUB @ATTACH $GROUND_FILL_SET` では前者が定義、後者がセットである。
- パイプによって定義を渡すことはできない：パイプで渡されたオブジェクトは第1スロットを埋め、ASとATTACHはそれを定義スロットの外でロール対応により照合するためである（5.5）。したがって `$GROUND @ATTACH &vss` を `$GROUND => @ATTACH &vss` と書くことはできない。
- 定義として、入れ子の無名定義を書くこともできる：`#M1 @SET-SYMBOL { @DEFINE-SYMBOL {…}}`。
- 一般定義は後方の文や別レベルに書かれている場合があるため、ASおよびATTACHのオブジェクト数、ロール名、パラメータはレベルが有効になるときに検査される（7.1）。

### 5.7 ハンドルと名前

- ホストオブジェクトのハンドル（インスタンス名、ネット名）はホストが与える。端子はインスタンスと端子番号からなるため、`#M1:1` と `#M1:d` は同じ端子である。
- RNLが作るものについては、それを作る文からハンドルが生まれる。他の文がそれを参照するには名前を通じるしかなく、番号で名前のないオブジェクトを参照するソルバーのレコードを除けば、名前がそれを見つける唯一の手段である（5.9）。名前のないオブジェクトは、それ自身の文の内部（パイプや入れ子）でしか使用できない。
- 1つの名前が2つのものを指すことはない：名前は1つのレベル内で1度だけ束縛される（6.6）。
- サブオブジェクトのハンドルはその親オブジェクトと名前であり、それ自身の名前を必要としない。
- 一般定義の展開で作られるローカルオブジェクトのハンドルはその適用オブジェクトとローカル名であり、外部からは `%c1::mid` のように記述する（9.4）。名前のない適用オブジェクトのローカルオブジェクトは診断では位置でのみ示され、ソルバーのレコードからのみ適用オブジェクトの番号を通じて `%#5::mid` のように参照できる（5.9）。
- 生成セットの個々のオブジェクトは名前を持たず、単独で参照することはできない：オブジェクトは種別や関連先のオブジェクトによって識別されるのではなく（自然キーは存在しない）、セットもインデックスによる参照を提供しない。

### 5.8 事実のキー

- キーを持つ事実はキーによって上書きされる：同じキーについては後の事実が有効になり、後のものが失敗した場合は前の有効な値が保持される。
- 幾何的事実が例外である：PLACEのxとy（各座標につき1つのキー）、およびORIENT（各オブジェクトにつき1つのキー、および各ピンにつき1つのキー；11.2）。同じキーに対して異なる2つの値が書かれた場合は競合となり8.5で解決される：同じ優先度なら後のものが採用され（キーによる上書きと同じ結果）、優先度が異なる場合は高い方が採用される。PLACEは指定された座標のみを変更し、一度も指定されない座標は自由のまま残る。
- すでに束縛された名前のもとで新たにオブジェクトを作ることはキーによる上書きではない：名前は1つのレベル内で1度だけ束縛される（6.6）。RNLが作ったオブジェクトを変更するには、`%g0 @PLACE(40, 38)` のようにそれを変更する文を書く。
- キーを持たない事実は加算される：互いに矛盾しないものはともに成り立ち、矛盾する場合は8.5で解決される。
- SET-SYMBOLとSET-STYLEはキーによる上書きではなく、外観キューを通じて有効になる（8.3）。
- VERSIONとPACKAGEはヘッダーレコードに1度だけ記述されるため（16.1、16.2）上書きされない：2つ目はエラーとなって失敗し、最初のものが有効になる。
- CURRENTは各端子につき1つのキーを持ち（15.2）、LAYERは各オブジェクトにつき1つのキーを持つ（11.6）。
- 適用オブジェクトはキーを持たない：1つの定義を複数回適用するとその回数分の適用オブジェクトが作られ、互いに上書きしない。同一の適用を2度書くと2つの適用オブジェクトが作られるため、`$GROUND @ATTACH &vss` を2回書くと2つのグラウンドが描画される。1つの適用オブジェクトに対してそれを変更する文（PLACEなど）が書く事実はキーを持ち、上記の規則に従う。
- オブジェクトの優先度はキーを持つ事実である。優先度同士が上書きし合う順序は14.8に示す。
- キー付きのTEXT（`key=`）は取り付け先オブジェクトとkeyの組ごとに1つのテキストであり、後のものがパラメータ単位で上書きする（13.3）。keyのないTEXTはキーによる上書きを受けず、書くたびに新しいテキストが追加される（13.3）。
- 配線はキーを持たない：2回書けば2本の配線になる（13.1）。配線を受け取ったWIREはそれを書き換える。この書き換えは「その配線」をキーとして持つため、後の書き換えが前の書き換えを置き換える（13.1）。
- 制約はキーを持たない。制約を変更するには無効化し（`"disabled"`；14.8）て新しい制約を書くか、テキストを編集する。

### 5.9 名前のないオブジェクトの番号

```spice fragment
* @RNL(type="header") { @VERSION("0.4"); @USE-PACKAGE(name="rnl-std-all", version="0.4")}
.model nch nmos level=1
.subckt amp in out vdd vss
M1 out in vss vss nch
R1 vdd out 10k
* @RNL {
*   #M1 #R1 @ALIGN("x");
*   &out @WIRE {#M1:1 (_, _) #R1:2};         /* %#1: the wire; %#2: the free point */
*   {#M1 #R1} @TEXT("${name}")               /* %#3: the label of M1; %#4: that of R1 */
* }
* @RNL(type="generated", priority="high", author="rnl-solver 0.1", hash="sig1:…", numbering="…") {
*   #M1 @PLACE(10, 0); #R1 @PLACE(10, 8);
*   %#2 @PLACE(12, 4);
*   %#1 @WIRE(mode="straight") {#M1:1 (12, 2) %#2 (12, 6) #R1:2};
*   %#3 @PLACE(13, 1); %#4 @PLACE(13, 9)
* }
.ends amp
```

- ソルバーのレコードは、下したすべての決定を書き戻せるよう、名前で到達できないオブジェクトを番号で参照する（14.8）。番号は `%#` に続けて符号なし整数を書いたもの（`%#3` など）であり、名前と同様に使われる：`%#5::pin` は適用オブジェクト `%#5` のシンボルのピンであり、`%#5::mid` はそのローカルオブジェクトの1つである。番号はそのオブジェクトを参照するだけであり、名前のようには束縛されないため、`%#3 = …` や `=> %#3` は構文エラーとなる（4.1）。
- **対象となるオブジェクト。** 固有の名前を持たず、かつ名前または番号を持つオブジェクトから `::` を通じて到達できない点、配線、ラベル、バンドル、注釈、および適用オブジェクト（6.5、9.4）。入れ子になったセット内でのみ束縛された名前は（ソルバーのレコードからは使えないため）名前として数えない。1つのソルバーレコードに対する対象オブジェクトは次の順序で並ぶ：
  1. そのレベルのauthoredレコード（`type="authored"`；2.8）のメンバー、およびそれらのメンバーが作る適用オブジェクトの定義本体内で作られたもの。これらはソルバーが見る状態のレベル、すなわち `type="generated"` のレコードを除いた状態で数えられ（2.8）、それらのレコードを含めてレベルを解釈するときも番号はそのまま保たれる。
  2. そのレコード自身のメンバー、およびそれらが作る適用オブジェクトの定義本体内で作られたもの。これらは、内部のすべての番号が解決できるものとして記述されたままのレコード上で数えられ、下記の検査が一致するかどうかによって番号は変わらない。

  制約およびセットには番号を振らない。ルールが1つずつ生成するオブジェクト（10.5）にも番号を振らない：ソルバーはそれらを明示的な文として書き出すため、それらは項目2に該当する。ソルバーの各レコードはそれぞれ自身の番号を持つ：項目1はすべてに共通であり、項目2はそのレコード自身のメンバーのみを数える。
- **順序。** authoredレコードは2.6の順序でたどる：そのレベル自身のテキスト、次に `scope` によって外部からそのレベルに書かれたレコード。1つのメンバー内では、オブジェクトはそれを作るトークン（点は `(`、その他はキーワード）の出現順に番号が振られる。1つのトークンがセットのメンバーごとにオブジェクトを作る場合（5.2.1）、セットのメンバー順に各オブジェクトに固有の番号が振られる。適用オブジェクトの定義本体内のオブジェクトはその適用オブジェクトの直後に定義本体の順序で番号が振られ、入れ子の適用オブジェクトについても同様に下っていく。番号は1から始まる。
- **記述場所。** 番号を書けるのは、`numbering` フィールドを持ち `scope` を持たない `type="generated"` のレコード内だけである（2.6、2.8）。それ以外の場所で番号を書くとエラーとなる（authoredレコードは名前でオブジェクトを参照する）。同一レコード内では、名前と同様にそれを作るメンバーより前で番号を参照してよい（6.7）。
- **検査。** `numbering` には番号付きオブジェクトがどのように作られたかの検査データが格納される。各番号につき順に1行ずつ以下が並ぶ：
  - オブジェクトを作ったレコードのメンバーまたは定義本体のメンバーのトークン列（全セグメントを含み；4.1、自由テキストとコメントを除き、1つの空白で区切ったもの）。ここでのトークンとは字句単位を指す：キーワード、参照（端子・サブオブジェクト・添字を含み空白なしで書いたもの）、記述どおりの文字列または数値、名前、`_`、あるいは `{ } ( ) [ ] , = ; =>` またはメンバー位置指定の一部（`:`、`end`、`-`；5.2.3）。したがって `&out @WIRE {#M1:1 (_, _) #R1:2}` は `&out @WIRE { #M1:1 ( _ , _ ) #R1:2 }` となる。
  - 適用オブジェクトの定義本体内のオブジェクトについては、その適用オブジェクトが番号を持つか否かにかかわらず同様に形成された適用オブジェクトの行が先に来、次にタブ、その後に定義本体での記述どおりの定義本体メンバーのトークン列が続く。
  - トークンがセットのメンバーごとにオブジェクトを作る場合は、続いてタブと、参照として表記されたそのメンバーのハンドルが続く：ホストのインスタンスまたはネットはその名前、端子は `#M1:1` のようにインスタンスと端子番号、ピンは `#X1::vdd_t` のようにオブジェクトとピン名（名前がない場合はその端子）、オブジェクトの位置またはkey付きテキストはオブジェクトの後に `::position` または `::` とkeyを続けたもの、RNLオブジェクトはレベルがそれに束縛している `%` 名（複数ある場合は元のセットで書かれた名前にかかわらず2.6の順序で最初に束縛されたもの）、そのような名前のないオブジェクトはその番号、あるいは適用オブジェクトのローカルオブジェクトである場合は同じ規則で作られた適用オブジェクトの参照に `::` とそのローカル名（定義本体内で複数ある場合は、セットに書かれた名前にかかわらず1つのメンバー内も含め最初に束縛された名前：`%p = (0, 0) => %q` なら `p`。複数の適用オブジェクトのローカルオブジェクトになっている場合は最初に適用された適用オブジェクトを通じたもの）を続けたもの。名前はASCII英字・数字・`_` のみからなる場合はそのまま書き、そうでなければ二重引用符で囲んで内部の各 `"` を二重化する（3.6）。例えば `%p = (0, 0); %q = %p; %s = {%q}` の後で `%s @TEXT("x")` が作る注釈の行は `%s @TEXT ( "x" )`、タブ、`%p` となり、検査値は `675df5171032726d` となる。`$D = @DEFINE(roles=["x"]) { %p = (0, 0) => %q }; %u = #M1 @AS $D; %s = {%u::q}` の場合、`%s @TEXT("x")` の行はタブと `%u::p` で終わり、検査値は `a8c9571193175903` となる。

  検査値は、これらの各行をUTF-8で改行（LF）終端して連結したデータのSHA-256の先頭16桁（小文字16進数）である。
- レコードの検査値がレベルと一致しない場合、そのレコード内の番号を使用する文は効力を持たず、そのような文が1つでもあればレコードに1つのヒント（「名前のないオブジェクトに対する求解結果が古い」）が出される。番号を使用しないレコードは `numbering` を持つ必要がない。レコード内の他の文は通常どおり有効になる（第17章）。最後の番号付きオブジェクトを超える番号はエラーである。
- 上記の例では、検査データは6つの番号につき各1行からなる：WIREメンバーが2回（配線と点）、TEXTメンバーが2回（`#M1` の後と `#R1` の後）、そして書き換え用のWIREがさらに2回（その中の座標として書かれた2つの点が、番号5と6を持つレコード自身のオブジェクトであるため）。求解を行わないビューアは、ソルバーが選んだ自由点、配線経路、および2つのラベルをそのまま描画する。
- `{#R1 #M1}` のように書き換えるとラベル3と4が入れ替わり、検査値が一致しなくなる。その結果、再び求解するまで番号付きの文は効力を持たなくなるが、M1とR1の位置はそのまま保たれる。ALIGNの書き方を変えたりM1を移動したりするだけでは番号は変わらない。
- 注記：この検査は名前のないオブジェクトがどのように作られるかのみを対象とする。素子の移動や、名前のないオブジェクトを作らない文の変更では番号は変わらない。そのようなオブジェクトを作るメンバーを挿入・削除・変更・並べ替えすると、再求解するまで番号が古くなる。ソルバーのレコードは通常、セットや定義を変更する文を含まないが、いずれにせよ項目1はそれらのレコードを除いて数えられる。
