## 11 配置と外観

### 11.1 位置：PLACE

```rnl
#M1 @PLACE(10, 20);
#M1 @PLACE(x=10)
```

- PLACEはオブジェクトに位置を与える。`x` と `y` の少なくとも一方を記述しなければならない。PLACEは記述された座標のみを設定する。各座標は最初は自由であり、記述されなかった座標は自由なまま残され、制約とソルバーによって決定される。
- PLACEが設定するのは座標のみであり、回転、鏡像反転、拡大縮小、または端子の向きは設定しない。向きはORIENTで設定する（11.2）。
- 1つのPLACEはx用とy用の2つの幾何的事実であり、競合時にはそれぞれ単独で破棄され得る（8.5）。パラメータ `priority=` はその優先度を与える（`#M1 @PLACE(12, 20, priority="high")` など、14.8）：位置指定のxとyが先に来て、名前指定のパラメータが後に続く（4.2項目9）。
- オブジェクト：インスタンス、適用オブジェクト（自身の点による、14.1）、バンドル（11.8）、点、TEXT（注釈およびラベル；PLACEはテキスト自身の位置を設定する、13.3）、および原点 `::position`（中心で書かれたRECTANGLE、CIRCLE、ELLIPSEの中心を含む）。PLACEは他の図形をとらない。それらを動かすにはそれらの点を動かす（13.4）。一般定義の定義本体内では、その座標は適用オブジェクト自身の点からのオフセットとなる（9.4）。シンボル定義本体内では、PLACEは `?` に取り付けられたTEXTのみをローカル座標で配置する（9.2.2）。
- 出力は入力のハンドルを保持する（5.1）。
- オブジェクトとしてセットが渡された場合はメンバーごとに配置される（5.2.1）：`%pair_set @PLACE(10, 20)` は両方のメンバーを (10, 20) に置く。セットは自身の位置を持たない（14.1）。
- 座標の軸、単位、小数および許容差については11.7を参照。

### 11.2 向き：ORIENT

```rnl
%pair_set = {#M3 #M4};
#M2 @ORIENT("MY");          /* flipped left-right */
%pair_set @ORIENT("R90");   /* each member turns about its own origin and stays where it is */
#M5 @ORIENT(["R0", "MY"])   /* not turned, or flipped left-right: the solver chooses */
#M6::g @ORIENT("left")      /* M6 is oriented so that its gate faces left */
```

- オブジェクト：インスタンス、シンボルを持つ適用オブジェクト、バンドル、およびピン（下記）。シンボルを持たない適用オブジェクトへのORIENTは失敗する（12.1）。点、ラベル、図形、配線、ネットは受け入れられない。
- オブジェクトとしてセットが渡された場合はメンバーごとに向きが設定される（5.2.1）：各メンバーは自身の原点を中心に回転し、その場に留まり、各メンバーが1つの記述となる。セットが1つのブロックとしてまとめて回転するわけではない。セット全体をまとめて回転させる機能は提供されない：セットは位置を持たないためである（14.1）。
- シンボルを持つ適用オブジェクトは自身の点を中心に回転する。自身の向きを持ち、そのロールを埋めるオブジェクトとともに回転することはない（12.1）。また、定義本体が描画・配置するものもそれとともに回転することはない（9.4）。
- **コードのリスト**（`["R0", "MY"]` など）は1つの事実を作り、そのオブジェクトが列挙された向きのいずれかを持つときに成り立つ。これは全体として採用または破棄され（8.5）、ソルバーがコードの中から1つを選択する。リストには少なくとも1つのコードが含まれる。1コードのリストはそのコード単独と同じである。ソルバーは選択した向きを自身のレコードに単一のコードとして書き戻す（14.8）。作成者のレコードにあるリストはそのまま残り、次回の求解で再度選択される。求解を行わないレンダラでそのオブジェクトの結果を持たないものは、リストの先頭のコードで描画する。
- ORIENTがなければ制約はなく、ソルバーが選択する。求解を行わないレンダラは `"R0"` で描画する（8.5）。複数のオブジェクトの向き同士の関係（同じ向き、鏡像反転）はORIENT-RELATIONで記述する（14.9）。
- ORIENTは1つの幾何的事実であり、競合解決に参加する（8.5）。パラメータ `priority=` はその優先度を与える（14.8）。
- **向きコード。** 各コードは1つの向きを表す。表の8通りの綴りと下記の4つの語のみが受け入れられ、大小文字が区別される（3.6）。名前はVirtuosoのものであり、y軸上向き（11.7）においてその意味も同様である。等価な別綴り（MYにあたる `"MXR180"` など）や任意の角度は、単独でもリスト内でも受け入れられない：誤ったパラメータ値となり、ORIENTは失敗する。ツールが書き戻すのはこれら8通りのみであり、1回につき1つである。現在の向きからさらに回転させる相対形式は存在しない（第17章）。

  | コード | (x, y) の変換結果 | 意味 |
  |---|---|---|
  | `"R0"` | (x, y) | 回転なし |
  | `"R90"` | (−y, x) | 反時計回りに90°回転 |
  | `"R180"` | (−x, −y) | 180°回転 |
  | `"R270"` | (y, −x) | 反時計回りに270°回転（すなわち時計回りに90°回転） |
  | `"MY"` | (−x, y) | y軸に対する鏡像反転：左右反転 |
  | `"MX"` | (x, −y) | x軸に対する鏡像反転：上下反転 |
  | `"MYR90"` | (−y, −x) | MYの後、R90 |
  | `"MXR90"` | (y, x) | MXの後、R90 |

- **4方向の回転を表す語。** 回転は同じコードを意味する方向として記述することもできる：`"left"` は `"R0"`、`"down"` は `"R90"`、`"right"` は `"R180"`、`"up"` は `"R270"` であり、リスト内でも同様である。ORIENT-RELATIONはコードのみをとる（14.9）。オブジェクトに対してこの語は単なる別綴りにすぎない：`#M2 @ORIENT("left")` は `#M2 @ORIENT("R0")` である。ピンに対しては字義どおりに読まれる：左を基準としてピンが向く方向である。
- **ピン。** ピン（またはそのピンを代表する端子；5.2.4）に与えられたORIENTは、図面内でのピンの向き——シンボル内で `direction=` により書かれた向き（9.2.4）をそのオブジェクトの向きで回転させた4方向のいずれか——を制約する。オブジェクトがそのピンをその向きにする向き（8通りのうちの2通り）のいずれかを持つときに成り立つため、オブジェクトの向きを一意には固定しない。リストは列挙された各方向を許容する。ピンに鏡像反転コードを与えた場合、それはleftをどの向きに変えるかを表す：`"MY"` は `"right"`、`"MX"` は `"left"` である。このようなORIENTはそのピンをkeyとする独自の幾何的事実となり、オブジェクト自身のORIENTとは別に存在する。両者は他の任意の2つの事実と同様に解決される（8.5）。`direction=` が書かれていないピンには制約すべきものがない：そのピンのORIENTは失敗し、同じ文の他のメンバーは通常どおり有効になる（5.2.1）。求解を行わないレンダラでそのオブジェクトの結果を持たないものは、ピンのORIENTが書かれていないかのように描画する。
- **合成順序。** MXR90およびMYR90は先に鏡像反転し、その後に回転する。名前はCadenceやOpenROADのOpenDBと同様に操作の順に読む。
- **作用の仕方。** 向きはシンボルの原点を中心にシンボルのローカル座標に作用し、その原点がオブジェクトの位置に置かれる：シンボルの各点は、オブジェクトの位置にローカル座標へ向きを適用した結果を加えた位置に描画される。シンボルの図形およびピン位置はそれとともに剛体変換され、ピンから配線が出る向きもともに回転する（9.2.4）。テキストは9.2.5の定めに従って表示され、字形は鏡像反転されない。
- **どこに描画されるかのみ。** 向きが変わるのはピンが描画される位置だけであり、どの端子に属するかは変わらない。ブロックシンボルを上下反転すると、inpのピンは下側に描かれ、inpへの配線もそれに追従する。inpを上に保つために2つのピンが入れ替えられることはない：それではどの配線がどの端子に接続するかというネットリストの事柄が変わってしまうためである（原則 2.2）。inpを別の場所に描くには別のシンボルを使用する（11.3）。

### 11.3 シンボルとスタイル：SET-SYMBOLとSET-STYLE

```rnl
%w13 = &x @WIRE {#M1:1 #M3:1};
#M1 @SET-SYMBOL $NMOS;
# @SELECT-INSTANCE(model="nch") => @SET-SYMBOL $NMOS;
%w13 @SET-STYLE $signal;
# @SELECT-INSTANCE => @SET-STYLE $base
```

- SET-SYMBOLはオブジェクトにシンボルを与える。オブジェクトはインスタンス、適用オブジェクト、バンドル、またはそれらのセット（選択および1つずつの生成の結果を含む）であり、各メンバーに1回ずつシンボルが与えられる（5.2.1）。サブサーキット内では `# @SET-SYMBOL` がブロックシンボルを与える（9.2.6）。
- シンボルを与えられた適用オブジェクトは描画される：これが仮想部品である（第12章）。
- **端子とピンの対応付け。** シンボルの端子名とは、そのピンが束縛する名前である（9.2.4）。SET-SYMBOLがインスタンスにシンボルを与えるとき、シンボルの各端子名は、DEVICEまたはサブサーキットのポートによって与えられたそのインスタンスの同名端子に対応付けられる（6.12）。番号はその位置にある端子に対応付けられる。どのピンも束縛しないインスタンスの端子は、3端子シンボルにおけるバルクのようにピンを持たない。インスタンスが持たないシンボルの端子名はそのピンを何も束縛しないままとし、警告を出す。
  - `terminals=` はこのSET-SYMBOLにおける対応付けを変更する。標準形式では、インスタンス行のノードの順に（DEVICEの `terminals` と同様に、6.12）、シンボルの端子名を列挙する：ピンが `"a"`、`"b"`、`"c"` を束縛するシンボルにおいて、`#X1 @SET-SYMBOL(terminals=["b", "a", "c"]) $GATE` はノード1をbのピンに、ノード2をaのピンに、ノード3をcのピンに束縛する。インスタンスの端子を先、シンボルの端子を後にしたペアのリスト（`terminals=[["d", "b"], ["g", "a"], ["s", "c"]]`）を書くこともでき、ペアに列挙されなかった端子は名前で対応付けられる。どちらの形式でもないリスト、または同じ端子を2度挙げたリストは誤ったパラメータであり、SET-SYMBOLは失敗する。
  - 適用オブジェクトに対しては、シンボルの端子名はその定義のロール名に対応付けられる。番号、またはどのロールにもない名前はいずれのロールも束縛せず、警告が出される。`terminals=` はロールリストの順でシンボルの端子名を列挙するか、ロール名とシンボル端子名のペアを列挙する（12.1）。
- SET-STYLEはオブジェクトにスタイルを与える。オブジェクトはインスタンス、適用オブジェクト、バンドル、配線、または図形（テキストを含む）、あるいはそれらのセット（選択および1つずつの生成の結果を含む）である。ネット、レベル、制約、定義、または点はとらない。端子はそのオブジェクトのシンボルで描画され、そのオブジェクトのスタイルをとる。適用オブジェクトに与えられたスタイルはそのシンボルおよび定義本体内で作られた描画可能なオブジェクトに渡される（8.3）ため、シンボルのない意味を表す適用オブジェクトにスタイルを与えてもエラーにはならない。定義本体内で何も描画されない場合は目に見える効果がないだけである。
  - 注記：そうでなければ、標準パッケージのルール `# @SELECT-USAGE => @SET-STYLE $base` がすべての意味を表す適用オブジェクトに対して警告を出してしまうことになる。
- 出力は入力のハンドルを保持する。オブジェクトがセットのとき、出力はそのセットである。
- 両者ともkeyによる上書きではなく外観キューを通じて有効になる。ティアは2つある：オブジェクトを直接名指しするSET-SYMBOLまたはSET-STYLEは、選択を通じて到達するものや引き継がれるものより上位にある（8.3）。
- デフォルトルールが存在する場合（標準パッケージ、16.3）、それらを記述する必要はない。
- **パラメータとスタイル。** TEXTの `size=` のようにオブジェクトに書かれたスタイルパラメータはそのオブジェクトの直接スタイルであり、選択によるスタイルや引き継がれるスタイルより上位にある。オブジェクトを直接名指しし後に書かれたSET-STYLEは位置によってそれらを上書きする（8.3）。エディタが単一のオブジェクトを変更するのはこの仕組みによる。定義のパラメータが渡されなかった場合は書かれなかったものとして扱われるため、スタイルが有効になる（9.4）。
- **ラベルと接続点の黒丸。** オブジェクトのスタイルはそれに取り付けられたテキストに渡される。選択されたスタイルまたは引き継がれたスタイルのティアにおいて、テキストを選択するルール（SELECT-LABELなど）と位置で比較される。テキスト自身のパラメータとテキストを直接名指しするSET-STYLEは直接ティアにある。したがって `#M1 @SET-STYLE $signal` がラベルルールの後に書かれた場合、M1の名前もその色をとり、名前をドラッグしてもその色は変わらない。シンボル内の `?` に取り付けられたテキストもラベルであり、SELECT-LABELがそれらを選択する。点に取り付けられた固定テキストはシンボルの図形であり、そのオブジェクトのスタイルをとる。ネットまたは点に取り付けられたテキストは取り付け先からスタイルを受け取らず、自身のスタイルのみを用いる。接続点の黒丸は `$JUNCTION` の適用オブジェクトである（13.2）：黒丸がそのシンボルであり、その色は適用オブジェクトのスタイルに従う。

### 11.4 1つのオブジェクトの複数描画

1つのホストオブジェクトを複数回描画する方法はない：`#M1` のようなホストハンドルは常にそのオブジェクトの唯一の描画を意味する。将来のバージョンで1つのオブジェクトの複数描画が追加される場合、それらは固有の名前を持つ別々のオブジェクトとなり、ホストハンドルはその意味を保つ（付録 C）。

注記：1つとして描画される複数のインスタンスはバンドルである（11.8）。

### 11.5 グループ：GROUP

```rnl
%stage1_set = {#M1 #M2 #M5} @GROUP;
%stage2_set = {#M3 #M4} @GROUP(spacing_x=-1);
{%stage1_set %stage2_set} @GROUP;
%stage1_set %stage2_set @DISTANCE("left-to-right", min=1)
```

- GROUPはセットに1つの事実を追加する：ソルバーがそのメンバーを1つのまとまりとして扱うこと。セットのハンドルを保持するため、`%stage1_set` は依然としてそのセットである。
- **グループはオブジェクトではない。** 位置も外接枠も持たず、グループに対して制約を書くことはできない：制約にグループ化されたセットが渡された場合、それは単なるセットであり、それを保持する場所は各メンバーそれぞれを表す（14.1）。またGROUPは第5の原子制約でもない。グループとなる標準パッケージの構造は匿名のグループを持つ。
- **メンバー。** グループのメンバーはそのセット内のオブジェクトであり、入れ子になったセットは最も内側のオブジェクトまでたどられる。シンボルを持たない適用オブジェクトはそのロールを埋めるオブジェクトを表し、最も下位のオブジェクトまで同様にたどられる。シンボルで描画される適用オブジェクトはそれ自身がメンバーとなる。ROUTE-OBJECTも同様に適用オブジェクトのロールをたどり、シンボルで描画される適用オブジェクト自身のピンもあわせてとる（13.7）。
- **何をするか。** グループは2つの点でのみソルバーを導く：グループのメンバーを他の要素より前にまたは他の要素と分けてまとめて配置すること、および事実が許す限り他のオブジェクトをグループの領域外に保つことである。両者とも言語のすべての記述の後にランク付けされるソルバーの基準である（8.5）：グループはいかなる幾何的関係も保証せず、事実によってグループの領域内に置かざるを得ないオブジェクトはそこに描画される。入り混じらないこと（例のDISTANCE）や中央揃えなどの位置要件は原子制約として記述する。
- **グループの木はソルバーに属する。** グループは包含関係によって入れ子になる：`{%stage1_set %stage2_set}` のメンバーは5つのインスタンスであるため、両方の段がその内部にある。互いに包含関係にないままメンバーを共有する2つのグループは両方をブロックにすることができない。ソルバーは自身の規則でそのうち一方を採用し、ヒントが他方を名指す。これ以外にグループが探索とスコアリングにどう影響するかは実装に委ねられる。
- **間隔。** `spacing_x` と `spacing_y` はグリッド単位の整数であり（11.7）、ソルバーがグループ内部のデフォルト間隔に加算する値（x方向とy方向）である。各々は省略でき、負の値はグループを詰めて描画する。2つのオブジェクトの間では両者を含む最も内側のグループの間隔を、グループを共有しないオブジェクト同士の間ではレベルのデフォルト間隔（`@SOLVER-CONFIG` が同名のkeyで設定する、14.10）を、グループとその外部との間では囲むグループまたはレベルの間隔を使用する。ソルバーは値の範囲を制限してもよく、その場合はその旨を明記する。間隔はソルバーの基準であって事実ではない：採用されたすべての事実に譲歩する。
- GROUPはキーワードであり、標準パッケージの定義ではない：その意味はソルバーのみが知っており、定義の定義本体内に記述することはできない（1.5項目7）。
- ビューアが枠などを用いてグループを描画してもよい。これはビューア次第であり、本標準はそれを規定しない。
- GROUPは原子制約ではない：競合解決に参加せず（8.5）、優先度を持たず、有効・無効のみを持つ。`%stage1_set @PRIORITY("disabled")` はそのグループをソルバーに与えないようにし、グループ化を取り消す。外側の適用オブジェクトが無効化された場合、その展開内のグループも無効になるが、外部から `::` を通じてグループに直接書かれたPRIORITYが再び有効にした場合はその限りでない（14.8）。定義の展開内のグループを単独で無効にできるのは、それが名前付きのローカルオブジェクトであり外部から参照される場合のみである（9.4）。

### 11.6 描画順とレイヤー：LAYER

```rnl
@RECTANGLE(fill="fillcolor") {(0, 0) (40, 30)} => @LAYER("bottom") => %f1;    /* a frame, drawn below everything */
(2, 28) @TEXT("input stage") => @LAYER("top") => %n1
```

- レイヤーは `"bottom"`、`"middle"`、`"top"` の3つがある。最初にbottomレイヤーが描画され、次にmiddle、最後にtopが描画される。1つのレイヤー内ではオブジェクトは位置順に描画される：後のオブジェクトが前のオブジェクトの上に描かれて覆う。
- `@LAYER(…)` はオブジェクトのレイヤーを設定する。これがなければオブジェクトは `"middle"` にある。各オブジェクトにつき1つのkeyがあり、後のLAYERが上書きする（5.8）。LAYERはレイヤー内でのオブジェクトの位置を変えない。
- **位置**（記述位置）は記述の順序（1.5項目2）であり、8.3および8.5と同じ順序である：レベル内ではテキストの順序、パッケージの内容はそのUSE-PACKAGEの位置（ルートのパッケージが先頭；16.3）、`scope=` で書かれた文は対象サブサーキット自身のテキストの後となる。各種別のオブジェクトは以下の位置をとる：
  - 配線、図形、テキスト（注釈およびラベル）：それを作る文；
  - 適用オブジェクト：有効になるSET-SYMBOL、またはルールでシンボルが与えられる場合はそのルール（8.3）；
  - ルール、定義の展開、1つずつの生成によって作られたオブジェクト：それを作る文、および1つの展開内では定義本体の順；
  - インスタンス：自身のレイヤーの最下部で、インスタンス同士ではネットリスト順。別レイヤーに置かれたインスタンスはそのレイヤーの最下部にある。バンドルは1つのインスタンスとして数え、最初のメンバーのネットリスト順となる。
- PLACE、ORIENT、SET-STYLE、LAYERなどのオブジェクトを変更する文はその位置を動かさない。
- オブジェクト：インスタンス、シンボルを持つ適用オブジェクト、バンドル、配線、図形、ラベル。セットはメンバーごと（5.2.1）。シンボルのない適用オブジェクトへのLAYERはエラーではないが効力を持たない（SET-STYLEと同様、11.3）。点、ネット、制約、定義に対しては失敗する。
- シンボルのメンバーはレイヤーを持たない：そのオブジェクトとともにメンバー順に描画される（9.2.1）。
- 数値の `z=` は存在しない。上書き（事実のkeyによる）と重なり順（レイヤーと位置による）は別個のものである。
- ここでの「レイヤー」とは描画の順序を意味し、ホストのレベル（2.6）とは無関係である。

### 11.7 座標と単位

- **軸。** xは右向き、yは上向きであり、yが大きいほど上にある。したがってORDERとDISTANCEの `"bottom-to-top"` は上向きに進み（14.3、14.5）、R90は反時計回りである（11.2）。SVGや他の形式および一部のエディタではyが下向きになっているが、実装は描画・インポート・エクスポート時にyを反転する。
- **単位。** 単位は物理サイズを持たない。1単位をどれだけの大きさで描画または印刷するかはビューアに委ねられる。
- **小数。** 座標と長さは小数で書いてもよい（3.7）。整数である必要はなく、桁数に制限はない。座標は書かれたとおりに描画され、整数に丸められる（スナップされる）ことはない。
- **グリッド。** ピンは整数点上にあるべきである（9.2.4）。シンボル内の図形には制限はない。インスタンスを整数点に8通りの向きのいずれかで配置すると、整数座標のピン位置は変換後も整数のままとなるため、配線も整数点で終わる：整数点が通常のグリッドである。言語自体には固有のグリッドはない。ソルバーが自由な座標を整数に丸めるかどうかは言語のすべての記述の後にランク付けされるソルバー自身の規則である（8.5）。制約が小数を強制する場合はその小数が使われる。配線モードが計算した折れ曲がり点は計算されたまま保持され、丸められない（13.1）。
- **許容差。** 制約が成り立つかを検査するときおよび競合を判定するとき（8.5）、許容差以内の差は満たされたものとして数えられる。許容差はユーザーが設定できるソルバーのオプションであり、本標準はその値を固定しないが、有限小数表現を持たない値を書き戻せるよう0より大きい（下記）。求解を行わないビューアは検査時に自身の設定を用いる。したがって2つのツールが許容差の境界ちょうどにあるケースで異なる判定をすることがある。ソルバーは座標をさらなる切り詰めなしに同じ値として読み戻せる小数として書き戻す。1/3のように有限小数表現を持たない値は、レコードを読み戻したときにそれが満たす事実が許容差以内で依然として成り立つだけの十分な桁数で書き出される（第17章）。
- **シンボル座標。** DEFINE-SYMBOL定義本体内のローカル座標はシーンと同じ単位と軸を持ち、その原点はシンボルの原点である（9.2.1、6.5）。拡大縮小はない：シンボルは拡大縮小パラメータをとらず、インスタンスを拡大縮小することもできない。インポータは他のツールのシンボルをRNL単位へ変換する。
- **その他の長さ。** 言語内のすべての長さは座標単位であり、図面とともに拡大縮小される：DISTANCEの `min`、`max`、`exact`、CIRCLEの `radius=`、RECTANGLEとELLIPSEの `width=` と `height=`、テキストサイズ `size`（SVGの `font-size` と同様）、線幅 `linewidth`、矢尻の長さ `arrowsize`（9.3）、および長さとして使われる定義パラメータ（`gap=3` など）。線幅0が例外である：どの拡大率でも同じ細さのヘアラインであり、デフォルトでもある（9.3）。
- **原点と用紙。** シーンの原点は特別な意味を持たない。各サブサーキットは固有の座標を持つ1つの回路図であり（6.1）、ビューアは内容の範囲に合わせて表示をフレーミングする。RNLは用紙サイズもエディタのスナップグリッドも記録しない。

### 11.8 バンドル：BUNDLE

Virtuosoの `I0<3:0>` のような反復インスタンスは、1つのシンボルでありながらネットリスト内では4行となる：

```spice
* A unit cell repeated four times
* @RNL(type="header") { @VERSION("0.4")}
.subckt unit in out vdd vss
R1 in out 1k
.ends unit
XI0<3> D<3> out vdd vss unit
XI0<2> D<2> out vdd vss unit
XI0<1> D<1> out vdd vss unit
XI0<0> D<0> out vdd vss unit
* @RNL {
*   #XI0<3:0> @BUNDLE => @PLACE(30, 10) => %x;   /* four instances drawn as one symbol */
*   &D<3:0> @WIRE {(20, 10) %x:in};              /* a bus to the in pin of the bundle */
*   &out @WIRE {%x:out (40, 10)};                /* all four members are on out: an ordinary pin */
*   %x @TEXT("I0<3:0>", key="name")              /* the name, written out */
* }
.end
```

- **新しいオブジェクト。** BUNDLEはホストインスタンスのセットを受け取り、これらのインスタンスの代わりに1回だけ描画されるバンドルを作る。メンバーは書かれた順であり、最初のメンバーがピンとシンボルを決める。
- **ピンとシンボル。** 端子名と端子数は最初のメンバーのものである。外観キューはバンドルをその最初のメンバーとして扱う：選択はその最初のメンバーの条件でバンドルに到達し（10.1）、サブサーキットのブロックシンボルが適用される。バンドルに直接書かれたSET-SYMBOL、スタイル、PLACE、ORIENT、LAYER、制約およびテキストはバンドルに属する。
- **端子。** `%x:in` のようなバンドルの端子は、すべてのメンバーの同名端子を表す：すなわちバスピンである。
  - **名前による**：バンドルの端子は、各メンバーの順序における位置にかかわらず、メンバーのその名前の端子を表す。その名前の端子を持たないメンバーはその一部にならない。
  - `::net`：すべてのメンバーが同じネット上にあるときはそのネット（`%x:out::net` の `&out` など）、そうでなければメンバー順に並べたそれらのネットのセット（`%x:in::net` の D<3>, D<2>, D<1>, D<0> など）。したがって定義内の `?t::net @WIRE {…}` は、セットを受け取ったときはバスを描き、単一のネットを受け取ったときは通常の配線を描く（13.1）。
  - バンドルの端子への配線は、すべてのメンバーのその端子を接続する（10.2）。
- **属性**（13.6）：すべてのメンバーで値が同じときはその値、そうでなければ値を `,` で連結したもの。`${w}` はすべて1uなら1uを表示し、`${name}` は `XI0<3>,XI0<2>,XI0<1>,XI0<0>` となるため、`I0<3:0>` を表示するには例のように同じkeyでテキストを書く。端子の `${net}` も同様に動作し、`D<3>,D<2>,D<1>,D<0>` などとなる。
- **選択。** メンバーは選択できず、代わりにバンドルが選択される（10.1）。したがって「未配線の各ピンにネット名を付ける」のようなルールはバンドルに1つのラベルを与え、それがバス全体を示す。インスタンスをとる定義のロールはバンドルもとり、端子をとるロールはバンドルの端子もとる（9.4）。
- **メンバーは単独では描画されない。** メンバーまたはメンバーの端子に直接書かれた描画に関する記述（位置、向き、シンボル、スタイル、レイヤー、制約、配線、またはテキスト）は失敗する：メンバーはバンドルを通じてのみ描画される。描画に関わらない記述（CURRENTや意味を表す適用オブジェクトのロールなど）は通常どおり動作する。
- **すべて同種であること。** メンバーは同じモデル名またはサブサーキット名と、数・名前・順序が同じ端子名を持つべきである。そうでない場合は警告が出されるが、引き続き最初のメンバーのピンとシンボルでバンドルされる。パラメータのみが異なるメンバーは警告を出さず、その属性は連結された値を表示する（下記）。
- **各インスタンスにつき1つのバンドル。** 複数のBUNDLEに書かれたインスタンスは後に書かれた方に属する（1.5項目2）。前の方は残りのメンバーを保持し、ヒントが出されてもよい。すべてのメンバーが奪われた先のバンドルは空になり、警告付きで描画されなくなる。
- BUNDLEは明示的に書かれたオブジェクトをとる：選択の結果、またはそれに依存するセット（10.4）が渡されると失敗する。バンドルはシンボルが与えられる前に存在しなければならないためである（8.2、10.4）。同じ理由から、ステップ6が生成する内容の中のBUNDLEも失敗する。空のセットによるBUNDLEは失敗する（5.2.1）。ホストインスタンスでないメンバーは失敗する（種別の誤り）。見つからないメンバーがあると文全体が失敗する（厳格、7.3）。
