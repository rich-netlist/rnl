## 12 仮想部品

### 12.1 概念

- 仮想部品（virtual part）とは、グラウンド、電源、ポートタグ、未接続マークのようにRNL内にのみ存在する部品である。電気的には存在せず、描画されるだけであり、電気的事実を作成したり変更したりすることはない。
- 仮想部品はシンボルを持つ適用オブジェクトであり、そのための専用のキーワードやオブジェクト種別はない。`$GROUND @ATTACH &vss` は1つの適用オブジェクトを作り、標準パッケージが `$GROUND` の適用オブジェクトにグラウンドシンボルを与えるため描画される。
- 規則：
  1. **ピンとロール。** 適用オブジェクトは端子を持たない。そのシンボルのピンには `%g0::pin` のように名前で到達し（6.5）、`%g0::p` は依然としてロールpを埋めるメンバーすなわちネットvssである。`terminal=` が定義のロールを名指しているピン（名前または `terminals=` で対応付けられる；11.3）はそのロールに束縛される：そのピンはそのロールを埋めるものの上に描かれるため、そのネット上の配線がそこで終端でき、ROUTE-NETがそれを結び（13.7）、ピンの `::net` はそのネットになる。ロールを束縛するピンは、そのロールを埋めるもの（ネット、または端子やピンのネット；5.2.4）のネット上に描かれる。したがって `$GROUND @ATTACH #M5:3` はM5:3のピン上ではなくM5:3のネット上に自身の位置でグラウンドを置く。ピン上にグラウンドを描くには、`$GROUND_STUB`（10.5）のように定義本体でそうする定義を用いる。束縛されたロールが空ノード（6.3）で埋められた場合、ピンはどのネット上にも置かれず、これは妥当である：その場合は空ノード上に書かれた配線によってのみ結ばれ（13.1）、標準パッケージの自動補完は何も与えない。束縛されたロールがインスタンスや点など別の種別で埋められた場合、ピンはネットを持たない：これは種別のエラーであり、その適用オブジェクトに対してSET-SYMBOLが失敗して描画されず、診断はその適用も指し示す。`"net"` 種別で宣言されたロールは、定義の適用時に端子をそのネットへ変換し（9.4）、シンボルが与えられた後にピンも変換する（5.2.4）。どのピンも束縛しないロールは、`$NO_CONNECT` の端子（12.6）のようにその定義が宣言する種別をとる。それは電気的な端子ではないため、SELECT-TERMINALはそれを選ばずASSERT-TERMINALも検査しないが、SELECT-PINは選ぶ（10.1）。どのロールも束縛しないピンは描画のみであり、その名前を通じて手で配線される。ピン名はロール名と同じであってはならない（6.5）。
  2. 適用オブジェクトはシンボルを与えられたときにのみ描画され、シンボルを持たない適用オブジェクトは描画されない。標準パッケージがシンボルを与えるのは描画されることを意図した定義に対してのみであるため、差動対のような意味を表す適用オブジェクトは描画されない。
  3. シンボルのない適用オブジェクトはそれ自体では何も描画しない：それに対するORIENTは失敗し、ピンを持たないためそのピン名への配線も失敗する（9.2.4）。これは8.2のステップ7の後に検査される。ただし自身の点 `%u::position` は持っており、PLACEはその点をとり、`%u::position` に対して書かれた制約もその点をとる一方、適用オブジェクト自体に対する制約はそのメンバーをとる（14.1）。その点は定義本体がそれに結び付けるものを通じてのみ図面上に現れる（14.1、9.4）。配線や図形はその点に `&n {%u::position %pt} @WIRE` のように `::position` を通じてのみ終端できる：それはピンではなく点であるため、配線は何も接続しない（5.2.4、6.5）。それにスタイルを与えてもエラーにはならない：スタイルはその定義本体内で作られる描画可能なオブジェクトに渡され（8.3）、定義本体内で何も描画されない場合は目に見える効果がないだけである（11.3）。
  4. 描画される適用オブジェクトは自身のシンボルのみを描画する。メンバーを包含したり移動させたりはせず、視覚的なコンテナではない。
  5. **どこに描画されるか。** そのシンボルの原点は適用オブジェクト自身の点である（14.1）：PLACEと制約がそれを動かし、ORIENTがその点を中心にシンボルを回転させ（11.2）、ロールを埋めるオブジェクトには（そのピンへの配線や定義本体内の事実などの事実を通じる場合を除き）追従しない。ピン上またはある点にマークを描く定義は、定義本体内で `{? ?t} @ALIGN("x"); {? ?t} @ALIGN("y")` のように適用オブジェクトの点をそれに結び付ける（9.4）。ORIENTがなければソルバーが向きを選んで書き戻し（14.8）、その解を持たないレンダラは `"R0"` で描画する（8.5）。配線がピンから出る向きには追従しない。最初のロールを埋めるオブジェクトはその適用オブジェクトの主オブジェクトである。適用オブジェクトは自身の名前を持たず、テキストは `${p}` のようにロールを通じて主オブジェクトを参照する（13.6）。
  6. 定義の定義本体は常に展開されるため、仮想部品の定義も定義本体を持ってよい。
- 原則 2.2の言葉で言えば、仮想部品とはホストオブジェクトでロールが埋められたシンボル付きの適用オブジェクトであり、標準仮想部品とはデフォルトシンボルを与えるルールを伴う標準パッケージの定義であり、ユーザー定義仮想部品とはユーザー自身の定義とシンボルルールまたは定義本体内で与えられたシンボルの組である。
- **仮想部品の定義。** 標準的な方法は、一般定義とその直後にその適用オブジェクトへシンボルを与えるルールを書くことである：`$GROUND = @DEFINE(roles=[["p", "net"]]) {}; # @SELECT-USAGE(recursive=true) $GROUND => @SET-SYMBOL $GROUND_SYMBOL`。このルールはシンボルキューに記述位置順に入る（8.3）ため、ハウススタイルパッケージやファイルの後のルールが同じ適用オブジェクト（他の定義の内部や自動補完で作られたものも含む）を別の方法で描画できる（`# @SELECT-USAGE(recursive=true) $GROUND => @SET-SYMBOL $EARTH` など）。1つの適用オブジェクトだけを別の方法で描くにはそれを名指しして `%g1 @SET-SYMBOL $EARTH` と書く。定義本体で `? @SET-SYMBOL $X` のようにシンボルを与えてもよく、単独の `?` が適用オブジェクトを表す（9.4）：これは適用オブジェクトを直接名指しする（8.3）ためどのルールもそれを置き換えず、別の方法で描かれることを意図しない部品に適している。描画を変えても端子やその上の配線は変わらない。
- ある適用オブジェクトが仮想部品であるか否かは、シンボルを持つか否かのみによる。
- 注記：描画されるべき定義にシンボルが与えられていない場合、その適用オブジェクトに向き付けや配線が行われたとき、またはそれに対する制約に目に見える効果がないときにのみ報告される（14.1）。

### 12.2 仮想部品の作成

```rnl id=g0
$GROUND @ATTACH &vss => @PLACE(24, 38) => %g0;
&vss @WIRE {#M5:3 %g0::pin}
```

- `$D @ATTACH &net` では、定義の後のオブジェクトが定義のロールリストに対応付けられる。これはATTACHで記述され、「ネット上にこれを追加する」と読む（9.4）。複数のロールを持つ仮想部品はネットリストのインスタンス行のように記述する：ロールaとbを持つ定義 `$DIFF_PORT` に対しては `$DIFF_PORT @ATTACH &inp(a) &inn(b)`、あるいは順で `$DIFF_PORT @ATTACH &inp &inn` と書く。
- ロールは通常ネットで埋められる：ロールを束縛する仮想部品のピンはそのネット上に描画され（12.1項目1）、素子のピンとの関係（どこに描かれるか、何に接続するか）は配線と制約によって与えられる（12.3）。ロールを束縛するピンはそれを埋めるもののネット上に描画される（12.1項目1）：`$GROUND @ATTACH #M5:3` は `$GROUND @ATTACH #M5:3::net` と同様に、M5:3のネット上に自身の位置でグラウンドを取り付ける。ロールがとるオブジェクトの種別は定義内で `roles=[["p", "net"]]` のように宣言できる（9.4）。
- この対応付けは記述的なものにすぎず、電気的接続は作らず、検査も行われない（原則 2.2）。
- 1つのネットは5つのグラウンドや2つのプローブなど、いくつでも仮想部品を持てる。適用オブジェクトはkeyを持たないため、適用のたびに1つ増える（5.8）。
- 1つの仮想部品には、独自のシンボル `$EARTH` を用いて `%g1 @SET-SYMBOL $EARTH` のように別のシンボルを与えられる。
- ATTACHは `priority` 以外の固有パラメータを持たない（14.8）。ポートの向きは標準パッケージの内容に属する（12.4）。表示される名前は主オブジェクトのものであり、別のテキストを表示するにはラベルを書く（13.3）。定義のパラメータは通常どおりATTACHを通じて渡される（9.4）。
- `%g0` は1つのレベルで1度だけ束縛される（6.6）。その位置を変えるには `%g0 @PLACE(…)` と書く。

### 12.3 端子に対する相対位置

パラメータはホスト参照を保持できないため、端子に対する相対位置は制約として記述する：

```rnl use=g0
{%g0::pin #M5:3} @ALIGN("x");
%g0::pin #M5:3 @DISTANCE("bottom-to-top", exact=2)    /* the pin of the ground 2 below the source of M5 */
```

DISTANCEの代わりに `@ALIGN("y")` と書くと、グラウンドのピンがM5のピンに重なる。2つのピンの間に長さ0の配線 `&vss @WIRE {#M5:3 %g0::pin}`（13.1）を書けばピンも配線済みとなるため、自動補完がそこに2つ目のグラウンドを追加しない（10.2、10.5）。

### 12.4 ポート

```rnl
$IO_PORT @ATTACH &inp => @PLACE(0, 20) => %p_inp
```

- サブサーキットのポートの名前はその内部のネットの名前であるため、ポートタグはネット `&inp` に関連付けられる。
- ポート自身（`#:inp`）は描画されず、仮想部品によってのみ示される。標準シリーズ 0.4の自動補完は、セット `$PORT_FILL_SET` を通じて、電源ネットとグラウンドネットを含むすべてのポートネットにポートタグを与える。ただしポートタグが書かれたネットは除外される（10.5）。1つのレベルのタグは縦1列に並び、それぞれ R0 でピンを右に向ける。この列は、レベルのどのインスタンスよりも、自身の点から測って少なくとも6単位左にとどまる。これは優先度 `"low"` の制約による。残りはソルバーが決める。ファイルは、タグを持たせたくないネットをセットから外す（例：`# @SELECT-NET(name="vdd") => @REMOVE-FROM $PORT_FILL_SET`）。自分で配置するタグには `$IO_PORT @ATTACH` を書く。あるいは同じ縦1列を書き出すために、1つのレベルに1回 `$PORT_LIST @ATTACH` を書く。その場合そのレベルでは自動補完は何も追加しない。`$PORT_LIST` 自身の点はその縦1列の線上にあるため（14.1）、その適用オブジェクトに対する制約はその縦1列を動かす。
- ポートの向きは表示上の事柄にすぎない：ネットリストには向きがなく、どのシンボルを描画するかはユーザーが決める。どのようなポート定義とシンボルがあるかは標準パッケージの内容に属する。
- **ポートタグの向き。** ポートタグには向きがある：例えば標準パッケージの `$IO_PORT_SYMBOL` ではピンが一方の端にあり、タグが反対側へ伸びる。ORIENTがない場合、ソルバーは折れ曲がり点を減らすことを目指して配線の向きから向きを選ぶ。これはソルバーの目標であり言語の一部ではないため（14.8）、ポートタグのORIENTは通常手書きしない。

### 12.5 標準の仮想部品

標準の仮想部品は標準パッケージに属し、本言語標準の一部ではない（16.3）。標準パッケージは例えばグラウンド `$GROUND`、電源 `$SUPPLY`、ポートタグ `$IO_PORT`、未接続マーク `$NO_CONNECT`（12.6）を、それらのシンボル、それらのシンボルを与えるルール、および自動補完（10.5）とともに提供する。

1つのネットvssに対して、3通りの書き方が3通りの描画を与える：

1. `&vss @ADD-TO $GROUND_NET_SET`：vss上の配線のない各端子が、短い配線を伴うグラウンドをその下に得る（標準パッケージの自動補完、10.5）。これは教科書でよく描かれる表現、すなわち接地された各端子の下にグラウンドシンボルを置く表現である。
2. `$GROUND @ATTACH &vss => %g`：ネット全体に対して1つのグラウンドを置き、ソルバーが配置する。端子はそのピンに `&vss @WIRE {#M5:3 %g::pin}` のような配線で結ばれるか、ネット全体のROUTE-NETで結ばれる（13.7）。
3. `$GROUND_STUB @ATTACH #M5:3`：M5のソースの下にのみ短い配線を伴うグラウンドを置く（自動補完が各ピンに対して描くのと同じ、10.5）。

- 電源も同様に、セット `$SUPPLY_NET_SET` と定義 `$SUPPLY` で記述する。ネット0はデフォルトで `$GROUND_NET_SET` に含まれる（10.1）。
- 3番目の方法では、スタブの定義本体内の配線がそのピンを配線済みにするため、自動補完がそこに2つ目のグラウンドを追加することはない（10.2、10.5）。
- ポート：自動補完がサブサーキットの各ポートネットにポートタグを与える（12.4）。それを配置したり制約したり表示名を変えたりするには、`$IO_PORT @ATTACH &out => %pout` のように書き出し、`%pout::pin` への配線を書き、名前には `%pout @TEXT("V_{OUT}", key="name")` と書く（13.3）。ポートタグを表示しないネットは `$PORT_FILL_SET` から外す。

### 12.6 未接続マーク

```rnl
$NO_CONNECT @ATTACH #M1:4    /* terminal 4 of M1 is left unconnected on purpose */
```

- 未接続マークは標準パッケージの定義 `$NO_CONNECT` であり、そのロールは端子またはピンをとる。専用のキーワードはない。端子は変換されずそのまま受け取られる（5.2.4）ため、`$NO_CONNECT @ATTACH #U1:d<3>` のようにバスピン（9.2.4）の1メンバーに付けたマークはどの端子が開かれているかを示し、1つのバスピン上の複数のマークはそのピンに重ねて描画される。このマークのシンボルのどのピンもこのロールを束縛しない（12.1項目1）。この定義は適用オブジェクトの点をそのロールを埋めるもののピンに結び付け（12.1項目5）、標準パッケージはそれに交差の中心を原点としピンを持たないバツ印のシンボルを与える。
- この適用オブジェクトは、その端子が意図的に未接続であることを記録する：`# @SELECT-USAGE $NO_CONNECT => @SELECT-TERMINAL` はこれらの端子を選択する。
- 検査（ネット上の他のホスト端子や端子に触れる配線がないか）は必須ではない（原則 2.4）。標準の `$NO_CONNECT` を知る実装は警告を出してもよい。
- 未接続マークは配線として数えられない（10.2）：このマークのみを持つピンは依然として `wired=false` である。ピン単位の自動補完がこれらのピンをスキップするには、10.5の差集合のようにそれらのピン `# @SELECT-USAGE $NO_CONNECT => @SELECT-TERMINAL => @SELECT-PIN` を差し引く。
- 注記：未接続マークがキーワードでないのは、描画以外に実装上の用途がないためである：ソルバーはそれを読み取らず、その描画方法は定義とシンボルで記述できる（1.5項目7）。
- ネットラベルは仮想部品ではない。13.3を参照。
