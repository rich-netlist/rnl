## 付録 D バージョン0.3からの変更点（参考情報）

バージョン0.4は、1つの事実が複数の選択肢ではなく1つのレイアウトを意味するよう、位置に関するすべての事実を方向付きで記述する。0.xバージョン同士では互換性を保証しない（16.1）。本付録では変更点とファイルが0.4へ移行する方法を列挙する。本標準はバージョン0.4のみを記述する。0.3のファイルはバージョン0.3を読み取るアップグレードツールによって0.4へ移行され、そのツールが本付録末尾の変更を行う（16.1）。

- Spectreの `transformer` の端子名 `p_plus`、`p_minus`、`s_plus`、`s_minus`：`p1`、`n1`、`p2`、`n2` と書く。
- ORIENT-RELATIONの両側のセット：各ペアに対して1つの事実を書く。
- `recursive` のないルール：下位レベルへ到達し続けるよう、ファイル、自身のパッケージファイル、およびインラインパッケージ内の選択にツールが `recursive=true` を書き込む。一部の選択に `recursive=false` を書き他には書いていないルールは報告される：0.4では1つの `true` でルール全体が下位へ到達するためである。
- ROUTE：ツールがその代わりにROUTE-NETを書く。
- 選択の結果が渡されたWIREまたはBUNDLE：配線にはROUTE-OBJECTを書き、バンドルのメンバーは1つずつ書き出す。
- `%g:p` など適用オブジェクトの端子：`%g::pin` のようにシンボルの名前付きピンを書く。シリーズ 0.3のシンボルは適用オブジェクトのロールを番号で束縛していたが、0.4では行わない（11.3）。
- `$GROUND @ATTACH #M5:3` など最初のロールが端子またはピンである仮想部品：これらは現在そのネット上に自身の位置で立つため、ピン上に保つにはスタブ `$GROUND_STUB @ATTACH #M5:3`、あるいはグラウンドのピンをM5のピンに置く制約を書く（12.3）。
- SELECT-TERMINAL上の `wired=`：`# @SELECT-INSTANCE => @SELECT-PIN(wired=false)` のようにSELECT-PINを書く。
- 中心で数えられていた `{%x}`、およびその中心であったセットの `::position`：0.4ではセットは位置を持たず、その `::position` はメンバーの位置のセットであるため、アップグレードはそのような文をレビュー用に残す。オブジェクト群を1つとして配置するには、定義本体がそれらを自身の点に結び付ける適用オブジェクトのメンバーにし、`%u::position` を制約する（14.1）。
- 1つの点として数えられていた制約のメンバーリスト内の適用オブジェクト：アップグレードは、そのままではそのメンバーを表すことになるシンボルを持たない適用オブジェクトに対して `%u::position` を記述する（14.1）。
- 2つのセット間のDISTANCE：すべてのペアに対して成り立つようになったため、`max` は範囲間の隙間ではなくすべてのペアを制限する。
- 一般定義の定義本体内のリテラル座標：適用オブジェクト自身の点からのオフセットとなったため、レベルの座標を意味していた定義はその適用オブジェクトを `$TITLE @ATTACH => @PLACE(0, 0)` のように `(0, 0)` に配置する。
- 標準パッケージ：`@USE-PACKAGE(name="rnl-std-all", version="0.4")` を書き、下記の「標準シリーズ 0.4」のとおりにシリーズ 0.3の使用箇所を書き換える（新しい名前とロール、0.3の自動補完がタグ付けしていた各ポートネットに対するポートタグ `$IO_PORT @ATTACH`、および削除された定義の使用箇所ごとの報告）。

**標準シリーズ 0.4。** 標準パッケージは本標準の一部ではない（16.3）。以下はシリーズ 0.3からシリーズ 0.4へ移行するファイルに関わる事項である。

- **使用法**：ファイルはヘッダーレコード内に `@USE-PACKAGE(name="rnl-std-all", version="0.4")` を書くか、それを追加するツールの設定で読み取られる（16.3）。
- **ポート**：自動補完はすべてのポートネットに、電源ネットとグラウンドネットも含めて、レベルのインスタンスより少なくとも6単位左に縦1列で、それぞれ R0 のポートタグを与える。ファイルはネットを `$PORT_FILL_SET` から外し、自分のタグには `$IO_PORT @ATTACH` を、書き出した縦1列には `$PORT_LIST @ATTACH` を書く（12.4）。
- **自動補完**：配線のないピンに各々短いスタブであるネットラベルを追加する。ファイルまたはパッケージがROUTE-NETやROUTE-OBJECTで指示しない限りどのネットも配線として描かれない。グラウンドネットと電源ネットは `@UNROUTE-NET(priority="high")` で除外されており、それらを描画したいファイルは `@ROUTE-NET(priority="high")` またはWIREを書く。手書きの配線であれ、文またはルールのROUTE-NET・ROUTE-OBJECTで描かれたものであれ、配線を持つピンに自動補完はグラウンドや電源シンボルを追加しない。それらを望むファイルはネット全体を描く場合の `$GROUND @ATTACH &vss` や1つのピン上の `$GROUND_STUB @ATTACH #R1:2` のように取り付ける。そのルールは `recursive=true` を書き、仮想部品のものを含めてピンを選択する。`$BIAS_NET_SET` 内のネットはグラウンド・電源ネットと同様にバイアスマークを得る。
- **パッケージ**：唯一のコレクションは `rnl-std-all` であり、シリーズのすべてのパッケージを参照し各言語用のヘッダーレコードを持つ（2.8、16.3）。シリーズ 0.3のコレクション `rnl-std`、`rnl-std-core`、`rnl-std-full` は廃止され、`rnl-std-structures` は `rnl-std-semantics` となった。`rnl-std-no-labels` は `drawn=true` で選択し、空テキストではなくスタイル `textvisible=false` でラベルを隠すため、ファイルは `textvisible=true` で1つを再び表示できる。オプションの `rnl-std-45deg` は新規である。
- **改名または変更**：`$DIFFERENTIAL_PAIR` はロール `left`、`right`、`tail` を持つ `$DIFFERENTIAL_PAIR_N` と `$DIFFERENTIAL_PAIR_P` になり、`$MIRRORED` はロール `left`、`right` および1つの `axis` を持つ `$MIRRORED_LAYOUT` へ改名され、新規の `$MIRRORED_VERTICAL_LAYOUT` は `top`、`bottom`、`axis` を持つ（配置のみを行う定義は `_LAYOUT` で終わるため）。`_N` と `_P` の構造はそのトランジスタの極性を表明し、`$FLOW` は何も配置せず方向もとらず経路の信号源と負荷を名指しできる `$SIGNAL_FLOW` となり、`$POWER_FLOW` と `$BIAS_CIRCUIT` は新規であり、`$CURRENT_MIRROR` は `$CURRENT_MIRROR_N` と `$CURRENT_MIRROR_P` になり、`$NO_CONNECT` のロールは端子またはピンをとる。シリーズが改名、統合、分割、または削除する定義の完全な一覧は標準パッケージの説明にあり、RNLコア 0.5.xの最終リリース（本言語ではなくツールのバージョン）のコマンド `rnl upgrade` がそれに従ってファイルを書き換える。構造内の位置に関するすべての事実は方向を明記し、もう一方の描画は `$BRANCH_HORIZONTAL` のように独自の変種となる。
- **削除**：`$CHAIN`、`$SUPPLY_HIGH`、および `$SUPPLY_LOW`。
