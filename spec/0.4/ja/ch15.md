## 15 電気的意味

### 15.1 意味定義の適用

```rnl
%dp1 = #M1(left) #M2(right) #M5(tail) @AS $DIFFERENTIAL_PAIR_N;
%cm1 = {#M3 #M9}(ref) {#M4 #M6}(out) @AS $CURRENT_MIRROR_P;
%in = {#M8 #M5} @AS $MATCHED
```

- オブジェクトが何を意味するかは、ASで意味定義を適用することで記述する（9.5）：適用により1つの適用オブジェクトが作られ、オブジェクトが定義のロールリストの各ロールを埋める。意味を記すこともレイアウト関係を記述することも、同じ種類の文である。
- 9.4および10.1の例のように、ある適用オブジェクトを別の適用オブジェクトのメンバーにすること（入れ子）ができる。
- ロールリスト内で `"{name}"` と書かれるセットロール（`$MATCHED` の `"{members}"` や例中の `$CURRENT_MIRROR_P` の `"{ref}"`・`"{out}"` など）は、メンバー数が固定されていないときのために1つのセットを受け取る（9.4）。
- ロールは `roles=[["in_p", "instance"], ["in_n", "instance"]]` のように受け取るオブジェクトの種別を宣言できる。誤った種別のオブジェクトを渡すと適用全体が失敗する（9.4）。定義本体が空の定義はロールを埋めるものを何も検査しないため、そのような宣言がなければ誤ったオブジェクトをそこで検出できない。
- 適用オブジェクトのロール名は `%dp1::left` のようにそのサブオブジェクトとなる。
- 定義を適用するとその定義本体が展開され、定義本体には優先度 `"low"` のデフォルト描画のような制約を含めることができ、それらは適用オブジェクトの優先度で無効にできる（9.5、14.8）。
- 検査されない事項：意味がネットリストの接続、型、パラメータと一致するかは検査されない（原則 2.4）。例えば本言語は `#M3(ref) #M4(out) @AS $MY_MIRROR` に対してM3のゲートとドレインが接続されているかを検査しない。定義は自身が主張する内容を定義本体内の表明によって検査する（15.3、15.4）。
- ある意味の適用オブジェクトはSELECT-USAGEで、あるオブジェクトを含む適用オブジェクトはSELECT-ANCESTOR-USAGEで選択され、適用オブジェクトのメンバーには適用オブジェクトをスコープとする選択で到達する（10.1）。
- 意味定義の語彙は標準パッケージに属し（9.5）、`$DIFFERENTIAL_PAIR_N` などの定義を提供する。
- 1つの記述の基本的妥当性（原則 2.4）とは、参照が見つかること、ロールが正しい種別のオブジェクトを受け取ること、単一ロールが埋められていること、および展開後の各文がそれ自体として妥当であることである（9.5）。2つのロールが同じオブジェクトで埋められたか否かは検査されない。

### 15.2 電流方向：CURRENT

```rnl
#M5:1 @CURRENT("in");                 /* drain: the current flows in */
#M5:3 @CURRENT("out")                 /* source: the current flows out */
```

- CURRENTは端子における定常電流の向きを設定する：`"in"`（流れ込む）、`"out"`（流れ出す）、または `"unspecified"`（パッケージのルールが与えた値を上書きするために用いる）。パラメータは `direction` である。CURRENTのルールはステップ6で評価される（10.4）。ピンを直接書いたものまたはロールを通じて到達したものは、端子を見つけるためにシンボルが必要である（5.2.4）：それはルールではなく、ステップ4でオブジェクトのシンボルが与えられたとき（ステップ6で生成されたオブジェクトについてはステップ7で）有効になる。ステップ6までは、選択の `current` 条件は端子に直接書かれたCURRENT文のみを読み取り、ステップ7以降ではスタイルキューと同様にすべての向きを読み取り、幾何計算および下記の検査も同様である。
- これは端子に関する事実であり、幾何的事実ではない：競合には参加せず（8.5）、ソルバーは向きを試す順序を決めるなどのヒントとしてのみ用いる。ORIENTと同様に変更を行う文であり、入力ハンドルをそのまま次へ渡す。端子ごとに1つのkeyを持ち、後のものが勝つ。一度も書かれていない端子は未指定（unspecified）である。
- これは端子に対してのみ与えられる。複数の端子を持つ素子の内部での電流は明確に分割できないためである：3端子素子に対して「aからbへ、bからcへ流れる」と言ってもbで流れ込むのか流れ出すのかが曖昧になり得るのに対し、端子における定常電流の向きは常に一意な意味を持つ。
- これが受け取るのはこのレベルのポートを含むホストの端子のみである：`#:inp @CURRENT("in")` はそこで電流がサブサーキット内へ流れ込むことを意味する。素子のピンは `#M1::d @CURRENT("in")` のようにその端子へ変換されるが、仮想部品は端子を持たないためそのピンは変換されない（5.2.4）。ピンのない端子も許容される（配線の場合とは異なる）。
- ネットリストと照合して検査されることはない（原則 2.4）。1つのネット上のCURRENT文は全体として1つの表明をなす（15.3）：このレベルのポートを含め、そのネット上のすべての端子が `"in"` または `"out"` のCURRENTを持ち、かつそのネットに対してすべて同じ向きに電流を流す場合、電流の行き場がないため、そのネットと端子を名指しする違反（7.6）が出される。`"in"` を持つ素子端子はネットから電流を吸い出し、`"in"` を持つこのレベルのポートはネットへ電流を送り込む。CURRENTを持たないか `"unspecified"` を持つ端子がネット上に1つでもあれば、そのネットは検査されない。`0` のようなグローバルネット（6.3）も検査されない：すべてのレベルで同じノードであるため、電流が他レベルの端子を通じて出ていく可能性があるためである。優先度が `"disabled"` であるレコード内または適用オブジェクトの定義本体内のCURRENTは数えない。これは8.2のステップ7の後に表明とともに検査され、表明と同様にそのネット、端子、およびそれらのCURRENT文を名指しする報告のみを行い、CURRENTの事実はそのまま有効に残る。
- 用途：端子における電流は、流れ出すときはシンボルの向きで回転されたピンから配線が出る方向（9.2.4）に流れ、流れ込むときはその反対向きに流れる。ソルバーはこれを用いて、電流が下向きに流れる配置を優先するなどのレイアウト選択を行える（14.8）。上向きか下向きかはハウススタイルの問題である。CURRENTを持たない端子、`"unspecified"` の端子、またはピンに `direction=` が書かれていない端子（9.2.4）は向きを与えず、実装が図形から推測する向きはここでは数えない。ルールはSELECT-TERMINALの条件 `current` で電流の向きにより端子を選択できる（10.1）。
- **矢印**：CURRENTは何も描画しない。CURRENTから矢印を描画するか否か、またどう描画するかは、どのネット名を表示するか（13.3）と同様にビューアの設定（そのハウススタイルの一部）である。自身で矢印を描くビューアは、標準の `$NO_CONNECT` を認識するのと同様に（12.6）、すでに標準の電流矢印の適用オブジェクトを持つ端子をスキップする。保持すべき矢印（インポートされた回路図に由来するもの、または作成者が決めたもの）は明示的なオブジェクトとして書く：

  ```rnl
  $CURRENT_ARROW @ATTACH #M5:1 => @ORIENT("R270") => @TEXT("I_{SS}", dx=1);   /* on the drain pin, with I_SS beside it */
  $CURRENT_ARROW @ATTACH (12, 20) => @ORIENT("R270")                           /* in the middle of a wire, at absolute coordinates */
  ```

  - 端子上に描かれる矢印は、その定義がその点を端子のピンに結び付ける適用オブジェクトである（12.1項目5）。ピンとともに回転することはないためその向きを記述し、その横のテキストはその適用オブジェクトに取り付けられる（13.3）。
  - 配線の途中の矢印はその配線にアンカーされているわけではなく、絶対座標の点に描画される。
  - 内向きの矢印と外向きの矢印をどう見分けるか、および矢印の定義とシンボルをどう描くかは標準パッケージに属する。シンボルは先端に矢尻の付いた単なる線分であってもよい（9.2.5）。
  - 描画された矢印はCURRENTとは別に保たれる：両者が1つのものであったなら、矢印をエクスポートすることでレイアウトが目指すものが変わってしまうためである。

### 15.3 表明：ASSERT-INSTANCE、ASSERT-TERMINAL、ASSERT-NET、ASSERT-USAGE、ASSERT-IN

```rnl
$MATCHED_PAIR = @DEFINE(roles=[["left", "instance"], ["right", "instance"]]) {
  {?left ?right} @ASSERT-INSTANCE(same=["model", "w", "l"], different=["name"]);
  {?left ?right} @SELECT-TERMINAL(terminal="s") => @ASSERT-TERMINAL(same=["net"], message="the sources of a pair share a net")
};
# @SELECT-INSTANCE(name="MD*") => @ASSERT-INSTANCE(type="nmos");
%dp1 @ASSERT-USAGE $DIFFERENTIAL_PAIR_N;                      /* %dp1 is a usage of this definition */
#M5:s @SELECT-NET => @ASSERT-IN $GROUND_NET_SET              /* the source of M5 is on a ground net */
```

- 表明（assertion）は、対の両側が同じモデルとサイズを持つか、ダミーが同じ型であるかなど、ファイルや定義の記述が回路の事実と一致しているかを検査する。表明は報告のみを行い、事実を作らず、描画を何も変えず、解決にも参加しない（8.5）。
- **各種別につき1つのキーワード**（選択と同様、10.1）：ASSERT-INSTANCEはインスタンス（および最初のメンバーによるバンドル；11.8）、ASSERT-TERMINALは端子、ASSERT-NETはネット、ASSERT-USAGEは適用オブジェクトを検査する。1つのスロットがその種別のオブジェクトのセットをとり、単一のオブジェクトは要素数1のセットとなる。オブジェクトの種別はテキストを読み取る時点で判明しており、種別の誤りはその時点でエラーとなる（5.2.4）ため、種別を検査する表明はない。
- **条件**は同じ種別の選択キーワードの条件（10.1）と同じ名前と意味を持つ（`type="nmos"`、`terminals=4`、`net="vss"`、`port=true` など）：すべてのメンバーが書かれた各条件を満たさなければならない。
- **`same=[…]`**：リスト内の各属性についてすべてのメンバーが同じ値を持つこと。**`different=[…]`**：リスト内の各属性について任意の2メンバーが異なる値を持つこと。属性名は `${…}` のものであり（13.6）、インスタンスでは `name`、`value`、`model`、`type` とそのパラメータ名、端子では `net`、ネットでは `name`、適用オブジェクトでは `definition` である。端子・ネット・適用オブジェクトではこれらがすべてであり、他の名前は誤ったパラメータ値となって表明が失敗する（7.1）。インスタンスではパラメータ名は開かれているため任意の名前が受け入れられ、メンバーが持たない属性は固有の値「不在（absent）」として扱われる：それを持たないメンバー同士は互いに等しく、書かれたすべての値と異なる。したがって `same=["nf"]` はどのメンバーも `nf` を書いていないときは成り立ち、一部が書いて一部が書かないときは違反を出し、そのパラメータを持たないプロセスの素子に対して専用の表明を書く必要はない。型を持たないインスタンス（10.1）は `type` を欠いている。値は式がないため評価せずホストが書いたとおりに比較される（3.7）。
- **`has=[…]`**（ASSERT-INSTANCE用）：`has=["w", "l"]` のように、すべてのメンバーがリスト内の各属性を持つこと。いずれかを欠くメンバーは違反を出す。`same` は属性が書かれていることを求めないが、`has` は求める。
- **ASSERT-USAGE** はSELECT-USAGEと同様に最後のオブジェクトとして定義をとり（5.6、10.1）、省略してもよい。これが書かれた場合、すべてのメンバーはその定義（名前の綴りではなく名前が解決する先によって認識される；9.5）の適用オブジェクトでなければならない。その条件は `symbol` と `drawn` である（10.1）。`same=["definition"]` はすべてのメンバーが1つの定義の適用オブジェクトであるときに成り立ち、`different=["definition"]` は同じ定義のものが2つないときに成り立つ。
- **ASSERT-IN**：`X @ASSERT-IN S` はXのすべてのメンバーがセットSのメンバーであるかを検査する。SはADD-TOと同様に最後に書かれ（5.2.2）、セットでなければならず、1つのセットへ包まれることはない。2つのメンバーが同じか否かはハンドルによって決まる（5.2）。メンバーは任意の種別でよく、Sは選択に依存してよい（10.4）。条件はなく `message` のみをとり、違反はSが含まないXのメンバーを名指しする。セットの差集合（5.2.2）と組み合わせれば、あるセットが空であることを言うこともできる。
- `different=["name"]` は2つのロールを同じオブジェクトで埋めてはならないときのように、インスタンスやネットが異なるオブジェクトであることを検査する。端子は `name` を持たないため、端子に対しては `different` でも `same` でも `name` は誤ったパラメータ値である。
- **報告**：成り立たない検査はメンバーと属性を名指しする違反（7.6）を出し、**`message`** はそれにテキストを追加する。何も失敗せず、描画は表明がない場合と同じである：表明は作成者や `rnl check` などのツールのための報告にすぎない。
- **場所と時期**：任意のレベル、および一般定義の定義本体（各適用ごとに検査される；9.4）に書ける。表明は `drawn` や `symbol` も含めすべての条件が読み取れる8.2のステップ7の後に検査される（10.1）。メンバーのないセットは自明に成り立ち、空ノードを渡された表明も同様である（6.3）。
- 表明は優先度を持たず、`priority="disabled"` を持つレコード内および優先度が `"disabled"` である適用オブジェクトの定義本体内（14.8）では検査されない。

### 15.4 トポロジ表明：ASSERT-TOPOLOGY

```rnl
{#R1 #R2 #R3} @ASSERT-TOPOLOGY("series");                  /* a chain: R1 to R2 to R3 */
{#M3 #M4} @ASSERT-TOPOLOGY("parallel", exclude=[["nmos", "g"], ["nmos", "b"]]);   /* drains on one net, sources on one net */
{#L1 #C1 #L2} @ASSERT-TOPOLOGY("star");                    /* a T network: three branches meet at one net */
{#C1 #L1 #C2} @ASSERT-TOPOLOGY("loop");                    /* a pi network: C1, L1 and C2 go round */
{%branch1 %branch2} @ASSERT-TOPOLOGY("parallel")           /* two branches, each a usage or a set taken as a black box, between the same nets */
```

- ASSERT-TOPOLOGYは複数のメンバーが指定された方法で接続されているかを検査する：直列、並列、スター、または単一ループである。これは15.3と同様の表明であり、15.3がそれらについて述べたことはこれにも当てはまる：報告のみを行い、成り立たない検査は違反（7.6）を出し、`message` がそれにテキストを追加し、どこで・いつ・どの優先度のもとで検査されるかも同じである。
- **メンバー**：1つのスロットは項目で数えられる順序付きメンバーのセットをとる（5.2）：1つのオブジェクトが1つのメンバーであり、`{…}` またはセットへの参照である項目は1つのメンバー（ブラックボックス）である。唯一のオブジェクトであるセットはまず1レベル展開されるため（5.2.1）、`%chain @ASSERT-TOPOLOGY("series")` は連鎖の各項目を検査し、`{%branch1 %branch2}` は2つのメンバーを持つ。したがってメンバーはインスタンス（または最初のメンバーによるバンドル；11.8）、適用オブジェクト、またはセットである。各メンバーにつき1項目を持つ選択の結果が渡された場合、メンバーはその結果の順序になる（10.3）。メンバーが2つ未満のときは検査は自明に成り立つ。
- **メンバーのネット**：
  - インスタンス：`exclude` が除外しないその端子が乗っているネット；
  - 適用オブジェクトまたはセット：自身がもたらす端子からなる1つの要素（ブラックボックス）。適用オブジェクト（シンボルの有無を問わない）はそのロールを埋めるものを表し、セットはそのメンバーを表し、最も内側までたどられる。インスタンスはそのすべての端子を、端子はそれ自身のみを、ピンはそれが束縛する端子をもたらし、ネットと点は何ももたらさず、バンドルはその最初のメンバーで数えられる。ブラックボックスのネットとは、それがもたらす端子のうち `exclude` が除外せず、かつその外部でも（それがもたらさない端子によって——バンドルの他のメンバーの端子を含む——、またはそのレベルのポートとして）使われている端子が乗っているネットである。それがもたらす端子のみによって使われているネットは数えない。注記：2つのメンバーが共有するネットは、それぞれのメンバーの外部で他方によって使われているため、ネットがポートであるか否かが判定を変えるのは、同じ端子をもたらすメンバー同士の場合に限られる。それ以外の場合は、ツールがそれを表示することがあるように、どのネットがそのブラックボックスのネットになるかを変えるにとどまる。
- **`exclude=[[type, terminal], …]`**：数えない端子を、型（条件 `type` と同様に比較される；10.1）と端子名または番号のペア（`exclude=[["nmos", "g"], ["nmos", "b"]]` など）として指定する。ペアの端子はSELECT-TERMINALの条件 `terminal` と同様に比較される（10.1）：番号は位置によって、名前はホストの大小文字規則によって比較され、そのインスタンスが持たない名前は何にも一致しない。型を持たないインスタンスの端子、またはリストが名指ししない型の端子は数えられる。`exclude` がなければすべての端子が数えられる。2つの文字列の配列または文字列と整数の配列でないペアは誤ったパラメータ値であり、表明は失敗する（7.1）。
- **トポロジ**（1番目のパラメータ、位置指定で与えられ、次の4つのいずれか）：
  - `"series"`：順序上隣接する各2つのメンバーがちょうど1つのネットを共有し、隣接しない2つのメンバーはネットを共有しないこと。共有ネット上に他に何があるかは検査されない：分圧回路の中間点が別の場所へ繋がっていてもよい。
  - `"parallel"`：少なくとも2つのネット（両端）がすべてのメンバーによって共有されていること。`"series"` で共有ネット上の他のものが検査されないのと同様に、1つの枝が引き出すタップのようなメンバーの他のネットは検査されない。
  - `"star"`：1つのネットがすべてのメンバーによって共有されており、他のどのネットも2つのメンバー間で共有されていないこと。
  - `"loop"`：少なくとも3つのメンバー。最後と最初の間を含めて順序どおり一周したとき、隣接する各2つのメンバーがちょうど1つのネットを共有し、それらのネットがすべて異なり、隣接しない2つのメンバーはネットを共有しないこと。2つのメンバーで `"loop"` を書くと違反になる。その場合は `"parallel"` を書く。
