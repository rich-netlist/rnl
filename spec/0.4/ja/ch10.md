## 10 選択、ルール、1つずつの生成

本章では選択キーワード、それを用いるルール、および1つずつの生成を扱う。

### 10.1 選択キーワード

選択されるオブジェクトの種別ごとに1つの選択キーワードがあり、それぞれ固定された条件の集合を持つ。選択の結果はセットである（5.2）。

各選択キーワードは1つのスコープオブジェクトをとる。`#` はその選択が評価されるレベルである（10.3）。オブジェクトまたはセットが与えられると、選択はそのオブジェクト群の中から探索する：例えばネットのセットが与えられると、SELECT-TERMINALはそのネット上の端子を選択する（スコープがどのように選択種別へ導かれるかは表の後に説明する）。スコープは省略できないため、単純な選択であっても `#` を書いて `# @SELECT-INSTANCE(name="R*") => @SET-SYMBOL $RESISTOR` のように記述する。

| キーワード | 選択対象 | 条件 |
|---|---|---|
| SELECT-INSTANCE | ホストインスタンス。スコープに端子がある場合はそれらが属するインスタンス、ネットがある場合はその上に端子を持つインスタンス | `name`（インスタンス名、`name="R*"` など）、`model`（インスタンス行のモデル位置にある名前：`.model` 名またはサブサーキット名）、`type`（`.model` またはDEVICEによるインスタンスの型、`"nmos"` など；`*` をとる）、`terminals`（インスタンスの端子数、`terminals=3` など）、`symbol` と `drawn`（下記） |
| SELECT-TERMINAL | ピンを持つか否かを問わないホストインスタンスの端子（回路側の選択） | インスタンスの `name`、`model`、`type`、`terminal`（端子名または番号）、`net`（接続先のネット名）、`current`（電流方向、15.2：`"in"`、`"out"`、または `"unspecified"`） |
| SELECT-PIN | 描画されるオブジェクトのピン（図面側の選択；9.2.4） | ピンを所有するオブジェクトの `name`、`model`、`type`、`terminal`（ピンが束縛する端子名またはロール名）、`net`（その `::net` の名前）、`wired`（10.2） |
| SELECT-NET | ネット。スコープにインスタンス・端子・配線がある場合はそれらが接続しているネット | `name`、`port`（このレベルのポートか否か）、`wired`（10.2）、`global`（グローバルネットか否か；6.3） |
| SELECT-WIRE | 配線。スコープにネットがある場合はその上に描かれた配線 | `net`（配線のネット名；バスの場合はいずれか1つのネットが一致すれば一致）、`bus`（`true`：バスのみ（13.1）、`false`：バス以外の配線（netスロットがセットではなくネットを受け取ったもの）のみ） |
| SELECT-LABEL | ラベル、すなわちオブジェクトに取り付けられたTEXT（13.3）。スコープにオブジェクトがある場合はそれに取り付けられたラベル | `key`（テキストのkey；`*` をとり大小文字を区別する；keyのないラベルはどの `key=` にも一致しない） |
| SELECT-ANNOTATION | 注釈、すなわちシーン内の図形および点に取り付けられたTEXT（13.4） | `role` と `recursive` 以外の条件はなし |
| SELECT-USAGE | `scope @SELECT-USAGE $D`：スコープ内で内向きに探した定義 `$D` の適用オブジェクト。`#` ではそのレベルの適用オブジェクト、適用オブジェクトではそれら自身とその内部の適用オブジェクト。`$D` がない場合は任意の定義の適用オブジェクト | 定義は最後のオブジェクト（5.6）であり省略可。`symbol` と `drawn`（下記） |
| SELECT-ANCESTOR-USAGE | `objects @SELECT-ANCESTOR-USAGE $D`：これらのオブジェクトをメンバーとして持つ外向きの `$D` の適用オブジェクト（間接的なメンバーも含む） | 定義は最後のオブジェクト（5.6）であり必須。`recursive` 以外の条件はなし |

これらに加えて、すべての選択キーワードは条件 `recursive` をとり、最初の7つは `role` をとる（これはスコープが適用オブジェクトを保持する場合にのみ意味を持つ；ともに下記）。

- **各種別に1つのキーワード。** 各選択キーワードは選択対象の種別にちなんで命名されている（ネットの配線を選ぶ `&clk @SELECT-WIRE => @SET-STYLE $signal` や、M1のラベルを選ぶ `#M1 @SELECT-LABEL` など）。すべての種別のオブジェクトをまとめてとる選択はない：すべての種別を対象にするには、標準パッケージがすべてのオブジェクトにベーススタイルを与えるために行っているように、種別ごとに1つずつルールを書く。
- **スコープがどのように選択種別へ導かれるか。** スコープ内の各オブジェクトは選択される種別へ向かって1段階だけ進む。そのような遷移先を持たないオブジェクトは何も選択しないが、これはエラーではない：
  - SELECT-INSTANCE：インスタンスはそれ自身、端子はそのインスタンス、ネットはその上に端子を持つインスタンス。
  - SELECT-TERMINAL：インスタンスはその端子群、ネットはその上の端子群、端子はそれ自身、ピンはそれが束縛する端子群。
  - SELECT-PIN：描画されるオブジェクト（インスタンス、バンドル、シンボルを持つ適用オブジェクト）は自身のシンボルのピン群へ導かれ、適用オブジェクトに `role` が付くと代わりに他の選択がメンバーをとるのと同様にそのロールを埋めるピン群へ導かれる（下記）。シンボルを持たない適用オブジェクトはロールを埋めるオブジェクト群の中のピン群へ、端子はそれを束縛するピン群へ、ネットは `::net` がそのネットであるピン群（そのネットで埋められたロールに束縛されたピンを含む）へ、ピンはそれ自身へ導かれる。`#` ではそのレベルのすべてのピンとなる。
  - SELECT-NET：ネットはそれ自身、インスタンスはその端子のネット群、端子はそのネット、配線はその描画対象のネット群。
  - SELECT-WIRE：ネットはその上に描かれた配線群、配線はそれ自身。SELECT-LABEL：オブジェクトはそれに取り付けられたラベル群、ラベルはそれ自身。SELECT-ANNOTATIONはスコープ内の注釈のみをとる。
  - 端子を経由する遷移はピンの有無にかかわらずすべての端子を数える（端子は回路に属するため）。描画されるものを選ぶときはピンを通じて選択する。したがって `&vss @SELECT-INSTANCE` には、シンボルで描画されないバルク端子だけがvssに繋がっているNMOSも含まれる。`#:inp` のようなこのレベルのポートはそのネットへ導かれる。
  - 適用オブジェクトがスコープの場合、選択される種別のメンバーのみが取り出され、メンバーを再度スコープとして先へ進むことはしない（下記）。
  - 例えば、クロックで制御されるトランジスタは `&clk @SELECT-INSTANCE`、そのうちゲートがclkに繋がるものだけは `&clk @SELECT-TERMINAL(terminal="g") => @SELECT-INSTANCE`、M1のネット群は `#M1 @SELECT-NET` である。
  - 注記：図面にグラウンド・配線・ラベル・スタイルを追加するルールはピンを選択するため（SELECT-PIN）、追加されるものが描画内容と一致する。回路を検査するルールは端子を選択する。
- **シンボルによる条件：`symbol` と `drawn`。** SELECT-INSTANCEとSELECT-USAGEは文字列 `symbol="$X"` をとる：そのオブジェクトが、その `$` 名を通じてSET-SYMBOLで与えられたシンボル（記述されたとおりの名前とワイルドカード `*` で比較、`symbol="$IO_PORT*"` など）で描画されていること。`%` 名または無名定義で与えられたシンボルはいずれの `symbol=` にも一致しない。そのSET-SYMBOL内の `$` 名の別名は元の名前として読み取られるため（16.5）、元の名前で比較される。`symbol=` の文字列は翻訳されない（16.5）ため元の名前で書く。名前が解決する先によって認識されるSELECT-USAGEの定義（9.5）とは異なり、これは名前の比較である。パラメータはリテラルのみをとるため（3.7）、他の条件で名前を書くときと同様に名前を文字列として書く。これらはまた `drawn` もとる（`true`：文、ルール、ブロックシンボル、または既定のブロックシンボル（9.2.6）で与えられたシンボルによってオブジェクトが描画されている；`false`：そうでない場合、例えばシンボルを持たない適用オブジェクト）。すべてのインスタンスは描画される。これらの条件はシンボルを読み取るため、シンボルが与えられた後に実行される生成ルールとスタイルキューで動作する（8.2）。SET-SYMBOLの選択内に書くと、シンボルキューはこれから与えるシンボル自身によって選択することはできないためエラーとなる。SELECT-PINも同様にシンボルを読み取るため同じ制限があり、スコープがピンである選択やピンを経由する選択（`#R1::p @SELECT-TERMINAL` など）も同様であり、SET-SYMBOLの選択内ではエラーとなる。オブジェクトのロール名・ローカル名・標準サブオブジェクト名ではない名前を `::` で続けたスコープ（`#X1::k` など）も同様である：それがシンボルのもたらすピン名かテキストのkeyかはシンボルが与えられて初めて判明するためである（6.5）。
- **このレベルのみか、下位レベルも含むか。** すべての選択キーワードは条件 `recursive` をとり、デフォルトは `false` である。ルールはそれが書かれたレベルで評価され、下位どこまで到達するかは次のように決まる。各評価においてその中のすべての選択とすべてのセットはそのレベルで評価され、そのレベルのメンバーのみを保持する（10.3）。
  - **選択が直接書かれたルール**（パイプ内またはそこに書かれた `{…}` 内）：それらの選択のいずれかが `recursive=true` と書いている場合、かつその場合にのみ下位レベルに到達する。使用するセットはこれを変えない。したがって `# @SELECT-INSTANCE(recursive=true) => @SELECT-PIN(net="vss", wired=false) => $GROUND_STUB @ATTACH` はこのレベルおよびその下位のすべてのレベルにグラウンドを追加する一方、`# @SELECT-NET(name="vdd") => @REMOVE-FROM $PORT_FILL_SET` は自身のレベルでのみ作用する。
  - **選択が直接書かれていないルール**（選択に依存するセットをとるルール；10.4）：それらのセットのいずれかが到達するすべての下位レベルに到達する。あるセットが到達するのは、自身のレベル、およびそれに選択の結果を追加する文（束縛元の文、項目中のセット、およびそれに追加するADD-TO文。ただし選択の直接記述がないADD-TOは追加先のセットではなく追加する側のセットの到達範囲を使う）が到達するレベルである。セットが到達しないレベルではそのセットはメンバーを持たない（そこに到達するルールがそのセットを使った場合も同様）。したがって `$GROUND_NET_SET = # @SELECT-NET(name="0", recursive=true)` のとき、このセットはすべてのレベルのネット0を持ち、`%g_set = {$GROUND_NET_SET}` もそこまで到達し、`$IO_PORT @ATTACH $PORT_FILL_SET` や `$SUPPLY_NET_SET @REMOVE-FROM $PORT_FILL_SET` はそれらのセットが到達するすべてのレベルで作用する。
  - 単一のホストオブジェクト（`&vss` など）は単に参照されるだけである：ホスト参照は自身のレベルでのみ解決されるため、`{&vss}` のようなそのセットが下位レベルに到達することはない。
- **SELECT-USAGEとSELECT-ANCESTOR-USAGE。** 両者とも定義をその名前が解決する先によって認識し（9.5）、常に適用オブジェクトを選択し、`role=` を持たない。
  - SELECT-USAGEは他の選択キーワードと同様に内向きに探索する。`#` をスコープにすると評価中のレベルの適用オブジェクトを選択し、適用オブジェクトまたはそのセットをスコープにするとそれら自身とその内部の適用オブジェクトを最も内側まで選択する。スコープ内のインスタンス、ネット、端子は適用オブジェクトではないため何も選択せず、それらが属する適用オブジェクトにはSELECT-ANCESTOR-USAGEを使うよう警告で案内する。
  - SELECT-ANCESTOR-USAGEは外向きに探索する：スコープ内のオブジェクトを直接または間接のメンバーとして持つ適用オブジェクトを選択する（下例参照）。スコープ内の適用オブジェクト自身は含まれない。`#` をスコープにするとエラーになる（レベルは何かのメンバーではないため）。
- **適用オブジェクトをスコープとする場合。** 適用オブジェクトをスコープとすると、他の選択キーワードはその適用オブジェクト内の自身の種別のメンバーを選択し、`role=` はそのロールのメンバーのみをとる。SELECT-PINのみが、シンボルを持ち `role` なしの適用オブジェクトについて自身のシンボルのピン群を返す点で異なる（上記）。適用オブジェクトであるメンバーは最も内側まで再帰的にたどられる：

  ```rnl
  $OTA = @DEFINE(roles=[["pair", "usage"], ["load", "usage"]]) {};
  %dp1 = #M1(left) #M2(right) #M5(tail) @AS $DIFFERENTIAL_PAIR_N;
  %cm1 = #M3(ref) #M4(out) @AS $CURRENT_MIRROR_P;
  %ota1 = %dp1(pair) %cm1(load) @AS $OTA;
  %all_set = %ota1 @SELECT-INSTANCE;                 /* {#M1 #M2 #M5 #M3 #M4} */
  %pair_set = %ota1 @SELECT-INSTANCE(role="pair");   /* {#M1 #M2 #M5} */
  %up_set = #M1 @SELECT-ANCESTOR-USAGE $OTA          /* {%ota1} */
  ```

  - `role=` の値は、その適用オブジェクトの定義の `definition=` 別名も受け入れる（16.5）。直接のメンバーだけを得るには、`%dp1::tail` のようにロールをサブオブジェクトとして書く。探索はすでに訪れた適用オブジェクトで停止する。メンバーとはロールを埋めるオブジェクトであり、定義本体のローカルオブジェクトではない（9.4）。
  - **選択対象の種別のメンバーのみ。** メンバーをスコープとしてさらに先へ進むことはせず、他の種別のメンバーも数えない。SELECT-TERMINALは端子メンバーのみをとる：`$GROUND @ATTACH &0; $CURRENT_ARROW @ATTACH #M5:1` の後で `# @SELECT-USAGE => @SELECT-TERMINAL` は {#M5:1} のみであり、ネット0上の端子群ではない。差動対 %dp1 のメンバーはインスタンスなので `%dp1 @SELECT-TERMINAL` は空になる。メンバーインスタンスの端子群を得るには `%dp1 @SELECT-INSTANCE => @SELECT-TERMINAL(terminal=2)`（テールを含む3つのトランジスタすべてのゲート）、メンバーネット上の端子群を得るには `… => @SELECT-NET => @SELECT-TERMINAL` と書く。各セグメントは1つのことだけを行うため、さらに進むにはセグメントを追加する。スコープに直接渡されたオブジェクトは上記の規則に従う：ネットはその上の端子群、インスタンスはその端子群を与える。
  - **変換を通じて埋められたロール**（5.2.4；端子が渡された種別 `"pin"` のロールなど）は、シンボルが与えられるまでは記述されたオブジェクトを保持し、それ以降は変換後のオブジェクトを保持する。したがって生成ルール以降では、ロールにピンが名前で渡されたかそれを代表する端子が渡されたかにかかわらず `@SELECT-PIN(role="t")` がそのピンを選択する。
- シーン内のオブジェクトを条件で探すには常に選択キーワードを使用する。`::` はそのオブジェクト自身の部分のみを取り出す（6.5）。
- **バンドル。** バンドルのメンバーを選択することはできず、代わりにバンドル自身が選択される（11.8）。SELECT-INSTANCEは最初のメンバーの条件でバンドル自身を、各バンドルにつき1回選択する。SELECT-TERMINALはバンドルの端子を選択し、`net=` はいずれか1つのメンバーのネットに一致すれば一致する。
- **条件**は `name=value` のように名前指定で書き、書かれたすべての条件が成り立つときにのみオブジェクトが選択される。「または（or）」を表すには複数のルールを書く。名前を比較する条件（`name`、`model`、`net`）はワイルドカード `*`（任意の0文字以上に一致）をとり、DEVICEと同様にホストの大小文字規則で比較する（6.12）。素子文字で選ぶには `name="R*"` と書く。Spectreのインスタンス名は素子文字で始まらないため、`model="resistor"` のように `model` で選択する（6.12）。
- **`model`** はインスタンス行のモデル位置に書かれた名前を比較する：M・Q・Dなどの素子では `.model` 名、Xインスタンス（ネットリストに定義のないPDK素子を含む；`# @SELECT-INSTANCE(model="sky130_fd_pr__nfet_01v8")` など）ではサブサーキット名、Spectreではマスタである。これはDEVICEの `model=` と同じである（6.12）。`type` はインスタンスの型（`.model` の型、またはXインスタンスのようにホストが持たない場合はDEVICEが与えた型；6.12）を比較し、どちらもないインスタンスは型を持たないためいずれの `type=` にも一致しない。`type` も名前比較条件と同様にワイルドカード `*` をとる：`type="*mos"` は nmos と pmos に一致し、`type="*"` は何らかの型を持つインスタンスを選択するため、ルールや表明から型不明の素子を除外したいときに使える。
- **`terminals`** はインスタンスの端子数（整数）を比較する：DEVICEがいくつ名前を与えたかにかかわらず、ホストがその行上で読み取り 1, 2, … と番号を振るノード数である（6.12）。したがって `terminals=3` は `Q1 c b e qn` を選び `Q2 c b e s qn` を選ばない。Xインスタンスではその行のノード数すなわちサブサーキットのポート数を数え、Spectreでは丸括弧内のノード数を数えるため `S1 (com t1 t2) switch` は3となる。これは `# @SELECT-INSTANCE(type="nmos", terminals=4) => @SET-SYMBOL $NMOS_4TERM` のように他の条件と組み合わせられる。バンドルは最初のメンバーで選択される（11.8）。
- 比較は3.6に従う：条件名と標準の列挙値は大小文字を区別し、ホストのものを名指す値（名前、モデル名、ネット名）はホストの規則に従う。
- ネットは名前で選択できる：`# @SELECT-NET(name="0")` はそのネットを、`# @SELECT-TERMINAL(net="0")` はその上の端子を選択する。意味によってオブジェクトを選択することもできる：`# @SELECT-USAGE $DIFFERENTIAL_PAIR_N => @SELECT-INSTANCE(role="left")` はすべての差動対の左トランジスタを選択する。
- 「ある適用オブジェクトに属するセットのメンバー」のような共通部分（積集合）のためのキーワードはない。REMOVE-FROMを2回使って記述する（5.2.2）：

  ```rnl
  %s_set = {#M1 #M3 #M5};
  %s_set @SELECT-ANCESTOR-USAGE $DIFFERENTIAL_PAIR_N => @SELECT-INSTANCE => %dp_m_set;
  %out_set = {%s_set};
  %dp_m_set @REMOVE-FROM %out_set;    /* the members of %s_set in no differential pair */
  %in_set = {%s_set};
  %out_set @REMOVE-FROM %in_set       /* the members of %s_set in a differential pair */
  ```

- **グラウンドネットと電源ネット**は標準パッケージが提供するセット `$GROUND_NET_SET`（デフォルトはネット0）および `$SUPPLY_NET_SET`（デフォルトは空）によって与えられる。ネットクラスという概念はない。
  - パッケージはホスト参照を含められないため（16.2）、このようなセットのデフォルト内容は `# @SELECT-NET(name="0", recursive=true)` のような選択としてのみ記述できる。
  - ユーザーはADD-TOとREMOVE-FROMでネットを追加・削除する：

    ```rnl
    &vss @ADD-TO $GROUND_NET_SET;                                       /* the vss of this level */
    # @SELECT-NET(name="vss", recursive=true) => @ADD-TO $GROUND_NET_SET;   /* the nets named vss of every level */
    # @SELECT-NET(name="vdd!", global=true, recursive=true) => @ADD-TO $SUPPLY_NET_SET  /* only the global vdd! */
    ```

    2つ目の文はサブサーキット内のローカルネット vss も追加する。1箇所だけあるネットを除外するには、セットをコピーしてそのコピーからネットを削除する：`%g_set = {$GROUND_NET_SET}; &vss2 @REMOVE-FROM %g_set`。
  - 自動補完ルールは `$GROUND_NET_SET @SELECT-PIN(wired=false, recursive=true) => $GROUND_STUB @ATTACH` のようにこのようなセットをスコープとして使う。これにより仮想部品がこれらのネット上に持つピンも取得されるため、標準パッケージはグラウンド自身など自身が配置した部品のピンを除外している。
  - 自分のレベルで `$GROUND_NET_SET = …` と書くとパッケージのセットが隠蔽され、パッケージのルールが新しいセットを参照しなくなる（6.8）。
  - グラウンドや電源をネット名から推測することはない。インポータはエディタファイル内のネットの電源ドメイン（`powerDomain` など）をADD-TOとして書き出す。
  - ソルバーは標準パッケージの定義を読み取るのと同様に、これらの標準セットをヒント（電源は上、グラウンドは下など）として読み取ってもよいが、必須ではない。
  - 注記：グラウンドや電源ネット用のキーワードはない（1.5項目7）：グラウンドの追加やシンボルの変更のために端子を選択するといった用途はすべてパッケージ内のルールとして書けるためである。
- **空ノード**（6.3）はネットではない：SELECT-NETがそれを返すことはなく、その上のピンはネットや `net=` 経由ではなくそのオブジェクトまたは `#` 経由でのみSELECT-PINに選ばれ、その上の配線は `net=` なしのSELECT-WIREでのみ選ばれる。
- **グローバルネット。** SELECT-NETの条件 `global=true` はグローバルネットのみを選択する（6.3）。異なるレベルの同名ローカルネットは別々のノードであり、名前で選択するとそれらすべてが選ばれるため、グローバルなものだけをとるにはこの条件を付ける。

### 10.2 条件 `wired`

- ピンが `wired=false` となるのは、どの明示的な配線上の点（端点または途中の点；端子に書かれた配線はその端子のピンで終端する；5.2.4）でもなく、かつROUTE-NETまたはROUTE-OBJECTのどのツリーにも含まれない場合である（13.7；ソルバーがツリーの配線を描くため）。バスピンは1つのピンであり、そのいずれかの端子を通じて配線が終端していれば配線済みである（9.2.4）。バス配線も明示的な配線である（13.1）。バンドルの端子への配線はすべてのメンバーのその端子を接続する（11.8）。
- ネットが `wired=false` となるのは、その上のホストインスタンスのどの端子も明示的な配線に触れておらず、かつROUTE-NETまたはROUTE-OBJECTのどのツリーもその上にない場合である。仮想部品のピンは数えない。
- どのピンがツリーに含まれるかは8.2の2つの段階で確定する。ステップ4の後、シンボルが与えられた時点でステップ3の文から確定するもの：ステップ5で評価されるROUTE-NET、ROUTE-OBJECT、UNROUTE-NET、UNROUTE-OBJECTのルール（10.4）はこのツリーを読み取り（`{&a &b} @SELECT-NET(wired=false) => @ROUTE-NET` など）、互いに他の結果を見ないため、あるルールが自身の作ったツリーを読み取ることはない。ステップ5の後、それらのルールが作成・変更したツリー：ステップ6以降の条件がこれらを読み取る。したがって生成ルール（標準パッケージの自動補完など；16.3）は、ROUTEルールが結んだピンを配線済みと数え、UNROUTEルールが除外したピンは（明示的に書かれた配線が触れていない限り）未配線と数える。ステップ6で生成された内容の中のroute文（生成された適用オブジェクトの定義本体など）もツリーを作成・変更するが、どの条件もそれを見ない。
- 空ノード上に書かれた配線（13.1）も他の配線と同様に数えられる：それが終端するピンは配線済みとなる。
- 数えられるのは明示的に書かれた配線のみであり、生成された配線は数えない。仮想部品の有無は影響しない。
- 配線は8.2のステップ3から記述されたとおりに数えられ、端子がピンを持たないために後で失敗する配線（7.1、9.2.4）も含まれる。書き換えられる配線については最後の書き換えが数えられる（13.1）。

### 10.3 選択の評価

- 選択は書かれた場所では展開されず、各評価は1つのレベルのみを見る。ルール（10.4）は書かれたレベルで1回、到達する下位の各レベルで1回ずつ評価され（10.1）、各評価において `#` はそのレベルであり、選択はそのレベルのオブジェクトのみを選択する。したがってトップレベルに書かれた `# @SELECT-INSTANCE(model="nch", recursive=true) => @ALIGN("y")` は各図面内で1回ずつ整列を行い、異なる図面のインスタンス同士を整列させることはない。
- 選択はそれを使用するフェーズで評価される：外観ルールはシンボルキューとスタイルキュー、routeキーワードのルールはステップ5、生成ルールは生成フェーズ（8.2）。セットも同様である（5.2）。
- 選択がどの種別を選択するかは読み込み時に判明する。その種別をとらないスロットに（セットの内部であっても）それを渡すと直ちにエラーとなる（`# @SELECT-TERMINAL(net="vss") => @SET-SYMBOL $NMOS` など）。
- SELECT-USAGEとSELECT-ANCESTOR-USAGEは常に適用オブジェクトを選択し、適用オブジェクトからそのメンバーへ進む選択ではそのキーワードが選択種別を決める。したがってあらゆる選択の種別は読み込み時に判明している。
- 選択の結果はセットであり、`%` または `$` で命名できる。あるレベルで評価されたセットはそのレベルのメンバーのみをとる：トップレベルに書かれた `&vss @ADD-TO $GROUND_NET_SET` はトップレベルのvssのみを追加し、サブサーキット内で評価されたときのそのセットには入らない（6.6）。
- **結果の順序。** 選択の結果のメンバーは次の順序で並び、これはORDER、DISTRIBUTE、TABLE、LINEや1つずつ適用されるルールの結果（5.2.1）などセットの順序が意味を持つあらゆる箇所で効力を持つ：
  - `#` がスコープの場合、そのレベルのオブジェクトは以下のシーン順：
    - インスタンスはネットリスト内の行順（バンドルはその最初のメンバーの行位置）、端子はインスタンスまたはバンドル順・次いで番号順。
    - ネット：そのレベルのポートをサブサーキット行の順、次にその他のネットをインスタンス行での初出順。
    - ピンはそれが属するオブジェクト順：まずインスタンスとバンドルを行順（バンドルは最初のメンバーの行位置）、次に適用オブジェクトをその順序で並べ、1つのオブジェクト内ではそのシンボルのPIN文の順。
    - 適用オブジェクト、配線、テキスト、および図形：まず8.2のステップ3で作られたものをその位置順（8.5）に並べ（適用オブジェクトの定義本体が作ったものはその適用オブジェクトの直後に定義本体の順）、次に後のステップで作られたものをステップ順に並べる。1つのステップ内ではそれを作る文またはルールの位置順となり、1つのルールの結果は入力の順（5.2.1）、シンボルがもたらすテキストはそれが属するオブジェクト順（ピンで示した順序）の次にシンボル内の順となる。keyによってシンボルのテキストを上書きするシーンのテキスト（13.3）は、最初にそれを書いた文の位置にある1つのテキストとなる。
  - それ以外のスコープでは、スコープの各メンバーが順に上記の順序で自身の結果を出し、すでに出力されたオブジェクトは重複して出力されない。これはSELECT-ANCESTOR-USAGEを含むすべての選択キーワードで成り立つ。
  - セットはメンバーが書かれた順序と追加された順序を保持する（5.2、5.2.2）：ADD-TOは末尾に追加して重複を保ち、UNIONは重複を除く。
- トップレベルに書いた `&Q<0:3:2, 1> @SELECT-TERMINAL(name="R*", recursive=true) => @TEXT("${net}", key="netname")` のように、選択のスコープがそのレベルのホストオブジェクトとして書かれている場合、ルールが下位レベルで評価されるときそれらのオブジェクトは存在しない：下位レベルではセットがそのレベルのメンバーのみをとるのと同様に選択は空になり、警告なしで何もしない。10.5の警告が出されるのは生成ルールの他のロールに対してのみである。

### 10.4 ルール

- 選択の結果を直接、または選択に依存するセットを通じて受け取る文はルールである。あるセットが選択に依存するのは、選択に束縛されているとき、自身の項目に選択またはそのようなセットを含むとき、そのようなセット同士のUNIONで作られたとき、あるいはADD-TOやREMOVE-FROMで選択の結果またはそのようなセットによって変更されるときである（5.2.2）：その場合、そのメンバーはそれを使用するフェーズでのみ判明する。適用オブジェクトの定義本体内では、セットロールを埋めるものが選択に依存するときそのセットロールも選択に依存する。
- BUNDLE（11.8）、WIRE（13.1）、および2点指定で書かれたRECTANGLE・CIRCLE・ELLIPSE（9.2.5）以外の任意のキーワードは、5.2.1の定めに従って1つずつまたは全体として選択の結果を受け取ることができる：`# @SELECT-INSTANCE(type="nmos") => @ORIENT("MY")`、`# @SELECT-INSTANCE(model="nch") => @ALIGN("y")`。
- 選択の結果をオブジェクトとするSET-SYMBOLとSET-STYLEは外観ルールであり、外観キューに入る（8.3）。ASとATTACHは生成ルールであり（10.5）、選択の結果に取り付けられたTEXT（13.3）、選択の結果を点とするサイズ指定付きのRECTANGLE・CIRCLE・ELLIPSE（9.2.5）、および描画オブジェクトを作るLINE・ARC・BEZIERのルールも同様である（これらのスロットはセットをとるため、そのルールはその結果の順序で全体を通る1つの図形を描く；5.2.1、10.3）。ROUTE-NET、ROUTE-OBJECT、UNROUTE-NET、UNROUTE-OBJECTのルールはそれらより前のステップ5で評価される：その条件はステップ3の文のツリーを読み取り、生成ルールはそれらが作ったツリーを参照する（10.2）。CURRENTのルールはステップ6で生成ルールとともに評価され、合わせてステップ6のルールを構成する：電流方向はステップ3の文から確定しており、ステップ6の条件はこれらのルールが変更する内容を参照しない（15.2）。BUNDLEは選択の結果をとれない：バンドルはシンボルが与えられる前に存在しなければならないためである（11.8）。その他のキーワード（制約、PLACE、ORIENTなど）のルールはそのキーワードのステップで有効になり、生成されたオブジェクトも参照する。他の任意のキーワードにおいて、ルールは選択された各オブジェクトに対して書いた文またはそれらすべてに対して書いた1つの文と同じであり、そのキーワードのフェーズで有効になる。
- ルールは、それが書かれたレベルおよび（自身に書かれた選択の `recursive=true` またはそれがなければ使用するセットを通じて）到達する下位レベルに適用され（10.1）、毎回そのレベルのみを見て各レベルで1回ずつ評価される（10.3）。パッケージ内のルールはそのパッケージのUSE-PACKAGEのレベルに書かれたものとして、またルートのパッケージはそのファイルのトップレベルで使われたものとして数えられる（16.2）ため、10.1の定めに従ってのみ下位レベルに到達する（標準パッケージが選択に `recursive=true` を書くのはこのためである）。一般定義の定義本体内のルールは適用オブジェクトのレベルに書かれたものとして数えられる（9.4）。
- **下位レベルに到達するルール内の、あるレベルのホストオブジェクト**：`%clk_set = {#VP1 #VP2}` かつ `%rest_set` が `recursive=true` の選択に束縛されているときの `%clk_set %rest_set @DISTANCE("bottom-to-top", min=3)` のように、下位レベルに到達するルールの他のスロットがそのレベルのホストオブジェクトを名指している場合、下位レベルではそれらのオブジェクトが見つからないためその文は効力を持たず、警告も出ない。警告が出るのは10.5が定める生成ルールのみである。

### 10.5 1つずつの生成

「vss上の配線の付いていない各端子に対して、グラウンドを配置して配線で結ぶ」：

```rnl
$GROUND_STUB = @DEFINE(roles=[["t", "pin"]], parameters=[["gap", 2]]) {
  %g = $GROUND @ATTACH ?t::net;
  ?t::net @WIRE {?t %g::pin};
  {?t %g::pin} @ALIGN("x");
  %g::pin ?t @DISTANCE("bottom-to-top", exact=?gap)
};
# @SELECT-INSTANCE => @SELECT-PIN(net="vss", wired=false) => $GROUND_STUB @ATTACH => %stubs_set
```

標準パッケージはこれと似た `$GROUND_STUB` を提供しているが、デフォルトのgapが1で最小距離のみを指定しており（`min=?gap`、長さの異なる部品のグラウンドを揃えるときなどソルバーが配線を長く伸ばせるようにするため）、グラウンドを下向きに固定し（`@ORIENT("R0")`）、制約の優先度が `"low"` である点が異なる。ここの定義はそれを隠蔽する（6.8）。

- ASまたはATTACHの単一ロールが選択の結果を受け取ると、選択されたオブジェクトごとに1回ずつ定義が適用され、他のロールはすべての適用で同じになる（5.2.1、9.4）。セットロールは選択の結果を全体として受け取り、定義は1回だけ適用される。ただし、そのロールがすべてセットロールの場合は、そのどれかに何かが入っているレベルでのみ適用される（9.4）。
- 仮想部品も同じ方法で1つずつ生成される：`# @SELECT-NET(port=true) => $IO_PORT @ATTACH` は各ポートネットにポートタグを与える。抵抗として描かれる2ロール定義 `$RLOAD` を用いた `# @SELECT-NET(name="out*", recursive=true) => $RLOAD @ATTACH &vss` は選択された各ネットとvssの間に1つずつ取り付けるが、`&vss` がこのレベルに属するため下記の警告を出してこのレベルでのみ有効になる。
- 標準パッケージの自動補完は配線付きのグラウンドおよび電源（`$GROUND_STUB`、`$SUPPLY_STUB`）を追加する：それらが書き戻されると、その配線によりピンはもはや `wired=false` ではなくなるため、自動補完はそれをスキップする。配線なしで制約だけでピンに置かれたグラウンドはピンを `wired=false` のまま残すため、自動補完はそこにも追加してしまう。2つのピンの間に長さ0の配線（13.1）を書けばピンは配線済みになる。
- 対応付けは各適用内で閉じる：定義のローカル名は適用のたびに新しくなるため、ある適用の `%g` はその適用で作られたグラウンドである。
- 結果は生成セットとなる。これには名前を付けて全体をSET-SYMBOLやSET-STYLEに渡すことができるが（`%stubs_set @SET-STYLE $grey` など）、個々のメンバーを単独で参照することはできない（5.7）。
- **手書きでの記述。** そのうちの1つを個別に記述するには、手で生成して配線する。するとそのピンはもはや `wired=false` ではなくなり、自動補完はそれをスキップする。生成を個別にキャンセルする別の手段はない。
- **スナップショット。** すべての生成ルールは同じスナップショット、すなわち8.2のステップ3〜5の結果（キーによる上書き後で、すべてのオブジェクトのシンボルとステップ5のツリーを備えた状態）を参照し、互いの結果を見ない。したがって同じルールを2回書くと2組生成される。
- 生成された事実は競合解決においてその生成ルールの位置をとる（8.5）。
- 位置を持たない生成オブジェクトはソルバーによって配置される。配置方法を指定するには制約付きの定義を用いる。
- **書き戻し。** 単一の生成オブジェクトは参照できない（5.7）。ソルバーがそれらを書き戻すときは、`$IO_PORT @ATTACH &out => @PLACE(40, 20) => %p_out` とそこへの配線のように明示的な文として書き出す。明示的オブジェクトが生成オブジェクトに取って代わるのは、標準パッケージの自動補完が配線のないピンのみを選択する（10.1）ように、あるいはネットごとの自動補完が2つのセットの差集合を書く（下記）ように、ルールがすでに書かれたものを除外している場合だけである。そうでない書き方のルールは、明示的オブジェクトの横に再び位置を持たないオブジェクトを生成してしまう。したがってソルバーが配置するオブジェクトを作るルールは、これら2通りのいずれかの方法で既出のものを除外すべきである。このように書き出された明示的な適用オブジェクトの定義本体内でローカル名を持たないオブジェクトは番号で参照される（5.9）。適用オブジェクトはルールがその適用に書いた優先度をそのまま付けて書き出され、あるいはそのルールのレコードヘッダーに `"disabled"` が書かれていればそれを付けて書き出される（14.8）。それ以外の場合は優先度なしで書き出され、定義本体が元の優先度を保つようにし、別の優先度を持つレコードヘッダーは書かれない。
- 生成は再帰しない：生成ルールが展開した内容にステップ5または6のルール（10.4）が含まれている場合、各ステップは1回しか走らないためそれらは失敗する。それ以外のルールは後のステップで通常どおり有効になる：SET-SYMBOLはステップ7のシンボルキュー、PLACE・ORIENT・LAYER・PRIORITYおよび制約はステップ8（これにより生成された適用オブジェクトの定義本体がそのロールの受け取るものを配置・回転できる）、SET-STYLEはスタイルキュー、表明は検査時である（8.2、15.3）。
- 下位レベルに到達する生成ルール（10.1）の他のロールが、そのレベルのオブジェクト（シーンオブジェクトまたはホストオブジェクト）で埋められている場合、それらのオブジェクトはそのレベルに属し下位レベルには存在しないため、警告を出してそれが書かれたレベルでのみ有効になる。定義が渡されたロールにはそのような制限はない。
- 生成によって作られたSET-SYMBOLとSET-STYLEは、それを作ったルールのグループ内の、そのルールの位置に属する（8.3）。
- 選択または生成セットに束縛された名前を再度束縛することはできない（6.6）。
- **ネットごとの自動補完。** 「すでに1つ存在する場合は追加しない」という組み込みルールはない。自動補完は2つのセットの差集合で記述する。ポートタグを追加するパッケージは次のように書く：

  ```rnl
  $PORT_FILL_SET = # @SELECT-NET(port=true, recursive=true);                                /* the nets that get a port tag */
  # @SELECT-USAGE(recursive=true) $IO_PORT => @SELECT-NET => @REMOVE-FROM $PORT_FILL_SET;   /* less those that have one */
  $IO_PORT @ATTACH $PORT_FILL_SET
  ```

  - 標準シリーズ 0.4の自動補完はこのように書かれ、そのセットは `rnl-std-basic` にあり、さらに各レベルのタグを縦1列に並べる（12.4）。電源ネットとグラウンドネットはセットに残される。スタブが立つ場所にタグを望まないファイルは `$SUPPLY_NET_SET @REMOVE-FROM $PORT_FILL_SET; $GROUND_NET_SET @REMOVE-FROM $PORT_FILL_SET` と書く。
  - 手書きされたポートタグは生成されるものに取って代わる：`$IO_PORT @ATTACH &inp => @PLACE(0, 20) => %p` を書くと、inpにはポートタグが生成されない。ユーザーは `# @SELECT-NET(name="vdd") => @REMOVE-FROM $PORT_FILL_SET` のように `$PORT_FILL_SET` からネットを除外することも、独自のポート定義の適用オブジェクトを数えることもできる（`# @SELECT-USAGE $MY_PORT => @SELECT-NET => @REMOVE-FROM $PORT_FILL_SET`）。
  - 生成されたポートタグはカウントされない：生成ルールはステップ6で `$PORT_FILL_SET` を使い、差集合の中の選択はステップ6より前の状態で評価されるためである（5.2）。
  - 注記：「すでに1つ存在する」が組み込みでないのは、複数ロールを持つ定義ではそれが不明瞭になること、ユーザー独自のポート定義が数えられなくなること、そしてレイアウト定義の重複は制約を繰り返すだけであり競合解決と優先度で処理されるためである（8.5、14.8）。
- 端子ごとの自動補完では、依然として手書きオブジェクトの配線が生成オブジェクトに取って代わる（配線を持つピンはもはや `wired=false` ではなくなるため）。この場合も生成をキャンセルする手段はなく、セットからネットを除外してもセットが変わるだけである。
