## 12 虚拟元件

### 12.1 概念

- 虚拟元件是只存在于 RNL 里的元件，如地、电源、端口符号、无连接标记。它在电气上不存在：只用于画出，不产生也不改变电气事实。
- 虚拟元件就是有符号的用例，没有单独的关键字或对象种类。`$GND @ATTACH &vss` 产生一个用例；标准包的一条规则给 `$GND` 的用例指派地符号，它就画出来。
- 规则：
  1. 用例的端子就是它的定义的角色：`%g0:p` 是端子，即符号上 p 引脚的位置；`%g0::p` 是填进角色 p 的成员，即网络 vss。这与元件一样：`#M5:3` 是端子，`#M5:3::net` 是它所在的网络。
  2. 用例被指派了符号才画、才能放置；没有符号的用例不画。标准包只给要画出来的定义配符号，所以差分对这类语义用例不画。
  3. 没有符号的用例对画图没有意义：用到它或它的端子的 PLACE、ORIENT、约束和导线失效，与没有引脚的端子相同（9.2.4）；这在 8.2 的第 6 步之后检查。收到样式不出错：样式传给它体里创建的可画对象（8.3），体里没画东西时看不出效果（11.3）。
  4. 画出来的用例只画它自己的符号。它不包含、也不带动它的成员，不是视觉容器。
  5. **画在哪里**：填第一个角色的对象是用例的主对象。主对象有坐标点时（端子是它的引脚的位置，元件是它的原点，点就是它自己），符号的原点画在这个点上，用例自己没有位置：用到它的 PLACE 和约束失效。没写 ORIENT 时由求解器选它的朝向，不求解的渲染器按 `"R0"` 画（8.5）；它不跟着引脚的出线方向。可以写 ORIENT：用例绕这个点转，有自己的朝向，不跟着主对象（11.2）。主对象没有坐标点时（如网络），用例自己有位置，用 PLACE 给出或由求解器定，它的 `::position` 是它自己的原点。用例没有自己的名字；文字经角色引用主对象，如 `${p}`（13.6）。
  6. 定义体一律展开，所以虚拟元件的定义也可以带体。
- 按原则 2.2 的说法，虚拟元件是有符号、角色填宿主对象的用例；标准虚拟元件是标准包里的定义，带一条给它默认符号的规则；用户自定义的虚拟元件是用户自己的定义，加上一条符号规则。
- 外观由规则按定义指派，如 `# @SELECT-USAGE $GND => @SET-SYMBOL $GROUND`。换画法不改变端子和接在上面的导线。
- 一个用例是不是虚拟元件，只看它有没有符号。
- 注：该画出来却没配符号的定义，只有它的某个用例被放置、被约束或接线时才会报出来。

### 12.2 创建虚拟元件

```rnl id=g0
$GND @ATTACH &vss => @PLACE(24, 38) => %g0;
&vss @WIRE {#M5:3 %g0:p}
```

- 在 `$D @ATTACH &net` 里，定义后面的对象按定义的角色表配位。它用 ATTACH 写，读作"把这个添在网络上"（9.4）。多端子的虚拟元件就像网表里的一行元件：定义 `$DIFF_PORT` 有角色 a、b 时，写 `$DIFF_PORT @ATTACH &inp(a) &inn(b)`，或按顺序写 `$DIFF_PORT @ATTACH &inp &inn`。
- 角色一般填网络：虚拟元件的端子和元件的端子一样接在网络上；它和某个端子的关系（画在哪、接谁）由导线和约束表达（12.3）。第一个角色填端子时，虚拟元件直接画在这个端子的引脚上（12.1 第 5 条），如 `$GND @ATTACH #M5:3`。角色收哪几种对象可以在定义里声明（9.4），如 `roles=[["p", ["net", "terminal"]]]`。
- 这种关联只是描述，不建立电气连接，也不校验（原则 2.2）。
- 同一个网络可以有任意多个虚拟元件，如五个地、两个探针。用例没有键：每套用一次就多一个用例（5.8）。
- 个别虚拟元件可以另换符号，如用自己的符号 `$EARTH` 写 `%g1 @SET-SYMBOL $EARTH`。
- ATTACH 除 `priority`（14.8）外没有自己的参数。端口的方向归标准包的内容（12.4）；显示的名字是主对象的名字，要显示别的文字就写标签（13.3）。定义的参数照常经 ATTACH 传入（9.4）。
- 同一层里 `%g0` 只绑定一次（6.6）；要改它的位置，写 `%g0 @PLACE(…)`。

### 12.3 相对端子的位置

参数里不能放宿主引用，所以相对端子的位置写成约束：

```rnl use=g0
{%g0:p #M5:3} @ALIGN("x");
%g0:p #M5:3 @DISTANCE("bottom-to-top", exact=2)    /* the pin of the ground 2 below the source of M5 */
```

要把虚拟元件直接画在引脚上，不隔距离也不画导线，就让它的第一个角色填这个端子（12.1 第 5 条）。

### 12.4 端口

```rnl
$IOPORT @ATTACH &inp => @PLACE(0, 20) => %p_inp
```

- 子电路的端口名就是它内部的网络名，所以端口符号关联的是网络 `&inp`。
- 端口本身（`#:inp`）不画，只靠虚拟元件显示。标准包用集合补上端口符号，已经显式写了端口符号的网络不补（10.5）；它们的位置由求解器定。
- 端口的方向只是显示上的事：网表里没有方向，画哪种符号由用户决定。有哪些端口定义和符号，归标准包的内容。
- **端口符号的朝向**：端口符号有方向，如标准包的 `$PORT_TAG` 引脚在一端，标签往另一边伸出。没写 ORIENT 时，由求解器按导线的方向选朝向，以拐点少为目标。这是求解器的目标，不属于语言（14.8），所以手写时一般不写端口符号的 ORIENT。

### 12.5 标准虚拟元件

标准虚拟元件归标准包，标准包不属于语言标准（16.3）。例如，标准包提供地 `$GND`、电源 `$SUPPLY`、端口符号 `$IOPORT` 和无连接标记 `$NC`（12.6），以及它们的符号、指派这些符号的规则和补位（10.5）。

同一个网络 vss，三种写法画出来不同：

1. `&vss @ADD-TO $GROUND_NET_SET`：vss 上每个没接导线的端子下面各补一个地，带短导线（标准包的补位，10.5）。教科书多这样画：每个接地的端子下面各一个地符号。
2. `$GND @ATTACH &vss => %g`：整个网络只有一个地，由求解器摆。各端子用导线接到它的引脚，如 `&vss @WIRE {#M5:3 %g:p}`，或整个网络写 ROUTE。
3. `$GND @ATTACH #M5:3`：地直接画在 M5 源极的引脚上，不画导线（12.1 第 5 条）。

- 电源同样写，集合是 `$SUPPLY_NET_SET`，定义是 `$SUPPLY`。网络 0 默认就在 `$GROUND_NET_SET` 里（10.1）。
- 第三种写法的端子，标准包的补位会把它扣掉，不会再补一个地（10.5）。
- 端口：标准包给子电路的每个端口网络补一个端口符号（10.5）。要放置它、约束它或改它显示的名字，就自己写出来：`$IOPORT @ATTACH &out => %pout`，导线接 `%pout:p`，名字写 `%pout @TEXT("V_{OUT}", key="name")`（13.3）。不要端口符号的网络从 `$PORT_FILL_SET` 里去掉。

### 12.6 无连接标记

```rnl
$NC @ATTACH #M1:4    /* terminal 4 of M1 is left unconnected on purpose */
```

- 无连接标记是标准包里的定义 `$NC`，它的角色收端子；不另设关键字。它的主对象是端子，所以叉画在引脚上（12.1 第 5 条）。标准包给它一个叉的符号，原点在叉的中心。
- 用例记下这个端子是故意不接的：`# @SELECT-USAGE $NC => @SELECT-TERMINAL` 选出这些端子。
- 检查（网络上还有别的宿主端子、有导线碰到这个端子）不作要求（原则 2.4）；认得标准 `$NC` 的实现可以给警告。
- 无连接标记不算导线（10.2）：只有这个标记的端子仍是 `wired=false`。按端子补位要跳过它们，就减去上面的选择，写法同 10.5 的差集。
- 注：无连接标记不做关键字，因为它对实现没有画图以外的用处：求解器不读它，画法能写进定义和符号（1.5 第 7 条）。
- 网名标签不是虚拟元件，见 13.3。
