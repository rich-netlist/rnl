## 11 放置与外观

### 11.1 位置：PLACE

```rnl
#M1 @PLACE(10, 20);
#M1 @PLACE(x=10)
```

- PLACE 给对象的位置赋值，x、y 至少应写一个。PLACE 只设定写出的坐标。每个坐标起初是自由的，没写过的一直自由，由约束和求解器决定。
- PLACE 只管坐标，不管旋转、镜像、缩放和端子的方向；朝向由 ORIENT 设置（11.2）。
- 一条 PLACE 是两个几何事实，x、y 各一个，冲突时可以各自丢弃（8.5）。参数 `priority=` 给它的优先级（14.8），如 `#M1 @PLACE(12, 20, priority="high")`：按位置写的 x、y 在前，写名字的参数在后（4.2 第 9 条）。
- 对象：元件、自己有位置的虚拟元件（12.1）、叠画（11.8）、点、TEXT（标注和标签；PLACE 定的是文字自己的位置，13.3）、原点 `::position`（含中心写法的 RECTANGLE、CIRCLE、ELLIPSE 的中心），以及集合的 `::position`。PLACE 不收别的图元；要移动它们，就移动它们的点（13.4）。没有符号的用例、画在主对象坐标点上的用例收到 PLACE 时失效（12.1）。符号体里的 PLACE 只给附着在 `?` 上的 TEXT 定位置，坐标是局部的（9.2.2）。
- 输出沿用输入的句柄（5.1）。
- 对象是集合时逐个放（5.2.1）：`%pair_set @PLACE(10, 20)` 把两个成员都放在 (10, 20)。要放集合的中心，写 `%pair_set::position @PLACE(10, 20)`（6.5）。
- 坐标的轴向、单位、小数和容差见 11.7。

### 11.2 朝向：ORIENT

```rnl
%pair_set = {#M3 #M4};
#M2 @ORIENT("MY");          /* flipped left-right */
%pair_set @ORIENT("R90")    /* each member turns about its own origin and stays where it is */
```

- 对象：元件、有符号的用例、叠画。没有符号的用例收到 ORIENT 时失效（12.1）；点、标签、图元、导线、网络不收。
- 对象是集合时逐个做（5.2.1）：每个成员绕自己的原点转，位置不变，每个成员是一条描述。不是把整个集合当一块转。不提供整个集合一起转：`%pair_set::position` 是点，ORIENT 不收。
- 画在主对象坐标点上的用例绕那个点转；它有自己的朝向，不跟着主对象转（12.1）。
- 没写 ORIENT 就是没有约束，由求解器选；不求解的渲染器按 `"R0"` 画（8.5）。几个对象的朝向之间的关系（同向、互为镜像）写 ORIENT-RELATION（14.9）。
- ORIENT 是一个几何事实，参加冲突的取舍（8.5）；参数 `priority=` 给它的优先级（14.8）。
- **朝向码**：一个码表示一种朝向。只认下表的八个写法，区分大小写（3.6）。名字与 Virtuoso 相同，y 向上（11.7）时含义也相同。等价的别的写法（如 `"MXR180"`，就是 MY）、任意角度都不认：它们是写错的参数值，这条 ORIENT 失效。工具写回时只写这八个。没有"在现在的朝向上再转"的相对写法（第 17 章）。

  | 码 | (x, y) 变成 | 含义 |
  |---|---|---|
  | `"R0"` | (x, y) | 不转 |
  | `"R90"` | (−y, x) | 逆时针转 90° |
  | `"R180"` | (−x, −y) | 转 180° |
  | `"R270"` | (y, −x) | 逆时针转 270°，即顺时针转 90° |
  | `"MY"` | (−x, y) | 关于 y 轴镜像，左右翻 |
  | `"MX"` | (x, −y) | 关于 x 轴镜像，上下翻 |
  | `"MYR90"` | (−y, −x) | 先 MY 再 R90 |
  | `"MXR90"` | (y, x) | 先 MX 再 R90 |

- **合成次序**：MXR90、MYR90 先镜像再转；名字按动作的先后读，与 Cadence、OpenROAD 的 OpenDB 相同。
- **怎样作用**：朝向绕符号的原点作用于局部坐标，再把原点放到对象的位置上：符号上一点画出的位置 = 对象的位置 + 朝向作用于这一点的局部坐标。符号里的图元、引脚位置都随之刚性变换，引脚的出线方向也跟着转（9.2.4）。文字按 9.2.5 的规定显示；字形不镜像。
- **只改变画在哪里**：朝向只改变引脚画在哪里，不改变引脚属于哪个端子。子电路符号上下翻以后，inp 的引脚画到了下面，接 inp 的导线跟着过去。不会为了让 inp 留在上面而把两个引脚对调：那等于改了哪根导线接哪个端子，是网表的事（原则 2.2）。要 inp 画在别处，换一个符号（11.3）。

### 11.3 符号与样式：SET-SYMBOL 与 SET-STYLE

```rnl
%w13 = &x @WIRE {#M1:1 #M3:1};
#M1 @SET-SYMBOL $NMOS;
# @SELECT-INSTANCE(model="nch") => @SET-SYMBOL $NMOS;
%w13 @SET-STYLE $signal;
# @SELECT-INSTANCE => @SET-STYLE $base
```

- SET-SYMBOL 给对象指派符号。对象可以是元件、用例、叠画，或它们的集合（含选择和逐个生成的结果），对每个成员各指派一次（5.2.1）。在子电路里，`# @SET-SYMBOL` 给的是子电路符号（9.2.6）。
- 用例被指派了符号就画出来：它就是虚拟元件（第 12 章）。
- SET-STYLE 给对象指派样式。对象可以是元件、用例、叠画、导线、图元（含文字），或它们的集合（含选择和逐个生成的结果）。不收网络、层、约束、定义、点。端子随所属对象的符号画，跟所属对象的样式。用例收到的样式传给它的符号和它体里创建的可画对象（8.3），所以没有符号的语义用例收到样式不出错；体里没画东西时，看不出效果。
  - 注：否则标准包的规则 `# @SELECT-USAGE => @SET-STYLE $base` 会对每个语义用例给警告。
- 输出沿用输入的句柄；对象是集合时，输出就是这个集合。
- 两者都经外观队列生效，不按键覆盖。分两级：直接指明对象的 SET-SYMBOL 或 SET-STYLE，高于经选择到达对象的和传给对象的（8.3）。
- 有默认规则时（标准包，16.3），可以不写。
- **参数与样式**：写在对象上的样式参数，如 TEXT 的 `size=`，是这个对象直接的样式，高于选择来的、传来的样式。之后写的、直接指明这个对象的 SET-STYLE 按位置盖过它们（8.3）；编辑器就靠这个单独改一个对象。定义的参数没传时当作没写，样式随之生效（9.4）。
- **标签与汇合点**：对象的样式传给附着在它上面的文字。在"选择来的、传来的"这一级里，它与选这段文字的规则（如 SELECT-LABEL）按位置比；文字自己的参数和直接指明这段文字的 SET-STYLE 在直接的一级。所以 `#M1 @SET-STYLE $signal` 写在标签规则之后时，M1 的名字也取这个颜色，拖动名字也不会换颜色。符号里附着在 `?` 上的文字也是标签，SELECT-LABEL 选得到；附着在点上的固定文字是符号的图元，用所属对象的样式。附着在网络或点上的文字不从附着的东西得到样式，只用自己的。汇合点是 `$JUNCTION` 的用例（13.2）；圆点是它的符号，颜色跟用例的样式。

### 11.4 一物多画

没有办法把一个宿主对象画几次：宿主句柄如 `#M1` 总是指这个对象唯一的那一次画出。以后的版本若加一物多画，多出的画法会是另外的对象，有自己的名字，宿主句柄的含义不变（附录 C）。

注：几个元件画成一个，是叠画（11.8）。

### 11.5 分组：GROUP

```rnl
%stage1_set = {#M1 #M2 #M5} @GROUP;
%stage2_set = {#M3 #M4} @GROUP;
{%stage1_set %stage2_set} @GROUP;
%stage1_set %stage2_set @DISTANCE("x", min=1);
{%stage1_set::position %stage2_set::position} @ALIGN("y")
```

- GROUP 给一个集合加一条事实：求解器把它当作一块。它沿用集合的句柄，所以 `%stage1_set` 仍然是那个集合。
- 集合本身就是求解器登记的东西。GROUP 不是第五种原子约束，也不是另一种对象。
- 要把几个对象当整体，PLACE 收集合的 `::position`（6.5）；写成 `{%x}` 的集合是 ORDER、ALIGN、DISTRIBUTE 的一个成员，按它的中心算；交给 DISTANCE 的集合按它的范围算（14.1、14.5）。任何集合都可以这样用，不需要 GROUP。
- 嵌套由包含关系得出：`{%stage1_set %stage2_set}` 的成员是五个元件（引用打散一层，5.2），所以两级都包含在里面。
- **含义**：GROUP 只是给求解器的提示，"求解时当作一块"，不保证任何几何关系。位置上的要求，如不穿插（例子里的 DISTANCE）或居中，写成原子约束；GROUP 对搜索和打分的影响由实现决定。不规定默认不穿插：那等于在用户背后加约束。两组可以部分重叠，即一个成员在两个互不包含的组里；由求解器处理。
- 分组后的集合仍是集合，引用写在 `{…}` 里会打散一层。要整组作约束的一个成员，写成单独的 `{…}`，或写它的 `::position`，如 `{#R1 {%rc_set} #M1} @ORDER("left-to-right")`（14.1、14.3、14.6）。
- GROUP 是关键字，不是标准包里的定义：它的含义只有求解器懂，写不进定义的体（1.5 第 7 条）。
- 查看器可以把分组画出来，如画一个框；这是查看器的事，本标准不规定。
- GROUP 不是原子约束：它不参加冲突的取舍（8.5），也没有优先级，只有开和关。`%stage1_set @PRIORITY("disabled")` 让求解器收不到这个组，也就是取消分组。外层用例为 disabled 时，它展开出的分组也关掉。位置上的要求（如两组不穿插）写成原子约束，各有优先级。定义展开里的分组，只有是命名的局部对象、从外面引用时，才能单独关掉（9.4）。

### 11.6 绘制顺序与图层：LAYER

```rnl
@RECTANGLE(fill="fillcolor") {(0, 0) (40, 30)} => @LAYER("bottom") => %f1;    /* a frame, drawn below everything */
(2, 28) @TEXT("input stage") => @LAYER("top") => %n1
```

- 有三个图层：`"bottom"`、`"middle"`、`"top"`。先画 bottom，再画 middle，最后画 top。同一图层里按位置先后画：后面的对象画在前面的上面，盖住它。
- `@LAYER(…)` 设对象所在的图层；不写就在 `"middle"`。每个对象一个键，后写的 LAYER 覆盖（5.8）。LAYER 不改变对象在图层里的位置。
- **位置**按书写的次序（1.5 第 2 条），与 8.3、8.5 用的次序相同：同一层里按文本先后；包的内容在它的 USE-PACKAGE 的位置，根上的包在最前（16.3）；用 `scope=` 写进来的语句排在目标子电路自己的文字之后。各类对象取下面的位置：
  - 导线、图元、文字（标注和标签）：创建它的语句；
  - 用例：实际生效的那条 SET-SYMBOL；符号由规则指派的，取规则的位置（8.3）；
  - 规则、定义展开、逐个生成产生的对象：产生它的那条语句，同一次展开里按体内的先后；
  - 元件：在所在图层的最底下，元件之间按网表顺序；放进别的图层的元件在那一层的最底下。叠画当作元件，取它第一个成员的网表顺序。
- 改变对象的语句，如 PLACE、ORIENT、SET-STYLE、LAYER，不移动它的位置。
- 对象：元件、有符号的用例、叠画、导线、图元、标签；集合逐个做（5.2.1）。没有符号的用例收到 LAYER 不出错，只是没有效果（与 SET-STYLE 相同，11.3）；点、网络、约束、定义收到时失效。
- 符号里的成员没有图层：按成员顺序（9.2.1）跟着所在的对象一起画。
- 不设数字的 `z=`。覆盖（按事实的键）和遮挡（按图层和位置）是两回事。
- "图层"在这里指绘制的先后，与宿主的层（2.6）无关。

### 11.7 坐标与单位

- **轴向**：x 向右，y 向上；y 越大越靠上。所以 ORDER、DISTANCE 的 `"bottom-to-top"` 是从下往上（14.3、14.5），R90 是逆时针（11.2）。SVG 等格式和一些编辑器是 y 向下，画出、导入、导出时由实现把 y 取反。
- **单位**：单位没有物理尺寸。一个单位画多大、打印多大，由查看器决定。
- **小数**：坐标和长度都可以写小数（3.7），不必是整数，位数不设上限。坐标照写的值画，不吸附到整数上。
- **网格**：建议引脚放在整数点上（9.2.4）；符号里的图元不受此限。元件放在整数点上、朝向是八种之一时，整数的引脚位置变换以后仍是整数，导线也就落在整数点上：整数点就是通常说的网格。语言没有自己的网格。求解器给自由坐标取不取整数是它自己的规则，排在全部语言描述之后（8.5）；约束逼出小数时就用小数。走线方式算出的拐点照算出的值，不取整（13.1）。
- **容差**：检查约束是否满足、判断冲突时，差在容差以内就算满足。容差是求解器的参数，本标准不规定；不求解的查看器检查时用自己的设置。所以恰好卡在容差边上的情况，两个工具的结论可能不同。求解器写回坐标时，写成读回来还是同一个值的十进制小数，不另外截短（第 17 章）。
- **符号的坐标**：DEFINE-SYMBOL 体里的局部坐标与场景同单位、同轴向，原点就是符号的原点（9.2.1、6.5）。没有缩放：符号不带缩放参数，元件也不能缩放。导入器把别的工具的符号换算成 RNL 的单位。
- **其他长度**：语言里的长度都按坐标单位算，随图一起缩放：DISTANCE 的 `min`、`max`、`exact`，CIRCLE 的 `radius=`，RECTANGLE、ELLIPSE 的 `width=`、`height=`，字号 `size`（同 SVG 的 font-size），线宽 `linewidth`，箭头长度 `arrowsize`（9.3），以及定义里当长度用的参数（如 `gap=3`）。线宽 0 是例外：在任何缩放下都一样细的细线，也是默认（9.3）。
- **原点与纸面**：场景的原点没有特别的含义。每个子电路一张图（6.1），各有自己的坐标；查看器按内容的范围取景。RNL 不记纸面大小，也不记编辑器的吸附网格。

### 11.8 叠画：BUNDLE

Virtuoso 的叠合元件，如 `I0<3:0>`，是一个符号，网表里却是四行：

```spice
* A unit cell repeated four times
* @RNL(type="header") { @VERSION("0.2")}
.subckt unit in out vdd vss
R1 in out 1k
.ends unit
XI0<3> D<3> out vdd vss unit
XI0<2> D<2> out vdd vss unit
XI0<1> D<1> out vdd vss unit
XI0<0> D<0> out vdd vss unit
* @RNL {
*   #XI0<3:0> @BUNDLE => @PLACE(30, 10) => %x;   /* four instances drawn as one symbol */
*   &D<3:0> @WIRE {(20, 10) %x:in};              /* a bus to the in pin of the bundle */
*   &out @WIRE {%x:out (40, 10)};                /* all four members are on out: an ordinary pin */
*   %x @TEXT("I0<3:0>", key="name")              /* the name, written out */
* }
.end
```

- **新的对象**：BUNDLE 收一个宿主元件的集合，产生一个叠画，代替这些元件画一次。成员按写的次序，第一个成员决定引脚和符号。
- **引脚和符号**：端子名、端子个数照第一个成员。外观队列把叠画当作它的第一个成员：选择按第一个成员的条件选到叠画（10.1），子电路符号照用。直接写在叠画上的 SET-SYMBOL、样式、PLACE、ORIENT、LAYER、约束、文字都是叠画的。
- **端子**：叠画的端子，如 `%x:in`，代表各成员的同名端子：它是一个总线引脚。
  - `::net`：各成员接同一个网络时就是这个网络，如 `%x:out::net` 是 `&out`；否则是按成员次序的网络集合，如 `%x:in::net` 是 D<3>、D<2>、D<1>、D<0>。所以定义里的 `?t::net @WIRE {…}` 收到集合时画成总线，收到单个网络时是普通导线（13.1）。
  - 导线接到叠画的端子，就是接了各成员的这个端子（10.2）。
- **属性**（13.6）：各成员相同时就是这个值，否则用 `,` 把各值连起来。`${w}` 都是 1u 时显示 1u；`${name}` 是 `XI0<3>,XI0<2>,XI0<1>,XI0<0>`，要显示 `I0<3:0>`，就写同引用名的文字，如上例。端子的 `${net}` 同理，如 `D<3>,D<2>,D<1>,D<0>`。
- **选择**：成员选不到，选到的是叠画（10.1）。所以"给每个没接线的引脚补一个网名"这类规则在叠画上只补一个标签，显示整条总线。定义里收元件的角色也收叠画，收端子的角色也收叠画的端子（9.4）。
- **成员不单独画**：关于画图的描述（位置、朝向、符号、样式、图层、约束、导线、文字）直接写在成员或成员的端子上时失效，与没有符号的用例相同（12.1 第 3 条）。不涉及画图的描述照常，如 CURRENT 和语义用例的角色。
- **都是同一种**：建议各成员的元件字母、模型名或子电路名、参数（按原文比较）、端子个数都相同。不同时给警告；照样叠画，引脚和符号照第一个成员。
- **一个元件只在一个叠画里**：一个元件写进几个 BUNDLE 时，归后写的那个（1.5 第 2 条）；先写的保留其余成员，可以给提示。先写的叠画成员都被拿走时是空的，不画，给警告。
- BUNDLE 收到空集合时失效（5.2.1）。成员不是宿主元件时失效（种类不对）。找不到的成员使整条语句失效（严格，7.3）。
