## 5 对象与语句

### 5.1 对象

- 每条带关键字的语句产生一个新的 RNL 对象，由句柄和事实组成。`{…}` 也产生一个新对象，即集合（5.2）。
- 引用（`#M1`、`&vss`、`%x`、`$X`，以及端子、子对象）不产生对象，只取已有的句柄。单独的 `#M1` 也是语句，得到 M1，不带事实；单独的 `#` 得到本层，不带事实。
- 句柄是被描述的那个东西：宿主的元件、网络、端子，或本层；或由 RNL 创建的点、导线、集合、用例、约束等。句柄不会是另一个 RNL 对象。
- 一条语句的对象，要么用新的句柄（语句创建，如 WIRE、图元、`{…}`、选择、AS、ATTACH、约束），要么沿用输入的句柄、再加上新的事实（语句修改，如 PLACE、ORIENT、SET-SYMBOL、SET-STYLE、GROUP、CURRENT；ADD-TO、REMOVE-FROM 沿用目标集合的句柄）。是哪一种写在签名里（5.3）。
- 两条内容相同的语句是两个对象，如两句 `#M1 @PLACE(1, 2)`。它们的事实不矛盾，一起生效。
- 事实只在产生它的语句处提交一次（5.4）。本层生效时，同一个句柄的全部事实合在一起，矛盾按 1.5 第 3 条处理。
- 属性就是事实：位置、朝向、符号、样式都是对象上的事实，没有可以改写的属性字段。本层生效时，把同一个句柄的事实合起来算出最终的值：PLACE 的 x、y 按几何事实（5.8、8.5），符号、样式按外观队列（8.3）。
- 句柄的种类由它的来历决定：宿主对象由宿主给出，RNL 对象由创建它的语句决定。签名规定每个对象槽位收哪些种类（附录 A），收到种类不对的对象时，这条描述失效。能在读入时查的读入时查；要到后面才知道的（用例有没有符号、定义的角色）在本层生效时查（7.1）。

对象的种类：

| 种类 | 怎样产生 | 画不画 |
|---|---|---|
| 本层 | 宿主；`#` | 不画 |
| 元件 | 宿主；`#M1` | 用它的符号画 |
| 端子 | 宿主；`#M1:d`、`#:inp`。用例的端子是它的定义的角色（6.4） | 作为符号的引脚画 |
| 网络 | 宿主；`&vss` | 不画；导线、标签是另外的对象 |
| 点 | `(x, y)` | 不画；汇合圆点是套在点上的 `$JUNCTION`（13.2） |
| 导线 | WIRE；网络槽位收到集合的导线是总线（13.1） | 画 |
| 标签 | 附着在对象上的 TEXT；写了引用名时，是那个对象的子对象 `object::key`（13.3） | 画 |
| 叠画 | BUNDLE（11.8） | 代替各成员画一次 |
| 标注 | 场景里的图元（LINE、RECTANGLE、CIRCLE、ELLIPSE、ARC、BEZIER），或附着在点上的 TEXT（13.4） | 画 |
| 用例 | AS、ATTACH（9.4） | 有符号才画，这时它是虚拟元件（第 12 章） |
| 约束 | ALIGN、ORDER、DISTRIBUTE、DISTANCE、ORIENT-RELATION（第 14 章） | 不画 |
| 集合 | `{…}`、选择、UNION、逐个生成的结果（5.2、第 10 章） | 本身不画，成员各自画 |
| 定义 | DEFINE-SYMBOL、DEFINE-STYLE、DEFINE（第 9 章） | 不画，被用到时才起作用 |

这些种类里，元件、端子、网络、点、导线、标签、叠画、标注、用例有种类名（5.3），`text` 也是种类名，指任何 TEXT，不论标签还是标注；其余几种在签名里怎样写见附录 A。

另有子对象（6.5），句柄是父对象和名字；以及失效对象（第 7 章）。

### 5.2 集合

- `{…}` 产生一个集合对象，成员有序。集合可以命名（`%pair_set = {#M1 #M2}`），有名字的集合可以被别的语句增删成员（5.2.2）。
- 集合保留重复的成员和写出的次序，如 `{#M1 #M2 #M3 #M1}`。是不是同一个成员按句柄判断：分别写出的两个 `{…}` 是两个句柄，内容相同也不是同一个成员。
- **引用打散一层**：集合里写的引用如果指向一个集合，就在原处放进那个集合的成员，所以 `{%a_set %b_set}` 是 a_set 的成员接着 b_set 的成员。结果是集合的语句（如选择）同样打散；下标展开的一组引用（如 `&D<7:0>`，6.11）也一样。要去重，写 `%a_set %b_set @UNION`（5.2.2）。
- **直接写的 `{…}` 保留**：集合里直接写的 `{…}` 作为一个成员保留，所以 `{{%a_set} {%b_set}}` 是由两个集合组成的集合。
- **散写的对象也打散**：只有一个槽位的关键字收到几个不加花括号写的对象时，把它们合在一起，与写在 `{…}` 里完全相同（5.2.1 第 3 条），所以其中的集合打散。设 `%bias_set = {#R1 #R2 #R3}`，`%lbl` 是一段文字：
  - `%bias_set %lbl @ALIGN("x")` 就是 `{%bias_set %lbl} @ALIGN("x")`：R1、R2、R3 和文字逐个 x 相同；
  - `{%bias_set} %lbl @ALIGN("x")` 把集合保留为一个成员：文字与 R1–R3 的中心 x 相同；
  - 集合是唯一的对象时，用的就是它本身：`%bias_set @ALIGN("x")` 对齐 R1、R2、R3。

  在 ORDER、ALIGN、DISTRIBUTE 的成员里，只有写成 `{%x}` 的集合才作为一个成员、按它的中心算（14.1）。

  注：打散在约束里最容易读错。`{%stage1_set %stage2_set} @ORDER("x")` 把两组的成员逐个排序，常与组内的 ALIGN 矛盾。要在两组之间排序，写 `{{%stage1_set} {%stage2_set}} @ORDER("x")`，或用 DISTANCE 的两个槽位（14.5）。保留打散，是因为它是把集合拼起来的唯一写法。散写的对象完全按写在 `{…}` 里读，这样多加花括号不会让含义颠倒：要是散写的对象不打散，`%bias_set @ALIGN("x")` 会把集合算作一个成员，什么也不对齐；`{%bias_set} @ALIGN("x")` 会打散它，对齐 R1–R3；`{{%bias_set}} @ALIGN("x")` 又把它整个保留。
- 集合的内容在用到它的阶段求出，与选择一样：初始内容和各条增删语句里的选择，都按这个阶段开始之前的状态求值，增删按写的次序（它们的位置，8.5）处理。所以写在前面的使用也看到全部增删（1.5 第 1 条）；同一个集合在不同阶段可以不同：生成对象的规则看到的不含生成的对象，样式规则看到的含（8.2）。

  注：内容不在某一步一次算完，因为那样给选择起个名字就会改变结果：`%g_set = # @SELECT-USAGE $GND; %g_set @SET-STYLE $grey` 会选不到生成的地，而不起名的同一个选择选得到；名字只是引用对象的另一种写法（1.5 第 5 条）。

#### 5.2.1 对象与对象槽位

一条语句写出的对象按以下规则对到签名的对象槽位。

1. **标了角色**：标了角色的对象整个填进它的角色，不拆开。一条语句里要么全标，要么全不标。
2. **先拆一层**：没标角色时，如果整条语句只有一个对象，而且它是集合，先把它拆开一层。定义、管道送来的结果都算对象。所以 `{#M1 #M2} @DISTANCE(…)` 等于 `#M1 #M2 @DISTANCE(…)`；`{#M1 #M2} @SET-SYMBOL $X` 是两个对象（集合和定义），不拆。
3. **按签名配位**：
   - 有多个槽位的关键字（定义也占一个槽位）：对象个数应与槽位个数相等，按顺序一一对应；不等时这条语句失效。
   - 只有一个槽位的关键字（如 PLACE、ORIENT、ALIGN、ORDER、DISTRIBUTE、GROUP、除 SELECT-USAGE、SELECT-ANCESTOR-USAGE 以外的各选择关键字（这两个还收定义，5.6），以及定义关键字，它们的槽位是定义体）：一个对象直接放入；多个对象合成一个集合放入，引用的集合在其中打散一层，直接写的每个 `{…}` 保留为成员。这些对象正是由唯一的集合按第 2 条拆开的时，放入的就是那个集合本身。
   - 唯一的对象是空集合时：
     - 要单个对象的槽位逐个做零次：什么也不发生，也不失效。名字照常绑定到这个空集合，用这个名字的语句什么都不做。
     - 要单个对象的槽位收到直接写出的空集合时给警告，如 `{} @PLACE(1, 2)`。由选择、规则得到的空集合不警告：规则在写它的层和下面每一层各求一次，某一层没有这类对象是常态。用户自己写的选择在它求值的每一层都没选到东西时，实现可以给一次警告，多半是条件写错了。
     - 要集合的槽位收空集合，如空的定义体 `@DEFINE(roles=["a"]) {}`，或没有成员的约束（自然成立）。例外是 BUNDLE 和 WIRE 的网络槽位：它们要用这个集合造一个新对象，空的造不出来，这条语句失效（11.8、13.1）。
     - 一个对象也没写的语句，如单独的 `@PLACE(1, 2)`，与签名不符，失效。
4. **对象槽位收到集合**：
   - 要单个对象的槽位对每个成员各做一次。每个成员是一条描述，结果是这些结果组成的集合。成员本身还是集合时，再拆开逐个做。唯一的例外是 PRIORITY：收到 GROUP 标过的集合时，作用于这个分组本身（11.5、14.8）。
   - 要集合的槽位整个收下。
   - 收对象或集合的槽位（如 DISTANCE 的两个槽位）把集合整个收下，集合在那里按范围算（14.5）。
   - 一条语句里至多一个要单个对象的槽位可以收到多成员的集合。超过一个时这条语句失效：按顺序配对和两两组合都说得通，含义不唯一。

| 写法 | 结果 |
|---|---|
| `{#M1 #M2} @SET-SYMBOL $X` | 两个对象，不拆。元件槽位收到集合：M1、M2 各得到这个符号 |
| `#M1 #M2 @SET-SYMBOL $X` | 三个对象对两个槽位：这条语句失效 |
| `{#M1 #M2} @DISTANCE(…)`、`%pair_set @DISTANCE(…)` | 唯一的对象是集合，拆开：从 M1 到 M2 |
| `%a_set %b_set @DISTANCE(…)` | 两个对象，各是一个集合，整个收下：两组之间（14.5） |
| `{#M1 #M2} @ALIGN("y")`、`#M1 #M2 @ALIGN("y")` | ALIGN 只有一个槽位，收到 {M1 M2} |
| `%bias_set %lbl @ALIGN("x")`，其中 `%bias_set = {#R1 #R2 #R3}` | 散写的对象合成 `{%bias_set %lbl}`，其中 bias_set 打散：R1、R2、R3 和文字逐个 x 相同 |
| `{%bias_set} %lbl @ALIGN("x")` | 直接写的 `{…}` 保留：文字与 R1–R3 的中心 x 相同 |
| `%pair_set @PLACE(10, 20)` | 槽位收到的是 pair_set 本身，逐个成员放：两个成员都在 (10, 20)。要放集合的中心，写 `%pair_set::position @PLACE(10, 20)` |
| `{#M1 #M2} @SET-SYMBOL $X => @ALIGN("y")` | 管道的结果是唯一的对象，放入 ALIGN：对齐 M1、M2 |
| `{#M1 #M2} @SET-SYMBOL $X => #M3 @DISTANCE(…)` | 两个对象，不拆。槽位 `from` 把集合整个收下，按范围算：从 M1、M2 合起来到 M3（14.5） |
| `# @SELECT-NET(…) => $PULL_DOWN @ATTACH &vss` | 三个对象对三个槽位（两个角色和定义）。第一个角色是单个角色，所以对每个选中的网络各套用一次定义，每次第二个角色都是 vss |
| `# @SELECT-INSTANCE(type="nmos") => @ORIENT("MY")` | 逐个镜像；没有 NMOS 时做零次，什么也不发生 |
| `# @SELECT-INSTANCE(name="Q*") => @SET-SYMBOL $NPN` | 两个对象，不拆；没有 BJT 时做零次，什么也不发生 |
| `{{#M1 #M2 #M3}} @ALIGN("y")` | 拆开一层后剩一个集合对象：对齐 M1、M2、M3 |
| `#R1 {#R2 #R3} #R4 @AS $CHAIN` | 四个对象对四个槽位（三个角色和定义）；集合角色 `series` 收到 {R2 R3}（9.4） |
| `&D<7:0> @WIRE {…}` | 两个对象，不拆。网络槽位整个收下这组网络：一根总线（13.1） |
| `#XI0<3:0> @ALIGN("y")` | 唯一的对象是下标展开的一组，拆开：对齐四个元件（6.11） |

- 成员不够的约束自然成立，不失效，如只有一个成员的 ALIGN（第 14 章）。
- 要把一个集合当作整体：PLACE 用它的 `::position`（6.5）；作 ORDER、ALIGN、DISTRIBUTE 的成员时写成 `{%x}`，按它的中心算；作 DISTANCE 的对象时按它的范围算（14.1、14.5）。
- 定义的角色分单个角色和集合角色（9.4）。角色表里写成 `"{name}"` 的是集合角色，整个收下集合；其余是单个角色，收到集合时对每个成员各套用一次定义。

#### 5.2.2 增删成员与去重

- `X @ADD-TO S` 在集合 S 的末尾追加 X（X 是集合时追加它的各成员）；`X @REMOVE-FROM S` 去掉 S 里这些成员的所有出现。目标写在最后，所以选择可以用管道送入：`# @SELECT-NET(name="vss") => @ADD-TO %gnd_set`。
- 目标应是集合，不自动包装成集合。`%tail = #M5` 之后，`#M3 @ADD-TO %tail` 失效，因为 M5 不是集合。
- 几条增删按位置的次序处理（1.5 第 2 条）。集合在某层求值时只含这一层的成员（10.3）。
- `%a_set %b_set @UNION` 产生一个去重的新集合，次序取第一次出现处；是不是同一个成员按句柄判断。
- 产生新集合而不改动原来的：拼接写 `{%a_set %b_set}`；并集写 `%a_set %b_set @UNION`；差集写 `%c_set = {%a_set}; %b_set @REMOVE-FROM %c_set`。
- 带删除的循环没有确定的结果，如 `%b_set = {%a_set}` 同时写了 `%b_set @REMOVE-FROM %a_set`：a_set 的一个成员在 a_set 里就要被删，不在就该留着。解释失败（1.5 第 3 条）。

### 5.3 语句与签名

- 语句由至多一个关键字、若干对象和一组参数组成。
- 每个关键字有签名，声明：
  - 对象的个数，每个对象槽位的名字和它收的种类。AS、ATTACH 的个数是定义的角色表的长度，再加定义本身（AS 写在最后，ATTACH 写在最前），种类是角色声明的种类（9.4）；
  - 参数：名字、类型、是否必需、可选值，以及按位置写时的顺序；
  - 输出：新对象、输入的句柄、子对象、定义，或没有句柄；
  - 每个输入的消费方式（5.4），以及对失效严格还是容错（7.3）；
  - 关键字能写在哪里（见下面的标准词表）。
- 对象个数固定，个数不定的用集合。没有可选槽位，例外是：AS、ATTACH 没填的集合角色是空集合（9.4）；SELECT-USAGE 的定义可以省略（10.1）；USE-PACKAGE 的体可以省略（16.2）。定义也占一个槽位。
- 对象按角色或按顺序对到槽位，全标或全不标；同一个角色只能标一次。管道送来的对象算第一个对象；AS、ATTACH 按角色配它，它不占定义的槽位（5.5）。对象怎样对到槽位，见 5.2.1。
- 不论什么关键字，语句里写出的对象都能标角色。角色名就是签名里的槽位名：`#M5:3(to) #M1:3(from) @DISTANCE("x", min=1)` 与按顺序写的 `#M1:3 #M5:3 @DISTANCE("x", min=1)` 相同。角色名不是这个关键字的槽位名时，这条语句失效，不会被忽略（原则 2.3、2.8）。只有一个槽位的关键字，对象也能标角色，但标了不增加什么。
- AS、ATTACH 的参数是定义的参数表里的参数（9.4），另有一个标准参数 `priority`（14.8）；定义的参数不能叫 `priority`。
- **标准词表**：每个语言版本发布一份机器可读的标准词表，是标准的一部分。各关键字收什么、有哪些参数只写在表里，正文写它们的含义。附录 A 由表生成，两者矛盾算勘误。解释器的检查、文档、编辑器的补全、一致性测试的骨架、给 LLM 的写作参考都从表生成。0.2 版的表发布为 `rnl-words-0.2.json`。
  - 表里收全部标准词：关键字及其签名、槽位名、参数名和取值、记录头的字段、种类名、子对象名、`${…}` 读的属性名、样式属性，以及 `true`、`false`。代称（16.5）是给表里的词声明的，版本检查和"最接近的名字"都查这张表。
  - 表是 JSON 文件，JSON Schema `rnl-words.schema.json` 说明表本身的结构。读写它的是工具和标准的维护者，不是描述电路的人。每个词带 `since`，即加它的版本；预留的词标出来（0.2 版没有预留的关键字）。文件声明的版本里还没有的词，按不认识的词处理，诊断说明要哪个版本（16.1）。
  - 表里为每个关键字写：
    - 每个槽位：名字、收哪些种类、要单个对象还是要集合（5.2.1）、消费方式（5.4，严格或容错由它决定，7.3）；定义的槽位；AS、ATTACH 的槽位按定义的角色表；
    - 每个参数：名字；类型（数、字符串、真假值，或数组及元素的类型；取值固定的列出取值）；必需与否；默认值；能按位置写的参数的次序（其余的只能写名字）；以及组合条件，如 PLACE 的 `x`、`y` 至少写一个，RECTANGLE 的中心写法和对角写法只能写一种；
    - 输出：新对象及其种类、沿用输入、沿用目标（ADD-TO）、定义、子对象（写了 `key=` 的 TEXT），或没有；
    - 能写在哪里：层里；只在符号体里（PIN）；只在头段记录里（如 VERSION、ALIAS、DEVICE）；只在包文件的头段记录里（PACKAGE）；
    - 事实怎样覆盖（5.8）：按键覆盖，及其键；按几何事实（8.5）；按外观队列（8.3）；或累加；
    - 标准写法和标准例句（4.3、4.5、附录 B）；
    - 一句说明和正文的节号。
  - 不进表的：含义（关键字产生什么事实、在哪个阶段、怎样冲突）写在正文。包里普通定义的签名就是它的角色表和参数表（9.4）。

  ```json
   ],
   "params": [
    {
     "name": "x",
     "type": "number",
     "since": "0.2"
    },
    {
     "name": "y",
     "type": "number",
     "since": "0.2"
    },
    {
     "name": "priority",
     "type": "enum",
     "values": [
      "disabled",
      "low",
      "normal",
      "high"
     ],
     "since": "0.2"
    }
   ],
   "positional": [
    "x",
    "y"
   ],
   "at_least_one": [
    "x",
    "y"
   ],
   "output": "same",
   "override": "geometry",
   "key": "object and axis",
   "form": "{target} @PLACE(x, y)",
   "sentence": "#M1 is at @PLACE(10, 20)"
  }
  ```

- **内置关键字的槽位名**：每个槽位都有名字，就是能标的角色名。槽位名是标准词，与关键字一样随版本，改名就是不兼容的改动；同一关键字的各槽位不重名。定义的槽位也有名字，表里、诊断里用，但不能标（4.2 第 7 条）。种类名只有一套，签名和定义的角色声明（9.4）共用：`instance`、`terminal`、`net`、`point`、`wire`、`usage`、`bundle`、`text`、`annotation`、`label`（附录 A）。

### 5.4 消费方式

| 方式 | 关键字 | 输入的事实 | 失效（默认） | 名字 |
|---|---|---|---|---|
| 吸收 | 大多数关键字 | 带到输出 | 严格 | 嵌套集合里的名字只在该集合内有效 |
| 封装 | DEFINE、DEFINE-SYMBOL、DEFINE-STYLE | 成为定义的内容，不外传 | 容错 | 局部；每次套用时改名，每个用例有自己的一份（9.4） |
| 提交 | 记录，`@RNL` | 按顺序并入本层 | 容错 | 发布到本层，本层各记录共享；可以先用后绑定 |

- 一个成员的产物是它各段、各嵌套集合产生的全部事实，不只是最后的句柄。它们随所在的顶层成员一起提交。
- 记录里的每条语句都提交，有没有名字都一样。提交后起什么作用，看对象是什么：场景里的描述画出来或参与求解；定义可以被使用，本身不画；引用和只由引用组成的集合不起作用。普通 `{…}` 里的语句随所在的成员提交，所以 `{ @LINE {…}}` 的线会画出来（13.4）。
- 定义体里的语句不提交，只成为定义的内容。普通定义在套用时才展开（9.4）。
- 带体的 USE-PACKAGE 也按封装方式收体：体里的语句是包的内容，不提交到本层。包里的名字怎样可见，见 16.2。

### 5.5 管道与嵌套

- `a => @K(…)` 把 `a` 的结果作为 K 的第一个对象；AS、ATTACH 把它填进第一个角色，不填进定义的槽位。结果是集合也只算一个对象（5.2.1）。`=>` 后面的段只能按位置收这个对象，不能给它标角色。
- 管道不是逐步执行的，而是展开成用句柄连起来的几条描述：每一段描述的是前一段结果的句柄；逐个成员做的一段展开成多条平行的描述（1.5 第 1 条）。
- **失效只波及依赖它的描述。** 一条描述失效，只有两种原因：它自己读不懂或自相矛盾；或者它要用的句柄本该由一条失效的描述创建。
  - `$GND @ATTACH &vss => @PLACE("20", 38) => @ORIENT("R90") => %g1` 里只有 PLACE 失效（PLACE 要数的地方写了字符串，5.3）；地照样创建，ORIENT 照样生效。
  - `#XI0<3:0> @BUNDLE(bad=1) => @PLACE(10, 20) => %s` 里叠画没建成（BUNDLE 没有参数 `bad`），PLACE 没有要描述的对象，也跟着失效。
- 名字绑定什么：写在开头的 `%x =` 绑定整条管道最后的句柄；`=> %x` 绑定它左边那一段的结果，写在末尾就是最后的句柄，写在中间就是那一段的结果，如 `#M1 @AS $A => %a => @AS $B => %b`。PLACE、ORIENT、SET-SYMBOL、SET-STYLE、GROUP 沿用输入的句柄，所以 `$GND @ATTACH &vss => @PLACE(24, 38) => %g0` 里的名字 `%g0` 是这次套用的用例，也就是这个地。AS、ATTACH 产生新句柄：`#M1 @AS $A => @AS $B` 的第二段把 `$B` 套用到第一段产生的用例上（嵌套），不是 M1。要给 M1 套用两个定义，写成两条语句。名字左边那一段失效时：它本来沿用输入的句柄，名字仍指这个句柄（上例的 `%g1` 是那个地）；它本来要创建新对象，名字指失效对象（上例的 `%s`）。
- 对象可以写成一个集合，集合里是语句（嵌套）。嵌套集合里绑定的名字只在该集合内有效。嵌套的语句各是一条描述：`{%a = #M1 @PLACE(1, 2); #M9} @ALIGN("y")` 在宿主没有 M9 时 ALIGN 失效，M1 的坐标照常生效。
- 标准写法是平铺的：给对象起名，再在别的语句里引用它。单条语句在开头写 `%x =` 起名，管道用 `=> %x`（4.3）。

### 5.6 定义作为对象

用到定义的关键字把定义作为它的一个对象，定义在哪个槽位由关键字定：ATTACH 的定义是写出的第一个对象；SET-SYMBOL、SET-STYLE、AS、SELECT-USAGE、SELECT-ANCESTOR-USAGE 的定义是最后一个对象，SELECT-USAGE 的可以省略（10.1）。

```rnl
%ax = (_, _);
%w13 = &x @WIRE {#M1:1 #M3:1};
#M1 @SET-SYMBOL $NMOS;
%w13 @SET-STYLE $signal;
#M1(a) #M2(b) %ax(axis) @AS $MIRROR_PAIR;
$GND @ATTACH &vss;
# @SELECT-USAGE $GND => @SET-SYMBOL $GROUND
```

- 定义不标角色，也不计入"全标或全不标"。定义也是对象、占一个槽位，所以 `{#M1 #M2} @SET-SYMBOL $X` 是两个对象（5.2.1）。
- 定义的槽位由关键字固定，所以解析语句时不用知道一个 `$` 名字指的是定义还是集合：`$GND_STUB @ATTACH $GND_FILL_SET` 里前一个是定义，后一个是集合。
- 定义不能经管道送入：送来的对象填第一个槽位，AS、ATTACH 按角色配它，不占定义的槽位（5.5）。所以 `$GND @ATTACH &vss` 不能写成 `$GND => @ATTACH &vss`。
- 定义可以是嵌套的匿名定义：`#M1 @SET-SYMBOL { @DEFINE-SYMBOL {…}}`。
- 普通定义可能写在后面或别的层里，所以 AS、ATTACH 的对象个数、角色名和参数在本层生效时核对（7.1）。

### 5.7 句柄与名字

- 宿主对象的句柄由宿主给出：元件名、网络名。端子是元件加端子序号，所以 `#M1:1` 与 `#M1:d` 是同一个端子。
- RNL 创建的东西，句柄由创建它的语句产生。别的语句只能通过名字引用它：名字是找到它的唯一办法。没有名字的对象只能在它自己的语句里使用（管道、嵌套）。
- 一个名字不会指两个东西：同一层里只绑定一次（6.6）。
- 子对象的句柄是父对象和它的名字，不必另起名字。
- 普通定义展开出的局部对象，句柄是用例和局部名，从外面写作 `%c1::mid`（9.4）。没有名字的用例，它的局部对象只在诊断里按位置显示，不能引用。
- 生成集里的单个对象没有名字，不能单独引用：不按种类和关联的对象认对象（没有自然键），集合也不提供按下标引用。

### 5.8 事实的键

- 有键的事实按键覆盖：同一个键，后写的生效；后写的失效时，保留较早的有效值。
- 几何事实例外：PLACE 的 x、y（每个坐标一个键）和 ORIENT（每个对象一个键）。同一个键写了两个不同的值就是冲突，按 8.5 取舍：优先级相同时保留后写的，与按键覆盖结果相同；优先级不同时保留高的。PLACE 只改它写出的坐标，从没写过的坐标是自由的。
- 用已经绑定的名字再创建对象，不是按键覆盖：名字同一层只绑定一次（6.6）。要改 RNL 创建的对象，写修改它的语句，如 `%g0 @PLACE(40, 38)`。
- 没有键的事实累加：不冲突的并存，冲突的按 8.5 取舍。
- SET-SYMBOL、SET-STYLE 不按键覆盖，按外观队列生效（8.3）。
- VERSION 只在头段记录里写一次（16.1），所以谈不上覆盖。
- CURRENT 每个端子一个键（15.2），LAYER 每个对象一个键（11.6）。
- 用例没有键：一个定义套用几次就是几个用例，互不覆盖。两句相同的套用产生两个用例，所以 `$GND @ATTACH &vss` 写两次就画两个地。对一个用例写的修改语句（如 PLACE），其事实是有键的，照上面的规则处理。
- 对象的优先级是一条有键的事实；优先级之间按什么次序覆盖，见 14.8。
- 写了引用名（`key=`）的 TEXT，每个附着对象、每个引用名是一段文字，后写的按项覆盖它（13.3）。没写引用名的 TEXT 不按键覆盖：每写一次就多一段文字（13.3）。
- 约束没有键。要改一条约束，就把它关掉（`"disabled"`，14.8）再写新的，或者直接改文本。
