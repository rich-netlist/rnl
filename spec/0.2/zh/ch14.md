## 14 布局意图

### 14.1 共同规则

- 约束产生一个约束对象。命名的约束可以引用，便于定位、编辑，如 `%row1 = {#M1 #M2} @ALIGN("y")`；约束也可以匿名。
- **词汇**：位置的原子约束只有 ALIGN、ORDER、DISTRIBUTE、DISTANCE 四种，加上 PLACE、ORIENT、GROUP。别的关系写成普通定义：对称（14.7）、居中（三个成员的 DISTRIBUTE）、行列（ALIGN 加 ORDER）、信号流向（14.6）、镜像对、按比例的间距（几条精确的 DISTANCE）。没有 LEFT、ABOVE（它们就是带方向的 ORDER 或 DISTANCE），也没有 RATIO、NEAR、INSIDE。相对朝向（同向、互为镜像）写 ORIENT-RELATION（14.9）；一对器件的栅极相向还是朝外，仍用一个 ORIENT 或端子上的 ORDER 定（14.3）。符号不重叠、间距常数、网格归求解器（11.7），不属于约束的词汇。
- **没有相对整张图的位置**："最左""最右""最上"没有关键字，也没有整张图或符号外框的范围。写成相对一组对象的 ORDER 或 DISTANCE，求解器据此找出布局。如端口在最右边：`{#M6 #M7 #CL} %pout @DISTANCE("left-to-right", min=2)`，或者在 M7 本来就在最右时写 `{#M7 %pout} @ORDER("left-to-right")`。
- **成员**是能定位的对象：元件、自己有位置的虚拟元件（12.1）、叠画、点、TEXT（取文字自己的位置，13.3）、端子、按中心写的 RECTANGLE、CIRCLE、ELLIPSE 的中心、集合的 `::position`，以及集合（见下）。导线、网络、约束、定义、没有符号的用例、画在主对象坐标点上的用例不能作成员：收到时这条约束失效（12.1）。导线上的位置应先写成点（13.1）。
- **取哪一点**：元件取它的原点，即它的符号的原点，PLACE 放的也是它；端子取引脚的位置，是器件位置加上符号里引脚位置的刚性变换，不能单独移动；点取它自己；虚拟元件取它自己的位置（12.1）；TEXT 取文字自己的位置；按中心写的 RECTANGLE、CIRCLE、ELLIPSE 取中心。不取符号外框的中心：三端、四端 MOS 符号的外框不同，排成一行会错位。要按引脚对齐就写端子。视觉上的对称要求原点落在符号的对称轴上，这归符号库。
- **集合作成员**：ORDER、ALIGN、DISTRIBUTE 的成员是集合时，算作一个成员，取它的中心，即它的 `::position`。DISTANCE 的两个槽位收对象或集合，集合按范围算（14.5）。中心和范围都按成员的那一点算，嵌套的集合取到最里层的对象，与符号无关。空的集合不算成员；集合里有不能定位的对象时，这条约束失效。引用仍打散一层（5.2）：`{%a_set %b_set} @ALIGN("y")` 是把两个集合的成员拼起来逐个对齐。要两个集合各算一个成员，写 `{{%a_set} {%b_set}} @ALIGN("y")`，或者用 `%a_set::position` 和 `%b_set::position`。

  注：本意是 `{{%a_set} {%b_set}}` 却写成 `{%a_set %b_set}`，是常见的错误（5.2）。
- 投影只有 `"x"` 和 `"y"`。
- 约束不改变网表。冲突时一条原子约束整条保留或整条丢弃（8.5）。
- 四种原子约束和 ORIENT-RELATION 都收参数 `priority=`（14.8）。

### 14.2 ALIGN

`{…} @ALIGN("y")`：成员在 `axis` 这一投影上相等，`"y"` 是 y 相同（排成一行），`"x"` 是 x 相同（排成一列）。`axis` 必写，可以按位置写。成员不到两个时这条约束自然成立，不失效：选择和集合有几个成员，写语句的时候不知道。

### 14.3 ORDER

```rnl
%rc_set = {#R2 #C2};
{#M1 #M1:2 #M2:2 #M2} @ORDER("x");              /* the two gates face each other */
{#R1 {%rc_set} #M1} @ORDER("left-to-right")     /* left to right; R2 and C2 count as one member, by their centre */
```

- `{…} @ORDER(direction)`：成员沿方向所在的投影严格单调。成员不到两个时自然成立。
- **方向**：参数 `direction`，必写，按位置写在最前。取值：
  - `"left-to-right"`、`"right-to-left"`：沿 x 递增、递减；
  - `"bottom-to-top"`、`"top-to-bottom"`：沿 y 递增、递减（y 向上，11.7）；
  - `"x"`、`"y"`：只定在哪一轴上排，正序、倒序都可以。

  DISTANCE 的取值与此相同。
- 成员是集合时按它的中心算（14.1）。只比中心，所以两个集合的成员仍可能交错；要两个集合分开，用 DISTANCE（14.5）。
- ORDER 是严格的：相邻成员至少差一个坐标单位（11.7）。要坐标相等，用 ALIGN。

### 14.4 DISTRIBUTE

`{…} @DISTRIBUTE("x")`：相邻成员在 `axis` 投影上的差相等，步长可以是正、负或零。比的是成员那一点之间的步长（集合取中心），不是外框之间的间隙。`axis` 必写，可以按位置写。成员不到三个时这条约束自然成立。

### 14.5 DISTANCE

```rnl
#M1:2 #M1 @DISTANCE("left-to-right", min=1);      /* the gate is on the left */
#R1 #R2 @DISTANCE("left-to-right", exact=8)       /* R2 exactly 8 units to the right of R1 */
```

```rnl
%stage1_set = {#M1 #M2 #M5};
%stage2_set = {#M3 #M4};
%stage1_set %stage2_set @DISTANCE("x", min=1);                /* the two sets do not interleave in x; either may be on the left */
%stage1_set %stage2_set @DISTANCE("left-to-right", min=1)     /* all of stage 2 is to the right of all of stage 1 */
```

- `A B @DISTANCE(direction, min=…, max=…)`：A 填槽位 `from`，B 填槽位 `to`；各是一个对象或一个集合。
- **方向**：参数 `direction`，必写，按位置写在最前，取值同 ORDER（14.3）。只约束这一轴，不是欧氏距离。
  - 沿递增方向（`"left-to-right"`、`"bottom-to-top"`）约束 B − A；
  - 沿递减方向（`"right-to-left"`、`"top-to-bottom"`）约束 A − B；
  - `"x"` 和 `"y"` 约束 |B − A|，边界不能为负。
- **集合按范围算**：A、B 是集合时，沿递增方向约束 B 的最小值减 A 的最大值，B 整个在 A 之后时为正；沿递减方向反过来，约束 A 的最小值减 B 的最大值；`"x"` 和 `"y"` 约束两者之间的间隔，哪边在前都行，两者交错时为负。单个对象是只有一点的范围，结果与上一条相同。范围按成员的那一点算（14.1）。一边是空集合时这条约束自然成立。所以要两个集合不交错，写 DISTANCE 就行，不需要别的写法。
- `min`、`max`、`exact` 至少应写一个；`min` 不应大于 `max`。
- `exact=` 是精确的距离，就是 `min`、`max` 相等的简写：沿递增方向时 B − A = exact，沿递减方向时 A − B = exact，`"x"` 和 `"y"` 时 |B − A| = exact，哪边在前都行（不能为负）。它不能与 `min` 或 `max` 同写：同写是无效的参数，这条语句失效。工具写精确距离时写 `exact`（4.3）。

### 14.6 信号流向

信号流向（原则 2.4）写成普通定义的用例，没有关键字。标准包提供不提供这样的定义、叫什么名字，归标准包（16.3）；例子用 `$FLOW`，它按参数给出的方向，给一条写成集合的路径排序。

```rnl
%rc_set = {#R2 #C2} @GROUP;
{#R1 {%rc_set} #M1} @AS $FLOW            /* the signal goes from R1 through the block of R2 and C2 to M1, left to right */
```

- 信号流向是软的概念：不是所有电路都有严格的方向。所以它写成低优先级的约束（14.8）。
- 路径上由几个对象组成的一段，单独写成一个 `{…}`，如 `{%rc_set}`，按它的中心算（14.1）。GROUP（11.5）只让求解器把它当作一块，可以不写。
- 方向在套用定义时作为参数给出（9.4）：`{…} @AS(direction="top-to-bottom") $FLOW` 就是从上往下（y 向上，11.7）。

### 14.7 对称

对称写成普通定义的用例。对称轴只是一个自由点，不需要关键字。标准包提供 `$MIRROR_PAIR`，角色是 `a`、`b`、`axis`：a、b 同高，关于轴点对称，b 的朝向是 a 左右翻过来的。

```rnl
%ax = (_, _);
%sym12 = #M1(a) #M2(b) %ax(axis) @AS $MIRROR_PAIR
```

- `$MIRROR_PAIR` 不定实际的朝向：栅极朝内还是朝外，仍要给一边写 ORIENT（14.9）。要两边同向的对称，另写一个普通定义，不带其中的 ORIENT-RELATION。

### 14.8 优先级：PRIORITY

```rnl id=dpl
$DP_LAYOUT = @DEFINE(roles=["in_p", "in_n"]) {
  {?in_p ?in_n} @ALIGN("y", priority="low")                    /* a default layout, the first to give way */
};
%dp2 = #M1(in_p) #M2(in_n) @AS(priority="high") $DP_LAYOUT;     /* this pair keeps the default layout strictly */
#M1 @PLACE(12, 20, priority="high")                             /* fixes the position of M1 */
```

```rnl use=dpl
# @SELECT-USAGE $DP_LAYOUT => @PRIORITY("disabled")    /* a house-style package turns the default layout off, to apply its own */
```

- **四档**：`"disabled"`、`"low"`、`"normal"`、`"high"`。没写优先级的事实都是 `"normal"`，不论写在用户的记录里、包里还是定义体里。
- **分级，不加权**：冲突时先比优先级，高的保留；优先级相同，后写的保留（8.5）。约束不做加权求和。

  注：加权时，十条低优先级的约束能压过一条高优先级的；而且各求解器量"违反了多少"的办法也不同。
- **纳入的都是硬的**：`"low"` 的意思是"冲突时先丢"，不是"尽量接近"。纳入的事实，不论优先级是哪一档，求解器都必须满足；实现自己的美观目标只在纳入的事实之内优化，排在语言的全部描述之后。
- **`"disabled"`**：这条事实在排序之前去掉，不交给求解器。这不是失效：对象照样存在，依赖它的描述不受影响，不给警告，后写的优先级可以把它重新打开。
- **写法**：
  - PLACE、ORIENT、四种原子约束、ORIENT-RELATION、AS、ATTACH 都收参数 `priority=`，优先级跟着这条事实。`priority` 是 AS、ATTACH 唯一的标准参数；定义的参数不能叫这个名字。
  - PRIORITY 语句用来事后改优先级。它只收有自己句柄的对象：约束、用例，以及带 GROUP 的集合（只能开关，11.5）。收到带 GROUP 的集合时作用于分组本身；别的集合逐个成员处理（5.2.1）。收到元件或别的对象时失效（种类不对）：`#M1 @PLACE(…) => @PRIORITY(…)` 是错误，因为 PLACE 沿用 M1 的句柄；优先级要写成 PLACE 的参数。
  - 记录头 `@RNL(priority=…)` 给记录里收这个参数、又没写它的语句一个默认值，也给 TEXT 的 `dx`、`dy`（13.3）。
- **覆盖的次序**，从低到高：记录头的默认值；语句自己的参数；PRIORITY 语句（几条之间后写的生效；包里的按 USE-PACKAGE 的位置）；外层用例的优先级；从用例外面经 `::` 直接写在它的某个局部对象上的 PRIORITY 语句（几条之间后写的生效）。这些都没有时，优先级是 `"normal"`。
- **用例的优先级向下传**：用例的优先级（它自己的参数，或写在它上面的 PRIORITY 语句）作用于它展开出的全部事实，包括嵌套的用例展开出的，并盖过它们自己的优先级；嵌套时，最外层带优先级的用例说了算。要只调里面的一部分，就从外面经 `::` 直接写在那个局部对象上（9.4）：它比用例的优先级更具体，所以盖过用例的优先级，越具体的越优先。这种语句若写在外层定义的体里，仍受外层用例的优先级管。记录里的每条语句都能直接改，所以记录头只给默认值。
- **求解器的输出**：求解器把结果写成 PLACE、ORIENT 等，用 `"high"`，放在这一层自己的文字的最后一个记录里，如 `@RNL(type="generated", priority="high") {…}`。子电路写在它的 `.subckt … .ends` 之内，哪怕它在被 include 的文件里；顶层写在主文件的文件层（第 17 章）。求解器求解时不应读 `type="generated"` 的记录（2.8），所以旧结果不会约束下一次求解；求完后删掉它们，在最后写上新的结果。
  - 两次求解之间，新写的 normal 语句若与求解结果冲突，会被丢弃，下一次求解后才生效。查看器可以按记录头的 hash 建议重新求解；这类丢弃不必逐条报告。
  - 编辑器里的拖动写成 `"high"` 的 PLACE，同样写在这一层自己的文字里，放在求解器的记录之后。这就把位置固定住了：以后每次求解都把它当硬约束。要放开，删掉那条语句。
- **求解器的优化目标**不属于语言：目标的种类和次序因求解器而异，本标准定不出它们的共同词汇。求解选项是 hash 所覆盖的输入的一部分（第 17 章），存进文件本有利于复现结果；本版没有扩展机制（16.4），所以求解器把自己的设置放在它自己的文件里。

### 14.9 朝向关系：ORIENT-RELATION

```rnl
#M1 #M2 @ORIENT-RELATION("MY");                  /* M2 is drawn as M1 flipped left-right */
{#M1 #M3} {#M2 #M4} @ORIENT-RELATION("MY");      /* M1 and M3 alike, M2 and M4 alike, the two pairs mirror images */
#M5 {#M7 #M8} @ORIENT-RELATION("R0")             /* M5, M7 and M8 have the same orientation */
```

- `A B @ORIENT-RELATION(relation)`：两个槽位 `from`、`to`，各是一个对象或一个集合。关系是 ORIENT 的八个朝向码之一（11.2），按位置写。B 的朝向等于先按 A 的朝向变换、再做这个关系的变换。变换在图的坐标系里做，所以 `"MY"` 总是关于竖直线左右翻，与 A 本身转没转无关。
- 一边是集合时，这一边的成员朝向都相同，两边之间满足关系。要一个集合全部同向，就把其中一个成员拿出来，如 `#M5 {#M7 #M8} @ORIENT-RELATION("R0")`，或者把集合写两遍：`{#M5 #M7 #M8} {#M5 #M7 #M8} @ORIENT-RELATION("R0")`。
- 没有"只给一个集合、集合里朝向都相同"的写法：关键字说的是两者之间的关系，只给一个集合时看不出关系作用在什么上。只写一个对象与签名不符，是错误。只写一个集合时，照 5.2.1 先拆一层，所以 `{#M1 #M2} @ORIENT-RELATION("MY")` 就是 `#M1 #M2 @ORIENT-RELATION("MY")`；拆出来不是两个对象时是错误。
- 成员是有朝向的对象，与 ORIENT 相同（11.2）：元件、叠画、有符号的用例。端子、点、网络、导线、没有符号的用例是错误：这条约束失效。一边是空集合时这条约束自然成立。
- 它是约束：产生一个约束对象，可以命名，收 `priority=`，可以用 PRIORITY 改（14.8）；冲突时整条作为一个单位保留或丢弃（8.5）。写了 ORIENT 的成员朝向已经定了；别的成员由求解器在满足关系的朝向里选。
- 它不定实际的朝向：两个 MOS 互为镜像时，栅极朝内、朝外都满足 `"MY"`。要定下来，再写一个 ORIENT，或者端子上的 ORDER（14.3）。
