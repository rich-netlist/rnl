## 9 定义

### 9.1 共同规则

- 有三种定义：DEFINE-SYMBOL 产生符号，DEFINE-STYLE 产生样式，DEFINE 产生普通定义。符号和样式是特殊的定义（1.4.4）。它们都收一个集合作定义体；体内的语句逐条容错（7.3）。
- 定义是对象，用 `$name =` 或 `%name =` 命名（6.6），作关键字的对象被使用，所在的槽位由关键字定（5.6）。
- 提交一个定义只是发布它的名字。定义本身不画任何东西，只在被使用时起作用：符号在被 SET-SYMBOL 指派时，样式在被 SET-STYLE 指派时，普通定义在被 AS 或 ATTACH 套用时。
- 直接写作记录的成员、不嵌套在语句里、又没有名字的定义，不会被用到，给警告。嵌套在语句里的匿名定义照常使用。
- **并入**：DEFINE-SYMBOL 或 DEFINE-STYLE 的定义体里引用同类的定义，就是在该处并入它的内容。有键的成员后写的覆盖先写的；没有键的成员累加。没有 `base=` 参数。
- 普通定义之间不并入，用体内的 AS、ATTACH 组合。派生和扩充也这样做；没有继承关系（9.4）。

### 9.2 符号：DEFINE-SYMBOL

#### 9.2.1 求值

- 符号是值：定义体在定义处求值，体内的语句按符号的局部坐标产生引脚和图元。它们成为定义的内容，不提交给场景。
- 成员的顺序就是绘制顺序。
- 局部坐标与场景同单位、同轴向（x 向右、y 向上），(0, 0) 是符号的原点（6.5）；本版没有缩放（11.7）。体内的点两轴都应写数，不能用 `_`。

#### 9.2.2 体内的语句

- 体内只能写：图元、引脚、命名的局部点（如 `%tip = (0, 0.7)`）、并入别的符号、只用来画的用例（用 ATTACH 或 AS，9.4）以及写在这种用例上的 SET-SYMBOL 和 ORIENT（9.2.7），还有附着在所属对象 `?`（即用这个符号画出的对象）上的 TEXT 以及给这种文字定位的 PLACE（13.3）。
- 其他语句失效，被丢弃（体是容错的）；宿主引用也失效。
- 引脚只能写在 DEFINE-SYMBOL 体里。图元也可以写在场景里，那时用场景坐标，是标注（13.4）。

#### 9.2.3 参数

- `box=[x1, y1, x2, y2]`：符号的外框，用局部坐标，轴对齐，随元件的朝向变换。语言本身不用它；查看器通常拿它当选择框，求解器当符号互不重叠的边界，怎样用由实现决定。不写时取符号里除文字以外全部图元的外接框，因为文字的大小随字体和渲染器变。

#### 9.2.4 引脚

```rnl
$RES_BOX = @DEFINE-SYMBOL {
  %p = (0, 3) @PIN(terminal=1, label="P", direction="up");
  %n = (0, -3) @PIN(terminal=2, label="N", direction="down");
  @LINE {%p (0, 1.5)};
  @LINE {(0, -1.5) %n};
  (0, 0) @RECTANGLE(width=1.2, height=3)
}
```

- 引脚是绑定到端子的点。命名后可以当点用，如上例的引线从 `%p` 画起、画到 `%n` 为止。
- 建议引脚放在整数点上（11.7）：元件放在整数点上时，它的引脚和接上的导线也都落在整数点上。放在别处不是错误，实现可以给提示。符号里的图元不受此限。
- `terminal=`：用这个符号画出的对象的一个端子，写序号、DEVICE 给的端子名（6.12）或子电路的端口名；用例则写它的定义的角色名或角色的序号（6.4）。一个符号里一个端子只有一个引脚：引脚以端子为键。
- **总线引脚**：`terminal=` 可以收数组，一个引脚对几个端子，如子电路的总线端口：`(-4, 0) @PIN(terminal=["D<3>", "D<2>", "D<1>", "D<0>"], label="D<3:0>", direction="left")`。数组至少有一个元素，每个元素是序号或名字。参数里的字符串不展开下标（6.11），所以名字要逐个写。
  - 这几个端子都画在这个引脚上：导线或约束接到其中任何一个，就是接在这个引脚上；导线接到其中任何一个时，这几个端子都算接了线（10.2）。
  - 同一个端子写在几个引脚里时，引脚按端子覆盖：后写的引脚得到它，前面的引脚保留自己其余的端子（9.2.7）。
  - 叠在同一点的几个引脚代替不了总线引脚：坐标相同不算接上（13.1），导线只接到其中一个引脚，其余的仍是 `wired=false`，标准包的补位规则会给它们补标签、补地。
- `label=`：引脚名，只用于显示，不能用来引用端子（6.4）。显不显示、显示在哪里由查看器决定。可以用文字记号，如 `\overline{CS}`（13.6）。
- **不画的端子就没有引脚。** 没有引脚的端子没有绘图意义：导线或约束接到它上面时失效（"符号没有这个端子的引脚"），补位也不选它（10.1）。没有把有引脚的端子藏起来的写法；不想画衬底，就用一个没有衬底引脚的三端符号。
- `direction=`：导线离开引脚的方向，取 `"right"`、`"up"`、`"left"` 或 `"down"`。它写在符号的局部坐标里，随朝向一起转（11.2）。它是给求解器和查看器的提示，如自由走线从哪个方向离开引脚、电流在端子上的走向（15.2），或选朝向时的参考；它不是约束，不参加冲突。可以不写，不写时引脚没有方向，实现可以按图形推断一个。
- 没有引线长度：引线用 LINE 画在符号里。
- 没有电气类型：引脚和端子不设 input、output 之类的参数，网表里也没有这类信息。需要时，用户用语义定义的用例表达；导出到 Virtuoso 之类工具的导出器，按自己的配置把普通定义对应到电气类型。
- 引脚只是一个点：画不画引线由符号决定，引脚的点怎样标出来（小方框、圆点或不标）由查看器决定。所以没有引线的引脚不用专门的写法：写 PIN、不写 LINE 就是。例如原图把导线接到编辑器隐藏的衬底引脚上，就导入成保留衬底 PIN、不画衬底引线的符号。一般的符号，包括标准包里的，都画引线。

#### 9.2.5 图元

位置是点对象，标量是参数。表中写法里的 *point* 代表任何点对象。

| 写法 | 含义 |
|---|---|
| `@LINE {point point …}` | 两个点是线段，更多是折线；最后一个点与第一个点位置相同时图形闭合，接头按转角画 |
| `@RECTANGLE {point point}` | 矩形；两个点是对角，不分先后 |
| `(0, 0) @RECTANGLE(width=4, height=2)` | 矩形；点是中心，`width`、`height` 是宽和高 |
| `@CIRCLE {point point}` | 圆；第一个点是圆心，第二个点在圆上 |
| `(0, 0) @CIRCLE(radius=1)` | 圆；点是圆心 |
| `@ELLIPSE {point point}` | 椭圆；两个点是外接框的对角 |
| `(0, 0) @ELLIPSE(width=4, height=2)` | 椭圆；点是中心，`width`、`height` 是外接框的宽和高 |
| `@ARC {point point point}` | 圆弧，从第一个点经过第二个点到第三个点 |
| `@BEZIER {point point point point …}` | 三次贝塞尔曲线，3n+1 个点：起点，然后每段两个控制点和一个终点；相邻两段共用端点 |
| `(1, 0) @TEXT("…")` | 附着在点上的文字：符号的固定文字，不能按元件改变 |
| `? @TEXT("${name}", key="name") => @PLACE(1, 0)` | 附着在所属对象（用这个符号画出的对象）上、读它属性的文字；引用名是 `name`，所以对 M1 就是 `#M1::name`，场景里引用名相同的文字按项覆盖它（13.3） |

- **两种写法**：RECTANGLE、CIRCLE、ELLIPSE 按有没有写尺寸参数区分。写了尺寸（RECTANGLE、ELLIPSE 的 `width` 和 `height`，CIRCLE 的 `radius`），对象槽位收一个点，就是中心；收到集合时每个点各画一个（5.2.1）。没写尺寸，对象槽位收两个点的集合，点数不对时这条图元失效。尺寸只写了一部分是参数写错，这条图元失效。两点的写法里点是对象：可以命名，也可以是引脚的位置，图形跟着点走。
- 矩形和椭圆都是轴对齐的；斜的矩形用闭合的 LINE 画。
- **填充**：除 TEXT 外的图元都收 `fill=`。不闭合的 LINE、ARC、BEZIER，按从最后一个点到第一个点连一条直线围成的区域填，这条连线不描边；填充的 ARC 是弦和弧围成的弓形。只填充、不描边的图形（MOS 的栅极、箭头、汇合圆点）写 `fill="linecolor", linestyle="none"`（9.3）。
- **线端箭头**：LINE、ARC、BEZIER 收 `arrow=`：`"none"`（默认）、`"start"`、`"end"` 或 `"both"`，如 `@LINE(arrow="end") {%from %to}`。箭尖落在起点或终点上，指向线在这一端的走向：LINE 取首段或末段，ARC 取圆弧在端点的切线，BEZIER 取从相邻控制点到端点的连线（两点重合时取下一个不重合的点）。箭头的长度由 `arrowsize` 给（9.3），形状由实现决定。端点是点对象；被约束挪动时箭头跟着走，可以是任意角度，而画在点上的箭头用例只有 8 种朝向。WIRE 不收 `arrow=`。
- **样式参数**：图元可以直接把样式属性写成参数（9.3）：LINE、ARC、BEZIER 收 `linecolor`、`linestyle`、`linewidth`、`cap`、`join`、`fillcolor` 和 `arrowsize`；RECTANGLE、CIRCLE、ELLIPSE 收前六个；TEXT 收 `textcolor`、`size`、`font`、`bold` 和 `italic`。写了的是这个图元直接的样式，高于所属对象传来的样式（8.3），所以符号里写死的颜色不随主题变；没写的取所属对象的样式，所以换主题不用改符号。填充用 `fill=` 写：`"none"`（默认）、`"linecolor"`（用 `linecolor` 的颜色）或 `"fillcolor"`（用 `fillcolor` 的颜色）。
- **不设**：SVG 路径字符串、POLYGON（用闭合的 LINE）、单独的箭头图元（线端的箭头见上；别处用填充的闭合 LINE，或画在点上的箭头用例，9.2.7）、圆角矩形、椭圆弧（用 BEZIER 近似）和图片。
- **文字**：TEXT 另有 `size=`（字号，11.7）、`halign=`（水平：`"start"`（默认）、`"middle"`、`"end"`）、`valign=`（竖直：`"baseline"`（默认）、`"top"`、`"middle"`、`"bottom"`）和 `rotate=`（0、90、180 或 270，默认 0）。符号体里附着在 `?` 上的 TEXT 引用所属对象的属性，附着在点上的是固定文字；场景里的 TEXT 按附着的东西分成标注和标签（13.3、13.4）。文字记号见 13.6。
- **基线**：`valign="baseline"` 时，锚点在第一行的基线上，后面几行往下排，与 SVG、PostScript 和多数编辑器相同；`"top"`、`"middle"`、`"bottom"` 按整个文字框对齐。基线是默认。
- **文字的方向**：锚点就是文字自己的位置（13.3）。文字框按 `halign`、`valign` 放在锚点旁边，绕锚点按 `rotate` 转；符号里的文字再随元件的朝向变换，旋转、镜像都算。框里的字总是正读：横排从左往右，竖排从下往上，字形从不镜像。所以 `rotate=180` 按 0 显示、270 按 90 显示，文字框在锚点的另一边；元件镜像时锚点照常镜像，文字框沿镜像的方向移到锚点的另一边，但字不镜像。例：NMOS 的名字锚点在 (1.5, 1.5)，`halign="start"`，往右展开；`"MY"` 时锚点到 (−1.5, 1.5)，文字往左展开，离开本体；`"R90"` 时锚点到 (−1.5, 1.5)，文字竖排，从下往上读。场景里的文字不随元件转。

#### 9.2.6 子电路符号

写在子电路 `.subckt ota5t … .ends` 之内：

```rnl subckt
%ota5t = @DEFINE-SYMBOL(box=[-4, -4, 4, 4]) {
  (-4, 1) @PIN(terminal="inp");
  (-4, -1) @PIN(terminal="inn");
  (4, 0) @PIN(terminal="out");
  @LINE {(-4, -4) (-4, 4) (4, 0) (-4, -4)};
  ? @TEXT("${name}", key="name") => @PLACE(-1, 0)
};
# @SET-SYMBOL %ota5t
```

- 子电路给自己的 `#` 指派的符号，就是该子电路的元件不论在哪里的默认外观，即它的子电路符号。引脚按名字对应子电路的端口。
- 它是原则 2.5"定义只向下生效"这条规则的例外：它作用于实例化该子电路的各层。
- 子电路的总线端口在网表里已拆成单个端口（6.11）；子电路符号用总线引脚把它们画成一个（9.2.4）。
- 在符号队列里，它排在根上的包的规则之后，在各层的规则（包括在某层用到的包）之前，所以上层可以用规则或给单个元件写的 SET-SYMBOL 换掉它（8.3）。
- 没有元件实例化文件层，所以写在文件层的 `# @SET-SYMBOL` 不起作用。
- 子电路没有子电路符号时，它的元件怎样画由查看器决定，本标准不规定。一个子电路里有几条 `# @SET-SYMBOL` 时，它们在符号队列的同一组里，按文本先后，后写的生效（8.3）；实现可以给警告。

#### 9.2.7 变体与片段

```rnl
$NMOS_BULK = @DEFINE-SYMBOL(box=[-3, -3, 2, 3]) {
  $NMOS;
  %b = (1, 0) @PIN(terminal=4, label="B", direction="right");
  @LINE {(0, 0) %b}
}
```

- 在体内并入另一个符号再添改，就是变体：引脚按端子覆盖（总线引脚按其中各个端子算，9.2.4），图元累加。
- 只在本层用的片段用 `%` 命名，如 `%MOS_CHANNEL = @DEFINE-SYMBOL {…}`，别的符号体里写 `%MOS_CHANNEL;` 并入它。
- 图元没有键：并入只加不减，并入的图元去不掉。要少画一部分，就另定义一个符号：把共用的部分拆成片段，各个符号并入自己要的部分，如 `$NMOS3 = @DEFINE-SYMBOL {%MOS_BODY}` 和 `$NMOS4 = @DEFINE-SYMBOL {%MOS_BODY; %BULK}`。
- **体里的用例**：需要放在不同位置或不同朝向的图形，如箭头，写成画在点上的用例：

  ```rnl
  $ARROWHEAD = @DEFINE(roles=[["p", "point"]]) {};
  $ARROWHEAD_SYM = @DEFINE-SYMBOL {
    @LINE(fill="linecolor", linestyle="none") {(0.4, 0) (-0.4, 0.3) (-0.4, -0.3) (0.4, 0)}
  };
  $ISRC_DOWN = @DEFINE-SYMBOL {
    (0, 3) @PIN(terminal=1, direction="up");
    (0, -3) @PIN(terminal=2, direction="down");
    @LINE {(0, 3) (0, 1.5)};
    @LINE {(0, -1.5) (0, -3)};
    (0, 0) @CIRCLE(radius=1.5);
    @LINE {(0, 0.9) (0, -0.5)};
    $ARROWHEAD @ATTACH (0, -0.6) => @SET-SYMBOL $ARROWHEAD_SYM => @ORIENT("R270")
  }
  ```

  - 第一个角色填体里的一个点，用局部坐标。用例按它的符号画在这个点上，朝向绕这个点转，再随所在的符号一起变换；嵌套用例的变换逐级向外合成，所以箭头跟着器件转。
  - 只用来画：外面的规则看不到符号体里面，所以用例的符号要在体里用 SET-SYMBOL 指派；没指派符号的用例不画，给警告。普通定义的体在符号里不展开，约束和导线在符号里没有意义；这里的 ORIENT 是符号内部的数据，不参加冲突，没有优先级。
  - 场景里同样的写法就是画在点上的虚拟元件（12.1），规则可以给它指派符号；风格包的规则伸不到符号里面。
- 引脚名和公式：引脚名显不显示由查看器决定（9.2.4）；公式就是引用属性的 TEXT（13.6），没有特别的规则。文字记号见 13.6。

#### 9.2.8 符号与对象相配

符号不分"给器件的"和"给用例的"。一个符号能不能用于某个对象，看它的引脚对不对得上对象的端子。

### 9.3 样式：DEFINE-STYLE

```rnl
$ink = @DEFINE-STYLE(linecolor="#202020", textcolor="#202020", fillcolor="#ffffff", size=1.2) {};
$accent = @DEFINE-STYLE(linecolor="#1f4fd8", linestyle="bold") {$ink};
$shade = @DEFINE-STYLE(fillcolor="#1f4fd833") {}
```

- 括号里的参数是这个样式自己的属性，最后生效。集合里只能引用别的样式，在该处并入它们的属性，后写的覆盖先写的。没有基样式的样式写 `{}`。
- 样式只在被 SET-STYLE 指派时生效（11.3）。同样的属性也能作参数直接写在图元、TEXT 和 WIRE 上（9.2.5、13.1），按 8.3 的两级取值。
- 样式只管描线上色：位置、朝向、形状（符号或图元的点）和文字的内容都不属于样式。
- **属性**：

| 类 | 属性 | 取值 |
|---|---|---|
| 线 | `linecolor` | 颜色；也是 `fill="linecolor"` 的颜色 |
| | `linestyle` | `"solid"`（默认）、`"dashed"`、`"dotted"`、`"dash-dot"`、`"double"`（两条平行的实线）、`"bold"`、`"none"`（不画线） |
| | `linewidth` | 线宽，坐标单位（11.7）；`0` 是在任何缩放下都一样细的细线，也是默认 |
| | `cap` | 线端：`"butt"`、`"round"`、`"square"` |
| | `join` | 转角：`"miter"`、`"round"`、`"bevel"` |
| 填充 | `fillcolor` | `fill="fillcolor"` 的颜色 |
| 文字 | `textcolor` | 文字的颜色；不给时取 `linecolor` |
| | `size` | 字号，坐标单位（11.7） |
| | `font` | 字体名，只是提示；查看器没有这个字体就用自己的 |
| | `bold`、`italic` | 整段文字的粗体、斜体，`true` 或 `false`；记号 `\textbf`、`\textit` 照样能给局部加上（13.6） |
| 其他 | `arrowsize` | 线端箭头的长度，坐标单位（9.2.5） |

- 线只有颜色、线型、线宽、线端、转角五个属性。`"bold"` 画两倍的线宽，线宽为 0 时画两倍的细线；虚线的划长和间隔、双线的间距由实现决定，随线宽成比例。以后的语言版本可以给 `linestyle` 增加取值（16.1）。
- `"none"` 不画线，线端的箭头也不画（箭头属于线，9.2.5）；`fill="linecolor"` 照样取 `linecolor` 的颜色，所以只填充、不描边的图形写 `fill="linecolor", linestyle="none"`，它的颜色照样随主题变。导线和图元都收它；导线写了它就是一根看不见的导线，但仍是导线（13.1）。
- **颜色**照 CSS 的十六进制写法：`"#RRGGBB"` 或 `"#RRGGBBAA"`，或简写 `"#RGB"`、`"#RGBA"`。透明度在后：`00` 全透明，`FF` 不透明；不写就是不透明。线和填充各有各的颜色，所以透明度也分开设，如上例 `$shade` 只让填充部分透明。本版不收颜色名和 `rgb()`。颜色是字符串。
- 本版不设：图案填充、渐变、阴影；可见性 `visible`（显示和隐藏是查看器的事，16.2）；主题、profile 这类对象（主题就是一个带样式和规则的包，用 USE-PACKAGE 引入，16.2）。
- 某个属性没有任何样式或参数给值时，用渲染器自己的默认值，这不是错误（原则 2.7）。标准包给出可移植的默认外观（16.3），用户写的规则和语句覆盖它。
- 不认识的属性与语法错误同等处理（原则 2.3）。

### 9.4 普通定义：DEFINE

```rnl id=gdef
$TAIL_MID = @DEFINE(roles=["a", "b", "t"]) {
  %mid = (_, _);
  {?a %mid ?b} @DISTRIBUTE("x");
  {%mid ?t} @ALIGN("x")
};
$CHAIN_ROW = @DEFINE(roles=["source", "{series}", "load"]) {
  {?source ?series ?load} @ORDER("x")
};
$GND_BELOW = @DEFINE(roles=[["t", "terminal"]], parameters=[["gap", 2]]) {
  %g = $GND @ATTACH ?t::net;
  ?t::net @WIRE {?t %g:p};
  {?t %g:p} @ALIGN("x");
  %g:p ?t @DISTANCE("bottom-to-top", exact=?gap)
};
%c1 = #M1:3(a) #M2:3(b) #M5:1(t) @AS $TAIL_MID;
#R1(source) {#R2 #R3}(series) #R4(load) @AS $CHAIN_ROW;
# @SELECT-TERMINAL(net="vss", wired=false) => $GND_BELOW @ATTACH(gap=3)
```

- 普通定义由角色表、参数表和定义体组成。体内用 `?name` 引用角色和参数（6.10）。定义做什么由它的内容决定，见 9.5。
- **套用**：AS 和 ATTACH 把对象填进定义的角色，产生一个用例。两个关键字做同一件事，只是定义写的位置不同：
  - AS 的定义写在最后，读作"这些对象，作为某某"，用于语义和摆法，如 `#M1(in_p) #M2(in_n) @AS $DIFFPAIR`；
  - ATTACH 的定义写在最前，在写出的对象之前，标准写法把关键字放在定义后面，如 `$GND @ATTACH &vss`；读作"某某，添在这些对象上"，用于虚拟元件和补位（第 12 章、10.5）。
  - 挑了另一个关键字不算错，只是读着别扭；定义写错位置才是错误（4.2 第 7 条）。管道送来的对象直接按角色配位，两个关键字写出来一样；这时照定义的用途挑。
  - 怎样挑：对象合起来构成这个东西时用 AS，如电路结构、摆法、由这几个对象组成的局部画法；这个东西添在对象上时用 ATTACH，如地、端口符号、无连接标记、汇合圆点、每个元件一个的标签、补位。标准例句分别是 `#M1(in_p) and #M2(in_n) are treated @AS $DIFFPAIR` 和 `$GND is @ATTACH to &vss`（4.5）。
- **角色表**：参数 `roles`，是一个数组，每项是角色名，或 `[name, kind]` 对。DEFINE 的两个参数都只能写名字。
  - 写成 `"{name}"` 的项是集合角色，整个收下一个集合；其余是单个角色（5.2.1 第 4 条）。
  - 集合角色收到单个对象，当作只有它的集合；收到空集合也合法，体里成员不够的约束自然成立（第 14 章）。
  - 单个角色收到集合，就对每个成员各套用一次，空集合就是零次；一次套用里至多一个单个角色可以收到多成员的集合（否则语句失效，5.2.1）。
  - 集合角色的 `?name` 写在 `{…}` 里时，集合打散一层，所以上例的 ORDER 排的是 R1、R2、R3 和 R4。
  - 集合角色收到含集合成员的集合时原样收下，由体决定怎样用。
  - 集合角色不对应端子（6.4）。
  - 一次套用里每个角色只能标一次；要给集合角色多个对象，就写成集合，如上例的 `{#R2 #R3}(series)`。
  - **种类**：写成 `[name, kind]` 的项声明这个角色收哪种对象；只写名字的项收任何种类。种类名就是词表里的（5.3）：`"instance"`、`"terminal"`、`"net"`、`"point"`、`"wire"`、`"usage"`、`"bundle"`、`"text"`、`"annotation"` 和 `"label"`。在角色声明里，`"instance"` 也收叠画，`"terminal"` 也收叠画的端子（11.8）；写成数组表示几种之一，如 `["p", ["net", "terminal"]]`。集合角色的种类管它的每个成员，如 `["{members}", "instance"]`。没有"某个定义的用例"这一种。
  - 角色收到的对象种类不对时，整个套用失效，诊断写明哪个角色、要什么、收到了什么；集合角色里有一个成员种类不对也一样。选择逐个产生套用时，只有收错对象的那一次套用失效。
  - 注：语义定义的体是空的，角色填错了不会有语句失效，只有声明了种类才查得出来。声明了种类，体里对角色的用法也能在定义处检查（6.9）。
  - **可选的角色与个数**：单个角色应填上；集合角色可以不填，不填就是空集合。按顺序给出对象而对象少于角色时，剩下的角色应都是集合角色；给对象标角色时，没写的集合角色是空集合。没有最少、最多个数：成员不够的约束自然成立（第 14 章）。形状不同的变体写成另一个定义（见下面的派生与扩充）。同一对象填两个角色、期望的连接这类合法性规则，见 9.5。
- **参数表**：参数 `parameters`，可以不写。每项是参数名，或 `[name, default]`。
  - 参数在 AS、ATTACH 的括号里传入，如 `$GND_BELOW @ATTACH(gap=3)`，按参数表的顺序按位置写，或写名字；两种都用时，按位置的在前（4.2 第 9 条）。标准写法写名字（4.3）。名字不在参数表里，这次套用失效。选择逐个产生套用时，每次套用都用同一组参数。
  - 体里能写字面量的地方都能改写参数的空位：参数的值、数组的元素、点的坐标。所以在定义体里，"参数里只放字面量"（4.1）这条规则成了"字面量或参数的空位"；展开后它们仍是字面量。AS、ATTACH 自己的参数只能是字面量，不能传对象；对象经角色传入。
  - 没传、也没有默认值的参数，在用到它的地方当作没写：作具名的参数时就是没写这个参数，如 `@TEXT(?label, size=?size)` 里的 `size=?size`，这时文字用 TEXT 自己的默认字号或它的样式的字号（11.3）；作点的坐标时就是 `_`；写在按位置的参数里或数组的元素里没有确定含义，那条语句失效。所以不需要"必填"标记。
  - 参数用于数值、文字这类量；结构不同的变体建议写成独立的定义，语言不强制这一点。参数只传进体里；不能按参数的值选择用例。
- 角色名和参数名在同一张表里，应各不相同；它们都不能是标准子对象名（6.5）。参数不能叫 `priority`，它是 AS 和 ATTACH 的标准参数（14.8）。
- 体内绑定的 `%` 名字是局部名：每次套用都为它们生成新的对象，从外面经用例引用（见下）。几次套用共用的对象，如对称轴，经角色传入。
- 套用可以给对象标角色（`#M1(a) #M2(b) … @AS $T`、`$T @ATTACH #M1(a) #M2(b) …`），也可以按角色表的顺序给出对象（`#M1 #M2 … @AS $T`）。单个角色没填，或给的对象多于角色时，整条语句失效；没填的集合角色是空集合。
- 一次套用产生一个用例，它记下定义和每个角色填了什么，可以命名（如 `%c1`）。删掉这条语句，展开出的描述也一起消失。用例没有键：每次套用都是一个单独的对象（5.8）。
- **展开**：
  - 空位换成实参和参数值；
  - 局部名换成新句柄"用例 + 局部名"，写作 `%c1::mid`；匿名的用例在诊断里按语句的位置显示；
  - 体外的名字不在套用处重新解析（6.9）；
  - 展开的结果在 AS 或 ATTACH 语句的位置提交，冲突取舍时也取这个位置（8.5）。
- 嵌套的用例逐层往下取（`%c1::inner::mid`）。用例也可以填进别的定义的角色：`#M1(in_p) #M2(in_n) @AS $DIFFPAIR => #M5 @AS $INPUT_STAGE` 是一个输入级，它的角色 pair 填的是差分对的用例（5.5）。
- **循环套用**：展开中的一次套用，若直接或经别的定义套用了某个外围用例正在展开的定义，就闭合了一个循环。这次套用失效，诊断列出整条链；其余照常生效。下例把 `$A` 套用到 M1 时展开 `$B`，其中对 `$A` 的套用闭合了循环 `$A → $B → $A`，失效；`$B` 里的 ORIENT 照样把 M1 翻转：

  ```rnl error
  $A = @DEFINE(roles=["x"]) {?x @AS $B};
  $B = @DEFINE(roles=["x"]) {
    ?x @AS $A;               /* closes the cycle $A → $B → $A: this application fails */
    ?x @ORIENT("MY")
  };
  #M1 @AS $A
  ```

- **从外面引用局部对象**：

  ```rnl use=gdef
  $DP_BLOCK = @DEFINE(roles=["in_p", "in_n"]) {
    %pair = {?in_p ?in_n} @GROUP
  };
  %dp1 = #M1(in_p) #M2(in_n) @AS $DP_BLOCK;
  %c1::mid @PLACE(x=20);              /* moves the midpoint of c1 */
  {%c1::mid #M9:1} @ALIGN("x");       /* aligns the drain of M9 with the midpoint of c1 */
  %dp1::pair @PRIORITY("disabled")    /* turns off only the group expanded for dp1 */
  ```

  - 体里每个起了名的局部对象，都能经用例从外面引用，写作 `usage::local_name`；没起名的够不着。起不起名由定义的作者选择，与"要引用就命名"（5.7）一样；不另设导出表。
  - 路径可以连写：`%st1::dp::mid` 是 st1 体里的局部用例 dp 的 mid。经角色走也一样：`%st1::pair::mid` 是填进角色 pair 的那个用例的 mid。
  - 它们是普通的引用：可以加事实（PLACE、SET-STYLE、TEXT、PRIORITY 等），可以用在别的语句里，可以填进别的定义的角色；与展开出的事实冲突时按 8.5 取舍。不能从外面给局部名重新绑定：`%c1::mid = …` 是错误。
  - 名字：经 `::` 从一个用例取到的名字应唯一。所以局部名不能与角色名或标准子对象名相同，这在定义处检查；用例上文字的引用名也不能与这些名字中的任何一个相同（6.5、13.3）。局部名可以与参数名相同：参数是值，`::` 不取值。
  - 优先级：从外面直接写在局部对象上的 PRIORITY 语句，盖过用例的优先级（14.8）。
  - 够不着的：匿名用例的局部对象，以及选择逐个生成的用例的局部对象。以用例为范围的选择仍只选它的角色成员，不选局部对象（10.1）：局部对象只能按名字引用，包里的规则看不到定义内部。
  - 所以局部名是定义的接口的一部分：定义改了局部名，外面的引用就找不到它，失效（第 7 章），求解结果随之过时，并给提示建议重新求解（第 17 章）。标准包写明它的定义中哪些局部名可以依赖。
- **体内的写法**：角色和参数写 `?name`，局部名写 `%name`（6.9、6.10）。
- **派生与扩充**：只用组合，没有继承关系（9.1）。派生定义的体里套用基础定义，再加自己的语句：

  ```rnl
  $FILTER = @DEFINE(roles=["in", "out"]) {};
  $LOWPASS = @DEFINE(roles=["in", "out", "r", "c"]) {
    %f = ?in(in) ?out(out) @AS $FILTER;
    {?r ?c} @ORDER("x")
  }
  ```

  - 增加内容靠体里的语句，数值上的变体靠参数；要在下层遮蔽并扩充一个定义，体里引用外层的同名定义（6.9）。
  - 按基础定义选择不需要特别的规则：派生定义展开出的 FILTER 用例本来就在场景里，所以 `# @SELECT-USAGE $FILTER` 选得到它，按 `$FILTER` 写的规则对低通滤波器同样起作用，只作用在里面那个 FILTER 用例上，不作用于派生定义自己加的语句。
  - 没有专门去掉基础定义一部分的机制：派生定义的体可以写 `%f::x @PRIORITY("disabled")` 关掉其中一部分，但外层用例上的优先级会盖过它（14.8）；要稳定地少一部分，就把基础定义拆小，或另写一个。

### 9.5 普通定义的用途

定义做什么由它的内容决定，不由关键字决定：

```rnl
$PAIR = @DEFINE(roles=["in_p", "in_n"]) {};                /* meaning: roles only */
$SIDE_BY_SIDE = @DEFINE(roles=["a", "b"]) {               /* layout: constraints in the body */
  {?a ?b} @ALIGN("y");
  {?a ?b} @ORDER("left-to-right")
};
$PROBE = @DEFINE(roles=["p"]) {};                          /* virtual part: a rule gives its usages a symbol (chapter 12) */
$PROBE_SYM = @DEFINE-SYMBOL {(0, 0) @PIN(terminal=1); (0, 0) @CIRCLE(radius=0.5)};
# @SELECT-USAGE $PROBE => @SET-SYMBOL $PROBE_SYM
```

标准包里的 `$DIFFPAIR`、`$MIRROR_PAIR` 和 `$GND` 分别属于这三种。

- 它们都是同一种东西：一个用例（记下套用了哪个定义、每个角色填了什么），加上定义体展开出的描述。两部分的使用者不同：
  - 体展开出的约束由求解器处理，必须满足，冲突时按 8.5 取舍；
  - 用例给人和 LLM 读，也给 RNL 自己的选择和规则用（10.1）。

  所以布局定义的用例同样带有语义；语义定义只是体为空的定义，它的含义由标准包或它的作者写明。
- 语义用例不是注释：它的引用应找得到，角色应对得上，基本合法性受检查（原则 2.4），选择和规则也能用它；不规定的只是怎样画。
- "是什么"和"怎么画"分开写，写成两个定义，分别套用。删掉布局的用例不影响语义的用例。从语义到画法这一步可以写成包里的规则，换包就换了画法：`# @SELECT-USAGE $DIFFPAIR => @AS $DP_LAYOUT`。
- **画法都写成 RNL**：语义用例不带画法。要让某种语义画成某个样子，就写一个布局定义，再用规则套用它，如上一条，可以放在包里；不要依赖渲染器对某种语义的默认约定。语义定义不带画法是写包的一种做法，本标准不另作规定。RNL 没有描述的部分怎样摆由实现决定（原则第 1 节），但那不是对某种语义的画法约定，不能依赖。渲染器决定没有描述的对象的默认符号和样式（原则 2.7），是另一回事。
- **词汇归标准包**：首批语义定义和标准虚拟元件都是标准包的内容，标准包不属于语言标准（16.3）。标准包里的定义怎样写明含义和角色，也由标准包决定。用户的定义的含义就是它的体，名字只给人读。
- **基本合法性**（原则 2.4）：定义的语法不检查两个角色是否填了同一个对象。一次套用的基本合法性是：引用找得到，角色收到的种类对，单个角色都已填上（9.4），以及展开出的每条语句自身合法。

  ```rnl error
  $DP_LAYOUT = @DEFINE(roles=[["in_p", "instance"], ["in_n", "instance"]]) {
    {?in_p ?in_n} @ALIGN("y");
    ?in_p ?in_n @DISTANCE("x", min=4)
  };
  #M1(in_p) #M1(in_n) @AS $DP_LAYOUT      /* the expanded DISTANCE asks M1 to be at least 4 from itself */
  ```

  - 上例展开出的 DISTANCE 自相矛盾：它失效并给诊断，只丢弃这一条（5.5、7.3）；ALIGN 照常成立。体为空的语义定义，如 `#M1(in_p) #M1(in_n) @AS $DIFFPAIR`，查不出这种填法，不报错。
  - 两端接在同一网络上的虚拟元件有确定的含义，所以"同一对象填两个角色"一般不能算错误。
  - 更多的检查，如要求两个角色不同，本版不提供。
- **关键字与普通定义**（1.5 第 7 条）：实现必须自己懂、用别的描述写不出来的，是关键字，如原子约束、GROUP、WIRE、TEXT、CURRENT；能写进普通定义的体的，是普通定义，如差分对、电流镜、地和电源、信号流向（14.6）。DEFINE-SYMBOL、DEFINE-STYLE、SET-SYMBOL、SET-STYLE 也是关键字：符号体用局部坐标，在定义处求值；样式的属性是字面量；SET-SYMBOL、SET-STYLE 给已有的对象设一个属性，在全部对象都齐了以后在队列里决定，而 AS、ATTACH 每次产生一个新对象。
- 定义按它的名字解析到的定义认，不按名字字符串：下层自己定义了 `$DIFFPAIR`，那就是另一个定义，包里按标准的 `$DIFFPAIR` 写的规则不认它。
