## 6 名字与作用域

### 6.1 层级

- **层级按文字的包含关系。** 一个层的 RNL 作用于本层，以及它在文字上包含的各层；谁实例化谁不起作用。
  - 文件包含它定义的子电路和它 include 的文件。
  - 写在子电路里的 `.include`，和嵌套在子电路里的 `.subckt` 定义（SPICE3、ngspice 的局部定义），挂在那个子电路下面。
- 从上往下，到一个子电路的层级链是：根上的包（标准包，以及头段记录里 USE-PACKAGE 的包，16.3）→ 主文件的文件层 → ……（逐级 include 的文件）→ 定义这个子电路的文件 → 子电路自己。例如：

  ```text
  packages at the root (the standard package)
  └─ file level of tb.sp (the top level)
     ├─ load                    a subcircuit defined in tb.sp
     ├─ file level of ota.sp    a file included by tb.sp
     │  ├─ ota                  ota instantiates cell
     │  └─ cell
     └─ file level of bias.sp
        └─ bias                 also instantiates cell, but neither the RNL of bias.sp nor that of bias reaches cell
  ```

- **子电路的 RNL 只管它自己。** 取舍时它的语句排在各文件层的内容之后，因而优先于它们（8.5）；但不传给它实例化的子电路，嵌套定义在它里面的除外。amp 实例化了 cell，amp 的定义和规则到不了 cell。
- **被 include 的文件影响不到 include 它的层。** 它的文件层的定义、规则、USE-PACKAGE 只作用于它的子电路和它再 include 的文件。从网表看，它写在子电路之外的器件属于 include 它的那一层，但它的 RNL 改不到这些器件。所以一个文件不会被它 include 的文件改动。
- **被 include 的文件的文件层没有自己的电路。** 只有主文件的文件层是电路。被 include 的文件在文件层写的宿主引用（`#M1`、`&vss`）失效（6.3），在那里起作用的只有定义、规则、USE-PACKAGE 和 `scope`。单独打开的文件就是主文件。
- **被 include 的文件继承 include 它的层。** 主文件的风格（它的规则和 USE-PACKAGE 的包）一直传到库文件的子电路里。所以同一个库文件在不同的主文件下，或单独打开时，可能画得不同，而它的求解结果只存一份（第 17 章）。要让库里用到的符号不受上层外观规则的影响，在库文件或子电路里用 USE-PACKAGE 再用一次标准包（16.2）。只想钉住标准包的版本、仍让上层的风格盖过它，就把 USE-PACKAGE 写在库文件的头段记录里（16.3）。主文件里只该作用于顶层的规则，写 `recursive=false`（10.1）。
- **一个子电路一张图。** 查看器不展开子电路：子电路的元件总是用它的符号画，子电路内部单独画、单独求解。每个子电路只有一条上层链，所以一份文档里每个子电路恰好一张图。
- **包。** `@USE-PACKAGE` 写在哪层，包的 `$` 定义和规则就在那层及以下生效（16.2）。标准包隐式用在根上，头段记录里 USE-PACKAGE 的包也放在根上（16.3）。include 把文件放在本层下面，文件继承本层；USE-PACKAGE 把包放在本层上面，本层继承包。
- **规则按定义对待。** 写在某层的规则在该层和下面每一层各求一次，每次只看那一层（10.4）。选择加 `recursive=false` 就只在写规则的那一层选，规则实际上只作用于这一层。这正是原则 2.5 对定义的要求：定义能把自己的生效范围限定在当前层，或让下层继承，未限定时默认继承。原则 2.5 说只属于所在层的描述，指逐个对象写的语句，它们的宿主引用本来就只在本层解析。

### 6.2 前缀

| 前缀 | 指什么 | 在哪里解析 |
|---|---|---|
| `#` | 宿主的元件；单独的 `#` 是本层 | 本层的宿主 |
| `&` | 宿主的网络 | 本层的宿主 |
| `%` | 在本层起的名字：场景对象的，已有对象的（如 `%tail = #M5`），或只在本层用的定义的 | 本层 |
| `$` | 定义，或集合（6.6） | 绑定它的层及其下层 |
| `?` | 定义的角色或参数；符号体里单独的 `?` 是用这个符号画出的对象（13.3） | 普通定义或符号的定义体 |

`$X` 与 `%X` 是两个不同的名字。

### 6.3 宿主引用

- `#M1`、`&vss` 只在本层的宿主里解析，不跨层（原则 2.5）。不同子电路里的同名元件互不相关。
- 找不到的宿主引用失效（原则 2.4）。被 include 的文件的文件层没有自己的电路，所以那里的宿主引用都失效（6.1）。
- 名字后面可以紧跟下标，表示一个或一组宿主名字，如 `&D<3>`、`#XI0<3:0>`（6.11）。
- 某一层有哪些网络，由宿主适配器按宿主的语义决定：
  - 局部网络：这一层的网表行用到的结点，含端口。
  - 全局网络：`0` 在各种 SPICE 方言里都是全局地。仿真器自己认的地的别名（如 ngspice 的 `gnd`，HSPICE 的 `GND`、`GND!`、`!GND`、`GROUND`）由这种方言的适配器并到 `0`；并入后 `&gnd` 与 `&0` 是同一个句柄。`.GLOBAL vdd`（Spectre 写 `global vdd`）声明的名字，在任何子电路里都是同一个结点。名字以 `!` 结尾（如 `vdd!`）是 Virtuoso 原理图的习惯，起作用的是声明。
  - 全局网络在用到它的每一层各有一个句柄，即这一层里的那一份；网表行没有用到它的层没有这一份。所以 `&0` 指写它的那一层的那一份：每张图各画各的，事实属于那一层，下层的描述改不到上层。
  - 要指每一层里的那个全局网络，在上层按名字选，加条件 `global=true`（10.1）。

### 6.4 端子

- `object:terminal` 是端子：`#M1:1`、`#M1:d`、`#XU1:inp`、`%g0:p`。`#:inp` 是本层的端口 inp。
- 数字是宿主的端子序号，从 1 起。
- 名字是宿主的端子名：头段记录里 `@DEVICE` 给的名字（6.12），或子电路的端口名。不能不加引号写的名字（3.6）要加引号，如 `#XU1:"in+"`。端子名、端口名后面可以紧跟下标，如 `#X1:D<7:0>`、`#:D<7:0>`（6.11）。
- 大小写：子电路的端口名和 DEVICE 给的端子名都按宿主的规则：SPICE 不分大小写，`#M1:D` 也行；Spectre 区分。用例的端子名是它的定义的角色表里的名字，按 RNL 名字的规则（3.6）。
- 引脚的 `label=` 只用于显示，不能用来引用端子：端子属于网表，引用端子不取决于用的是哪个符号。
- 用例的端子就是它的定义的角色，按角色表的顺序编号；集合角色不是端子（9.4）。只有带符号的用例，它的端子才有引脚、能接导线（第 12 章）。
- 找不到的端子失效。端子在符号里有没有引脚，在定了符号之后检查（7.1）。
- 除了子电路的端口名，端子名由 DEVICE 给出；SPICE 系的标准名字见 6.12。
- 网表里没有定义的子电路（如 `XM1 … sky130_fd_pr__nfet_01v8` 里的 PDK 器件），只有用户在头段记录里用 DEVICE 给出端子名（6.12），或用了写有 DEVICE 语句的包（16.2）时，才有端子名；否则只能写序号。

### 6.5 子对象

- `object::name` 是子对象。它总是对象，不是数值。它的句柄是父对象和名字。
- 子对象有：
  - 文字的引用名：写了 `key=` 的 TEXT 在它附着的对象上产生的子对象，如 `#M1::wl`。符号里写了引用名的文字，是用这个符号画出的每个对象的子对象（13.3）。`::name`、`::value` 不是标准子对象，只是常用的引用名（13.3）。
  - `::position`：对象的原点。`#M1::position @PLACE(…)` 等于 `#M1 @PLACE(…)`。对画出来的用例，它是画这个用例的那个点：主对象有坐标点时就是那个点，否则是用例自己的原点（12.1）。对 TEXT，它是文字自己的位置（13.3）；对中心写法的 RECTANGLE、CIRCLE、ELLIPSE，它是中心（13.4）。
  - 端子的 `::net`：它所在的网络，如 `#M5:1::net` 就是 `&tail`。叠画的端子见 11.8：成员接在不同网络上时，是这些网络的集合。
  - 用例的角色名：填进这个角色的对象，如 `%dp1::in_p` 是 M1，`%g0::p` 是网络 vss。集合角色取到的是那个集合。
  - 用例体里起了名的局部对象，如 `%c1::mid`（9.4）。
  - 集合的 `::position`：成员所占范围的中点，按每个成员的那一点（原点、引脚或点）算；嵌套的集合一直取到最里层的对象，与符号无关。`%pair_set::position @PLACE(10, 20)` 把 pair_set 的中心放在 (10, 20)。集合的范围没有子对象：要让两组分开，写 DISTANCE（14.5）；要把一组作为约束的一个成员，写成 `{%x}`（14.1）。
- 标准子对象名保留：普通定义的角色名、参数名、局部名，以及文字的引用名，都不能与它们相同（按原样比较，3.6）。局部名不能与角色名相同，文字的引用名也不能与它所附着的用例的角色名、局部名相同。局部名可以与参数名相同：参数是值，`::` 不取值。定义的参数也不能叫 `priority`（14.8）。
- **`::` 后面的名字按这个次序找**：用例自己的角色名和局部名；它们的 `definition=` 代称；标准子对象名和它们的代称；文字的引用名（代称见 16.5）。
  - 引用名排在最后，所以不能与排在它前面的名字拼写相同：标准子对象名和本文件声明的它们的代称（如 `rnl-zh` 的 `"位置"`）、用例的角色名和局部名，以及这些名字的 `definition=` 代称。这样的引用名是错误，与上面的重名一样（13.3）。
- `::` 只取对象自己的部分；在场景里按条件找对象，一律用选择关键字。所以"某个定义的全部用例"写成选择（10.1），不写成定义的子对象。要用例成员的范围，就给成员的集合起名。
- 端子用 `:`、子对象用 `::`，免得以后的版本新增的子对象名与网表的端口名冲突。
- **子对象名**：标准子对象名有两个，`position` 和 `net`，都保留。其余子对象名都是动态的：文字的引用名、用例的角色名、定义体里的局部名。以后的版本新增的标准子对象名按版本区分（16.1）：旧版本的文件里，同名的引用名照旧有效。

### 6.6 命名

- `%name = statement`、`$name = statement` 给语句的结果起名；管道里 `=> %name`、`=> $name` 给它们左边那一段的结果起名（5.5）。名字只是引用对象的另一种写法，不产生对象。
- `$name` 绑定定义或集合，含选择的结果。`$` 集合在某层求值时只含这一层的成员（10.3）。其他场景对象属于某一层，不能有 `$` 名字。
- `%name` 可以绑定本层的任何对象：本条语句创建的对象、已有的对象（`%tail = #M5`）、集合（`%pair_set = {#M1 #M2}`），或只在本层用的定义。
- **同一层里一个名字只绑定一次。** 再绑定同一个对象可以，如 `%x = #M1` 写两次；绑定别的对象是错误，名字保留第一个有效的绑定。只有全部绑定都失效时，名字才绑定到失效对象（7.2）。创建对象的语句、定义、集合、选择的结果都一样。
- 覆盖针对事实，不针对名字：要改 RNL 创建的对象，写修改它的语句，如 `%g0 @PLACE(40, 38)`（5.8）。

### 6.7 名字的范围

- `@RNL` 提交的名字发布到本层：本层的所有记录共享，名字可以在绑定它的语句之前使用（原则 2.9）。
- 嵌套集合里绑定的名字只在该集合内有效。
- 定义体里绑定的名字是体内局部的（6.9）。

### 6.8 继承与遮蔽

- `$` 定义沿层级（6.1）向下继承，绝不向上：进本文件的子电路，也进被 include 的文件。一个层看不到它 include 的文件里的 `$` 定义；要给上层提供定义，做成包，用 USE-PACKAGE 使用（16.2）。子电路符号是唯一向上的例外（9.2.6）。
- 下层定义了与继承来的同名的 `$X`，就在这一层及其下层遮蔽继承来的定义，并给提示；上层看到的仍是自己的。
- 一层里 USE-PACKAGE 的包，它的 `$` 定义算作这一层上面的一层（16.2）。它们遮蔽上面各层或根上的包的定义时，与任何遮蔽一样给提示。头段记录里使用的包定义了标准包里的名字，或排在它前面、放在根上的包里的名字时，也给提示（16.3）。
- `%` 名字只在本层有效，不继承：不进本文件的子电路，也不跨 include。包里的 `%` 定义是包内私有的辅助定义。

### 6.9 定义体里的名字

- 定义体里的名字在写定义的地方解析，套用处不重新解析。
- 所以遮蔽一个定义只改变这个名字指什么：别的定义内部已经用到的定义不变。例如在下层遮蔽 `$DIFFPAIR`，不会改变 `$INPUT_STAGE` 体内用到的差分对。
- 体内的 `%name` 先在体内的局部名里找，再在本层的定义里找。本层的场景对象（点、导线等）不能从体内引用，这样的引用是错误。
- **体内的写法**：角色和参数写 `?name`。局部名用 `%name =`（管道里用 `=> %name`）绑定，用 `%name` 引用。从外面经用例引用局部名（9.4）。
- 定义体看不到正在定义的名字：`$NMOS = @DEFINE-SYMBOL {$NMOS; …}` 里，体内的 `$NMOS` 是外面（上层或包里）这个名字的定义。下层就是这样遮蔽并扩展上层定义的；外面没有这样的定义时是错误。
- DEFINE-SYMBOL、DEFINE 体里的宿主引用是错误：`#M1`、`&vss`、`#:inp`、`#M1:d` 和单独的 `#` 都不能写在那里。体里的名字在写定义的地方解析，普通定义却会在别的层、别的文件里套用，在那里宿主引用仍会指到定义所在的那一层，含义不唯一。普通定义要用宿主对象，经角色传进来。
- **普通定义的体什么时候检查**：
  - 按定义查一次：不依赖实参的都在这时查，包括关键字、签名（对象个数、参数名和类型）、`$` 和 `%` 名字（在写定义的地方解析）、宿主引用、局部名的撞名（9.4），以及声明了种类的角色用得对不对：角色 t 声明为 `"instance"` 时，体里写 `?t::net` 是错误。签名在读入时查（7.1）；名字要整层读完才能解析，所以要用到名字的检查在本层生效时做。两者每个定义都只做一次，与套用几次无关。
  - 按套用查：依赖实参的，如没声明种类的角色收到的对象、符号里有没有那个引脚，每次套用时查，报在套用处，并指出普通定义里的原句。
  - 错误的范围：体里查出错的语句（含撞名的局部名）在定义处报一次，每次展开都不含它，体的其余部分照常（体是容错的，9.1）。角色表、参数表写错（重名、与标准子对象名撞名、不认识的种类名），整个普通定义失效，用到它的套用也都随之失效。
  - 从没被套用的普通定义也查。这些检查与套用无关，所以能查出包里没用到的定义的错误。

### 6.10 空位

- `?name` 只出现在普通定义的体里，名字应在角色表或参数表里；否则读入时就是错误。
- 写在对象的位置是角色，如 `?t`、`?t::net`；写在字面量的位置是参数，如 `min=?gap`、`[?w, 2]`、`(?x, 0)`（9.4）。角色写在字面量的位置，或参数写在对象的位置，读入时就是错误。角色名和参数名在同一张表里，不能重名。
- 角色的空位可以带路径，如 `?t::net`；参数的空位不带路径。

### 6.11 下标

| 写法 | 表示 |
|---|---|
| `&D<3>` | 与 `&"D<3>"` 相同 |
| `&D<7:0>` | 一组：`D<7>`、`D<6>`、…、`D<0>` |
| `&D<1,2:3>` | `D<1>`、`D<2>`、`D<3>` |
| `&D<0:6:2, 9>` | `D<0>`、`D<2>`、`D<4>`、`D<6>`、`D<9>` |
| `&D[3:0]` | `D[3]`、`D[2]`、`D[1]`、`D[0]` |
| `#XI0<3:0>` | 四个元件 |
| `#X1:D<7:0>` | X1 的八个端子 |
| `#:D<7:0>` | 本层的八个端口 |
| `&"D"<1:0>` | `D<1>`、`D<0>` |
| `&"D<7:0>"` | 名字就叫 `D<7:0>` 的结点：引号里的不解析 |

- 网表里没有总线：Virtuoso 等工具出网表时把总线拆成单个的位，如 Spectre 网表里的 `D\<3\>`；子电路的总线端口、叠合元件也拆开。下标是写一个或一组这类名字的简写。它只是拼名字，不靠宿主认总线，所以含义唯一。
- **写法**：宿主名字（加不加引号都行）后面紧跟 `<…>` 或 `[…]`，里面是用 `,` 分开的若干项。每项是 `i`、`a:b` 或 `a:b:s`，几种可以混写。i、a、b、s 都是不带符号的十进制整数，s 至少为 1。名字与括号之间没有空白；括号里可以有空白和注释（3.5）。
- **展开**：各项按写的次序展开、拼接，重复的照留。`a:b` 从 a 到 b，`a:b:s` 每次走 s，不越过 b：`<7:0>` 是 7、6、…、0，`<0:7:2>` 是 0、2、4、6。步长写在最后，与 Virtuoso、Xschem 相同，与 MATLAB 的 `a:s:b` 不同。生成的名字是括号前的名字、左括号、不带前导零的十进制数和右括号，括号照写的那一种：`&D<07>` 是 `D<7>`，`&D[3]` 是 `D[3]`。
- **一个还是一组**：只有一项且是单个数时，是一个引用：`&D<3>` 就是 `&"D<3>"`。否则是一组，即对一个集合的引用，如 `&D<3:3>`、`&D<3,5>`。一组放进集合时打散一层（5.2）；作语句唯一的对象时先拆一层（5.2.1），所以 `#XI0<3:0> @ALIGN("y")` 对齐四个元件；放在要单个对象的槽位时逐个成员做；放在 WIRE 的网络槽位时整个收下，是一根总线（13.1）。
- **用在哪里**：`#`、`&` 之后的宿主名字，以及 `#` 引用里的端子名、端口名。RNL 名字（`%`、`$`、`?` 之后的）、用例的端子名（即定义的角色名）和子对象名不收下标，后面紧跟 `<`、`[` 是错误。
- **名字后面不能直接写点**：名字后紧跟的 `<`、`[` 一律开始一个下标，后面不合写法就是语法错误，不会读成点。要在名字后面写点，就隔开，如 `&D (1, 2)`。
- **一处展开**：一个名字后面至多一个下标，所以 `A<1>[2]` 这样的名字加引号写，`&"A<1>[2]"`。一个引用里至多一处下标展开成一组：`#XI0<3:0>:a`、`#X1:D<7:0>` 可以，`#XI0<1:0>:D<1:0>` 是错误；两处都是单个数的可以，如 `#XI0<3>:D<1>`。展开成一组的引用后面接 `::` 时，对每个成员各取子对象，如 `#XI0<3:0>::name`。
- **引号里的不解析**：`&"D<7:0>"` 指名字就叫 `D<7:0>` 的结点；`&"D"<7:0>` 才展开。网表里的名字含有不表示总线位的 `<`、`[` 时，加引号照原样引用。
- **比的是适配器读出的名字**（3.6）：Spectre 网表里的 `D\<7\>`（反斜杠是 Spectre 的转义）由适配器读成 `D<7>`，所以 `&D<7>` 能引用它。
- 每个成员各自解析。找不到的成员是失效对象，按收它的槽位的规定严格或容错处理（7.3）。
- 参数里的字符串不展开，如 PIN 的 `terminal=`（9.2.4）、选择的条件 `name=`。
- 不收：Virtuoso 的重复 `<*2>A`、`A<0:2*2>` 和并列 `A,B`（集合已经能写）；KiCad、Xschem 的 `D[0..7]`，它的成员是不带括号的 D0 … D7。
- 叠合元件（如 Virtuoso 的 `I0<3:0>`：几个宿主元件画成一个）写成叠画：`#XI0<3:0> @BUNDLE`（11.8）。

### 6.12 端子名：DEVICE

```spice
* sky130 transistors, defined in the PDK and not in this netlist
* @RNL(type="header") {
*   @VERSION("0.2");
*   @DEVICE(name="X*", model="sky130_fd_pr__nfet_*", terminals=["d", "g", "s", "b"]);
*   @DEVICE(name="X*", model="sky130_fd_pr__pfet_*", terminals=["d", "g", "s", "b"])
* }
XM1 out in 0 0 sky130_fd_pr__nfet_01v8 w=1 l=0.15
XM2 out in vdd vdd sky130_fd_pr__pfet_01v8 w=2 l=0.15
* @RNL { #XM1:d @CURRENT("in") /* XM1 is a sky130 NMOS; its terminal 1 is named d */}
.end
```

- **端子名由 RNL 起。** `@DEVICE` 给一类器件的端子起名：`terminals` 按网表行上结点的顺序列出名字。它只给宿主的端子序号起名，不改端子的顺序，也不改子电路的接口；它是原则 2.2 允许的显示别名。
- **只写在头段记录里**（2.8）：DEVICE 写在别处是错误。包文件的头段记录也算（16.2）。内嵌的包里不能写 DEVICE，要写在文件的头段记录里。
- **匹配**：`name` 比元件名，可以用通配符 `*`（任意多个字符）。`model` 可以不写；它比元件行上写的模型名或子电路名（Spectre 里是元件的 master，原生器件如 `resistor`），也可以用 `*`。两项都按宿主的大小写规则比，两项都对上，DEVICE 才与元件匹配。选择条件里比名字的条件也收 `*`，规则相同（10.1）。
- **几条都匹配时后写的生效**：适配器的默认在最前，然后是这一层用到的包里的 DEVICE 语句（按包的排序位置，16.2），再是外层文件的头段记录里的，再是被 include 的文件的；同一条头段记录里按写的先后。所以文件自己写的盖过它的包，包盖过适配器；具体的语句建议写在通用的后面。所有包的 DEVICE 语句都排在各文件的之前，不论它们的 USE-PACKAGE 写在哪里：头段记录总在文件最前面，要是按 USE-PACKAGE 的位置排包，包反倒会盖过文件自己写的。写了 `model` 的 DEVICE 不算更具体，不另设特异性规则。
- **范围**：文件的头段记录里的 DEVICE，作用于这个文件和它 include 的文件；被 include 的文件只能改它自己和它再 include 的文件（6.1）。包文件的头段记录里的 DEVICE，作用于用到这个包的各层（16.2）。例如一个 sky130 的包可以写 DEVICE 语句、符号和选符号的规则，用户写一条 `@USE-PACKAGE(name="sky130-rnl")` 就既有端子名又有符号。
- **适配器的默认**：每种方言的标准元件定义，算作写在最外层。不用写进文件，工具也可以把它们写出来。同一种方言的工具应给出相同的定义。SPICE 系：

  ```rnl header
  @DEVICE(name="M*", terminals=["d", "g", "s", "b"]);
  @DEVICE(name="Q*", terminals=["c", "b", "e", "s"]);
  @DEVICE(name="J*", terminals=["d", "g", "s"]);
  @DEVICE(name="D*", terminals=["a", "k"]);
  @DEVICE(name="R*", terminals=["p", "n"]);             /* and one each like it for C, L, V, I, B, F, H, W */
  @DEVICE(name="E*", terminals=["p", "n", "cp", "cn"])   /* and one each like it for G, S */
  ```

  Spectre 的元件名不以元件字母开头，所以按 `model` 认：原生器件写 `@DEVICE(name="*", model="resistor", terminals=["p", "n"])` 之类；模型卡里的模型，由适配器按模型的类型逐个给出名字。本版不列 Spectre 的表。
- **网表里有定义的子电路**（含 include、lib 进来的库文件里的）：端口名照定义，这是宿主的事实（原则 2.2）。DEVICE 不改它们；与这样的元件匹配而名字不同的 DEVICE 给警告。DEVICE 只给没有端子名的器件起名：原生器件，以及网表里没有定义的子电路（PDK 器件），后者由用户或 LLM 写 DEVICE。
- **名字的个数**：元件的结点比 `terminals` 的名字多时，多出的端子只有序号；比它少时，引用多出的名字失效。
- **大小写**：DEVICE 给的端子名按宿主的规则比（6.4）。
- 序号总能用，子电路的端口名和 `#:port` 也一样。
