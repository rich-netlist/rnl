## 1 概述

### 1.1 范围

RNL（Rich Netlist）写在宿主网表的注释里。它描述网表定义的电路怎样理解、怎样呈现为原理图：用哪些符号，元件放在哪里，元件的朝向、对齐、连线、标注和样式怎样，几个元件合起来是什么意思（原则第 1 节）。

器件、类型、参数、连接和子电路接口只由宿主网表定义。RNL 引用它们，不能改变它们。RNL 也不校验绘图暗示的电气含义（原则 2.2）。

本标准定义：

- 怎样从宿主网表的注释里取出 RNL（第 2 章）；
- RNL 文本的词法和文法（第 3、4 章）；
- 文本描述什么对象，名字怎样解析，失效怎样处理，各条描述怎样合在一起生效（第 5–8 章）；
- 各类描述的词汇（第 9–17 章）；
- 标准词表，与本文一起发布，即 `rnl-words-0.2.json`（5.3、附录 A）。

本标准不规定布局算法和唯一的渲染结果（原则第 1 节），也不规定宿主网表怎样解析（原则 2.1）。标准包 `rnl-std` 和 `rnl-zh` 这类代称包是用 RNL 写的；本标准规定包怎样起作用（16.2、16.3、16.5），包的内容另行发布。

本文定义语言的 0.2 版。0.x 各版本之间不承诺兼容（16.1）。

### 1.2 本标准的结构

本标准由一个抽象模型和一种文本语法组成。抽象模型是对象、事实、消费方式和生效阶段（第 5–8 章）；文本语法是它的书写形式（第 2–4 章）。工具之间交换的是文本。

附录 A 列出各关键字的签名，由标准词表生成，是规范性的。附录 B 给出标准例句，附录 C 列出留给以后版本的内容，两者都是说明性的。注和例子是说明性的。其余都是规范性的。

### 1.3 一瞥

```spice
* Five-transistor OTA, input stage
* @RNL(type="header") { @VERSION("0.2")}
.subckt ota5t inp inn out vdd vss vbias
M1 x    inp   tail vss nch W=2u L=0.5u
M2 out  inn   tail vss nch W=2u L=0.5u
M5 tail vbias vss  vss nch W=4u L=1u
* @RNL {
*   %dp1 = #M1(in_p) and #M2(in_n) treated @AS $DIFFPAIR;
*   {#M1 #M2} @ALIGN("y"), i.e., same y;
*   #M5 is at @PLACE(20, 6) => it @ORIENT("R0");
*   %g0 = $GND is @ATTACH to &vss;
*   net &vss has a @WIRE connecting {#M5:3 %g0:p}
* }
.ends ota5t
.end
```

- `* ` 开始一行 SPICE 注释。`@RNL {…}` 是一条记录，花括号里是用 `;` 分开的成员（第 2 章）。文件开头的头段记录声明语言版本（16.1）。
- `#M1`、`&vss`、`#M5:3` 引用宿主的元件、网络和端子。`%dp1`、`%g0` 是本层的 RNL 名字。`$DIFFPAIR`、`$GND` 是标准包（16.3）里的普通定义（9.4）。`%g0` 是套用 `$GND` 得到的用例，标准包给它配了地符号，所以画成一个地（第 12 章）。
- `@AS`、`@ALIGN`、`@PLACE`、`@ORIENT`、`@ATTACH`、`@WIRE` 是关键字。参数写在紧贴关键字的括号里，只放字面量。AS 把写在它前面的对象填进写在它后面的那个定义的角色；ATTACH 把写在它前面的定义添在写在它后面的对象上（9.4、第 12 章）。
- `(in_p)` 标出角色。`%dp1 =` 给语句的结果起名。`=>` 把一段的结果交给下一段；后面只跟一个名字时，给前一段的结果起名（5.5）。
- `and`、`treated`、`, i.e., same y`、`is at`、`it`、`is … to`、`net`、`has a … connecting` 是自由文本，不改变含义（3.3）。标准例句在记号之间加这类词，让语句读起来像句子（4.5、附录 B）。去掉它们，这条记录就是：

```rnl
%dp1 = #M1(in_p) #M2(in_n) @AS $DIFFPAIR;
{#M1 #M2} @ALIGN("y");
#M5 @PLACE(20, 6) => @ORIENT("R0");
%g0 = $GND @ATTACH &vss;
&vss @WIRE {#M5:3 %g0:p}
```

### 1.4 术语与约定

#### 1.4.1 规范用语

- **应**（需要强调时写**必须**）、**不应**：对文件或实现的要求。
- **建议**、**建议不要**：推荐的做法；也可能有理由不这样做，建议先弄清这些理由。
- **可以**：允许的事。

语言本身的含义用陈述句写："语句失效""后写的生效"。

#### 1.4.2 失效与诊断

- **失效**的条目（字段、语句、记录或文件；7.6）不起作用；失效的语句以失效对象为值（7.2）。每一处失效都是**错误**，不论原因是什么（7.6）。
- **警告**标出合法、照常生效、但可能不是作者本意的条目。**提示**标出常见的覆盖、遮蔽或取舍，它们也可能是写错了。具体情况列在 7.6；本标准说某处给警告或提示的地方，建议实现把它报告出来。
- **解释失败**时，什么都不画，并报错（1.5 第 3 条、7.6）。

#### 1.4.3 写法

- 正文里关键字写大写的名字，不带 `@`：PLACE、SET-SYMBOL。写语法和例子时带 `@`。
- 标准词、名字和字面量用代码字体写：`priority`、`"high"`、`instance`、`$GND`。
- 括号里的节号指本标准的节，如（9.4）。"原则 2.4"指 RNL 原则文档的 2.4 节，即 `rich-netlist.zh.md`；它以英文版 `rich-netlist.md` 为准。
- 例子用标准写法（4.3），不带自由文本，以自由文本为题的地方除外。标为错误的例子示范的是写错的写法。

### 1.5 核心原则

本标准的规则遵循以下几条原则。第 1–6 条细化原则 2.9；第 7 条说明词汇怎样分工。

1. **一切皆描述。** RNL 文本是一组描述。解释器先收齐全部描述，再给出结果。没有执行过程，名字可以在绑定它的语句之前使用。
2. **书写位置只作排序数据。** 描述写在哪里（所在的层和在文本里的先后）只在三处起作用：描述互相矛盾时保留后写的（几何事实先比优先级；8.3、8.4、8.5）；绘制顺序（11.6）；集合成员的次序（5.2）。此外结果与书写顺序无关。
3. **矛盾。**
   - 读不懂的描述（语法错、名字找不到、种类不对等），以及自相矛盾的描述，失效（原则 2.4、2.9；第 7 章）。
   - 能读懂但互相矛盾的描述，在本标准给出确定办法的地方按办法取舍，如按键覆盖（8.4）、外观队列（8.3）和几何事实的取舍（8.5）；可以给提示。
   - 暂时还没有确定办法的，整个解释失败（7.6）。这类情况很少。以后的版本可以定出办法，改为容错；现在能用的文件不受影响。
4. **每条描述看到的是生效前的状态。** 一条描述读到的是它所在阶段开始时的状态；它自己的效果和同一阶段其他描述的效果都不在内（8.2）。
5. **对象与名字。** 每条带关键字的语句和每个 `{…}` 都产生一个新对象，由句柄和事实组成。引用不产生对象。名字只是指向一个对象，在一层里只绑定一次。覆盖针对事实，不针对名字（5.1、6.6）。
6. **不为可读性限制写法。** 难读、但含义确定的写法照常允许，由作者自己克制。只有没有确定含义的写法才是错误。
7. **关键字与定义。** 实现必须自己懂、用别的描述写不出来的，是关键字。能用已有描述写进普通定义的体里的，是定义，它的名字只作提示（9.5）。

### 1.6 一致性

**文件。** 一份宿主网表的记录，按第 2–4 章读、按第 5–17 章解释，不出错误（7.6），包括它使用的包的内容里的错误，这份网表就符合 RNL 0.2。警告和提示不影响一致性。包文件单独检查时（16.2）同样判断。头段记录声明了别的语言版本的文件，不受本版本约束（16.1）。

**实现**指解释器（只用来检查的解释器也叫 lint）、查看器、求解器、编辑器以及其他读写 RNL 的工具。符合标准的实现：

1. 按第 2 章从宿主的注释里取出 RNL，按第 3、4 章读它；
2. 按第 5–17 章给每条描述应有的效果，使用标准词表里的签名（5.3）；
3. 报告每个错误，给出位置和原因（7.6）；错误不能调低，也不能关掉；
4. 建议报告本标准列出的警告和提示（7.6）；
5. 可以另加自己的检查，但只能是警告或提示：不应让本标准允许生效的条目失效，也不应让本标准规定失效的条目生效；
6. 可以提供更严的模式，停下或拒绝整份输入，但不作为默认；
7. 让用户能看到诊断；怎样呈现由实现决定（7.6）；
8. 声明自己支持哪些语言版本，对不支持的版本的文件按 16.1 处理；
9. 把不认识的关键字、参数和取值当作错误（16.4）；
10. 按 16.3 在根上使用标准包；
11. 写 RNL 时，新语句用标准写法写，不重排用户写的语句（4.3）；保存文件时写头段记录和版本（16.1）；不认识的语句、失效的语句、宿主文字、普通注释和不支持的版本的文件都原样保留（16.4）；只改第 17 章允许它改的记录。

本标准不规定求解器在满足约束的各种位置中怎样选，也不规定查看器怎样画 RNL 没有定下的部分；留给它们决定的地方在正文里写明（如 9.2.6、13.1）。

**一致性测试**查错误（连同位置和每处失效的范围）和得到的场景。警告可以作为可选的期望来查；提示不查（7.6）。
