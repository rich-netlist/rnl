## 13 走线与文字

### 13.1 导线：WIRE

```rnl id=w13
&x @WIRE(mode="straight") {#M1:1 (10, 37) #M3:1} => @SET-STYLE $signal => %w13;
&out @WIRE(mode="manhattan") {#M2:1 #M4:1};
&tail @WIRE {#M1:3 #M5:1}                    /* no mode: "auto", routed freely */
```

- WIRE 收一个网络（或网络的集合，即总线，见下）和一组有序的点，至少两个点。点可以是端子（包括虚拟元件的端子）或点对象。点可以重复；首尾两点相同时，导线是一圈。
- **走线方式**：导线经过点列里的每一个点；相邻两点之间怎样走，由参数 `mode=` 决定。设相邻两点是 A(x1, y1)、B(x2, y2)，dx = x2 − x1，dy = y2 − y1：

  | `mode` | 从 A 到 B |
  |---|---|
  | `"auto"`（默认） | 由求解器和查看器的设置决定；求解器可以按实际情况优化 |
  | `"straight"` | 一段直线 |
  | `"horizontal-vertical"` | A → (x2, y1) → B |
  | `"vertical-horizontal"` | A → (x1, y2) → B |
  | `"manhattan"` | \|dx\| ≥ \|dy\| 时，先横走 dx 的一半，竖走 dy 的全程，再横走另一半：A → (x1 + dx/2, y1) → (x1 + dx/2, y2) → B；否则横竖对调 |
  | `"manhattan45"` | \|dx\| ≥ \|dy\| 时，先横走 (\|dx\| − \|dy\|)/2，再走一段 45° 斜线（横竖各 \|dy\|），最后横走剩下的；否则横竖对调 |

  - 除 `"auto"` 外，每种走法都是严格的规则，查看器照定义画。dx 或 dy 为 0 时，每种走法都是一段直线。|dx| = |dy| 时，`"manhattan"` 按 |dx| ≥ |dy| 的情况走，`"manhattan45"` 就是一段斜线。走法算出的拐点保持确切的值，不取整，可能落在半个单位上（11.7）。
  - 走法加出的拐点不是对象：不能引用，也不能在上面放汇合点。要在拐点上接支线或画圆点，就把拐点写成点。自由点 `(_, _)` 先由求解器定坐标，再按走法连。
  - 不在表里的 `mode` 值是无效的参数值：这根导线失效。
- **样式参数**：WIRE 也收线的样式属性作参数：`linecolor`、`linestyle`、`linewidth`、`cap`、`join`（9.3）。它们是这根导线直接的样式（8.3），如电源轨写 `@WIRE(linestyle="bold")`，衬底连接写 `@WIRE(linestyle="dashed")`。
  - `"auto"` 导线的走法不写回：导线没有键，求解器也不改用户的记录（第 17 章），所以不求解的查看器按自己的设置画。要固定走法，就写出拐点，并改用 `"auto"` 以外的走法；保留确切形状的导出器写 `mode="straight"` 并列出全部拐点。
- **同一网络上的几个端子**（原则 2.6）用共用点的几根导线连接。只有共用同一个点对象（命名的点）或同一个端子，导线才接在一起；坐标相同不算（原则 2.2）。没有一句写一棵树的语句，也没有图对象。
- **T 形接头**：直通的导线把接头点列为中间的一个点，不必断成两根；支线从这个点出发（见 13.2 的例子）。没有"导线某段上的一点"。
- **引脚直接相接**：两个引脚画在同一点、中间没有导线时，也写一根导线把两个端子连上，如地符号直接画在电容的引脚上：`&0 @WIRE(mode="straight") {#C1:2 %g3:p}`。它的两端重合，长度为 0，画不出东西，但写明了连接：两个端子算接了线（10.2），标准包不会再补一个地。坐标相同本身不算接上（原则 2.2）。导出器转换靠位置相同连接引脚的原理图时，写这样的导线；导线从引脚或汇合点上直穿过去的，把那个点列为中间点（T 形接头）；汇合点只接一根导线、又正好落在引脚上的，把导线直接接到那个端子。
- **网络只是注明**，必须写。端点实际所在的网络不必与它一致，不校验（原则 2.2）；网络也不从端点推导，端点可以在不同的网络上。
  - 点列里的端子不在导线的网络上（总线导线：不在它的网络集合里）时，给警告：多半是端子写错了，如把 `#R1:2` 写成 `#R1:1`。端子的网络查得到（虚拟元件的端子在填它角色的对象的网络上）；点没有网络，不查。导线合法，照画（原则 2.2、7.6）。
- **总线**：网络槽位收一个网络，或整个收下一个网络的集合。收到集合时，这根导线是总线导线，一个成员也算。网表里没有总线（6.11）；总线只是把几个网络画成一根线的画法。

  ```spice
  * A 4-bit bus between two blocks, with two taps
  * @RNL(type="header") { @VERSION("0.2")}
  .subckt blk D<3> D<2> D<1> D<0>
  RL D<3> D<0> 1k
  * @RNL {
  *   $BLK_SYM = @DEFINE-SYMBOL {
  *     (-3, 0) @PIN(terminal=["D<3>", "D<2>", "D<1>", "D<0>"], label="D<3:0>", direction="left");
  *     @RECTANGLE {(-3, -2) (3, 2)}
  *   };
  *   # @SET-SYMBOL $BLK_SYM                                             /* one bus pin for four ports (9.2.4) */
  * }
  .ends blk
  XA D<3> D<2> D<1> D<0> blk
  XB D<3> D<2> D<1> D<0> blk
  RT3 D<3> 0 1k
  RT2 D<2> 0 1k
  * @RNL {
  *   %t3 = (20, 10); %t2 = (24, 10);
  *   %bus = &D<3:0> @WIRE(linestyle="bold") {#XA:D<3> %t3 %t2 #XB:D<3>};   /* a bus between the bus pins of XA and XB */
  *   %bus @TEXT("D<3:0>");                                                /* the name of the bus, written out */
  *   &D<3> @WIRE {%t3 #RT3:1};                                            /* a tap: a single wire that shares %t3 with the bus */
  *   &D<2> @WIRE(mode="straight") {#RT2:1 (23, 9) %t2}                    /* its last stretch enters the bus at 45° */
  * }
  .end
  ```

  - 集合的次序就是位的次序，重复的照留；直接写在集合里的集合按次序取到最里层的成员。有不是网络的成员时，这根导线失效（种类不对）。空集合也失效：导线至少带一个网络（5.2.1）。
  - 网络槽位是严格的（7.3）：有一位找不到，整根导线失效，与单个网络找不到时一样。
  - 点、`mode=`、样式参数、汇合点、T 形接头都与别的导线相同。没有 BUS 关键字：实现画总线与画导线相同，加粗是样式的事（1.5 第 7 条）。导入器可以直接写 `linestyle="bold"`；标准包用 SELECT-WIRE 的条件 `bus=true` 默认给总线导线加粗（10.1、16.3）。
  - **分接**不加机制：单根导线与总线共用一个点就是分接，总线把分接点列为中间点（T 形接头）。一小段 45° 斜线进总线，只是单根导线末段的走法。分接符号是套在分接点上的定义，归标准包（16.3）。位名是单根导线上的标签 `${net}`（13.3）。单根导线的网络在不在总线里不校验（原则 2.2）；实现可以给提示。
  - 总线导线的属性 `net` 是各网络名按次序用 `,` 连起来，不加空格，如 `D<3>,D<2>,D<1>,D<0>`；要显示 `D<3:0>`，就照写这段文字。实现不压缩这个列表：压缩取决于宿主怎样写名字，结果不唯一。
  - 所以 `{&a &b} @WIRE {…}` 是一根总线导线，不是重合的两根导线。
  - 几个宿主元件画成一个（叠合元件），写成叠画（11.8）。
- 导线接到的端子，在它的符号里必须有引脚；否则这根导线失效（9.2.4）。
- 线条接触、交叉或重叠都只是几何，不建立连接（原则 2.2）。不共用点的导线交叉时不画圆点；交叉处画小弧之类，归样式和实现。
- 每条 WIRE 是一个新对象，没有键：写两次就是两根（5.8）。要从别的语句引用一根导线，就给它起名。端点是端子的，跟着器件动；写成坐标的点不动；命名的点可以加约束。
- **没画出来的连接**：RNL 里没有导线的连接怎样呈现（求解器布线并写回成 WIRE、飞线、标签），由求解器和查看器的风格以及所用的风格包决定，语言不规定。风格包可以用规则生成标签或导线，这些是 RNL。要某个网络画成导线、走法交给求解器，写 ROUTE（13.7）。

### 13.2 汇合点

```rnl
%j1 = (10, 30);
&x @WIRE {#M1:1 %j1 #M3:1};          /* the through wire passes %j1 */
&x @WIRE {%j1 (30, 30) #M4:2};       /* the branch starts at %j1 */
$JUNCTION @ATTACH %j1                /* draws the dot */
```

- 分支就是几根导线共用一个点（13.1）。
- 汇合圆点显式写出：只在套了 `$JUNCTION` 的地方画圆点；渲染器不自己加。
- 圆点是用例，不是关键字。`$JUNCTION` 是标准包里的定义，只有一个角色，收点或端子；圆点画在这个主对象的坐标点上（12.1 第 5 条），与 `$NC`（12.6）、电流箭头（15.2）相同。引脚上接了两根导线时，可以套在端子上。标准包给这些用例指派实心圆点作符号：圆点的大小来自符号，颜色来自用例样式的 `linecolor`；圆点的大小没有单独的设置。
  - 同一个点套两次 `$JUNCTION`，就是重叠的两个圆点，看上去是一个。
  - 选出全部汇合点写 `# @SELECT-USAGE $JUNCTION`。
  - 绘制次序按指派符号的规则的位置（11.6）。标准包的规则在最前，所以圆点先画、导线后画；圆点与导线同色、比导线宽，看不出差别，不必加 LAYER。
- 圆点不按共用点上接了几根导线推导：真实的原理图里有只接两根导线也画了圆点的分支点，推导出的圆点还要另加一种去掉它的写法。导出器照原图写出圆点。共用点上接了三根以上导线却没套 `$JUNCTION` 时，实现可以给提示；本标准不要求。
- **求解器补圆点**：求解器的输出也是 RNL，可以有 `$JUNCTION` 的用例。求解器在 ROUTE 的分叉点（13.7）写上圆点；用户写的导线在共用点上接了三根以上却没套 `$JUNCTION` 时，求解器也可以在输出里补上。共用点一定是命名的点或端子（坐标相同不算），所以圆点写得出来。补不补圆点是求解器的设置，不是语言规则。
- 圆点只是画法：不建立连接，不校验（原则 2.2）。套了 `$JUNCTION` 的点上没有导线，也照画圆点。

### 13.3 文字：TEXT

```rnl use=w13
(50, 18) @TEXT("5T OTA testbench");                         /* an annotation: attached to a point */
(1, 1) @TEXT("see here") => @PLACE(2, 2);                   /* attached to (1, 1); the text itself is at (2, 2) */
#M1 @TEXT("W/L=${w}/${l}", key="wl") => @PLACE(12, 18);     /* a label: attached to M1, with the key wl, so it is #M1::wl */
#R1 @TEXT("R_{D}", key="name");                             /* a key the symbol has: new content, the position still from the symbol */
#M1::name @PLACE(13, 18);                                   /* the name of M1, dragged in an editor */
%w13 @TEXT("${net}");                                       /* the net name on a wire; no key; placed by the implementation */
&out @TEXT("${name}");                                      /* shows the name of the net out; placed by the implementation */
# @SELECT-TERMINAL(wired=false) => @TEXT("${net}", key="netname")    /* net names on terminals without wires */
```

- **附着**：TEXT 收一个点，或一个画得出来的对象，文字附着在它上面。附着的东西决定三件事：`${…}` 读谁的属性（13.6）；没给位置时文字放在哪；写了引用名时文字是哪个对象的子对象。
  - 点（`(x, y)`、命名的点、`::position`）：文字是标注（13.4）。它只能引用点的属性 `x` 和 `y`。
  - 对象：文字是标签。对象可以是元件、画出来的用例、叠画、有引脚的端子、导线或图元。也可以是网络：网络本身不画，附着在网络上的文字由实现放在它的某根导线或某个端子旁边。文件就是这样指定哪些网络显示名字。
  - 没有符号的用例、没有引脚的端子对画图没有意义：收到它们时这条 TEXT 失效（12.1、9.2.4）。
  - 收到集合时，TEXT 给每个成员附着一段文字（5.2.1），如上例最后一句。
  - 符号体里，附着在点上的文字是符号的固定文字；附着在单独的 `?` 上的文字，附着在用这个符号画出的对象上（见下）。
- **内容**：`text` 必写，写了引用名也一样；不写时这条 TEXT 失效。它可以按位置写在最前，如 `@TEXT("${name}", key="name")`。没有默认内容：要显示名字，写 `"${name}"`。文字记号和属性引用见 13.6。
- **位置**：文字有自己的位置，不是它附着的点或对象。
  - 文字的位置起初是自由的，如同 `(_, _)`。没有 PLACE、`dx`、`dy` 或约束定它时，由求解器和查看器决定：附着在点上的文字通常就放在这个点，附着在对象上的放在对象旁边；为了不重叠，两者都可以挪开。
  - PLACE 定的是文字自己的位置。所以 `(1, 1) @TEXT(…) => @PLACE(2, 2)` 不矛盾：前一部分把文字附着在 (1, 1) 上，后一部分把文字放在 (2, 2)。要把标注确切地放在某处，就写 PLACE。
  - `dx`、`dy`：偏移，只有 TEXT 收。附着的东西有坐标点时（点、元件的原点、画用例的那个点、端子的引脚），文字放在这个点加 (dx, dy) 处。导线和网络没有坐标点：附着在它们上的文字写了偏移，这条 TEXT 失效。
    - 文字仍只有一个位置，就是加了偏移以后的那个；约束和求解器都按它算，没有"偏移前"的位置。附着对象被挪动或由求解器摆放时，文字跟着走；别的约束拉动文字时，附着对象也跟着动。偏移等于 x、y 各一条精确的、沿递增方向（`"left-to-right"`、`"bottom-to-top"`；14.5）的 DISTANCE，只是写在文字上。
    - 偏移按场景的轴，不随附着对象的朝向转，因为场景里的文字不跟对象转。符号体里也可以写偏移，那时它是局部坐标，随元件变换，与 `=> @PLACE(…)` 写的局部位置一样。
    - **偏移与 PLACE 互相取代**：文字在每一轴上的位置，要么是绝对位置（PLACE 的 x 或 y），要么是偏移（`dx` 或 `dy`），不会同时成立。同一段文字的同一轴上，按位置（8.5 的位置）后写的那种生效，先写的那种整个不再起作用：写了偏移以后，这一轴的绝对位置是自由的，由偏移算出；写了 PLACE 以后，这一轴的偏移不再起作用。这是取代，不是冲突：与优先级无关，也不给提示。例如先写 `dx`、`dy`，后写 `#M1::name @PLACE(x=13)`，x 就是绝对的 13，`dx` 不再起作用，y 仍按 `dy`；编辑器拖动一段按偏移放的文字时就这样写。符号里给的位置排在最前（见下），场景里的 PLACE 或偏移都取代它。
    - 生效的那种照常是几何事实：偏移的 x、y 各是一个单位，它们的位置是写它们的 TEXT 语句的位置，优先级是记录头的默认（14.8）；它们与别的事实按 8.5 取舍。同一轴上的几条 PLACE 之间按 8.5 取舍。写了引用名的文字，`dx`、`dy` 分别覆盖（8.4）。
  - 文字可以按它自己的位置作约束的成员（14.1）。文字的 `::position` 就是它自己的位置：`%n1::position @PLACE(…)` 等于 `%n1 @PLACE(…)`。
  - 场景里的文字不跟附着对象的朝向转；要转就写 `rotate=`。
  - 求解器可以把它选定的位置写回，前提是文字有句柄：引用名（见下）或名字。
- **引用名 `key=`**：
  - 不写引用名：文字是附着对象上一段没有引用名的文字；再写一次就是另一段，与导线一样（13.1）。可以用 `%x =` 给它起名，在本层引用、修改。规则生成的、没写引用名的文字没有句柄，求解器不能写回它们的位置。
  - 写了引用名：文字是附着对象的子对象 `object::key`，如 `#M1::wl`。同一个对象同一个引用名就是同一段文字，后写的语句按项覆盖它：字号、对齐、旋转等各自覆盖，没写的参数保持不变（8.4）。内容每条都写（`text` 必写），后写的内容总是换掉先写的；只改对齐或旋转，也要把内容照写一遍，如 `#M1 @TEXT("${name}", key="name", halign="end")`。位置照 PLACE 的规则（8.5）。别的记录、编辑器、求解器靠这个句柄找到这段文字。
  - 附着在点上的文字不收 `key=`，因为点没有子对象：写了引用名，这条 TEXT 失效。
  - `::` 后面的名字按固定的次序查，引用名排在最后（6.5）：先是用例的角色名和局部名，然后是它们的 `definition=` 代称，然后是标准子对象名和它们的代称，最后是文字的引用名。所以引用名不应与排在它前面的任何名字同拼写：标准子对象名（`position`、`net`）或本文件声明的它们的代称（如 `rnl-zh` 的 `位置`）；所附着用例的角色名或局部名；或这些名字的 `definition=` 代称。这样的引用名是错误，与 6.5 的撞名相同。写在符号里的文字，代称取写这个符号的文件的。`name` 和 `value` 不是标准子对象名，只是常用的引用名。
- **符号里的文字**：
  - 符号体里，单独的 `?` 指用这个符号画出的对象：画 M1 时是 M1，画用例 `%g0` 时是 `%g0`。它只能作 TEXT 的对象，用在别处失效，如在符号里写 `? @PLACE(…)`，含义不通。
  - `? @TEXT("${name}", key="name") => @PLACE(1.5, 1.5)`：文字附着在用这个符号画出的对象上，`${…}` 读它的属性。这里的 PLACE 是局部坐标，随元件变换（见 9.2.5 的文字方向）。没写 PLACE 时，由实现把文字放在对象旁边。
  - 写了引用名的文字是用这个符号画出的对象的子对象，如 `#M1::name`。符号里的文字排在最前，场景里同一个引用名的文字按项覆盖它：`#R1 @TEXT("R_{D}", key="name")` 只改内容，位置仍取符号里的；`#M1::name @PLACE(13, 18)` 只改位置，内容仍取符号里的。场景里给的位置是场景坐标，不再随元件转。
  - 符号给的引用名在指派符号以后才有（8.2 第 4、6 步）。M1 的符号没有引用名为 `name` 的文字、场景里也没写时，`#M1::name` 失效。要不依赖符号，就在场景里写这个引用名的 TEXT。
  - 符号里附着在点上的文字是固定文字，如运放符号里的 `(-2, 2) @TEXT("+")`，不能按元件改。
- **规则**：`# @SELECT-TERMINAL(wired=false) => @TEXT(…)` 这类规则按符号选端子，所以与逐个生成一起在第 5 步求值（8.2）。实现自己补飞线或标签时，跳过已有标签的端子。
- 显示哪些网名、显示在哪里，没画导线的连接用标签还是飞线显示，默认都由实现决定：它们属于实现的风格（原则 2.7）。用标签代替导线会改变布局，所以求解器和渲染器用同一份设置。RNL 只在需要时写这些：表达意图（不写位置），或保存已经定下的位置。
- 没有沿导线的位置：导线本身的坐标就不是固定的。
- 参数：`text`（必写，可以按位置写）、`key`、`dx`、`dy`、`halign`、`valign`、`rotate`，以及文字的样式属性 `textcolor`、`size`、`font`、`bold`、`italic`（9.3）；附着在点上的文字没有 `key`。`halign`、`valign`、`rotate` 见 9.2.5。样式参数是这段文字直接的样式（8.3）；文字的样式怎样取见 11.3。

### 13.4 标注：场景里的图元

```rnl
(50, 18) @TEXT("5T OTA testbench") => @SET-STYLE $note => %n1;
%f1 = @RECTANGLE {(0, 0) (40, 30)};
%n1 @PLACE(60, 18)                            /* moves the text; may also be written in another record */
```

- LINE、RECTANGLE、CIRCLE、ELLIPSE、ARC、BEZIER 和 TEXT 可以直接写在场景里，也就能写在普通定义的体里。写在符号体里是局部坐标，写在场景里是场景坐标；由写在哪里决定，关键字不变。
- 原则 2.2 的 note 对象（自由文字、图形、边框等纯绘图对象，没有端子，没有电气语义）就是本标准的标注：写在场景里的图元和附着在点上的 TEXT。
- PIN 只能写在 DEFINE-SYMBOL 的体里：引脚绑定的是用这个符号画出的对象的端子，场景里没有这样的对象。
- 附着在点上的 TEXT 是标注（13.3）：它只能引用点的属性 `x` 和 `y`；不收 `key=`，因为点没有子对象（写了引用名，这条 TEXT 失效）。要显示对象的名字或值，把 TEXT 附着在对象上，它就是标签。
- 图元的位置由它的点给出。点可以是任何点对象：命名的点、加了约束的自由点，或跟着器件走的 `#M1::position`。PLACE 不收图元本身：要从别的记录移动中心写法的 RECTANGLE、CIRCLE、ELLIPSE，就移动它的 `::position`；LINE、ARC、BEZIER 和两点写法的图元有几个点，就给点起名后移动点。TEXT 例外：它有自己的位置，附着的点只给它默认的去处，PLACE 直接定文字的位置（13.3）。
- 外观：图元可以直接写样式参数（9.2.5），也收 SET-STYLE，按 8.3 的两级取值；都没给的属性用渲染器的默认值。
- 边框写成 RECTANGLE，或首尾相同的 LINE。没有框住一组对象的图元：画一个 RECTANGLE，用约束把它的角定在这组对象外面，如 `%tl %stage1_set @DISTANCE("left-to-right", exact=1)`（集合按范围算，14.5）；框住的是各成员的点加上边距。查看器可以把 GROUP 画成框，这归查看器（11.5）。没有 `::box`。
- 绘制次序按图层和位置（11.6）。
- **类别**：是不是标注，由对象的种类得出：场景里的图元就是标注，所以渲染器可以整类显示或隐藏。SELECT-ANNOTATION 选出场景里的全部图元，包括普通定义的体展开出来的（如风格包画的框）；符号里的图元、标签、导线、用例（含汇合点）不是标注。更细的类别（说明文字、标题框、某个包画的装饰）用命名的集合，一个图元可以同时在几个集合里。显示和隐藏是查看器的事；语言没有 `visible`。
- 器件上的文字是附着在器件上的 TEXT，即标签（13.3）。附着在 `#M1::position` 上的 TEXT 是标注；默认它也跟着器件走，但只能引用这个点的坐标，也没有引用名。

### 13.6 文字记号与属性引用

```rnl
#R1 @TEXT("R_{D}", key="name");                              /* subscript */
(50, 18) @TEXT("\textbf{5T OTA} testbench\\VDD = 1.8 V");    /* bold, two lines */
#M1 @TEXT("W/L=${w}/${l}", key="wl");                        /* host parameters */
$NMOS_M = @DEFINE-SYMBOL {
  $NMOS;
  ? @TEXT("${model}", key="model") => @PLACE(1.5, -1.5)      /* the model name, in a symbol */
}
```

- **文字记号**是 LaTeX 文本模式的一个子集，不是完整的 TeX：

  | 写法 | 含义 |
  |---|---|
  | `_{…}`、`^{…}` | 下标、上标 |
  | `\textbf{…}`、`\textit{…}` | 粗体、斜体 |
  | `\overline{…}` | 上划线，如低有效的 `\overline{RST}` |
  | `\frac{…}{…}` | 分式：分子在上、分母在下，中间一条横线，如 `\frac{${w}}{${l}}`；不能上下叠排的查看器显示成"分子/分母" |
  | `\alpha` … `\omega`、`\Gamma` … `\Omega` | 希腊字母，名字与 LaTeX 相同 |
  | `\pm`、`\times`、`\cdot`、`\infty`、`\approx`、`\neq`、`\leq`、`\geq`、`\ll`、`\gg`、`\propto`、`\parallel`、`\angle`、`\circ`、`\to`、`\uparrow`、`\downarrow` | 常用符号 |
  | `\\` | 换行 |
  | `\_`、`\{`、`\}`、`\$`、`\%`、`\&`、`\#`、`\textbackslash` | 字符 `_`、`{`、`}`、`$`、`%`、`&`、`#`、`\` 本身 |

- 希腊字母：小写 `\alpha` 到 `\omega`（LaTeX 没有 `\omicron`，直接写 o），以及变体 `\varepsilon`、`\vartheta`、`\varpi`、`\varrho`、`\varsigma`、`\varphi`；大写只有与拉丁字母不同的 `\Gamma`、`\Delta`、`\Theta`、`\Lambda`、`\Xi`、`\Pi`、`\Sigma`、`\Upsilon`、`\Phi`、`\Psi`、`\Omega`。表里没有的符号直接写成 Unicode 字符（字符串可以含非 ASCII 字符，3.7）。
- 文字记号可以嵌套，如 `\textit{V}_{\textit{DD}}`、`I_{D_{1}}`。`V_{in}^{+}` 的上下标怎样排（叠放或先后），由查看器决定。
- **上下标要带花括号**：单独的 `_`、`^` 是普通字符。这与 LaTeX 不同，LaTeX 里 `g_m` 的 m 是下标：名字和说明里常有 `vin_1`、`bias_ctrl`，按那条规则会排坏。代价是 `g_m` 照原样显示。
- 其他字符照原样显示，包括单独的 `{`、`}`、`$`、`~`、`%`、`&`、`#`，它们在 LaTeX 里另有含义。
- **反斜杠**：`\\` 是换行，与 LaTeX 相同；反斜杠本身写 `\textbackslash`。反斜杠后面不是认得的命令时，照原样显示并给警告，如 `C:\temp`（`\temp` 是不认识的命令，见下条）；不要警告就写 `C:\textbackslash{}temp`。只有反斜杠后面紧跟 `\`、`{`、`}`、`_`、`^`、`$`、`%`、`&`、`#` 或认得的命令名时，才需要写 `\textbackslash`。RNL 字符串没有反斜杠转义（3.7）：`"\textbf{V}"` 照这样写，不写成 `\\textbf`。
- 不认识的命令（`\` 后面跟着不在上表里的字母，如 `\sqrt`、`\alpah`）和不配对的花括号：照原样显示并给警告；这段文字仍然有效。
- **命令名之后**：命令名是 `\` 后面连续的字母。认得的命令名后面的空格吞掉，不显示；紧跟的空 `{}` 只作分隔，也不显示。所以 `10 \mu A`、`10 \mu{}A` 都显示 10 μA；要留空格，写 `\mu{} A`；`\textbackslash{}temp` 显示 \temp。`\_`、`\{` 这类转义字符后面的空格照留。

  注：以后的版本支持更多 TeX，只会放宽。到时数学模式写 `\(…\)`，不写 `$…$`，因为 `$` 用于属性引用。
- **分式**：`\frac` 后面要紧跟两个花括号里的组；少一个时按不认识的文字记号处理，照原样显示并给警告。分子、分母里可以写文字记号和 `${…}`。
- 上下标、分式升降多少、缩小多少，由查看器决定。字体，以及整段文字的粗体和斜体，来自样式或参数 `font`、`bold`、`italic`（9.3）。
- 文字记号在 TEXT 的 `text` 和 PIN 的 `label` 里解释（如 `\overline{CS}`）。别的字符串参数（`key`、枚举值、选择条件）不解释文字记号。
- 注：导入导出时，KiCad 的 `_{…}`、`^{…}` 写法相同，它的 `~{…}` 就是 `\overline{…}`；Altium 在每个字符后加 `\` 的上划线改写成 `\overline{…}`。
- **属性引用** `${name}` 显示附着对象的一个属性。要写 `${` 本身，写 `\${`；从 `\${` 到与它配对的 `}` 都照原样显示，这个 `}` 不算不配对的花括号。能引用的属性：
  - 元件：`name`；`value`，宿主行里写的值，原文照搬，没有就是空的（不退而取模型名）；`model` 和 `type`，与选择条件相同（10.1），所以 X 元件的 `${model}` 显示子电路名；以及宿主参数，如 `w`。与标准属性同名的宿主参数写 `${#…}`（见下）。
  - 端子和导线：`net`，所在的网络，显示成它的名字。总线导线的 `net` 是各网络名按次序用 `,` 连起来，不加空格（13.1）。叠画的端子：各成员接同一个网络时是这个网络的名字，否则用 `,` 把各名字连起来（11.8）。
  - 网络：`name`。
  - 用例：各角色和它的定义的参数。`${p}` 就是填角色 p 的对象，按下面的规则显示。用例没有自己的名字：地、电源、端口的符号写 `${p}`，p 是网络时显示网名；用例画在引脚上（12.1 第 5 条）时 p 是端子，也显示它所在网络的名字。
  - 叠画：各成员相同的属性取这个值，否则把各值用 `,` 连起来（11.8）。
  - 点：`x`、`y`，最后的坐标，即求解以后的。
  - 图元：没有属性。
- **属性路径**：`${a::b::c}` 里，第一个名字取附着对象的属性，后面每个 `::name` 取前一个值的属性，如 `${p::x}`（角色 p 是点时它的 x）、`${pair::in_p::w}`。
  - 属性的值可以是对象（用例的角色；端子、导线的 `net`），也可以是文字（`name`、`value`、宿主参数等）。文字没有属性，后面不能再接 `::`。
  - `${…}` 里的 `::` 只取属性，与语句里取子对象的 `::` 不同（6.5）：`${m::name}` 是元件 m 的名字，而语句里的 `#M1::name` 是 M1 上引用名为 `name` 的文字（13.3）。
  - `${m::#type}` 只找宿主参数，与 `${#type}` 相同（见下）。
- **显示**：路径最后的值是文字时，照原样显示。是对象时：元件和网络显示名字；端子和导线显示所在网络的名字，总线导线把各网络名用 `,` 连起来；叠画按上面说的；集合（如集合角色）显示它的成员，各按这里的规则，用 `,` 连起来。点、用例、图元显示不出来：这段文字失效。所以角色 p 是点时，要写 `${p::x}`，不写 `${p}`。
- 引用取原文，不求值：`w=1u` 显示 1u。各方言给出什么，由它的宿主适配器定；如 Spectre 里电阻的值是参数 `r`。
- 上面列的属性总是有的，没有值时为空。引用不存在的属性名时，这段文字失效。
- 引用来的内容照原样显示，不当作文字记号解释：宿主的名字和值不是按这套文字记号写的。
- 引用只能从附着对象的属性往下取，不能跳到任意对象。没有 KiCad 的 `${R3:VALUE}` 这种引用别的对象的写法。
- **代称**：`${…}` 里的属性名也认本文件声明的代称，按标准属性、代称、宿主参数的次序查；`${#name}` 只找宿主参数（16.5）。用例的角色名、参数名是 RNL 名字，只认它的定义的 `definition=` 代称，每一步按这一步的用例的定义查，如 `${输入对::正输入::w}`（16.5）。
- **与标准属性同名的宿主参数**：标准属性优先，同名的宿主参数写 `${#type}`（RNL 里 `#` 指宿主）。任何宿主参数都可以这样写；没有同名的标准属性和代称时，`${w}` 是 `${#w}` 的简写。标准属性名按原样比较，宿主参数名按宿主的规则比较：SPICE 宿主里 `${Type}` 不是标准属性，所以它是宿主参数 type。
- **名字的排法**：语言没有办法给引用内容的个别字符改格式。要把 M1 显示成 M₁，就写文字本身，`#M1 @TEXT("M_{1}", key="name")`，改名后它不跟着变。"器件名末尾的数字一律排成下标"这类统一的约定，属于查看器的风格。

### 13.7 整个网络画成导线：ROUTE

```rnl
&x @ROUTE;                                  /* x is drawn as wires; the solver decides the branches and paths */
%jo = (_, _);
&out @WIRE {#M2:1 %jo};
&out @ROUTE;                                /* this wire is drawn as written; the solver adds the rest */
$ROUTED_NET_SET = # @SELECT-NET;
$GROUND_NET_SET @REMOVE-FROM $ROUTED_NET_SET;
$ROUTED_NET_SET @ROUTE                      /* as a house-style package would write it: every net except the ground nets */
```

- ROUTE 让文件可以要求把整个网络画成导线，而不必说在哪里分叉、圆点画在哪里。
- **签名**：一个槽位，收网络；收到集合时逐个成员处理（5.2.1），不当作总线。参数：`mode`（给求解器的走法提示，取值同 WIRE，默认 `"auto"`）和导线的样式参数（13.1）。
- **含义**：这个网络在本层画成导线。网络上全部有引脚的端子（器件的，以及套在网络或它的端子上的虚拟元件的）连成一棵树；在哪里分叉、怎样走由求解器决定。已经写出的导线是这棵树的一部分，求解器补齐其余的。
- 注：WIRE 的点列为空不表示这个意思。点列可能是算出来的，选择碰巧选空时就会悄悄把全部连上；所以 ROUTE 是单独的关键字；本版也没有可选槽位（5.3）。
- **求解器写回**：具体的 WIRE（带拐点和 `mode="straight"`）、分叉用的命名点和汇合点（13.2），带上 ROUTE 的样式参数，写进求解器自己的记录。ROUTE 本身是用户的意图，留着；下次求解时重新计算（第 17 章）。
- **不求解的查看器**画飞线或什么也不画，由查看器决定（原则 2.7）。
- ROUTE 不是几何事实，不参加冲突（8.5）。没有引脚的端子不在树里。网络上要连的点不到两个时，ROUTE 什么也不做。
- 风格包用集合和规则选择哪些网络画成导线，如上例；没有规定网络怎样显示的关键字。
