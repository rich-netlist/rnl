## 附录 C 留给以后版本的内容（说明性）

本附录列出本版标准没有收入、并说明以后的版本可能加入的内容，以及提到它们的节。本版没有为这些内容预留关键字或写法（5.3、16.4），以后的版本也不一定加入。

| 留给以后版本的 | 见 |
|---|---|
| 更多宿主的载体，包括块注释（如 Eldo 的 `#com … #endcom`），以及由此带来的宿主注释结束符的处理 | 2.2、2.5 |
| 记录 ID；工具按 `type`、`author` 和语句的键找自己的记录 | 2.8 |
| 表达式 | 3.7 |
| 说明一个定义是对整个集合套用一次还是对每个成员各套用一次的标准例句（`each`） | 4.5 |
| 可选槽位；没有可选槽位，选择总要写范围，至少写 `#` | 5.3、10.1、13.7 |
| 一个引用里展开多处下标，以及更多的下标写法，如 `<*2>A`、`A<0:2*2>`、`D[0..7]` | 6.11 |
| 标准的诊断码 | 7.6 |
| 在文件里压制诊断的写法和严格模式，例如作为记录头的字段 | 7.6 |
| 几条事实组成的单位：定义或用例展开出的事实在冲突取舍里一起保留或一起丢弃。还没定的有：这种单位的优先级、嵌套的用例、从外面经 `::` 写的优先级 | 8.5 |
| 符号和元件的缩放 | 9.2.1、11.7 |
| 导线两端的箭头 | 9.2.5 |
| 更多的线型 | 9.3 |
| 颜色名和 `rgb()` | 9.3 |
| 图案填充、渐变和阴影 | 9.3 |
| 断言语句，用于检查如两个角色不能填同一个对象这样的条件 | 9.5 |
| 在一条语句里求集合的交集 | 10.1 |
| 按端子数或参数给原生元件选符号。每种方言里有几个原生元件，类别由模拟器按行决定，现有的 `name`、`model`、`type` 条件分不出来：Spectre 的 `switch` 接两个端子是单刀单掷，接三个是单刀双掷；SPICE 的 B 源写 `V=` 是电压源，写 `I=` 是电流源。子电路和模型不会这样，它们的端口和模型类型都是固定的。一种做法是给 SELECT-INSTANCE 加通用条件，如 `terminals=`（端子数）、`param=`（行上有这个参数）。另一种是由方言的适配器给这些原生元件一个区分用的类型（6.12），如 B 的 `"current"`、三端 switch 的 `"spdt"`，用 `type=` 选，这时它也比较适配器给原生元件的类型。在那之前，标准包照现在的规则画这两类 | 10.1、6.12 |
| 按元件所用的语言模式选符号。Spectre 文件中间可以有 `simulator lang=spice` 的段落，段里写着要画的元件，如 `I1 a b 1m`；这个文件是 Spectre 方言（16.3），所以这些元件按 Spectre 的规则找符号，可能画成方框。用 USE-PACKAGE 用上 SPICE 的规则，又会把整个文件里像 `I0` 这样命名的 Spectre 元件画成电流源。要按段区分，规则得能看到元件是用哪种语法写的。这和上一条按端子数、按参数选符号是同一类问题，以后一起考虑。被 include 的另一种方言的文件在子电路外面写的元件，属于 include 它的层（6.1），也是这样 | 16.3、10.1 |
| 用 ORIENT 把整个集合当作一块旋转 | 11.2 |
| 一个宿主对象画几次，各是有自己名字的独立对象 | 11.4 |
| 框住一组对象的图元 | 13.4 |
| 锚在导线上的标注：沿导线的位置（如 `t`、`offset`），以及锚在导线中间的符号或箭头 | 13.3、15.2 |
| 文字里更多的 TeX，含写作 `\(…\)` 的数学模式 | 13.6 |
| `${…}` 引用别的对象的属性，如 KiCad 的 `${R3:VALUE}` | 13.6 |
| 约束的对角投影 `"x+y"`、`"x-y"` | 14.1 |
| 文件里放实现的设置（如求解器的设置）的地方，作为识别但不解释的内容 | 14.8、16.4 |
| 只用于本层的 USE-PACKAGE | 16.2 |
| 分在几个文件里的包 | 16.2 |
| 网表和它的包文件的清单格式 | 16.2 |
| 包的内容摘要，如 USE-PACKAGE 的 `digest=` 参数 | 16.2 |
| 包只给自己用的引用，与转给使用者的引用分开 | 16.2 |
| 包限定名、给包另起的名字和层级标签，如 `$acme.DIFFERENTIAL_PAIR` 或 `as=`，写法不用名字后面紧跟 `.` | 16.2 |
| 扩展机制：带厂商前缀的关键字，如 `@ACME.ROUTE`，在头段记录里声明为必需或可选的扩展 | 2.8、16.4 |
| 精确 RNL，即文件不经求解器就能画出的条件，以及往返的判据；这些也可以改由工具之间约定 | 第 17 章 |
