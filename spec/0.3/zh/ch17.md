## 17 修改模型

- RNL 只描述当前状态，不记录得到它的编辑过程：
  - 没有撤销、删除操作，删除就是编辑文本；
  - 没有相对位移，编辑器写入新的绝对值。
- **谁改哪些记录**。求解器换掉 `type="generated"` 的记录。别的工具只应改 `author` 是它自己的记录，如编辑器整理它自己写过的修改，或重新导入时换掉上次导入写的。工具不应碰没有 `author` 的 authored 记录（2.8）。
- 后追加的描述按先后覆盖较早的（8.4）；几何事实先比优先级（8.5）。`type` 和 `author` 不影响先后（8.3）。
- **输出跟着子电路走**。求解器的输出和用户在编辑器里做的修改，都写进那一层自己的文字：子电路写在它的 `.subckt … .ends` 之内，哪怕它在被 include 的文件里；顶层写在主文件的文件层。求解器用 `priority="high"` 把输出写在这一层自己的文字的最后；它求解时，不把 `type="generated"` 的记录算进解释（2.8），求完后换掉它们（14.8）。它应把自己定下的每个决定都写回（14.8）。`scope=` 只用于作者自己选择写在外面的语句（2.6）。文件只读时保存不保存，由工具决定。
- **结果过时只给提示**。上层或包改了以后，库里子电路的求解结果可能过时，如主文件换了符号。旧结果照常生效；查看器发现记录头的 `hash` 与当前输入不符时，给提示，建议重新求解（2.8）。
  - hash 按这一层继承后的实际输入算：流下来生效的规则、选定的符号、包的版本和求解器的选项，不算 `type="generated"` 的记录，也不算元数据字段。它按层算，不按文件算，也不只算子电路自己的文字，否则主文件的修改就查不出来。
  - hash 不改变解释。它的算法归工具；值建议带算法的标记，如 `"sig1:…"`，工具不认识这个算法就不比较。
  - 注：要是规定 hash 对不上就不用旧结果，它的算法就成了语言的一部分，各工具必须算得一样，不求解的查看器也画不出这一层。
  - 编号是例外：产生无名对象的语句变了，编号的校验值就对不上，用到编号的语句在这一层重新求解之前都不生效（5.9）。校验值只看这一层和它用到的定义的文本，各工具都算得一样，旧结果的其余部分照画。
- **生成的对象**。求解器给规则生成的对象定了位置、接了线以后，就把它们写成显式的语句，与导线一起写进自己的记录。显式的对象优先，补位规则不再生成同一个对象（10.5）。它们的定义体里没有局部名字的对象，用编号引用（5.9）。
- **改求解器做出来的对象**。求解器给它写出的对象起的名字，只绑定在它自己的记录里，而求解时这条记录不算进解释（2.8）。所以别的记录里用这个名字的语句，求解时找不到对象，求解器也就顾及不到它。要单独描述这样的对象，编辑器按 10.5 的说法在自己的记录里手写它，再写上修改，如 `%g_r4 = $GROUND_STUB @ATTACH #R4:2; %g_r4::g @PLACE(30, -4, priority="high")`：stub 的导线让这个端子有了导线，补位跳过它，下次求解不再写出那个对象；在此之前，求解器记录里的那个也照画。要改的若是生成的用例本身，如端口符号，从宿主对象出发的选择在求解时和画图时都找得到它，如 `&out @SELECT-ANCESTOR-USAGE $IO_PORT => @PLACE(40, 20, priority="high")`；用例的局部对象选不到（9.4）。
- 记录头的字段作用于记录里的每条语句（2.8）。
- **例：编辑器里的修改**。下面是一个完整的片段，带宿主的注释前缀。头段记录之后，设计者写了第一条记录，求解器写了第二条；用户在编辑器里把 VIN 往左拖，编辑器追加了第三条：

  ```spice
  * Common-source stage
  * @RNL(type="header") { @VERSION("0.3")}
  .model nch nmos level=1
  M1 out in 0 0 nch W=4u L=1u
  RD vdd out 5k
  VDD vdd 0 1.8
  VIN in 0 DC 0.6 AC 1
  * @RNL {
  *   {#RD #M1} @ALIGN("x");
  *   #M1 #RD @DISTANCE("bottom-to-top", min=2);
  *   &vdd @ADD-TO $SUPPLY_NET_SET
  * }
  * @RNL(type="generated", priority="high", author="rnl-solver 0.3", hash="sig1:5be1c09a") {
  *   #M1 @PLACE(10, 0); #RD @PLACE(10, 8); #VIN @PLACE(0, -2); #VDD @PLACE(20, 4)
  * }
  * @RNL(author="rnl-editor 0.1") { #VIN @PLACE(x=-4, priority="high")}
  .end
  ```

  - 拖动写成一条新的记录，追加在求解器的记录之后，优先级是 `"high"`。两者都是 high，所以后写的保留，求解器写的 x 被丢弃，并给提示（8.5）；以后每次求解这一层，新的 x 都是固定的位置（14.8）。
  - 写进设计者的记录不行。那里的语句默认是 `"normal"`，盖不过求解器的 `"high"`；写成 `"high"` 也不行，因为求解器的记录在后面，同一优先级里后写的事实保留。这种失误不是错误，只给一条关于取舍的提示。这个位置要到下次求解这一层时才生效，那时设计者的语句是约束之一；在那之前图上不变。
  - 按位置写的参数在写名字的参数之前（4.2 第 9 条）：`@PLACE(-4, -2, priority="high")` 与 `@PLACE(x=-4, y=-2, priority="high")` 相同，`@PLACE(x=-4, -2)` 是错误。
  - 要改设计者写的内容（换符号、改名字、删约束），直接改设计者的记录。求解器的记录不碰，下次求解这一层时整个换掉。
- 要暂时停用一条语句，就用 `/* … */` 把它包起来。
- **原图往返**。RNL 不保证任意导出成 RNL 再导入后图不变（原则第 1 节）；导出器可以选择写坐标级的精确 RNL（原则第 3 节）。本版不定义什么是精确 RNL，也不定义往返的判据。
