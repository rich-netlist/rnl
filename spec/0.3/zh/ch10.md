## 10 选择、规则与逐个生成

本章讲选择关键字、用到它们的规则，以及逐个生成。

### 10.1 选择关键字

选出的每种对象各有一个选择关键字，每个的条件固定。选择的结果是集合（5.2）。

每个选择关键字收一个范围对象。`#` 表示求值时所在的那一层（10.3）。给一个对象或集合，就在这些对象里选：比如给网络的集合时，SELECT-TERMINAL 选接在这些网络上的端子（怎样从范围走到要选的种类，见表后）。范围不能省略，所以简单的选择也写 `#`：`# @SELECT-INSTANCE(name="R*") => @SET-SYMBOL $RESISTOR`。

| 关键字 | 选出 | 条件 |
|---|---|---|
| SELECT-INSTANCE | 宿主元件。范围里给端子时，选它们所属的元件；给网络时，选在上面有引脚的元件 | `name`（元件名，如 `name="R*"`）；`model`（元件行上写在模型位置的名字：`.model` 名或子电路名）；`type`（`.model` 里的类型，如 `"nmos"`） |
| SELECT-TERMINAL | 宿主元件的端子；只选所属元件的符号里有引脚的 | 所属元件的 `name`、`model`、`type`；`terminal`（端子名或序号）；`net`（所在网络的名字）；`wired`（10.2）；`current`（电流方向，15.2：`"in"`、`"out"` 或 `"unspecified"`） |
| SELECT-NET | 网络。范围里给元件、端子或导线时，选它们所在的网络 | `name`；`port`（是否本层的端口）；`wired`（10.2）；`global`（是否全局网络，6.3） |
| SELECT-WIRE | 导线。范围里给网络时，选画在这些网络上的导线 | `net`（导线所在网络的名字；总线有一个网络对上就算）；`bus`（`true`：只选总线，13.1；`false`：只选不是总线的导线，即网络槽位收到的是一个网络、不是集合） |
| SELECT-LABEL | 标签，即附着在对象上的 TEXT（13.3）。范围里给对象时，选附着在它们上面的标签 | `key`（文字的引用名；收 `*`，区分大小写；没有引用名的标签对不上任何 `key=`） |
| SELECT-ANNOTATION | 标注，即场景里的图元和附着在点上的 TEXT（13.4） | 除 `role` 和 `recursive` 外没有别的条件 |
| SELECT-USAGE | `scope @SELECT-USAGE $D`：范围里定义 `$D` 的用例，往里找。给 `#` 时是本层的用例；给用例时是这些用例本身和它们里面的用例。不写 `$D` 时是任何定义的用例 | 定义是最后一个对象（5.6），可以省略。除 `recursive` 外没有别的条件 |
| SELECT-ANCESTOR-USAGE | `objects @SELECT-ANCESTOR-USAGE $D`：把这些对象当成员的 `$D` 的用例，往外找；间接的成员也算 | 定义是最后一个对象（5.6），不能省略。除 `recursive` 外没有别的条件 |

除此之外，每个选择关键字都收条件 `recursive`，前六个还收 `role`，它只在范围里有用例时才有意义（两者都见下）。

- **每种一个关键字。** 每个选择关键字按它选出的种类命名，如某个网络的导线写 `&clk @SELECT-WIRE => @SET-STYLE $signal`，M1 的标签写 `#M1 @SELECT-LABEL`。没有一种选择能选出所有种类的对象：要覆盖每一种，就每种写一条规则，标准包给每个对象配基础样式就是这样做的。
- **范围怎样走到要选的种类。** 范围里的每个对象朝要选的种类走一步；走不到的对象不选出东西，这不是错误：
  - SELECT-INSTANCE：元件就是它自己；端子走到所属的元件；网络走到在上面有引脚的元件。
  - SELECT-TERMINAL：元件走到它的端子；网络走到接在上面的端子；端子就是它自己。
  - SELECT-NET：网络就是它自己；元件走到它各个端子所在的网络；端子走到它所在的网络；导线走到它所在的网络。
  - SELECT-WIRE：网络走到画在上面的导线；导线就是它自己。SELECT-LABEL：对象走到附着在它上面的标签；标签就是它自己。SELECT-ANNOTATION 只取范围里的标注。
  - 经过端子的一步只算符号里有引脚的端子，与 SELECT-TERMINAL、补位、ROUTE 相同（9.2.4）。所以 `&vss @SELECT-INSTANCE` 就是 `&vss @SELECT-TERMINAL => @SELECT-INSTANCE`：用三端符号画的 NMOS 只有衬底接在 vss 上时选不到；对这样的管子 M1，`#M1 @SELECT-NET` 也不含 vss。本层的端口，如 `#:inp`，照样走到它的网络。符号队列给出符号之前，全部端子都算（8.2）。
  - 以用例为范围时，只取要选种类的成员；成员不再当作范围（见下）。
  - 例：受时钟控制的管子是 `&clk @SELECT-INSTANCE`；只要栅极接 clk 的，是 `&clk @SELECT-TERMINAL(terminal="g") => @SELECT-INSTANCE`；M1 接的网络是 `#M1 @SELECT-NET`。
  - 注：只算有引脚的端子，选出来的就与画出来的一致，后面的规则加上的地、导线和样式都与图对得上。
- **只选本层。** 每个选择关键字都有条件 `recursive`，默认 `true`。写 `recursive=false` 时只选写这条语句那一层的对象；在下层求值时为空，所以规则只在它自己那一层生效（10.4）：`# @SELECT-TERMINAL(net="vss", wired=false, recursive=false) => $GROUND_STUB @ATTACH` 只给本层补地。单个宿主对象直接引用即可，如 `&vss`：宿主引用本来就只在本层解析。
- **SELECT-USAGE 和 SELECT-ANCESTOR-USAGE。** 两个都按名字解析到的定义认定义（9.5），选出的总是用例，都没有 `role=`。
  - SELECT-USAGE 往里找，与别的选择关键字一样。范围给 `#` 时，选求值那一层的用例；给用例或用例的集合时，选这些用例本身和它们里面的用例，一直到最里层。范围里的元件、网络和端子不是用例，选不出东西；这时给警告，提示要找它们所在的用例用 SELECT-ANCESTOR-USAGE。
  - SELECT-ANCESTOR-USAGE 往外找：选出把范围里的对象当成员的用例，直接的、间接的都算（见下例）。范围里的用例本身不算在内。范围写 `#` 是错误：一层不是任何东西的成员。
- **以用例为范围。** 以用例为范围时，别的选择关键字选出这些用例里本种类的成员，`role=` 只取那个角色的成员。是用例的成员继续往里走，一直到最里层：

  ```rnl
  $OTA = @DEFINE(roles=[["pair", "usage"], ["load", "usage"]]) {};
  %dp1 = #M1(in_p) #M2(in_n) #M5(tail) @AS $DIFFERENTIAL_PAIR;
  %cm1 = #M3(ref) #M4(out) @AS $CURRENT_MIRROR;
  %ota1 = %dp1(pair) %cm1(load) @AS $OTA;
  %all_set = %ota1 @SELECT-INSTANCE;                 /* {#M1 #M2 #M5 #M3 #M4} */
  %pair_set = %ota1 @SELECT-INSTANCE(role="pair");   /* {#M1 #M2 #M5} */
  %up_set = #M1 @SELECT-ANCESTOR-USAGE $OTA          /* {%ota1} */
  ```

  - `role=` 的值也认这个用例的定义的 `definition=` 代称（16.5）。只要直接成员，就把角色当子对象用，如 `%dp1::tail`。遇到已经走过的用例就停。成员指填进角色的对象，不含体里的局部对象（9.4）。
  - **只取本种类的成员。** 成员不再当作范围往下走，别的种类的成员不算。SELECT-TERMINAL 只取端子成员：`$GROUND @ATTACH &0; $GROUND @ATTACH #M5:3` 之后，`# @SELECT-USAGE $GROUND => @SELECT-TERMINAL` 只是 {#M5:3}，不含网络 0 上的其他端子。差分对 %dp1 的成员是元件，所以 `%dp1 @SELECT-TERMINAL` 是空集合。要成员元件的端子，写 `%dp1 @SELECT-INSTANCE => @SELECT-TERMINAL(terminal=2)`（三个管子的栅极，尾管也在内）；要成员网络上的端子，写 `… => @SELECT-NET => @SELECT-TERMINAL`。每一段只做一件事；要往下走，就多写一段。范围里直接给的对象照前面的规则：网络给出它上面的端子，元件给出它的端子。
- 在场景里按条件找对象，一律用选择关键字；`::` 只取对象自身的部分（6.5）。
- **叠画。** 叠画的成员选不到，选到的是叠画（11.8）。SELECT-INSTANCE 按叠画第一个成员的条件选到叠画本身，每个叠画只算一次。SELECT-TERMINAL 选到叠画的端子，`net=` 对上其中任何一个成员的网络就算对上。
- **条件**写名字，形如 `name=value`；写出的条件都满足时才选中。要"或"，就写几条规则。比较名字的条件（`name`、`model`、`net`）收通配符 `*`，它匹配任意多个字符，与 DEVICE 一样按宿主的大小写规则比较（6.12）。按元件字母选，写 `name="R*"`。Spectre 的元件名不以元件字母开头，按 `model` 选，如 `model="resistor"`（6.12）。
- **`model`** 比较元件行上写在模型位置的名字：M、Q、D 等元件是 `.model` 名；X 元件是子电路名，包括网表里没有定义的 PDK 器件，如 `# @SELECT-INSTANCE(model="sky130_fd_pr__nfet_01v8")`；Spectre 里是 master。它与 DEVICE 的 `model=` 相同（6.12）。`type` 比较 `.model` 里的类型；X 元件没有类型。
- 比较照 3.6：条件名和标准的枚举值区分大小写；指宿主东西的值（名字、模型名、网络名）按宿主的规则。
- 网络可以按名字选：`# @SELECT-NET(name="0")` 选这个网络，`# @SELECT-TERMINAL(net="0")` 选接在它上面的端子。对象也可以按语义选：`# @SELECT-USAGE $DIFFERENTIAL_PAIR => @SELECT-INSTANCE(role="in_p")` 选出每个差分对的正输入管。
- 没有求交集的关键字，如求一个集合里属于某个用例的成员；用两次 REMOVE-FROM 写（5.2.2）：

  ```rnl
  %s_set = {#M1 #M3 #M5};
  %s_set @SELECT-ANCESTOR-USAGE $DIFFERENTIAL_PAIR => @SELECT-INSTANCE => %dp_m_set;
  %out_set = {%s_set};
  %dp_m_set @REMOVE-FROM %out_set;    /* the members of %s_set in no differential pair */
  %in_set = {%s_set};
  %out_set @REMOVE-FROM %in_set       /* the members of %s_set in a differential pair */
  ```

- **地和电源网络**由标准包提供的集合给出：`$GROUND_NET_SET`（默认是网络 0）和 `$SUPPLY_NET_SET`（默认为空）。没有网络类别。
  - 包里不能写宿主引用（16.2），所以这种集合的默认内容只能写成选择，如 `# @SELECT-NET(name="0")`。
  - 用户用 ADD-TO 和 REMOVE-FROM 增删网络：

    ```rnl
    &vss @ADD-TO $GROUND_NET_SET;                                       /* the vss of this level */
    # @SELECT-NET(name="vss") => @ADD-TO $GROUND_NET_SET;               /* the nets named vss of every level */
    # @SELECT-NET(name="vdd!", global=true) => @ADD-TO $SUPPLY_NET_SET  /* only the global vdd! */
    ```

    第二条语句也会加上子电路里叫 vss 的局部网络。只在某处不算某个网络，就复制一份集合，再从副本里删掉它：`%g_set = {$GROUND_NET_SET}; &vss2 @REMOVE-FROM %g_set`。
  - 补位规则用这样的集合作范围，如 `$GROUND_NET_SET @SELECT-TERMINAL(wired=false) => $GROUND_STUB @ATTACH`。
  - 在自己的层里写 `$GROUND_NET_SET = …` 会遮蔽包里的集合，包里的规则看不到新的这个（6.8）。
  - 不按网络名猜哪些是地和电源。导入器把编辑器文件里网络的电源域（如 `powerDomain`）写成 ADD-TO。
  - 求解器可以把标准集合当提示读（如电源在上、地在下），与它可以读标准包里的定义一样；这不作要求。
  - 注：地和电源网络没有关键字（1.5 第 7 条）：这些集合的用处，如选端子补地、换符号，都能写成包里的规则。
- **全局网络。** SELECT-NET 的条件 `global=true` 只选全局网络（6.3）。不同层里同名的局部网络是不同的结点，按名字选会都选上；只要全局的那一个，就加这个条件。

### 10.2 条件 `wired`

- 端子不是任何显式导线的点（端点或中间的点），也不与这样的端子共用总线引脚（9.2.4）时，它是 `wired=false`。总线导线也是显式导线（13.1）。导线接到叠画的端子，就是接了每个成员的这个端子（11.8）。
- 接在网络上的宿主元件的端子都没被显式导线接触时，网络是 `wired=false`；虚拟元件的端子不算。
- 只算显式写出的导线，不算生成的。有没有虚拟元件没有影响。
- 导线按写出的样子算，从 8.2 第 3 步起就算数，后来因为端子没有引脚而失效的也算（7.1、9.2.4）。导线被改写过的，算最后那次改写（13.1）。

### 10.3 选择的求值

- 选择不在写它的地方展开，每次求值只看一层。含选择的语句（规则，10.4）在写它的那一层求一次，在下面每一层各求一次；每次求值时 `#` 就是那一层，选择只选这一层的对象。所以顶层写的 `# @SELECT-INSTANCE(model="nch") => @ALIGN("y")` 在每张图里各对齐一次，不会把不同图里的元件放在一起对齐。
- 选择在用到它的阶段求值：外观规则在符号队列和样式队列里，生成规则在生成阶段（8.2）。集合也一样（5.2）。
- 选择选出的种类在读入时就知道。把它交给收不了这种对象的槽位，当即是错误，放在集合里也一样，如 `# @SELECT-TERMINAL(net="vss") => @SET-SYMBOL $NMOS`。
- SELECT-USAGE 和 SELECT-ANCESTOR-USAGE 选出的总是用例；从用例走到成员时，选出的种类由关键字决定。所以每个选择选出的种类都在读入时就知道。
- 选择的结果是集合，可以用 `%` 或 `$` 命名。集合在某层求值时只取这一层的成员：顶层写的 `&vss @ADD-TO $GROUND_NET_SET` 只加顶层的 vss，集合在子电路里求值时不含它（6.6）。
- 选择的范围写成本层的宿主对象时，如顶层的 `&Q<0:3:2, 1> @SELECT-TERMINAL(name="R*") => @TEXT("${net}", key="netname")`，规则在下层求值时这些对象不存在：选择在那里为空，什么也不做，不给警告，正如集合只取这一层的成员。10.5 的警告只针对生成规则的其余角色。

### 10.4 规则

- 收选择结果的语句是规则。
- 任何关键字都能收选择的结果，按 5.2.1 的规定逐个做或整个收：`# @SELECT-INSTANCE(type="nmos") => @ORIENT("MY")`、`# @SELECT-INSTANCE(model="nch") => @ALIGN("y")`。
- 以选择的结果为对象的 SET-SYMBOL 和 SET-STYLE 是外观规则，进外观队列（8.3）。AS 和 ATTACH 是生成规则（10.5）。其他关键字的规则，等于对选中的每个对象各写一条语句，或对它们全体写一条，在该关键字的阶段生效。
- 规则作用于写它的层及其下层，每一层各求一次，只看那一层（10.3）；包里的规则作用于用到这个包的所有层。选择加 `recursive=false` 时，规则只在写它的那一层生效。规则按定义对待（6.1）。

### 10.5 逐个生成

"对所有没接导线的 vss 端子，各放一个地并用导线接上"：

```rnl
$GROUND_STUB = @DEFINE(roles=[["t", "terminal"]], parameters=[["gap", 2]]) {
  %g = $GROUND @ATTACH ?t::net;
  ?t::net @WIRE {?t %g:p};
  {?t %g:p} @ALIGN("x");
  %g:p ?t @DISTANCE("bottom-to-top", exact=?gap)
};
# @SELECT-TERMINAL(net="vss", wired=false) => $GROUND_STUB @ATTACH => %stubs_set
```

标准包提供一个这样的 `$GROUND_STUB`，只是它只给最小距离（`min=?gap`），求解器可以把导线画得更长，如把长短不同的元件的地排齐；它还让地朝下（`@ORIENT("R0")`），约束的优先级都是 `"low"`；这里的定义遮蔽了它（6.8）。

- AS 或 ATTACH 的单个角色收到选择的结果时，对选中的每个对象各套用一次定义，其余角色在每次套用中都相同（5.2.1、9.4）。集合角色把选择的结果整个收下，定义只套用一次。
- 虚拟元件也这样逐个创建：`# @SELECT-NET(port=true) => $IO_PORT @ATTACH` 给每个端口网络一个端口符号；`$RLOAD` 是一个画成电阻的两角色定义，`# @SELECT-NET(name="out*") => $RLOAD @ATTACH &vss` 在每个选中的网络与 vss 之间接一个；因为 `&vss` 属于本层，这条规则只在本层生效，并给下面说的警告。
- 地也可以直接画在引脚上，不用导线：`# @SELECT-TERMINAL(net="vss", wired=false) => $GROUND @ATTACH`。这时角色填的是端子，用例画在它的引脚上（12.1）。这样的地没有导线，所以端子仍是 `wired=false`：在同一引脚上再显式写一个地时，规则仍会生成一个，两个重叠。所以标准包的补位用带导线的定义补地和电源（`$GROUND_STUB`、`$SUPPLY_STUB`）：写回以后，导线让端子不再是 `wired=false`，补位就跳过它。对用户直接写在引脚上的地，补位用 `# @SELECT-USAGE $GROUND => @SELECT-TERMINAL => @REMOVE-FROM $GROUND_FILL_SET` 这样的规则扣掉它的端子（10.1），所以不会再补第二个。照常放一个地、用长度为 0 的导线接上（13.1）也行。
- 配对在每次套用的内部：定义的局部名每次套用都是新的，所以一次套用里的 `%g` 就是这次套用建的那个地。
- 结果是一个生成集。它可以命名，可以整个交给 SET-SYMBOL 或 SET-STYLE（如 `%stubs_set @SET-STYLE $grey`），但不能引用其中单个成员（5.7）。
- **手写一个。** 要单独描述其中某一个，就手动创建它并接上线。它的端子就不再是 `wired=false`，补位跳过它。没有另外取消生成的办法。
- **快照。** 所有生成规则看同一个快照，即 8.2 第 3、4 步的结果（按键覆盖之后，含全部对象的符号），彼此看不到对方的结果。所以同一条规则写两次，就生成两份。
- 生成的事实在冲突取舍时取生成规则的位置（8.5）。
- 生成的对象没有位置时由求解器摆放；要说明怎样摆，就用带约束的定义。
- **写回。** 单个生成的对象不能被引用（5.7）。求解器写回它们时，写成显式的语句，如 `$IO_PORT @ATTACH &out => @PLACE(40, 20) => %p_out`，加上接到它的导线。只有规则把已经写出的去掉时，显式的对象才取代生成的对象，标准包的补位就是这样，它写两个集合的差集（见下面的按网络补位）；别的写法的规则会在显式对象旁边再生成一个，没有位置。所以要由求解器摆放其对象的规则，应写成这样的差集。只要朝向、不用接线的对象（如画在引脚上的地）也可以经选择写回，如 `#M1:3 @SELECT-ANCESTOR-USAGE $GROUND => @ORIENT("R180")`。这样写出的显式用例，定义体里没有局部名字的对象用编号引用（5.9）。写出的用例照原样带上规则在套用上明写的优先级，或者它从规则所在记录的记录头继承的 `"disabled"`（14.8）；此外什么都不写，它的体保持原来的优先级，记录头别的优先级不写。
- 生成不递归：生成规则展开出的内容里有规则时，这些规则失效。生成阶段只有一个，这样的展开产生的规则没有可以生效的阶段。
- 生成规则的其余角色填的是本层的对象（场景对象或宿主对象）时，规则只在写它的那一层生效，并给警告：这些对象属于那一层，下层没有。填定义的角色没有这个限制。
- 生成产生的 SET-SYMBOL 或 SET-STYLE 归入产生它的规则所在的组，位置取规则的位置（8.3）。
- 绑定到选择或生成集的名字不能重新绑定（6.6）。
- **按网络补位。** 没有内置的"已有就不补"规则。标准包的补位写两个集合的差集；标准包写的是：

  ```rnl
  $PORT_FILL_SET = # @SELECT-NET(port=true);                               /* the nets that get a port tag */
  $SUPPLY_NET_SET @REMOVE-FROM $PORT_FILL_SET;                             /* none on a supply net */
  $GROUND_NET_SET @REMOVE-FROM $PORT_FILL_SET;                             /* nor on a ground net: the stubs stand there */
  # @SELECT-USAGE $IO_PORT => @SELECT-NET => @REMOVE-FROM $PORT_FILL_SET;   /* less those that have one */
  $IO_PORT @ATTACH $PORT_FILL_SET
  ```

  - 这几条语句如果写在文件里而不是包里，就会遮蔽标准包的集合（6.8），并多出第二套端口补位。
  - 手写的端口符号取代生成的：`$IO_PORT @ATTACH &inp => @PLACE(0, 20) => %p` 之后，inp 不再得到生成的端口符号。用户还可以从 `$PORT_FILL_SET` 去掉网络，如 `# @SELECT-NET(name="vdd") => @REMOVE-FROM $PORT_FILL_SET`，或把自己的端口定义的用例算进来：`# @SELECT-USAGE $MY_PORT => @SELECT-NET => @REMOVE-FROM $PORT_FILL_SET`。
  - 生成的端口符号不算：生成规则在第 5 步用 `$PORT_FILL_SET`，差集里的选择按第 5 步之前的状态求值（5.2）。
  - 注："已经有一个"不内置，因为对多角色的定义它说不清，用户自己的端口定义不会算在内，而布局定义的重复只是约束的重复，由冲突取舍和优先级处理（8.5、14.8）。
- 按端子补位时，取代生成对象的仍是手写对象的导线：接了导线的端子不再是 `wired=false`。仍然没有取消生成的办法：从集合里去掉网络只是改了集合。
