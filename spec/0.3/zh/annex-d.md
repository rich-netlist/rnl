## 附录 D 与 0.2 版相比的改动（说明性）

0.3 版让求解器把自己定下的每个决定都写回，使不求解的查看器画出的就是求解器画的图。0.x 各版本之间不承诺兼容（16.1）；本附录列出改了什么，以及文件怎样迁到 0.3 版。

| 改动 | 见 |
|---|---|
| 经名字找不到的对象有编号，如 `%#3`，只用在求解器的记录里。记录头字段 `numbering` 是编号的校验值；对不上时，用到编号的语句不生效 | 5.9、2.8、3.2、5.7、7.6、9.4、13.1、13.3 |
| WIRE 收到的不是网络而是一根导线时，改写这根导线；求解器这样写回 `"auto"` 导线的走法 | 13.1、5.1、5.3、5.8、10.2 |
| 求解器应把自己定下的每个决定都写回，交给别的工具的结果只用求解器的记录能含有的形式 | 14.8、1.6、8.2、8.5、12.1、13.3、17 |
| 求解时，`type="generated"` 的记录不算进解释；此外怎样用它们，由求解器决定。0.2 版说求解器不应读它们 | 2.8、14.8、17 |
| 澄清：用例的优先级管住它的定义体里的 PRIORITY 语句；从外面经 `::` 写在局部用例上的 PRIORITY 管住这个用例展开出的一切；停用的用例里的分组可以从外面重新打开 | 14.8、11.5 |
| 澄清：`scope` 记录绑定的名字发布到目标层，在那里再绑定到同一个对象是可以的 | 2.6 |
| 关于怎样取舍冲突的一条注 | 8.5 |
| 澄清：有解，是指有实数的坐标使事实在容差内成立，整数格点只是目标；写不成有限小数的值，写回时写足够多的位数 | 8.5、11.7 |
| 实现可以限定检查有没有解所花的时间；检查没做完的事实丢弃，并给警告。这个上限和容差都是求解器的选项，用户可以设定；容差大于 0 | 8.5、7.6、11.7 |
| 澄清：求解器写回的对象，只在规则把已经写出的去掉时，才取代规则生成的对象，标准包的补位就是这样 | 10.5 |
| 被丢弃的事实的提示列出与它冲突的每一组事实；这些组里的语句也会得知因它而丢弃的事实；priority 为 `"low"` 的事实，这些提示可以不给 | 8.5 |
| 澄清：单独就无解的事实是自相矛盾，失效，不参加取舍；0.2 版的 9.5 已经是这个读法 | 8.5、9.5 |
| 澄清：管道的每一段在文本里有自己的位置，凡是书写位置起作用的地方，后面的段都算后写，如按键覆盖、外观队列和取舍次序 | 5.5、1.5、8.3、8.4、8.5、13.1 |
| 编辑器怎样改求解器写出的对象 | 17 |
| 0.3 版的文件隐式去掉另一种方言的规则包：SPICE 方言的文件不用 `rnl-std-spectre`，Spectre 方言的文件不用 `rnl-std-spice`。文件的方言看它第一条语句的语言模式；层链上写了这两个包任一个的 USE-PACKAGE，那里就留下它 | 16.3 |
| T、O 的默认端子名（`p1`、`n1`、`p2`、`n2`），U 的（`a`、`b`、`ref`），Z 的（`d`、`g`、`s`），按元件那一行所在文件的版本 | 6.12 |
| 列出了 Spectre 的默认端子名：原生器件的、`switch` 的，以及模型卡的元件按模型的器件族给的，还有选择条件 `type` 比较的类型 | 6.12、10.1 |
| 澄清：经 `.lib` 读入的一节按一个文件算，它的头段记录是节里的第一条记录 | 2.8 |
| 澄清：文件里的名字和较新版本新加的标准词拼写相同时，升版本给警告，版本照样升 | 16.1 |
| 记录头的优先级不给 AS、ATTACH 作默认值，`"disabled"` 除外：用例没被给优先级时，体保持各自的优先级；关掉的记录仍连同其中的用例和体一起关掉。求解器写出规则生成的用例时，照原样带上规则在它上面明写的优先级，或者从关掉的记录继承的 `"disabled"`，此外什么都不写 | 14.8、2.8、10.5 |
| 隐式标准包随文件的语言版本：0.2 版的文件用标准系列 0.2，0.3 版的文件用标准系列 0.3；钉住的版本优先 | 16.3、16.1 |
| 0.3 版取代 0.2 版，工具仍可以读 0.2 版：写出的是 0.3 版，写进 0.2 版的文件时把它升到 0.3 版，并钉住标准系列 0.2，使文件的名字和画法不变 | 16.1、16.3 |

**文件从 0.2 版迁到 0.3 版**：把头段记录里的版本改成 0.3（16.1）；工具写进 0.2 版的文件时自己会这样做，并钉住系列 0.2（16.1）。0.3 版加了一个标准词，即记录头字段 `numbering`；在 0.2 版里它是不认识的字段。升版本时，与它同拼写的名字会给警告（16.1）；在 0.3 版里，与它同拼写的代称是错误（16.5）。为 0.2 版写的求解器记录不用编号，照样有效；下次求解时，0.2 版容纳不下的决定也会写回。有几处结果可能与工具对 0.2 版的理解不同：从外面写在局部用例上的优先级，对这个用例展开出的一切说了算（14.8）；文件不再用另一种方言的规则包，所以在 Spectre 网表里，`I0` 这样的元件不再画成电流源（16.3）；T、O、U、Z 有了默认的端子名，文件里的 DEVICE 照样可以改写它们（6.12）。没钉标准包的文件升到 0.3 版后，也从标准系列 0.2 换到 0.3，有些定义和符号改了名；要沿用 0.2 的名字，就在头段记录里写 `@USE-PACKAGE(name="rnl-std", version="0.2")` 钉住它（16.3）；见下面的标准系列 0.3。

**标准系列 0.3**：标准包不属于本标准（16.3），它的系列 0.3 改了什么，标准包的 README 里列全了。下面是文件从系列 0.2 换到系列 0.3 时要知道的。

**改了名的**：0.3 的名字写全称，虚拟元件的符号是它的定义名后面加 `_SYMBOL`。角色名和参数名不变（`$CHAIN` 的角色 `series` 除外，见下），只换下面这些名字：

| 系列 0.2 | 系列 0.3 | 种类 |
|---|---|---|
| `$GND` | `$GROUND` | 定义 |
| `$IOPORT` | `$IO_PORT` | 定义 |
| `$NC` | `$NO_CONNECT` | 定义 |
| `$DIFFPAIR` | `$DIFFERENTIAL_PAIR` | 定义 |
| `$DIFFPAIR_TAIL` | `$DIFFERENTIAL_PAIR`，填上它的 `tail` | 定义 |
| `$MIRROR_PAIR` | `$MIRRORED` | 定义 |
| `$GND_STUB` | `$GROUND_STUB` | 定义 |
| `$GND_FILL_SET` | `$GROUND_FILL_SET` | 集合 |
| `$LABEL_TERM_SET` | `$LABEL_TERMINAL_SET` | 集合 |
| `$GROUND` | `$GROUND_SYMBOL` | 符号 |
| `$SUPPLY_BAR` | `$SUPPLY_SYMBOL` | 符号 |
| `$PORT_TAG` | `$IO_PORT_SYMBOL` | 符号 |
| `$NC_CROSS` | `$NO_CONNECT_SYMBOL` | 符号 |
| `$JUNCTION_DOT` | `$JUNCTION_SYMBOL` | 符号 |
| `$CURRENT_ARROW_SYM` | `$CURRENT_ARROW_SYMBOL` | 符号 |
| `$ARROW_HEAD` | `$ARROW_SYMBOL` | 符号 |
| `$RES` | `$RESISTOR` | 符号 |
| `$CAP` | `$CAPACITOR` | 符号 |
| `$IND` | `$INDUCTOR` | 符号 |
| `$VSRC` | `$VOLTAGE_SOURCE` | 符号 |
| `$ISRC` | `$CURRENT_SOURCE` | 符号 |
| `$NMOS4` | `$NMOS_4TERM` | 符号 |
| `$PMOS4` | `$PMOS_4TERM` | 符号 |

`$GROUND` 两个系列都有，含义不同：在 0.2 里是地的符号，在 0.3 里是地这个定义，即 0.2 的 `$GND`。所以文件先改 `$GROUND`，再改 `$GND`，而且只改整个名字：`$GND_STUB` 里的 `$GND` 不是一个名字。

**名字没变、画法或含义变了的**：

- `$VCVS`、`$VCCS` 只画输出的两个端子。四个端子都画的符号是 `$VCVS_4TERM`、`$VCCS_4TERM`，E、G 元件和 Spectre 的 master `vcvs`、`vccs` 默认配它们。文件自己给元件配 `$VCVS` 或 `$VCCS` 的，这个元件现在只有两个引脚，接到它第 3、4 端子的导线失效（9.2.4）；文件应改配带 `_4TERM` 的符号。
- 符号照 Analog Canvas 的重画了，许多符号的引脚换了位置：`$RESISTOR` 这样的两端元件，两个引脚相距 4，不是 6；二极管横着放；`$OPAMP` 的 + 输入，即端子 1，在上方。线宽是 0.16，0.2 画的是细线。为 0.2 的符号写回的位置和走线因此可能对不上引脚；这样的文件要重新求解，或钉住系列 0.2。
- `$DIFFERENTIAL_PAIR` 多了第三个角色，集合角色 `tail`，可以不填，所以照 0.2 写的差分对含义不变。
- `$CURRENT_MIRROR` 的两个角色都是集合角色：有几个参考管或输出管的电流镜是一个用例，而 `#M3(ref) {#M4 #M6}(out)` 在 0.2 是两个用例。
- `$CHAIN` 的集合角色 `series` 改叫 `chain`。
- `$DIFFERENTIAL_PAIR` 体里一条优先级为 `"low"` 的约束把尾管放在两管中间（9.5），所以没摆尾管的文件，画出来和 0.2 不同；`%dp1 @PRIORITY("disabled")` 能单独关掉一对（14.8）。
- 标准包的定义体里的约束，优先级一律是 `"low"`（9.5）。`$MIRRORED` 让 a 在 b 的左边（14.7）；`$BRANCH` 让成员同一列，`$CHAIN` 让源、链条、负载从左到右。
- `$CASCADE` 的四个角色都是集合角色：由几个对象组成的一级是一个集合，而 `{#RZ #CC}(feedback)` 在 0.2 是每个成员各一个用例。
- `$OPAMP` 不在 `rnl-std` 里了，在 `rnl-std-functional` 里；文件在头段记录里写这个包，单写或经 `rnl-std-full` 都可以（16.3）。
- `$GROUND_STUB`、`$SUPPLY_STUB` 只给离引脚的最小距离 `gap`，不再是确定的距离，求解器可以把导线画得更长；它们还让地朝下、电源朝上，`@ORIENT("R0")`；这些优先级都是 `"low"`（10.5）。
- 补位不在地网络和电源网络上加端口符号；0 以外的地网络（如加进 `$GROUND_NET_SET` 的 vss）上的地用 `$NAMED_GROUND_SYMBOL` 画，它标出网络名（10.5）。
- 系列 0.2 没有配专门符号的元件，现在默认有了：S 配 `$VOLTAGE_CONTROLLED_SWITCH`，W 配 `$SWITCH`，B 配 `$BEHAVIORAL_SOURCE`，SPICE 的 F、H、J、Z、T、O、U 也配了各自的符号，Spectre 里这些元件的 master 同样，如 `relay`、`switch`。

**去掉的**：`$INPUT_STAGE`：把它的尾管写进对应差分对的角色 `tail`，如 `#M1(in_p) #M2(in_n) #M5(tail) @AS $DIFFERENTIAL_PAIR`。`$TAIL_CENTER`：标准包自己会把每个差分对的尾管放在中间；要让别的对象居中，文件自己写一个定义，如 9.4 的 `$TAIL_MID`。`rnl-std-semantics` 和 `rnl-std-layout`：合成了一个包 `rnl-std-structures`（16.3）；原来去掉 `rnl-std-layout` 来不要默认布局的文件，改为对每个定义写一条规则，如 `# @SELECT-USAGE $MIRRORED => @PRIORITY("disabled")`（14.8）。

**新加的**：`rnl-std-basic`、`rnl-std-semiconductors` 加了符号，如开关、电流控制的源、传输线、JFET。系列还加了 `rnl-std` 不带进来的包：`rnl-std-functional`、`rnl-std-rf`、`rnl-std-logic`、`rnl-std-signal-flow`，把它们和 `rnl-std` 合在一起的集合 `rnl-std-full`，以及可选的 `rnl-std-no-labels`（16.3）。文件自己定义了、系列 0.3 又新加的名字，如 `$SWITCH`，遮蔽标准包的那个并给提示（6.8），文件用的仍是它自己的。

**修订 2**：编辑性的修订，语言没有改动。1.3 和 5.9 的例子写上了晶体管的模型卡 `.model nch nmos level=1`，让标准包认得出它们的极性、给它们符号。
