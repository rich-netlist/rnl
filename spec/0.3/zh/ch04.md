## 4 文法

### 4.1 文法

记录的文法用 EBNF 给出。每条产生式写作 `name = expression ;`；`|` 分开各个选项，`[ … ]` 是可选的，`{ … }` 重复零次或多次，`( … )` 分组，双引号里的文字照原样写，`(* … *)` 是注释。

```ebnf
record         = "@RNL" [ parameters ] set ;          (* the bracket touches "@RNL" *)
set            = "{" [ member ] { ";" [ member ] } "}" ;
member         = [ front-naming ] segment { naming } { "=>" segment { naming } } ;
front-naming   = ( "%" rnl-name | "$" rnl-name ) "=" ;
naming         = "=>" ( "%" rnl-name | "$" rnl-name ) ;
segment        = argument { argument } [ call { argument } ]
               | call { argument } ;
call           = keyword [ parameters ] ;          (* the bracket touches the keyword *)
keyword        = "@" keyword-name ;                (* upper case, or a declared alias *)
argument       = object [ "(" role-label ")" ] ;   (* the bracket touches the object *)
object         = reference | placeholder | point | set ;
reference      = "#" [ host-name [ subscript ] ] path
               | "&" host-name [ subscript ] path
               | "%" rnl-name path
               | "%#" integer path                (* a number, in a record of the solver, 5.9 *)
               | "$" rnl-name ;
placeholder    = "?" rnl-name path
               | "?" ;                             (* alone, in a symbol body *)
path           = { ":" terminal-name [ subscript ] | "::" rnl-name } ;
subscript      = "<" subscript-item { "," subscript-item } ">"
               | "[" subscript-item { "," subscript-item } "]" ;
subscript-item = integer [ ":" integer [ ":" integer ] ] ;   (* unsigned, 6.11 *)
host-name      = name | string ;
rnl-name       = name | string ;
terminal-name  = name | string ;
role-label     = bracket-name | string ;
point          = "(" coordinate "," coordinate ")" ;   (* after white space, a comment, "{", ";", "=>" or "=", 3.8 *)
coordinate     = number | "_" | parameter-placeholder ;
parameters     = "(" [ value { "," value } [ "," named-value { "," named-value } ]
                     | named-value { "," named-value } ] ")" ;
named-value    = parameter-name "=" value ;
parameter-name = bracket-name | string ;
value          = number | string | "true" | "false"
               | "[" [ value { "," value } ] "]"
               | parameter-placeholder ;
parameter-placeholder = "?" rnl-name ;
```

- `name`、`bracket-name`、`keyword-name`、`string`、`number` 和 `integer` 的写法见第 3 章。`name` 是不加引号的名字（3.6）。`bracket-name` 是角色括号里或参数的 `=` 前面不加引号的名字：由 ASCII 字母、数字、`_` 和任何非 ASCII 字符组成，不以 ASCII 数字开头（3.6）。`keyword-name` 由字母、数字和 `_` 组成，词间用 `-` 连接；`-` 后面跟字母时才属于它（3.3）。标准关键字是大写的（3.6）；代称由任何文字的字母、数字和 `_` 组成，不含 `-`（16.5）。`string` 和 `number` 见 3.7；`integer` 是不带符号的十进制整数。
- `rnl-name`、`host-name`、`terminal-name`、`role-label` 和 `parameter-name` 也可以加引号，含义相同，只是在角色名和参数名的位置上，加引号的名字永远不是代称（3.6）。关键字、参数名、角色括号里的槽位名、子对象名、`true` 和 `false` 可以写成声明过的代称；不加引号的非 ASCII 代称只用在 `@` 后面和括号里，`::` 后面的代称加引号（16.5）。
- 下标直接跟在宿主名字或端子名后面，中间不能有空白；下标里可以写空白和注释（3.5、6.11）。哪些名字收下标，见 4.2 第 10 条。
- 参数括号紧贴关键字，角色括号紧贴对象；隔了空白或注释的 `(` 开始一个点（3.5）。
- `=>` 是管道还是命名，看它后面是什么（4.2 第 3 条）。
- 带名字的空位只写在普通定义的体里（6.10）。在对象的位置上，它是一个角色，可以带路径；在收字面量的位置上（参数的值、数组的元素、点的坐标），它是定义的一个参数，不带路径（6.10、9.4）。单独的 `?` 只写在符号体里（13.3）。
- 自由文本和注释可以写在括号外任意两个记号之间，也可以写在成员开头（3.3、3.4）；空白和注释也可以写在括号里。文法里不写出它们。
- 空成员（如 `;;`）忽略；最后一个成员之后的 `;` 可以省略。

### 4.2 文法之外的约束

1. 段不能为空。
2. 一段至多一个关键字。`@RNL` 只出现在记录开头。
3. 一个 `=>`，后面是一个 `%` 或 `$` 名字，再往后是 `=>`、`;`、`}` 或成员结束时，它是命名。别的 `=>` 都开始下一段；那一段恰好有一个关键字，写在那里的名字是那一段的对象。管道的第一段可以没有关键字，这时它恰好有一个对象。所以要先给结果起名、再接着管道，写 `=> %g0 => @PLACE(1, 2)`。在 `=> %g0 @PLACE(1, 2)` 里，`%g0` 是 PLACE 的对象；它通常没有绑定，这条语句因为找不到 `%g0` 而失效。诊断可以问是不是漏了 `=>`。
4. 没有关键字的段里，每个实参各是一条语句：`{#M1 #M2}` 里的 `#M1 #M2` 是两条语句。这样的段带命名时（`%p =` 或 `=> %p`），只能有一个对象：写 `%p = {#M1 #M2}`，不写 `%p = #M1 #M2`。
5. 角色只标在有关键字的段的实参上。管道后面的段不标角色。
6. 一段里的实参要么全部标角色，要么全部不标。同一个角色只标一次。
7. 收定义的关键字，定义的槽位由关键字定：ATTACH 的定义是写出的第一个对象；AS、SET-SYMBOL、SET-STYLE、SELECT-USAGE 和 SELECT-ANCESTOR-USAGE 的定义是最后一个对象。SELECT-USAGE 可以省略它的定义：最后一个对象是定义时，才填定义的槽位（10.1）。定义不标角色，也不计入第 6 条（5.6）。
8. 命名有两种写法，可以并用。`name =` 只能是成员的第一个记号（前面可以有自由文本），一个成员至多一个。`=> name` 跟在段后面，在成员末尾，或在下一段的 `=>` 之前，一个成员可以有几个。第 3 条把它与管道分开。
9. 按位置写的参数在前，写名字的在后：写了一个 `name=value` 以后，后面的参数都写名字。只有签名里列了位置次序的参数可以按位置写，按那个次序写。同一个参数不写两次。
10. 下标只跟在 `#` 或 `&` 后面的宿主名字之后，或 `#` 引用里的端子名、端口名之后。RNL 名字、用例的端子名（角色名）和子对象名不收下标（6.11）。
11. 一个引用里至多一处下标展开成一组名字（6.11）。

### 4.3 语序

- 关键字连同参数可以放在对象之间的任何位置；对象之间的先后有意义。`#M1 #M2 @DISTANCE(…)`、`#M1 @DISTANCE(…) #M2`、`@DISTANCE(…) #M1 #M2` 相同。
- 每个关键字有一种标准写法，工具应只写这一种。标准写法记在标准词表里（5.3）：关键字放在哪里，哪些参数按位置写、哪些写名字，标不标角色。
- 默认的标准写法是：对象在前，然后是关键字和参数，定义写在关键字后面。ATTACH 先写定义，再写关键字，再写对象：`$GROUND @ATTACH &vss`。签名里列了位置次序的参数按位置写，写在前面；其余的写名字，按标准词表的次序：`@PLACE(10, 20)`、`@ORIENT("R90")`、`@DISTANCE("bottom-to-top", min=4)`、`@TEXT("W/L", key="wl")`。PLACE 只在两轴都写时按位置写 x 和 y；只写一轴时写名字，如 `@PLACE(x=10)`。去掉也不改变含义的参数不写，如 WIRE 的 `mode="auto"`。内置关键字不标角色；普通定义有两个或更多角色时，AS 和 ATTACH 标出全部角色。
- 版面：括号里每个逗号后空一格；参数的 `=` 两边不空；命名的 `=` 和 `=>` 两边各空一格；关键字紧贴它的括号；`{` 和关键字之间空一格，如 `{ @…`（2.3）；数写成能读回同一个值的最短的十进制。
- **命名的标准写法。** 没有管道的成员在开头命名，`%x = statement`；有管道的成员在末尾命名，`statement => … => %x`，名字跟在它所命名的那一段后面。这样开头的名字总是给整个成员起名，读的人不用猜它指管道的哪一段。文法两种写法都收。
- "只写这一种"指工具新写的语句。工具改写已有的记录时，不应重排用户写的语句（16.4）；只在用户要求格式化时，才把它们改成标准写法。
- 标准例句见 4.5。

### 4.4 错例

下面每一条都是错误；注释说明原因。

```rnl error
#M1 @PLACE (10, 20)    /* a bracket after white space is a point, and PLACE has no parameters (3.5) */
```

```rnl error
#M1 (in_p) #M2 (in_n) @AS $DIFFERENTIAL_PAIR    /* role brackets touch the object; a separate bracket is a point (3.5) */
```

```rnl error
#M2 @PLACE(62, 40) (MY)    /* the second bracket is a point, and its content is not a point */
```

```rnl error
&vss @ATTACH $GROUND    /* the definition of ATTACH is written first: $GROUND @ATTACH &vss */
```

```rnl error
R1 -> R2 {#R1 #R2} @ORDER("x")    /* ">" cannot be free text (3.3) */
```

```rnl error
#M1 @PLACE(1, 2), #M2 @PLACE(3, 4)    /* a comma does not separate statements: two keywords in one segment */
```

```rnl error
#M1 #M2 @SET-SYMBOL $NMOS    /* three objects, and SET-SYMBOL has two slots (5.2.1); write {#M1 #M2} @SET-SYMBOL $NMOS */
```

```rnl error
#M1 => #M2    /* the segment after a pipe has no keyword */
```

```rnl error
#M1 #M2 #M3 @DISTANCE("x", min=1)    /* three objects for two slots */
```

```rnl error
#M1 @PLACE(x=10, 20)    /* a parameter given by position after one given by name (4.2 item 9) */
```

```rnl error
{#M1 #M2} @ORDER(axis="x", direction="increasing")
/* ORDER has no axis: the axis and the direction are one parameter, direction, as in @ORDER("left-to-right") (14.3) */
```

```rnl error
#M1 @SET-SYMBOL($NMOS)    /* brackets hold only literals */
```

```rnl error
{#M1 #M2} @ALIGN(axis=y)    /* enumerations are written as strings */
```

```rnl error
%ax = (_, _);
#M1(a) #M2 %ax @AS $MIRRORED    /* roles are marked on all objects or on none */
```

```rnl error
$NMOS(symbol) #M1(target) @SET-SYMBOL    /* the definition is written last and is not marked with a role */
```

```rnl error
#R1(source) #R2(chain) #R3(chain) #R4(load) @AS $CHAIN    /* the same role is marked twice */
```

```rnl error
(0, 0) @PIN(terminal=1)    /* a pin cannot be written in the scene (13.4) */
```

```rnl error
#M1 @CURRENT("in")    /* CURRENT takes only terminals (15.2) */
```

```rnl error
&D<1:0>[1:0]    /* a name has at most one subscript (6.11) */
```

```rnl error
#XI0<1:0>:D<1:0>    /* one reference has at most one expansion (6.11) */
```

```rnl error
&D<_, 1>    /* a "<" directly after a name starts a subscript, and its content is not a subscript (3.5) */
```

```rnl error
%p<1, 2>    /* RNL names take no subscript; a point is written (1, 2) (6.11) */
```

### 4.5 标准例句

标准例句是用标准写法写、在记号之间加上自由文本、读起来像一句话的语句。标准例句用于写作参考，也用于格式化工具给语句加词或去词。自由文本不影响含义（3.3）：例句只是建议，用户和语言模型可以照写，也可以不写，或写别的词。

- **读作事实。** 语句说的是图上成立的事实，不是要做的操作。对象在前当主语，关键字当谓语或名词，参数是它的值。只加连接的词，如英文的 `is`、`are`、`has`、`is at`、`there is`，中文的 `是`、`处于`、`位于`、`有`、`的`、`按……排列`。少数语句也可以读作操作，如 `#M1 @SET-SYMBOL to $NMOS`。
- **词由语句算出。** 工具生成的词只取决于关键字、参数、对象的个数和种类、语句写在哪一层，不取决于电路的意思。例如写 `is` 还是 `are` 按对象的个数；只给一轴时写 `the x of`（`x 坐标`）；选择的候选的说法按范围和要选的种类（附录 B）。这是生成例句的办法，不限制用户。
- **不写像有含义、其实语句没有这个含义的词。** 不写 `must`、`required`、`only`（`必须`）这类词；方向词只在参数有这个方向时写。读的人会相信句子里的词，建议写作参考提醒他们注意这一点。
- **补一句。** 读的人未必懂朝向码和轴。可以在关键字后面用 `, i.e., …`（`，即……`）说出代码本身的意思，如 `#M2 @ORIENT("MX"), i.e., flipped upside down`、`#M2 @朝向("MX")，即上下镜像`。
- **ORIENT-RELATION 和 DISTANCE** 有两个槽位，读作 `from A to B`（`A 到 B`）；中文里 ORIENT-RELATION 接 `的`，DISTANCE 接 `有`。方向只是一个轴（`"x"` 或 `"y"`）的 DISTANCE 读作 `between A and B`（`A 和 B 之间有`）。
- **选择**一律读作在候选里选：英文是 `among <candidates>, @SELECT-…`，中文是 `从<候选>中 @选出…`。范围是 `#` 时，候选读作 `the <kind> at each level in # and below`（本层 # 及以下每一层的<种类>），说出规则在每一层各求一次值（10.4）。种类算不出时，读作 `for X,`（对于 X，）。
- **AS 与 ATTACH。** 对象合起来构成这个东西时用 AS：`#M1(in_p) and #M2(in_n) are treated @AS $DIFFERENTIAL_PAIR`。这个东西添在对象上时用 ATTACH：`$GROUND is @ATTACH to &vss`（9.4）。
- **管道。** 后一段指前一段的结果。英文用 `it`（前一段是 AS、ATTACH 或单个对象时）或 `they`（前一段是选择时）；中文一律用 `其`，与别的对象并列时写 `其与`。管道里的名字前面写 `named`（`记作`），如 `… => named %pout`（`… => 记作 %pout`）；它照样是命名（4.2 第 3 条）。
- **命名。** 单条语句的名字写在开头（4.3）。给 AS 的语句起名时，英文去掉 `are`：`%dp = #M1(in_p) and #M2(in_n) treated @AS $DIFFERENTIAL_PAIR`。
- **集合的名字。** 指集合的名字建议以 `_SET`（`$` 名字）或 `_set`（`%` 名字）结尾，中文以 `集` 结尾，如 `$GROUND_FILL_SET`、`%bias_set`、`%"接地补位集"`；标准包照此命名。
- **不写 `each`。** 不写 `each`（`每一个`）这类词。一个集合是整个套用还是逐个成员套用，要看定义的角色表，标准例句不说是哪一种。
- **中文。** 中文例句用代称包 `rnl-zh` 的代称（16.5）。中文逗号后面接 `@` 时仍要空一格（2.3）。
