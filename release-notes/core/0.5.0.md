# RNL core 0.5.0

The `rnl` command and the npm package `@rich-netlist/runtime` 0.5.0, built from the same core.
RNL Viewer 0.5.0 is released alongside it under `viewer-v0.5.0`; the language standard is
unchanged at 0.3.

## What is new

- **A role takes every kind name of 9.4** ([#223](https://github.com/rich-netlist/rnl/pull/223)).
  A definition's role can be declared with any of the ten kinds of the word list (5.3):
  `instance`, `terminal`, `net`, `point`, `wire`, `usage`, `bundle`, `text`, `annotation` and
  `label`. The core knew only the first six and failed the other four with "unknown kind name …
  (9.4)", so every statement that applied such a definition failed too. What the new kinds take:
  - `text`: every TEXT;
  - `label`: a TEXT attached to an object, such as `#R1::name`;
  - `annotation`: a TEXT attached to a point, and the graphics (5.1);
  - `bundle`: a bundle. A role declared `bundle` used to refuse bundles, as they were compared as
    `instance`; `instance` still takes bundles, and `terminal` their terminals (11.8).
- **A usage's parameters in the snapshot** ([#221](https://github.com/rich-netlist/rnl/pull/221)).
  The editor interface's snapshot (`rnl snapshot`, and `snapshot()` of the npm package) gives each
  usage the parameters that the statement applying it writes (9.4), as `params`:
  - only those written at the statement, in the order of the definition, without its defaults;
  - each value of the type it is written in: a string as written, a number, a truth value, or a
    list of them. Numbers are written as every number of the snapshot is, as floats: `drop=2`
    gives `2.0`;
  - no `params` for a usage that writes none, or for an instance, so every other snapshot is
    unchanged. The TypeScript declaration of the snapshot has the new field.
- **Display settings in manifests** ([#220](https://github.com/rich-netlist/rnl/pull/220),
  [#224](https://github.com/rich-netlist/rnl/pull/224)). The manifest module,
  `@rich-netlist/runtime/manifest`, reads and writes a manifest's `display`: the view of its level
  (fitted, or a centre and a scale), the background, colours by the viewer's names, whether usages
  and current directions are shown, and the grid. A reader gives the settings it reads as
  `display`, and names in `displayIgnored` those a viewer will not apply: those of another shape,
  left out, and those it does not know, kept as they are so that writing the manifest again loses
  nothing. A colour is kept as the manifest writes it. RNL Viewer offers the settings and applies
  only those the user keeps.

## Other changes

- The diagnostic for an alias of a `$` name gives an English example,
  `@ALIAS("$DP", "$DIFFERENTIAL_PAIR")` ([#232](https://github.com/rich-netlist/rnl/pull/232)).

## For users of 0.4.1

- Netlists read and draw as before. A definition whose role names `text`, `label`, `annotation` or
  `bundle` used to fail and now applies; nothing that passed before fails now.
- A snapshot's usages may have a new key, `params`; a reader that ignores keys it does not know
  sees no change.
- A manifest without `display` reads as before.

`npm i @rich-netlist/runtime` installs 0.5.0 under the dist-tag `latest`.

Linux on arm64 is not built yet; build the command from the source there.

## Not signed

The executables have no code signature. Windows may show a SmartScreen warning. On macOS, a file
downloaded with a browser may need `xattr -d com.apple.quarantine rnl` after it is extracted
before it runs. Check each download against `SHA256SUMS.txt` first.
