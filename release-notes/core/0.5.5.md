# RNL core 0.5.5

The `rnl` command and the npm package `@rich-netlist/runtime` 0.5.5, built from the same core.
RNL Viewer 0.5.3 is released with it; the language standard is unchanged at 0.3. The solver stays
at 0.1.

## What is new

- **The parameters of subcircuits are in the Document** ([#340](https://github.com/rich-netlist/rnl/pull/340)).
  A viewer can now show a subcircuit with the values its instance gives it, or with values typed
  into a dialog. Nothing drawn changes: `${w}` still shows what is written (13.6), and the numbers
  are for showing only.
  - A subcircuit level lists its formal parameters, `Level.params`, each with its default as
    written, the value it has, the number that comes to, and where the value comes from: `"bound"`,
    `"default"` or `"unset"` (no default and no value).
  - An instance lists the parameters it writes, `Child.params`, evaluated in the level the
    instance is in; also when the subcircuit is not defined. When it is defined, `Child.effective`
    lists the subcircuit's parameters for this instance: those the instance writes
    (`"instance"`) and the defaults of the others, evaluated with them.
  - A build can bind values to a subcircuit's parameters, for showing. They are text, such as
    `2u`, `1e-06` or `{2*l}`, and only these lists change; nothing is remembered. A bound name that
    is not a parameter of the subcircuit is a warning, with the closest name when there is one, as
    is a subcircuit the netlist does not define; parameters whose defaults refer to each other
    have no number and a hint says so.
  - The host adapters read the formal parameters of `.subckt` (after `params:`, or without it as
    HSPICE writes them, with `+` lines) and `.param` statements in SPICE, and `parameters` in
    Spectre; they still evaluate nothing. The core evaluates numbers: scale factors (SPICE
    without case, with `meg` and `mil`; Spectre with case, `M` for mega), `+ - * / ^ **`,
    parentheses, unary signs, common functions, and `{…}` and `'…'`. Anything else has no number
    and no diagnostic. A name is looked up in the bound or given values, then the subcircuit's
    defaults and `.param`s, then the subcircuits it is written in, then the files' values.
  - **`rnl view --bind SUBCKT [--param NAME=VALUE]...`** builds the Document with those values.
    No other command takes the options.
- **An instance of a subcircuit that Auto Include found defined several times lists the
  definitions** ([#338](https://github.com/rich-netlist/rnl/pull/338)). Auto Include still
  includes none of them, so the instance has no level, but `Child.candidates` now lists them, in
  the Library index's order: the Library file that would be included, the file that defines it,
  how that file is shown, and the line. Two definitions in one file are told apart by the line.
  Every instance of that subcircuit has the list, by the dialect's rule for names (SPICE without
  case, Spectre with it). A viewer can offer the choice.
  The warning is reworded, and its severity is unchanged: it was
  `Auto Include: subcircuit X has conflicting definitions in a, b; add an explicit include to choose one`
  and is now
  `Auto Include: subcircuit X is defined 2 times in the Library (/a.inc:1, /b.inc:1); enter the instance to choose one, or add an explicit include`.
  It counts definitions, not files, so it holds when one file defines the subcircuit twice.

## Additions to the npm package

Everything here is new; no field is removed or changed, and the snapshot (`snapshot.d.ts`) is
unchanged.

The Document (`document.d.ts`) gains, all left out of the JSON when empty, so the Document of a
netlist with no parameters and no several definitions is what it was:
- `Level.params?: SubcktParam[]`: on every subcircuit level that has parameters, also one that
  nothing calls;
- `Child.params?: ParamValue[]`: the parameters the instance writes;
- `Child.effective?: SubcktParam[]`: the parameters for this instance, when its subcircuit is
  defined;
- `Child.candidates?: AutoIncludeCandidate[]`: the definitions Auto Include found, when there are
  two or more and it included none;
- the types `SubcktParam` (`name`, `default`, `value`, `number`, `from`: `"bound"`, `"instance"`,
  `"default"` or `"unset"`), `ParamValue` (`name`, `value`, `number`) and `AutoIncludeCandidate`
  (`path`, `file`, `source`, `line`).

The request (`core.d.ts`) gains `bind?: { subckt: string; params?: Record<string, string> }`.

## For users of 0.5.4

- Netlists read and draw as before; `${…}` and 13.6 are unchanged.
- A tool that matched the text of the Auto Include warning, `has conflicting definitions`, must
  match the new text. The warning is still a warning.
- `rnl view` takes two more options; the other commands are as they were.

## Not signed

The executables have no code signature. Windows may show a SmartScreen warning. On macOS, a file
downloaded with a browser may need `xattr -d com.apple.quarantine rnl` after it is extracted
before it runs. Check each download against `SHA256SUMS.txt` first.
