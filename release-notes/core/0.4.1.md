# RNL core 0.4.1

The `rnl` command and the npm package `@rich-netlist/runtime` 0.4.1, built from the same core.
RNL Viewer 0.4.1 is released alongside it under `viewer-v0.4.1`; the language standard is
unchanged at 0.3.

## What is new

- **A hint for a subcircuit no file defines** ([#213](https://github.com/rich-netlist/rnl/pull/213)).
  When an instance's subcircuit is defined in no file read and nothing gives it a symbol, so it is
  drawn as the renderer's box of its terminals (9.2.6), the core now says so: one hint per level
  and per subcircuit, at its first instance, naming the instances drawn so (at most eight, then
  "and N more"):

  ```
  hint t.sp:5:1: no file read defines the subcircuit L3_CDAC_V1, so X1, X2 are drawn as a box of its terminals; an include may be missing (6.4, 9.2.6)
  ```

  - A subcircuit that a rule, a package or `@SET-SYMBOL` gives a symbol, such as a PDK device
    (6.4), is not told, so PDK netlists do not fill up with hints.
  - It is a hint, as the core's other advisory diagnostics: nothing fails, and `rnl check` passes.
    `rnl check`, RNL Viewer on the desktop and on the web, and the npm package all give it.
- **Manifests in the npm package** ([#209](https://github.com/rich-netlist/rnl/pull/209),
  [#211](https://github.com/rich-netlist/rnl/pull/211)). `@rich-netlist/runtime/manifest` reads
  and writes the manifest format that RNL Viewer uses for external manifests (`?manifest=`),
  projects (`rnl-project.json` in a ZIP archive) and manifests of links, and that the RNL gallery
  writes for its designs:
  - `readManifest(url)` fetches a manifest and its files, checks each file against the SHA-256 and
    size of its bytes, and gives what a build takes: `entry`, `files`, the `pool` in its order and
    the `formats` chosen, under one workspace directory, with the `level` to show.
  - `loadManifest(json, { readFile })` reads a manifest already parsed, such as a project's, whose
    files come from its archive; `writeManifest(...)` writes one, and checks it as a reader does;
    `checkManifest` checks one; `ManifestError` names the file at fault.
  - Addresses are https (http only on the local machine); a fetched manifest holds at most 300
    files, 2 MB each and 20 MB in all, and a project's archive at most 5000 files and 1 GiB, or
    less where the caller says (`limits`).
  - The module imports nothing else of the package and runs in Node 18 and later and in browsers.

## Fixes

- **Structures in files that use `rnl-std-no-labels`** ([#215](https://github.com/rich-netlist/rnl/pull/215)).
  Every netlist that Analog Canvas writes uses the standard package `rnl-std-no-labels`, which
  empties the default labels with a rule, `# @SELECT-USAGE => @TEXT("", key="name")` (and `value`,
  `model`). By 10.4 that rule gave a TEXT to every usage, so a file that added a structure usage
  (`$MIRRORED`, `$DIFFERENTIAL_PAIR`, `$FLOW`, `$CURRENT_MIRROR`, `$BRANCH`, …) failed its check
  with `a usage of $MIRRORED has no symbol and no drawing meaning: this TEXT fails (12.1, 13.3)`.
  Now **a TEXT that a rule gives through a selection, landing on a usage without a symbol or a
  terminal without a pin, does nothing and gives no diagnostic.** A TEXT written for the object
  itself still fails, at its own place, so a mistake in writing stays visible; a usage with a
  symbol, such as a port, still has its default label emptied by the package.
  - **This departs on purpose from the text of 0.3**, where 13.3 makes any such TEXT fail. It
    follows what 8.3 already says of SET-STYLE on a semantic usage, for the same reason. The
    departure is recorded in `docs/supported-profile-0.3.md`, under "Deliberate departures from
    the text of 0.3"; the published standard is unchanged, and the language takes it up for 0.4.

## For users of 0.4.0

- Netlists read and draw as before. A netlist with instances of subcircuits that no file defines
  now has hints for them; a tool that counts diagnostics of every severity sees more.
- A netlist that failed only because a rule's TEXT reached a usage without a symbol now passes and
  draws; nothing that passed before fails now.
- The manifest module is an addition; the rest of the npm package is unchanged.

Linux on arm64 is not built yet; build the command from the source there.

## Not signed

The executables have no code signature. Windows may show a SmartScreen warning. On macOS, a file
downloaded with a browser may need `xattr -d com.apple.quarantine rnl` after it is extracted
before it runs. Check each download against `SHA256SUMS.txt` first.
