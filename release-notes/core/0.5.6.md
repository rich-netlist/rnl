# RNL core 0.5.6

The `rnl` command and the npm package `@rich-netlist/runtime` 0.5.6, built from the same core.
It is the last core of 0.5.x and the last that reads and writes the language 0.3: it reads the
language 0.4 beside 0.2 and 0.3, and `rnl upgrade` turns a file of 0.2 or 0.3 into 0.4. RNL
Viewer is not released with it and stays at 0.5.3. On npm it is published with the dist-tag
`legacy-0.3`: `latest` does not move, and stays at 0.5.5 until 0.6.0.

## The language 0.4

- **Files of the language 0.4 are read, with the standard series 0.4** ([#382](https://github.com/rich-netlist/rnl/pull/382), [#468](https://github.com/rich-netlist/rnl/pull/468), [#492](https://github.com/rich-netlist/rnl/pull/492)).
  A file says `@VERSION("0.4")`; files of 0.2 and 0.3 read as before, and the series of a file
  follows its version. A file of 0.4 loads the standard packages it uses with `USE-PACKAGE`
  ([#433](https://github.com/rich-netlist/rnl/pull/433)).
- What 0.4 adds that a user writes, among others:
  - usages with points of their own, and body coordinates relative to them ([#401](https://github.com/rich-netlist/rnl/pull/401)); a usage
    without a symbol among the items of a constraint stands for its members, `%u::position` names
    its own point, and `::position` of a set is the position of each member ([#704](https://github.com/rich-netlist/rnl/pull/704));
  - constraint items expanded into independent facts, one for each combination, a combination
    that takes one object twice left out ([#399](https://github.com/rich-netlist/rnl/pull/399), [#704](https://github.com/rich-netlist/rnl/pull/704)); directions written in DISTRIBUTE, ORIENT and
    ORIENT-RELATION as lists ([#394](https://github.com/rich-netlist/rnl/pull/394)); DISTANCE bounds that are not negative ([#398](https://github.com/rich-netlist/rnl/pull/398));
  - pins as objects of their own, with names, and selections of terminals and of drawing pins
    ([#405](https://github.com/rich-netlist/rnl/pull/405), [#416](https://github.com/rich-netlist/rnl/pull/416), [#418](https://github.com/rich-netlist/rnl/pull/418)); a nested TABLE as one geometric fact ([#442](https://github.com/rich-netlist/rnl/pull/442)); the spacing of a group ([#443](https://github.com/rich-netlist/rnl/pull/443));
  - commands that format names in a text ([#395](https://github.com/rich-netlist/rnl/pull/395)); formulas with upright runs and roots ([#434](https://github.com/rich-netlist/rnl/pull/434));
  - empty nodes and wires to them ([#454](https://github.com/rich-netlist/rnl/pull/454)); junction dots drawn by a configured definition ([#445](https://github.com/rich-netlist/rnl/pull/445), [#447](https://github.com/rich-netlist/rnl/pull/447));
  - the modules of the Verilog-A files that `ahdl_include` or `.hdl` brings in give block symbols
    ([#546](https://github.com/rich-netlist/rnl/pull/546), [#554](https://github.com/rich-netlist/rnl/pull/554), [#555](https://github.com/rich-netlist/rnl/pull/555));
  - an instance with no symbol is drawn as a box ([#611](https://github.com/rich-netlist/rnl/pull/611)).
- **Assertions**: ASSERT-INSTANCE, ASSERT-TERMINAL, ASSERT-NET and ASSERT-TOPOLOGY (series,
  parallel, star, loop), checked after the geometry phase. A failed assertion is a **violation**,
  a fourth level of report between error and warning ([#387](https://github.com/rich-netlist/rnl/pull/387), [#391](https://github.com/rich-netlist/rnl/pull/391), [#392](https://github.com/rich-netlist/rnl/pull/392), [#453](https://github.com/rich-netlist/rnl/pull/453), [#539](https://github.com/rich-netlist/rnl/pull/539)).
  `rnl check` exits 1 on errors or violations.
- **The standard series 0.4**, in sixteen packages: `rnl-std-all`, which loads the others a
  drawing usually needs, `rnl-std-basic`, `rnl-std-semantics`, `rnl-std-functional`,
  `rnl-std-signal-flow`, `rnl-std-semiconductors`, `rnl-std-logic`, `rnl-std-rf`, `rnl-std-fill`,
  `rnl-std-style`, `rnl-std-45deg`, `rnl-std-spice`, `rnl-std-spectre`, `rnl-std-no-labels`,
  `rnl-std-no-instance-labels` and `alias-zh`. They bring new symbol families, upright
  transformers and diodes, and structures such as differential pairs, current mirrors, mirrored
  layouts, signal flows, branches, degenerated amplifiers, transmission gates and translinear
  loops; the fill gives each port net a port tag in one column, and stubs stand near their pins.
  `$BIAS`, `$IO_PORT` and `$NET_LABEL` no longer turn their pins ([#707](https://github.com/rich-netlist/rnl/pull/707)).

## Diagnostics

- **Every diagnostic has a kind: a number `RNLnnnn` and a short name** ([#383](https://github.com/rich-netlist/rnl/pull/383), [#385](https://github.com/rich-netlist/rnl/pull/385)), such as
  `RNL3120 param-wrong-type`. `rnl check` prints it after the place; the Document and the npm
  package carry it. No severity, place or message changed with it. A tool that matched message
  texts should match the kind.
- The geometry hints of a drawing (texts over texts, nets drawn in pieces, silent opens, nodes
  of more than 20 devices) are printed by `rnl check` and given to a Document when it asks for
  them ([#372](https://github.com/rich-netlist/rnl/pull/372), [#449](https://github.com/rich-netlist/rnl/pull/449), [#606](https://github.com/rich-netlist/rnl/pull/606), [#626](https://github.com/rich-netlist/rnl/pull/626), [#695](https://github.com/rich-netlist/rnl/pull/695)).

## Commands

- **`rnl upgrade FILE`** shows the migration of a file of 0.2 or 0.3 to 0.4; `-o DIR` or
  `--in-place` saves it, and `--report` writes a JSON report ([#404](https://github.com/rich-netlist/rnl/pull/404) and following). The upgraded file is
  read again and compared with the original, its objects, nets, positions and facts, and an
  upgrade succeeds only when nothing differs. A statement it cannot convert is kept with a comment
  that says why. `--approximate` allows replacements by polarity; `--keep-generated` keeps the
  solver's records and upgrades them instead of discarding them ([#415](https://github.com/rich-netlist/rnl/pull/415), [#544](https://github.com/rich-netlist/rnl/pull/544)). Changes of the
  standard package's default look are reported apart and do not fail the upgrade ([#552](https://github.com/rich-netlist/rnl/pull/552)). Files of
  `analog-canvas-extensions` 0.1 to 0.6 move to the published 0.7 ([#656](https://github.com/rich-netlist/rnl/pull/656)); instances drawn with the
  box of 0.3 keep it, as a symbol of the file ([#668](https://github.com/rich-netlist/rnl/pull/668)).
- **`rnl render --png`** writes a PNG image of each level, drawn with the fonts the command holds
  ([#393](https://github.com/rich-netlist/rnl/pull/393)); `--net-names` writes the name of each connected part of every net ([#615](https://github.com/rich-netlist/rnl/pull/615)).
- **`rnl replace-records FILE --level TITLE --records RECORDS`** puts a level's new drawing back
  into a netlist that has records ([#396](https://github.com/rich-netlist/rnl/pull/396)).
- **`rnl groups FILE`** prints the tree of groups of each level, with `--all`, `--json` and
  `--level` ([#695](https://github.com/rich-netlist/rnl/pull/695)).
- **`rnl solver-defaults`** prints the solver's defaults as RNL named parameters, for each layout;
  `--json` gives the table of settings, objectives and stages ([#585](https://github.com/rich-netlist/rnl/pull/585), [#640](https://github.com/rich-netlist/rnl/pull/640), [#669](https://github.com/rich-netlist/rnl/pull/669)).
- `rnl solve`:
  - `--progress=json` reports a solve as events ([#541](https://github.com/rich-netlist/rnl/pull/541)); `--check` prints the settings of each level and
    where each comes from ([#570](https://github.com/rich-netlist/rnl/pull/570)); `--profile OUT.json` writes the solver's timings and counters, each
    stage of the lines layout counted as its own ([#711](https://github.com/rich-netlist/rnl/pull/711));
  - `--respace` spaces a solved drawing wider without a new search, as `rnl preview --respace`
    does ([#577](https://github.com/rich-netlist/rnl/pull/577)); `--timeall` limits the whole file beside each level's own limit ([#595](https://github.com/rich-netlist/rnl/pull/595));
  - `--external-solver PROGRAM` runs a solver of one's own through a versioned JSON protocol,
    with `--external-arg` and `--external-timeout` ([#496](https://github.com/rich-netlist/rnl/pull/496)); the protocol is described in
    [docs/solver-protocol.md](https://github.com/rich-netlist/rnl/blob/core-v0.5.6/docs/solver-protocol.md);
  - a junction dot that cannot be placed costs only itself ([#601](https://github.com/rich-netlist/rnl/pull/601)); a level's limits bound the placement
    of its dots too ([#614](https://github.com/rich-netlist/rnl/pull/614)); the objects a level loses when its record is read back are named
    ([#616](https://github.com/rich-netlist/rnl/pull/616)); `--report` no longer spends a level's limit on the conflicts of facts of priority low
    ([#705](https://github.com/rich-netlist/rnl/pull/705)).

## The solver

- **The lines layout is the default for a level of 0.4** ([#513](https://github.com/rich-netlist/rnl/pull/513), [#580](https://github.com/rich-netlist/rnl/pull/580)); the rows and tree layouts
  remain. Its ranking of drawings is set by `lines_order` and `lines_weights` ([#660](https://github.com/rich-netlist/rnl/pull/660), [#681](https://github.com/rich-netlist/rnl/pull/681), [#685](https://github.com/rich-netlist/rnl/pull/685));
  `join_trees`, `reroute_nets` and `nudge_wires` are settings of their own ([#605](https://github.com/rich-netlist/rnl/pull/605), [#688](https://github.com/rich-netlist/rnl/pull/688), [#702](https://github.com/rich-netlist/rnl/pull/702)). A
  DISTRIBUTE kept stays even through the table ([#706](https://github.com/rich-netlist/rnl/pull/706)).
- Budgets of time and of work shared by a solve, replayable with the settings it reports
  ([#495](https://github.com/rich-netlist/rnl/pull/495), [#569](https://github.com/rich-netlist/rnl/pull/569)). `SOLVER-CONFIG` in a file's header reaches the levels of the files it includes,
  and a value that is not taken fails its own key alone ([#581](https://github.com/rich-netlist/rnl/pull/581), [#584](https://github.com/rich-netlist/rnl/pull/584)).
- A drawing that reads as joined where it is not never wins ([#627](https://github.com/rich-netlist/rnl/pull/627)); texts over texts count among
  the crowding ([#619](https://github.com/rich-netlist/rnl/pull/619), [#635](https://github.com/rich-netlist/rnl/pull/635), [#641](https://github.com/rich-netlist/rnl/pull/641)).
- The solver is still a preview, and its drawings may be poor; `rnl solve` says so.

## The npm package

- **The solver is in the package, as a WebAssembly module of its own** ([#579](https://github.com/rich-netlist/rnl/pull/579), [#593](https://github.com/rich-netlist/rnl/pull/593)):
  `import { loadSolver } from "@rich-netlist/runtime/solver"`, with `solver.wasm` beside it. Its
  `solve`, `settings` and `check` take the same settings as `rnl solve`, so a browser can solve.
- The request (`core.d.ts`) gains, all optional: `include_std`, which gives a main file of 0.4 the
  standard package ([#433](https://github.com/rich-netlist/rnl/pull/433)); `flylines`, lines between the connected parts of every net, off
  by default ([#362](https://github.com/rich-netlist/rnl/pull/362), [#368](https://github.com/rich-netlist/rnl/pull/368)); `hints`, the geometry hints ([#372](https://github.com/rich-netlist/rnl/pull/372)); and `constraints`, the
  constraints of each level after expansion and whether each fact holds on the drawing ([#345](https://github.com/rich-netlist/rnl/pull/345), [#347](https://github.com/rich-netlist/rnl/pull/347)).
  The last two are experimental.
- `replaceRecords` on the core and on the worker does what `rnl replace-records` does ([#396](https://github.com/rich-netlist/rnl/pull/396)).
- The edit interface (`write`) gains the operations `add-rule` ([#576](https://github.com/rich-netlist/rnl/pull/576), [#586](https://github.com/rich-netlist/rnl/pull/586)), `add-annotation` and
  `declare-device` ([#649](https://github.com/rich-netlist/rnl/pull/649)), `terminals` on `set` and on `add-usage` ([#568](https://github.com/rich-netlist/rnl/pull/568)), and `language_version`;
  a write of 0.4 that fails rejects with an `EditError`, which carries the kind of the
  diagnostic ([#438](https://github.com/rich-netlist/rnl/pull/438)).
- The Document (`document.d.ts`) gains, all optional: `Level.hints` and `Level.constraints`, a
  pin as an object (`Object.pin`), the registration point of each object (`Hit.origin`) ([#349](https://github.com/rich-netlist/rnl/pull/349)),
  where each usage stands in the tree of groups (`Usage.parent`, `group_parent`, and others)
  ([#533](https://github.com/rich-netlist/rnl/pull/533)), `Text.transform`, and the spacing of a group.
- The snapshot (`snapshot.d.ts`) gains what an exporter needs for 0.4 ([#575](https://github.com/rich-netlist/rnl/pull/575)): annotations
  (`AnnotationView`), the junction of a level (`JunctionView`), pins with names, the point a text
  at a point hangs on ([#485](https://github.com/rich-netlist/rnl/pull/485)), and the type of each host instance, `HostInstance.type`, from the
  host or DEVICE ([#670](https://github.com/rich-netlist/rnl/pull/670)).

## Host formats

- Spectre: an instance named `IF` or `Real` is an instance, not a directive ([#471](https://github.com/rich-netlist/rnl/pull/471)); keywords are
  lowercase, as the directives are ([#657](https://github.com/rich-netlist/rnl/pull/657)).
- A package lock may hold several versions of one package ([#486](https://github.com/rich-netlist/rnl/pull/486)).

## For users of 0.5.5

- Files of 0.2 and 0.3 read and draw as before: the conformance corpus of 0.2 and 0.3 gives the
  same drawings, with the kinds of the diagnostics added. The box drawn for an instance with no
  symbol is for files of 0.4 only.
- Diagnostics have kinds; a tool that matched message texts should match kinds ([#383](https://github.com/rich-netlist/rnl/pull/383)).
- A violation is a new level of report, and `rnl check` exits 1 on one.
- The types of the npm package changed in ways a TypeScript program may notice:
  - `PinView.at` in the snapshot may be `null`: a pin of 0.4 may have no place;
  - `Vertex` has a variant for a pin of an owner (`owner`, `pin`, `reference`), `Run` one for a
    root (`kind: "sqrt"`), and the write operations the new ones above: a `switch` that covers
    every case needs the new ones;
  - `Diagnostic.code` and `Diagnostic.name`, `Level.net_labels` and `HostInstance.type` are
    always given: code that builds these objects by hand, as a test does, must give them.
- To keep the language 0.3 after 0.6.0, install by exact version or with
  `npm i @rich-netlist/runtime@legacy-0.3`.

## Not signed

The executables have no code signature. Windows may show a SmartScreen warning. On macOS, a file
downloaded with a browser may need `xattr -d com.apple.quarantine rnl` after it is extracted
before it runs. Check each download against `SHA256SUMS.txt` first.
