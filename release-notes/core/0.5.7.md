# RNL core 0.5.7

The `rnl` command and the npm package `@rich-netlist/runtime` 0.5.7, built from the same core.
It fixes what a review of 0.5.6 found, and corrects four passages of the notes of 0.5.6. It still
reads and writes the language 0.3 beside 0.4, and `rnl upgrade` still turns a file of 0.2 or 0.3
into 0.4. RNL Viewer is not released with it and stays at 0.5.3. On npm it is published with the
dist-tag `legacy-0.3`: `latest` does not move, and stays at 0.5.5 until 0.6.0.

## `rnl upgrade`

- **A main file given with a directory, such as an absolute path, keeps its title**
  ([#736](https://github.com/rich-netlist/rnl/pull/736)). Its file was not recognised, so the
  header went above its first line, and a SPICE title that reads like an element became one.
- **`--in-place` replaces the files only with a successful upgrade** ([#736](https://github.com/rich-netlist/rnl/pull/736)). Otherwise it writes
  nothing, says so and exits 1; `-o DIR` still writes the result to be reviewed.
- `--keep-generated` changes only the hash in the header of a record of the solver, where it
  changed every occurrence of the old hash in the output, comments included ([#736](https://github.com/rich-netlist/rnl/pull/736)).
- An upgraded file brings the Verilog-A files it reads with it, so `-o DIR` copies them ([#736](https://github.com/rich-netlist/rnl/pull/736)).
- An instance drawn with a standard symbol, whose DEVICE renames its terminals, gets its symbol
  with the terminal map checked, or a notice, where its pins bound the wrong terminals ([#736](https://github.com/rich-netlist/rnl/pull/736)).
- A file and an included file of another directory, or a subcircuit, with the same title are
  compared level by level, not merged by title ([#736](https://github.com/rich-netlist/rnl/pull/736)).
- The g_m text of `$DIFFERENTIAL_TRANSCONDUCTOR` takes the key `label`, as that of
  `$TRANSCONDUCTOR` does ([#742](https://github.com/rich-netlist/rnl/pull/742)).

## `rnl solve` and writing records back

- **A destination that holds another input is refused before anything is written**
  ([#740](https://github.com/rich-netlist/rnl/pull/740)), such as `-o lib` beside a `lib/` holding a file of the entry's name, which lost that
  file.
- **A file is written whole**: the files a solve rewrites, in place or under `-o`, are written
  beside themselves and then put in place, so a write that fails part way leaves the file as it
  was ([#740](https://github.com/rich-netlist/rnl/pull/740)).
- `strip-generated`, and every removal of records, removes once a record that two readings of one
  file read, such as a library section selected twice; the second removal cut the next host line
  ([#740](https://github.com/rich-netlist/rnl/pull/740)).
- A level of 0.4 with no junction dots to place is read back too, and is not written when the
  document read with its record loses objects the solve read, such as texts on pins that a written
  route then reaches ([#740](https://github.com/rich-netlist/rnl/pull/740)).
- The junction dots of a level are placed beside a statement that fails before them as it fails
  after, such as a DISTANCE written wrong, and in a file with tokens after its old generated record
  on the record's last line, which the record written anew leaves on a line of their own; such a
  file made `rnl solve` stop with exit 2 ([#748](https://github.com/rich-netlist/rnl/pull/748)).
- A solve limited by work whose finishing steps the safety limit stopped is reported stopped by
  the safety limit: not reproducible, with no replay configuration. It was reported stopped by its
  work, and the replay it offered did not give the same drawing ([#728](https://github.com/rich-netlist/rnl/pull/728)).
- The solver's charges that multiply two counts are made in 64 bits, so they are the same on 32-bit
  and 64-bit targets; on a 64-bit target nothing changes ([#728](https://github.com/rich-netlist/rnl/pull/728)).
- The protocol of an external solver: a result that wires one net through the pins of another,
  or joins wires of two nets at one branch point, is refused. It was written as one net, and the
  command exited 0 with a file that failed its check ([#732](https://github.com/rich-netlist/rnl/pull/732)).

## `rnl preview`

- **`--confine DIR` reads files only within DIR** ([#741](https://github.com/rich-netlist/rnl/pull/741)), following links: an include by an
  absolute path elsewhere, or one that a link leads out of DIR, is not found.

## The language 0.4

- A usage without a symbol written twice in a constraint (`%u %u` in a DISTANCE, or `%u::position`
  beside `%u`) stands for its members first: the pairs of two different members are kept, where
  they were left out as one object twice ([#739](https://github.com/rich-netlist/rnl/pull/739)).
- A subscript range counts on u64: a decreasing range across the largest i64 is no longer empty,
  and an increasing one that reaches the largest u64 no longer overflows ([#739](https://github.com/rich-netlist/rnl/pull/739)).
- The standard series 0.4 ([#726](https://github.com/rich-netlist/rnl/pull/726)):
  - `$PARALLEL_HORIZONTAL` and `$PARALLEL_VERTICAL` put their own point midway between their first
    and last member, so a structure that aligns them by `::position` keeps the row in its column;
  - `$DEGENERATED_DIFFERENTIAL_PAIR_TYPE_T` becomes `$DEGENERATED_DIFFERENTIAL_PAIR_TYPE_T_N` and
    `_TYPE_T_P`, as the differential pairs: a file of 0.4 that names the old one names one of these
    now;
  - the differential transconductors draw g_m as a text of key `label`, as the single-ended ones do;
  - the current mirrors no longer relate the orientations of their transistors, which fought the
    structure a mirror reaches into; their sources or emitters keep their direction;
  - the fill gives a bus pin whose nets are not all of one rail a net label, where the ground,
    supply or bias stub it took failed: `{#R2 #R3} @BUNDLE` with a member to ground gave five
    errors ([#747](https://github.com/rich-netlist/rnl/pull/747)).

## The npm package

- **A manifest's source address is kept only when it is an https one**, as its author's links
  are: `loadManifest` leaves out a `javascript:`, `data:` or `http:` source address, which a page
  would have linked. `@rich-netlist/runtime/manifest` exports `webLink(url)`, which gives `url`
  when it is an https address and `null` otherwise ([#731](https://github.com/rich-netlist/rnl/pull/731)).
- The Document (`document.d.ts`) gains `UsageRole.points`, optional: the points among a role's
  members, which are not objects, so two usages that frame the same objects at other points are
  told apart ([#731](https://github.com/rich-netlist/rnl/pull/731)).

## Hosts

- Spectre: an instance of a subcircuit named like an analysis in another case, such as
  `X1 (a b) AC`, is an instance; an analysis is read in its case, in any case only after
  `insensitive=yes` ([#737](https://github.com/rich-netlist/rnl/pull/737)).
- SPICE `.include`, `.lib FILE SECTION` and `.hdl`, in the SPICE adapter and in the SPICE mode of the
  Spectre adapter: a file name in quotes may hold spaces ([#737](https://github.com/rich-netlist/rnl/pull/737)).

## Corrections to the 0.5.6 notes

- **False joins.** The notes said that in 0.4 a drawing that reads as joined where it is not
  never wins. Among the drawings the solver compares, such a drawing ranks below every other; but
  a router's search that runs out of its budget joins a net by straight runs, and can leave such a
  join in the drawing it returns.
- **Diagnostic numbers.** The notes said that every diagnostic has a number `RNLnnnn` and a short
  name. Every kind has a short name, and the kinds of the toolkit's list have a number; some kinds
  that only the languages 0.2 and 0.3 give have none: `rnl check` prints the name alone, and their
  `code` in the Document is `null`. A tool matches those by `name`.
- **The solver in the npm package.** The notes said that its `solve`, `settings` and `check` take
  the same settings as `rnl solve`. `solve(request)` and `check(request)` do; `settings()` takes
  no argument and returns the table of the solver's settings and objectives, as
  `rnl solver-defaults --json` prints it. And where the report of a solve says of each fact
  whether it holds on the drawing, `holds` is `null` when a point the fact needs has no position
  there, or the level has no record of the solver.
- **The limit of a level and its dots.** The notes said that a level's limits bound the placement
  of its dots too. A level's time limit keeps a part of itself for the dots, but does not bound
  their stage: the dots are placed after the limit, with a bound on the number of candidates tried,
  and only the safety limit stops that stage.

## For users of 0.5.6

- A file of 0.4 that names `$DEGENERATED_DIFFERENTIAL_PAIR_TYPE_T` names `_TYPE_T_N` or `_TYPE_T_P`
  now ([#726](https://github.com/rich-netlist/rnl/pull/726)).
- A drawing of 0.4 with a current mirror may change, as the mirror no longer relates the
  orientations of its transistors ([#726](https://github.com/rich-netlist/rnl/pull/726)).
- `rnl upgrade --in-place` exits 1 and writes nothing when the upgrade is not clean ([#736](https://github.com/rich-netlist/rnl/pull/736)).
- A manifest whose source address is `http:` is no longer linked from it; give an https address
  ([#731](https://github.com/rich-netlist/rnl/pull/731)).
- To keep the language 0.3 after 0.6.0, install by exact version or with
  `npm i @rich-netlist/runtime@legacy-0.3`.

`npm i @rich-netlist/runtime@legacy-0.3` installs 0.5.7; `npm i @rich-netlist/runtime` still
installs 0.5.5 under the dist-tag `latest`.

The links of the form `releases/latest/download/…` still give the files of 0.5.5, as the release
GitHub shows as latest does not move: download the files of 0.5.7 from its own release page.

Linux on arm64 is not built yet; build the command from the source there.

## Not signed

The executables have no code signature. Windows may show a SmartScreen warning. On macOS, a file
downloaded with a browser may need `xattr -d com.apple.quarantine rnl` after it is extracted
before it runs. Check each download against `SHA256SUMS.txt` first.
