# RNL core 0.3.0

The `rnl` command and the npm package `@rich-netlist/runtime` 0.3.0, built from the same core.
RNL Viewer 0.3.0 is released alongside it under `viewer-v0.3.0`; the language standard is
unchanged at 0.3.

## What is new

- **Inspection overlays in `rnl render`** ([decision 0014](../../docs/decisions/0014-inspection-overlay-geometry.md)).
  All of them are off by default and none of them changes the drawing itself:
  - `--usages semantic|all` frames usages: `semantic` frames the usages without a drawing of
    their own, and `all` frames every usage;
  - `--currents` draws an arrow at each terminal with `@CURRENT("in")` or `@CURRENT("out")`,
    including explicit subcircuit port symbols;
  - `--usage-roles` labels the roles of the framed usages;
  - `--overlay-style FILE` sets their colours, widths and dashes from a JSON file, independently
    of RNL styles.
- **The geometry is in the Document.** Each level lists its usages with their roles, members,
  objects and source lines (`Level.usages`). Each usage has its frame and label anchors
  (`Usage.frame`), and each level has its current arrows (`Level.currents`). The viewers draw
  their overlays from this geometry, so the CLI and the viewers agree.
- **Saving keeps a file's encoding.** `rnl solve` and `rnl strip-generated` write each file in
  the encoding it was read in: UTF-8, with its byte order mark when it had one, or Latin-1.
  - If the text needs a character Latin-1 cannot hold, nothing is written and the error names
    the character.
  - `--encoding utf8` writes UTF-8 instead.
  - Every file is encoded before any is written, so an encoding error leaves all of them
    unchanged ([output encoding](../../docs/output-encoding.md)).

## Fixes

- **Drawing order.** Nested symbols, graphics and fixed text are drawn in the order they are
  declared. Before, nested symbols always came after the other graphics.
- **Deep nesting.** Fixed text and inferred bounds now follow nested symbols as deep as their
  graphics do; they used to stop at depth eight. Cycles, and nesting beyond 64 symbol levels,
  are reported instead of being cut off silently.
- **Pins differing only in case.** In Spectre, `P` and `p` stay two pins, also on a symbol
  reused from a SPICE file. SPICE stays case-insensitive.
- **Include-file versions.** An included file that declares a supported RNL version is read
  even when the file including it has an unsupported version. Files without a declaration
  inherit the nearest declared version.
- **Host regions.** RNL records in text that is not part of the circuit are left
  uninterpreted and diagnosed. Such text includes scripts, embedded Verilog, `reliability`
  blocks, preprocessing, encrypted sections and the title line after `.newjob`. The solver and
  the editor never write records into these regions ([host regions](../../docs/host-regions.md)).
- **New hints and warnings:**
  - a hint, once per file, that non-ASCII characters in host comments have not been checked
    against a simulator;
  - spelling hints for free text that come after all forward, inherited and package names are
    known;
  - a warning for RNL after the main `.end` in Spectre's SPICE mode.
  `rnl check` can therefore show hints it did not show before.
- **Net-label highlighting.** Net labels in the drawing highlight the same way in the native
  and WebAssembly cores.
- **Vocabulary check in CI.** CI checks that the words the runtime knows match the standard's
  word list.

## For users of 0.2.0

- Drawings do not change, apart from the order fix above for symbols that nest other symbols.
- The overlays are opt-in.
- The Document's new fields are additions. Code that reads 0.2.0's Document keeps working.

`npm i @rich-netlist/runtime` installs 0.3.0 under the dist-tag `latest`.

Linux on arm64 is not built yet; build the command from the source there.

## Not signed

The executables have no code signature. Windows may show a SmartScreen warning. On macOS, a file
downloaded with a browser may need `xattr -d com.apple.quarantine rnl` after it is extracted
before it runs. Check each download against `SHA256SUMS.txt` first.
