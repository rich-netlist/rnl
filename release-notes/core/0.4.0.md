# RNL core 0.4.0

The `rnl` command and the npm package `@rich-netlist/runtime` 0.4.0, built from the same core.
RNL Viewer 0.4.0 is released alongside it under `viewer-v0.4.0`; the language standard is
unchanged at 0.3.

## What is new

- **Each file is read in its own format** ([#199](https://github.com/rich-netlist/rnl/pull/199),
  [#204](https://github.com/rich-netlist/rnl/pull/204)). A format is the adapter that reads a file:
  `spice` (the SPICE family) or `spectre`. Each file of a netlist, included files too, is read by
  its own format, and the main file no longer decides it for them.
  - **By default**, a file is Spectre when it is a `.scs` file or has a `simulator lang=spectre`
    line among its first 50 lines, and SPICE otherwise. A Spectre file starts in SPICE mode unless
    it is a `.scs` file, as Spectre itself reads it, and `simulator lang=` switches as before.
  - **A format can be set for any file**, which then wins over the default.
  - **Names across files** follow the rule of each file: a SPICE file ignores case, a Spectre file
    does not. Finding a subcircuit, a model card or a global net ignores case when either the
    reference or the definition does. For a subcircuit or a model card, an exact spelling wins,
    and two definitions that still both match are an error: the name then names neither, and an
    instance of it is not taken for a subcircuit. The nets and instance names of one circuit
    compare by the rule of the file that holds the circuit (its `.subckt`, or the main file).
    `gnd` is ground only where a statement of a SPICE file writes it.
  - **Auto Include** does not add a library file that would change what a reference already finds
    in a netlist of two formats; it says why instead.
  - **Writing back** a record (the solver, the editor) uses the comment marker of the file's own
    format and language mode, as before for netlists of one format.
  - In the command line, and in RNL Viewer on the desktop, a set format matches the file whatever
    the case of its path on Windows and macOS, as the file system does; the WebAssembly core
    compares the paths it is given as they are.
- **Command line.** `--format FILE=NAME`, which may be given several times, sets a file's format
  for every command that reads a netlist (`check`, `render`, `dump`, `view`, `problem`,
  `snapshot`, `solve`, `preview`, `strip-generated`). A relative path is taken from the current
  directory, as FILE is; a path the netlist does not read is warned of, and an unknown format
  name is an error, for a package file (`.rnl`) too. `rnl formats` prints the formats as JSON:
  each with its name, its title, its extensions and whether it is the fallback. `--dialect` now
  names the main file's format only.
- **Documents and snapshots.** Each file of a Document has its `format` and the
  `default_format` it would have without a setting (`null` for an `.rnl` package), and the
  Document lists the formats (`Document.formats`). A snapshot gives each file's format only when
  the netlist has files of several formats or formats were set, so other snapshots are unchanged.
- **WebAssembly and npm.** Build, snapshot and Library index requests take an optional
  `formats`, `{ path: format }`. A request `{ formats: { detect } }` gives the list of formats and
  the default format of each file it is given. `write.dialect` is unchanged.

## Changes in reading

These change what you get only for a netlist whose files are of two formats; a netlist whose files
are all SPICE or all Spectre reads as before.

- **A SPICE netlist that includes a Spectre file** (a `.scs` file, or a model library that starts
  with `simulator lang=spectre`): that file is now read as Spectre. Its statements and its records
  in `//` comments are read, and its names compare by case. Before, the whole netlist was read as
  SPICE.
- **A Spectre netlist that includes a SPICE file** (not `.scs`, and no `simulator lang=spectre` in
  its first 50 lines): that file is now read as SPICE. Its names ignore case, `gnd` is ground, and
  its elements no longer name the Spectre primitive they equal, so `model="resistor"` no longer
  selects its `R1 a 0 1k`; a `simulator lang=spectre` after its first 50 lines switches nothing.
  The standard rule package used for it is unchanged (`rnl-std-spice`), so its drawing is the
  same. In the conformance corpus only `cases-0.3/02-dialect-rules` has such a file; its drawing
  is unchanged, and its snapshot no longer gives a master to `I1` and `R1` of that file.
- **`--dialect`, `BuildOptions::dialect` and the WebAssembly `dialect`** name the main file's
  format only. An included file is read by its own unless `--format` sets it.

## Fixes

- **`@ORIENT("R0")` is written** ([#195](https://github.com/rich-netlist/rnl/pull/195)). A write
  request (`rnl write`, the npm package's `write`) that gives an object the orientation R0 now
  writes it. It used to be left out, and in 0.3 an object without ORIENT is the solver's to
  orient, so a placement drawn by hand could be mirrored.
- **Rules evaluated below their level** ([#198](https://github.com/rich-netlist/rnl/pull/198)).
  The warning that a rule takes effect only in the level it is written in (10.5) is now given
  only for generation rules (AS and ATTACH), as 10.3 says; other rules that use a selection and
  name objects of their level no longer warn. A rule whose selection is `recursive=false` no
  longer leaves an empty fact, such as a DISTANCE between nothing and nothing, in the levels
  below.

## For users of 0.3.0

- Netlists whose files are all of one format read and draw as before.
- The new fields of the Document and the requests are additions. A snapshot changes only for a
  netlist of two formats, or when formats are set.
- Code that passes `dialect` to read a whole netlist of several files in one format should pass
  `formats` for the included files too.

Linux on arm64 is not built yet; build the command from the source there.

## Not signed

The executables have no code signature. Windows may show a SmartScreen warning. On macOS, a file
downloaded with a browser may need `xattr -d com.apple.quarantine rnl` after it is extracted
before it runs. Check each download against `SHA256SUMS.txt` first.
