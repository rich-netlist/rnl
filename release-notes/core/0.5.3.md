# RNL core 0.5.3

The `rnl` command and the npm package `@rich-netlist/runtime` 0.5.3, built from the same core.
RNL Viewer stays at 0.5.1; the language standard is unchanged at 0.3.

## What is new

- **A terminal's label stands for the nets of its pin** ([#292](https://github.com/rich-netlist/rnl/pull/292)).
  In the Document, a label attached to a terminal now stands for what that terminal's pin stands
  for: its net, or its nets for a bus pin. A viewer that uses the Document's hits, such as RNL
  Viewer, selects and highlights the net when the label is clicked, as when the pin is, and
  selecting the net marks the terminal labels on it. Before, such a label stood for nothing
  (rnl#102); use showed that was wrong.
  - A terminal without a net, or whose pin is not drawn, still stands for nothing.
  - The Document's shape is unchanged: only the objects of terminal labels are filled. The
    TypeScript declaration changes in its comments only.

## Other changes

- The manifest module, `@rich-netlist/runtime/manifest`, words two of its errors more clearly
  ([#286](https://github.com/rich-netlist/rnl/pull/286)): a path that leaves the manifest or has an
  empty segment "must be a relative path within the manifest without empty segments", and a file
  without an address is reported as `Entry … has no "url" field and the manifest has no "base"
  URL.` They are still thrown as `ManifestError` naming the same file.

## For users of 0.5.2

- Netlists read and draw as before.
- A Document's terminal labels now name their pin's nets as their objects; a tool that treated a
  terminal label as standing for nothing sees those objects.
- A tool that matches the text of the two manifest errors above sees the new wording.

`npm i @rich-netlist/runtime` installs 0.5.3 under the dist-tag `latest`.

Linux on arm64 is not built yet; build the command from the source there.

## Not signed

The executables have no code signature. Windows may show a SmartScreen warning. On macOS, a file
downloaded with a browser may need `xattr -d com.apple.quarantine rnl` after it is extracted
before it runs. Check each download against `SHA256SUMS.txt` first.
