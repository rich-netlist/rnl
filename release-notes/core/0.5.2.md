# RNL core 0.5.2

The `rnl` command and the npm package `@rich-netlist/runtime` 0.5.2, built from the same core.
RNL Viewer stays at 0.5.0; the language standard is unchanged at 0.3.

## What is new

- **An object's style, written and read back** ([#274](https://github.com/rich-netlist/rnl/pull/274)).
  A tool can now write the style of an instance or a usage through the runtime, and read it back,
  as Analog Canvas does with the colours of its parts and of symbols such as a red ground:
  - The edit ops `set` and `add-usage` take `style`, style properties (9.3), such as
    `{"linecolor": "#2275e2", "textcolor": "#2275e2"}`. They are written the standard way, a style
    that the object's statement gives it (11.3):

    ```
    *   $style1 = @DEFINE-STYLE(linecolor="#2275e2", textcolor="#2275e2") {};
    *   #R1 @SET-STYLE $style1 => @PLACE(0, 0);
    ```

    Within a level, styles of the same properties and values are one definition, first in the
    level's record. Each level that uses a style defines it itself, under a name of its own, so an
    included file reads the same opened on its own and no definition hides one of a level above
    (6.8). A property the language does not know is written as given and fails when the netlist is
    read, as one written by hand does. A `set` may give only a style.
  - The editor interface's snapshot (`rnl snapshot`, and `snapshot()` of the npm package) gives
    each object the style properties the document's own records give it, as `style`: each property
    as it wins in the style queue (8.3), merged, so the properties rather than the name of a style;
    those a package gives, such as the standard package's defaults, are left out, as for the
    `style` of wires, texts and graphics. An object the document gives no style has no `style`.
  - An object's style passes on to its labels as before (11.3): the name of an instance written in
    a colour is drawn in that colour.

  The TypeScript declarations have the new fields.

## For users of 0.5.1

- Netlists read and draw as before; nothing is drawn differently.
- A snapshot's objects may have a new key, `style`; a reader that ignores keys it does not know
  sees no change.
- `set` and `add-usage` without `style` are written as before.

`npm i @rich-netlist/runtime` installs 0.5.2 under the dist-tag `latest`.

Linux on arm64 is not built yet; build the command from the source there.

## Not signed

The executables have no code signature. Windows may show a SmartScreen warning. On macOS, a file
downloaded with a browser may need `xattr -d com.apple.quarantine rnl` after it is extracted
before it runs. Check each download against `SHA256SUMS.txt` first.
