# RNL core 0.5.1

The `rnl` command and the npm package `@rich-netlist/runtime` 0.5.1, built from the same core.
RNL Viewer stays at 0.5.0; the language standard is unchanged at 0.3.

## What is new

- **`add-usage` writes a usage's parameters** ([#245](https://github.com/rich-netlist/rnl/pull/245)).
  The edit op `add-usage` of the write interface (`rnl-edit`, and the edit transactions of the npm
  package) takes `params`, the parameters the usage writes, so that a tool can write a
  definition's parameters through the runtime, such as Analog Canvas's
  `$CANVAS_NAME @ATTACH(name="M1") #XM1(part)` with analog-canvas-extensions 0.2:
  - they are written as `@ATTACH(k=v, …)`, in the order given; a name that is not an ASCII name is
    written in quotes, the name itself, as a role is (16.5);
  - each value is a literal as the snapshot reads it back in `ObjectView.params` (0.5.0): a string
    in quotes, with a quote doubled; a number exactly, in the shortest form that reads back the
    same; `true` or `false`; a list in brackets, nested or empty. The snapshot gives numbers as
    floats, so `7` reads back as `7.0`, one number to a reader of JSON;
  - a parameter the definition does not declare is written as given and fails when the netlist is
    read, with the same error as the statement written by hand;
  - a string with a line break is refused, as the comment that carries the record would end there;
    so is any other value, such as `null` or an object.

  The TypeScript declaration has `params?: Record<string, ParameterValue>`, where a
  `ParameterValue` is a string, a number, a boolean or a list of them.

## For users of 0.5.0

- Netlists read and draw as before; nothing else changed.
- An `add-usage` without `params` is written as before.

## Files

| File | |
| --- | --- |

| `SHA256SUMS.txt` | The SHA-256 sums of the archives: `sha256sum --check --ignore-missing SHA256SUMS.txt`, or `Get-FileHash` in PowerShell |

`npm i @rich-netlist/runtime` installs 0.5.1 under the dist-tag `latest`.

Linux on arm64 is not built yet; build the command from the source there.

## Not signed

The executables have no code signature. Windows may show a SmartScreen warning. On macOS, a file
downloaded with a browser may need `xattr -d com.apple.quarantine rnl` after it is extracted
before it runs. Check each download against `SHA256SUMS.txt` first.
