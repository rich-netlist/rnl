# RNL core 0.5.4

The `rnl` command and the npm package `@rich-netlist/runtime` 0.5.4, built from the same core.
RNL Viewer stays at 0.5.2; the language standard is unchanged at 0.3. The solver stays at 0.1.

## What is new

- **The solver says it is a preview** ([#336](https://github.com/rich-netlist/rnl/pull/336)).
  Each time `rnl solve` or `rnl preview` solves, it prints one line on the standard error before
  anything else:
  `note: the solver is a preview, and its layouts may be poor; for comparison, have the model write the exact RNL placement directly`.
  The standard output, `preview`'s JSON among it, the files written and the exit codes do not
  change.
- **The usages each object is a member of, and `rnl explain`** ([#317](https://github.com/rich-netlist/rnl/pull/317)).
  For every instance, net and usage, the Document now lists the usages it is a member of in its
  level, `Object.usages` (`MemberOf`). Each entry gives:
  - the usage, its definition and the roles the object fills;
  - the statement's file and line;
  - where the usage comes from: written, a rule (with its package and place), the body of a
    definition, or a record a solver wrote back;
  - whether it takes effect: in effect, failed (with the error), overridden (with the conflict) or
    disabled.

  An application that failed, and so made no usage, is listed too. The chain upward is the usage's
  own entry. The new command `rnl explain FILE REF [--level TITLE] [--json]` prints these lists:
  one line for each usage, with the usages that contain it indented below. A REF that names
  nothing is an error that lists up to five close names.
- **Groups are listed with the usages** ([#331](https://github.com/rich-netlist/rnl/pull/331), [#333](https://github.com/rich-netlist/rnl/pull/333)).
  A set marked with GROUP (11.5) is listed as a usage of kind `"group"`:
  - in the usage table `Level.usages`, after the usages, with one role, `members`, and a frame
    titled `@GROUP: %core`, which the exported SVG now writes too;
  - in `Object.usages` of each member;
  - in `rnl explain`, as `member of group %stage1`.

  A reference to a set is spread in a set (5.2), so a group is within another when all its members
  are among the other's; a group lists the smallest groups it is within. Each row of the usage
  table now says whether it takes effect, `state` and `reason`.
- **A fourth format, RNL package** ([#313](https://github.com/rich-netlist/rnl/pull/313)).
  A file is a package file by its format, `rnl`, not by its `.rnl` suffix. A file whose first
  record starts a line and is a header record with `@PACKAGE` is claimed by its content.
  `--dialect` and `--format` take `rnl`. A package file that a netlist includes is not read; the
  include is an error, and USE-PACKAGE is the way to bring a package in (2.7, 16.2).
- **A file of a hardware description language is text** ([#311](https://github.com/rich-netlist/rnl/pull/311)).
  `.va`, `.vams`, `.v`, `.vh`, `.sv`, `.svh`, `.vhd` and `.vhdl` files are of the format `text`.
  They are kept and not read, with one hint instead of SPICE's diagnostics, whether opened or
  included. A format set for the file still wins.
- **The solver tells supply, ground and port symbols by their drawing** ([#197](https://github.com/rich-netlist/rnl/pull/197)).
  It knew them only by the names of the series 0.2, so on a file of 0.3 grounds and ports were
  placed as ordinary row elements and the current direction was not in force. It now reads them
  off the symbols' pins and boxes. Files of the series 0.2 solve exactly as before. A file of 0.3
  may now solve to another layout, with grounds below, supplies above and the rows from supply to
  ground, often with less work.

## Additions to the npm snapshot

The snapshot (`snapshot.d.ts`) only gains fields; none is removed or changed:

- `ObjectView.usages?: UsageOf[]` and `HostNet.usages?: UsageOf[]`: the usages and groups the
  object or net is a member of. Left out when empty.
- `UsageOf`: `kind` (`"usage"` or `"group"`), `id`, `definition`, `roles` (`RoleOf`), `file`,
  `line`, `source`, `rule?` (`RuleAt`), `made_in?`, `state`, `reason?`.
- `LevelModel.groups?: GroupView[]`: the groups of the level, with `id`, `members`, `file`,
  `line`, `source`, `rule?`, `made_in?`, `state` and `usages?`. Left out when the level has none.

The Document (`document.d.ts`) gains:
- `Object.usages: MemberOf[]`;
- `Usage.kind`, `Usage.state` and `Usage.reason`;
- the object kind `"group"`.

`dialect` and the formats may be `"rnl"` and `"text"`.

## For users of 0.5.3

- Netlists read and draw as before.
- `rnl solve` and `rnl preview` print one more line, on the standard error.
- A tool that reads `Level.usages` or `Document.objects` sees rows and objects of kind `"group"`.
  It should look at `kind` if it handles only usages.
- A file of 0.3 may solve to a different layout (#197).
- A netlist that includes a package file now has an error, and `rnl check` exits 1. Before, it
  read the package as SPICE with warnings.
- A `.va` file and the like is no longer read as SPICE. Set a format for it to read it as before.

## Not signed

The executables have no code signature. Windows may show a SmartScreen warning. On macOS, a file
downloaded with a browser may need `xattr -d com.apple.quarantine rnl` after it is extracted
before it runs. Check each download against `SHA256SUMS.txt` first.
