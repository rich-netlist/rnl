# RNL core 0.6.1

The `rnl` command and the npm package `@rich-netlist/runtime` 0.6.1, built from the same core.
It reads large designs faster, and every reading gives what 0.6.0 gives: the same diagnostics,
the same model and the same drawing. RNL Viewer 0.6.1 is released with it.

## Faster reading of large designs

Two costs grew with the number of objects in a level faster than the level did:

- A selection of the pins of instances or usages, such as each stub of the fill of the standard
  package makes when it selects its pin, took and sorted the pins of every object of the level
  first. It now takes them only when its pool is empty or holds a net, which is when it needs them.
- Finding the nets of an instance's pin took the instance's terminals again for each of its
  terminals, and copied the pins of its symbol each time. It now takes them once.

With both, two designs from a local set read as follows:

| | 0.6.0 | 0.6.1 |
| --- | --- | --- |
| a design of 82 levels, `rnl check` | 13.2 s | 5.7 s |
| a design of 82 levels, in the browser's WebAssembly core | 13.2 s | 7.0 s |
| a design of 34 levels, `rnl check` | 31.7 s | 18.7 s |
| a design of 34 levels, in the browser's WebAssembly core | 29.4 s | 26.2 s |

The WebAssembly numbers are those of a build of the Document in Node, as the web viewer makes it.
For both designs, the output of `rnl check`, `rnl view` and `rnl dump` is byte-for-byte that of 0.6.0.

## Known limits

- A level of many instances whose pins the fill gives stubs still reads in a time that grows
  faster than the level: each stub's reference to its pin's net resolves the references of the
  level again. A level of 1600 instances of five pins takes over 20 s, where one of 400 takes about 2 s.
- A bus pin, such as a terminal of a bundle, on two different nets of one rail class, such as
  `vdda` and `vddd` both in `$SUPPLY_NET_SET`, gives errors in the fill of the standard package,
  RNL3512 first, and gets no label: take one of the nets out of the class, or wire the pin.

## For users of 0.6.0

Nothing to change: files, options and the npm package's interface are those of 0.6.0.

## Files

The same four CLI archives as 0.6.0, each holding the `rnl` command and its licence, with
`SHA256SUMS.txt`, the checksums of every archive, the npm package's too, as a separate asset
beside them; and the npm package `@rich-netlist/runtime@0.6.1`, published with the dist-tag
`latest`.

| File | |
| --- | --- |
| `rnl-x86_64-pc-windows-msvc.zip` | Windows x64 |
| `rnl-x86_64-unknown-linux-musl.tar.gz` | Linux x86_64, statically linked |
| `rnl-aarch64-apple-darwin.tar.gz` | macOS on Apple Silicon |
| `rnl-x86_64-apple-darwin.tar.gz` | macOS on Intel |
| `SHA256SUMS.txt` | The SHA-256 sums: `sha256sum --check --ignore-missing SHA256SUMS.txt`, or `Get-FileHash` in PowerShell |

`npm i @rich-netlist/runtime` installs 0.6.1; `npm i @rich-netlist/runtime@legacy-0.3` still
installs 0.5.7. This release is the one GitHub shows as latest, so the links of the form
`releases/latest/download/…` give the files of 0.6.1.

Linux on arm64 is not built yet; build the command from the source there.

## Not signed

The executables have no code signature. Windows may show a SmartScreen warning. On macOS, a file
downloaded with a browser may need `xattr -d com.apple.quarantine rnl` after it is extracted
before it runs. Check each download against `SHA256SUMS.txt` first.
