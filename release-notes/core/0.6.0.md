# RNL core 0.6.0

The `rnl` command and the npm package `@rich-netlist/runtime` 0.6.0, built from the same core.
It reads and writes the language 0.4 alone, with the standard series 0.4. Files of the
languages 0.2 and 0.3 are no longer read: core 0.5.7, the last core that reads them, converts
them to 0.4 with `rnl upgrade`.

## The language 0.4 alone

- A file that declares `@VERSION("0.2")` or `@VERSION("0.3")` is a file of a version this core
  does not read: an error at the declaration, RNL2102 `version-unsupported`, and none of the
  RNL of the file interpreted (16.1). The message says that core 0.5.7 reads the file and that
  its `rnl upgrade` writes it in 0.4.
- A main file or a package file without a header record is read in 0.4, the tool's default;
  an included file without one still follows the file that includes it (16.1).
- The core bundles the standard series 0.4 alone. The series 0.2 and 0.3 are gone from the
  repository and from the core; core 0.5.7 has them.
- The editor writes 0.4: a write request without `language_version` writes `@VERSION("0.4")`,
  and one that asks for another version is refused.

## Changed

- The instances of a file of a version this core does not read, whose netlist is still read, are
  drawn as an instance of 0.4 without a symbol is: with the default block symbol and a pin for
  each node (9.2.6), where they had the viewer's default without pins.
- Every kind of diagnostic has a number. The kinds `unsolved-at-point` and
  `unsolved-wire-through-centre`, which had none, are RNL8215 and RNL8216.
- A package file or a main file without a header record is read in 0.4 throughout: a package
  file is cut into records by the rules of 0.4 and keeps its first PACKAGE, and the summary of a
  main file says "1 error", not "1 errors".
- A write request to the WebAssembly core without `language_version` writes 0.4, and a refusal
  comes as an `EditError` with its code, as for one that names 0.4.
- Spectre `tline` and `transformer` instances have the terminal names `p1 n1 p2 n2` (6.12).
- `rnl groups` gives every level its tree of groups; a level has no flat list of groups any more.

### For users of the npm package and of the Document

These change the TypeScript declarations of `@rich-netlist/runtime` and are not compatible with
0.5.x:

- `Diagnostic.code` is a `string`; it was `string | null`, null for the kinds of 0.2 and 0.3 alone.
- `Unplaced.reason` is gone: only the instances of 0.2 that were not drawn, for a missing model card,
  had one. In 0.4 such an instance is drawn with the default block symbol (9.2.6). The model's
  `LevelView.undrawn` and the host's `Instance.model_missing` are gone with it.
- `CatalogPackage.implicit` is true for `rnl-std-all`, the package `include_std` adds, of the version
  the reading takes.

## Files of 0.3, and of 0.2

Files of 0.3 are still being written: by Analog Canvas and by the exports of rnl-virtuoso 0.9.6,
until they write 0.4. Such a file is opened in one of two ways:

- read as it is in the frozen web viewer of 0.3, `viewer-0.3/` on the website, which reads files
  of 0.2 and 0.3 and draws them as the cores of 0.5.x do;
- or converted to 0.4 with core 0.5.7: install it (`npm i @rich-netlist/runtime@0.5.7`, or the
  CLI from its release page) and run `rnl upgrade FILE` there; the file it writes is read by
  0.6.0, by the current viewers and by the web viewer.

## Removed

- `rnl upgrade`, with `--report`, `--approximate` and `--keep-generated`. `rnl upgrade` now says
  that core 0.5.7 has the command.
- What only files of 0.2 and 0.3 needed: `rnl solve` raising a file of 0.2 that it writes into
  to 0.3, the hints for names of the series 0.2 where the series 0.3 is in effect, the kinds of
  diagnostics of 0.2 and 0.3 alone, which had no number, and the vocabulary of 0.2 and 0.3 that
  0.4 does not have (`ROUTE`, DISTRIBUTE's `axis`, SELECT-TERMINAL's `wired`), which stays
  among the removed words with the sections that replace them.
- The kinds of diagnostics that no file of 0.4 can give: RNL1138, RNL2300, RNL2308, RNL3011,
  RNL3107, RNL3204, RNL3412, RNL4000 and RNL4001, and the kinds without a number. They are listed
  among the retired kinds of the list of diagnostics, whose numbers and names no other kind takes.
- The hint RNL8111 `solve-preview-notice`: `rnl solve` and `rnl preview` no longer say on the
  standard error that the solver is a preview. The number and the name are retired, given to no
  other kind.
- The progress event `level` has no `again` field: no level is solved a second time.
- `--std-version` selects the version of the standard package that `--include-std` adds.

## Known limits

- A bus pin, such as a terminal of a bundle, on two different nets of one rail class, such as
  `vdda` and `vddd` both in `$SUPPLY_NET_SET`, gives errors in the fill of the standard package,
  RNL3512 first, and gets no label: take one of the nets out of the class, or wire the pin.

## For users of 0.5.x

- Convert files of 0.2 and 0.3 with core 0.5.7 before reading them with 0.6.0, or keep them in
  the web viewer of 0.3.
- A tool that matched the messages of `rnl upgrade` or of the raise from 0.2 to 0.3 finds
  neither.

## Files

The same four CLI archives as 0.5.7, each with `SHA256SUMS.txt`, and the npm package
`@rich-netlist/runtime@0.6.0`, published with the dist-tag `latest`.
