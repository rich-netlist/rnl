# RNL core 0.6.2

The `rnl` command and the npm package `@rich-netlist/runtime` 0.6.2, built from the same core.
Its main addition is a frontend reading a design one file at a time: the outline of the whole
design first, then the files it shows, each read in the context of its entry. RNL Viewer 0.6.2 is
released with it. Every reading of a whole document gives what 0.6.1 gives, except that the texts
of constraints now use the words of RNL 0.4, as described under Changed.

## Added

- **The outline of a document.** `outline()` in `core.js` and `client.js`, and `collectOutline()`
  in `client.js`, give the outline: what reading the files gives before any RNL is interpreted.
  It has:
  - the files, their includes, and the hashes of their texts and records;
  - every level, with its kind, file, lines, parent, ports, and the subcircuits its instances
    call;
  - the roots, the global nets and the missing files.

  In WebAssembly, the request is a build request with `"outline": true`. In Rust, it is
  `rnl_view::outline`.
- **Reading one file in the context of its entry.** `buildFile()` (with `collectFile()`, which
  reads what is missing) gives the levels of one file, drawn as the whole Document draws them. It
  also gives the subcircuits they call, with the outline level of each (`host`), and the inputs
  the result depends on, by role and with their hashes, so that a frontend can keep the result.
  `symbols()` gives the block symbols of a file's subcircuits. `version.js` gives the core version
  and the format of a file's result before the module is loaded. In Rust, these are
  `rnl_view::build_file`, `rnl_view::symbols`, `rnl_view::core_version` and
  `rnl_runtime::Options::only_file`.
- **The command line:**
  - `rnl view --file F` prints the reading of one file as a viewer gets it;
  - `rnl dump --file F` prints the model of one file;
  - `rnl dump --each-file` reads every file alone, compares each with the whole reading, and
    exits 1 on any difference.
- **Verilog-A in the outline.** A module level now lists the modules its instances name, in
  `calls`, the same way a subcircuit does. Each module is found by name, with case, in any
  Verilog-A file of the document; a name that no module has is given `level: null`. A new optional
  field `OutlineCall.lines` gives the line of each instance, counted from 1. Netlist levels get it
  too. A module level still has no circuit or drawing.
- **Manifests.** A level of a manifest may name its file (`file`), when it is written in a file
  other than the entry. `loadManifest` gives the files in the order of the manifest, and a read
  stopped by the caller's signal now rejects with the signal's reason.

## Changed

- Constraints write their direction as RNL 0.4 does: `ORDER left-to-right`, `DISTRIBUTE x`,
  `DISTANCE bottom-to-top`, and `exact=6` for a DISTANCE whose least and most are the same. Before,
  they wrote `x increasing` and `min=6 max=6`. This applies to:
  - the `what` of the constraints in a Document;
  - the facts, discarded facts and hints of the `rnl solve` report.

  A DISTRIBUTE constraint now gives its `sense` (`ConstraintKind`), as ORDER and DISTANCE do. The
  solver's input, its signatures and the files it writes do not change.

## Faster

- Reading one file reads the RNL records of only the subcircuits it depends on, instead of those
  of every file, so a file of a large design opens faster.
- A thread keeps the parse of each record text, so later readings in the same thread do not parse
  the same text again. An example is the next file a viewer's Worker reads with `buildFile`.

The output of `rnl check`, `rnl view` and `rnl dump` on the examples of the gallery, the examples
of the skill, the cases of the solver and two large generated designs is byte-for-byte that of
0.6.1, and every file of them read alone gives what the whole reading gives for it.

## Known limits

- A level of many instances whose pins the fill gives stubs still reads in a time that grows
  faster than the level. In a level of instances of five pins, two of them on the supply and
  ground nets, so that the fill gives each instance two stubs, 400 instances take about 1.6 s and
  1600 take about 19 s.
- A bus pin, such as a terminal of a bundle, on two different nets of one rail class, such as
  `vdda` and `vddd` both in `$SUPPLY_NET_SET`, gives errors in the fill of the standard package,
  RNL3512 first, and gets no label: take one of the nets out of the class, or wire the pin.
- The parameters of a Verilog-A module, with their defaults, are not in the outline yet.

## For users of 0.6.1

Nothing to change in files or options. A program that reads the text of a constraint, or of the
`rnl solve` report, gets the new direction words above. The rest of the npm package's interface
is that of 0.6.1, with the additions above.

## Files

The same four CLI archives as 0.6.1, each holding the `rnl` command and its licence, with
`SHA256SUMS.txt`, the checksums of every archive, the npm package's too, as a separate asset
beside them; and the npm package `@rich-netlist/runtime@0.6.2`, published with the dist-tag
`latest`.

| File | |
| --- | --- |
| `rnl-x86_64-pc-windows-msvc.zip` | Windows x64 |
| `rnl-x86_64-unknown-linux-musl.tar.gz` | Linux x86_64, statically linked |
| `rnl-aarch64-apple-darwin.tar.gz` | macOS on Apple Silicon |
| `rnl-x86_64-apple-darwin.tar.gz` | macOS on Intel |
| `SHA256SUMS.txt` | The SHA-256 sums: `sha256sum --check --ignore-missing SHA256SUMS.txt`, or `Get-FileHash` in PowerShell |

`npm i @rich-netlist/runtime` installs 0.6.2; `npm i @rich-netlist/runtime@legacy-0.3` still
installs 0.5.7. This release is the one GitHub shows as latest, so the links of the form
`releases/latest/download/…` give the files of 0.6.2.

Linux on arm64 is not built yet; build the command from the source there.

## Not signed

The executables have no code signature. Windows may show a SmartScreen warning. On macOS, a file
downloaded with a browser may need `xattr -d com.apple.quarantine rnl` after it is extracted
before it runs. Check each download against `SHA256SUMS.txt` first.
