# Foundations and file-boundary audit for toolkit profile 0.3

Audit baseline: published `spec-0.3-r2`, English `spec/0.3/en/`. This is evidence for a bounded toolkit profile, **not a conformance certificate**. Every normative subsection in chapters 1–8, 16–17 and Annex A is covered below. Final validation commands and results are recorded in the [supported profile](supported-profile-0.3.md#validation).

Status: **I** implemented mechanism with relevant inspected evidence, not exhaustive proof; **P** partial or known gap; **C** implementation choice; **N** informative/no independent behavior; **F** corrected in this change; validation is recorded in the [supported profile](supported-profile-0.3.md#validation). Missing tests are coverage gaps, not proof of missing implementation.

Path abbreviations: `R/` = `crates/rnl-runtime/src/`; `I/` = `R/interp/`; `T/` = `crates/rnl-cli/tests/`; `C03/` = `tests/conformance/cases-0.3/`; `L/` = `tests/conformance/cases/`; `E/` = `crates/rnl-edit/src/`. Fixture names mean the input plus same-base expected model/snapshot JSON. `L/` fixtures are **legacy 0.2 evidence** and cannot alone establish 0.3 behavior. Runners: `T/conformance.rs::{cases_of_0_3_match_their_expected_models,cases_of_0_3_match_their_expected_snapshots}` and corresponding `cases_match_*` for legacy.

## Findings

- **F-01 — excluded host regions (§2.2): fixed for the [documented host-region profile](host-regions.md).** Both adapters use `crates/rnl-host-spice/src/regions.rs::Regions::{skip,finish}` before carrier extraction. It classifies scripts/Verilog, Spectre reliability/encrypted envelopes, WRspice main-file job titles and preprocessing conditions/directive continuations. Unknown conditions warn and are not read; literal-selected branches remain readable. `R/host.rs::HostDocument::{unwritable_at,unwritable_in}` and `R/writeback.rs::{record_line,free_place,Top::kept}` share safe insertion spans, including unselected/selected library boundaries. `T/host_regions.rs` and the public editor tests linked in the host-region profile cover extraction and reread after writing. Unsupported simulator syntax is explicitly listed there.
- **F-02 — duplicate header fields (§2.8): fixed.** `R/syntax.rs::Parser::params` preserves repeated fields only in record heads; ordinary keyword duplicates still fail their member. `Params::get` makes repeated fields absent for generated/header classification and metadata reads. `I/unit.rs::read_header_fields` emits one error per repeated known field and retains the body and unrelated fields. `T/header.rs::repeated_record_head_fields_are_absent_without_losing_the_body` covers all seven fields, solver reading and stripping; `a_repeated_head_field_keeps_other_fields_and_keyword_duplicates_still_fail` covers the recovery boundary.
- **F-03 — file-local versions (§16.1): fixed.** `I/unit.rs::read_file_versions` discovers versions before declarations or package loading; `unsupported_file` stops at the nearest explicit version. Unsupported files contribute no RNL; explicitly supported includes interpret normally and may inherit visible declarations/packages from supported ancestors across an unread file. `T/include_versions.rs` covers inherited/explicit 0.2/0.3/unsupported versions, skipped package imports and names, selected library sections, and child-only solver writeback.
- **F-04 — encoding preservation (§3.1): fixed for UTF-8/Latin-1 native output.** CLI and desktop share `rnl-cli/src/codec.rs::{decode,encode,encode_file}`. Default save refuses unrepresentable Latin-1 characters before any batch write; CLI solve/strip-generated and desktop save/copy offer explicit UTF-8 conversion. Save As follows the source encoding. Missing disk sources fail preserve mode; tracked memory and bundled sources use UTF-8. See [the policy and regressions](output-encoding.md). Other legacy encodings are outside the supported boundary.
- **F-05 — published word-list parity (§5.3/Annex A): fixed.** `T/vocabulary_parity.rs` compares actual `R/words.rs::words` signatures and the 0.3 header supplement with the published JSON, including inventories, types/enums, slots, contexts, style groups, output/override metadata, sections and version introductions. Published defaults and handler-owned shape/key/rewrite rules are executed separately; new unhandled schema fields fail. Human-readable template/explanation strings are explicitly outside machine-signature comparison. The three old metadata discrepancies are corrected without changing dispatch behavior. Rust CI runs the test for vocabulary/schema changes as well as source changes. This closes parity assurance, not all optional-value/negative-combination coverage.
- **F-06 — finite numeric range (§3.7): fixed.** `Parser::number` previously accepted Rust `Ok(infinity)` for `1e999`; now nonfinite conversion and nonzero decimal underflow to zero report an implementation-range error. New test `R/syntax.rs::tests::out_of_range_numbers_fail_the_member_without_becoming_infinite_or_zero` rejects `1e999`, `-1e999`, `1e-999` and `-1e-999`; checks member recovery; accepts finite small values, signed zero with extreme exponents and subnormal `±5e-324`. Ordinary binary64 finite rounding is unchanged and must not be described as arbitrary precision.
- **F-07 — record-head adjacency (§2.4): fixed.** `Parser::record` previously skipped whitespace/comments before accepting the head. It now rejects detached `(` with record failure/no body. New test `R/syntax.rs::tests::a_record_head_separated_from_the_entry_fails_the_whole_record` covers space/TAB/comment and valid attached/headless records.
- **F-08 — advisory diagnostics (§§2.2,3.1,3.3,7.6): fixed.** The generic host adapters explicitly document no verified simulator/version combinations for non-ASCII comments and emit a located compatibility hint once per file; input and drawing remain unchanged. Spectre in SPICE mode scans after the main `.end` only to warn about ignored RNL, without resuming host interpretation. `I/unit.rs::check_free_words` runs after forward declarations, scope names and effective packages are available, using the actual name-visibility lookup and lexical definition scopes; private names do not leak and package diagnostics retain §7.6 filtering. `T/advisory_diagnostics.rs` covers the three paths, locations, includes, package privacy, self-visibility and unchanged drawing. The host unit test `comment_advice_tests::compatibility_detection_distinguishes_comments_from_host_names_and_strings` checks comment classification.

## Implementation choices and questions for clarification

- Binary64 is the numerical representation (`R/syntax.rs::Value::Num`, `R/geom.rs::Pt`). Numeric range failure is permitted only with an explicit implementation-limit error (§3.7). Ordinary finite decimal-to-binary rounding is not arbitrary precision; its limits should be stated.
- Host parsing algorithms are outside this standard, but excluding non-netlist regions is still normative. A practical SPICE/Spectre subset must not be called exhaustive simulator support. Ground aliases beyond generic SPICE `gnd` and `0` require dialect-specific validation.
- A nonsolving reader may draw explicit geometry without checking all cross-statement conflicts (§8.5). Apply solver requirements to solver/preview paths, not every read/view operation.
- §16.4 requires keeping unknown/failing statements when rewriting owned records; §17 says the solver replaces generated records as a whole. `R/writeback.rs::replace_generated` removes them wholesale. Clarify whether generated records are an exception before calling this interaction a defect. Unrelated authored/host text preservation is unambiguous.
- §17 protects records authored by others but its example allows directly editing the designer's record. Distinguish an explicit user source edit from automatic tool-owned record maintenance.
- Standard package version and language version are distinct. Raising syntax to 0.3 while pinning standard series 0.2 is intentional compatibility behavior.
- The existing 24 0.3 fixtures are not an exhaustive MUST/error/failure corpus. F-01/F-02/F-03/F-04/F-08 have dedicated host, recovery, boundary, encoding and advisory regressions; F-05 supplies maintained published-list parity. These do not replace exhaustive semantic coverage.

## Runtime reproductions

During the initial audit, F-01, F-02 and F-03 were reproduced with the compiled CLI using `target/audit-probes`: RNL inside Spectre reliability and SPICE .verilog regions incorrectly drew text; duplicate priority dropped the full record; a child file declaring 0.3 with a subcircuit containing `(1,2) @TEXT(...)` drew directly but disappeared when included by a parent declaring 9.9. These original findings were runtime-reproduced, not only source inference. The former duplicate-priority and unsupported-ancestor failures are now covered by the committed F-02 recovery and `T/include_versions.rs` regressions. The probes are local validation artifacts, not committed conformance fixtures.

The F-01 reproductions are now committed regressions in `T/host_regions.rs`; they expect excluded text to remain uninterpreted, preserved by writing, and absent when the result is reread.
