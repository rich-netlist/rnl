## Reading and rendering

- [x] Implement the Rust runtime and the SPICE and Spectre host adapters for language draft 0.2, without a solver: constraints are checked against the written coordinates and unplaced objects are reported.
- [x] Implement the shared renderer (primitives and SVG) and the draft standard package with its symbols ([`libraries/standard/`](../libraries/standard/README.md)); every symbol writes its box.
- [ ] Add standard symbols for the elements that still lack one (J, F, H, B and others).
- [x] Make reading SPICE and Spectre netlists linear in their size. Each reader keeps the names of a level's instances to find a name defined twice, the SPICE reader looks through a run of comment lines once, the Spectre reader joins `\` continuations in place, and records that leave a comment open no longer each look to the end of their run of carrier lines. Reading 32,000 resistors takes 0.05 to 0.06 s instead of 1.3 to 1.5 s, and the rich synthetic of 16,000 cells (32,000 elements, 142,000 comment lines) 0.11 s instead of 9.9 s in SPICE; doubling the netlist about doubles the time.
- [x] Make checking with the standard package linear in the number of subcircuits. Its fill sets are shared by all levels; a set now keeps the `@ADD-TO` and `@REMOVE-FROM` of each level apart, so that a level copies and goes through its own only. Whether a set is lazy no longer goes through its changes once it cannot be lazy any more (no member can be, as in `$SUPPLY_NET_SET`, or a change adds a selection), nor through changes from sets that cannot be. Building a level no longer goes through every statement above it to find the rules, nor through every `scope=` record above it. Checking 4,000 subcircuits of one resistor takes 1.2 s instead of 7.8 s and 8,000 take 2.5 s instead of 34 s, against 0.13 and 0.24 s without the standard package (as before); the rich synthetic of 8,000 subcircuits of six kinds, which change the sets in several levels and through `scope=`, takes 6 s instead of 207 s (1.0 s instead of 3.5 s without the standard package), and a set holding a selection that receives from each of 8,000 levels a set edited with a selection takes 2.7 s instead of 70 s. Doubling the subcircuits about doubles the time. A shared set still goes through the changes from sets that can still become lazy, as before: receiving from each of 8,000 levels a set holding a selection extended with another such set takes 17 s (84 s before).
- [x] Follow the revised rule on cycles of sets (draft 5.2.2, 7.5). A set depends on the sets written in the statement that makes it and on the sets that `@ADD-TO` and `@REMOVE-FROM` add to it or remove from it; taking a level's statements in order of position (8.5), the one that closes a cycle fails, its diagnostic lists the whole cycle with the places of its statements, and the rest takes effect. A cycle through a removal no longer makes the whole interpretation fail, and a cycle of additions is no longer interpreted; nothing makes the whole interpretation fail any more. Each level checks the edits that take effect in it, so edits of a package set in two levels that would make a cycle only together make none. When the statement that closes a cycle was evaluated before the one that found it (a package used later in the level, a name used before the statement that binds it, an edit generated at the earlier place of its rule), the interpretation is run again with that statement failing from the start, so that what depends on it fails too. Cycles through sets holding a selection, which overflowed the stack, now fail like the others; a chain of 4,000 sets each added to the next is checked as fast as before. Corpus case 19 shows the rule.
- [x] Count each segment of a pipe as written after the earlier ones wherever the place of writing matters (draft 0.3, 5.5, in every version): the appearance and style queues, LAYER, the order of resolution, the drawing order, bundles, PRIORITY, CURRENT, the rewrites of a wire and the edits of a set.
- [x] Count the segments in 13.3 too: between the PLACE of a text and its `dx` or `dy`, and between the TEXTs written on one key, the later in the order of writing wins, also over a text made in a statement nested in an earlier segment.
- [x] Count the segments in the rule on cycles of sets (5.2.2) too: the statement that closes a cycle and comes last in the order of writing fails, where a later segment of a pipe is written later than one nested in an earlier segment.
- [ ] Find the members of a set, and whether it is lazy, without a call for each set of a chain of `@ADD-TO`: each takes some 2 KB of stack in a debug build and 0.3 to 0.5 KB in a release build, so a chain of a few thousand sets overflows a stack of 1 MiB, such as the main thread's on Windows or that of WebAssembly. The test of a chain of 1,000 runs on a thread of its own with a larger stack, since in a debug build it needs more than the 2 MiB of a test's thread on macOS.
- [x] Add the CLI: check, render, dump, and strip generated records.
- [x] Add a desktop viewer that opens a netlist, draws its levels, shows the netlist text and its diagnostics, follows a selected instance or net between the drawing and the text, and moves and zooms the view ([`apps/desktop/`](../apps/desktop/README.md)). It calls the Rust runtime directly through Tauri; it does not edit or solve.
- [x] Measure the desktop viewer's startup: on Windows 11 the first drawing appears after 0.6 to 1.0 s, most of it the WebView engine starting.

## Shared core and web viewer

One shared Rust core decides the drawing; the frontends are per platform ([decision 0008](decisions/0008-shared-core-per-platform-frontends.md)). In order:

- [x] Make style resolution linear in the number of objects. A chain of 2,000 resistors takes 0.17 s to check instead of 36 s, and doubling the chain about doubles the time (0.78 s for 8,000).
- [x] Add `crates/rnl-view`, the core interface (a workspace in, a Document out). It takes over the desktop viewer's document builder and the parts of `rnl-cli` that read no files: dialect detection, the bundled standard packages, level status. The desktop viewer and the CLI use it.
- [x] Give the Document each level's primitives in serializable form, with SVG written from them; generate type definitions for frontends. The frontend chooses the outputs; by default the Document is as before. The TypeScript declarations are in [`crates/rnl-view/types`](../crates/rnl-view/README.md#type-definitions).
- [x] Draw line styles in the renderer rather than the SVG writer (the hairline's width, dashes, double lines on every shape, flylines), and give them in the primitives, so that every frontend draws them as the SVG does. Each shape has a list of strokes, drawn in turn over its fill: a colour, a width, dashes and a dash offset in scene units or in pixels, a cap and a join. A double line is two strokes, now on rectangles, circles and ellipses too, which the SVG drew as one plain line. The SVGs of the 24 earlier files of the corpus are byte-identical, and the new case 17 draws every style on every shape kind.
- [x] Ship fonts with the core and lay out text with their metrics; choose the font set, including Chinese, and its licence ([decision 0009](decisions/0009-fonts-shipped-with-the-core.md)). The fonts are Noto Sans SC Regular and Bold, the Simplified Chinese subset of Noto Sans CJK (思源黑体), under the SIL Open Font License 1.1, chosen for now. [`scripts/fonts.py`](../scripts/README.md) downloads them at a pinned tag and checks their sums; it writes the metrics the renderer needs, 8.5 KB for the 30,890 code points they map, which CI checks against the fonts, and the page's web fonts, 17.3 MB in slices by Unicode range of which a drawing loads what it uses: 45 KB in Latin, 205 KB for corpus case 15 with its Chinese. The renderer lays out each text and the primitives give its runs at their places, with their sizes and widths, and its bars as strokes; the SVG writes them with `textLength`, so a browser without the fonts keeps the layout. The models and the expected files of the corpus do not change; the SVGs change in their texts and in the frames the texts' exact boxes give, and native and WebAssembly Documents stay identical.
- [x] Use a pure-Rust math library in the core, and test in CI that native and WebAssembly builds give identical Documents on the conformance corpus. The core takes its sines, cosines and arc tangents from `libm`, which changed no output; the 24 files of the corpus, the two standard packages and a Latin-1 file give identical Documents. Two things in the Document followed a hash map's order, which changes from build to build: which of several equally close names a hint offers, and the order of the overridden statements. Both are fixed, and corpus case 16 keeps them so.
- [x] Add the WebAssembly binding in [`bindings/`](../bindings/README.md), run in a Worker ([`bindings/runtime-wasm`](../bindings/runtime-wasm/README.md)): a JSON request in and a Document out, with no generated glue, and JavaScript modules that load it, run it in a Worker and collect the files a document needs. The module is 1.20 MB, 407 KB gzip-compressed.
- [x] Split the desktop viewer's page into modules behind a shell interface and a command table, so that the web viewer can reuse it.
- [x] Add the web viewer in [`apps/web/`](../apps/web/README.md): open files, a folder or a URL, collect the included files, an HTML menu bar, and the panels of the desktop viewer. It is a static site of 1.36 MB with the core, and for the same files its Documents are `rnl view`'s but for the paths that name the files.
- [x] Test the shared page in Chromium, WebKit and Firefox against a fake shell, and smoke-test the desktop viewer. [`tests/viewer`](../tests/viewer/README.md) runs 60 tests of the page per engine with Playwright, on Documents that `rnl view` built from the corpus; on Windows the desktop viewer's smoke test drives the app through WebView2's DevTools port. The tests found that an initial of the subcircuit index scrolled to the end of the list, that in Firefox a double click on a row of the tree did not fold it, and that the narrowest side panel covered the file tabs; the page is fixed, and they pass in every engine. So does a test of selecting a double line, which showed as one solid band: the SVG marks the strokes after a shape's first, and the selection leaves them as they are.
- [x] Smoke-test the web viewer. [`tests/viewer`](../tests/viewer/README.md#the-web-viewer) builds the site with the samples, serves it, and runs 15 tests per engine on the real core in its Worker: netlists by URL with their includes, by an address that redirects and at a server's root, files and a folder set on the file inputs, with the dialog that asks which is the netlist, dropped files, a Latin-1 file, a missing include and one above the files opened, Reload after a served file changed, and the About box. Each Document is the one `rnl view` builds for the same files but for the paths that name them. WebKit skips the test of dropped files: the entries of a drop made in the page cannot read their files there. The core now names the files of an entry at the root of the workspace, `/top.sp`, as it does in a directory, and keeps a `..` above the root, so the web shell names files opened from the computer `/NAME` and a URL's by their paths on the server that served the netlist, after any redirect.
- [x] Publish the web viewer on the project site, at [rich-netlist.github.io/rnl/viewer/](https://rich-netlist.github.io/rnl/viewer/), with the conformance corpus as samples, and give the site a page for the tools ([`site`](../site/README.md)): what the viewers do, the web viewer with a few samples, and the desktop viewer's downloads, whose version and links the site's build takes from the newest tag `viewer-vX.Y.Z`. [`pages.yml`](../.github/workflows/pages.yml) builds the web viewer with the site, and builds the site again after each release of the desktop viewer. In the web viewer, Help › Desktop Viewer opens that page.
- [x] Load a netlist's text from the clipboard in both viewers, shown before it opens (File › Load from Clipboard); dim the text outside the definition of the subcircuit drawn, and bring its start into view when the subcircuit is entered. The Document gives each subcircuit level the lines of its definition (`Level::lines`).

## Solving and editing

- [ ] Edit RNL text in the viewers and redraw on request (a refresh button and a shortcut), including a netlist pasted without a file ([decision 0008](decisions/0008-shared-core-per-platform-frontends.md)).

- [ ] Define the precise RNL output contract, source metadata, and input fingerprint in the language draft.
- [x] Give the solver its input and write its output, in the runtime ([`rnl-runtime`](../crates/rnl-runtime/README.md#for-a-solver)). A level is read without its `type="generated"` records in every file (`Options::generated`, `rnl … --no-generated`); `LevelProblem` gives each level's objects with each coordinate and the orientation fixed or free, their symbols and write-back references, the geometric facts in the order of 8.5 with their members, priorities, sources and usage chains, and the wires, ROUTEs, groups and usages; `write_record` writes a solution as the level's one generated record, the usages that rules made written out under stable names; `sig1:<input>.<options>` hashes the input and the solver's options apart, so that a viewer compares the input alone. The checks' tolerance is an option. `rnl problem` prints the problems; the brainstorm's cases are in [`tests/integration`](../tests/integration/README.md).
- [ ] Implement the solver, separate solver WASM binding/package, and native/WASM consistency checks.
- [x] Write no record in a region written to be encrypted (2.2). `writeback::record_line` puts the record of a level whose end lies in one before the region, and before the subcircuit of the level that holds that place; a level whose own text lies in one, such as a subcircuit of an encrypted library, has no place: `rnl solve` solves it and writes nothing for it, with a note in its report, and `rnl-edit` refuses its ops. A header record in such a region gets no VERSION, and one that moves above a subcircuit whose `.subckt` lies in one goes before the region.
- [x] Choose the comment marker of a record by the language mode where it is written (2.2). The Spectre adapter lists the lines it reads in SPICE mode (`HostDocument::spice_mode`), and both writers carry a record there with `*`, where `//` is no comment, and elsewhere with the carrier of the file (`writeback::carrier_at`).
- [x] Give `rnl-edit` the name of the file it writes, as an optional field of the request, `file` (also of the WebAssembly `write` request, and the name of OUT for `rnl write`), and write its header with the rules of `writeback::with_header` (`writeback::add_header`): a Spectre netlist saved without the `.scs` suffix is read in the SPICE mode up to its `simulator lang=spectre`, and its header goes after that statement with `//`, or above it with `*` (16.3); its records follow the header's marker. A request without `file` writes as before.
- [x] Raise the version of a file that the solver writes into only when its record needs it (16.1). In a file of 0.2 whose record needs the numbers of objects without a name (5.9) or the routes of wires (13.1) (`Unsolved::needs_0_3`), `rnl solve` writes `@VERSION("0.3")` in the header record, followed by `@USE-PACKAGE(name="rnl-std", version="0.2")` unless the file, or a file that includes it, pins the standard package already (`writeback::raise_version`, `pins_std`), and solves its levels again as they read in 0.3; its output says so. A name in the file spelled like `numbering`, the word that 0.3 adds (keys of texts, role and parameter names, sub-object names, aliases, fields of record heads, host parameters; `writeback::spelled_like_new_words`), keeps it at 0.2 with a warning, and what only 0.3 can write is unsolved, as before. A record without such forms leaves the version as it is. `rnl-edit` writes new netlists only, in 0.3, and raises no version.
- [ ] Add `rnl migrate`, which moves a whole file to 0.3: the header record to `@VERSION("0.3")`, the standard names renamed by the table of the series 0.3 (`notes/rnl-standard-0.3/rename-0.3.md` in rnl-dev fec4245), whole words only and not where the file defines a name of its own, `$GROUND` to `$GROUND_SYMBOL` before `$GND` to `$GROUND`, and the pin of the series 0.2 taken out. The names can come from the tables that the runtime already has for its hints ([`interp/renames.rs`](../crates/rnl-runtime/src/interp/renames.rs)), private to it now: the 21 names that the series 0.3 renamed (`RENAMED`); `$GROUND`, a symbol in 0.2 and a definition in 0.3 (`SYMBOL_NOW_DEFINITION`); and `$OPAMP`, which 0.3 keeps in `rnl-std-functional`, a package that rnl-std does not bring in (`MOVED`), so that a file using it gets a USE-PACKAGE of that package or of `rnl-std-full`. `rnl migrate` should share them rather than keep a second table. It lists what keeps its name but is drawn or means otherwise in 0.3, such as `$VCVS` and `$VCCS`, which draw two terminals only, and E, G and S, whose default is four terminals.
- [x] Give each usage of the problem the place of its AS or ATTACH statement (`UsageEntry::source`), so that the solver's hints of a conflict name a usage by the line it is written on. Like every place, it is left out of the hash of the problem.
- [x] Read Spectre's `switch`, `relay` and `transformer` as built-in elements, not as subcircuit calls. A `switch` has a terminal for each node, `t0` its common terminal and `t1` to `tn` its throws, as Spectre numbers its positions; a `relay` has `p n cp cn`, also as the master of a model card, whose model type is `sw`, as S of SPICE; a `transformer` has `p_plus p_minus s_plus s_minus`. The rules of the series 0.3 draw them as `$SWITCH`, `$VOLTAGE_CONTROLLED_SWITCH` and `$TRANSFORMER`; a switch of three or more throws is still drawn with two pins, on `t0` and `t1` (Annex C).
- [ ] Tell apart, in the places of diagnostics, the package files of one name in two package directories, such as `rnl-std.rnl` of the series 0.2 and 0.3. A package file's level and the places of its diagnostics are named by its bare file name (`load_package_file`), so a diagnostic in one does not say which file it is in. Their texts are two sources already, and both count in the revision of a snapshot.
- [x] Read a library section as a file of its own (2.8) wherever a file is meant: two sections of one library, `.lib file sec` or `include "file" section=sec`, are two file levels, each with its header record, its version and its dialect. Each level records the lines that open and close its section (`Level::section_lines`), and `HostDocument::file_level` and `file_level_at` give the file level that holds a level or a line. `rnl solve` raises only the section whose record needs 0.3, both in one pass when both need it; an instance of T, O, U or Z has the terminal names of the version of its section (6.12), whichever section is read first; and a section has the dialect of its own first statement (16.3). The subcircuits of the main file have the dialect of the main file, whose title is no statement.
- [x] Report a second VERSION in a header record, which a file never has (16.1): it is an error and ignored, and the first stands, as the scan of the package directories takes it for a package file. Before, the last one silently won.
- [ ] Add viewer integration that requests solving only when needed or requested.
- [ ] Implement the framework independent editor core, transactions, and safe host writeback. Set aside on 2026-10-17: Analog Canvas only stays compatible with RNL and is no RNL editor. It reads RNL into its own format and writes RNL anew when it exports, so [`rnl-edit`](../crates/rnl-edit/README.md) writes an edit only into a netlist without RNL records, and refuses one that has them. Merging into a netlist's records, replacing the author's own record, checking a snapshot's revision as the base, and the snapshot's sources wait until a frontend edits RNL.
