## Reading and rendering

- [x] Implement the Rust runtime and the SPICE and Spectre host adapters for language draft 0.2, without a solver: constraints are checked against the written coordinates and unplaced objects are reported.
- [x] Implement the shared renderer (primitives and SVG) and the draft standard package with its symbols ([`libraries/standard/`](../libraries/standard/README.md)); every symbol writes its box.
- [ ] Add standard symbols for the elements that still lack one (J, F, H, B and others).
- [x] Make reading SPICE and Spectre netlists linear in their size. Each reader keeps the names of a level's instances to find a name defined twice, the SPICE reader looks through a run of comment lines once, the Spectre reader joins `\` continuations in place, and records that leave a comment open no longer each look to the end of their run of carrier lines. Reading 32,000 resistors takes 0.05 to 0.06 s instead of 1.3 to 1.5 s, and the rich synthetic of 16,000 cells (32,000 elements, 142,000 comment lines) 0.11 s instead of 9.9 s in SPICE; doubling the netlist about doubles the time.
- [x] Make checking with the standard package linear in the number of subcircuits. Its fill sets are shared by all levels; a set now keeps the `@ADD-TO` and `@REMOVE-FROM` of each level apart, so that a level copies and goes through its own only. Whether a set is lazy no longer goes through its changes once it cannot be lazy any more (no member can be, as in `$SUPPLY_NET_SET`, or a change adds a selection), nor through changes from sets that cannot be. Building a level no longer goes through every statement above it to find the rules, nor through every `scope=` record above it. Checking 4,000 subcircuits of one resistor takes 1.2 s instead of 7.8 s and 8,000 take 2.5 s instead of 34 s, against 0.13 and 0.24 s without the standard package (as before); the rich synthetic of 8,000 subcircuits of six kinds, which change the sets in several levels and through `scope=`, takes 6 s instead of 207 s (1.0 s instead of 3.5 s without the standard package), and a set holding a selection that receives from each of 8,000 levels a set edited with a selection takes 2.7 s instead of 70 s. Doubling the subcircuits about doubles the time. A shared set still goes through the changes from sets that can still become lazy, as before: receiving from each of 8,000 levels a set holding a selection extended with another such set takes 17 s (84 s before).
- [x] Follow the revised rule on cycles of sets (draft 5.2.2, 7.5). A set depends on the sets written in the statement that makes it and on the sets that `@ADD-TO` and `@REMOVE-FROM` add to it or remove from it; taking a level's statements in order of position (8.5), the one that closes a cycle fails, its diagnostic lists the whole cycle with the places of its statements, and the rest takes effect. A cycle through a removal no longer makes the whole interpretation fail, and a cycle of additions is no longer interpreted; nothing makes the whole interpretation fail any more. Each level checks the edits that take effect in it, so edits of a package set in two levels that would make a cycle only together make none. When the statement that closes a cycle was evaluated before the one that found it (a package used later in the level, a name used before the statement that binds it, an edit generated at the earlier place of its rule), the interpretation is run again with that statement failing from the start, so that what depends on it fails too. Cycles through sets holding a selection, which overflowed the stack, now fail like the others; a chain of 4,000 sets each added to the next is checked as fast as before. Corpus case 18 shows the rule.
- [x] Add the CLI: check, render, dump, and strip generated records.
- [x] Add a desktop viewer that opens a netlist, draws its levels, shows the netlist text and its diagnostics, follows a selected instance or net between the drawing and the text, and moves and zooms the view ([`apps/desktop/`](../apps/desktop/README.md)). It calls the Rust runtime directly through Tauri; it does not edit or solve.
- [x] Measure the desktop viewer's startup: on Windows 11 the first drawing appears after 0.6 to 1.0 s, most of it the WebView engine starting.

## Shared core and web viewer

One shared Rust core decides the drawing; the frontends are per platform ([decision 0006](decisions/0006-shared-core-per-platform-frontends.md)). In order:

- [x] Make style resolution linear in the number of objects. A chain of 2,000 resistors takes 0.17 s to check instead of 36 s, and doubling the chain about doubles the time (0.78 s for 8,000).
- [x] Add `crates/rnl-view`, the core interface (a workspace in, a Document out). It takes over the desktop viewer's document builder and the parts of `rnl-cli` that read no files: dialect detection, the bundled standard packages, level status. The desktop viewer and the CLI use it.
- [x] Give the Document each level's primitives in serializable form, with SVG written from them; generate type definitions for frontends. The frontend chooses the outputs; by default the Document is as before. The TypeScript declarations are in [`crates/rnl-view/types`](../crates/rnl-view/README.md#type-definitions).
- [x] Draw line styles in the renderer rather than the SVG writer (the hairline's width, dashes, double lines on every shape, flylines), and give them in the primitives, so that every frontend draws them as the SVG does. Each shape has a list of strokes, drawn in turn over its fill: a colour, a width, dashes and a dash offset in scene units or in pixels, a cap and a join. A double line is two strokes, now on rectangles, circles and ellipses too, which the SVG drew as one plain line. The SVGs of the 24 earlier files of the corpus are byte-identical, and the new case 17 draws every style on every shape kind.
- [x] Ship fonts with the core and lay out text with their metrics; choose the font set, including Chinese, and its licence ([decision 0007](decisions/0007-fonts-shipped-with-the-core.md)). The fonts are Noto Sans SC Regular and Bold, the Simplified Chinese subset of Noto Sans CJK (思源黑体), under the SIL Open Font License 1.1, chosen for now. [`scripts/fonts.py`](../scripts/README.md) downloads them at a pinned tag and checks their sums; it writes the metrics the renderer needs, 8.5 KB for the 30,890 code points they map, which CI checks against the fonts, and the page's web fonts, 17.3 MB in slices by Unicode range of which a drawing loads what it uses: 45 KB in Latin, 205 KB for corpus case 15 with its Chinese. The renderer lays out each text and the primitives give its runs at their places, with their sizes and widths, and its bars as strokes; the SVG writes them with `textLength`, so a browser without the fonts keeps the layout. The models and the expected files of the corpus do not change; the SVGs change in their texts and in the frames the texts' exact boxes give, and native and WebAssembly Documents stay identical.
- [x] Use a pure-Rust math library in the core, and test in CI that native and WebAssembly builds give identical Documents on the conformance corpus. The core takes its sines, cosines and arc tangents from `libm`, which changed no output; the 24 files of the corpus, the two standard packages and a Latin-1 file give identical Documents. Two things in the Document followed a hash map's order, which changes from build to build: which of several equally close names a hint offers, and the order of the overridden statements. Both are fixed, and corpus case 16 keeps them so.
- [x] Add the WebAssembly binding in [`bindings/`](../bindings/README.md), run in a Worker ([`bindings/runtime-wasm`](../bindings/runtime-wasm/README.md)): a JSON request in and a Document out, with no generated glue, and JavaScript modules that load it, run it in a Worker and collect the files a document needs. The module is 1.20 MB, 407 KB gzip-compressed.
- [x] Split the desktop viewer's page into modules behind a shell interface and a command table, so that the web viewer can reuse it.
- [x] Add the web viewer in [`apps/web/`](../apps/web/README.md): open files, a folder or a URL, collect the included files, an HTML menu bar, and the panels of the desktop viewer. It is a static site of 1.36 MB with the core, and for the same files its Documents are `rnl view`'s but for the paths that name the files.
- [x] Test the shared page in Chromium, WebKit and Firefox against a fake shell, and smoke-test the desktop viewer. [`tests/viewer`](../tests/viewer/README.md) runs 60 tests of the page per engine with Playwright, on Documents that `rnl view` built from the corpus; on Windows the desktop viewer's smoke test drives the app through WebView2's DevTools port. The tests found that an initial of the subcircuit index scrolled to the end of the list, that in Firefox a double click on a row of the tree did not fold it, and that the narrowest side panel covered the file tabs; the page is fixed, and they pass in every engine. So does a test of selecting a double line, which showed as one solid band: the SVG marks the strokes after a shape's first, and the selection leaves them as they are.
- [x] Smoke-test the web viewer. [`tests/viewer`](../tests/viewer/README.md#the-web-viewer) builds the site with the samples, serves it, and runs 15 tests per engine on the real core in its Worker: netlists by URL with their includes, by an address that redirects and at a server's root, files and a folder set on the file inputs, with the dialog that asks which is the netlist, dropped files, a Latin-1 file, a missing include and one above the files opened, Reload after a served file changed, and the About box. Each Document is the one `rnl view` builds for the same files but for the paths that name them. WebKit skips the test of dropped files: the entries of a drop made in the page cannot read their files there. The core now names the files of an entry at the root of the workspace, `/top.sp`, as it does in a directory, and keeps a `..` above the root, so the web shell names files opened from the computer `/NAME` and a URL's by their paths on the server that served the netlist, after any redirect.

On a pushed tag `viewer-v<version>`, [`viewer-release.yml`](../.github/workflows/viewer-release.yml) builds the app as a single executable, an NSIS installer for the current user without administrator rights, in English and Simplified Chinese, and an MSI for the machine, with the Tauri command line pinned in [`apps/desktop`](../apps/desktop/README.md#building); checks that the executable needs no `WebView2Loader.dll` beside it, which MSVC builds link in, smoke-tests it, installs both installers, smoke-tests the installed app and uninstalls it; and publishes the files with their SHA-256 sums as the GitHub release titled `RNL Viewer <version>`, not marked as the repository's latest release, which stays the language standard's. The installers carry the MIT License and the fonts' licence. Help › Check for Updates in the desktop viewer looks there for a newer release when asked, and never by itself.
