## Reading and rendering

- [x] Implement the Rust runtime and the SPICE and Spectre host adapters for language draft 0.2, without a solver: constraints are checked against the written coordinates and unplaced objects are reported.
- [x] Implement the shared renderer (primitives and SVG) and the standard packages for 0.2 and 0.3 with their symbols ([`libraries/standard/`](../libraries/standard/README.md)).
- [x] Add the standard 0.3 symbols and selection rules for J, F, H and B: `$NJFET`/`$PJFET`, `$CCCS`, `$CCVS` and `$BEHAVIORAL_SOURCE`, verified by [`std03.rs:every_native_element_gets_its_symbol`](../crates/rnl-cli/tests/std03.rs) and [`device_symbols.rs`](../crates/rnl-cli/tests/device_symbols.rs). The terminal-count variants deferred to language 0.4 remain listed above.
- [ ] Add symbol packages for the devices of foundries' PDKs. Their instances are calls of subcircuits that the netlist does not define, and are drawn as boxes until a package gives them symbols.
- [x] Make reading SPICE and Spectre netlists linear in their size. Each reader keeps the names of a level's instances to find a name defined twice, the SPICE reader looks through a run of comment lines once, the Spectre reader joins `\` continuations in place, and records that leave a comment open no longer each look to the end of their run of carrier lines. Reading 32,000 resistors takes 0.05 to 0.06 s instead of 1.3 to 1.5 s, and the rich synthetic of 16,000 cells (32,000 elements, 142,000 comment lines) 0.11 s instead of 9.9 s in SPICE; doubling the netlist about doubles the time.
- [x] Make checking with the standard package linear in the number of subcircuits. Its fill sets are shared by all levels; a set now keeps the `@ADD-TO` and `@REMOVE-FROM` of each level apart, so that a level copies and goes through its own only. Whether a set is lazy no longer goes through its changes once it cannot be lazy any more (no member can be, as in `$SUPPLY_NET_SET`, or a change adds a selection), nor through changes from sets that cannot be. Building a level no longer goes through every statement above it to find the rules, nor through every `scope=` record above it. Checking 4,000 subcircuits of one resistor takes 1.2 s instead of 7.8 s and 8,000 take 2.5 s instead of 34 s, against 0.13 and 0.24 s without the standard package (as before); the rich synthetic of 8,000 subcircuits of six kinds, which change the sets in several levels and through `scope=`, takes 6 s instead of 207 s (1.0 s instead of 3.5 s without the standard package), and a set holding a selection that receives from each of 8,000 levels a set edited with a selection takes 2.7 s instead of 70 s. Doubling the subcircuits about doubles the time. A shared set still goes through the changes from sets that can still become lazy, as before: receiving from each of 8,000 levels a set holding a selection extended with another such set takes 17 s (84 s before).
- [x] Follow the revised rule on cycles of sets (draft 5.2.2, 7.5). A set depends on the sets written in the statement that makes it and on the sets that `@ADD-TO` and `@REMOVE-FROM` add to it or remove from it; taking a level's statements in order of position (8.5), the one that closes a cycle fails, its diagnostic lists the whole cycle with the places of its statements, and the rest takes effect. A cycle through a removal no longer makes the whole interpretation fail, and a cycle of additions is no longer interpreted; nothing makes the whole interpretation fail any more. Each level checks the edits that take effect in it, so edits of a package set in two levels that would make a cycle only together make none. When the statement that closes a cycle was evaluated before the one that found it (a package used later in the level, a name used before the statement that binds it, an edit generated at the earlier place of its rule), the interpretation is run again with that statement failing from the start, so that what depends on it fails too. Cycles through sets holding a selection, which overflowed the stack, now fail like the others; a chain of 4,000 sets each added to the next is checked as fast as before. Corpus case 19 shows the rule.
- [x] Count each segment of a pipe as written after the earlier ones wherever the place of writing matters (draft 0.3, 5.5, in every version): the appearance and style queues, LAYER, the order of resolution, the drawing order, bundles, PRIORITY, CURRENT, the rewrites of a wire and the edits of a set.
- [x] Count the segments in 13.3 too: between the PLACE of a text and its `dx` or `dy`, and between the TEXTs written on one key, the later in the order of writing wins, also over a text made in a statement nested in an earlier segment.
- [x] Count the segments in the rule on cycles of sets (5.2.2) too: the statement that closes a cycle and comes last in the order of writing fails, where a later segment of a pipe is written later than one nested in an earlier segment.
- [ ] Find the members of a set, and whether it is lazy, without a call for each set of a chain of `@ADD-TO`: each takes some 2 KB of stack in a debug build and 0.3 to 0.5 KB in a release build, so a chain of a few thousand sets overflows a stack of 1 MiB, such as the main thread's on Windows or that of WebAssembly. The test of a chain of 1,000 runs on a thread of its own with a larger stack, since in a debug build it needs more than the 2 MiB of a test's thread on macOS.
- [x] Add the CLI: check, render, dump, and strip generated records.
- [x] Add a desktop viewer that opens a netlist, draws its levels, shows the netlist text and its diagnostics, follows a selected instance or net between the drawing and the text, and moves and zooms the view ([`apps/desktop/`](../apps/desktop/README.md)). It calls the Rust runtime directly through Tauri; it does not edit or solve.
- [x] Measure the desktop viewer's startup: on Windows 11 the first drawing appears after 0.6 to 1.0 s, most of it the WebView engine starting.

## Solving and editing

- [ ] Define the precise RNL output contract, source metadata, and input fingerprint in the language draft.
- [x] Give the solver its input and write its output, in the runtime ([`rnl-runtime`](../crates/rnl-runtime/README.md#for-a-solver)). A level is read without its `type="generated"` records in every file (`Options::generated`, `rnl … --no-generated`); `LevelProblem` gives each level's objects with each coordinate and the orientation fixed or free, their symbols and write-back references, the geometric facts in the order of 8.5 with their members, priorities, sources and usage chains, and the wires, ROUTEs, groups and usages; `write_record` writes a solution as the level's one generated record, the usages that rules made written out under stable names; `sig1:<input>.<options>` hashes the input and the solver's options apart, so that a viewer compares the input alone. The checks' tolerance is an option. `rnl problem` prints the problems; the brainstorm's cases are in [`tests/integration`](../tests/integration/README.md).
- [ ] Implement the solver, separate solver WASM binding/package, and native/WASM consistency checks.
- [ ] Have the solver recognize the names of the standard series 0.3 (in progress). It comes with the second version of the objectives, which moves every name of the standard package out of the solver into its configuration; until then the solver of the toolkit recognizes grounds, ports and mirror pairs only by the names of the series 0.2, so in a file of 0.3 the objectives `current_direction`, `ground_direction` and `signal_flow` have nothing to act on.
- [x] Write no record in a region written to be encrypted (2.2). `writeback::record_line` puts the record of a level whose end lies in one before the region, and before the subcircuit of the level that holds that place; a level whose own text lies in one, such as a subcircuit of an encrypted library, has no place: `rnl solve` solves it and writes nothing for it, with a note in its report, and `rnl-edit` refuses its ops. A header record in such a region gets no VERSION, and one that moves above a subcircuit whose `.subckt` lies in one goes before the region.
- [x] Choose the comment marker of a record by the language mode where it is written (2.2). The Spectre adapter lists the lines it reads in SPICE mode (`HostDocument::spice_mode`), and both writers carry a record there with `*`, where `//` is no comment, and elsewhere with the carrier of the file (`writeback::carrier_at`).
- [x] Give `rnl-edit` the name of the file it writes, as an optional field of the request, `file` (also of the WebAssembly `write` request, and the name of OUT for `rnl write`), and write its header with the rules of `writeback::with_header` (`writeback::add_header`): a Spectre netlist saved without the `.scs` suffix is read in the SPICE mode up to its `simulator lang=spectre`, and its header goes after that statement with `//`, or above it with `*` (16.3); its records follow the header's marker. A request without `file` writes as before.
- [ ] Add `rnl migrate`, which moves a whole file to 0.3: the header record to `@VERSION("0.3")`, the standard names renamed by the table of the series 0.3 (`notes/rnl-standard-0.3/rename-0.3.md` in rnl-dev fec4245), whole words only and not where the file defines a name of its own, `$GROUND` to `$GROUND_SYMBOL` before `$GND` to `$GROUND`, and the pin of the series 0.2 taken out. The names can come from the tables that the runtime already has for its hints ([`interp/renames.rs`](../crates/rnl-runtime/src/interp/renames.rs)), private to it now: the 21 names that the series 0.3 renamed (`RENAMED`), `$MIRROR_PAIR` to `$MIRRORED` among them; `$GROUND`, a symbol in 0.2 and a definition in 0.3 (`SYMBOL_NOW_DEFINITION`); and `$OPAMP`, which 0.3 keeps in `rnl-std-functional`, a package that rnl-std does not bring in (`MOVED`), so that a file using it gets a USE-PACKAGE of that package or of `rnl-std-full`; the definitions that 0.3 left out (`LEFT_OUT`); and the role `series` of `$CHAIN`, `chain` in 0.3 (`ROLE_RENAMED`). `rnl migrate` should share them rather than keep a second table. Of the definitions left out, `$DIFFPAIR_TAIL` is only renamed, to `$DIFFERENTIAL_PAIR`, whose role `tail` it fills; an `$INPUT_STAGE` is no rename: its tail goes into the role `tail` of the differential pair it names, and where that cannot be done a comment is left. `(series)` becomes `(chain)` only in the usages of `$CHAIN`. A current mirror written `#M3(ref) {#M4 #M6}(out)` is two usages in 0.2 and one in 0.3, whose roles are sets, and is not rewritten. The series 0.3 merged `rnl-std-layout` and `rnl-std-semantics` into `rnl-std-structures` (`MERGED`), whose definitions carry their default drawings in their bodies, of priority low: `@USE-PACKAGE(name="rnl-std-layout") {}`, which turned the default layouts of 0.2 off, becomes a rule `# @SELECT-USAGE $X => @PRIORITY("disabled")` for each definition of `rnl-std-structures` with a default drawing, and where that cannot be done, as for another USE-PACKAGE of the two names, a comment is left. It lists what keeps its name but is drawn or means otherwise in 0.3, such as `$VCVS` and `$VCCS`, which draw two terminals only, and E, G and S, whose default is four terminals.
- [x] Give each usage of the problem the place of its AS or ATTACH statement (`UsageEntry::source`), so that the solver's hints of a conflict name a usage by the line it is written on. Like every place, it is left out of the hash of the problem.
- [x] Read Spectre's `switch`, `relay` and `transformer` as built-in elements, not as subcircuit calls. A `switch` has a terminal for each node, `t0` its common terminal and `t1` to `tn` its throws, as Spectre numbers its positions; a `relay` has `p n cp cn`, also as the master of a model card, whose model type is `sw`, as S of SPICE; a `transformer` has `p_plus p_minus s_plus s_minus`. The rules of the series 0.3 draw them as `$SWITCH`, `$VOLTAGE_CONTROLLED_SWITCH` and `$TRANSFORMER`; a switch of three or more throws is still drawn with two pins, on `t0` and `t1` (Annex C).
- [ ] Tell apart, in the places of diagnostics, the package files of one name in two package directories, such as `rnl-std.rnl` of the series 0.2 and 0.3. A package file's level and the places of its diagnostics are named by its bare file name (`load_package_file`), so a diagnostic in one does not say which file it is in. Their texts are two sources already, and both count in the revision of a snapshot.
- [x] Read a library section as a file of its own (2.8) wherever a file is meant: two sections of one library, `.lib file sec` or `include "file" section=sec`, are two file levels, each with its header record, its version and its dialect. Each level records the lines that open and close its section (`Level::section_lines`), and `HostDocument::file_level` and `file_level_at` give the file level that holds a level or a line. `rnl solve` raises only the section whose record needs 0.3, both in one pass when both need it; an instance of T, O, U or Z has the terminal names of the version of its section (6.12), whichever section is read first; and a section has the dialect of its own first statement (16.3). The subcircuits of the main file have the dialect of the main file, whose title is no statement.
- [x] Read the ports of a `.subckt` written on the `+` lines that continue it, up to its parameters, and none from an end-of-line comment, in a SPICE netlist and in the SPICE mode of a Spectre one: they name the terminals of its instances (6.4, 6.12). Before, the `+` lines of a `.subckt` were dropped and `.subckt cell a b ; two ports` had five ports. A comment line between a statement and the `+` line that continues it has a warning in both adapters (2.2); before, the Spectre adapter gave none in SPICE mode.
- [x] Give an instance the version of the include it is read through (`Instance::file_level`, `HostDocument::file_level_of`): a library section without a header record that a file of 0.2 and one of 0.3 both read is two file levels, each in the version of the file that reads it (2.8, 16.1), and its T, O, U and Z have the terminal names of that version whichever is read first (6.12).
