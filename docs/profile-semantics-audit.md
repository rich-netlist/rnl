## Explicit 10.5 / 14.8 write-back cross-check

The published 0.3 rule differs from 0.2. K::kw_usage takes an application's explicit priority and only `disabled` from its record head. An ordinary/high/low/normal record head does not give AS/ATTACH a priority. P::eff_priority then resolves enclosing usages and direct local overrides. W::usage_statement serializes the stored optional priority, omitting it when absent in 0.3. Its separate 0.2 branch writes normal where needed to preserve older interpretation behavior.

cli/priority::a_usage_that_a_rule_makes_keeps_the_priorities_of_its_body_through_a_solve checks these four cases:

| Generation input | Explicit usage output | Effective body after read-back |
|---|---|---|
| No priority, ordinary record | No priority parameter | Original low/high/normal |
| Explicit high on ATTACH | Explicit high | All high |
| No priority, high record head | No priority parameter | Original low/high/normal |
| No priority, disabled record head | Explicit disabled | All disabled |

The test compares serialized fragments, read-back constraint priorities and no unplaced duplicates. Its generated body's explicit wire makes the terminal leave the wired=false fill. This is a property of that rule: §10.5 does not promise built-in deduplication for an arbitrary rule. The `solution` tests also cover numbered unnamed body objects, rewritten wires and unrepresentable results. The main profile's fixture-backed round-trip harness supplements these procedural assertions with reviewable serialized input/output.

## Confirmed gaps and corrections

**S1 — nested symbol drawing order: corrected (§§9.2.1, 9.2.7, 11.6).** runtime/src/interp/obj.rs::SymbolDef::push_prim/push_usage assign positions from one declaration sequence. K::merge_symbol offsets those positions at each inclusion, O::symbol_view exports them and R::Out::symbol uses them as hierarchical drawing keys. Primitive/text indices remain stable for text expansion. The viewer draws its optional pin-name labels after the symbol members. cli/symbol_drawing_order::nested_graphics_and_fixed_text_keep_their_position_through_repeated_inclusion checks repeated fragments, nested fixed text, rotation and SVG output; nested_order_does_not_depend_on_a_fixed_primitive_count checks 130 preceding primitives.

**S2 — deep nested symbol content: open normative gap (§§9.2.3, 9.2.7, 13.3).** O::symbol_extent traverses nested symbols only while `depth < 8`; O::symbol_texts returns when `depth > 8`. O::symbol_view still exports deeper symbols and R::Out::symbol draws their geometry. Thus a deeper valid acyclic symbol can have truncated bounds and missing fixed text while its geometry remains. These sections specify no such silent depth limit. Future regression: nine or more drawing-only wrappers around a graphic/text, asserting full extent and emitted text. A correction should use cycle-aware traversal or report a resource limit, not silently omit content.

**S3 — terminal selection case: fixed (§10.1 with §§6.4/6.12).** S::select formerly used eq_ignore_ascii_case unconditionally for terminal string filters. It now follows S::host_case, also corrected to read the instance's own case_sensitive field, the first member for bundles, and the level for ports. This matters for SPICE sections of Spectre files. cli/profile_semantics::terminal_selections_obey_the_hosts_case_rules checks distinct Spectre P/p ports, SPICE p/P matching and a Spectre file switching to SPICE.

**S4 — heterogeneous bundle terminal-count panic: fixed (§11.8).** P::resolve_bundles correctly warns and retains heterogeneous members, but S::term_net/tnets previously indexed every member by the first member's terminal index without checking its length. Checked access now omits nonexistent later-member nodes while retaining the warning and existing connections. No remaining net produces the existing “is on no net” diagnostic. cli/profile_semantics::a_shorter_bundle_member_contributes_only_its_existing_terminals exercises ::net, WIRE, SELECT-TERMINAL and exported pin nets on a four-/two-terminal bundle. This removes the panic; it does not resolve S5.

**S5 — heterogeneous bundle ordinal correspondence: open normative gap (§11.8).** The text says a bundle terminal stands for terminals “of the same name” of all members. S::term_net/tnets instead use the first member's numeric index for every member. When two subcircuits declare the same names in different port orders, a bundle pin can therefore collect the wrong later-member net. The ordinary uniform bundle fixtures do not expose it. Name-based correspondence needs its own implementation and regression; missing names in heterogeneous members are additionally underdefined (C1). Do not describe S4's checked-index fix as full heterogeneous-bundle compliance.

**S6 — arrow tangent after coincident Bézier controls: fixed (§9.2.5).** R::Out::arrows now scans inward for the next point that differs from an endpoint when the immediately neighboring control point coincides with it. This follows the published fallback instead of producing a degenerate arrow direction. render/src/lib.rs::tests::bezier_arrows_skip_coincident_control_points checks normal controls, coincident controls at both ends, multiple coincident starting controls and multiple coincident ending controls, including arrow tip and triangle bounds.

**S7 — case-sensitive terminal names collide in symbol pins: P2 open normative gap (§§9.2.4, 9.2.7, 9.2.8 with §6.4).** K::add_pin uses runtime/src/interp/obj.rs::TermKey::same, whose named-terminal branch always calls eq_ignore_ascii_case. Thus a symbol containing separate PIN(terminal="P") and PIN(terminal="p") retains only the later pin even when the owning Spectre subcircuit has two distinct ports P and p. The existing CLI dump reproduced one remaining lowercase pin, no selected uppercase-terminal label and no diagnostic; using numeric pins 1 and 2 retained both pins and produced exactly the uppercase label. This is separate from S3's corrected selector matching. The selector regression deliberately uses numeric pins to isolate its target. A complete correction needs pin replacement to preserve host/role-sensitive names without breaking case-insensitive SPICE overrides, with a dedicated regression.

## Choices and standard questions

**C1 — missing heterogeneous terminal names.** §11.8 keeps members with differing types/models/counts after a warning but does not expressly state what a later member contributes when it has no corresponding terminal name. S4 contributes no invented node and preserves the warning. Reordered existing names have the clear S5 requirement; missing names need a stated policy.

**C2 — computed box precision and empty boxes.** G::shape_extent_points bounds Bézier control points rather than tight curve extrema. O::symbol_extent falls back to pins when there are no non-text graphics, then to [0,0,0,0]. §9.2.3 excludes text, but does not define empty-graphics boxes or bounding tightness tolerance. Document these consumer-visible choices without claiming identical layout across tools.

**C3 — allowed visual/solver choices.** Fallback block arrangements, font metrics/fallback, arrowhead shape, script/fraction spacing, unconstrained text placement, pin labels, hairline rendering, free routing, group scoring and default tolerance are implementation choices. Current-direction and signal-flow objectives are not required vocabulary. Primitive round-trip tests prove this implementation's drawing transport, not a standardized house style.
